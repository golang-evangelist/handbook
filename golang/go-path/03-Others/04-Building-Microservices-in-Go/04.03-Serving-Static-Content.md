# 04.03 Serving Static Content

> **Go Path - Zero to Gopher** / **03 Others → Building Microservices in Go** / Lesson 04.03

## Lesson goals

After this lesson you should:

- serve files from disk via `http.FileServer` and `http.Dir`
- embed static resources into the binary with `embed.FS`
- mount an FS on a path without path leakage (`http.StripPrefix`)
- understand when static content comes from the Go process, and when from CDN/object storage
- avoid common security mistakes (directory listing, path traversal)

## Prerequisite

- Go 1.22+
- lesson 04.02 (HTTP server skeleton, timeouts)
- basic knowledge of HTML/CSS/JS as “files the browser requests”
- `embed` package available since Go 1.16 (you use it on 1.22+ without issues)

## Problem this lesson solves

A microservice is often not only JSON. You need:

- an admin SPA build (`dist/`)
- OpenAPI HTML
- a small marketing landing next to the API
- internal assets (logo, template files)

If you manually read files with `os.ReadFile` in every handler, you quickly get mistakes around MIME types, cache headers, path traversal, and deploy (“works on my machine because I have a `static/` folder next to the binary”).

`FileServer` and `embed` solve **byte delivery** correctly and predictably.

## Mental model

Static content is **URL → file mapping** with:

1. **Root FS** — where you read from (`os` dir or `embed.FS`).
2. **URL prefix** — which part of the path you strip before mapping into the FS.
3. **Policy** — whether you allow listing, cache, compress (often on a reverse proxy).

`embed` changes the deploy mental model: **the asset travels with the binary**. No “I forgot to copy `static/` into the Docker image”.

## Mechanism

### FileServer from disk

```go
mux := http.NewServeMux()
mux.Handle("GET /assets/", http.StripPrefix("/assets/", http.FileServer(http.Dir("static"))))
```

Request `GET /assets/app.css` → StripPrefix → `app.css` → reads `static/app.css`.

### embed.FS

```go
package main

import (
	"embed"
	"io/fs"
	"net/http"
)

//go:embed static/*
var staticRoot embed.FS

func assetsHandler() http.Handler {
	sub, err := fs.Sub(staticRoot, "static")
	if err != nil {
		panic(err)
	}
	return http.FileServer(http.FS(sub))
}

func main() {
	mux := http.NewServeMux()
	mux.Handle("GET /assets/", http.StripPrefix("/assets/", assetsHandler()))
	_ = http.ListenAndServe(":8080", mux)
}
```

`fs.Sub` is critical: otherwise the URL looks for `/static/...` inside the embed tree and you easily get the mapping wrong.

### Index and SPA fallback

`FileServer` automatically serves `index.html` for a directory. For an SPA (React/Vue) you often need: if the file does not exist, return `index.html` so the client router takes over. That is **not** built in — you write a small wrapper:

```go
func spa(fsys http.FileSystem) http.Handler {
	fileServer := http.FileServer(fsys)
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		path := r.URL.Path
		if path != "/" {
			if f, err := fsys.Open(path); err != nil {
				r.URL.Path = "/"
			} else {
				_ = f.Close()
			}
		}
		fileServer.ServeHTTP(w, r)
	})
}
```

Caution: such a fallback must stay behind auth if the admin app is protected.

### MIME types

`FileServer` uses `mime.TypeByExtension` and a sniffer. For non-standard extensions register:

```go
_ = mime.AddExtensionType(".webmanifest", "application/manifest+json")
```

### Cache headers

For hashed assets (`app.9f3a.css`) you can:

```go
func withCache(h http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Cache-Control", "public, max-age=31536000, immutable")
		h.ServeHTTP(w, r)
	})
}
```

For `index.html` keep a short cache or `no-cache`, otherwise users get stuck on an old shell.

## Rules and syntax

1. The `//go:embed` directive sits immediately above a `var` of type `embed.FS` or `[]byte` / `string`.
2. Embed paths are relative to the file that contains the directive.
3. Do not embed secrets (`.env`, private keys).
4. Always `StripPrefix` when mounting under `/assets/`.
5. Prefer `fs.Sub` so the FS root matches the URL root after the strip.
6. Directory listing: `http.FileServer` can list directories if there is no index — in production you often want to forbid that with a custom FS wrapper.
7. Timeouts from 04.02 still apply; large files may need a larger `WriteTimeout` or streaming via a proxy.

```go
//go:embed static/index.html static/app.css
var assets embed.FS
```

You can pick files or a glob. `*` does not enter subfolders; the `all:` prefix (Go 1.18+) includes files that start with a dot — use consciously.

## Examples

### Example 1 — disk vs embed in the same API

```go
func mountAssets(mux *http.ServeMux, dev bool) {
	var h http.Handler
	if dev {
		h = http.FileServer(http.Dir("static"))
	} else {
		sub, _ := fs.Sub(staticRoot, "static")
		h = http.FileServer(http.FS(sub))
	}
	mux.Handle("GET /assets/", http.StripPrefix("/assets/", h))
}
```

### What happens here

In development you change CSS without a rebuild. In production embed guarantees the image contains exactly those assets compiled with that API version.

### Example 2 — forbidden listing

```go
type noList struct{ fs http.FileSystem }

func (n noList) Open(name string) (http.File, error) {
	f, err := n.fs.Open(name)
	if err != nil {
		return nil, err
	}
	stat, err := f.Stat()
	if err != nil {
		_ = f.Close()
		return nil, err
	}
	if stat.IsDir() {
		_ = f.Close()
		return nil, fs.ErrNotExist
	}
	return f, nil
}
```

### What happens here

Directories “do not exist” for the client. You reduce leakage of file names. You can still serve an index file via explicit routes.

### Example 3 — OpenAPI UI next to a JSON API

```go
//go:embed openapi.yaml public/*
var docs embed.FS

mux.Handle("GET /docs/", http.StripPrefix("/docs/", http.FileServer(http.FS(mustSub(docs, "public")))))
mux.HandleFunc("GET /openapi.yaml", func(w http.ResponseWriter, r *http.Request) {
	b, _ := docs.ReadFile("openapi.yaml")
	w.Header().Set("Content-Type", "application/yaml")
	_, _ = w.Write(b)
})
```

### What happens here

One binary carries the spec and swagger static UI. Documentation does not lag behind the service deploy.

### Example 4 — mistake: path traversal expectations

`http.Dir` and `http.FS` already protect against `..` escaping the root. Still, **never** join a user string by hand:

```go
// BAD
http.ServeFile(w, r, filepath.Join("static", r.URL.Query().Get("f")))
```

### What happens here

A manual join opens a hole for `../../etc/passwd` style attacks. Leave mapping to FileServer or explicitly clean the path.

### Example 5 — CDN in front of Go

In production often: browser → CDN → object storage. Go serves only `/api/...`. Local `FileServer` remains for dev and small internal tools.

### What happens here

CDN takes CPU/bandwidth off the Go process. Embed still makes sense for small UIs where you want one artifact.

## Decision analysis

| Approach | When |
|---------|------|
| `http.Dir` | local dev, large assets that change often |
| `embed.FS` | small UI, docs, single-binary deploy |
| CDN + bucket | public traffic, global latency |
| Reverse proxy (nginx) | the team already has an edge layer for static |

Do not mix “the microservice must serve static” with “the microservice must be the origin for the whole web”. Often it is better that the API stays clean and the SPA is on a separate host.

## Trade-offs

- **Embed** = simple deploy, larger binary, rebuild for every CSS change.
- **Disk** = fast iteration, risk that the image has no files, dependence on working directory.
- **SPA fallback** = nice UX routing, but careful with 404 for real API paths (mount SPA only on `/app/`).
- **Long cache** = speed, but requires a fingerprint in the file name.

## Common mistakes

1. Forgotten `StripPrefix` → 404 on all assets.
2. Embed without `fs.Sub` → you look for the wrong root.
3. Working directory in Docker is not where you think → `http.Dir("static")` empty.
4. Cache `index.html` for a year → users do not see the new release.
5. Directory listing on the public internet.
6. Embedding secret files “for convenience”.
7. WriteTimeout too short for a large download through the same server.

## Idiomatic Go

- Assets in `static/` or `ui/dist/` with a clear `//go:embed`.
- `internal` does not need to know about FS; `main` or `cmd/server` mounts routes.
- In tests use `httptest` and a small `fstest.MapFS` instead of real files.
- Do not introduce a heavy web framework only for static — the standard library covers this well.

```go
sub, err := fs.Sub(staticRoot, "static")
if err != nil {
	return err
}
```

An explicit error at start is better than 404 in production.

## Practical scenario

A team has a Go billing API and a small React admin console. First they copied `dist/` into the Docker image next to the binary. Once CI built Go but forgot `npm run build` — production served an old UI with a new API and broke forms.

**Fix:** multi-stage Docker: node stage builds UI, Go stage does `embed` or `COPY` into a known path *in the same image tag*. Later they move to embed for admin (small bundle) and CDN for the public marketing site.

After that “API and UI version” become one artifact for the admin surface — fewer tickets of the “looks different on my machine” kind.

### Security note

Admin static UI still needs auth on the API. Static JS is not a secret. Do not put a JWT secret in embed; put a public config endpoint.

## Summary

- `FileServer` maps URL to file with correct headers.
- `embed.FS` packs assets into the binary — predictable deploy.
- `StripPrefix` + `fs.Sub` are the key to mapping.
- Beware of listing, manual path join, and wrong cache.
- Next lesson: routing with ServeMux 1.22 and path values.

## Extra insight: what you should not serve from the Go process

Large video, user uploads, and a public marketing site rarely need to go through the same Go binary that does billing. Object storage plus CDN take the load off.

Go `FileServer` and `embed` are perfect for an admin UI of a few MB, documentation next to the API, and internal tools.

When the bundle grows and CI slows because of embed rebuild, that is a signal to extract the asset pipeline. An idiomatic Go microservice stays thin: JSON/gRPC first, static only when it truly belongs to the same artifact.

### Docker note

In a multi-stage build, copy static from the node stage into the same final image as the Go binary, or embed in the compile stage. Never rely on a volume mount in production as the only source of admin UI — the mount gets forgotten, the tag stays.

### Security reminder

- do not embed `.env` or private keys
- do not allow directory listing on a public host
- do not mix a user upload folder with the static root without strict authorization
- keep `Cache-Control` for `index.html` short; for hashed assets you may go long

These four points prevent most “static” incidents you see in code review.


## Mechanism (deepening): FileServer, embed.FS, defense

Trace: `GET /static/app.css` → mux → `StripPrefix` → `FileServer` → `fs.FS` (disk or `embed.FS`) → Content-Type + body.

```go
//go:embed static/*
var staticFS embed.FS
mux.Handle("GET /static/", http.StripPrefix("/static/", http.FileServer(http.FS(staticFS))))
```

**Predict:** wrong `StripPrefix` → 404. **Predict:** embed without rebuild after a CSS change → old content. Defense: narrow root, no secrets in static, never `FileServer` over a user upload dir without control. `filepath.Clean` mindset — do not serve `..`.

For SPA: careful with fallback to `index.html` (do not mask API 404). Cache headers consciously. Static is not an excuse for a fat monolith — CDN is often better for public assets.

## Mechanism (deepening): from URL to byte — FileServer trace

Static content in a Go process looks “trivial” until you get `StripPrefix`, embed path, or cache policy wrong. This section fixes the exact mechanism.

### Trace: disk FS

```text
GET /static/css/app.css
  → ServeMux match GET /static/
  → StripPrefix("/static/") → css/app.css
  → FileServer opens root/css/app.css
  → Content-Type (sniff/ext)
  → body + status 200
```

### Trace: embed.FS

```text
//go:embed static/*
var staticFS embed.FS
http.FS(staticFS) or fs.Sub(staticFS, "static")
  → same FileServer mechanism
  → file is in the binary; no disk read at runtime
```

```go
sub, err := fs.Sub(staticFS, "static")
if err != nil {
	log.Fatal(err)
}
mux.Handle("GET /static/", http.StripPrefix("/static/", http.FileServer(http.FS(sub))))
```

**Predict:** embed path `static/*` but `fs.Sub(..., "assets")`.  
**Answer:** empty / error — Sub must match the real tree in embed.

**Predict:** without `StripPrefix`.  
**Answer:** FileServer looks for `/static/css/...` inside the root → 404.

## Mechanism (deepening): why StripPrefix exists

`FileServer` interprets the request path relative to its FS root. If the URL prefix is `/static/`, and files live as `app.css` in the FS root, you must strip the prefix. That is not “decoration” — it is mapping the URL ↔ FS name space.

| URL | StripPrefix | FS path |
|-----|-------------|------------|
| /static/app.css | /static/ | app.css |
| /assets/app.css | /assets/ | app.css |
| /app.css | (none) | app.css |

## Mechanism (deepening): embed limits that must stick

- no `..` in embed directive paths  
- a CSS change requires a **rebuild** of the binary  
- large embed = larger artifact and slower CI  
- do not embed secrets (`.env`, private keys)  
- `_test.go` and test files have special rules — do not rely on “it happened to work”

**Predict:** in production you mount a volume over the embed path “to iterate faster”.  
**Answer:** you lose the predictable artifact advantage; choose disk FS **or** embed, not magic.

## Mechanism (deepening): security mechanism (defense)

1. **Narrow root** — FileServer only over `static/`, never over project `/`.  
2. **No listing** for a public host unless required (check default behavior; do not enable directory list without need).  
3. **Upload ≠ static root** — a user upload dir never directly as FileServer without auth and type control.  
4. **Path clean mindset** — do not join a user string into a path by hand; if you must, `filepath.Clean` + check you stay under the root.  
5. **Cache-Control** — `index.html` short; hashed `app.[hash].js` long.

### Attack trace (what you defend)

```text
GET /static/../../etc/passwd
  → (correct) FS root + clean → does not leave static
GET /files/<user-upload>/../../../
  → (badly designed root) leakage
```

## Mechanism (deepening): SPA fallback caution

“All unknown routes → index.html” easily masks API 404:

```text
GET /api/orders/123  (API does not exist)
  → SPA fallback index.html 200
  → frontend thinks HTML is success
```

Rule: register API routes **before** catch-all; catch-all only for UI paths. Test a deliberate API 404.

## Mechanism (deepening): when CDN beats Go FileServer

| Content | Better home |
|---------|-----------|
| marketing site, video | CDN / object storage |
| admin UI 2MB next to API | Go embed or sidecar static |
| user upload | object storage + signed URL |
| internal tool | Go FileServer OK |

A microservice that serves billing does not have to serve a 500MB campaign video. The responsibility boundary from 04.01 still applies.

## Mechanism (deepening): Docker multi-stage

```text
stage node: npm build → dist/
stage go: go build (+ optionally embed dist)
final: binary (+ static if not embed)
```

Never rely on “a volume with a laptop path” as the only UI source in production.

## Mechanism (deepening): Content-Type and cache

`FileServer` sets Content-Type. For API JSON do not use FileServer. For static:

- `Cache-Control: no-cache` or short for HTML  
- `Cache-Control: public, max-age=31536000, immutable` for hash assets  

Wrong cache = “deploy did not go through” tickets.


## Mechanism summary

Static in Go = exact URL→FS mapping + conscious embed vs disk decision + root defense + cache policy. When you hold that, UI next to the API does not become a security hole or deploy drama.

## Mechanism (deepening): hash assets and cache policy in practice

```text
index.html          → Cache-Control: no-cache
app.9f3a2.js        → immutable, long max-age
styles.9f3a2.css    → same
```

A release changes the hash in HTML. If you cache HTML for a year, users stay on an old shell that references deleted hash files → blank page.

### embed vs disk decision (checklist)

| Question | embed | disk/CDN |
|---------|-------|----------|
| UI < ~10MB next to API? | often yes | optional |
| frequent UI changes without API rebuild? | no | yes |
| secrets in the folder? | never | never |
| global marketing traffic? | no | CDN |

## Mechanism (deepening): fs.Sub traps

```go
//go:embed static/*
var raw embed.FS
sub, err := fs.Sub(raw, "static")
```

If you embed `static/static/...` by mistake, the Sub path breaks. Check the `embed` tree with one `fs.WalkDir` in a test.

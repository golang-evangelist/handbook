# 04.06 Creating Middleware

> **Go Path - Zero to Gopher** / **03 Others → Building Microservices in Go** / Lesson 04.06

## Lesson goals

After this lesson you should:

- write middleware as `func(http.Handler) http.Handler`
- wire logging, request ID, and an authz hook into a chain
- pass values through `context.Context`
- avoid classic mistakes (losing the ResponseWriter wrapper, double WriteHeader)
- understand middleware order and why it matters

## Prerequisite

- Go 1.22+
- lessons 04.02–04.05 (server, routes, JSON)
- basic understanding of `context.WithValue` (without abusing it for everything)

## Problem this lesson solves

Every handler should not have to:

- generate a request ID
- log method/path/status/latency
- check the Authorization header
- record metrics

If you copy that into 40 handlers, half will forget. Middleware extracts **cross-cutting concerns** to the edge of the HTTP stack.

## Mental model

Middleware is a hoop around the handler:

```text
request → m1 → m2 → m3 → handler → m3 → m2 → m1 → response
```

Outer middleware sees the whole request life (e.g. logging measures time). Inner does a narrower check (authz after the ID exists).

Request ID is a **correlation key** across logs and later across gRPC metadata.

## Mechanism

### Type

```go
type Middleware func(http.Handler) http.Handler

func chain(h http.Handler, ms ...Middleware) http.Handler {
	for i := len(ms) - 1; i >= 0; i-- {
		h = ms[i](h)
	}
	return h
}
```

Application: `chain(mux, withRequestID, withLogging, withAuthz)` means requestID is outermost if you put it first in the list with reverse apply — keep the team convention documented.

### Request ID

```go
type ctxKey int

const requestIDKey ctxKey = 1

func withRequestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id := r.Header.Get("X-Request-ID")
		if id == "" {
			id = uuidNew() // your implementation / google/uuid
		}
		w.Header().Set("X-Request-ID", id)
		ctx := context.WithValue(r.Context(), requestIDKey, id)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

func RequestIDFrom(ctx context.Context) string {
	v, _ := ctx.Value(requestIDKey).(string)
	return v
}
```

### Logging status — ResponseWriter wrapper

```go
type statusWriter struct {
	http.ResponseWriter
	status int
}

func (w *statusWriter) WriteHeader(code int) {
	w.status = code
	w.ResponseWriter.WriteHeader(code)
}

func withLogging(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		sw := &statusWriter{ResponseWriter: w, status: 200}
		next.ServeHTTP(sw, r)
		log.Printf("rid=%s %s %s %d %s",
			RequestIDFrom(r.Context()),
			r.Method, r.URL.Path, sw.status, time.Since(start),
		)
	})
}
```

If you use Hijack/Flush, the wrapper must forward those interfaces (`http.Flusher`) — otherwise SSE breaks.

### Authz hook

```go
func withAuthz(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.URL.Path == "/healthz" {
			next.ServeHTTP(w, r)
			return
		}
		token := r.Header.Get("Authorization")
		principal, err := authorize(r.Context(), token)
		if err != nil {
			http.Error(w, "unauthorized", http.StatusUnauthorized)
			return
		}
		ctx := context.WithValue(r.Context(), principalKey, principal)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}
```

`authorize` is a hook: JWT locally, introspection, or a call to an auth service. Middleware does not hardcode resource business rules — that stays in the handler (`canEditOrder`).

## Rules and syntax

1. Middleware returns a new `http.Handler`; it does not mutate global request state outside context/headers.
2. After `WriteHeader`/`Write` do not try another status in outer middleware.
3. Context keys: private type (`ctxKey`), not string (collisions).
4. Do not put huge structs in context without need.
5. The skip list (healthz) must be explicit.
6. Order: request ID → logging → auth → panic recover (if you have it) → mux.
7. Panic recover middleware, if present, logs rid and returns 500 — do not swallow silently.

```go
srv.Handler = chain(mux, withRequestID, withLogging, withAuthz)
```

## Examples

### Example 1 — complete chain in main

```go
mux := http.NewServeMux()
order.Register(mux, svc)
var h http.Handler = mux
h = withAuthz(h)
h = withLogging(h)
h = withRequestID(h)
srv := &http.Server{Addr: ":8080", Handler: h}
```

### What happens here

Here request ID is outermost (last wrap). Logging sees the ID. Authz runs inside. Keep the same behavior everywhere.

### Example 2 — recover

```go
func withRecover(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				log.Printf("rid=%s panic: %v", RequestIDFrom(r.Context()), rec)
				http.Error(w, "internal error", http.StatusInternalServerError)
			}
		}()
		next.ServeHTTP(w, r)
	})
}
```

### What happens here

One panic in a handler does not take down the whole process. Still fix the root cause — recover is a net, not a design.

### Example 3 — metrics hook

```go
func withMetrics(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		sw := &statusWriter{ResponseWriter: w, status: 200}
		next.ServeHTTP(sw, r)
		httpDuration.Observe(time.Since(start).Seconds())
		httpCount.Add(1, sw.status)
	})
}
```

### What happens here

Same wrapper pattern as logging. Later go-kit does something similar at the endpoint layer — here it is the HTTP level.

### Example 4 — propagating request ID to an outbound call

```go
req, _ := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
req.Header.Set("X-Request-ID", RequestIDFrom(ctx))
resp, err := client.Do(req)
```

### What happens here

Correlation crosses the service boundary. In the gRPC lessons you do the same via metadata.

### Example 5 — authz only on a route group

```go
api := http.NewServeMux()
order.Register(api, svc)
mux.Handle("/v1/", withAuthz(http.StripPrefix("", api))) // or mount pattern
mux.HandleFunc("GET /healthz", health)
```

### What happens here

Health stays public. The API requires a token. Better than a huge skip list of strings.

## Decision analysis

| Middleware | Required in API? | Note |
|------------|-----------------|----------|
| Request ID | yes | correlation |
| Access log | yes | incidents |
| Authz | almost always | public webhook exception |
| Recover | recommended | with alert on panic count |
| Metrics | yes in production | histogram + status |

## Trade-offs

- **Context values** — convenient, but a hidden API; document getters.
- **Fat auth middleware** — centralizes, but can become a god-object; keep the hook thin.
- **One chain for everything** — simple; different policies need mount by group.
- **ResponseWriter wrapper** — needed for status; fragile with special interfaces.

## Common mistakes

1. Logging before `next` without measuring status → always 200.
2. Losing `Flusher` in the wrapper.
3. String keys in context.
4. Authz on healthz → kube kills / removes wrongly.
5. Middleware that reads the body and does not restore it → handler sees EOF.
6. Double `WriteHeader` (middleware 401 after the handler already wrote).
7. Too much middleware that calls external services synchronously without a timeout.

## Idiomatic Go

- Small, composable middleware.
- Public helper `RequestIDFrom`.
- Test the chain with `httptest`.
- Do not introduce a heavy framework only for middleware — the stdlib pattern is enough.

```go
func TestRequestIDPropagates(t *testing.T) {
	h := withRequestID(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if RequestIDFrom(r.Context()) == "" {
			t.Fatal("missing id")
		}
	}))
	req := httptest.NewRequest(http.MethodGet, "/", nil)
	h.ServeHTTP(httptest.NewRecorder(), req)
}
```

## Practical scenario

During an incident the team cannot connect the API log with the payment log. They introduce `X-Request-ID`: generation at the edge, logging middleware, propagation into outbound HTTP/gRPC calls.

Next incident: they find the same `rid` across 4 services in 2 minutes. The authz hook stays separate — token introspection has its own 200 ms timeout; on auth failure they return 503/401 per policy, they do not hang forever.

### Order they chose

`recover → requestID → metrics → logging → authz → mux`

Recover outermost; authz near the handler. Logging sees the final status and rid.

## Summary

- Middleware composes cross-cutting concerns around the handler.
- Request ID, logging, and an authz hook are the minimum for a microservice.
- Context carries rid/principal; a ResponseWriter wrapper captures status.
- Chain order is part of the behavior contract.
- Next: when JSON HTTP is not enough — gRPC.

## Extra insight: middleware and performance

Every middleware adds allocations and branches. Ten wrappers per request is not free at high RPS. Measure. Often it is cheaper to merge request ID and a short access log into one pass than to keep five thin layers for aesthetics.

Authz that calls the network must have a timeout and a cache with a clear TTL. Otherwise your API inherits the auth service’s latency. The hook stays thin: *who is the principal*, not all RBAC rules in the world in one file.

### Observability minimum

With the access log, export: request count by status class, p95 latency, auth fail count. Request ID must be in the log line, not only in the response header. Without that middleware exists but does not help in an incident.

### Order as a team standard

Write the exact chain order in the service README. Otherwise a new member puts auth *before* request ID and debugs for hours why logs have no `rid` on 401 responses. Convention is worth more than another library abstraction.


## Mechanism (deepening): trace through the chain

```text
request enters
  → recover (catches panic, logs rid if it already exists — that is why rid is often right after recover)
  → requestID (set/propagate X-Request-ID, put in context)
  → metrics (start timer)
  → logging (waits for the end to see status)
  → authz (skip healthz; otherwise principal in context)
  → mux → handler
  ← authz
  ← logging writes access line (rid, method, path, status, latency)
  ← metrics Observe
  ← requestID (header already set)
  ← recover
response leaves
```

**Predict:** authz sits *before* requestID.  
**Answer:** 401 logs without `rid` — a nightmare. Document order in README.

**Predict:** logging measures status *before* `next.ServeHTTP` without a wrapper.  
**Answer:** you always see 200. You need `statusWriter`.

### statusWriter + Flusher

```go
type statusWriter struct {
	http.ResponseWriter
	status int
}

func (w *statusWriter) WriteHeader(code int) {
	w.status = code
	w.ResponseWriter.WriteHeader(code)
}

func (w *statusWriter) Flush() {
	if f, ok := w.ResponseWriter.(http.Flusher); ok {
		f.Flush()
	}
}
```

Without forwarding `Flush`, SSE/streaming through your logging middleware breaks. The same applies to `Hijacker` if you do websocket upgrade through the same chain.

## Mechanism (deepening): chain implementation

```go
type Middleware func(http.Handler) http.Handler

func chain(h http.Handler, ms ...Middleware) http.Handler {
	for i := len(ms) - 1; i >= 0; i-- {
		h = ms[i](h)
	}
	return h
}

// application: first in the list = outermost
var h http.Handler = mux
h = chain(h, withRecover, withRequestID, withMetrics, withLogging, withAuthz)
```

**Predict:** `chain(h, A, B)` — who sees the request first?  
**Answer:** A (outer), because the loop wraps from the end: first B then A.

Write the convention: “the first argument after h is outer”. A team that mixes conventions wastes hours.

## Mechanism (deepening): request ID in detail

```go
type ctxKey int

const requestIDKey ctxKey = 1

func withRequestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id := r.Header.Get("X-Request-ID")
		if id == "" {
			id = uuidNew()
		}
		if len(id) > 128 {
			id = id[:128] // defense against header abuse
		}
		w.Header().Set("X-Request-ID", id)
		ctx := context.WithValue(r.Context(), requestIDKey, id)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}
```

**Predict:** context key is the string `"request_id"`.  
**Answer:** collision with another package. Private type `ctxKey` is idiomatic.

### Outbound propagation

```go
req, err := http.NewRequestWithContext(ctx, http.MethodGet, url, nil)
if err != nil {
	return err
}
req.Header.Set("X-Request-ID", RequestIDFrom(ctx))
```

Same later in gRPC metadata (`x-request-id`). One name across languages.

## Mechanism (deepening): thin authz hook

```go
func withAuthz(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.URL.Path == "/healthz" || r.URL.Path == "/readyz" {
			next.ServeHTTP(w, r)
			return
		}
		ctx, cancel := context.WithTimeout(r.Context(), 200*time.Millisecond)
		defer cancel()
		principal, err := authorize(ctx, r.Header.Get("Authorization"))
		if err != nil {
			http.Error(w, "unauthorized", http.StatusUnauthorized)
			return
		}
		next.ServeHTTP(w, r.WithContext(context.WithValue(r.Context(), principalKey, principal)))
	})
}
```

**Predict:** auth introspection hangs 30s without a timeout.  
**Answer:** the whole API inherits the auth service’s latency. Timeout + auth fail/latency metric are mandatory.

Better than a huge skip list: mount auth only on the `/v1/` mux, health stays on root.

## Mechanism (deepening): middleware mistakes

| Mistake | Symptom | Fix |
|--------|---------|-----|
| Log before next without statusWriter | always 200 | wrapper |
| Body read in MW, not restored | handler EOF | do not read / tee / GetBody |
| Double WriteHeader | warning / wrong status | authz before handler write |
| String context key | silent collision | private type |
| Auth on healthz | kube kills pod | skip or separate mux |
| 10 MW for aesthetics | allocations at RPS | merge cheap passes |

**Predict:** middleware does `json.NewDecoder(r.Body).Decode` for “audit”, then calls next.  
**Answer:** handler sees an empty body. Either do not read, or `io.TeeReader` into a buffer and replace `r.Body`.

## Mechanism (deepening): recover

```go
func withRecover(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				log.Printf("rid=%s panic: %v", RequestIDFrom(r.Context()), rec)
				http.Error(w, "internal error", http.StatusInternalServerError)
				panicCount.Add(1)
			}
		}()
		next.ServeHTTP(w, r)
	})
}
```

Recover is a net, not a design. Alert on `panicCount`. Do not swallow silently.

## Mechanism (deepening): testing the chain

```go
func TestAuthzSkipsHealth(t *testing.T) {
	h := withAuthz(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusNoContent)
	}))
	req := httptest.NewRequest(http.MethodGet, "/healthz", nil)
	rec := httptest.NewRecorder()
	h.ServeHTTP(rec, req)
	if rec.Code != http.StatusNoContent {
		t.Fatalf("got %d", rec.Code)
	}
}

func TestAuthzBlocksAPI(t *testing.T) {
	h := withAuthz(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		t.Fatal("should not run")
	}))
	req := httptest.NewRequest(http.MethodGet, "/v1/orders", nil)
	rec := httptest.NewRecorder()
	h.ServeHTTP(rec, req)
	if rec.Code != http.StatusUnauthorized {
		t.Fatalf("got %d", rec.Code)
	}
}
```

## Predict-then-check

**A.** Logging outer, requestID inner → log without rid on success?  
**Answer:** yes, rid is not in context yet when logging starts; at the end it can read context if inner MW set it — but 401 from authz *before* rid still hurts. Keep rid outer of logging/auth.

**B.** `withMetrics` and `withLogging` both wrap ResponseWriter.  
**Answer:** works if both forward WriteHeader; test that status reaches both.

**C.** Principal in context as a huge struct with the token.  
**Answer:** leakage risk into logs; keep a thin Principal{ID, Roles}.

**D.** Same chain on gRPC.  
**Answer:** different API (unary interceptor), same mental model — module 05.

## Mechanism (deepening): complete main wire

```go
func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /healthz", health)
	order.Register(mux, svc)

	h := chain(mux,
		withRecover,
		withRequestID,
		withMetrics,
		withLogging,
		withAuthz,
	)

	srv := &http.Server{
		Addr:              ":8080",
		Handler:           h,
		ReadHeaderTimeout: 5 * time.Second,
	}
	log.Fatal(srv.ListenAndServe())
}
```

**Predict:** you forget ReadHeaderTimeout.  
**Answer:** Slowloris-ish risk; 04.02 already teaches timeouts — middleware does not replace them.

## Mechanism (deepening): unary interceptor counterpart

```go
func unaryLog(ctx context.Context, req any, info *grpc.UnaryServerInfo, handler grpc.UnaryHandler) (any, error) {
	start := time.Now()
	resp, err := handler(ctx, req)
	log.Printf("rpc=%s code=%v dur=%s", info.FullMethod, status.Code(err), time.Since(start))
	return resp, err
}
```

Same mental model as `withLogging`: measure after inner work, read code/status. Details in module 05.

## Mechanism (deepening): what does not go in context

| Put | Do not put |
|-------|-------------|
| request ID | DB connection |
| principal ID/roles | the whole HTTP request |
| trace span | a large file blob |
| deadline (already in ctx) | the whole app configuration |

Context is a request-scoped signal, not a service locator.

### Rate limit sketch

```go
func withRateLimit(next http.Handler, lim *rate.Limiter) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if !lim.Allow() {
			http.Error(w, "rate limit", http.StatusTooManyRequests)
			return
		}
		next.ServeHTTP(w, r)
	})
}
```

Put it inside of logging so you see 429 in the access log with rid.

### Tracing inject

OpenTelemetry middleware puts a span in context; rid still in the log. Do not replace rid with span id in human runbooks until the team agrees.

### Body audit trap

Reading the body for WAF/audit must restore `r.Body`. Otherwise the JSON handler gets EOF — “mysterious” 400.

# 04.04 Routing Requests

> **Go Path - Zero to Gopher** / **03 Others → Building Microservices in Go** / Lesson 04.04

## Lesson goals

After this lesson you should:

- use Go 1.22+ `ServeMux` patterns with an HTTP method
- read path parameters via `Request.PathValue`
- understand route priority and conflicts
- organize route registration by package without global chaos
- know when the standard mux stops being enough

## Prerequisite

- Go 1.22 or newer (older mux does **not** have method-aware patterns or `PathValue`)
- lessons 04.02 and 04.03
- knowledge of REST verbs: GET, POST, PUT, PATCH, DELETE

Check:

```bash
go version   # go1.22+
```

## Problem this lesson solves

Before Go 1.22, `ServeMux` did not distinguish methods. People wrote:

```go
if r.Method != http.MethodPost {
	http.Error(w, "method not allowed", 405)
	return
}
```

in every handler, or pulled in external routers just for `/users/{id}`.

From 1.22 the standard library covers **method + path + values**. This lesson teaches the exact model so you do not mix old and new style.

## Mental model

A route is a pattern:

```text
METHOD /path/{name}/...
```

For example: `GET /orders/{id}/items/{itemID}`

On match:

1. the method must match (if specified),
2. path segments must match,
3. `{name}` captures a segment,
4. `{name...}` (wildcard) captures the rest of the path.

`r.PathValue("id")` returns the captured string (may be empty if there is no match context).

## Mechanism

### Registration

```go
mux := http.NewServeMux()
mux.HandleFunc("GET /healthz", health)
mux.HandleFunc("GET /orders/{id}", getOrder)
mux.HandleFunc("POST /orders", createOrder)
mux.HandleFunc("DELETE /orders/{id}", deleteOrder)
```

### PathValue

```go
func getOrder(w http.ResponseWriter, r *http.Request) {
	id := r.PathValue("id")
	if id == "" {
		http.Error(w, "missing id", http.StatusBadRequest)
		return
	}
	// ...
}
```

### Wildcard

```go
mux.Handle("GET /files/{path...}", fileHandler)
```

`PathValue("path")` can be `reports/2026/a.pdf`.

### Trailing slash and host

Go 1.22 mux has more precise rules around trailing slash and an optional host prefix (`example.com/`). Read `net/http` docs for edges; in practice keep a consistent style without mixing `/orders` and `/orders/` without need.

### 405 Method Not Allowed

When a path exists for another method, the new mux can answer 405 instead of 404. That is better for API clients. Do not rely on the old reflex “everything that is not a match is 404”.

### Modular registration

```go
// internal/order/http.go
package order

func Register(mux *http.ServeMux, svc *Service) {
	mux.HandleFunc("GET /orders/{id}", svc.handleGet)
	mux.HandleFunc("POST /orders", svc.handleCreate)
}
```

`main` only calls `order.Register(mux, svc)`. Package boundaries stay clean.

## Rules and syntax

1. Pattern with method: `"GET /path"` — space required.
2. Path value name: identifier in `{id}` — use the same names consistently.
3. Do not mix old `Handle("/orders/", ...)` style with new patterns without reason.
4. Validation of `PathValue` is still needed: mux does not know that `id` is a UUID.
5. For a sub-router feel, mount a prefix carefully; often full paths are clearer.
6. Test methods: GET and POST on the same path must go to different handlers.
7. Panic or fail start if you register a duplicate the mux rejects.

```go
id := r.PathValue("id")
if _, err := uuid.Parse(id); err != nil {
	http.Error(w, "bad id", http.StatusBadRequest)
	return
}
```

## Examples

### Example 1 — CRUD set

```go
func RegisterUserRoutes(mux *http.ServeMux, h *UserHandlers) {
	mux.HandleFunc("GET /users", h.list)
	mux.HandleFunc("POST /users", h.create)
	mux.HandleFunc("GET /users/{id}", h.get)
	mux.HandleFunc("PATCH /users/{id}", h.patch)
	mux.HandleFunc("DELETE /users/{id}", h.delete)
}
```

### What happens here

One resource, five patterns, zero `switch r.Method`. Readable in review and in OpenAPI mapping.

### Example 2 — specificity conflict

```go
mux.HandleFunc("GET /orders/recent", recent)
mux.HandleFunc("GET /orders/{id}", byID)
```

`/orders/recent` should stay a literal. Registration order is not “first wins” like in some libraries; mux picks the most specific match. Still, avoid ambiguous designs (`/orders/{id}` where `id=recent` has special meaning without a literal route).

### What happens here

Literal segments beat a path value when that is the match rule. Design the API so “action” paths are explicit.

### Example 3 — wildcard for download

```go
mux.HandleFunc("GET /blob/{key...}", func(w http.ResponseWriter, r *http.Request) {
	key := r.PathValue("key")
	// authorize then stream
	_ = key
})
```

### What happens here

One handler covers nested keys. Authorization must see the whole `key` — do not trust the client blindly.

### Example 4 — route test

```go
func TestGetOrderRoute(t *testing.T) {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /orders/{id}", func(w http.ResponseWriter, r *http.Request) {
		_, _ = w.Write([]byte(r.PathValue("id")))
	})
	req := httptest.NewRequest(http.MethodGet, "/orders/abc", nil)
	rec := httptest.NewRecorder()
	mux.ServeHTTP(rec, req)
	if rec.Body.String() != "abc" {
		t.Fatalf("got %q", rec.Body.String())
	}
}
```

### What happens here

`httptest` exercises a real match. Always also test the wrong method (expect 405/404 per behavior).

### Example 5 — when to leave for chi/echo/gin

If you need:

- middleware trees by group with complex skip rules,
- regex constraint in the route,
- huge compatibility with old code,

then a library can help. For most JSON microservices, 1.22 mux + your middleware stack (04.06) is enough.

### What happens here

A framework is not free: another abstraction, another learning curve, another upgrade path. Idiomatic Go chooses stdlib until it hurts.

## Decision analysis

| Choice | Motive |
|-------|--------|
| Stdlib mux 1.22 | fewer dependencies, enough for REST |
| External router | advanced patterns, legacy |
| PathValue + manual validation | clear; mux is not a schema validator |
| Prefix by domain (`/v1/orders`) | API version (see 04.05) |

Path versioning (`/v1/...`) is done here; semantic versioning of JSON fields in the next lesson.

## Trade-offs

- **Methods in the pattern** — cleaner handlers, but requires Go 1.22+ on all build agents.
- **Wildcard** — flexible, harder for authorization policies and metrics per route.
- **Central Register** — overview; risk of a god-object if you stuff everything in one file.
- **405 vs 404** — better for clients, can surprise old tests.

## Common mistakes

1. Running code on Go 1.21 and wondering why the pattern does not work.
2. Expecting `{id}` to validate type — it does not.
3. `r.URL.Query().Get("id")` instead of `PathValue` after migration.
4. Registering `GET /orders/{id}` and a separate middleware that strips the path before the mux.
5. Mixing `http.Handle` (DefaultServeMux) and a local mux — confusion in tests.
6. Assuming `HandleFunc` call order determines priority like in regex routers.
7. An SPA fallback route that “eats” API paths because it is too wide.

## Idiomatic Go

- One `*http.ServeMux` per process (or per test).
- `Register(mux, deps)` per package.
- Path parameters = strings; parse immediately at the edge.
- Do not use `DefaultServeMux` in libraries.

```go
// bad in a library package:
http.HandleFunc("/x", h)

// good:
func Mount(mux *http.ServeMux) { mux.HandleFunc("GET /x", h) }
```

## Practical scenario

A team migrates from Gin to stdlib after Go 1.22. First they rewrite routes 1:1, keep Gin middleware for a week, then replace middleware with the chain from 04.06.

The biggest bug in migration: old tests expected 404 for `POST /orders/{id}` when only GET exists — the new mux returns 405. They update tests and client retry so they do not treat 405 as “no resource”.

Result: one less dependency, faster cold start in small images, new team members read `net/http` docs instead of a Gin cheat-sheet.

### Mapping to microservice boundaries

Routes are part of the public contract. Changing `/users/{id}` to `/accounts/{id}` is breaking — treat it as an API version, not as “rename in the IDE”.

## Summary

- Go 1.22+ `ServeMux` understands methods, path value, and wildcard.
- `PathValue` + explicit validation = a clean API edge.
- Register routes modularly; avoid DefaultServeMux in libs.
- Stdlib is enough for most microservices in this course.
- Next: JSON request/response DTOs and message versioning.

## Extra insight: routes as a contract

Every route you register enters the public attack surface and support. So in review ask:

1. Is the method the least privileged that is needed?
2. Does `PathValue` have validation and authorization?
3. Can metrics aggregate by pattern (`/orders/{id}`) and not by full URL with thousands of IDs?

High cardinality in metrics kills Prometheus. In logs you can log the full path; in metrics use the route template. Go 1.22 mux gives you a clear pattern — use it in telemetry too.

### Migration from old mux style

If you still have `if r.Method != POST` blocks, replace them with the method in the pattern. Tests that expected 404 for the wrong method may now see 405 — update them consciously; that is a contract improvement.

### File organization

Suggested structure:

```text
cmd/api/main.go          # wire + server
internal/order/service.go
internal/order/http.go   # Register(mux, svc)
internal/platform/httpx/ # decode/encode helpers
```

Routes live near the domain, not in one 2000-line `routes.go` until you must. When the route count outgrows overview, split by aggregate — not by technical layer.

## Mechanism (deepening): how ServeMux 1.22 picks a route

This section is the longest part of the lesson. The goal is not to list patterns, but to **predict** what the mux does before you run a test.

### Trace 1 — successful GET with PathValue

```text
client: GET /orders/ord_42 HTTP/1.1
  ↓
ServeMux: looks for a pattern that covers method GET and path
  ↓
candidates: "GET /orders/{id}" (match), "POST /orders" (method no), "GET /orders/recent" (literal no)
  ↓
win: GET /orders/{id}  →  PathValue("id") = "ord_42"
  ↓
handler getOrder writes JSON
```

**Predict the result:** status 200, body with the order.  
**Answer:** correct — provided the handler does not do extra validation that rejects `ord_42`.

### Trace 2 — wrong method on an existing path

```text
client: DELETE /orders/ord_42
registered: only GET /orders/{id} and POST /orders
```

**Predict the result:** 404 or 405?  
**Answer:** Go 1.22+ mux typically returns **405 Method Not Allowed** when the path exists for another method. That is not a bug — it is a better contract for API clients. Update old tests that expected 404.

### Trace 3 — literal beats path value

```go
mux.HandleFunc("GET /orders/recent", recent)
mux.HandleFunc("GET /orders/{id}", byID)
```

Request: `GET /orders/recent`.

**Predict:** does `id` become `"recent"`?  
**Answer:** no. A literal segment is more specific. The `recent` handler is called. Design the API so “action” paths are explicit literals, not magic in the handler (`if id == "recent"`).

### Trace 4 — wildcard

```go
mux.HandleFunc("GET /blob/{key...}", serveBlob)
// GET /blob/reports/2026/a.pdf  →  PathValue("key") == "reports/2026/a.pdf"
```

**Predict:** does the mux check path traversal (`..`)?  
**Answer:** no. The wildcard captures a string. Authorization and path cleaning are your responsibility before reading a file or object storage key.

## Mechanism (deepening): registration, panic at start, test

### Duplicate pattern

If you register the same method+pattern twice, the mux may panic at registration (depending on the exact situation). **Fail start** — do not wait for the first request in production to discover the conflict.

```go
func mustRegister(mux *http.ServeMux) {
	mux.HandleFunc("GET /healthz", health)
	mux.HandleFunc("GET /orders/{id}", getOrder)
	// deliberate duplicate in a test environment catches the error immediately
}
```

### httptest as source of truth

```go
func TestMethodNotAllowed(t *testing.T) {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /orders/{id}", func(w http.ResponseWriter, r *http.Request) {
		_, _ = w.Write([]byte(r.PathValue("id")))
	})
	req := httptest.NewRequest(http.MethodPost, "/orders/x", nil)
	rec := httptest.NewRecorder()
	mux.ServeHTTP(rec, req)
	if rec.Code != http.StatusMethodNotAllowed && rec.Code != http.StatusNotFound {
		t.Fatalf("unexpected status %d", rec.Code)
	}
	t.Logf("status=%d (document as team contract)", rec.Code)
}
```

Do not “guess” the status from memory — write it in the test and in OpenAPI.

### Table: pattern → what PathValue returns

| Request | Pattern | PathValue |
|--------|---------|-----------|
| `GET /u/42` | `GET /u/{id}` | `id=42` |
| `GET /f/a/b` | `GET /f/{path...}` | `path=a/b` |
| `GET /u/42` | `GET /u/me` + `GET /u/{id}` | goes to `{id}` (not `me`) |
| `POST /u` | `GET /u` + `POST /u` | POST handler, no path value |

## Mechanism (deepening): modular Register and dependencies

```go
package order

type Handlers struct {
	Svc *Service
}

func (h *Handlers) Register(mux *http.ServeMux) {
	mux.HandleFunc("GET /v1/orders/{id}", h.get)
	mux.HandleFunc("POST /v1/orders", h.create)
	mux.HandleFunc("DELETE /v1/orders/{id}", h.delete)
}

func (h *Handlers) get(w http.ResponseWriter, r *http.Request) {
	id := r.PathValue("id")
	if id == "" {
		http.Error(w, "missing id", http.StatusBadRequest)
		return
	}
	// authorization: may this principal see exactly this id?
	ord, err := h.Svc.Get(r.Context(), id)
	if err != nil {
		http.Error(w, "not found", http.StatusNotFound)
		return
	}
	_ = ord
}
```

**Predict:** what if middleware strips `/v1` before the mux, and the pattern still says `/v1/orders/{id}`?  
**Answer:** match fails → 404. StripPrefix and patterns must agree. That is why it is often clearer to keep **full** paths in `HandleFunc` without a hidden rewrite.

### Why not DefaultServeMux in a library

```go
// bad — pollutes global state, breaks tests
func init() {
	http.HandleFunc("/orders", handle)
}

// good — the caller controls the mux
func Mount(mux *http.ServeMux, h *Handlers) { h.Register(mux) }
```

A library that calls `http.Handle` in `init` makes parallel tests and two servers in the same process a nightmare.

## Mechanism (deepening): PathValue validation is not optional

Mux only guarantees that a segment was captured. It does not guarantee UUID, does not guarantee the resource exists, does not guarantee the user may see it.

```go
func parseOrderID(raw string) (string, error) {
	if raw == "" {
		return "", errMissing
	}
	if len(raw) > 64 {
		return "", errTooLong
	}
	// e.g. prefix policy: ord_
	if !strings.HasPrefix(raw, "ord_") {
		return "", errBadFormat
	}
	return raw, nil
}
```

### IDOR reminder

`GET /orders/{id}` without an ownership check is a classic IDOR. PathValue is an input like a JSON field — a **trust boundary**. Authz middleware says *who the principal is*; the handler says *whether that principal may this id*.

## Mechanism (deepening): trailing slash and host

Go 1.22 has more precise rules. The team needs **one** standard:

| Choice | Example | Note |
|-------|--------|----------|
| No trailing slash | `/orders/{id}` | often simplest |
| With slash for “collection” | `/orders/` | consistently or not at all |
| Host in the pattern | `api.shop.local/v1/...` | rare; use when you truly share mux by host |

**Predict:** client calls `/orders/1/` and you only have `/orders/{id}` without slash.  
**Answer:** may be 404 or redirect depending on rules — so write a test and document. Do not mix styles in the same API.

## Mechanism (deepening): metrics by pattern, not by full URL

```text
bad:  http_requests{path="/orders/ord_1"}  http_requests{path="/orders/ord_2"} ...
good: http_requests{route="GET /orders/{id}", code="200"}
```

High cardinality kills Prometheus. Go 1.22 gives you a clear template — use it in telemetry. In logs you may use the full path; in metrics not.

## Mechanism (deepening): version in the path

```go
mux.HandleFunc("GET /v1/orders/{id}", h.getV1)
mux.HandleFunc("GET /v2/orders/{id}", h.getV2)
```

`/v1` and `/v2` are part of the **routing contract**. A semantic change of JSON fields (rename, new meaning) goes with a version — details in 04.05. Here remember: changing `/users/{id}` to `/accounts/{id}` is a breaking surface, not “rename in the IDE”.

## Predict-then-check (set for code review)

**A.** Registered `GET /items/{id}` and `GET /items/{id}/parts`. Request `GET /items/a/parts`.  
**Predict:** which handler?  
**Answer:** the second — longer/more specific match for that path.

**B.** Handler does `id := r.URL.Query().Get("id")` after migration to PathValue.  
**Predict:** what does it see?  
**Answer:** empty string if the client sends id only in the path. Migration bug.

**C.** Library package calls `http.HandleFunc("GET /x", h)` in `init`.  
**Predict:** problem in tests?  
**Answer:** yes — global DefaultServeMux, state leak between tests.

**D.** Wildcard `GET /files/{path...}` serves `http.Dir(".")` without StripPrefix discipline.  
**Predict:** risk?  
**Answer:** path traversal / too-wide root. Narrower root + validate `path`.

**E.** SPA fallback `GET /{path...}` registered before API routes.  
**Predict:** API disappears?  
**Answer:** depends on specificity; a wide catch-all easily “eats” the API. Register API first and keep SPA fallback widest and conscious.

## Mechanism (deepening): when stdlib stops being enough

Stay on ServeMux while you only need:

- method + path + path value + wildcard,
- your middleware chain (04.06),
- JSON DTO (04.05).

Consider chi/echo/gin when:

- you need nested middleware groups with complex skip rules on a subtree,
- regex constraint in the route itself is a hard requirement,
- legacy code already lives in that framework and migration costs more than the dependency.

A framework is not free: another abstraction, another learning curve, another upgrade path. Idiomatic Go chooses stdlib until it hurts.

## Mechanism (deepening): migration from Gin / old mux

Steps that work in practice:

1. Rewrite routes 1:1 to `"METHOD /path/{id}"` patterns.
2. Replace `c.Param("id")` with `r.PathValue("id")`.
3. Run the test suite; expect 404→405 changes.
4. Keep old middleware a week next to the new chain, then remove the framework.
5. Move telemetry to the route template.

The biggest bug in migration is usually not PathValue — but **status code expectations** and client retry that treats 405 as “no resource”.

## Mechanism (deepening): file organization that scales

internal/order/service.go       # domain
internal/order/http.go          # Handlers + Register
internal/catalog/http.go        # second aggregate

## Scenario (deepened): review checklist for a new route

Before merge ask:

1. Is the HTTP method the least privileged that is needed? (GET instead of POST for read)
2. Does `PathValue` have format validation?
3. Does authz check the resource, not only “has a token”?
4. Does the metric use the route template?
5. Is the path part of the `/v1` contract and changelog?
6. Is there httptest for match + wrong method?
7. Does OpenAPI / proto-gateway map (if any) know about this route?

If seven points pass, the route is not just “another HandleFunc” — it is part of a public system.

## Mechanism (deepening): complete mini service with routes

Blind join of 04.02 + 04.04 — without JSON details (that is 04.05), but with real matching:

```go
package main

import (
	"log"
	"net/http"
	"time"
)

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /healthz", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("ok"))
	})
	mux.HandleFunc("GET /v1/orders/{id}", getOrder)
	mux.HandleFunc("POST /v1/orders", createOrder)
	mux.HandleFunc("GET /v1/orders/recent", recentOrders)

	srv := &http.Server{
		Addr:              ":8080",
		Handler:           mux,
		ReadHeaderTimeout: 5 * time.Second,
	}
	log.Fatal(srv.ListenAndServe())
}

func getOrder(w http.ResponseWriter, r *http.Request) {
	id := r.PathValue("id")
	if id == "" {
		http.Error(w, "missing id", http.StatusBadRequest)
		return
	}
	_, _ = w.Write([]byte(id))
}

func createOrder(w http.ResponseWriter, r *http.Request) {
	w.WriteHeader(http.StatusCreated)
}

func recentOrders(w http.ResponseWriter, r *http.Request) {
	_, _ = w.Write([]byte("recent"))
}
```

**Predict:** `GET /v1/orders/recent` — does it hit `getOrder` with `id=recent`?  
**Answer:** no, if `GET /v1/orders/recent` is registered as a literal (as above). Order in code is not “first wins” like in some libraries; specificity is. Still: **always** register literals consciously and test.

**Predict:** `PUT /v1/orders/x` without a registered PUT.  
**Answer:** 405 (or 404 at edges) — write it in a test for your Go version.

### Trace through the server

```text
ListenAndServe
  → accepts TCP
  → reads request line + headers (ReadHeaderTimeout protects)
  → mux.ServeHTTP
  → pattern match
  → handler
  → response
```

Routes are only one step. Without timeouts on `Server` (04.02) and without a body limit (04.05), a perfect mux does not save the service.

## Mechanism (deepening): sub-routing without a fake “Group”

Some frameworks offer `r.Group("/v1")`. In stdlib you have two clean options:

1. **Full paths** in every `HandleFunc` — most readable in grep and OpenAPI.
2. **Separate mux** mounted on a prefix — useful when you want a different middleware stack.

```go
api := http.NewServeMux()
order.Register(api) // patterns: "GET /orders/{id}" inside api mux

root := http.NewServeMux()
root.Handle("/v1/", http.StripPrefix("/v1", api))
root.HandleFunc("GET /healthz", health)
```

**Predict:** inside `api` you register `GET /v1/orders/{id}` instead of `GET /orders/{id}`.  
**Answer:** after StripPrefix the path no longer has `/v1` → 404. Align patterns with what the mux actually sees.

## Mechanism (deepening): HEAD and OPTIONS

`ServeMux` and `net/http` have history around HEAD/GET. For an API:

- explicitly register `OPTIONS` only if you do CORS by hand (often a reverse proxy does CORS);
- do not assume “free” HEAD always works as you want for all handlers — test if clients send HEAD.

For most JSON microservices: GET/POST/PATCH/DELETE explicitly, CORS on the gateway.

## Lesson glossary

| Term | Meaning |
|-------|----------|
| pattern | `"METHOD /path/{name}"` string for ServeMux |
| PathValue | captured segment from the match |
| wildcard | `{name...}` captures the rest of the path |
| literal | fixed segment that beats value when more specific |
| Register | package function that mounts routes on the passed mux |
| DefaultServeMux | global mux behind `http.Handle` — avoid in lib |
| 405 | method not allowed — path exists, method does not |

## Final orientation

If you can explain why `PathValue` is not validation, why 405 is not a regression, and why metrics use route templates — you know this lesson. The code is short; the discipline is long.

## Mechanism (deepening): lab matrix route × status × metric

For every route in the service keep a table (spreadsheet or ADR addendum):

| Pattern | Authz | PathValue validation | Metric route label | OpenAPI |
|---------|-------|----------------------|---------------------|---------|
| GET /v1/orders/{id} | principal owns id | ord_ prefix | GET /v1/orders/{id} | yes |
| POST /v1/orders | authenticated | — | POST /v1/orders | yes |
| GET /healthz | none | — | GET /healthz | no |

Without a table, routes “appear” in a PR without ops and contract.

### httptest table-driven template

```go
tests := []struct {
	name   string
	method string
	path   string
	want   int
}{
	{"ok", http.MethodGet, "/v1/orders/ord_1", 200},
	{"bad method", http.MethodPost, "/v1/orders/ord_1", 405},
	{"missing", http.MethodGet, "/v1/nope", 404},
}
for _, tc := range tests {
	t.Run(tc.name, func(t *testing.T) {
		req := httptest.NewRequest(tc.method, tc.path, nil)
		rec := httptest.NewRecorder()
		mux.ServeHTTP(rec, req)
		if rec.Code != tc.want {
			t.Fatalf("got %d want %d", rec.Code, tc.want)
		}
	})
}
```

### CORS and OPTIONS note

If the gateway does CORS, do not duplicate OPTIONS on every route. If you must in Go: explicit `OPTIONS` patterns or middleware — document where it lives.

### Reverse proxy and path rewrite

Nginx `strip` `/api` before Go: patterns must see the path **after** rewrite. The most common 404 in staging is rewrite ↔ HandleFunc pattern mismatch.

```text
client: /api/v1/orders/1
proxy strip /api → /v1/orders/1
mux expects: GET /v1/orders/{id}  ✓
mux wrongly expects: GET /api/v1/orders/{id}  ✗
```

### Security review for path

1. IDOR on `{id}`  
2. Wildcard path traversal  
3. Too-wide SPA fallback  
4. Admin routes without authz  
5. Debug routes in prod binary (`/debug/pprof` consciously or not)

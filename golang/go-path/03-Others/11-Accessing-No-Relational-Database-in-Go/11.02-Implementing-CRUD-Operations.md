# 11.02 Implementing CRUD operations on MongoDB

> **Go Path - Zero to Gopher** / **03 Others → Accessing No-Relational Database in Go** / Lesson 11.02

## Lesson goals

After this lesson you should be able to:

- implement `InsertOne`, `FindOne`, `UpdateOne` (with `$set`), `DeleteOne` with the official driver
- read multiple documents via `Find` + `cursor.Decode` / `cursor.All` with `Close`
- map `mongo.ErrNoDocuments` to a clear application “not found” error
- check `MatchedCount`, `ModifiedCount`, `DeletedCount` instead of lying with HTTP 200
- write filters and update documents as `bson.D` / `bson.M` (structured data)
- create a unique index via `Indexes().CreateOne`
- shape a repository pattern around `*mongo.Collection`
- close module **03 Others** and return to the course index

## Prerequisite

- Lesson 11.01: `mongo.Connect`, `Ping`, `Database`, `Collection`, BSON, context timeout
- MongoDB available locally (Compose from 11.01)
- Go 1.22+; package `go.mongodb.org/mongo-driver`
- HTTP or CLI as a thin UI for exercises
- understanding of `errors.Is` and sentinel errors

## Problem this lesson solves

After connecting, without CRUD discipline typical incidents arise:

1. `FindOne` does not check `ErrNoDocuments` → 500 instead of 404
2. `UpdateOne` matches 0 documents, the API still returns 200 — the client thinks it saved
3. a “patch” without `$set` replaces or corrupts the document
4. `Find` without a limit pulls the Collection into memory
5. timeout is missing — a goroutine hangs after a network partition
6. filter built as a string — fragile and dangerous; here you learn **only** structured BSON filters

This lesson fixes the four basic operations, cursor, indexes, counters, and the repository contract — enough to build a store before aggregations and change streams.

## Mental model

```text
InsertOne(ctx, doc)           → InsertedID
FindOne(ctx, filter).Decode   → document or ErrNoDocuments
UpdateOne(ctx, filter, update)→ MatchedCount / ModifiedCount
DeleteOne(ctx, filter)        → DeletedCount
Find(ctx, filter)             → Cursor → Decode / All → Close
Indexes().CreateOne(...)      → unique / sort key
```

A filter is a **document** (`bson.M{"sku": sku}`), not a SQL WHERE string.

An update for a partial change uses operators — most often:

```go
bson.M{"$set": bson.M{"name": name, "cents": cents}}
```

Without `$set`, you easily do a wrong field replacement. For a patch in the API: **`$set`**.

Timeout: short on the request path (typically 1–5s), longer on batch. The repository takes `ctx` and adds `WithTimeout` as needed.

### Error mapping (mental table)

| Driver / result | Application | HTTP (typical) |
|-----------------|-------------|----------------|
| `ErrNoDocuments` | `ErrNotFound` | 404 |
| `MatchedCount == 0` | `ErrNotFound` | 404 |
| `DeletedCount == 0` | `ErrNotFound` | 404 |
| duplicate key | `ErrConflict` | 409 |
| `context.DeadlineExceeded` | timeout | 504 / 503 |
| other | wrap | 500 |

## Mechanism

The longest section: exact flow of each operation, traces, prediction → answer.

### 1. InsertOne

```go
res, err := coll.InsertOne(ctx, product)
if err != nil {
	return err // can be duplicate key if a unique index exists
}
id := res.InsertedID // often primitive.ObjectID
```

**Success trace:**

```text
InsertOne(ctx, doc)
  → marshal struct/M to BSON
  → OP_MSG insert
  → server assigns _id if missing
  → InsertOneResult{InsertedID}
```

**Prediction:** struct without `omitempty` on `_id` and with zero ObjectID — you can send an “empty” `_id`.

**Answer:** `bson:"_id,omitempty"` or explicitly `primitive.NewObjectID()` before insert.

**Prediction:** second insert of the same `sku` with a unique index.

**Answer:** server returns duplicate key; in newer driver check `mongo.IsDuplicateKeyError(err)` (or error labels) and map to 409.

### 2. FindOne + Decode

```go
var p Product
err := coll.FindOne(ctx, bson.M{"sku": sku}).Decode(&p)
if errors.Is(err, mongo.ErrNoDocuments) {
	return Product{}, ErrNotFound
}
if err != nil {
	return Product{}, err
}
return p, nil
```

**Hit trace:**

```text
FindOne(filter)
  → one document
  → Decode into &p (BSON → struct)
  → err == nil
```

**Miss trace:**

```text
FindOne(filter)
  → no document
  → Decode → mongo.ErrNoDocuments
  → map to ErrNotFound
```

**Prediction:** you ignore `ErrNoDocuments` → zero-value `Product` and `nil` error if you are not careful, or a raw 500 in the handler.

**Answer:** always `errors.Is(err, mongo.ErrNoDocuments)` before the generic error path.

The filter remains data:

```go
// sku comes from outside — enters as a value, not as query shape
filter := bson.M{"sku": sku}
// or when order matters:
filterD := bson.D{{Key: "sku", Value: sku}}
```

### 3. UpdateOne with `$set`

```go
res, err := coll.UpdateOne(ctx,
	bson.M{"_id": id},
	bson.M{"$set": bson.M{"name": name, "cents": cents}},
)
if err != nil {
	return err
}
if res.MatchedCount == 0 {
	return ErrNotFound
}
// ModifiedCount can be 0 if values are the same — that is not not found
```

**Trace:**

```text
UpdateOne(filter, {$set: {...}})
  → find document
  → apply $set to fields
  → MatchedCount=1, ModifiedCount=0|1
```

**Prediction:** `MatchedCount == 0`, but the handler returns 200.

**Answer:** treat `MatchedCount == 0` as not found. `ModifiedCount == 0` with a match = idempotent “already like that”.

**Prediction:** you send `UpdateOne(filter, bson.M{"name": name})` without `$set`.

**Answer:** behavior is not “patch as you think” — use explicit `$set` for partial changes. For full document replacement there is `ReplaceOne` — consciously.

### 4. DeleteOne

```go
res, err := coll.DeleteOne(ctx, bson.M{"_id": id})
if err != nil {
	return err
}
if res.DeletedCount == 0 {
	return ErrNotFound
}
return nil
```

**Trace:**

```text
DeleteOne({_id: id})
  → 0 or 1 deleted
  → DeletedCount
```

**Prediction:** `DeleteMany(bson.M{})` “for cleanup” on a shared database.

**Answer:** no. In tests use a separate database or a narrow filter. An empty filter on Many is a dangerous pattern.

### 5. Find + cursor

```go
opts := options.Find().SetLimit(limit).SetSort(bson.D{{Key: "sku", Value: 1}})
cur, err := coll.Find(ctx, bson.M{}, opts)
if err != nil {
	return nil, err
}
defer cur.Close(ctx)

var out []Product
if err := cur.All(ctx, &out); err != nil {
	return nil, err
}
return out, nil
```

Stream alternative:

```go
for cur.Next(ctx) {
	var p Product
	if err := cur.Decode(&p); err != nil {
		return nil, err
	}
	out = append(out, p)
}
if err := cur.Err(); err != nil {
	return nil, err
}
```

**All trace:**

```text
Find → Cursor
  → All loads all results into a slice
  → Close (defer)
```

**Prediction:** no `SetLimit` → huge collection → memory pressure.

**Answer:** hard cap (e.g. max 100) in the repository method, even if the caller asks for more.

**Prediction:** forgotten `Close` → cursor leak on the server.

**Answer:** `defer cur.Close(ctx)` immediately after a successful `Find`.

### 6. Indexes — `CreateOne`

```go
_, err := coll.Indexes().CreateOne(ctx, mongo.IndexModel{
	Keys:    bson.D{{Key: "sku", Value: 1}},
	Options: options.Index().SetUnique(true),
})
```

**Trace:**

```text
EnsureIndexes / CreateOne
  → creates unique index on sku
  → insert duplicate → duplicate key error
```

**Prediction:** the application “checks unique” with Find then Insert — race of two admins.

**Answer:** the unique index is the source of truth; the application check is only UX.

Call `EnsureIndexes` at start (idempotent-ish) or via a migration job. Do not rely on luck.

### 7. Repository pattern — isolation mechanism

```text
Handler
  → ProductRepo.BySKU(ctx, sku)
       → coll.FindOne + Decode
       → ErrNotFound | Product
  → HTTP 404 | 200 JSON
```

Repo:

- holds `*mongo.Collection` (or `*mongo.Database` + name)
- does not leak BSON details into the HTTP layer more than necessary
- defines `var ErrNotFound = errors.New("not found")`
- always takes `context.Context` first

```go
type ProductRepo struct {
	coll *mongo.Collection
}

func NewProductRepo(db *mongo.Database) *ProductRepo {
	return &ProductRepo{coll: db.Collection("products")}
}
```

### 8. Context timeout in repo methods

```go
func (r *ProductRepo) BySKU(ctx context.Context, sku string) (Product, error) {
	ctx, cancel := context.WithTimeout(ctx, 3*time.Second)
	defer cancel()
	// ...
}
```

**Mechanism:** even if someone passes `context.Background()`, the operation has an upper bound. If the parent (`r.Context()`) expires earlier, the earlier deadline is respected.

**Prediction:** timeout 1ms in a test.

**Answer:** you see `context.DeadlineExceeded` (often wrapped) — proof the brake works.

### 9. ObjectID on the CRUD path

```go
id, err := primitive.ObjectIDFromHex(hex)
if err != nil {
	return ErrInvalidID // → 400
}
res, err := coll.UpdateOne(ctx, bson.M{"_id": id}, update)
```

Filter by `_id` must be `ObjectID`, not a hex string — otherwise it does not match the document.

**Prediction:** `bson.M{"_id": hexString}` while the database has ObjectID.

**Answer:** `MatchedCount == 0` forever. Parse hex into `primitive.ObjectID`.

### 10. InsertedID type assert

```go
res, err := r.coll.InsertOne(ctx, p)
if err != nil {
	return p, err
}
oid, ok := res.InsertedID.(primitive.ObjectID)
if !ok {
	return p, fmt.Errorf("unexpected InsertedID type %T", res.InsertedID)
}
p.ID = oid
return p, nil
```

**Prediction:** blind `.(primitive.ObjectID)` panics if you ever change `_id` type.

**Answer:** comma-ok or a generic fallback.

### 11. Soft delete (orientation)

```go
// instead of DeleteOne — mark
_, err := coll.UpdateOne(ctx,
	bson.M{"_id": id, "deletedAt": bson.M{"$exists": false}},
	bson.M{"$set": bson.M{"deletedAt": time.Now().UTC()}},
)
// Find filter always adds: "deletedAt": bson.M{"$exists": false}
```

Same pattern as soft delete in GORM, but manual. For this lesson hard `DeleteOne` is enough; know the variant.

### 12. Cache invalidation next to Redis (link to 11.01)

After a successful `UpdateOne` / `DeleteOne`:

```go
_ = rdb.Del(ctx, "product:"+sku).Err()
```

Not part of Mongo CRUD, but the consistency mechanism of the read path: primary store first, then invalidate.

### 13. Aggregations — lesson boundary

`Collection.Aggregate` with `$match` / `$group` is not a substitute for CRUD. Learn Insert/Find/Update/Delete reliably before pipeline magic. This lesson stops at CRUD + index.

### 14. Transactions — lesson boundary

Multi-document transactions require a replica set. Local single `mongod` is often not enough without rs init. For basic CRUD exercises transactions are not required.

### 15. Full trace: HTTP GET → FindOne

```text
GET /products/{sku}
  → PathValue("sku")
  → repo.BySKU(r.Context(), sku)
       → WithTimeout(3s)
       → FindOne(bson.M{"sku": sku})
       → Decode
       → ErrNoDocuments? → ErrNotFound
  → errors.Is(ErrNotFound) → 404
  → else err → 500
  → else JSON 200
```

### 16. Full trace: HTTP PATCH → UpdateOne `$set`

```text
PATCH /products/{id}
  → ObjectIDFromHex
  → invalid? 400
  → UpdateOne({_id}, {$set: fields})
  → MatchedCount==0 → 404
  → OK 204 / 200
  → optionally Redis Del
```

## Rules and syntax

1. Every store method takes `ctx context.Context` as the first argument.
2. Filters and update: `bson.M` / `bson.D` — values as data; do not concatenate a “query”.
3. Partial change: always `$set` (or other explicit operators).
4. Check `ErrNoDocuments` on `FindOne`.
5. Check `MatchedCount` / `DeletedCount` when the API must distinguish not found.
6. Unique index on the business key (`sku`) before relying on luck.
7. `Find`: `SetLimit` + hard cap; `defer cursor.Close(ctx)`.
8. Do not do `DeleteMany` with an empty filter on a shared database.
9. Map duplicate key to conflict (409).
10. `_id` in the filter: `primitive.ObjectID`, not a raw hex string.
11. Timeout on the repo or strictly on the parent context — document the policy.
12. Test and prod: different database names.

### Syntax list

```go
coll.InsertOne(ctx, doc)
coll.FindOne(ctx, filter).Decode(&out)
coll.UpdateOne(ctx, filter, bson.M{"$set": fields})
coll.DeleteOne(ctx, filter)
cur, err := coll.Find(ctx, filter, opts)
cur.All(ctx, &slice)
cur.Decode(&one)
cur.Close(ctx)
coll.Indexes().CreateOne(ctx, model)
```

## Examples

### Example 1 — Model, repo, indexes, Insert

```go
package store

import (
	"context"
	"errors"
	"fmt"
	"time"

	"go.mongodb.org/mongo-driver/bson"
	"go.mongodb.org/mongo-driver/bson/primitive"
	"go.mongodb.org/mongo-driver/mongo"
	"go.mongodb.org/mongo-driver/mongo/options"
)

var (
	ErrNotFound = errors.New("not found")
	ErrConflict = errors.New("conflict")
)

type Product struct {
	ID    primitive.ObjectID `bson:"_id,omitempty" json:"id"`
	SKU   string             `bson:"sku" json:"sku"`
	Name  string             `bson:"name" json:"name"`
	Cents int                `bson:"cents" json:"cents"`
}

type ProductRepo struct {
	coll *mongo.Collection
}

func NewProductRepo(db *mongo.Database) *ProductRepo {
	return &ProductRepo{coll: db.Collection("products")}
}

func (r *ProductRepo) EnsureIndexes(ctx context.Context) error {
	ctx, cancel := context.WithTimeout(ctx, 10*time.Second)
	defer cancel()
	_, err := r.coll.Indexes().CreateOne(ctx, mongo.IndexModel{
		Keys:    bson.D{{Key: "sku", Value: 1}},
		Options: options.Index().SetUnique(true),
	})
	return err
}

func (r *ProductRepo) Insert(ctx context.Context, p Product) (Product, error) {
	ctx, cancel := context.WithTimeout(ctx, 3*time.Second)
	defer cancel()
	res, err := r.coll.InsertOne(ctx, p)
	if err != nil {
		if mongo.IsDuplicateKeyError(err) {
			return p, ErrConflict
		}
		return p, err
	}
	oid, ok := res.InsertedID.(primitive.ObjectID)
	if !ok {
		return p, fmt.Errorf("unexpected InsertedID type %T", res.InsertedID)
	}
	p.ID = oid
	return p, nil
}
```

#### Prediction

Two parallel inserts of the same SKU.

#### Answer

One succeeds, the other `ErrConflict` thanks to the unique index — not thanks to “check then write”.

### Example 2 — FindOne, UpdateOne, DeleteOne

```go
func (r *ProductRepo) BySKU(ctx context.Context, sku string) (Product, error) {
	ctx, cancel := context.WithTimeout(ctx, 3*time.Second)
	defer cancel()
	var p Product
	err := r.coll.FindOne(ctx, bson.M{"sku": sku}).Decode(&p)
	if errors.Is(err, mongo.ErrNoDocuments) {
		return p, ErrNotFound
	}
	return p, err
}

func (r *ProductRepo) ByID(ctx context.Context, id primitive.ObjectID) (Product, error) {
	ctx, cancel := context.WithTimeout(ctx, 3*time.Second)
	defer cancel()
	var p Product
	err := r.coll.FindOne(ctx, bson.M{"_id": id}).Decode(&p)
	if errors.Is(err, mongo.ErrNoDocuments) {
		return p, ErrNotFound
	}
	return p, err
}

func (r *ProductRepo) UpdateCents(ctx context.Context, id primitive.ObjectID, cents int) error {
	ctx, cancel := context.WithTimeout(ctx, 3*time.Second)
	defer cancel()
	res, err := r.coll.UpdateOne(ctx,
		bson.M{"_id": id},
		bson.M{"$set": bson.M{"cents": cents}},
	)
	if err != nil {
		return err
	}
	if res.MatchedCount == 0 {
		return ErrNotFound
	}
	return nil
}

func (r *ProductRepo) Delete(ctx context.Context, id primitive.ObjectID) error {
	ctx, cancel := context.WithTimeout(ctx, 3*time.Second)
	defer cancel()
	res, err := r.coll.DeleteOne(ctx, bson.M{"_id": id})
	if err != nil {
		return err
	}
	if res.DeletedCount == 0 {
		return ErrNotFound
	}
	return nil
}
```

#### What happens here

A single `ErrNotFound` for HTTP 404. `$set` changes only `cents`. Counters prevent a fake success.

#### Prediction

`UpdateCents` with the same `cents` as in the database → `MatchedCount=1`, `ModifiedCount=0`, `err=nil`.

#### Answer

That is success (idempotent), not 404.

### Example 3 — List with limit and sort

```go
func (r *ProductRepo) List(ctx context.Context, limit int64) ([]Product, error) {
	ctx, cancel := context.WithTimeout(ctx, 5*time.Second)
	defer cancel()
	if limit <= 0 || limit > 100 {
		limit = 50
	}
	opts := options.Find().
		SetLimit(limit).
		SetSort(bson.D{{Key: "sku", Value: 1}})
	cur, err := r.coll.Find(ctx, bson.M{}, opts)
	if err != nil {
		return nil, err
	}
	defer cur.Close(ctx)

	var out []Product
	if err := cur.All(ctx, &out); err != nil {
		return nil, err
	}
	return out, nil
}
```

#### Prediction

Caller sends `limit=1_000_000`.

#### Answer

Repo sets 50 (or max 100) — memory protection.

### Example 4 — List with `Next` + `Decode` (stream)

```go
func (r *ProductRepo) ListStream(ctx context.Context, limit int64) ([]Product, error) {
	ctx, cancel := context.WithTimeout(ctx, 5*time.Second)
	defer cancel()
	if limit <= 0 || limit > 100 {
		limit = 50
	}
	cur, err := r.coll.Find(ctx, bson.M{}, options.Find().SetLimit(limit))
	if err != nil {
		return nil, err
	}
	defer cur.Close(ctx)

	out := make([]Product, 0, limit)
	for cur.Next(ctx) {
		var p Product
		if err := cur.Decode(&p); err != nil {
			return nil, err
		}
		out = append(out, p)
	}
	return out, cur.Err()
}
```

#### When you choose All vs Next

- small result, simplicity → `All`
- large stream / transform per document → `Next` + `Decode`

### Example 5 — HTTP handler sketch

```go
func (h *Handlers) GetProduct(w http.ResponseWriter, r *http.Request) {
	sku := r.PathValue("sku")
	p, err := h.repo.BySKU(r.Context(), sku)
	if errors.Is(err, store.ErrNotFound) {
		http.Error(w, "not found", http.StatusNotFound)
		return
	}
	if err != nil {
		http.Error(w, "internal", http.StatusInternalServerError)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(p)
}

func (h *Handlers) PatchCents(w http.ResponseWriter, r *http.Request) {
	id, err := primitive.ObjectIDFromHex(r.PathValue("id"))
	if err != nil {
		http.Error(w, "bad id", http.StatusBadRequest)
		return
	}
	var body struct {
		Cents int `json:"cents"`
	}
	if err := json.NewDecoder(r.Body).Decode(&body); err != nil {
		http.Error(w, "bad json", http.StatusBadRequest)
		return
	}
	err = h.repo.UpdateCents(r.Context(), id, body.Cents)
	if errors.Is(err, store.ErrNotFound) {
		http.Error(w, "not found", http.StatusNotFound)
		return
	}
	if err != nil {
		http.Error(w, "internal", http.StatusInternalServerError)
		return
	}
	w.WriteHeader(http.StatusNoContent)
}
```

#### Trace of a canceled client

```text
client closes connection
  → r.Context() Done
  → FindOne/UpdateOne interrupts with ctx
```

Do not log the whole document if it has PII.

### Example 6 — Dynamic `$set` without gluing strings

When the API allows only some fields, you build a map in code:

```go
func (r *ProductRepo) Patch(ctx context.Context, id primitive.ObjectID, name *string, cents *int) error {
	ctx, cancel := context.WithTimeout(ctx, 3*time.Second)
	defer cancel()

	set := bson.M{}
	if name != nil {
		set["name"] = *name
	}
	if cents != nil {
		set["cents"] = *cents
	}
	if len(set) == 0 {
		return nil // nothing to change
	}

	res, err := r.coll.UpdateOne(ctx,
		bson.M{"_id": id},
		bson.M{"$set": set},
	)
	if err != nil {
		return err
	}
	if res.MatchedCount == 0 {
		return ErrNotFound
	}
	return nil
}
```

#### Why this is a safe pattern

The update document structure (`$set` + known keys) comes from your code. User values enter only as values of known keys. You do not build BSON “from a query string”.

### Example 7 — Filter with multiple conditions (`bson.D`)

```go
filter := bson.D{
	{Key: "cents", Value: bson.D{{Key: "$gte", Value: minCents}}},
	{Key: "name", Value: bson.D{{Key: "$regex", Value: "^F"}}}, // careful: user regex = ReDoS risk — allowlist/prefix
}
cur, err := coll.Find(ctx, filter, options.Find().SetLimit(50))
```

For an ordinary catalog by SKU stay on equality `bson.M{"sku": sku}`. You add operators as nested documents, not as a textual DSL the user writes.

### Example 8 — ReplaceOne vs UpdateOne (contrast)

```go
// replaces the whole document (keep _id in the filter)
_, err := coll.ReplaceOne(ctx, bson.M{"_id": id}, Product{
	SKU: "ABC", Name: "New", Cents: 100,
})

// patch
_, err = coll.UpdateOne(ctx, bson.M{"_id": id}, bson.M{
	"$set": bson.M{"name": "New"},
})
```

#### Prediction

Replace without all fields → you lose fields you did not send.

#### Answer

For REST PATCH prefer `UpdateOne` + `$set`.

## Decision analysis

### Timeout in repo vs only parent

Inner timeout protects from `Background()`. Downside: hides a longer parent deadline. Compromise `WithTimeout(ctx, d)` from the parent is acceptable if you document it.

### ReplaceOne vs UpdateOne+`$set`

Replace = whole document. `$set` = partial change. API patch → `$set`.

### Soft delete

Field `deletedAt` + filter on all Find — more discipline, audit trail. Hard delete simpler for exercises.

### `All` vs `Next`

`All` for small lists. `Next` when you stream or transform.

### Repository vs bare `*mongo.Collection` in the handler

Repo centralizes timeout, error mapping, indexes. Handler stays thin. For a micro script bare coll OK; for a service — repo.

### Counting ModifiedCount in the API

Rarely need to distinguish “same data” from “changed” at HTTP level. Not found = `MatchedCount`. Idempotent PUT can return 204 even when `ModifiedCount=0`.

## Trade-offs

| Approach | Gain | Cost |
|----------|------|------|
| Manual mongo-driver | Control, clear BSON | More code |
| ODM library | Faster writing | Another layer, magic |
| Large embed documents | One Find read | Harder partial update |
| Small documents + references | Normalization | More round-trips |
| Unique index | Truth about uniqueness | Migration / duplicates on Create |
| Inner timeout | Brake | Can shorten parent |
| Soft delete | Audit, undo | Every query must filter |
| List without limit | “simple” | OOM / latency |

## Common mistakes

1. **Without checking `ErrNoDocuments`** — wrong status code.
2. **Update without `$set`** when you think you are doing a patch.
3. **Ignoring `MatchedCount` / `DeletedCount`** — fake 200.
4. **Find without a limit** — memory hit.
5. **Forgotten `cursor.Close`** — leak.
6. **`_id` filter as a string** instead of `ObjectID` — eternal miss.
7. **DeleteMany with too wide a filter** — data loss.
8. **Unique only in the application** without an index — race.
9. **Ignoring duplicate key** — 500 instead of 409.
10. **Same URI/database for test and prod**.
11. **Connect per request** (regression from 11.01) inside CRUD handlers.
12. **Regex filter from raw user input** without limits — DoS on CPU; prefer exact equality or a strictly limited prefix.

## Practical scenario

A catalog API returns **200** on PATCH of a non-existent ID because nobody looked at `MatchedCount`. The mobile app caches “success” and shows the old price as new. Incident:

```text
PATCH /products/66f...  (id deleted yesterday)
  → UpdateOne → MatchedCount=0
  → handler ignores → 200
  → app: “saved”
```

Fix:

1. `MatchedCount == 0` → `ErrNotFound` → 404
2. a test that deletes then patches
3. unique on `sku` catches race of two admins

## Summary

CRUD in the Mongo Go driver rests on `InsertOne`, `FindOne`, `UpdateOne`, `DeleteOne`, BSON filters as data, `$set` for patch, `Find`+cursor (`Decode`/`All`/`Close`), counters `MatchedCount`/`DeletedCount`, unique indexes via `CreateOne`, and `context` timeouts. Map `ErrNoDocuments` and duplicate key into clear application errors. The repository keeps the driver behind a clean API.

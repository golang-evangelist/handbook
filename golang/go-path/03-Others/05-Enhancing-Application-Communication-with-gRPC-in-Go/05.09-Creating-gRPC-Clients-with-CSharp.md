# 05.09 Creating gRPC Clients with CSharp

> **Go Path - Zero to Gopher** / **03 Others → Enhancing Application Communication with gRPC in Go** / Lesson 05.09

## Lesson goals

After this lesson you should be able to:

- open a `GrpcChannel`
- create a typed client (`InventoryClient` / `CatalogClient`)
- set a deadline
- catch `RpcException` and read `StatusCode`
- propagate metadata (`x-request-id`, auth)
- reuse the channel (DI singleton pattern)
- compare with Go `NewClient` and Java blocking stub

## Prerequisite

- 05.08 C# server or Go/Java server on the same proto
- .NET 8 preferred
- 05.02 glossary (status, deadline, metadata)

## Problem this lesson solves

C# clients mix HTTP `HttpClient` habits with gRPC, forget the deadline, open a new `GrpcChannel` per call, and catch `Exception` instead of `RpcException` — so the dashboard never sees StatusCode.

## Mental model

```text
GrpcChannel.ForAddress(target)
  → new Inventory.InventoryClient(channel)   // stub
       → GetStockAsync(req, deadline, headers)
            → GetStockResponse
            OR RpcException(StatusCode)
  → Dispose channel when the host shuts down
```

| C# | Go | Java |
|----|----|------|
| GrpcChannel | ClientConn via NewClient | ManagedChannel |
| InventoryClient | NewInventoryClient | BlockingStub |
| deadline: DateTime | context.WithTimeout | withDeadlineAfter |
| RpcException | status.FromError | StatusRuntimeException |

## Mechanism

### Basic call

```csharp
using var channel = GrpcChannel.ForAddress("http://127.0.0.1:50051");
var client = new Inventory.InventoryClient(channel);

try
{
  var resp = await client.GetStockAsync(
      new GetStockRequest { Sku = "A" },
      deadline: DateTime.UtcNow.AddMilliseconds(200));
  Console.WriteLine(resp.Quantity);
}
catch (RpcException ex)
{
  Console.WriteLine($"{ex.StatusCode}: {ex.Status.Detail}");
}
```

### Catalog SayHello

```csharp
var catalog = new Catalog.CatalogClient(channel);
var reply = await catalog.SayHelloAsync(
    new HelloRequest { Name = "Ana" },
    deadline: DateTime.UtcNow.AddMilliseconds(800));
Console.WriteLine(reply.Message);
```

### Metadata

```csharp
var headers = new Metadata
{
  { "x-request-id", rid },
  { "authorization", "Bearer " + token },
};
var resp = await client.GetStockAsync(
    new GetStockRequest { Sku = sku },
    headers: headers,
    deadline: DateTime.UtcNow.AddMilliseconds(200));
```

### Success trace

```text
ForAddress
GetStockAsync
  → HTTP/2 HEADERS + DATA
  → response Quantity
  → StatusCode.OK (no exception)
```

### Error trace

```text
GetStockAsync sku=""
  → server InvalidArgument
  → RpcException
  → ex.StatusCode == StatusCode.InvalidArgument
```

**Predict:** `catch (Exception)` without RpcException.  
**Answer:** you lose StatusCode branching; metrics lie.

**Predict:** a new `GrpcChannel` inside a `foreach` 10_000 times.  
**Answer:** latency and socket pressure — reuse.

## Rules and syntax

1. Reuse `GrpcChannel` (often a singleton in DI).  
2. Always set a deadline (or an inherited CancellationToken with a timeout).  
3. `RpcException` for the code.  
4. Metadata for rid/auth — lowercase convention.  
5. Same proto as the server.  
6. `Dispose` / host lifetime tears down the channel.  
7. Lab cleartext HTTP/2 may need extra .NET settings — check the docs (uncertainty by SDK version).  
8. Do not log the bearer.  
9. Map StatusCode → domain error.  
10. Prefer async on the ASP.NET request path.  
11. Do not mix REST `HttpClient` JSON with a gRPC stub under the same “URL” mental model.  
12. Retry only by the matrix (Unavailable on read).

## Examples

### Example 1 — NotFound branch

```csharp
catch (RpcException ex) when (ex.StatusCode == StatusCode.NotFound)
{
  return Results.NotFound();
}
```

#### What happens here

The `when` filter matches an `RpcException` whose `StatusCode` is `NotFound`. The body returns `Results.NotFound()`, an HTTP 404 from this minimal API handler. Other gRPC status codes do not enter this catch. The branch follows the status code, which is the stable contract across servers.

### Example 4 — DI

```csharp
builder.Services.AddSingleton(_ => GrpcChannel.ForAddress(builder.Configuration["Inventory:Url"]!));
builder.Services.AddSingleton(sp =>
    new Inventory.InventoryClient(sp.GetRequiredService<GrpcChannel>()));
```

#### What happens here

The first `AddSingleton` creates one `GrpcChannel` from the configuration value `Inventory:Url`. The `!` asserts that URL string is non-null for the compiler. The second `AddSingleton` builds one `Inventory.InventoryClient` on that same channel, resolved from the service provider. Handlers inject the client and share the channel across requests.

### Example 5 — deadline lab

Server `Task.Delay(500)`, client 100ms → `DeadlineExceeded`.

### Example 6 — CancellationToken

```csharp
await client.GetStockAsync(req, cancellationToken: ct);
```

#### What happens here

`GetStockAsync` sends `req` and forwards `ct` through the named argument `cancellationToken`. That token is the cancellation signal for this RPC. When `ct` already belongs to an HTTP request with a timeout, the gRPC call shares that budget. Canceling `ct` cancels the awaited call, and the server observes that cancellation on its own call context.

If `ct` comes from an HTTP request with timeout middleware, the budget travels with it.

### Example 7 — status detail

```csharp
ex.Status.Detail // message
ex.StatusCode     // enum
```

#### What happens here

`ex.Status.Detail` is the status message string, such as the text the server attached to the failure. `ex.StatusCode` is the gRPC code enum on the same `RpcException`. Branching and metrics use the enum (`NotFound`, `Unavailable`, and the rest). The detail string is the human-readable text that traveled with that code.

Code is a more stable contract than the Detail string.

## Decision analysis

| Choice | When |
|-------|------|
| ForAddress | default |
| custom handler | mTLS / special TLS |
| singleton channel | most worker/API |
| typed client singleton | often OK with the channel |
| transient client | if you want a thin wrapper; channel still singleton |

## Trade-offs

Channel lifecycle in DI must be clear. Cleartext HTTP/2 in the lab needs attention to .NET security defaults. Async everywhere improves readability with ASP.NET, but errors still go through RpcException.

## Common mistakes

1. Channel per request.  
2. No deadline.  
3. `catch (Exception)` instead of RpcException.  
4. Wrong `http`/`https` scheme.  
5. Forgotten dispose / lifetime.  
6. Retry burn on Create.  
7. Logging a secret from Metadata.  
8. Wrong generated client (stale proto).  
9. Mixing REST and gRPC.  
10. Ignoring StatusCode in metrics.  
11. `localhost` confusion — use `127.0.0.1` in the lab.  
12. Different keep/case expectation because you are looking at JSON — this is protobuf.

## Idiomatic Go (reminder)

```go
conn, err := grpc.NewClient("127.0.0.1:50051",
  grpc.WithTransportCredentials(insecure.NewCredentials()))
client := pb.NewInventoryClient(conn)
ctx, cancel := context.WithTimeout(context.Background(), 200*time.Millisecond)
defer cancel()
resp, err := client.GetStock(ctx, &pb.GetStockRequest{Sku: "A"})
```

C# `GrpcChannel` ≈ channel; `InventoryClient` ≈ stub; `deadline` ≈ ctx timeout.

## Practical scenario

A .NET worker calls Go Catalog `SayHello` as a ping and Inventory `GetStock` before a campaign. First version: `ForAddress` in a loop — p95 climbs. Refactor: singleton channel, 200ms deadline, metrics by StatusCode, rid in Metadata. Incident: `http://` toward a TLS server — fixed the scheme.

## Mechanism (deep dive): mapping to HTTP BFF

```csharp
catch (RpcException ex)
{
  return ex.StatusCode switch
  {
    StatusCode.InvalidArgument => Results.BadRequest(),
    StatusCode.NotFound => Results.NotFound(),
    StatusCode.Unauthenticated => Results.Unauthorized(),
    StatusCode.PermissionDenied => Results.Forbid(),
    StatusCode.DeadlineExceeded => Results.StatusCode(504),
    StatusCode.Unavailable => Results.StatusCode(503),
    _ => Results.StatusCode(500),
  };
}
```

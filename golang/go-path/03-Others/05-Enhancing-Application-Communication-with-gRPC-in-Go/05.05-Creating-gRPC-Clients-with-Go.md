# 05.05 Creating gRPC Clients with Go

> **Go Path - Zero to Gopher** / **03 Others → Enhancing Application Communication with gRPC in Go** / Lesson 05.05

## Lesson goals

After this lesson you should be able to:

- open a connection via `grpc.NewClient` (preferred over the older `Dial`)
- create a stub (`NewCatalogClient` / `NewInventoryClient`)
- set a timeout via `context`
- read status from an error
- propagate metadata (request id, auth)
- reuse one conn per process

## Prerequisite

- 05.04 server runs locally (or bufconn in a test)
- 05.02 glossary

## Problem this lesson solves

Clients without a timeout and without status parsing treat everything as fatal. `Dial` per request kills performance. Older tutorials teach only `Dial` — this course prefers `NewClient`.

## Mental model

```text
grpc.NewClient(target, opts...) → ClientConn (channel)
  → New*Client(conn) → stub
       → WithTimeout(ctx)
            → RPC
                 → reply OR status error
  → Close() on process shutdown
```

## Mechanism

### Preferred form

```go
conn, err := grpc.NewClient("127.0.0.1:50051",
	grpc.WithTransportCredentials(insecure.NewCredentials()))
if err != nil {
	log.Fatal(err)
}
defer conn.Close()

client := pb.NewInventoryClient(conn)

ctx, cancel := context.WithTimeout(context.Background(), time.Second)
defer cancel()

resp, err := client.GetStock(ctx, &pb.GetStockRequest{Sku: "A"})
if err != nil {
	st, _ := status.FromError(err)
	log.Printf("code=%v msg=%s", st.Code(), st.Message())
	return
}
log.Printf("qty=%d", resp.GetQuantity())
```

### Catalog SayHello

```go
client := demopb.NewCatalogClient(conn)
ctx, cancel := context.WithTimeout(context.Background(), 800*time.Millisecond)
defer cancel()
reply, err := client.SayHello(ctx, &demopb.HelloRequest{Name: "Ana"})
```

### Trace

```text
NewClient OK (object created)
SayHello(ctx)
  → connect if needed
  → HTTP/2 stream /demo.v1.Catalog/SayHello
  → HelloReply OR codes.*
```

**Predict:** `NewClient` success means the server is up.  
**Answer:** no. The first RPC can be `Unavailable`.

### Metadata out

```go
md := metadata.Pairs("x-request-id", RequestIDFrom(ctx), "authorization", "Bearer "+tok)
ctx = metadata.NewOutgoingContext(ctx, md)
```

### Parent ctx from HTTP

```go
func (h *Handler) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	ctx, cancel := context.WithTimeout(r.Context(), 800*time.Millisecond)
	defer cancel()
	reply, err := h.catalog.SayHello(ctx, &demopb.HelloRequest{Name: r.URL.Query().Get("n")})
	_ = reply
	_ = err
}
```

When the HTTP client aborts, cancellation propagates downward.

## Rules and syntax

1. Always a timeout `ctx` (or an inherited deadline).  
2. `Close` the conn on process shutdown — not per RPC.  
3. `status.FromError` / `status.Code` for branching.  
4. `insecure` only in the lab.  
5. Propagate request id MD.  
6. Do not `NewClient`/`Dial` on every request.  
7. Follow the docs: `NewClient` preferred; `Dial` older.  
8. `defer cancel()` immediately after `WithTimeout`.  
9. Target `127.0.0.1` in the lab because of IPv6 confusion with `localhost`.  
10. WaitForReady optional for startup race — use deliberately.

## Examples

### Example 1 — reuse

One `conn` in `main`, stub in a struct, HTTP handlers share the stub.

### Example 2 — NotFound branch

```go
if status.Code(err) == codes.NotFound {
	// UX: no sku
}
```

#### What happens here

`status.Code` reads the gRPC status code carried on the RPC error. The branch runs when that code equals `codes.NotFound`, the missing-sku result sent by the server. The comment marks the UX for that case. Any other code fails the comparison and remains for the caller to handle.

### Example 3 — Unavailable

Stop the server; the client sees Unavailable — limited retry.

### Example 4 — CallOptions

```go
reply, err := client.SayHello(ctx, req, grpc.WaitForReady(true))
```

#### What happens here

`grpc.WaitForReady(true)` is a per-call option on this `SayHello`. While the channel is not ready, the RPC waits until the connection becomes ready or the deadline on `ctx` expires. The option applies only to this call, so other RPCs on the same stub keep their own options. The lesson treats it as a deliberate choice for a startup race, together with a real timeout on `ctx`.

### Example 5 — Dial vs NewClient

Older code:

```go
grpc.Dial(target, grpc.WithInsecure()) // historical
```

#### What happens here

`grpc.Dial` is the older constructor, and the comment marks this call as historical. `grpc.WithInsecure()` configures that connection with TLS disabled. Current course code uses `grpc.NewClient` with `insecure.NewCredentials()` for the same lab setup. Whether `Dial` is deprecated in your module depends on the grpc minor version, which is why the lesson points at the release notes.

New course:

```go
grpc.NewClient(target, grpc.WithTransportCredentials(insecure.NewCredentials()))
```

#### What happens here

`grpc.NewClient` creates a `ClientConn` for `target`. `WithTransportCredentials(insecure.NewCredentials())` installs credentials that leave TLS disabled, which is the lab form of this call. The value it returns is the connection later stubs are built from and that the process closes on shutdown. A successful return creates that client object; the server is contacted when an RPC actually runs.

Read the release notes for your grpc version (uncertainty: the deprecation wave depends on the minor version).

## Decision analysis

| Choice | When |
|--------|------|
| insecure | local lab only |
| TLS creds | everything else |
| conn per request | anti-pattern |
| WaitForReady | startup / rolling |
| service config retry | advanced; learn before enabling |

## Trade-offs

One long-lived conn is efficient; it requires understanding LB, keepalive, and reconnect. Overly aggressive retry burns Downstream.

## Common mistakes

1. Dial/NewClient every time.  
2. No `cancel`.  
3. Ignoring status.  
4. Hardcoded host without config.  
5. Retry burn on Create.  
6. Logging a secret token from MD.  
7. `localhost` vs IPv6 confusion.  
8. Timeout 0 / Background forever.  
9. Mixing local `errors.New` with an RPC err.  
10. Forgotten `Close` in short-lived CLI rescue scripts (less critical) vs servers (critical FD leak).

## Idiomatic Go

```go
type CatalogAPI struct {
```

## Practical scenario

An API gateway first opens a new Dial per HTTP request — TIME_WAIT explodes. Refactor: conn in `main`, stub in a struct, `WithTimeout(parent, 800ms)`. InvalidArgument does not retry; Unavailable gets a limited retry. Metrics by code.

## Mechanism (deep dive): grpc.NewClient vs Dial — what exactly you prefer

In modern gRPC-Go, `grpc.NewClient` is the preferred way to get a `ClientConn`. Older tutorials and blogs still show `grpc.Dial` / `DialContext`. The course does not forbid reading legacy code, but **new code you write uses `NewClient`**.

### What NewClient guarantees (and what it does not)

```go
conn, err := grpc.NewClient("127.0.0.1:50051",
	grpc.WithTransportCredentials(insecure.NewCredentials()))
```

- Returns a `ClientConn` object; an error here is rare (bad target/option), not “server down”.
- It does **not** guarantee that TCP is already established at return time.
- The first RPC (or an explicit idle→ready transition) starts the connect.

**Predict:** after `NewClient` with no error you think the server is up.  
**Answer:** the server can be down; you will see `Unavailable` on the first RPC.

**Predict:** `Dial` in a loop per HTTP request.  
**Answer:** the same anti-pattern as a new channel per request — expensive and slow.

### Trace: server down

```text
NewClient → OK
SayHello(ctx)
  → connect attempt
  → connection refused
  → err, codes.Unavailable
```

### Trace: successful SayHello

```text
NewClient → OK
stub := NewCatalogClient(conn)
ctx, cancel := WithTimeout(..., 800ms)
SayHello(ctx, {name:Ana})
  → HTTP/2 /demo.v1.Catalog/SayHello
  → HelloReply
  → cancel()
```

## Mechanism (deep dive): Catalog three RPCs on the client

Assume generated `demopb` from the same proto as the server (show the proto in your notes; do not invent that it “just works” without a contract).

```protobuf
service Catalog {
  rpc SayHello(HelloRequest) returns (HelloReply);
  rpc List(ListRequest) returns (stream Item);
  rpc Upload(stream UploadChunk) returns (UploadSummary);
}
```

### Unary

```go
reply, err := client.SayHello(ctx, &demopb.HelloRequest{Name: name})
```

### Server-stream List

```go
stream, err := client.List(ctx, &demopb.ListRequest{PageSize: 10})
for {
	item, err := stream.Recv()
	if errors.Is(err, io.EOF) {
		break
	}
	if err != nil {
		return err
	}
	// use item
}
```

### Client-stream Upload

```go
stream, err := client.Upload(ctx)
for _, chunk := range chunks {
	if err := stream.Send(&demopb.UploadChunk{Data: chunk}); err != nil {
		return err
	}
}
sum, err := stream.CloseAndRecv()
```

Forgotten `CloseAndRecv` / `CloseSend` = server waits.

## Mechanism (deep dive): timeout travels downward

```go
ctx, cancel := context.WithTimeout(parent, 200*time.Millisecond)
defer cancel()
resp, err := inv.GetStock(ctx, req)
```

If the HTTP handler has `r.Context()` and you create a **new** `context.Background()` with 30s — you break the cancel chain when the user closes the tab.

```text
HTTP abort
  → r.Context done
  → gRPC ctx done   // ONLY if you passed parent
  → server sees cancel
```

**Predict:** wrapper API always takes `context.Background()`.  
**Answer:** BFF cannot cancel upstream; goroutine leaks on shutdown.

## Mechanism (deep dive): status.FromError discipline

```go
st, ok := status.FromError(err)
if !ok {
	// transport / ctx error outside the status model — still log
	return err
}
switch st.Code() {
case codes.InvalidArgument:
	// do not retry
case codes.Unavailable:
	// limited retry
case codes.DeadlineExceeded:
	// metric + budget
}
```

Do not parse the `err.Error()` string as a contract. `Message()` is for humans; `Code()` is for machines.

## Mechanism (deep dive): WaitForReady

```go
resp, err := client.GetStock(ctx, req, grpc.WaitForReady(true))
```

Without WaitForReady, the RPC can fail quickly while the channel is in TransientFailure (e.g. startup). With WaitForReady it waits for Ready or the deadline. Use deliberately during rolling deploy; not as the default for every call forever.

## Mechanism (deep dive): metadata outbound


## Mechanism (deep dive): one conn in an HTTP service

```go
type API struct {
	catalog demopb.CatalogClient
}

func main() {
	conn, err := grpc.NewClient(target, grpc.WithTransportCredentials(insecure.NewCredentials()))
	// handle err
	defer conn.Close()
	api := &API{catalog: demopb.NewCatalogClient(conn)}
	// http server uses api
}
```

The stub is cheap; the conn is expensive. On graceful HTTP shutdown, close the conn too.

## Mechanism (deep dive): connectivity intuition

States (simplified): Idle → Connecting → Ready → TransientFailure → Shutdown. For the course: do not write your own reconnect state machine before you understand that the runtime already retries; your responsibilities are timeout, retry policy by code, and Close.

## Mechanism (deep dive): wrapper API and metric by code

```go
type CatalogAPI struct{ c demopb.CatalogClient }

func (a *CatalogAPI) Hello(ctx context.Context, name string) (string, error) {
	ctx, cancel := context.WithTimeout(ctx, 800*time.Millisecond)
	defer cancel()
	r, err := a.c.SayHello(ctx, &demopb.HelloRequest{Name: name})
	if err != nil {
		st, _ := status.FromError(err)
		metrics.Inc("grpc_client", st.Code().String())
		return "", err
	}
	return r.GetMessage(), nil
}
```

A default timeout in the wrapper prevents forgetting. Metric by code, not by `err != nil` bool.

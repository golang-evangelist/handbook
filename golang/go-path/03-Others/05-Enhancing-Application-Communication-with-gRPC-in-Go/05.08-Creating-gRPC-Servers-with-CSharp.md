# 05.08 Creating gRPC Servers with CSharp

> **Go Path - Zero to Gopher** / **03 Others → Enhancing Application Communication with gRPC in Go** / Lesson 05.08

## Lesson goals

After this lesson you should be able to:

- set up a Grpc.AspNetCore project
- implement a service class over the generated `*Base`
- map the service via `MapGrpcService`
- return `RpcException` with `StatusCode`
- compare with Go `Register*Server` and Java `ServerBuilder`

## Prerequisite

- 05.07
- .NET 8 preferred
- the same `.proto`

## Problem this lesson solves

C# teams expect the ASP.NET pipeline; they need a clear bridge to gRPC without mixing it with MVC JSON and without forgetting HTTP/2 on Kestrel.

## Mental model

```text
.proto + Grpc.Tools (csproj)
  → Inventory.InventoryBase (generated)
  → class InventoryService : InventoryBase
  → builder.Services.AddGrpc()
  → app.MapGrpcService<InventoryService>()
  → Kestrel HTTP/2
```

Go counterpart: `RegisterInventoryServer`. Java: `ServerBuilder.addService`.

## Mechanism

### csproj Protobuf

```xml
<ItemGroup>
  <Protobuf Include="Protos\inventory.proto" GrpcServices="Server" />
</ItemGroup>
<PackageReference Include="Grpc.AspNetCore" Version="2.62.0" />
```

Pin versions; the number is illustrative.

### Service + MapGrpcService

```csharp
public class InventoryService : Inventory.InventoryBase
{
  public override Task<GetStockResponse> GetStock(
      GetStockRequest request, ServerCallContext context)
  {
    if (string.IsNullOrEmpty(request.Sku))
      throw new RpcException(new Status(StatusCode.InvalidArgument, "sku required"));

    context.CancellationToken.ThrowIfCancellationRequested();

    return Task.FromResult(new GetStockResponse
    {
      Sku = request.Sku,
      Quantity = 3
    });
  }
}

// Program.cs
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddGrpc();
var app = builder.Build();
app.MapGrpcService<InventoryService>();
app.Run();
```

### Catalog SayHello

```csharp
public override Task<HelloReply> SayHello(HelloRequest request, ServerCallContext context)
{
  if (string.IsNullOrWhiteSpace(request.Name))
    throw new RpcException(new Status(StatusCode.InvalidArgument, "name required"));
  return Task.FromResult(new HelloReply { Message = $"zdravo, {request.Name}" });
}
```

### Trace

```text
Kestrel HTTP/2
  → MapGrpcService routing
  → InventoryService.GetStock
  → response OR RpcException(StatusCode)
```

**Predict:** Kestrel HTTP/1.1 only.  
**Answer:** gRPC does not work properly. Enable HTTP/2.

**Predict:** `throw new Exception("x")` instead of RpcException.  
**Answer:** you lose a clean StatusCode (often Unknown).

## Rules and syntax

1. `Grpc.AspNetCore` package.  
2. `RpcException` + `StatusCode` for errors.  
3. Do not mix an HTTP JSON controller for the same RPC contract without reason.  
4. Kestrel HTTP/2.  
5. Same proto.  
6. Respect `ServerCallContext.CancellationToken` (deadline).  
7. Pin package versions.  
8. `GrpcServices="Server"` in csproj for server gen.  
9. Health optional (`MapGrpcHealthChecksService`).  
10. Lab plaintext vs prod TLS deliberately.

## Examples

### Example 1 — NotFound

```csharp
throw new RpcException(new Status(StatusCode.NotFound, "sku not found"));
```

#### What happens here

Throwing `RpcException` fails the ASP.NET Core gRPC call with an explicit status. The `Status` value carries `StatusCode.NotFound` and the detail `sku not found`. The framework writes that code and detail into the RPC trailers. The code matches Go `codes.NotFound` and Java `Status.Code.NOT_FOUND`.

### Example 2 — Go client to C#

Go `NewClient` + stub to a `MapGrpcService` server — polyglot proof.

### Example 3 — metadata

```csharp
var rid = context.RequestHeaders.GetValue("x-request-id");
```

#### What happens here

`context.RequestHeaders` holds the metadata that arrived with the RPC. `GetValue("x-request-id")` returns the correlation id sent under that key. The lowercase name matches the metadata convention used by the Go, Java, and Node clients in this module. When the header is absent, `GetValue` returns null and `rid` stays null.

### Example 4 — DI

The service goes through DI; inject a domain `StockService` into the constructor — counterpart of Go wire in main.

### Example 5 — graceful

ASP.NET host lifetime handles shutdown; still respect the cancel token in long RPCs.

## Trade-offs

ASP.NET hosting is rich in middleware; heavier than a Go binary. Payoff: one stack with the existing .NET team.

## Common mistakes

1. HTTP/1.1 only Kestrel.  
2. Ordinary Exception instead of RpcException.  
3. Wrong `GrpcServices` flag.  
4. Different package/proto.  
5. Ignoring CancellationToken.  
6. Mixing JSON camelCase assumptions with proto names.  
7. Reflection in prod without control.  
8. Blocking the thread pool with heavy sync IO without async.  
9. Auth middleware that breaks gRPC content-type.  
10. Port conflict with MVC without clear endpoint mapping.

## Mechanism (deep dive): MapGrpcService from Program.cs to the handler

A C# ASP.NET Core gRPC server is not a “separate process model” from the Kestrel HTTP server — it is Kestrel with HTTP/2 and generated base classes. `MapGrpcService<T>` registers routes of the form `/package.Service/Method` the same as Go `Register*Server`.

### Trace: successful SayHello

```text
1. webBuilder / WebApplication — Listen :50051 (HTTP/2)
2. services.AddGrpc()
3. app.MapGrpcService<CatalogService>()
4. client HTTP/2 POST /demo.v1.Catalog/SayHello
5. Kestrel demux → generated Catalog.CatalogBase.SayHello
6. your override implementation
7. return new HelloReply { Message = "..." }
8. trailers grpc-status:0
```

### Minimal proto (same contract as Go/Java)

```protobuf
syntax = "proto3";
package demo.v1;
option csharp_namespace = "Demo.V1";

service Catalog {
  rpc SayHello(HelloRequest) returns (HelloReply);
  rpc List(ListRequest) returns (stream Item);
  rpc Upload(stream UploadChunk) returns (UploadSummary);
}
```

Without this `.proto` and generate step there is no `Catalog.CatalogBase` — do not pretend a “full project” in a snippet without a contract.

### Implementation (sketch)

```csharp
public class CatalogService : Catalog.CatalogBase
{
    public override Task<HelloReply> SayHello(HelloRequest request, ServerCallContext context)
    {
        if (string.IsNullOrWhiteSpace(request.Name))
        {
            throw new RpcException(new Status(StatusCode.InvalidArgument, "name required"));
        }
        return Task.FromResult(new HelloReply { Message = $"Hello {request.Name}" });
    }
}
```

**Predict:** you forget `MapGrpcService<CatalogService>`.  
**Answer:** the client sees Unimplemented / connection behavior as if the method does not exist.

**Predict:** you throw an ordinary `Exception` instead of `RpcException`.  
**Answer:** the client often gets Unknown; you lose the semantic code.

## Mechanism (deep dive): DI and adapter to domain

```csharp
public class CatalogService : Catalog.CatalogBase
{
    private readonly ICatalogApp _app;
    public CatalogService(ICatalogApp app) => _app = app;

    public override async Task<HelloReply> SayHello(HelloRequest request, ServerCallContext context)
    {
        var msg = await _app.GreetAsync(request.Name, context.CancellationToken);
        return new HelloReply { Message = msg };
    }
}
```

The gRPC layer stays thin: input validation → domain → map errors to `StatusCode`. Same pattern as Go: do not put SQL in a generated override without a boundary.


## Mechanism (deep dive): List server-stream

```csharp
public override async Task List(
    ListRequest request,
    IServerStreamWriter<Item> responseStream,
    ServerCallContext context)
{
    foreach (var item in _store.Page(request.PageSize))
    {
        context.CancellationToken.ThrowIfCancellationRequested();
        await responseStream.WriteAsync(item);
    }
}
```

Trace:

```text
List RPC start
  → WriteAsync Item #1
  → WriteAsync Item #2
  → ...
  → complete stream
  → trailers OK
```

If you ignore `CancellationToken`, the client deadline will not stop the loop — the same bug as a Go `for` without `ctx.Done()`.

## Mechanism (deep dive): Upload client-stream

```csharp
public override async Task<UploadSummary> Upload(
    IAsyncStreamReader<UploadChunk> requestStream,
    ServerCallContext context)
{
    long n = 0;
    await foreach (var chunk in requestStream.ReadAllAsync(context.CancellationToken))
    {
        n += chunk.Data.Length;
    }
    return new UploadSummary { Bytes = n };
}
```

**Predict:** the client does not close the send side.  
**Answer:** `ReadAllAsync` waits; the deadline on the context is your protection.

## Mechanism (deep dive): HTTP/2 and cleartext in the lab

Kestrel for gRPC requires HTTP/2. In Docker/lab you often need it explicitly:

```csharp
builder.WebHost.ConfigureKestrel(o =>
{
    o.ListenAnyIP(50051, lo => lo.Protocols = HttpProtocols.Http2);
});
```

Cleartext HTTP/2 (h2c) is a lab convention; production uses TLS. .NET has security defaults — read the version documentation before you declare “works on my laptop” as prod ready.

| Profile | Typical |
|---------|---------|
| Lab | h2c :50051, no cert |
| Prod | HTTPS + HTTP/2, cert rotation |
| Dev proxy | watch HTTP/1.1 upgrade limbo |

## Mechanism (deep dive): StatusCode map aligned with Go

| C# StatusCode | Go codes | Semantics |
|---------------|----------|-----------|
| InvalidArgument | InvalidArgument | bad input |
| NotFound | NotFound | no resource |
| Unauthenticated | Unauthenticated | missing/bad auth |
| PermissionDenied | PermissionDenied | auth ok, no rights |
| Unavailable | Unavailable | temporary |
| DeadlineExceeded | DeadlineExceeded | timeout |
| ResourceExhausted | ResourceExhausted | quota/limit |
| Unimplemented | Unimplemented | method not registered |

Wire values are the same — that is why a Java blocking stub and a Go client read the same outcome against a C# server.

## Mechanism (deep dive): health and readiness

For an orchestrator:

- liveness: process is alive
- readiness: gRPC service can accept traffic (dependencies OK)

ASP.NET health checks can cover HTTP `/healthz`; for gRPC teams often also add the standard gRPC Health protocol if the mesh requires it. Do not confuse “Kestrel is listening” with “the database is up”.

## Mechanism (deep dive): interceptor / middleware caution

HTTP middleware that expects a JSON content-type can break gRPC. Test:

```text
grpcurl -plaintext localhost:50051 demo.v1.Catalog/SayHello
```

after every global middleware. Auth for gRPC works via metadata + interceptors, not via a cookie form login pipeline blindly pasted on.

## Mechanism (deep dive): CancellationToken = context

`ServerCallContext.CancellationToken` is the counterpart of Go `ctx`. Pass it into EF/HTTP/outbound gRPC. Ignoring it = zombie work after client cancel.

```text
client deadline
  → CT canceled
  → ThrowIfCancellationRequested in the loop
  → RPC stops
  → client DeadlineExceeded or Cancelled
```

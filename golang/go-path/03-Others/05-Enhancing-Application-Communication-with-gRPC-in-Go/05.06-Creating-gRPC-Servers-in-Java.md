# 05.06 Creating gRPC Servers in Java

> **Go Path - Zero to Gopher** / **03 Others → Enhancing Application Communication with gRPC in Go** / Lesson 05.06

## Lesson goals

After this lesson you should be able to:

- sketch Gradle/Maven proto generation
- implement `*ImplBase`
- start a server via `ServerBuilder`
- return errors via `Status` + `StreamObserver`
- compare the exact Go counterpart (`Register*Server` + `status.Error`)

## Prerequisite

- 05.05
- Java 17+ preferred
- the same `.proto` as Go (Catalog or Inventory)
- 05.03 generate discipline

## Problem this lesson solves

Java teams get a proto from the Go team without a clear picture of how to wire generation into Gradle and how `Status` maps to Go `codes`. Without the `ServerBuilder` pattern people wander into Spring magic before they understand RPC.

## Mental model

```text
.proto
  → protobuf-gradle-plugin / protoc
  → InventoryGrpc.InventoryImplBase (or CatalogImplBase)
  → override methods (StreamObserver)
  → ServerBuilder.forPort(...).addService(...).build().start()
```

Go counterpart:

```text
Unimplemented* + methods (resp, err) → Register*Server → Serve
```

### InventoryService + ServerBuilder

```java
class InventoryService extends InventoryGrpc.InventoryImplBase {
  @Override
  public void getStock(GetStockRequest req, StreamObserver<GetStockResponse> obs) {
    if (req.getSku().isEmpty()) {
      obs.onError(Status.INVALID_ARGUMENT
          .withDescription("sku required")
          .asRuntimeException());
      return;
    }
    // ... lookup
    obs.onNext(GetStockResponse.newBuilder()
        .setSku(req.getSku())
        .setQuantity(3)
        .build());
    obs.onCompleted();
  }
}

Server server = ServerBuilder.forPort(50051)
    .addService(new InventoryService())
    .build()
    .start();
server.awaitTermination();
```

### Catalog SayHello

```java
class CatalogService extends CatalogGrpc.CatalogImplBase {
  @Override
  public void sayHello(HelloRequest req, StreamObserver<HelloReply> obs) {
    if (req.getName().isBlank()) {
      obs.onError(Status.INVALID_ARGUMENT.withDescription("name required").asRuntimeException());
      return;
    }
    obs.onNext(HelloReply.newBuilder().setMessage("zdravo, " + req.getName()).build());
    obs.onCompleted();
  }
}
```

### Trace of unary success

```text
ServerBuilder.start
  → RPC getStock
  → onNext(response)
  → onCompleted
  → client sees OK + body
```

### Trace of error

```text
getStock sku=""
  → onError(INVALID_ARGUMENT)
  → do NOT call onCompleted after onError
```

**Predict:** you forget `onCompleted` after `onNext`.  
**Answer:** client hangs / incomplete unary.

**Predict:** you throw a bare `RuntimeException` without `Status`.  
**Answer:** often `UNKNOWN` on the wire — you lose semantics.

### Go counterpart

```go
func (s *server) GetStock(ctx context.Context, req *pb.GetStockRequest) (*pb.GetStockResponse, error) {
	if req.GetSku() == "" {
		return nil, status.Error(codes.InvalidArgument, "sku required")
	}
	return &pb.GetStockResponse{Sku: req.GetSku(), Quantity: 3}, nil
}
```

## Rules and syntax

1. Same `.proto`; do not invent Java-only fields outside the contract.  
2. Unary success: `onNext` + `onCompleted`.  
3. Error: `onError` with `Status.*.asRuntimeException()`.  
4. Pin grpc versions.  
5. `shutdown()` / `shutdownNow()` on shutdown.  
6. Explanation in Serbian; identifiers in English.  
7. Compare the code with Go `codes.*`.  
8. Do not block the Netty thread with heavy CPU without offload.  
9. TLS: `ServerBuilder.useTransportSecurity` outside the lab.  
10. Deadline: respect `Context` cancellation in long calls.

## Examples

### Example 1 — NOT_FOUND

```java
obs.onError(Status.NOT_FOUND.withDescription("sku not found").asRuntimeException());
```

#### What happens here

The handler finishes the RPC by calling `onError` on the `StreamObserver`. `Status.NOT_FOUND` is the status code, `withDescription` sets the message to `sku not found`, and `asRuntimeException` wraps that status into the throwable `onError` accepts. On the wire this is the same code as Go `codes.NotFound`. `onError` is the error terminal for this call.

Same code as `codes.NotFound`.

### Example 2 — Maven

`protobuf-maven-plugin` instead of Gradle — same gen result, different XML.

### Example 3 — graceful

```java
Runtime.getRuntime().addShutdownHook(new Thread(() -> {
  server.shutdown();
  try {
    server.awaitTermination(10, TimeUnit.SECONDS);
  } catch (InterruptedException e) {
    server.shutdownNow();
  }
}));
```

#### What happens here

`addShutdownHook` registers a thread the JVM runs as it exits. `server.shutdown()` stops new RPCs and lets calls already on the server finish, which is the Java counterpart of Go `GracefulStop`. `awaitTermination(10, TimeUnit.SECONDS)` waits up to ten seconds for that drain. If the wait throws `InterruptedException`, `shutdownNow()` cancels what is still running.

Counterpart of `GracefulStop`.

## Decision analysis

| Choice | When |
|--------|------|
| Gradle + protobuf plugin | modern JVM |
| Maven plugin | legacy corporate |
| netty-shaded | fewer dependency conflicts |
| plain ServerBuilder | learning / small service |
| grpc-spring-boot-starter | later, once you understand the basics |

## Trade-offs

The Java ecosystem is heavier; builds are longer. The payoff for existing JVM services is huge. Spring hides `ServerBuilder` — learn the plain form first.

## Common mistakes

1. Forgotten `onCompleted`.  
2. Throwing a bare Exception.  
3. Different package from the agreed proto.  
4. Old grpc with a new proto.  
5. Blocking the event loop thread.  
6. No shutdown hook.  
7. Generating from a stale `.proto`.  
8. Both `onNext` + `onError`.  
9. Plaintext in prod.  
10. Mixing blocking work into an async observer without control.

## Idiomatic Go (reminder)

Go: `(resp, error)` + ctx. Java: `StreamObserver` + `Status`. Do not force Go style into Java; force the same code/deadline semantics.

## Practical scenario

A fraud team in Java implements Evaluate on the same proto. Go order calls it. Status codes match in the dashboard. First bug: forgotten `onCompleted` — Go client timeout. Second: `throw new Exception` → UNKNOWN.

# 05.10 Creating gRPC Server with Node.js

> **Go Path - Zero to Gopher** / **03 Others → Enhancing Application Communication with gRPC in Go** / Lesson 05.10

## Lesson goals

After this lesson you should be able to:

- choose `@grpc/grpc-js` (+ `@grpc/proto-loader` or static codegen)
- bring up a small server (`bindAsync` + `addService`)
- return gRPC status through the callback
- compare with Go `Register*Server`, Java `ServerBuilder`, C# `MapGrpcService`

## Problem this lesson solves

Node tutorials mix the old `grpc` package and the new `@grpc/grpc-js`. This course sticks to the modern stack. The callback idiom confuses people used to Go `(resp, err)`.

## Mental model

```text
load proto (loader) OR static gen
  → new grpc.Server()
  → addService(Service, impl)
  → bindAsync(addr, creds, cb)
  → start()
```

## Mechanism

### Dynamic loader (lab)

```javascript
const grpc = require('@grpc/grpc-js');
const loader = require('@grpc/proto-loader');

const def = loader.loadSync('inventory.proto', {
  keepCase: true,
  longs: String,
  enums: String,
  defaults: true,
  oneofs: true,
});
const pkg = grpc.loadPackageDefinition(def).inventory.v1;

const server = new grpc.Server();
server.addService(pkg.Inventory.service, {
  GetStock(call, callback) {
    if (!call.request.sku) {
      return callback({
        code: grpc.status.INVALID_ARGUMENT,
        message: 'sku required',
      });
    }
    callback(null, { sku: call.request.sku, quantity: 3 });
  },
});

server.bindAsync(
  '0.0.0.0:50051',
  grpc.ServerCredentials.createInsecure(),
  (err, port) => {
    if (err) throw err;
    server.start();
    console.log('listening', port);
  },
);
```

### Catalog SayHello

```javascript
server.addService(pkg.Catalog.service, {
  SayHello(call, callback) {
    const name = (call.request.name || '').trim();
    if (!name) {
      return callback({ code: grpc.status.INVALID_ARGUMENT, message: 'name required' });
    }
    callback(null, { message: `zdravo, ${name}` });
  },
  // List / Upload — stream handlers (03.04 style)
});
```

### Trace

```text
bindAsync OK
start
  → GetStock call
  → callback(null, resp)  // OK
  or callback({ code, message })
```

**Predict:** `server.start()` before the `bindAsync` callback.  
**Answer:** race / error. Wait for bind.

**Predict:** npm package `grpc` (legacy).  
**Answer:** avoid it; use `@grpc/grpc-js`.

## Rules and syntax

1. `@grpc/grpc-js`, not legacy `grpc`.  
2. `createInsecure` lab only.  
3. Error: `callback({ code: grpc.status.*, message })`.  
4. Document `keepCase` / loader options (field names).  
5. Same `.proto`.  
6. `bindAsync` before `start`.  
7. For larger projects: static codegen + TypeScript.  
8. Do not block the event loop with heavy sync CPU.  
9. Graceful: `tryShutdown`.  
10. Status enum aligned with Go codes.

## Examples

### Example 1 — NOT_FOUND

```javascript
callback({ code: grpc.status.NOT_FOUND, message: 'sku not found' });
```

#### What happens here

The unary handler ends the call by invoking `callback` with an error object. `grpc.status.NOT_FOUND` sets the not-found status, and `message` is the detail `sku not found`. That callback is the error completion for this handler. The code is the Node form of the same not-found status a Go server returns as `codes.NotFound`.

### Example 2 — static codegen sketch

```bash
grpc_tools_node_protoc --js_out=import_style=commonjs,binary:./gen \
  --grpc_out=grpc_js:./gen -I proto proto/inventory.proto
```

#### What happens here

`grpc_tools_node_protoc` compiles `proto/inventory.proto` into static JavaScript. `--js_out=import_style=commonjs,binary:./gen` writes the message classes as CommonJS modules under `./gen`. `--grpc_out=grpc_js:./gen` writes the `@grpc/grpc-js` service stubs into that same directory. `-I proto` is the import path the compiler uses to resolve the proto file.

More types, less runtime load.

### Example 3 — Go client toward Node

Polyglot: Node server, Go `NewClient`.

### Example 4 — metadata

```javascript
const rid = call.metadata.get('x-request-id')[0];
```

#### What happens here

`call.metadata` is the metadata received with this RPC. `get('x-request-id')` returns the list of values for that key, and `[0]` takes the first one as the correlation id. The key matches the name used by the Go, Java, and C# code in this module. If the client sent no such header, the list is empty and `rid` is `undefined`.

### Example 5 — tryShutdown

```javascript
process.on('SIGTERM', () => {
  server.tryShutdown(() => process.exit(0));
});
```

#### What happens here

The process listens for `SIGTERM`, the signal a process manager sends on stop. `server.tryShutdown` stops the server from accepting new RPCs and runs its callback once current calls have drained. That callback exits the process with status 0. This is the Node counterpart of Go `GracefulStop` for a lab server.

## Decision analysis

| Approach | When |
|---------|------|
| proto-loader | fast lab, small services |
| static codegen | larger / TypeScript |
| @grpc/grpc-js | always (modern) |

## Trade-offs

Loader is flexible, weaker types. Codegen the reverse. Callback style demands error discipline.

## Common mistakes

1. npm `grpc` old.  
2. `start` before `bindAsync`.  
3. Wrong package path from proto.  
4. `keepCase` surprises (`sku` vs `Sku`).  
5. No status code (string only).  
6. Blocking CPU in the handler.  
7. Different proto from Go.  
8. Insecure in prod.  
9. Forgotten callback.  
10. Mixing a Promise wrapper without mapping code.

## Idiomatic Go (reminder)

Go: `return nil, status.Error(...)`. Node: `callback({ code, message })`. Same semantics.

## Mechanism (deep dive): @grpc/grpc-js server — from loadProto to bind

The Node server in this course uses `@grpc/grpc-js` + `@grpc/proto-loader` (or static codegen). The dynamic loader is fast for the lab, but you must know the options (`keepCase`, `longs`, `enums`) because mismatch with Go/Java clients looks like an “undefined field”, not a nice compile error.

### Trace: SayHello OK

```text
1. protoLoader.loadSync("catalog.proto", options)
2. grpc.loadPackageDefinition(def)
3. server = new grpc.Server()
4. server.addService(pkg.demo.v1.Catalog.service, { SayHello, List, Upload })
5. server.bindAsync("0.0.0.0:50051", grpc.ServerCredentials.createInsecure(), cb)
6. client → /demo.v1.Catalog/SayHello
7. handler(call, callback)
8. callback(null, { message: "Hello Ana" })
```

### Proto (same contract)

```protobuf
syntax = "proto3";
package demo.v1;

service Catalog {
  rpc SayHello(HelloRequest) returns (HelloReply);
  rpc List(ListRequest) returns (stream Item);
  rpc Upload(stream UploadChunk) returns (UploadSummary);
}
message HelloRequest { string name = 1; }
message HelloReply { string message = 1; }
message ListRequest { int32 page_size = 1; }
message Item { string id = 1; string title = 2; }
message UploadChunk { bytes data = 1; }
message UploadSummary { int64 bytes = 1; }
```

### Unary handler

```js
function SayHello(call, callback) {
  const name = call.request.name;
  if (!name) {
    return callback({
      code: grpc.status.INVALID_ARGUMENT,
      message: "name required",
    });
  }
  callback(null, { message: `Hello ${name}` });
}
```

**Predict:** you call `callback` twice.  
**Answer:** undefined behavior / runtime crash — treat as a bug.

**Predict:** you `throw` instead of `callback({ code })`.  
**Answer:** often INTERNAL/Unknown instead of the desired code.

## Mechanism (deep dive): List server-stream in Node

```js
function List(call) {
  const items = store.page(call.request.page_size || 10);
  for (const item of items) {
    call.write(item);
  }
  call.end();
}
```

Trace:

```text
List start
  → write Item
  → write Item
  → end()
  → trailers OK
```

Check `call.cancelled` in long loops — counterpart of Go `ctx.Done()`.

## Mechanism (deep dive): Upload client-stream

```js
function Upload(call, callback) {
  let n = 0;
  call.on("data", (chunk) => { n += chunk.data.length; });
  call.on("end", () => {
    callback(null, { bytes: n });
  });
  call.on("error", (err) => { /* log */ });
}
```

**Predict:** no `end` handler.  
**Answer:** the unary response never starts; client hangs until deadline.

## Mechanism (deep dive): loader options that hurt

```js
const opts = {
  keepCase: true,   // or false — BUT align with clients
  longs: String,
  enums: String,
  defaults: true,
  oneofs: true,
};
```

If Go sends `page_size` and the loader renames it to `pageSize` without `keepCase` discipline, you read `undefined` and think the client is broken.

**Predict:** `keepCase: false` on the server, Go client generated with snake_case JSON names in the debug log.  
**Answer:** fields “disappear” in the handler.

Production: TLS credentials. Do not leave insecure “temporarily” forever behind a reverse proxy without a clear network boundary.

## Mechanism (deep dive): event loop and CPU

Node has one (main) event loop. Heavy sync CPU in `SayHello` raises p95 for every RPC. Offload or break up the work. Streaming large buffers without backpressure = memory spike.

**Predict:** `fs.readFileSync` of a huge file in the Upload `data` handler.  
**Answer:** you block the loop; other RPCs wait.

## Mechanism (deep dive): graceful try (intuition)

`server.tryShutdown(callback)` tries to finish active calls. In a container wire SIGTERM → tryShutdown → timeout → force. Same operational goal as Go `GracefulStop`.

```text
SIGTERM
  → tryShutdown
  → active List finishes or times out
  → process exit
```

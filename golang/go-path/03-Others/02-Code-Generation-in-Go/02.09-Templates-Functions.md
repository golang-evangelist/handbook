# 02.09 Templates: functions (FuncMap)

> **Go Path - Zero to Gopher** / **03 Others → Code Generation in Go** / Lesson 02.09

## Lesson goals

After this lesson you should be able to:

- register `template.FuncMap` via `Template.Funcs` **before** `Parse`;
- use built-in functions (`printf`, `len`, `index`, `slice`, `and`, `or`, `not`, `call`, …) deliberately;
- write your own codegen functions (identifiers, `export`, type mapping) that return an `error` when the input is invalid;
- read pipelines (`a | b`) as “last argument”;
- keep proportion: FuncMap for pure transformations, not for a hidden template ORM.

## Prerequisite

- 02.05–02.08 (dot, `$`, `if`/`with`, `range`, pipeline basics).
- Go 1.22+.
- `unicode`, `strings`, `fmt`, `strconv` for typical transformations.

## Problem this lesson solves

A template needs `json_name` → `GoName`, quoting, mapping `int64` → `int64`, joining paths. Without functions, the model balloons with thousands of prepared fields (`NameExported`, `NameQuoted`, `GoType`) or the same logic is copied into five templates.

FuncMap gives clean, unit-testable transformations. The cost: too much “magic” in the template makes review harder — you cannot see what `{{frob .X}}` does until you open another file. This lesson seeks the right measure for **codegen**.

## Mental model

```text
template.New("gen").Funcs(funcMap).Parse(tpl)
                 ^^^^
                 must be before Parse for that Template
```

Call in the template:

```text
{{ export .Name }}           ← function then arguments
{{ .Name | export }}         ← pipeline: .Name as last arg of export
{{ printf "%q" .Name }}      ← built-in
{{ call .Fn 1 2 }}           ← call a function value from the data
```

During execution: first the function map on the template, then the global built-ins. Your function with the same name can shadow a built-in — do that intentionally or not at all.

## Mechanism

This section is the heart of the lesson. Order of `Funcs`, signatures, errors, pipelines, then codegen idioms.

### Why `Funcs` before `Parse`

```go
t, err := template.New("gen").Funcs(funcs).Parse(tpl)
```

The parser binds function names in the tree. If `Parse` runs before `Funcs`, calls to unknown functions fail at parse time (or do not bind as you expect). Idiom: **always** `New` → `Funcs` → `Parse` (or `Funcs` on the set before `ParseFiles`).

For several related templates:

```go
base := template.New("root").Funcs(funcs)
template.Must(base.Parse(rootTpl))
template.Must(base.New("part").Parse(partTpl))
```

The FuncMap on the root set is visible from associated templates.

**Predict, then check:** `Parse` then `Funcs` then `Execute` with `{{export .}}` — what do you expect?

**Answer:** an error at Parse/Execute because `export` was not known at the moment it needed to be. Fix: `Funcs` before `Parse`.

### Function signature

Typical:

```go
func exportIdent(s string) string
func goType(proto string) (string, error)
```

Rules:

- arguments: types the template can pass (string, int, bool, slice…);
- one result, or two where the second is `error`;
- if `error != nil`, `Execute` stops and returns that error.

That is fail-fast for codegen: an unknown proto type **must not** become a wrong Go type in the file.

### Pipeline = last argument

```
{{ .Name | export }}
```

equivalent to

```
{{ export .Name }}
```

Multiple steps:

```
{{ .raw | trimSpace | export }}
```

requires that `trimSpace` and `export` are in the FuncMap (or built-in). Reading left→right: the value flows to the right as the last argument.

**Trace:** `raw = "  order "` → `trimSpace` → `"order"` → `export` → `"Order"`.

### Built-in functions you actually use in codegen

| Name | Role |
|------|------|
| `printf` / `print` / `println` | formatting; `printf "%q"` for Go string literals |
| `len` | length |
| `index` | indexing map/slice |
| `slice` | `slice x 1 2` ≈ `x[1:2]` |
| `eq` `ne` `lt` … | comparisons (02.07) |
| `and` `or` `not` | empty logic |
| `call` | call a function value from the data |

`html` / `js` / `urlquery` are not the focus for Go source — that is more the web/html world. For Go identifiers, write your own functions.

### `call` — when the function is in the data

```go
type Model struct {
	Transform func(string) string
}
```

```
{{ call .Transform .Name }}
```

Rare in classic codegen (harder to serialize the model). More useful when the template receives a strategy function in memory. Do not confuse with named FuncMap entries.

### Mechanism example: `exportIdent`

```go
func exportIdent(s string) string {
	if s == "" {
		return "X"
	}
	r := []rune(s)
	r[0] = unicode.ToUpper(r[0])
	return string(r)
}
```

Unit test without a template:

```go
if exportIdent("order") != "Order" { t.Fatal() }
```

Then:

```go
funcs := template.FuncMap{"export": exportIdent}
```

```
type {{export .name}} struct{}
```

**Trace:** `name = "cart"` → `Cart`.

### Mechanism example: `goType` with an error

```go
func goType(proto string) (string, error) {
	switch proto {
	case "string":
		return "string", nil
	case "int64":
		return "int64", nil
	case "bool":
		return "bool", nil
	default:
		return "", fmt.Errorf("unknown type %q", proto)
	}
}
```

```
{{ goType .ProtoType }}
```

Unknown type → generate fails. Better than `type X unknown`.

### Quoting

```
var Msg = {{printf "%q" .Text}}
```

or

```go
funcs := template.FuncMap{"quote": strconv.Quote}
```

```
var Msg = {{quote .Text}}
```

`strconv.Quote` and `printf "%q"` cover escaping. Manual `"` + `.Text` + `"` breaks on the first inner quote.

### Identifiers — a stricter function

Codegen often gets names from JSON/proto. Invalid ones must be rejected:

```go
func goIdent(s string) (string, error) {
	if s == "" || !unicode.IsLetter([]rune(s)[0]) && s[0] != '_' {
		return "", fmt.Errorf("invalid identifier %q", s)
	}
	for _, r := range s {
		if !unicode.IsLetter(r) && !unicode.IsDigit(r) && r != '_' {
			return "", fmt.Errorf("invalid identifier %q", s)
		}
	}
	return s, nil
}
```

(Adapt to your rules; this is a teaching sketch — in production use clear Unicode identifier rules per the Go spec.)

Fail-fast prevents `type 123Bad struct{}`.

### Predict, then check: shadowing `printf`

If you put `"printf": myPrintf` in the FuncMap, the built-in `printf` is no longer available under that name for that template. Do you still call `printf "%q"`?

**Answer:** your `myPrintf` is called — it must support the same signature or the template breaks. Do not shadow built-ins without a reason.

### Lookup order

1. FuncMap on `*Template`
2. Global built-ins

That is why a local `len` in the FuncMap shadows the built-in `len`. Name clearly: `goLen` only if you absolutely must; otherwise use the built-in.

### Pipelines and errors mid-chain

```
{{ .Proto | goType | export }}
```

If `goType` returns an error, the chain stops — `export` is not called. Good.

If `goType` returns a string and `export` does not expect that shape, debug in unit tests of the functions separately, then an integration test of the template.

### FuncMap size — a pragmatic rule

| Number of functions | Signal |
|---------------------|--------|
| 1–8 | healthy for a small generator |
| 8–20 | split packages (`ident`, `types`) and document |
| 20+ | business logic is probably leaking into the template |

If a function needs half the model to decide, put a field on the model instead of a function.

### Testing strategy

1. **Unit** the functions (`exportIdent`, `goType`) — fast, no template.
2. **Render test** of a small template fragment with FuncMap.
3. **Golden** of the whole file.

Do not test only #3 — bugs often sit at the pipeline + range junction.

### Trace: a complete small generator

```go
funcs := template.FuncMap{
	"export": exportIdent,
	"goType": goType,
	"quote":  strconv.Quote,
}
const tpl = `package {{.Package}}
type {{export .Name}} struct {
{{- range .Fields }}
	{{export .Name}} {{goType .Proto}}
{{- end }}
}
var Label = {{quote .Label}}
`
```

Input: Name `order`, Fields `[{id,string},{n,int64}]`, Label `hi"x`.

1. `export order` → `Order`
2. fields: `Id string`, `N int64` (depends on export rules for short names — document them!)
3. `quote` → a correct literal with escapes

Note: `export("id")` → `Id` (Unicode upper on the first rune), not necessarily `ID`. If you need `ID` as a special case, use a function or an exception map in Go (`acronyms`).

### Acronyms — where they live

```go
var acronyms = map[string]string{"id": "ID", "url": "URL", "api": "API"}

func exportIdent(s string) string {
	if v, ok := acronyms[strings.ToLower(s)]; ok {
		return v
	}
	// ... default
}
```

The template still only calls `export`. Exceptions are testable in Go.

### `ParseFiles` / embed

```go
t, err := template.New("root").Funcs(funcs).ParseFS(fs, "tmpl/*.tmpl")
```

Same principle: Funcs before ParseFS. Embedding files keeps the template out of Go strings — FuncMap stays in code.

### What not to put in FuncMap

- I/O (reading files, network) during render
- a global mutable cache without synchronization
- “dedup” that depends on call order across template parts
- time (`time.Now`) — breaks generate determinism

FuncMap should be **pure** or at least deterministic for the same input.

### Predict, then check: two results without an error type

If a function returns `(string, string)`, the template will not treat the second as an error. The second must be of type `error` for fail-fast to work. Otherwise the behavior is not a “magic error channel”.

### Link to previous lessons

- Pipeline + `$q :=` (02.06): `{{$t := goType .Proto}}`
- `if eq (export .Name) "ID"` — better as a flag; FuncMap does not justify deep logic in `if`
- `range` + `export` (02.08): transformation per element

### In more detail: sharing FuncMap between tests and main

```go
func funcMap() template.FuncMap {
	return template.FuncMap{
		"export": exportIdent,
		"goType": goType,
		"quote":  strconv.Quote,
	}
}
```

Both `newGenTemplate` and ad-hoc tests call `funcMap()`. One source of names — no “works in main, fails in test” because of a forgotten function.

### In more detail: signature with `any` / `...any`

Built-in `printf` takes `...any`. Your own functions can do the same, but you lose type clarity. For codegen prefer narrow signatures (`string`, `int`) — errors surface earlier.

### Predict, then check: `len` on a string

`{{len .Name}}` for `Name: "Ž"` (one rune, maybe 2 bytes). `len` in the template follows Go `len` — for a string that is **bytes**, not runes. For rune count prepare `utf8.RuneCountInString` as FuncMap `runeCount` or compute it in the model.

### When the template calls a method and you add a same-named FuncMap entry

`.Export` as a method and `export` as a function are different — one is a field/method on the dot, the other is a function name. Do not mix them up in review: `{{export .Name}}` is not `{{.Export}}`.

### Workshop scenario: proto types grow

Week 1: `string|int64|bool`. Week 6: `bytes`, `google.protobuf.Timestamp`. Without `error` from `goType`, someone adds a silent `interface{}`. With `error`, CI goes red until you add a case or reject the input. FuncMap becomes a **registry** of supported types — keep it next to a table in the README.

### Note on `html/template`

Same action language, but escaping for HTML. For `.go` source use **`text/template`**. Mixing packages in codegen for Go code is a mistake — escaping will break `<` in generic types or comments.

## Rules and syntax

| Rule | Detail |
|------|--------|
| Order | `Funcs` before `Parse` |
| Name | identifier; do not shadow built-ins without need |
| Signature | `func(...) T` or `func(...) (T, error)` |
| Error | non-nil error → Execute fails |
| Pipeline | left result = last arg of the right |
| Purity | determinism for the same input |

Built-ins to remember: `printf`, `len`, `index`, `slice`, `eq`, `and`, `or`, `not`, `call`.

## Examples

### Example 1 — `exportIdent` + Must

```go
package main

import (
	"os"
	"text/template"
	"unicode"
)

func exportIdent(s string) string {
	if s == "" {
		return "X"
	}
	r := []rune(s)
	r[0] = unicode.ToUpper(r[0])
	return string(r)
}

func main() {
	t := template.Must(template.New("t").Funcs(template.FuncMap{
		"export": exportIdent,
	}).Parse(`type {{export .name}} struct{}`+"\n"))
	_ = t.Execute(os.Stdout, map[string]string{"name": "order"})
}
```

#### What happens here

FuncMap registers `export`. Input `order` → `type Order struct{}`.

### Example 2 — `printf` quoting

```
var Msg = {{printf "%q" .Text}}
```

#### What happens here

A safe Go string literal without your own function.

### Example 3 — pipeline chain

```go
funcs := template.FuncMap{
	"trim":   strings.TrimSpace,
	"export": exportIdent,
}
```

```
{{ .raw | trim | export }}
```

#### What happens here

Trim then export. Both functions are unit-testable.

### Example 4 — `goType` with an error

```go
func goType(proto string) (string, error) {
	switch proto {
	case "string":
		return "string", nil
	case "int64":
		return "int64", nil
	default:
		return "", fmt.Errorf("unknown type %q", proto)
	}
}
```

```
{{ goType .ProtoType }}
```

#### What happens here

An unknown type breaks generate — fail-fast.

### Example 5 — Complete small generator

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"strconv"
	"text/template"
	"unicode"
)

func exportIdent(s string) string {
	if s == "" {
		return "X"
	}
	r := []rune(s)
	r[0] = unicode.ToUpper(r[0])
	return string(r)
}

func goType(proto string) (string, error) {
	switch proto {
	case "string", "int64", "bool":
		return proto, nil
	default:
		return "", fmt.Errorf("unknown type %q", proto)
	}
}

type Field struct{ Name, Proto string }
type Model struct {
	Package string
	Name    string
	Label   string
	Fields  []Field
}

func gen(m Model) ([]byte, error) {
	const tpl = `package {{.Package}}
type {{export .Name}} struct {
{{- range .Fields }}
	{{export .Name}} {{goType .Proto}}
{{- end }}
}
var Label = {{quote .Label}}
`
	t, err := template.New("g").Funcs(template.FuncMap{
		"export": exportIdent,
		"goType": goType,
		"quote":  strconv.Quote,
	}).Parse(tpl)
	if err != nil {
		return nil, err
	}
	var b bytes.Buffer
	if err := t.Execute(&b, m); err != nil {
		return nil, err
	}
	return format.Source(b.Bytes())
}

func main() {
	out, err := gen(Model{
		Package: "demo",
		Name:    "order",
		Label:   `say "hi"`,
		Fields:  []Field{{"id", "string"}, {"n", "int64"}},
	})
	if err != nil {
		panic(err)
	}
	fmt.Print(string(out))
}
```

#### What happens here

FuncMap + range + format. One file shows the whole join of lessons 02.06–02.09.

### Example 6 — Unit-test the function separately

```go
func TestGoType(t *testing.T) {
	_, err := goType("float128")
	if err == nil {
		t.Fatal("expected error")
	}
}
```

#### What happens here

You do not need to render a template to prove type mapping.

### Example 7 — Deliberate fail in CI

Pass `Proto: "timestamp"` without a case branch — the generator exits ≠ 0. CI catches it. Then add a case or reject in input validation with a clear message.

## Decision analysis

| Decision | Choose when... | Avoid when... |
|----------|----------------|---------------|
| FuncMap transform | pure type→type | you need half the model |
| Field already computed | expensive / frequent value | explosion of fields for tiny things |
| `error` from the function | invalid input | “silent” default of the wrong type |
| Shadowing a built-in | intentional replacement | accidental same name |
| Acronym map | ID/URL/API | 200 ad-hoc exceptions without tests |

## Trade-offs

- **More functions:** shorter template; heavier mental model for review.
- **More fields on the model:** explicit; adapter churn.
- **Fail-fast error:** safer output; stricter input data.
- **Silent default:** generate “passes”; production carries the bug.

## Common mistakes

1. **Wrong:** `Parse` then `Funcs`.  
   **Effect:** unknown function / behavior.  
   **Why:** names are bound at parse.  
   **Fix:** `Funcs` before `Parse`.

2. **Wrong:** a function without `error` returns `"invalid"` as a type.  
   **Effect:** wrong Go compiles or fails later.  
   **Why:** no fail-fast.  
   **Fix:** `(string, error)`.

3. **Wrong:** manual quotes instead of `quote` / `printf "%q"`.  
   **Effect:** breakage on special characters.  
   **Why:** escaping.  
   **Fix:** `strconv.Quote` or `printf "%q"`.

4. **Wrong:** FuncMap with I/O and `time.Now`.  
   **Effect:** non-determinism, slow tests.  
   **Why:** side effects.  
   **Fix:** pure functions; time outside generate or a fixed string.

5. **Wrong:** `export` that does not cover acronyms, so `Id` instead of `ID`.  
   **Effect:** non-idiomatic Go, review noise.  
   **Why:** naive ToUpper of the first rune.  
   **Fix:** acronym map + tests.

6. **Wrong:** accidentally shadowed `printf`.  
   **Effect:** strange formatting errors.  
   **Why:** lookup prefers local FuncMap first.  
   **Fix:** do not use reserved names.

7. **Wrong:** business logic in FuncMap (`ShouldEmitDelete(svc, meta, flags)`).  
   **Effect:** unreadable template.  
   **Why:** wrong layer.  
   **Fix:** a bool on the model.

8. **Wrong:** only golden is tested, not a `goType` unit test.  
   **Effect:** harder to localize a regression.  
   **Why:** mixed failure.  
   **Fix:** test pyramid.

## Idiomatic Go

- Small pure functions in `internal/genfuncs`.
- `Funcs` in one factory place (`newTemplate() *template.Template`).
- Fail-fast for types and identifiers.
- Deterministic generate (no `time.Now` in the output unless explicitly required).
- Document acronyms.
- `format.Source` after Execute.

## Practical scenario

A generator for OpenAPI → Go client. The template called `{{title .Name}}` from a “strings” helper copied from the internet that did not know about `ID`. Hundreds of `Id` fields. Linter `revive` / review bot spam.

`exportIdent` is introduced with an acronym map and a unit-test table (`id→ID`, `url→URL`, `user_id` → a special snake→export rule). The template stays `{{export .Name}}`. A diff in one PR fixes the names; from then on a new acronym = one row in the map + one test, not hunting through templates.

Second incident: `goType` defaulted to `interface{}` for unknowns. Generated code compiled; runtime panicked. Replacement: error from `goType`. CI immediately shows which proto type is missing from the map.

## Check questions

1. **When to call `Funcs`?**  
   Before `Parse` on that template/set.

2. **How does a pipeline pass a value?**  
   As the last argument of the next command.

3. **What if a function returns a non-nil error?**  
   `Execute` stops with that error.

4. **Why not manual quotes?**  
   Escaping / special characters.

5. **Where to test `exportIdent`?**  
   First unit without a template, then render.

6. **What does `call` do?**  
   Calls a function value from the data with arguments.

7. **Why avoid `time.Now` in FuncMap?**  
   Non-deterministic generated output.

8. **When to put a bool on the model instead of a function?**  
   When the decision depends on multiple fields / a business rule.

When `{{frob .X}}` looks like magic in review, either rename it to something obvious (`export`, `goType`) or compute the field in the adapter.

### Mini FuncMap checklist

1. `Funcs` before `Parse`
2. No accidental shadowing of built-ins
3. `(T, error)` for mappings that can fail
4. Unit tests of transformations
5. No I/O / time on the render path
6. Documented acronyms
7. Factory `newTemplate()` in one place

### Extra trace: factory

```go
func newGenTemplate() *template.Template {
	return template.Must(template.New("gen").Funcs(template.FuncMap{
		"export": exportIdent,
		"goType": goType,
		"quote":  strconv.Quote,
	}).Parse(genTpl))
}
```

All tests and `main` call `newGenTemplate()` — no copy-paste of the Funcs/Parse order.

### Extra predict-then-answer: pipeline with an error in the middle

Template: `{{ .X | goType | export }}`. `goType` returns an error. Does `export` run?

**Answer:** No. Execute stops at the first error result in the pipeline.

### One more table: built-in vs custom

| Need | Choose |
|------|--------|
| Go string literal | `printf "%q"` or `quote` |
| Slice length | built-in `len` |
| Proto→Go mapping | custom `goType` + error |
| Title-case identifier | custom `export` + acronyms |
| HTML escape | not for Go source (`text/template`) |

### Scenario add-on: review comment

A reviewer writes: “What does `{{norm .}}` do?” If they have to ask, the function name is bad or it belongs on the model. Rename to `goIdent` or compute `Field.GoName` in the extract step. FuncMap is not a place for cryptonyms.

### Last check before merging a FuncMap PR

Run three things: unit tests of the functions, one render test, one `go generate` + `git diff`. If all three are quiet — only then merge. A template without that loop stays “works on my machine”.

Remember the order as a mantra: **New → Funcs → Parse → Execute → format.Source**. Any other order is a regression waiting for a PR.

If you remember only one thing from this lesson: test FuncMap functions **without** a template first — the template then only wires already proven pieces.

That is the same discipline as for the rest of codegen: small provable parts, then the join.

## Summary

`FuncMap` adds named transformations to the template language. Register before `Parse`, keep functions pure and fail-fast, use pipelines deliberately, do not shadow built-ins. Codegen likes `export`, `goType`, `quote` — it does not like side effects. The next lesson joins `//go:generate`, model, template, and optional AST steps into one pipeline and shows the path toward the gRPC block.

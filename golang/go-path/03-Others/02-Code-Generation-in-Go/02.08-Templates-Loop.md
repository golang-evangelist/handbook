# 02.08 Templates: loops (range)

> **Go Path - Zero to Gopher** / **03 Others → Code Generation in Go** / Lesson 02.08

## Lesson goals

After this lesson you should be able to:

- use `{{range}}` over slice, array, and map values;
- bind index/key and value with `{{range $i, $v := ...}}` (and know that **one** variable captures the element — opposite of Go `for i := range`);
- combine `range` with `$` / `$root`, `else`, `break` / `continue`;
- emit lists (struct fields, enum cases, map literals) in valid Go form;
- watch nested `range` and deterministic map key order.

## Prerequisite

- 02.05–02.07 (dot, `$`, `if`/`with`, empty rules).
- Go 1.22+.
- Basic work with `[]T` and `map[K]V` in Go.

## Problem this lesson solves

Almost every codegen has a list: struct fields, enum values, RPC methods, HTTP routes. Without `range` the template does not scale — you manually copy ten blocks. With a bad `range` you get:

- wrong context (`.Package` on the element);
- commas and empty `switch` branches;
- non-deterministic order when you range a map without awareness of sorting;
- nested `range` where the inner `.` overwrites the outer element.

This lesson focuses loops for **source code**.

## Mental model

```text
range over slice/array:
  . = element
  optionally: range $i, $v := .Items   → $i index, $v element

range over map:
  . = value
  range $k, $v := .Map              → $k key, $v value
  (basic-type keys with order → visit in sorted order)

range empty / nil:
  body does not run; else branch (if present) does
```

`break` / `continue` affect the nearest `range` — available in modern `text/template` (Go 1.18+ for break/continue in templates; use Go 1.22+ as the path requires).

## Mechanism

This section is the heart of the lesson. First slice, then map, then commas, then nesting and traces.

### Basic `range` over a slice

```
{{range .Fields}}
{{.Name}} {{.Type}}
{{end}}
```

**Trace:** `Fields = [{Name:ID, Type:string}, {Name:Age, Type:int}]`.

1. Iteration 0: `. = {ID, string}` → emits `ID string` (plus spaces/newlines from the template).
2. Iteration 1: `. = {Age, int}` → `Age int`.
3. End.

During the loop the root model is not in `.`. For `Package` use `$.Package` or an alias before the loop.

### One variable vs two — trap from Go habit

```
{{range $v := .Fields}}
{{$v.Name}}
{{end}}
```

`$v` is the **element**, not the index. In Go `for i := range s` gives the index; in the template one variable = element. That is officially documented and opposite of the Go convention.

```
{{range $i, $f := .Fields}}
// field {{$i}} is {{$f.Name}}
{{end}}
```

Here `$i` is the index, `$f` the element — closer to `for i, f := range`.

**Predict, then check:** `{{range $x := .Fields}}{{$x}}{{end}}` where Fields is `[]string{"a","b"}`. What does `$x` print?

**Answer:** `a` then `b` (elements), not `0` then `1`.

### `range` + `else`

```
var Hooks = []string{
{{- range .Hooks }}
	"{{.}}",
{{- else }}
	// no hooks
{{- end }}
}
```

If `Hooks` is nil or empty, `else` runs (comment). Dot in `else` is **not** moved to an element — it stays the context from before `range`.

### Map: key, value, order

```
var Labels = map[string]string{
{{- range $k, $v := .Labels }}
	{{printf "%q" $k}}: {{printf "%q" $v}},
{{- end }}
}
```

For a map with basic-type keys that have a defined order, the template visits **sorted** keys. That helps deterministic generate — but do not rely blindly: for complex key types or older habits, safest is to extract a sorted `[]Pair` in Go then `range` over a slice.

**Predict, then check:** map `{"b":"2","a":"1"}` — what key emission order do you expect for `string` keys?

**Answer:** sorted: first `"a"`, then `"b"`.

### Why not range a map “raw” in CI without awareness

If you ever move to a key type without stable sorting in the implementation, or prepare a map in a loop that depends on `map` iteration in Go before the template, you get a flaky diff. Discipline:

1. Template `range` over map[string]T — OK, sorts.
2. Go `for k := range m` when building the model — **sort.Strings** the keys before inserting into the model slice.

### Root inside the loop

```
{{$pkg := .Package}}
{{range .Types}}
{{$pkg}}.{{.}}
{{end}}
```

or

```
{{range .Types}}
{{$.Package}}.{{.}}
{{end}}
```

Both work. `$pkg` is more readable when the root is needed in ten places; `$.` is shorter for one occurrence.

### Nested `range` — carefully

```
{{range .Services}}
{{$svc := .}}
{{range .Methods}}
func (c *{{$svc.Name}}Client) {{.Name}}() {}
{{end}}
{{end}}
```

**Why `$svc := .`:** the inner `range` overwrites `.` to the method. Without `$svc` you lose the service name.

**Trace:** Services = [{Name:Order, Methods:[{Name:Create},{Name:Get}]}].

1. Outer: `. = Order service`, `$svc = Order service`.
2. Inner: `. = Create` → `func (c *OrderClient) Create() {}`.
3. Inner: `. = Get` → `Get`.
4. Outer next service…

Without `$svc`, `{{.Name}}Client` would read the method name.

### Commas in Go lists

Go allows a trailing comma. The calmest codegen:

```
var Xs = []string{
{{- range .Xs }}
	{{printf "%q" .}},
{{- end }}
}
```

Always a comma after the element — including the last. No “is it the last” logic. Avoid template math with `len` and index only for commas.

### `break` and `continue`

```
{{range .Items}}
{{- if eq . "skip" }}{{continue}}{{end}}
{{- if eq . "stop" }}{{break}}{{end}}
{{.}}
{{end}}
```

`continue` jumps to the next iteration; `break` exits the loop. Use rarely in codegen — a filter in Go (`Items` already cleaned) is more readable than conditions in the loop.

### `range` over an integer (newer Go template behavior)

In newer versions `range` can also iterate integers / iter.Seq. For this course the focus remains slice/map — if you need `0..n-1`, prepare `[]int` in Go or check the documentation for the exact Go version. Do not build generic codegen on a rarely used branch without a test.

### Trim in a loop

```
type S struct {
{{- range .Fields }}
	{{.Name}} {{.Type}}
{{- end }}
}
```

`{{-` strips whitespace before the action so fields sit with tab indentation. Check `gofmt` / `format.Source` — it tidies indentation anyway; trim helps more so golden files are not full of blank lines.

### Predict, then check: else vs empty range without else

Template A:

```
{{range .Xs}}{{.}}{{end}}
```

Template B:

```
{{range .Xs}}{{.}}{{else}}NONE{{end}}
```

For `Xs: nil` — A prints nothing; B prints `NONE`.

### Pipeline in the `range` argument

```
{{range .Items | someFilter}}
```

Works only if `someFilter` is in FuncMap and returns a range-able value. Often cleaner: filter in Go, the template ranges a ready slice.

### String as range?

Range over a string iterates runes? In the template documentation range expects array/slice/map/channel/integer/Seq — a string is not a classic “per character” range like Go `for range string` in all documentation versions the same way. **Do not** build codegen that ranges a string until you explicitly check and test on your Go version. Prepare `[]rune` or `[]string` in the model.

### Determinism checklist

| Source | Risk | Mitigation |
|-------|-------|------------|
| `range` map[string]T in the template | low (sort) | still a golden test |
| Go `for range map` when building the model | high | sort keys |
| nested map range | medium | slice of struct |
| parallel generate | high | one writer, stable order |

### Trace: enum stringer-like emit

Model:

```go
type Enum struct {
	Name   string
	Values []string
}
// Name: "Code", Values: ["OK","Fail"]
```

Template:

```
func (s {{.Name}}) String() string {
	switch s {
{{- range .Values }}
	case {{.}}:
		return "{{.}}"
{{- end }}
	default:
		return "{{$.Name}}(" + strconv.Itoa(int(s)) + ")"
	}
}
```

Steps:

1. `. = Enum`.
2. `range .Values`: `. = "OK"`, then `"Fail"`.
3. In `default`, `$.Name` is `Code` — the root, because `.` was a string in the loop (the loop is done; in default we are outside the range body — wait: `default` is inside the function but outside the `range` block, so `.` is Enum again). That is why `{{.Name}}` in default also works. `$.Name` is a defensive style after the loop in the same template fragment.

### Nesting three levels — when to stop

If you have Services → Methods → Params, consider a sub-template:

```
{{range .Services}}{{template "service" .}}{{end}}
```

Each level gets a clean `.`. Variables are **not** inherited in a `template` call — pass a struct that has everything needed (`ServiceView` with a `Package` field copied).

### Connection to 02.06/02.07

Without aliases and empty rules, `range` only multiplies errors. `if .Fields` before `range` is often not needed — an empty range does not emit the body; `else` covers a message.

### In more detail: what happens to `.` after `{{end}}`

After the `range` block ends, `.` is **restored** to the value it had before entering the loop. That is why you can:

```
{{range .Fields}}{{.Name}} {{end}}
package {{.Package}}
```

The second line sees the root model again (if `.` was the root before the loop). Still: do not rely on “memory” in a long template — use `$root` at the top. More readable for review.

### In more detail: `range` and `with` together

```
{{range .Items}}
{{with .Meta}}
{{.Note}}
{{end}}
{{end}}
```

Inside `with`, `.` is Meta; the Items element is no longer in `.`. If you need both the element and meta:

```
{{range .Items}}
{{$item := .}}
{{with .Meta}}
{{$item.Name}}: {{.Note}}
{{end}}
{{end}}
```

### Predict, then check: empty struct in a slice

`Fields: []Field{{}}` — one element, zero Field. Does `range` enter the body?

**Answer:** Yes — length is 1. The empty rule applies to the whole collection, not to “whether the element is zero.” Inside `.Name` can be `""`. Validation “field must have a name” goes in Go before render.

### Emitting function parameters with commas

```
func F(
{{- range $i, $p := .Params }}
	{{$p.Name}} {{$p.Type}},
{{- end }}
) {}
```

A trailing comma after the last parameter is legal in Go. An alternative with “no comma at the end” requires a condition on `$i` and `len` — more fragile. Stick with trailing comma.

### Channel and range (note only)

The documentation allows range over a channel. In a codegen template that is almost never a good model — a channel is for concurrency at runtime, not for a static list of fields. Prepare a slice.

### iter.Seq / Seq2 (Go 1.23+ note)

Newer Go versions extend range in templates. For this path (1.22+): stick to slice/map. If you use Seq, write an explicit test on the CI version — do not assume.

### Trace: JSON tags from a list

Field model: `{Name:"UserID", JSON:"user_id"}`.

```
{{- range .Fields }}
	{{.Name}} string `json:"{{.JSON}}"`
{{- end }}
```

**Predict, then check:** what if `.JSON` contains `"`? The tag literal breaks. Fix: validation in Go or a function that escapes tag content. For JSON names usually `[a-z0-9_]+` — reject the rest before the template.

### When `range` is not the answer

If you always emit exactly 2–3 fixed blocks of different structure, sometimes three `if` / three `define` are clearer than forcing into a list. `range` shines when **N** is unknown and elements share the same shape.

### Workshop trace: from JSON to slice model

1. Unmarshal a JSON array of methods.
2. Convert to `[]Method` with exported fields.
3. Sort by name if the API requires stable order.
4. `Execute` the template with `range .Methods`.
5. `format.Source`.
6. Compare golden.

Step 3 is where flaky CI disappears — not step 4.

### Note about `template` and range

```
{{range .Methods}}{{template "method" .}}{{end}}
```

Inside the `method` template, `.` is one method. `$` in that template is the **initial data of that ExecuteTemplate call** — i.e. that method — not the root file model. That is why in `method` pass `MethodView{Package: ..., Method: ...}` or use `{{template "method" $root}}` with a smarter view model. This is a common source of bugs when splitting templates.

### One more trace: emitting switch with validation in Go

Before render:

```go
if len(model.Values) == 0 {
	return fmt.Errorf("enum %s has no values", model.Name)
}
```

The template may assume that `range .Values` is not empty. `default` still exists for runtime resilience, but generate does not produce an empty switch without cases from a “forgotten” input.

**Predict, then check:** you remove validation, `Values: nil`, the template has `range` without `else` inside `switch`. What do you get?

**Answer:** `switch s {\n default: ...}` — compiles, but has no case for known constants. The stringer lies. Validation in the extract/adapter is part of the loop mechanism, not “optional kindness.”

### Comparison: manual copy vs range

Manual:

```
case OK:
	return "OK"
case Fail:
	return "Fail"
```

Range:

```
{{- range .Values }}
	case {{.}}:
		return "{{.}}"
{{- end }}
```

When you add `Pending`, manually you forget a case; range does not. That is the whole reason for loops in codegen.

### Whitespace control — when `gofmt` is not enough

`format.Source` tidies Go indentation, but does not fix **semantically** wrong text (glued `packageapi`). Trim in `range` serves so golden files are stable before format and so the diff is smaller. Rule: trim newline/indent; do not trim the space between a keyword and a name.

### Predict, then check: `range` over map[int]string

`int` keys have order — the template sorts. Input `{2:"b", 1:"a"}` — which order?

**Answer:** first key `1`, then `2`. Still, for a public API order better an explicit slice in the model.

## Rules and syntax

| Form | Meaning |
|-------|----------|
| `range .X` | `.` = element / map value |
| `range $v := .X` | `$v` = element (not index!) |
| `range $i, $v := .X` | index/key and value |
| `range` + `else` | empty collection |
| `break` / `continue` | control of the nearest loop |

Rules for codegen:

- Trailing comma in lists and map literals.
- `$svc := .` before an inner `range`.
- Do not build comma-logic via “last index.”
- Sort in Go when you build the model from a map.
- Prefer a filter in Go over `continue` in the template.
- Golden test for field order and case branches.

## Examples

### Example 1 — Struct fields

```
package {{.Package}}

type {{.Name}} struct {
{{- range .Fields }}
	{{.Name}} {{.Type}}
{{- end }}
}
```

```go
type Field struct{ Name, Type string }
type Model struct {
	Package string
	Name    string
	Fields  []Field
}
```

#### What happens here

One `range` draws all fields. Zero fields → `struct {\n}` — valid after `gofmt`.

### Example 2 — Enum case list

```
func (s {{.Name}}) String() string {
	switch s {
{{- range .Values }}
	case {{.}}:
		return "{{.}}"
{{- end }}
	default:
		return "{{$.Name}}(" + strconv.Itoa(int(s)) + ")"
	}
}
```

#### What happens here

`$.Name` is a defensive root; `.` in the loop is the constant name. Typical stringer-like emit.

### Example 3 — `range` else

```
var Hooks = []string{
{{- range .Hooks }}
	"{{.}}",
{{- else }}
	// no hooks
{{- end }}
}
```

#### What happens here

Else when the slice is empty. The literal stays valid.

### Example 4 — Map with quoting

```
var Labels = map[string]string{
{{- range $k, $v := .Labels }}
	{{printf "%q" $k}}: {{printf "%q" $v}},
{{- end }}
}
```

#### What happens here

`$k`/`$v` + `printf` for safe literals. Order for string keys sorted.

### Example 5 — Go Execute

```go
package main

import (
	"os"
	"text/template"
)

func main() {
	const tpl = `var Ns = []string{
{{- range . }}
	{{printf "%q" .}},
{{- end }}
}
`
	t := template.Must(template.New("n").Parse(tpl))
	_ = t.Execute(os.Stdout, []string{"a", "b"})
}
```

#### What happens here

The whole data is a slice — `range .` iterates strings. Trailing comma. Output ready for `gofmt`.

### Example 6 — Nested range with `$svc`

```
{{range .Services}}
{{$svc := .}}
{{range .Methods}}
func (c *{{$svc.Name}}Client) {{.Name}}(ctx context.Context) error { return nil }
{{end}}
{{end}}
```

#### What happens here

The outer element saved in `$svc` while the inner `.` becomes the method.

### Example 7 — Index in a comment / tag

```
{{- range $i, $f := .Fields }}
	{{$f.Name}} {{$f.Type}} `json:"{{$f.JSON}}" /* field {{$i}} */`
{{- end }}
```

#### What happens here

`$i` useful for debug comments; in production you often drop the comment. Shows the double binding.

## Decision analysis

| Decision | Choose when... | Avoid when... |
|--------|--------------|------------------|
| `range` over slice in the model | you need stable order | you currently only have a map |
| `range` over map in the template | string keys, small set | complex keys, strict order |
| filter in Go | business rule | trivial skip of one name |
| `continue` in the template | micro exception | half the loop in conditions |
| sub-template per level | 3+ nesting levels | one shallow list |
| trailing comma always | Go output | languages without trailing comma |

## Trade-offs

- **Everything in one template:** overview of one file; harder to test parts.
- **`template` per level:** clean; more names and context passing.
- **Map range:** less Go code; less control than an explicit slice.
- **Trim:** nicer golden; risk of wrong whitespace next to identifiers.

## Common mistakes

1. **Wrong:** `range $i := .Items` thinking `$i` is the index.  
   **Effect:** `$i` holds the element; types/fields break.  
   **Why:** template convention ≠ Go `for i := range`.  
   **Fix:** `range $i, $v := .Items` or only the element.

2. **Wrong:** `.Package` inside `range` without `$`.  
   **Effect:** error / wrong field.  
   **Why:** `.` is the element.  
   **Fix:** `$.Package` or `$pkg` before the loop.

3. **Wrong:** nested `range` without saving the outer element.  
   **Effect:** the inner name overwrites the outer.  
   **Why:** one dot.  
   **Fix:** `$outer := .` before the inner loop.

4. **Wrong:** comma-logic “if not last.”  
   **Effect:** complicated template, off-by-one.  
   **Why:** unnecessary in Go.  
   **Fix:** trailing comma always.

5. **Wrong:** Go `for range map` when building the model without sort.  
   **Effect:** flaky generated diff in CI.  
   **Why:** non-deterministic order.  
   **Fix:** `sort.Strings(keys)` then slice.

6. **Wrong:** empty `switch` without `default` when there are no Values — and without `else`.  
   **Effect:** incomplete or odd code.  
   **Why:** range did not emit a case.  
   **Fix:** always `default`, validation “at least one value” in Go.

7. **Wrong:** excessive `continue` instead of a filter.  
   **Effect:** business rules hidden in the template.  
   **Why:** wrong layer.  
   **Fix:** filter the slice in the adapter.

8. **Wrong:** rely on map order without a golden test.  
   **Effect:** surprise on upgrade.  
   **Why:** assumptions about sorting.  
   **Fix:** test + explicit slice when order is part of the API.

## Idiomatic Go

- Model: `[]Field`, `[]Method` — not `map` when order has meaning (protocols, API).
- Trailing comma in generated lists.
- `$outer := .` pattern for nesting.
- `format.Source` after render.
- Sort keys in Go whenever a map enters the pipeline.
- Golden tests for case / field order.

## Practical scenario

An event-type generator ranges `map[string]EventSpec` directly in the template. Locally the diff is always “green.” In CI (another Go minor version / another machine) key order in one edge case disorders comments generated from a Go loop **before** the template — flaky. The team moves to:

```go
keys := maps.Keys(spec)
sort.Strings(keys)
for _, k := range keys {
	model.Events = append(model.Events, ...)
}
```

The template does `range .Events`. Flakiness disappears. Another PR: nested range Services/Methods without `$svc` — generated methods were named `CreateClient` instead of `OrderClient`. Fix in one alias line + a unit test with two levels.

## Check questions

1. **What is `.` inside `range` over a slice?**  
   The current element.

2. **What does `range $v := .Items` bind?**  
   The element (not the index).

3. **How do you read the root package in a loop?**  
   `$.Package` or an alias before `range`.

4. **What is trailing comma for?**  
   Valid Go, without “last element” logic.

5. **Why sort keys in Go?**  
   Deterministic model and CI diff, especially when you iterate a map outside the template.

6. **What does `range` `else` do?**  
   Runs when the collection is empty/nil.

7. **Why `$svc := .` before an inner range?**  
   To preserve the outer element while `.` becomes the inner one.

8. **Does `break` break all loops?**  
   No — the nearest (inner) `range`.

When a generated list “looks whimsical,” first check whether the input was a map without sort in Go — that is the culprit more often than the template `range` itself.

### Mini loop checklist

1. Is the input a slice when order has meaning?
2. Is the root preserved (`$` / alias)?
3. Does nesting have `$outer`?
4. Is there a trailing comma?
5. Does empty input give valid Go (else or empty literal)?
6. Does golden fix the order?

### Extra scenario: comma in a middlewares list

A team emits:

```
var chain = []Middleware{
{{- range .MWs }}
	{{.}},
{{- end }}
}
```

A junior removes the trailing comma and adds:

```
{{if lt $i (sub (len $.MWs) 1)}},{{end}}
```

`sub` is not a built-in function — Execute breaks. Restore trailing comma. Lesson: do not invent arithmetic in the template for commas.

### Extra predict-then-answer: nil vs empty in else

**Question:** does `range` `else` distinguish a `nil` slice from `[]T{}`?

**Answer:** Not in practice of empty rules — both have length 0, else runs. If the domain must distinguish “not set” from “set empty,” use `*[]T` or a bool `HooksSet` in the model.

{{range .Fields}}

The loop stays the same; name transformation leaves template “smarts” for testable functions.

## Summary

`range` scales codegen lists: `.` becomes the element, you preserve the root consciously, one variable is the element (not the index). Maps in the template sort basic keys; maps in Go loops you sort yourself. Trailing comma and `$outer := .` remove whole classes of bugs. The next lesson adds `FuncMap` — name and type transformations without muddying the model.

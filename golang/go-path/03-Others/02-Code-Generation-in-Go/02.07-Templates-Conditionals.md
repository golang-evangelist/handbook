# 02.07 Templates: conditionals

> **Go Path - Zero to Gopher** / **03 Others → Code Generation in Go** / Lesson 02.07

## Lesson goals

After this lesson you should be able to:

- write `{{if}}` / `{{else}}` / `{{else if}}` / `{{end}}` in `text/template`;
- use comparisons `eq`, `ne`, `lt`, `le`, `gt`, `ge` and `not` / `and` / `or`;
- use `{{with}}` for a condition **and** narrowing the dot context;
- distinguish when `if` does not touch `.`, while `with` changes it — and how `$` / `$root` save the root;
- design conditions so that generated Go stays **valid** even for empty / false branches;
- choose between conditions in the template and separate `define` / preparing bool flags in Go.

## Prerequisite

- 02.05–02.06 (dot, `$`, pipeline, aliases).
- Go 1.22+.
- Understanding zero values in Go (here: how the template treats “empty” as falsey).

Without a solid model of `.` vs `$` from 02.06, `with` will look like random field errors.

## Problem this lesson solves

Codegen rarely emits always the same shape. Typical requirements:

- if there are methods — emit a methods block; if not — do not leave empty noise;
- if it is a streaming RPC — a different signature;
- if an option is not set — do not emit an `option` line;
- if `Count == 0` is a **valid** case — do not treat it as “no data” without thinking.

Without conditions the template forces one shape and produces dead or invalid code. With bad conditions you get a file without `package`, glued tokens because of trim, or a `with` that “eats” root fields.

This lesson covers branching and `with` for **source code**, not for HTML.

## Mental model

```text
if pipeline:
  truthy? → branch T1
  else    → else / else if / nothing
  . stays the same

with pipeline:
  truthy? → . becomes the pipeline value, then T1
  else    → else branch ( . unchanged) or nothing
```

**Truthy / falsey in the template** (officially “empty”):

- falsey: `false`, `0`, `nil` pointer or interface, array/slice/map/string of **length zero**
- otherwise: truthy

That is not 1:1 with “whether a zero value is meaningful in the domain.” `0` as a status number can be valid — that is why `if .HasCount` is often better than `if .Count`.

## Mechanism

This section is the heart of the lesson. First truthiness rules, then `if`, then `with`, then traces with numbers.

### What is “empty” — table with examples

| Value | Truthy? | Typical codegen placement |
|----------|---------|-------------------------|
| `true` | yes | flag `EmitHelpers` |
| `false` | no | same |
| `1`, `-1` | yes | counters |
| `0` | **no** | caution: valid enum/index |
| `""` | no | optional string |
| `"api"` | yes | package name |
| `nil` slice | no | no fields |
| `[]T{}` | no | same — length 0 |
| `[]T{{...}}` | yes | has elements |
| `nil` map | no | |
| `map[K]V{}` | no | |
| `nil` pointer | no | optional sub-struct |
| pointer to zero struct | yes (pointer is not nil) | often confuses |

**Predict, then check:** `if .Items` where `Items []string{}` (empty, not nil). Does it enter the branch?

**Answer:** No — length zero is empty. Same as a nil slice for `if`.

### `if` does not move dot

```
{{if .Enabled}}
  {{.Package}}
{{end}}
```

Inside the branch `.` is still the whole model. `.Package` works. That is the difference from `with`.

### `else` and `else if`

```
{{if eq .Kind "enum"}}
type {{.Name}} int
{{else if eq .Kind "struct"}}
type {{.Name}} struct{}
{{else}}
// unknown kind: {{.Kind}}
{{end}}
```

`else if` is sugar for a nested `if` in the else branch. Readable up to ~3 branches. After that: a strategy map in Go or more `define` templates.

### Comparison functions

| Function | Meaning |
|----------|----------|
| `eq A B` | A == B (more args: A==B \|\| A==C …) |
| `ne A B` | A != B |
| `lt` `le` `gt` `ge` | < ≤ > ≥ |
| `not X` | negation |
| `and` / `or` | short-circuit in the sense of empty rules |

`eq` for multiple arguments evaluates all arguments (not entirely like `||` in Go per the function’s short-circuit documentation — treat it as a function call).

**Trace:** `eq .Kind "enum" "Enum" "ENUM"` — true if Kind equals any of those listed after the first.

For types: comparison works on comparable values; int sizes are relaxed among integer types, but do not mix int and float productively. In codegen: **normalize to string or bool in Go** before the template when you have doubt.

### `not`, `and`, `or`

```
{{if not .Deprecated}}
func Active() {}
{{end}}

{{if and .Stable .HasAPI}}
const APIVersion = 1
{{end}}
```

`and` returns the first empty or the last argument. `or` returns the first non-empty or the last. Useful, but in a long template explicit bool flags (`ReadyToEmit`) are more readable in review.

### `with` — condition + new dot

```
{{with .Meta}}
package {{.Package}}
{{end}}
```

If `.Meta` is empty (nil pointer, zero…), the block is skipped. If not, inside `.` **is** `Meta`. That is why:

```
{{with .Client}}
type {{.Name}} struct{}
func (c *{{.Name}}) Pkg() string { return "{{$.Package}}" }
{{end}}
```

`.Name` is the client; `$.Package` is the root. Without `$`, `.Package` would look for a field on Client.

**Predict, then check:** `with .GoPackage` where `GoPackage` is an empty string. What is emitted?

**Answer:** nothing from the block — empty string is falsey.

### `with` + `else`

```
{{with .Header}}
// header: {{.}}
{{else}}
// no header
{{end}}
```

In the `else` branch `.` is **unchanged** (the root context for that level). That is mirror behavior relative to a successful `with`.

### `with` that immediately introduces a variable

From the documentation / idiom:

```
{{with $x := .Name}}{{$x}}{{end}}
```

`$x` captures the value; you often still use `.` inside if `with` has moved. For codegen it is often clearer:

```
{{$name := .Name}}
{{if $name}}
...
{{end}}
```

when you do not want to move `.`.

### Valid Go skeleton outside conditions

**Golden rule:** the `package ...` line and the basic file shape should exist even when optional branches are false.

Bad:

```
{{if .Emit}}
package {{.Package}}
func Hello() {}
{{end}}
```

If `Emit` is false, the file is empty — `go/format` and the compiler suffer.

Better:

```
package {{.Package}}

{{if .EmitHello}}
func Hello() string { return "hello" }
{{end}}
```

You always have a package. The condition only adds members.

### Lists and commas with a condition

```
var Features = []string{
{{- if .Features }}
{{- range .Features }}
	"{{.}}",
{{- end }}
{{- end }}
}
```

You always emit `var Features = []string{ }` — valid even when there are no elements. The condition fills the elements. Trailing comma in Go is allowed — use it so you do not solve the “comma before the end” puzzle.

### Trim (`{{-` / `-}}`) and conditions

Trim strips whitespace/newlines around the action so generated code is not full of blank lines. Cost: glued tokens.

```
package {{- if .X }}x{{end}}
```

can produce odd joins. Rule: trim for **indentation and blank lines**, not for joining identifiers.

**Trace:** template

```
{{- if .A }}A{{- end }}{{- if .B }}B{{- end }}
```

with A and B true → `AB` without a space. For Go keywords and names that is dangerous; for dense lists in `{}` often desired.

### Zero value trap: `if .Count`

```go
type Model struct {
	Count int
}
```

```
{{if .Count}}
const N = {{.Count}}
{{end}}
```

When `Count == 0`, the constant is **not** emitted — and 0 can be legitimate. Fix in the model:

```go
type Model struct {
	Count    int
	HasCount bool
}
```

or always emit `const N = {{.Count}}` without a condition.

### `eq` vs bool flag in Go

Template:

```
{{if eq .Kind "streaming"}}
```

Go preparation:

```go
if spec.Kind == KindStreaming {
	m.Streaming = true
}
```

```
{{if .Streaming}}
```

The second form is more readable when `Kind` has 10 values and the template should not know the string protocol. The first form is OK for small differences.

### Predict, then check: pointer to struct

```go
type Meta struct{ Package string }
type Model struct{ Meta *Meta }
```

`Model{Meta: &Meta{Package: ""}}` — `if .Meta`?

**Answer:** truthy — the pointer is not nil. Inside `with .Meta` you enter; `.Package` is an empty string. `if .Package` inside is falsey. Separate “has Meta” from “has Package string.”

### Nesting depth

More than 2–3 levels of `if` in the template = a sign that you need:

1. bool flags in the model, or
2. `{{define "emit_enum"}}` / `{{define "emit_struct"}}` + `{{template}}`, or
3. separate template files per kind.

Codegen review likes shallow branching.

### Trace: complete flow with `with` and root

Model:

```go
data := struct {
	Package string
	Client  *struct{ Name string }
}{
	Package: "shop",
	Client:  &struct{ Name string }{Name: "Cart"},
}
```

Template:

```
{{$root := .}}
package {{$root.Package}}

{{with .Client}}
type {{.Name}}Client struct {
	BaseURL string
}
func (c *{{.Name}}Client) Package() string { return "{{$root.Package}}" }
{{end}}
```

Steps:

1. `$root` = whole data.
2. `package shop`.
3. `with .Client` → `.` = Client{Name: Cart}.
4. Emit type `CartClient` and a method that returns `"shop"` via `$root`.

If `Client == nil`, only `package shop` remains — still a valid file.

### The false branch must compile

Test **both** paths in a generator unit test: `EmitX=true` and `false`. A false branch that leaves a duplicate `package` or a half-finished struct is more common than you think.

### Connection backward/forward

- 02.06: `$` / `$root` — mandatory with `with`.
- 02.08: `range` has its own `else` for empty collections — related, but changes `.` per element.
- 02.09: conditions often call `eq (export .Name) "ID"` — better a flag in Go.

### In more detail: why `if .Items` works for “has elements”

For slice and map, the empty rule looks at **length**. That is why `{{if .Items}}` is the idiom for “has at least one element” — for both `nil` and an empty slice. You do not need to write `if and .Items (gt (len .Items) 0)` — that is redundant.

**Predict, then check:** `len` on a nil slice in the template — `{{len .Items}}` prints `0`. `{{if .Items}}` is false. Both are consistent with Go (`len(nilSlice) == 0`).

### In more detail: `with` on a map key

```
{{with index .Attrs "feature"}}
// feature={{.}}
{{end}}
```

If the key does not exist, `index` on a map returns the zero value of the value type (e.g. `""` for `map[string]string`) — empty → `with` skips. If the key exists and the value is `"off"`, you enter the block (non-empty string). For bool flags in a map be careful: `false` is empty.

### When not to use `with`

If inside the block you need **five** root fields and one narrowed one, `with` costs more than it gives — write `if .Client` and use `.Client.Name` explicitly, or extract `ClientView` in the model. `with` shines when 80% of references are to the narrowed object.

### Syntax note about comments in branches

```
{{if .Debug}}
{{/* temporary emit */}}
var debug = true
{{end}}
```

Comments `{{/* ... */}}` do not go to the output. Do not mix them with Go comments `//` — one is template, the other is generated code. In the false branch you often emit a Go comment as documentation for the reader of the generated file.

## Rules and syntax

| Action | Role | Does it change `.`? |
|--------|-------|------------------|
| `if` | conditional branch | no |
| `else` / `else if` | alternatives | no (in an if chain) |
| `with` | condition + narrowing | yes, if truthy |
| `eq` / `ne` / … | comparison | n/a |
| `not` / `and` / `or` | empty-rule logic | n/a |

Rules for codegen:

- `package` line outside optional conditions.
- Prefer named bool flags for domain decisions (`HasDelete`, `EmitTest`).
- `with` when you narrow a path; `if` when you only branch.
- Trim for whitespace hygiene, not for gluing Go tokens.
- Test true and false (and empty slice) branches.
- Max 2–3 levels of nesting before splitting the template.

## Examples

### Example 1 — `if` over a bool field

```
// Code generated; DO NOT EDIT.
package {{.Package}}

{{if .EmitHello}}
func Hello() string { return "hello" }
{{end}}
```

```go
type Model struct {
	Package   string
	EmitHello bool
}
```

#### What happens here

When `EmitHello` is false, there is no function — no dead code. `package` always exists.

### Example 2 — `eq` for modes

```
{{if eq .Kind "enum"}}
type {{.Name}} int
{{else if eq .Kind "struct"}}
type {{.Name}} struct{}
{{else}}
// unknown kind {{.Kind}}
{{end}}
```

#### What happens here

One template covers small shape differences. For large divergences — separate `define`.

### Example 3 — `with` for an optional block

```
{{with .GoPackage}}
option go_package = "{{.}}";
{{end}}
```

#### What happens here

Empty `GoPackage` → the block is skipped. Inside, `.` is a string. For root fields use `$.` / `$root`.

### Example 4 — Valid Go in a list

```
var Features = []string{
{{- if .Features }}
{{- range .Features }}
	"{{.}}",
{{- end }}
{{- end }}
}
```

#### What happens here

Always a valid slice literal. The condition only fills elements. (`range` details in 02.08.)

### Example 5 — Go wrapper with a map

```go
package main

import (
	"os"
	"text/template"
)

func main() {
	const tpl = `package {{.Package}}
{{if .Stable}}
const APIVersion = 1
{{else}}
const APIVersion = 0
{{end}}
`
	t := template.Must(template.New("v").Parse(tpl))
	_ = t.Execute(os.Stdout, map[string]any{"Package": "api", "Stable": true})
}
```

#### What happens here

A boolean chooses the constant. Both branches leave valid Go. Easy to unit-test both map inputs.

### Example 6 — `with` + `$root`

```
{{$root := .}}
{{with .Client}}
type {{.Name}} struct {
	BaseURL string
}
func (c *{{.Name}}) Package() string { return "{{$root.Package}}" }
{{end}}
```

#### What happens here

Narrowed context for the client; root package via `$root`. Classic codegen pattern.

### Example 7 — `not` and deprecation

```
{{if not .Deprecated}}
func Active() {}
{{end}}
{{if .Deprecated}}
// Deprecated: use ActiveV2
func Active() {}
{{end}}
```

#### What happens here

Branching by flag. Alternative: one block with a comment conditionally above the function — what matters is that both branches are consciously designed.

## Decision analysis

| Decision | Choose when... | Avoid when... |
|--------|--------------|------------------|
| `if` in the template | small local difference | half the file diverges |
| more `define` | large different shapes | micro-difference of one line |
| bool in the model | domain meaning | template full of `eq` strings |
| `with` | narrowing a path | you need the root every other line without `$` |
| `if .Count` | Count is never a valid 0 | 0 is a legitimate value |
| `else` comment | debug / unknown kind | production without `package` |

## Trade-offs

- **Smart template:** less Go code; more expensive review and weaker branch tests.
- **Dumb template + smart model:** more adapter code; clear flags and stable output.
- **`with`:** shorter paths; easier to lose the root.
- **Deep `if`:** fast prototype; hard maintenance.
- **Trim:** nice output; risk of glued tokens.

## Common mistakes

1. **Wrong:** `{{with .Client}}` then `.Package` for the root package.  
   **Effect:** error or wrong field.  
   **Why:** `.` is Client.  
   **Fix:** `$.Package` or `$root.Package`.

2. **Wrong:** the whole file inside `{{if .Emit}}` including `package`.  
   **Effect:** empty output when false — invalid Go.  
   **Why:** no skeleton.  
   **Fix:** `package` outside the condition.

3. **Wrong:** `if .Count` when 0 is valid.  
   **Effect:** missing constant / block.  
   **Why:** 0 is empty.  
   **Fix:** `HasCount` or always emit the value.

4. **Wrong:** trim glues `package` and the name.  
   **Effect:** `packageapi`.  
   **Why:** `-` strips whitespace.  
   **Fix:** space in the text; trim only around newline indentation.

5. **Wrong:** comparing types that `eq` handles poorly — mixed float/int ad hoc.  
   **Effect:** Execute error or false.  
   **Why:** comparable rules.  
   **Fix:** normalize to string/bool in Go.

6. **Wrong:** only the true branch in the generator test.  
   **Effect:** false branch breaks CI for the user later.  
   **Why:** uncovered branch.  
   **Fix:** table-test `Emit: true/false`.

7. **Wrong:** `if .Meta` on a pointer, then assume `Package` is non-empty.  
   **Effect:** you emit empty strings in literals.  
   **Why:** non-nil pointer ≠ non-empty fields.  
   **Fix:** separate conditions or validation in Go.

8. **Wrong:** five levels of `if` instead of splitting.  
   **Effect:** unreadable template, regressions.  
   **Why:** wrong layer of complexity.  
   **Fix:** `define` / more files / flags.

## Idiomatic Go

- Named bool flags in the model (`HasMethods`, `EmitHello`, `Stable`).
- `package` and DO NOT EDIT outside optional branches.
- `$root` at the top when you use `with`.
- Table-test for generator branches.
- Prefer `format.Source` after render — catch syntactic errors of branches.
- Do not hide domain logic in `eq` chains of 20 strings.

## Practical scenario

An SDK generator for REST resources always emits `Delete`. OpenAPI says some resources have no delete. The compiler did not fail (the method exists and calls an API that returns 404), but documentation and linters lied — “all resources support Delete.”

`HasDelete bool` is introduced in the model (filled from OpenAPI). Template:

```
{{if .HasDelete}}
func (c *Client) Delete{{.Name}}(ctx context.Context, id string) error { ... }
{{end}}
```

The false branch tested with a golden file without Delete. The reviewer sees the flag in the adapter, not a string `eq` in the template. The number of “fake” methods in docs drops to zero.

Second incident: someone puts `{{with .OptionalMeta}}` and inside uses `.Package` from the root — generate passes only for resources where Meta is nil (block skip). When Meta exists, Package is read from Meta and breaks. Fix: `$root` + checklist “inside with no root fields without $.”

## Check questions

1. **What is falsey in the template?**  
   false, 0, nil pointer/interface, slice/map/array/string of length zero.

2. **How does `.` change in `with`?**  
   If the pipeline is truthy, `.` becomes that value until `end`.

3. **What is `eq` for?**  
   Equality comparison (more arguments = OR of equality with the first).

4. **Why `package` outside most conditions?**  
   So the file stays valid Go even when the optional branch is false.

5. **When to split the template instead of if/else?**  
   When shapes diverge strongly or nesting exceeds 2–3 levels.

6. **Does `if` move `.`?**  
   No.

7. **Why can `if .Count` be wrong?**  
   Because 0 is empty, and 0 can be valid data.

8. **How do you read the root package inside `with`?**  
   `$.Package` or `$root.Package`.

When a branch “sometimes” works, check: do you test empty slice, nil pointer, and false bool separately — three different inputs, often the same symptom in your head, different in the machine.

### Mini condition checklist before merge

1. True branch rendered and (preferably) passed `format.Source`
2. False branch rendered — the file still has `package`
3. Empty slice / nil slice checked separately if they affect output
4. Inside `with` no root fields without `$` / `$root`
5. No `if .Count` trap for a valid zero
6. Trim does not glue keywords and identifiers
7. `eq` chains shorter than ~3 or replaced by a flag
8. Golden / table-test covers at least one `else`

If the checklist fails, do not add another nested `if` — first simplify the model.

### Trace: `else if` equivalent

This:

```
{{if .A}}A{{else if .B}}B{{end}}
```

behaves like:

```
{{if .A}}A{{else}}{{if .B}}B{{end}}{{end}}
```

Dot does not move in any branch. Useful when you read an older template that is explicitly nested — refactor to `else if` for readability, behavior stays.

### Predict, then check: `and` result is not always bool

`and .A .B` returns the first empty or the last argument — so it can return a **string** or another type, not necessarily `bool`. In `{{if and .A .B}}` that still works via empty rules. But if you do `{{and .Name .Pkg}}` as output, you can print a string, not `true`/`false`.

**Expected answer:** for printing a bool use a condition + literal, or prepare a bool in Go. For `if`, `and` is fine.

### Combining `with` and `if` — order

```
{{with .Meta}}
  {{if .Package}}
  package {{.Package}}
  {{end}}
{{end}}
```

First Meta must exist; then non-empty Package. Alternative in Go: `if m.Meta != nil && m.Meta.Package != "" { EmitPackage = true }` — template only `{{if .EmitPackage}}`.

### Generator test template (short)

```go
func TestBranches(t *testing.T) {
	cases := []struct {
		name string
		in   Model
		want string
	}{
		{"on", Model{Package: "p", EmitHello: true}, "func Hello"},
		{"off", Model{Package: "p", EmitHello: false}, "package p"},
	}
	for _, tc := range cases {
		t.Run(tc.name, func(t *testing.T) {
			got, err := render(tc.in)
			if err != nil {
				t.Fatal(err)
			}
			if !strings.Contains(got, tc.want) {
				t.Fatalf("got %q", got)
			}
			if tc.name == "off" && strings.Contains(got, "func Hello") {
				t.Fatal("false branch emitted Hello")
			}
		})
	}
}
```

This pattern closes the “worked on the happy path” hole.

## Summary

`if` branches without moving context; `with` branches **and** narrows `.`. Empty rules include 0 and empty slice — that is why bool flags and validation in Go often beat raw `if .Field`. Always leave a valid Go skeleton outside options. `$root` is an ally. The next lesson adds `range` — the same muscles for context, plus lists and commas.

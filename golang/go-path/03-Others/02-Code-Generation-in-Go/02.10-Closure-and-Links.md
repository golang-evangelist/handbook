# 02.10 Block closure: small codegen pipeline and further links

> **Go Path - Zero to Gopher** / **03 Others → Code Generation in Go** / Lesson 02.10

## Lesson goals

After this lesson you should be able to:

- assemble a full mini pipeline: source → model → template (+ FuncMap) → `format.Source` → file → `//go:generate`;
- optionally plug in AST extract where the source of truth is Go code;
- verify generated code in CI (generate + diff / golden);
- map what you learned in this block to concrete tools;
- know what to study next in the gRPC / protobuf block;
- distinguish **end of this course block** from the Go term **closure** (a function literal that captures variables)—if you need that in a generator.

## Prerequisite

- 02.01–02.09 (generate, tools, AST/flags per block, `text/template`, variables, conditionals, `range`, FuncMap).
- Go 1.22+.
- `go generate`, `go test`, basic `flag` package.

## Problem this lesson solves

Individual techniques without wiring stay exercises. In practice you need **one repeatable flow** everyone on the team runs the same way: same command, same pinned tools, same DO NOT EDIT output, same CI signal when someone forgets to regenerate.

This lesson pulls the “Code Generation in Go” block into a concrete pipeline and builds a bridge to gRPC/protobuf—where generators (`protoc`, plugins) follow the same mental model: IDL → model → emit.

## Mental model

```text
1. Source of truth     (Go type / JSON / proto later)
2. Extract          (manual, encoding/json, go/ast, protoc)
3. Model            (clean struct, exported fields)
4. Render           (text/template + FuncMap)
5. format.Source    (gofmt equivalent in-process)
6. Write *.gen.go   (atomically when possible)
7. go test / build
8. CI: generate + diff
```

`//go:generate` is the button that runs steps 2–6. Template lessons (02.05–02.09) live in step 4. AST (if you had it in the block) lives in step 2.

**Note on the filename:** “Closure” here means **end of this lesson block**, not Go **closure**. If your generator uses a function literal that captures variables, that is Go **closure**.

## Mechanism

This section is the heart of the lesson—full flow with concrete values, then CI, then a knowledge map and bridge to gRPC.

### One command as contract

Directive next to source:

```go
package status

//go:generate go run ./internal/cmd/gen -in status.go -out status_codes_gen.go

type Code int

const (
	OK Code = iota
	Fail
)
```

Contract for people and CI:

```text
go generate ./...
```

Or narrower:

```text
go generate ./internal/status
```

Pin: `go run` uses code in the repo—no separate binary version except the module itself. For external tools (`stringer`, `mockgen`) pin the version in `go.mod` tool dependency / docs.

### Skeleton `internal/cmd/gen`

```go
package main

import (
	"flag"
	"fmt"
	"os"
)

func main() {
	in := flag.String("in", os.Getenv("GOFILE"), "input")
	out := flag.String("out", "", "output")
	flag.Parse()
	if *in == "" || *out == "" {
		fmt.Fprintln(os.Stderr, "need -in and -out")
		os.Exit(2)
	}
	if err := run(*in, *out); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
}
```

`GOFILE` / `GOPACKAGE` are set by `go generate`—useful when the directive lives in the same package. Explicit `-in`/`-out` is clearer in review.

### Step extract → model

Three typical variants:

| Source | Extract | Model |
|--------|---------|-------|
| JSON schema | `json.Unmarshal` | `Model{...}` |
| Go constants | `go/ast` + `go/parser` | `[]Value` |
| Manual list | Go literal in gen | same |

For this block closure, a **manual or JSON** model is enough; AST is an optional boost when truth lives in a `.go` file.

### Step render

```go
t, err := template.New("gen").Funcs(funcs).Parse(tpl)
// Execute → bytes.Buffer
```

Apply everything from 02.06–02.09: `$root`, conditionals, `range`, FuncMap. Do not invent new template language here—wire it together.

### Step format and write

```go
formatted, err := format.Source(buf.Bytes())
if err != nil {
	return fmt.Errorf("format: %w\n--- generated ---\n%s", err, buf.Bytes())
}
return os.WriteFile(out, formatted, 0o644)
```

Including the raw buffer in the error message saves hours—you see what the template emitted before `gofmt` fails.

**Predict, then check:** template emits `packageapi` (stuck together). What does `format.Source` return?

**Answer:** error. The generator must not write a half-broken file “so CI passes”—better to stop.

### Atomic write (recommended)

Write to `out + ".tmp"` then `os.Rename`. Reduces the chance a interrupted generate leaves an empty/half `.go` file.

### Trace: complete mini flow with numbers

Source of truth (simplified in gen):

```go
model := Model{
	Package: "status",
	Name:    "Code",
	Values:  []string{"OK", "Fail"},
}
```

Template (shortened):

```
// Code generated; DO NOT EDIT.
package {{.Package}}

func (c {{.Name}}) String() string {
	switch c {
{{- range .Values }}
	case {{.}}:
		return "{{.}}"
{{- end }}
	default:
		return "{{.Name}}(" + strconv.Itoa(int(c)) + ")"
	}
}
```

Steps:

1. `go generate` runs `go run ./internal/cmd/gen ...`
2. `run` builds model (here hardcoded / AST / JSON)
3. `Execute` fills buffer
4. `format.Source` fixes indentation
5. Write `status_codes_gen.go`
6. `go test ./...` uses `String()`

### Optional AST extract (tie-in with earlier lessons)

If truth is:

```go
const (
	OK Code = iota
	Fail
)
```

Parser:

1. `parser.ParseFile` with `parser.SkipObjectResolution` or full mode as needed
2. Walk `ast.File` for `const` block of type `Code`
3. Fill `model.Values` in order
4. Same render from there

AST does not replace the template—it **feeds** the model. The template does not parse Go.

### “Ready pipeline” checklist

1. One entry command in README (`go generate ./...` or specific path).
2. Pin tool / module versions.
3. DO NOT EDIT on output.
4. Deterministic order (sort keys, stable `range`).
5. `format.Source` / `gofmt`.
6. Test or snapshot/golden.
7. CI: regenerate + `git diff --exit-code`.

If point 7 is missing, discipline falls apart within two weeks.

### CI diff — PowerShell

```powershell
go generate ./...
git add -A
git diff --cached --exit-code
if ($LASTEXITCODE -ne 0) {
  Write-Error "generated files are not up to date"
  exit 1
}
```

On Unix CI often:

```text
go generate ./...
git diff --exit-code
```

Same idea: working tree must stay clean after generate.

### Snapshot / golden test

```go
func TestGenStable(t *testing.T) {
	got, err := runToString("testdata/in.go")
	if err != nil {
		t.Fatal(err)
	}
	want, err := os.ReadFile("testdata/out.golden")
	if err != nil {
		t.Fatal(err)
	}
	if string(got) != string(want) {
		t.Fatalf("diff:\n got=%s\nwant=%s", got, want)
	}
}
```

Golden lives in git. When you intentionally change emit, update golden in the same PR.

### Predict, then check: forgotten generate

Developer changes `Fail` to `Error` in const, commits source only, does not run generate. CI?

**Answer:** `go generate` + diff fails—generated still has `Fail`. That is the desired signal, not noise.

### When **not** to write your own generator

- A maintained tool exists (`stringer`, `mockgen`, `protoc-gen-go`) that does the job.
- Source of truth is already `.proto`—go to the gRPC/protobuf ecosystem.
- One-off transform—manual PR is cheaper than a generator.

Your own pipeline makes sense when the domain is specific and repeats.

### Closure in a generator (Go term, English)

Sometimes FuncMap or extract uses a function literal:

```go
sort.Slice(fields, func(i, j int) bool {
	return fields[i].Name < fields[j].Name
})
```

That is **closure** (function literal referring to surrounding variables—here `fields`). It has nothing to do with “end of block” in the lesson title. In course text for that Go concept use **closure**, not a Serbian substitute on the forbidden list.

### Determinism—repeat because it breaks CI

Sources of nondeterminism:

- `map` iteration in Go when building model without sort
- `time.Now` in generated file header comment
- unstable file order from `filepath.Glob` on different OS (sort paths)
- random order in parallel goroutines writing same out (avoid parallel write to same out)

**Trace:** two local generates in a row, then `git diff`—must be empty.

### README snippet (copy into project)

```text
## Code generation

- Source: status.go (const Code)
- Command: go generate ./internal/status
- Output: status_codes_gen.go (DO NOT EDIT manually)
- CI: generate + git diff --exit-code
```

Ten lines save onboarding.

### Bridge to gRPC block

Next course block (03 gRPC):

- **IDL** (`.proto`) = source of truth (like your JSON/Go const here)
- **protoc** + plugin = extract + render (often without your `text/template`, but same mental model)
- **HTTP/2** + RPC = transport
- Generated stubs = `*.pb.go`—same DO NOT EDIT discipline

What you carry forward:

1. Do not edit generated manually.
2. Pin tools.
3. CI checks freshness.
4. Model between source and emit must be clean.
5. Determinism.

When you see `protoc-gen-go`, you recognize steps 2–6 from this lesson in someone else’s code.

### Predict, then check: mixing tools

Repo has both `go generate` for stringer and a manual script overwriting the same file. What happens?

**Answer:** last-writer-wins chaos; flaky CI. One owner per output file.

### Pipeline errors—diagnostic order

1. Does `go run ./internal/cmd/gen` work alone?
2. Does the model look right (`t.Logf("%#v", model)`)?
3. Does raw Execute (without format) look sensible?
4. Does `format.Source` report an error?
5. Does CI actually run the same generate?

Do not start with “template is broken” until you see the model.

### Brief note on `embed` templates in pipeline

```go
//go:embed stringer.tmpl
var stringerTpl string
```

Pros: one binary/`go run` carries template. Cons: template change = rebuild gen tool. For small internal gen—OK.

### Tie-in with package tests

Generated code must compile with hand-written code. Often:

```text
status.go          // type + const + go:generate
status_codes_gen.go // String() / methods
status_test.go      // tests behavior, not template
```

Behavior test ≠ template golden. Both have a place.

## Rules and syntax

Checklist for a finished pipeline:

1. Documented command
2. Pin tools
3. DO NOT EDIT
4. Determinism
5. `format.Source`
6. Golden or equivalent
7. CI diff

CLI:

```text
go run ./internal/cmd/gen -in ... -out ...
//go:generate go run ./internal/cmd/gen -in $GOFILE -out ...
```

Do not mix two generators on the same out. Do not commit manual “hotfix” edits in gen files.

### Example 5 — run() with format error

```go
func run(in, out string) error {
	model, err := extract(in)
	if err != nil {
		return err
	}
	var buf bytes.Buffer
	if err := tmpl.Execute(&buf, model); err != nil {
		return err
	}
	formatted, err := format.Source(buf.Bytes())
	if err != nil {
		return fmt.Errorf("format: %w\n%s", err, buf.Bytes())
	}
	return os.WriteFile(out, formatted, 0o644)
}
```

#### What happens here

Extract → render → format → write. Error carries raw text.

### Example 6 — README + DO NOT EDIT

```
// Code generated by internal/cmd/gen; DO NOT EDIT.
```

#### What happens here

Signal for people and tools. Align with README command.

### Example 7 — Sort before render

```go
sort.Strings(model.Values)
```

#### What happens here

Determinism when Values come from map/set.

## Decision analysis

| Decision | Choose when... | Avoid when... |
|--------|--------------|------------------|
| Custom gen | domain-specific | good standard tool exists |
| AST extract | truth in Go code | truth already in JSON/proto |
| JSON input | external system | duplicating Go types |
| Golden + CI diff | team >1 | solo experiment without CI |
| `go run` gen | small internal tool | slow generate—then installed binary |

## Trade-offs

- **AST vs manual model:** less drift vs more extract code.
- **Embed tpl vs file:** portability vs quick edit without rebuild.
- **Strict CI diff:** discipline vs friction when emit changes often.
- **One monolithic gen vs several small:** clarity vs repeated factory code.

## Common mistakes

1. **Wrong:** commit source without regenerate.  
   **Effect:** CI diff fails or production carries old code.  
   **Why:** output not fresh.  
   **Correct:** `go generate` + CI check.

2. **Wrong:** manual hotfix in `*_gen.go`.  
   **Effect:** next generate wipes fix.  
   **Why:** file is not source of truth.  
   **Correct:** change generator or input.

3. **Wrong:** nondeterministic order (map without sort).  
   **Effect:** flaky diff.  
   **Why:** unstable model.  
   **Correct:** sort / slice.

4. **Wrong:** swallow `format.Source` error, write raw.  
   **Effect:** invalid Go in git.  
   **Why:** no fail-fast.  
   **Correct:** return error; do not write.

5. **Wrong:** two tools write same out.  
   **Effect:** last-writer chaos.  
   **Why:** no single owner.  
   **Correct:** one generator per file.

6. **Wrong:** no README command.  
   **Effect:** “works on my machine” / wrong generate.  
   **Why:** undocumented contract.  
   **Correct:** 10 lines in README.

7. **Wrong:** `time.Now` in generated header.  
   **Effect:** always dirty diff.  
   **Why:** nondeterminism.  
   **Correct:** drop time or fixed tool version string.

8. **Wrong:** mixing block closure with Go closure in team docs.  
   **Effect:** onboarding confusion.  
   **Why:** same word in different languages/contexts.  
   **Correct:** for Go use **closure**; for block end say “block closure / pipeline wrap-up”.

## Idiomatic Go

- `internal/cmd/gen` as small Main for generate.
- DO NOT EDIT + `format.Source`.
- Golden + `go test`.
- CI generate + diff.
- One owner per output file.
- Sort for stability.
- README contract.
- Function literal / **closure** only where it helps (e.g. `sort.Slice`), not as “architecture”.

## Practical scenario

Team has three generators: stringer-like, mock, and “helpers”. Nobody documented order. Developer runs only one, commits, CI sometimes fails. They introduce:

1. `go generate ./...` as the only command
2. CI step the same
3. README table source→tool→output
4. ban manual edits to gen files in review checklist

“Forgot generate” incident rate drops. Second PR: someone adds timestamp in header—diff explodes. They remove timestamp; keep `// Code generated by internal/cmd/gen; DO NOT EDIT.`

When they move to gRPC, same discipline applies to `protoc` output—only the button differs.

## Check questions

1. **What are the steps of the mini pipeline?**  
   Source → extract → model → render → format → write → test/CI.

2. **What is CI generate + diff for?**  
   Catches forgotten regenerate.

3. **Where does type naming logic live?**  
   FuncMap / Go adapter—not manual edit of gen file.

4. **Why `format.Source` before write?**  
   More valid Go + less style noise; error exposes bad emit.

5. **What do you carry into gRPC block?**  
   IDL as truth, DO NOT EDIT, pin, CI freshness, clean model.

6. **What is closure in Go?**  
   Function literal that captures surrounding variables—not “end of lesson”.

7. **Why one owner per out file?**  
   Prevents last-writer chaos.

8. **What if `format.Source` fails?**  
   Do not write; return error with raw buffer.

### Detailed trace: files on disk after successful generate

Assume module `example.com/shop`, package `internal/status`:

```text
internal/status/status.go              // source + //go:generate
internal/status/status_codes_gen.go    // output
internal/cmd/gen/main.go               // tool
internal/cmd/gen/template.go           // FuncMap + Parse
```

Commands to know by heart:

```text
go generate ./internal/status
go test ./internal/status
go test ./internal/cmd/gen
```

If `cmd/gen` has no tests, at least smoke `package main` via `go run` in docs.

### In more detail: what CI should cache

Cache Go module download and build cache—**do not** cache generated output as artifact replacing generate. Generate must run. Cache tools (`protoc` later) with pinned version.

### Predict, then check: exit codes

`flag` error → exit 2. `extract`/`Execute`/`format` error → exit 1. Success → 0. Why split 1 and 2?

**Answer:** scripts and CI can distinguish “bad usage” from “generator failed on input”. Not mandatory, but useful hygiene.

### How to explain pipeline to a new member in 3 minutes

1. Show `status.go` const.
2. Show directive.
3. Run `go generate`.
4. Open diff on `*_gen.go`.
5. Say: “you do not edit this; you edit input or gen”.
6. Show CI step.

If they still edit gen files after that, checklist in PR template is not optional.

### Tie-in to reflection / other blocks

Reflection (other course) sometimes replaces generate for small things at runtime. Tradeoff: speed, type clarity, binary size. This lesson does not judge—only: **if** you choose generate, finish pipeline through CI.

### Repeat forbidden traps from template lessons

In wired pipeline these still apply:

- unexported model fields
- `.` vs `$` in `range`
- `Funcs` before `Parse`
- trailing comma
- empty `0` trap

Pipeline does not forgive old mistakes—it runs them more often.

### In more detail: atomic write in practice

```go
tmp := out + ".tmp"
if err := os.WriteFile(tmp, formatted, 0o644); err != nil {
	return err
}
return os.Rename(tmp, out)
```

On Windows `Rename` over existing file sometimes needs remove target first—adapt helper. Point remains: do not leave empty out after mid-write failure.

### In more detail: what to put in generated file header

Good:

```
// Code generated by internal/cmd/gen; DO NOT EDIT.
```

Bad:

```
// Generated on 2026-09-26T00:11:00Z by SomeName
```

Timestamp and hostname break diff. Tool version (`// Code generated by internal/cmd/gen; version 3`) OK if changed rarely and intentionally.

### Predict, then check: only `go test` without generate in CI

Tests pass because old generated still compatible with new const name? Possible short-term. Then someone uses new constant in another package—it breaks. CI diff catches earlier. **Answer:** `go test` alone is not a substitute for generate+diff.

### Table: symptom → suspect

| Symptom | Suspect first |
|---------|----------------|
| flaky diff | map / time / file order |
| format error | trim / wrong token / empty package |
| “field does not exist” | `.` context / export |
| unknown function | `Funcs` after `Parse` |
| CI red, local green | different generate command / workdir |

### Short “definition of done” for PR with generator

- [ ] Input changed intentionally
- [ ] `go generate` run
- [ ] Generated diff reviewed (not blind accept)
- [ ] Golden updated if needed
- [ ] README still accurate
- [ ] No manual edits outside generate in `*_gen.go`

If one checkbox is missing, PR is not done—even when tests “pass”. That is discipline the gRPC block only amplifies with more generated files.

## Summary

This block ends by wiring: `//go:generate` runs extract and `text/template` render, `format.Source` cleans output, CI keeps discipline. AST is optional extract. Determinism and one file owner are not details—they are the product. Go **closure** is a separate language concept; block closure is pipeline wrap-up.

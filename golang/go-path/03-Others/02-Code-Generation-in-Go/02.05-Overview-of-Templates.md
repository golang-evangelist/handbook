# 02.05 Overview of templates for code generation

> **Go Path - Zero to Gopher** / **03 Others → Code Generation in Go** / Lesson 02.05

## Lesson goals

After this lesson you can:

- tell `text/template` apart from `html/template` and why codegen uses *text*;
- parse and execute a template over a Go struct / map;
- wire a template into a small generator with `go/format`;
- recognize template boundaries (it is not an AST transform);
- use basic pipeline actions and predict mistakes (unexported fields, HTML escape).

## Prerequisite

- 02.01–02.04.
- Basic Go `struct`, `map`, `io.Writer`.
- Go 1.22+.
- Preferably: a finished small AST extract from 02.03 (the model already exists).

## Problem this lesson solves

Emitting code through a pile of `fmt.Fprintf` quickly becomes unreadable. A template separates the *shape of the output* from the *data-collection logic*. The wrong choice (`html/template`) injects escape that breaks Go source (`&lt;` instead of `<`). This lesson sets the foundation: `text/template` + model + `format.Source`, plus an intro to pipelines.

## Mental model

```text
  model (struct / map / slice)
       +
  template text  ({{ ... }})
       │
       ▼
  Parse → Execute(writer, model)
       │
       ▼
  raw Go text  →  format.Source  →  *.gen.go
```

The template sees data through the “dot” context (`.`). Actions are in `{{ ... }}`.

**Important:** for HTML pages → `html/template` (escape). For `.go` / `.md` / `.yaml` codegen → `text/template`.

### Glossary table

| Term (English) | Meaning |
|----------------|---------|
| `text/template` | textual template without HTML escape |
| `html/template` | same language + contextual HTML escape |
| `{{.}}` | current context (dot) |
| `Parse` / `Execute` | load template / render |
| pipeline | chain `input \| func \| func` in an action |
| `define` / `template` | named parts |
| `{{-` `-}}` | trim whitespace around the action |
| model | Go value that Execute receives |

## Mechanism

### 1. Minimal Parse + Execute

```go
import "text/template"

tpl, err := template.New("file").Parse(codeTpl)
if err != nil {
	return err
}
err = tpl.Execute(w, data)
```

`New` gives a name (useful for errors and `define` sets). `Must` wraps a panic on error — OK in `main`/`init`, not in libraries.

### 2. Trace: from a map to a Go file

```go
const tpl = `// Code generated; DO NOT EDIT.

package {{.Package}}

const Answer = {{.Answer}}
`
t := template.Must(template.New("a").Parse(tpl))
_ = t.Execute(os.Stdout, map[string]any{
	"Package": "demo",
	"Answer":  42,
})
```

**Trace**

```text
Parse      → compiles template AST (template language, not Go)
Execute    → . = map
{{.Package}} → "demo"
{{.Answer}}  → 42
stdout:
  // Code generated...
  package demo
  const Answer = 42
```

### 3. Predict, then check: why not `html/template`

```go
import "html/template"

t := template.Must(template.New("x").Parse(`var S = "{{.S}}"`))
_ = t.Execute(os.Stdout, map[string]string{"S": "a<b"})
```

**Predict:** Output?

**Check:** something like `var S = "a&lt;b"` — **invalid** Go if you expect a literal `<`. HTML escape protects the browser, not the compiler.

For codegen always:

```go
import "text/template"
```

### 4. Struct as model

```go
type FileModel struct {
	Package string
	Types   []string
}
```

The template sees **exported** fields (`Package`, `Types`). Unexported `packageName` is invisible (empty / error depending on use).

**Predict:**

```go
type FileModel struct{ packageName string }
// {{.packageName}}
```

**Check:** Does not work as you expect for external access via template reflection — use `Package string`.

### 5. Pipeline — intro

A pipeline passes a value through functions:

```
{{.Name | printf "%q"}}
{{.Items | len}}
```

Built-in functions you often need in codegen:

| Function | Use |
|----------|-----|
| `printf` | format / quoting |
| `len` | length |
| `index` | index into slice/map |
| `slice` | subslice (rarer) |
| `eq` / `ne` / … | comparisons (more in 02.07) |

Do not build a DSL of 40 `FuncMap` functions on day 1 — that is 02.09.

### 6. Trace: pipeline step by step

```
{{.Name | printf "%q"}}
```

```text
1. take .Name  → e.g. Idle
2. pass to printf with format %q
3. output: "Idle"  (with quotes, escaped)
```

Useful when you emit string literals in Go code.

### 7. Predict, then check: `len` over a nil slice

```go
data := FileModel{Package: "p", Types: nil}
```

```
{{len .Types}}
```

**Predict:** Error or `0`?

**Check:** `0`. Design the template for a zero-value model — generate often runs even when the list is empty.

### 8. Whitespace trim

```
{{- .Name -}}
```

`-` next to `{{` / `}}` eats whitespace/newlines on that side. Useful for aligning generated code.

**Predict, then check:** Over-aggressive trim

```
package{{- .Package -}}
```

with `Package = "demo"` can glue `packagedemo` — broken Go syntax.

**Check:** Trim deliberately; leave a space in the template where Go requires it:

```
package {{.Package}}
```

### 9. `define` and `template`

```
{{define "header"}}
// Code generated; DO NOT EDIT.
package {{.Package}}
{{end}}

{{template "header" .}}

func Hello() string { return "hi" }
```

**Trace**

```text
Parse loads define "header"
template "header" .  → executes the named part with the current context
the rest of the template renders after
```

The same header is shared across multiple outputs in one `template.New` set (`Parse` of multiple strings / files).

### 10. render helper with format

```go
func render(tpl string, data any) ([]byte, error) {
	t, err := template.New("out").Parse(tpl)
	if err != nil {
		return nil, err
	}
	var raw bytes.Buffer
	if err := t.Execute(&raw, data); err != nil {
		return nil, err
	}
	return format.Source(raw.Bytes())
}
```

**Trace**

```text
Execute → raw bytes (maybe ugly)
format.Source → gofmt
format error → emit is not valid Go
```

### 11. Predict, then check: error in Execute

```
{{.Missing.Field}}
```

over a map without the key / a nil pointer chain.

**Predict:** Panic or `error`?

**Check:** `Execute` returns `error` (in typical cases) — handle it. Test the template with a typical and an empty model.

### 12. Where to keep template text

| Place | When |
|-------|------|
| raw string in `.go` | up to ~50 lines |
| `*.tmpl` next to the generator | longer, review-friendly |
| `//go:embed` | one binary, file does not vanish on install |

```go
//go:embed file.tmpl
var fileTpl string
```

### 13. Trace: embed in the generator

```text
go build ./internal/cmd/gen
  → file.tmpl sewn into the binary
CI runs gen without special .tmpl copying
Parse(fileTpl)
Execute(...)
```

### 14. Prepare the model in Go, not in the template

Bad: complex `{{if}}` chains that compute business rules.

Better:

```go
m := FileModel{
	Package: pkg,
	Types:   filterExported(names),
}
return render(fileTpl, m)
```

The template only draws. Logic lives in testable Go code.

### 15. Predict, then check: map vs struct

```go
map[string]any{"package": "demo"}  // lowercase p
// template: {{.Package}}
```

**Predict:** Output?

**Check:** Empty / problem — map keys are case-sensitive; `package` ≠ `Package`. Struct fields are a clearer contract.

### 16. Basic `range` (preview; details in 02.08)

```
var Types = []string{
{{- range .Types }}
	{{ printf "%q" . }},
{{- end }}
}
```

**Trace**

```text
range .Types
  . becomes the element
  printf %q .  → "Idle"
after end, . returns (per range rules)
```

Enough to see why a template scales; do not learn every `range` edge here.

### 17. Predict, then check: empty `range`

`Types` is `nil` or empty.

**Predict:** Does invalid Go appear?

**Check:** With the template above you get

```go
var Types = []string{
}
```

which is valid. Watch templates that emit trailing-comma problems in older contexts — in a Go composite literal a trailing comma is OK.

### 18. Comments in the template

```
{{/* this is not emitted into the output */}}
```

Use for notes to the template reviewer, not for Go comments in the output (write those literally as `// ...` outside actions).

### 19. Trace: HTML escape error in review

```text
PR diff in foo.gen.go:
  case A:
    return "x &lt; y"
```

**Trace of diagnosis**

```text
1. see &lt;
2. check the import in the generator
3. html/template → replace with text/template
4. regenerate
5. return "x < y"  (if you need that string)
```

### 20. File layout

```text
/internal/cmd/gen/
  main.go
  model.go
  render.go
  tmpl/
    file.tmpl
    method.tmpl
```

Embed or `os.ReadFile` — pick one and be consistent.

### 21. Predict, then check: `template.Must` in a library

```go
// package genlib
var t = template.Must(template.New("x").Parse("{{"))
```

**Predict:** When does it blow up?

**Check:** At package init — panic in the import chain. In libraries return `error` from `Parse`; leave `Must` for `main`.

### 22. Test the template without disk

```go
func TestPackageLine(t *testing.T) {
	out, err := render(`package {{.Package}}`+"\n", map[string]string{"Package": "p"})
	if err != nil || !strings.Contains(string(out), "package p") {
		t.Fatalf("%v %q", err, out)
	}
}
```

**Trace:** fast feedback; no `WriteFile` in the unit test.

### 23. Link with AST extract (02.03)

```text
GOFILE → ParseFile → extract → FileModel
FileModel → text/template → format.Source → WriteFile
```

A template **does not replace** the parser. It replaces unreadable `Fprintf` emit.

### 24. Predict, then check: two template packages with the same name

```go
import (
	"html/template"
	"text/template"
)
```

**Predict:** Does it compile?

**Check:** Name conflict on `template`. Use an alias:

```go
import (
	htmltemplate "html/template"
	"text/template"
)
```

In a codegen file you most often do not import `html/template` at all.

### 25. Bar for a “good enough” template

- Readable for a reviewer without running it.
- Zero-value model yields valid Go.
- No business logic in a forest of `{{if}}`.
- After `format.Source` the package compiles.
- Template name (`New("file")`) makes sense in errors.

### 26. Trace: from Fprintf chaos to a template

```text
v1: 400 lines of Fprintf in one file
  → bug in a brace, hard to review
v2: FileModel + 3 templates (header, types, methods)
  → mapping bugs in Go code
  → output shape in .tmpl
v3: format.Source + snapshot test
  → CI catches shape drift
```

### 27. Pipeline + `printf` for identifiers vs strings

Identifier in code:

```
func {{.Name}}() {}
```

String literal:

```
return {{.Name | printf "%q"}}
```

**Predict:** If you inject an invalid identifier into the first form?

**Check:** `format.Source` / the compiler fails. Name validation belongs in Go code *before* Execute, not in the template.

### 29. Predict, then check: Execute into `bytes.Buffer` then string

```go
var buf bytes.Buffer
_ = t.Execute(&buf, data)
s := buf.String()
```

Valid. For Go codegen immediately run through `format.Source(buf.Bytes())` before write.

### 30. Anti-pattern: a template generating a template without discipline

Possible, but painful to debug. If you must, keep clear boundaries and tests. For this course — one level: Go generator + `text/template` → Go source.

### 31. Predict, then check: `ExecuteTemplate` vs `Execute`

You have a `define` set with `"header"` and `"body"`. You call `t.Execute(w, data)`.

**Predict:** What gets drawn?

**Check:** The default template (the one named from `New` / the first) — not all `define`s automatically. For a named part use `ExecuteTemplate(w, "header", data)` or an explicit `{{template "header" .}}` in the root template.

### 32. Trace: whitespace and `gofmt`

```text
template emits odd indentation
format.Source still cleans it up
but: format.Source does NOT fix wrong type names
nor logical bugs in the model
```

`gofmt` is not a type-check. After format still run `go test`.

### 33. Mini checklist before merging a generator with a template

- [ ] `text/template`, not `html/template`
- [ ] exported model fields
- [ ] `DO NOT EDIT`
- [ ] `format.Source`
- [ ] test with a fixture model (including empty)
- [ ] package compiles after generate

### 34. Predict, then check: `{{.Types}}` without `range`

```
var Types = {{.Types}}
```

where `Types` is `[]string{"A"}`.

**Predict:** Valid Go?

**Check:** No — the default print of a slice is not a Go literal. Use `range` + `printf "%q"` or prepare a finished string in the model (rarer).

### 35. Link with go generate env

The same `render` helper works in a generator that reads `GOPACKAGE`:

```go
m := FileModel{Package: mustEnv("GOPACKAGE"), Types: names}
return render(fileTpl, m)
```

The template does not know about env — the model carries already-resolved values.

## Rules and syntax

| Element | Example |
|---------|---------|
| Action | `{{ .Name }}` |
| Comment | `{{/* note */}}` |
| Trim | `{{- .Name -}}` |
| Pipeline | `{{ .Name \| printf "%q" }}` |
| Named | `{{ define "x" }}...{{ end }}` |
| Include | `{{ template "x" . }}` |

Basic wrapper:

```go
t, err := template.New("gen").Parse(`package {{.Package}}`)
```

## Examples

### Example 1: Smallest codegen template

See mechanism §2. After this, in a real generator call `format.Source`.

### Example 2: Struct model + list (preview range)

```go
type FileModel struct {
	Package string
	Types   []string
}

const listTpl = `package {{.Package}}

var Types = []string{
{{- range .Types }}
	{{ printf "%q" . }},
{{- end }}
}
`
```

#### What happens here

`FileModel` carries an exported package name and a slice of type names. The raw string is the template: it prints `package` plus `.Package`, then a variable `Types`. `range` walks `.Types`, and `printf "%q"` quotes each element as a Go string. The minus signs on `{{-` and `-}}` trim whitespace beside the loop so the composite literal stays compact.

See mechanism §3. Compare byte-for-byte with `text/template` for input `a<b&c`.

### Example 4: `render` helper

See mechanism §10. Drop it into the generator from 02.03 instead of a hand-built `Builder` format (or keep Builder for small bits).

### Example 5: `define` blocks

### Example 6: Predict, then check — unexported field

```go
type M struct{ name string }
t.Execute(w, M{name: "x"})
// {{.name}} or {{.Name}}
```

#### What happens here

The field on `M` is the unexported name `name`, and `Execute` receives a value holding `x`. The comment shows the two actions `.name` and `.Name`. Template lookup uses exported fields, so `.Name` does not read this lowercase field. Renaming the field to `Name` is what lets `.Name` print `x`.

**Check:** You do not get a reliable `"x"` via `.Name`; export `Name`.

### Example 7: embed file

```go
//go:embed file.tmpl
var fileTpl string

func gen(m FileModel) ([]byte, error) {
	return render(fileTpl, m)
}
```

#### What happens here

`//go:embed file.tmpl` stores that file's bytes in the string `fileTpl` when the package is compiled. `gen` passes the string and a `FileModel` to `render`. The template text lives in `file.tmpl`. This function only supplies the model and returns whatever `render` produces.

### Example 8: Empty model test

```go
func TestEmptyTypes(t *testing.T) {
	out, err := render(listTpl, FileModel{Package: "p"})
	if err != nil {
		t.Fatal(err)
	}
	pkg := "package p\n"
	if !bytes.Contains(out, []byte(pkg)) {
		t.Fatalf("%s", out)
	}
}
```

#### What happens here

`TestEmptyTypes` renders `listTpl` with a `FileModel` whose package is `p` and whose `Types` slice is nil. A non-nil error fails the test. The output must contain the bytes `package p` followed by a newline. That asserts the package clause while `range` has no elements to print.

### Example 9: Pipeline `printf`

```
const Label = {{.Label | printf "%q"}}
```

#### What happens here

The action is a pipeline: `.Label` is the last argument of `printf` with format `%q`. `%q` writes a quoted Go string and escapes quotes and other special characters inside it. The surrounding text stores that literal in `const Label`. A value such as `he said "hi"` stays a single valid string literal.

**Trace:** Label `he said "hi"` → correct Go string literal with escape.

### Example 10: Two templates in one set

```go
t := template.New("root")
template.Must(t.New("header").Parse(`package {{.Package}}`+"\n"))
template.Must(t.New("body").Parse(`var X = 1`+"\n"))
// execution: t.ExecuteTemplate(w, "header", m) etc.
```

#### What happens here

`template.New("root")` creates a template set named root. `t.New("header")` and `t.New("body")` add two templates to that set, one printing a package clause and one printing `var X = 1`. `template.Must` stops the program if either parse returns an error. `ExecuteTemplate` runs one of those names against the model.

### Example 11: Predict, then check — `&` in a string

Model input: `S = "a&b"`.

| Package | Expected fragment in output |
|---------|------------------------------|
| `text/template` | `a&b` |
| `html/template` | `a&amp;b` (often) |

If you see `&amp;` in a `.go` file — wrong template package.

### Example 12: Short “before / after” emit

**Before (Fprintf):**

```go
fmt.Fprintf(&b, "package %s\n\n", pkg)
for _, n := range names {
	fmt.Fprintf(&b, "\t%q,\n", n)
}
```

#### What happens here

Each `fmt.Fprintf` appends text straight to the buffer. The first call writes the `package` line from `pkg`. The loop writes one quoted name per entry, with a tab and a trailing comma. The shape of the generated file is those format strings in Go.

**After (template):** shape in `.tmpl`, loop in `range`, Go code only fills `FileModel`. The reviewer reads the template as a specification.

## Decision analysis

**Template vs pure fmt** — template when the shape has repetition and branches; fmt when it is 5 lines.

**Template vs AST rewrite** — template for emit; AST for *reading* input.

**Embed vs ReadFile** — embed for a distributable CLI generator; ReadFile OK in `go run` ignore scripts.

**FuncMap right away?** — no. First model + built-ins; `FuncMap` in 02.09.

## Trade-offs

| Approach | Advantage | Cost |
|----------|-----------|------|
| `text/template` | readable shape | errors at runtime Execute |
| `html/template` | safe HTML | breaks codegen |
| Fprintf only | simple | unsustainable |
| DSL generator | power | complexity |
| lots of logic in the template | fewer Go files | untestable |

## Common mistakes

1. `html/template` for `.go` output.
2. Unexported struct fields — empty output / error.
3. Forgotten `format.Source`.
4. Mixing domain logic inside the template instead of in Go code before Execute.
5. Trim `{{-` that glues tokens and breaks Go syntax.
6. `template.Must` in a library `init` with a bad string.
7. Case mismatch of map keys (`package` vs `Package`).
8. Emitting an invalid identifier without validation in the model.

## Idiomatic Go

- Prepare the model in Go; the template only draws.
- `template.Must` only in `main` / `init` when failure must be loud.
- Name templates meaningfully (`file`, `method`, `imports`).
- Keep the template in a raw string or an embed file.
- After generate — compile the package.
- Test the zero-value model.
- One import: `text/template` for codegen.

## Practical scenario

The team generates a client SDK from an internal JSON schema description. First version: 400 lines of `Fprintf`. Reviewers cannot see the output shape. After refactor: `FileModel` + three templates (`header`, `types`, `methods`) + `format.Source`. Field-mapping bugs live in Go code (testable); they read the template as an output specification. Once someone imports `html/template` “because it is newer” — the CI snapshot immediately shows `&lt;` in a `.go` file; rollback to `text/template` in 5 minutes.

## Summary

`text/template` is the standard way for a generator to draw Go (and other text) from a model. Combine it with a clean model, careful trim, a basic pipeline, and `go/format`. Leave `html/template` for HTML. The next lessons deepen variables, branches, `range`, and `FuncMap`.

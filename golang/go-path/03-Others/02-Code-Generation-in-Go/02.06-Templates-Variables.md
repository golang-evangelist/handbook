# 02.06 Templates: variables

> **Go Path - Zero to Gopher** / **03 Others → Code Generation in Go** / Lesson 02.06

## Lesson goals

After this lesson you should be able to:

- explain what **dot** (`.`) is during `Execute` and how it changes in `with` / `range` (preview);
- read and write fields, map keys, and methods without arguments via `{{.Field}}`;
- introduce template variables with `{{$x := pipeline}}` and reassign with `{{$x = pipeline}}`;
- use `$` (root data) and an explicit `{{$root := .}}` inside loops;
- bind a **pipeline** to a variable (`{{$q := .Name | printf "%q"}}`) without magic;
- prepare the model in Go so the template stays short and resistant to path refactors.

## Prerequisite

- 02.05 (`text/template` basics: `Parse`, `Execute`, `Must`, trim `-`).
- Go 1.22+ (`go version`).
- Basic `struct`, exported fields, `map[string]T`, `bytes.Buffer`, `go/format`.

If you are not sure what `template.New("x").Parse(...)` does, go back to 02.05 before continuing — this lesson assumes the template already successfully renders a simple `package {{.Package}}`.

## Problem this lesson solves

In codegen the model quickly becomes deep:

```text
{{.File.Meta.Module.Package}}
{{.File.Meta.Module.Package}}
{{.File.Meta.Module.Package}}
```

The same path three times. A schema refactor moves `Package` — the template breaks in twelve places. The reviewer does not see intent, only noise.

Second problem: inside `range` or `with`, **dot moves**. A field you “always” read as `.Package` suddenly looks for `Package` on the loop element. Without a clear model of `.` vs `$`, errors look like “the template is broken,” when the context is actually wrong.

This lesson solves both: **aliases** (`$p`) shorten the path, **`$` / `$root`** preserve the root, **pipeline + variable** capture an intermediate result before it goes into the Go output.

## Mental model

Think of `Execute` as a walk over a data tree with a single cursor:

```text
Execute(data)
  .     = current context (at start = data)
  $     = the same data at the beginning (root), until you overwrite it yourself
  $name = your named value in scope
```

Text outside `{{...}}` is copied literally. Inside an action, the pipeline computes a value. If you write the action only as `{{pipeline}}`, that value goes to the output (like `fmt.Print`). If you write `{{$x := pipeline}}`, the value is **not printed** — it goes into `$x`.

A pipeline is a chain of commands linked with `|`. The result of the left command enters as the **last** argument of the right:

```text
{{ .Name | printf "%q" }}
→ printf("%q", .Name)
```

Variables live until the `{{end}}` of the control in which they were declared (`if` / `with` / `range`), or until the end of the template if there is no such control. A call `{{template "other" .}}` **does not inherit** your `$` variables — only the data you pass.

## Mechanism

This section is the heart of the lesson. Read slowly: every subsection has concrete values you can predict before running.

### Dot at the start of Execute

Assume the model:

```go
type Model struct {
	Package string
	Service string
}
data := Model{Package: "api", Service: "Order"}
```

Template:

```
package {{.Package}}
```

**Trace:** `Execute(w, data)` sets `. = data`. `.Package` reads the `Package` field → string `"api"`. Output: `package api`.

If you pass `map[string]any{"Package": "api"}`, `.Package` reads the **map key** `"Package"` (it does not have to be exported like a Go field — the key is a string).

### Fields, chains, methods without arguments

```
{{.Meta.Package}}
{{.Client.Name}}
{{.Version}}
```

The chain `.Meta.Package` means: take the `Meta` field, then on that result the `Package` field. If somewhere there is a `nil` pointer or a missing field, `Execute` returns an error.

Methods **without arguments** (niladic) look like fields:

```go
type S struct{ n int }

func (s S) Doubled() int { return s.n * 2 }
```

```
{{.Doubled}}
```

That is a call to `s.Doubled()`. If the method returns `(T, error)` and `error != nil`, execution stops. Methods **with** arguments are not done this way — for that you need `FuncMap` / `call` (02.09).

### Why an unexported field “does not exist”

```go
type model struct {
	packageName string
}
```

The template uses reflection. From another package (or even when the type is not exported as you expect in generator practice) unexported fields are not available as `.packageName` the way you expect from ordinary Go code in the same package. **Rule for codegen:** the model for the template has exported fields (`Package`, `Name`) or is `map[string]any`.

**Predict, then check:** template `{{.packageName}}`, data `model{packageName: "api"}` from `package main` in the same file. What do you expect?

In the same package reflection can still see unexported fields in some cases, but the idiom and portability of generators require **exported** fields. Do not rely on luck — export `PackageName` or use a map.

### Introducing `$` variables

Syntax:

```
{{$x := pipeline}}
```

The action **produces no output**. It only binds a name.

```
{{$pkg := .Package}}
package {{$pkg}}
const Name = "{{$pkg}}"
```

**Trace with concrete values:** `.Package = "billing"`. After `{{$pkg := .Package}}`, `$pkg` holds `"billing"`. Both places in the text print `billing`. Refactor: change only the right-hand side of the assignment if the model path changes.

Reassignment (to an existing variable):

```
{{$x := .A}}
{{$x = .B}}
```

`:=` initializes; `=` assigns to an already declared one. Mixing without understanding yields a parse error or shadowing in an inner scope.

### What bare `$` is (without a name)

At the start of execution `$` is set to the **same** data as the initial `.` — the `Execute` argument. That is why inside a loop you often see:

```
{{range .Types}}
{{$.Package}}.{{.}}
{{end}}
```

Inside, `.` is the element; `$.Package` still reads the root model.

**Predict, then check:** root `Model{Package:"api", Types:[]string{"A","B"}}`. Inside `range`, what is `.Package`?

**Answer:** an error or empty behavior depending on the element type — `string` has no `Package` field. You need `$.Package` or ahead of time `{{$p := .Package}}` before the loop, then `{{$p}}` inside.

### Explicit `$root` — clearer than “magic” `$`

At the top of the template:

```
{{$root := .}}
{{range .Methods}}
func (c *{{$root.Service}}Client) {{.Name}}() {}
{{end}}
```

A new team member sees `$root` and does not have to memorize a special rule for bare `$`. An idiom in larger codegen templates.

### Pipeline that fills a variable

```
{{$q := .Name | printf "%q"}}
var Label = {{$q}}
```

**Trace:** `.Name = "Order"`. Pipeline: `printf("%q", "Order")` → Go representation with quotes, e.g. `"Order"`. `$q` holds that string. Output: `var Label = "Order"` (with correct quoting).

Without a variable:

```
var Label = {{.Name | printf "%q"}}
```

Same, but when the same quoting is needed in three places, `$q` prevents repetition and typos.

### `index` and map access

For a map with a dynamic key (not an identifier):

```
{{index .Attrs "go_package"}}
{{$g := index .Attrs "go_package"}}
```

`.Attrs.go_package` works only if the key is a valid identifier in template syntax. For keys with a hyphen or odd names — `index`.

**Predict, then check:** `Attrs = map[string]string{"go_package":"example.com/api"}`. What does `{{$g := index .Attrs "go_package"}}{{$g}}` print?

**Answer:** `example.com/api`.

### Scope and shadowing

```
{{$x := .A}}
{{range .Items}}
  {{$x := .}}
  {{/* here $x is the element, not .A */}}
{{end}}
{{/* here $x is .A again — the inner declaration ended with end */}}
```

The inner `{{$x := .}}` shadows the outer one only inside the `range` block. After `{{end}}`, the outer `$x` remains. Still: **do not intentionally shadow** the same short aliases — use `$item`, `$field`, `$m`.

### Dot does not change by itself with ordinary `{{$x :=}}`

```
{{$p := .Package}}
{{.Service}}
```

After the assignment, `.` is still the whole model. Only `$p` holds the package string. Opposite of `with` (next lesson), which **moves** `.`.

### Methods and errors in the pipeline

If a pipeline step returns `(value, error)` and error is not nil, `Execute` stops. That is why transformations that can fail (unknown type → Go type) often live in `FuncMap` with a clear error (02.09), and the variable captures the successful result:

```
{{$t := goType .Proto}}
{{$t}}
```

### Trim and variables — do not glue tokens

```
package {{- $pkg -}}
```

Trim strips whitespace around the action. If `$pkg` prints `api`, you can get `packageapi` without a space — invalid Go. For identifiers usually:

```
package {{$pkg}}
```

with a space in the template text, not aggressive trim on both sides of the name.

### Preparation in Go vs computation in the template

The template can do a little (`printf`, `index`, `len`). **Do not** do complex type-name joining in five steps inside the template. Better:

```go
type Method struct {
	Name     string
	FullName string // already "OrderCreate"
}
```

```
func (c *Client) {{.FullName}}() {}
```

Variables in the template are for **alias and intermediate display results**, not for business naming logic.

### Trace: a whole small flow from model to string

Model:

```go
m := struct {
	Package string
	Name    string
}{Package: "demo", Name: "Hook"}
```

Template:

```
{{$n := .Name}}
package {{.Package}}

type {{$n}} struct{}
func New{{$n}}() *{{$n}} { return &{{$n}}{} }
```

Step by step:

1. `. = m`, `$ = m`.
2. `$n := "Hook"`.
3. Text `package ` + `.Package` → `package demo`.
4. `type Hook struct{}`.
5. `func NewHook() *Hook { return &Hook{} }`.

One change to `.Name` changes all three places where `$n` stands.

### Predict, then check: pipeline order

Template: `{{"put" | printf "%s%s" "out"}}`.

**What is the result?** `printf` gets format `"%s%s"`, then `"out"`, then the result of the previous command `"put"` as the last argument → `"output"`.

### When `$` is not enough

If you do `{{$ := .Inner}}` (assigning bare `$`), you change the root binding for the rest of the scope. You rarely need that. Prefer `$root`, `$pkg`, `$svc`. If you overwrite `$`, `$.Field` no longer means “field of the initial Execute data.”

### Connection to the following lessons

- 02.07: `if` / `with` — `with` moves `.`; `$` and `$root` become a mandatory reflex.
- 02.08: `range` — same, plus `$i, $v`.
- 02.09: `FuncMap` — the pipeline often ends in `$x` before emitting an identifier.

Without this mechanism, conditions and loops look like random context errors.

### Dot on pointer and interface values

The template automatically dereferences a pointer when it needs to read a field. If `.` is of type `*Pkg` and is not `nil`, `.Name` reads the field on the pointed-to struct.

```go
p := &Pkg{Name: "api", Path: "example.com/api"}
// Execute(..., p) — .Name works
```

If the pointer is `nil`, reading a field typically ends with an execution error. That is why optional submodels are often kept as a pointer and combined with `with` (02.07): first check it is not empty, then read fields.

For `interface{}` / `any` in a map, the concrete dynamic type must support what you ask for (field, index, string for printing). A generator that swallows `map[string]any` should normalize types in an adapter — otherwise errors surface late in `Execute`.

### Printing the whole `.` for debugging

```
{{printf "%#v" .}}
```

or temporarily `{{.}}` — uses `fmt`-like default formatting. Do not leave that in a production codegen template (noise in the `.go` file), but in a unit test failure message you often do it in Go (`t.Logf("%#v", model)`), not in the template.

### Multiple actions on one line vs readability

```
{{$a := .A}}{{$b := .B}}
```

Allowed, but in a codegen review better one alias per line. Diff and blame stay readable.

### Predict, then check: does assignment print?

Template:

```
X{{$p := .Package}}Y
```

with `Package: "api"`.

**Answer:** the output is `XY`. Between X and Y there is no `api` — a declaration does not emit text. To print, you need `{{$p}}` or `{{.Package}}`.

### When the pipeline has more than one `|`

```
{{ .Name | printf "%sService" | printf "%q" }}
```

Left→right: first embed the suffix, then quote. You can capture the intermediate result:

```
{{$n := .Name | printf "%sService"}}
{{$q := $n | printf "%q"}}
```

The second form is easier to debug — you see `$n` in a test / temporary output.

### Map key vs struct field — same syntax, different semantics

```
{{.Package}}
```

On a struct: field `Package`. On a map: key `"Package"`. If you mix models (sometimes struct, sometimes map) in the same generator, errors become intermittent. Choose one model shape per template.

### Mini checklist before `Execute`

1. Are all fields the template reads exported (or map keys exact)?
2. Do repeated paths have an alias?
3. Are you entering `range`/`with` with `$root` / `$p` ready?
4. Does quoting go through `printf "%q"` where needed?
5. Will the output pass `format.Source`?

If the checklist fails, do not “fix” the template by luck — fix the model or the alias.

### Working with methods that return error

```go
func (m Model) Resolve() (string, error) {
	if m.Package == "" {
		return "", fmt.Errorf("package empty")
	}
	return m.Package, nil
}
```

```
{{.Resolve}}
```

If `Resolve` returns a non-nil error, `Execute` stops and returns that error to the caller. That is desirable in codegen: better to fail in the generator than to emit an empty `package `.

**Trace:** `Package: ""` → `Execute` error message contains `"package empty"`. You catch it in `main` / `run` and exit with exit code 1. The same pattern later applies to FuncMap functions (02.09).

### Constants and literals in the pipeline

The template accepts Go-like constants:

```
{{"hello"}}
{{`raw`}}
{{printf "%q" "hello"}}
```

Useful for fixed prefixes with variables:

```
{{$tag := printf "gen:%s" .Name}}
```

Do not build whole Go programs from literals alone — literals are for small pieces alongside data from the model.

### Predict, then check: single range variable (preview)

The documentation says: `range $v := .Items` binds the **element**, not the index — opposite of Go `for i := range`.

For this lesson remember only: when you enter a loop, `.` or `$v` is the element; you preserve the root via `$` / `$root` / aliases introduced **before** `range`. Details in 02.08.

### What the template does not do (intentionally)

- No short-circuit like Go `&&` for arbitrary code — there is `and`/`or` with empty semantics.
- No type declarations, `:=` in the Go sense, or `append`.
- No direct call of an arbitrary method with arguments without `FuncMap` / `call`.
- No safe HTML escape — that is `html/template`; for Go source you use `text/template`.

These limitations push logic into the Go layer — that is a feature for codegen, not a bug.

### Mental exercise: path refactor

Imaginary old template:

```
{{.File.Meta.Package}}
{{.File.Meta.Service}}
{{range .File.Meta.Methods}}{{$.File.Meta.Package}}.{{.Name}}{{end}}
```

After introducing aliases:

```
{{$root := .}}
{{$meta := .File.Meta}}
{{$pkg := $meta.Package}}
{{range $meta.Methods}}{{$pkg}}.{{.Name}}{{end}}
```

The number of deep paths drops; `$.File.Meta.Package` is no longer needed in the loop. That is a measurable gain in review.

## Rules and syntax

| Syntax | Meaning |
|----------|----------|
| `.` | current context (dot) |
| `.Field` | struct field / map key-identifier / niladic method |
| `$` | root data from the start of Execute (default) |
| `$name` | user variable |
| `{{$a := pipeline}}` | declaration; no output |
| `{{$a = pipeline}}` | assignment to existing |
| `{{pipeline}}` | compute and print |
| `a \| b` | result of `a` as last arg of `b` |
| `index .M "k"` | map/slice indexing |

Additional rules:

- Fields for the template model: exported names.
- Introduce an alias when the same path appears **2+** times or when you enter `range`/`with`.
- Do not shadow `$x` inside a loop with the same name without reason.
- Quoting strings: `printf "%q"` (or a FuncMap function), not manual escape.
- Keep the `package` line outside complicated conditions (02.07); here at least outside unnecessary trim.

## Examples

### Example 1 — Dot and fields

```go
package main

import (
	"os"
	"text/template"
)

type Pkg struct {
	Name string
	Path string
}

func main() {
	t := template.Must(template.New("p").Parse(
		`package {{.Name}} // path={{.Path}}` + "\n",
	))
	_ = t.Execute(os.Stdout, Pkg{Name: "api", Path: "example.com/api"})
}
```

#### What happens here

`.` is `Pkg`. `.Name` and `.Path` are exported fields. Output: `package api // path=example.com/api`. No variable — paths are short and one-off.

### Example 2 — Alias for a repeated type name

```
{{$s := .Service}}
package {{.Package}}

type {{$s}}Client struct{}

func New{{$s}}Client() *{{$s}}Client { return &{{$s}}Client{} }
```

```go
type Model struct {
	Package string
	Service string
}
```

#### What happens here

`$s` shortens `.Service`. Three occurrences of the type name share one source. Refactoring `Service` → another path changes one assignment line.

### Example 3 — `$` inside a range preview

```
{{range .Types}}
{{$.Package}}.{{.}}
{{end}}
```

#### What happens here

For each element, `.` is the element (`string` or struct). `$.Package` reads the root. Without `$`, `.Package` would look for a field on the element.

### Example 4 — `$root` + pipeline quoting

```go
package main

import (
	"bytes"
	"fmt"
	"text/template"
)

func main() {
	const tpl = `{{$root := .}}
{{$q := .Label | printf "%q"}}
package {{$root.Package}}

const Label = {{$q}}
`
	t := template.Must(template.New("c").Parse(tpl))
	var b bytes.Buffer
	_ = t.Execute(&b, map[string]string{
		"Package": "demo",
		"Label":   `say "hi"`,
	})
	fmt.Print(b.String())
}
```

#### What happens here

`$root` remembers the map. `$q` holds a safely quoted literal. Special characters in the label do not break generated Go.

### Example 5 — `index` into a variable

```
{{$gp := index .Attrs "go_package"}}
// go_package = {{$gp}}
package {{.Package}}
```

```go
type File struct {
	Package string
	Attrs   map[string]string
}
```

#### What happens here

A key with an underscore goes through `index`. You use the alias `$gp` in a comment and later in additional emits without repeating the `index` call.

### Example 6 — Generator with `format.Source`

```go
package main

import (
	"bytes"
	"fmt"
	"go/format"
	"text/template"
)

type M struct {
	Package string
	Name    string
}

func gen(m M) ([]byte, error) {
	const tpl = `{{$n := .Name}}
package {{.Package}}

// {{$n}} is a generated stub.
type {{$n}} struct{}
`
	t, err := template.New("m").Parse(tpl)
	if err != nil {
		return nil, err
	}
	var b bytes.Buffer
	if err := t.Execute(&b, m); err != nil {
		return nil, err
	}
	return format.Source(b.Bytes())
}

func main() {
	out, err := gen(M{Package: "demo", Name: "Hook"})
	if err != nil {
		panic(err)
	}
	fmt.Print(string(out))
}
```

#### What happens here

From model to `gofmt`-ed source. The `$n` alias holds the type name. This is the pattern that later lessons only extend with conditions, loops, and FuncMap.

### Example 7 — Trap: wrong context

```
{{range .Fields}}
{{.Package}}.{{.Name}}
{{end}}
```

If `Field` has no `Package`, this breaks. Fix:

```
{{$p := .Package}}
{{range .Fields}}
{{$p}}.{{.Name}}
{{end}}
```

or `{{$.Package}}`.

#### What happens here

The error is not in the field name on the root — the error is that you forgot `.` jumped to the element.

## Decision analysis

| Decision | Choose when... | Avoid when... |
|--------|--------------|------------------|
| Only `.Field` paths | one occurrence, shallow model | same path 3+ times |
| `$p := .Field` | repetition, entering a loop | alias for every one-off path |
| Bare `$` | short template, team knows the rule | onboarding, long files |
| `$root := .` | explicitness in review | micro-template of 5 lines |
| Map model | highly dynamic JSON input | stable shape — struct is clearer |
| Struct model | known schema, types in IDE | ad-hoc keys every week |
| Computation in Go before Execute | type names, validation | pure display (`printf "%q"`) |

Question before merging a template: **“Can I move a field in the model by changing one assignment line?”** If not — introduce an alias or flatten the model.

## Trade-offs

- **More `$` aliases:** shorter lines, but harder to follow scope if names are bad (`$a`, `$b`, `$c`).
- **Deep paths without aliases:** explicit, but brittle on refactor.
- **Prepare everything in Go:** the template becomes dumb and testable; more code before `Execute`.
- **Logic in the template:** fast prototype; expensive maintenance and weak unit test.
- **Map vs struct:** map swallows types; struct forces shape and export.

For codegen in a team: light preparation in Go + a few aliases in the template almost always beats a “smart” template.

## Common mistakes

1. **Wrong:** inside `range` you write `.Package` thinking of the root.  
   **Effect:** execution error or wrong/empty output.  
   **Why:** `.` is the loop element.  
   **Fix:** `$.Package` or `{{$p := .Package}}` before the loop.

2. **Wrong:** unexported field in the model for the template.  
   **Effect:** field “does not exist” / empty access.  
   **Why:** the template goes through reflection with export rules.  
   **Fix:** `Package string` (exported) or `map[string]any`.

3. **Wrong:** you expect `$` to follow the new `.` after `with`/`range`.  
   **Effect:** confusion; “why isn’t `$` the element?”  
   **Why:** `$` is the root Execute data (unless you change it yourself).  
   **Fix:** learn the model; for the element use `.` or `$v`.

4. **Wrong:** `{{$x := .A}}` inside a loop with the same name as outside, then you read the wrong `$x`.  
   **Effect:** silently wrong generate.  
   **Why:** scope shadowing until `{{end}}`.  
   **Fix:** `$item`, `$field` — different names.

5. **Wrong:** aggressive trim `{{- $pkg -}}` next to `package`.  
   **Effect:** `packageapi` — invalid Go.  
   **Why:** trim strips whitespace.  
   **Fix:** `package {{$pkg}}` with a space in the text.

6. **Wrong:** manual quotes around `{{.Name}}` instead of `printf "%q"`.  
   **Effect:** breaks on `"` inside the string; invalid source.  
   **Why:** special characters.  
   **Fix:** `{{.Name | printf "%q"}}` or `$q` alias.

7. **Wrong:** `{{$ := .Child}}` “to shorten.”  
   **Effect:** you lose root `$` for the rest of the scope.  
   **Why:** you overwrote the default binding.  
   **Fix:** `$child := .Child`, leave `$` alone.

8. **Wrong:** long concatenation of type names in the template.  
   **Effect:** unreadable template, hard to test.  
   **Why:** wrong layer for logic.  
   **Fix:** compute `FullName` in Go; in the template only `{{.FullName}}`.

## Idiomatic Go

- Model for the template: small struct with clear exported fields.
- Alias for repeated type and package names (`$s`, `$p`, `$root`).
- `$.` or `$root` consciously in loops and `with` blocks.
- Quoting and escape in pipeline / FuncMap, not “by hand.”
- After `Execute`: `format.Source` when you generate `.go`.
- Validate the model in Go before render (empty `Package` → error, not an empty file).
- Names of `$` variables short but meaningful — not alphabetical magic.

## Practical scenario

A team generates client stubs from an internal JSON service description. The template had `.Spec.Meta.Go.Package` 40 times. Product changes the schema: `Go` → `GoInfo`. CI goes red on half the generator; a PR with “fix templates” has a 200-line diff.

They introduce at the top:

```
{{$root := .}}
{{$pkg := .Spec.Meta.GoInfo.Package}}
{{$svc := .Spec.Service.Name}}
```

Loops and methods use `$pkg` / `$svc` / `$root`. At the same time the Go layer builds a flattened `Model{Package, Service, Methods}` so the template no longer knows about `Spec.Meta`. The next schema refactor changes only the adapter — the template stays still.

Second incident: a junior in `range .Methods` writes `{{.Package}}Client`. Generated code compiles “sometimes” because some method struct accidentally had a `Package` field from proto options. Fix: a lint rule in the review checklist — inside `range` forbid `.Package` without `$.` or `$pkg`. They add a unit test that renders a method without that field and expects the root package.

## Check questions

1. **What is `.` at the start of `Execute`?**  
   The data you passed — the initial context (dot).

2. **What is `$` for in `range`?**  
   Reading the root Execute data while `.` is the element.

3. **How do you introduce a new variable?**  
   `{{$name := pipeline}}` — without printing.

4. **Why does an unexported field work poorly in a codegen model?**  
   The template relies on reflection and export; an idiomatic model uses exported fields or a map.

5. **Where to do type-name concatenation — Go or template?**  
   In Go before `Execute`; the template displays the finished result.

6. **What does `{{$x := .A}}` do in terms of output?**  
   Prints nothing; only binds `$x`.

7. **How does a pipeline pass a value?**  
   The result of the left command is the last argument of the right.

8. **Why `$root := .` at the top?**  
   An explicit reference to the root when `.` later jumps in `with`/`range`.

When you get stuck on “field does not exist,” ask three things: (1) what is `.` now, (2) is the field exported, (3) do you need `$` / `$root` instead of `.`.

One more check: count how many times the same path repeats. If it is ≥ 2 and you enter a loop — an alias is not optional luxury, but hygiene.

## Summary

`{{.}}` is context; `{{$x :=}}` are aliases without output; `$` preserves the root Execute data when `.` jumps. Pipelines fill variables and do small display (`printf`). For codegen: flatten the model in Go, alias repetitions, do not shadow names, do not glue trim onto identifiers. The next lessons move `.` intentionally (`if`/`with`/`range`) — this mechanism is the assumption that that does not become chaos.

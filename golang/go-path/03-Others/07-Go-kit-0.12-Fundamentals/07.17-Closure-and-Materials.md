## Problem this lesson solves

Without wrap-up, knowledge stays fragmented: “I did middleware” without a map. Docker without a clear app structure packages **chaos** into an image. This lesson summarizes what you carry forward and what you consciously leave behind.

### Step 21 — reconstructing the arc: Service (07.05)

Service is the **domain**. Methods (`Uppercase`, `Count`, …) do not know about HTTP status, JSON fields, Prometheus labels, or OTel span names.

What you carry:

- your `Service` interface + concrete implementation
- domain errors (`ErrEmpty`, …) — not `http.Error`
- race-free: one `svc` shared through endpoint closures
- tests without transport

What you do not carry in Service:

- `net/http`, decode/encode, metrics types, tracer API

**G1.** May `Uppercase` log `r.RemoteAddr`? Predict “yes”. Answer: no — access/rid in transport; Service sees the use case.

### Step 22 — reconstructing the arc: Endpoint (07.06–07.07)

Endpoint is the **adapter**: `interface{}` request → assert DTO → call Service → response DTO (or error).

What you carry:

- `makeUppercaseEndpoint(svc)` — factory; `svc` captured in a **closure**
- `Endpoints` struct for wire (`MakeEndpoints`)
- non-generic `endpoint.Endpoint` in kit 0.12
- unit test: stub Service, without HTTP

What you do not carry in Endpoint:

- JSON tags as wire contract (that is transport DTO / encode)
- direct Prometheus `Inc()` (that is Service MW or Endpoint MW consciously)

**G2.** Why does the factory return a function instead of calling Service immediately? Predict “faster”. Answer: you get `endpoint.Endpoint` for Chain/transport; the closure fixes the dependency at boot.

### Step 23 — reconstructing the arc: Transport (07.08)

Transport is the **wire**: HTTP (JSON) and/or gRPC. Decode input → call endpoint → encode output. ErrorEncoder maps errors to status/body.

What you carry:

- `Decode*Request` / `Encode*Response`
- route + method (`POST /uppercase`)
- optional gRPC: same endpoint, different codec
- Graceful shutdown enters here (server lifecycle), not in Service

What you do not carry in Transport:

- business rules (empty string → ErrEmpty stays in Service)
- app-log MW around domain methods (that is 07.11)

**G3.** If you add gRPC, do you write a new Service? Predict “yes”. Answer: no — new transport + decode/encode; same Endpoint/Service (07.04/07.08).

### Step 24 — reconstructing the arc: transport logging (07.10)

Access log + request id at the edge. `Before` / `Finalizer` (or equivalent) — rid in context, status/latency on the way out.

What you carry:

- rid correlation (header in/out)
- access line: method, path, status, duration
- no PII in URL/query if policy forbids

What you do not mix:

- app log “Uppercase took 2ms” on the same line as access (different signals)

**G4.** Must rid live in the Service method? Predict “yes”. Answer: rid is in `context`; Service MW (07.11) reads from ctx — the signature need not be `rid string`.

### Step 25 — reconstructing the arc: application logging (07.11)

Service middleware with `go-kit/log`: method entry, error, duration. Structured key/value. Same style across methods.

What you carry:

- `ServiceMiddleware` type: `func(Service) Service`
- log around success and error
- levels / key convention agreed in the team

What you do not do:

- `fmt.Println` in the domain
- logging the whole request body without policy

**G5.** Does app log replace access log? Predict “yes”. Answer: no — access = HTTP edge; app = use case. Both.

### Step 26 — reconstructing the arc: metrics (07.12)

RED (Rate, Errors, Duration) via `kit/metrics` + adapter (e.g. Prometheus). Counter/Histogram as **interface**; implementation exposes `/metrics`.

What you carry:

- `InstrumentingMiddleware` (Service MW) — labels by method / error
- histogram latency, counter requests/errors
- scrape endpoint + CARDINALITY discipline (no user-id label)

What you do not do:

- metric by raw URL with unbounded path params
- mixing business KPIs into the same dashboard without agreement

**G6.** May Counter be a global `var` without an interface? Predict “yes for demo”. Answer: demo works; test/swap loses the seam — inject the metrics interface.

### Step 27 — reconstructing the arc: visibility gate (07.13)

Checklist: do signals exist, do board/runbook make sense, does ownership exist. Gate before SD/tracing dogma.

What you carry:

- “what I look at when it breaks” list
- rid ↔ log ↔ metrics correlation
- conscious: what you still *do not have* (e.g. trace) and why

### Step 28 — reconstructing the arc: service discovery (07.14)

What you do not carry in the summary:

**G8.** Is kit without `kit/sd` “incomplete”? Predict “yes”. Answer: no — complete is a service the platform finds; `kit/sd` is an option.

### Step 29 — reconstructing the arc: tracing (07.15)

OpenTelemetry: span around endpoint/transport edge, propagation (W3C Trace Context), export to the backend the org uses.

What you carry:

- Endpoint MW or otelhttp / gRPC interceptors
- parent/child span relationship across services
- sampling awareness (prod ≠ always-on 100% without budget)

What you do not do:

- span in every private helper without value
- mixing legacy OpenTracing API into new code without migration

**G9.** Does tracing replace metrics? Predict “yes”. Answer: no — metrics = aggregate/alert; trace = one request; log = detail.

### Step 31 — final request walkthrough through all layers

Imagine `POST /uppercase` with body `{"s":"go"}` and header `X-Request-Id: abc-1` (or a generated rid).

```
1. Transport (HTTP)
   - server receives request
   - Before/middleware: rid in context (07.10)
   - DecodeUppercaseRequest → uppercaseRequest{S:"go"}
   - call endpoint.Endpoint(ctx, req)

2. Endpoint MW chain (outside → inside)
   - Trace MW: start span "uppercase" (07.15)
   - (other Endpoint MW if any)
   - enter makeUppercaseEndpoint closure

3. Endpoint adapter (07.07)
   - assert request → uppercaseRequest
   - call svc.Uppercase(ctx, "go")
     where svc is already wrapped by the Service MW chain

4. Service MW chain (order you fixed in 07.11/07.12/07.16)
   - e.g. Logging MW: log method=Uppercase ...
   - Instrumenting MW: timer start; defer Observe + Inc
   - concrete service: strings.ToUpper → "GO", nil

5. Return upward
   - metrics: duration + success counter
   - app log: done / error=nil
   - endpoint: uppercaseResponse{V:"GO"}
   - trace MW: span OK, end
   - EncodeUppercaseResponse → JSON
   - Finalizer/access log: status 200, latency, rid=abc-1

6. Operator sees
   - access line with rid
   - app log with same rid (from ctx)
   - /metrics bump
   - trace in the backend (if export works)
```

If any step “vanishes” in your head — return to that lesson, not to Docker.

**G10.** Where in the walkthrough does Consul live? Predict “between 1 and 2”. Answer: nowhere mandatory — the client uses platform DNS/LB (07.14); this is *inside* one process.

### Step 32 — walkthrough: error through the same layers

`POST /uppercase` with `{"s":""}` → Service returns `ErrEmpty`.

```
Service → error
Instrumenting → error counter (+ latency)
Logging → log error=ErrEmpty
Endpoint → return nil, err (or response+err — be consistent with your style)
Trace → span record error / status
ErrorEncoder → HTTP 400 (or agreed code) + body
Access log → status 4xx, same rid
```

Check: do metrics and trace and access *all* see the failure? If only one — visibility gap.

### Step 33 — walkthrough: gRPC same path

Same Endpoint + Service + Service MW. Different transport decode/encode + (optional) OTel gRPC interceptor. RID/metadata instead of HTTP header — same correlation idea.

Point you must be able to say out loud: **domain and endpoint are not duplicated because of another wire**.

### Appendix: final glossary

- **Service** — business interface + impl
- **Endpoint** — `func(ctx, request) (response, error)`
- **Transport** — HTTP/gRPC bind
- **Middleware** — Service or Endpoint decorator
- **Signals** — log, metrics, traces
- **Course wrap-up** — module wrap-up
- **closure (Go)** — function literal that captures its environment
- **Pin** — fixed module version
- **ADR** — Architecture Decision Record

### Appendix: failure story bank

1. No ADR → rewrite to framework du jour.
2. Unpin → “code does not build tomorrow”.
3. Closure taken as Go theory → lost day.

# 07.08 Transport and Communication

> **Go Path - Zero to Gopher** / **03 Others → Go kit 0.12 Fundamentals** / Lesson 07.08

## Lesson goals

After this lesson you should be able to:

- write a **thin** `decode*Request` / `encodeResponse` for HTTP
- use **`httptransport.NewServer`** from `github.com/go-kit/kit/transport/http`
- mount the server on a **Go 1.22+** `ServeMux` (method-aware routes)
- configure **`ServerErrorEncoder`** (ErrorEncoder) when you use the error-return style
- apply **`http.MaxBytesReader`** on the body (in the spirit of 04.05)
- sketch the idea: **the same `endpoint.Endpoint`** for HTTP and gRPC
- recall the **graceful shutdown** pattern with `http.Server` (04.02)

## Prerequisite

- 07.07 — `Endpoints`, `make*Endpoint`
- 07.06 — DTO + JSON tags
- 07.05 — `Service`, `ErrEmpty`
- 04.xx HTTP — mux, timeout, MaxBytesReader, shutdown

## Problem this lesson solves

Transport must **only** translate wire ↔ request/response:

```
HTTP bytes ──decode──► uppercaseRequest ──► Endpoint ──► uppercaseResponse ──encode──► HTTP bytes
```

If decode does `strings.ToUpper`, or encode knows about SQL, the layers are dead. This lesson keeps transport thin and connects it to kit `NewServer`.

## Mental model

```
Client
  │  POST /uppercase  {"s":"go"}
  ▼
ServeMux (Go 1.22)
  │
  ▼
httptransport.Server (NewServer)
  ├─ decodeUppercaseRequest
  ├─ endpoints.Uppercase
  └─ encodeResponse / ErrorEncoder
  │
  ▼
JSON {"v":"GO"}
```

Position: **Transport (here)** → Endpoint → Service.

gRPC idea (same center):

```
gRPC Uppercase RPC ──decode proto──► (same) endpoints.Uppercase ──encode proto──► reply
```

## Mechanism

### Step 0 — import alias

```go
import (
	"context"
	"encoding/json"
	"net/http"

	httptransport "github.com/go-kit/kit/transport/http"
	"github.com/go-kit/kit/endpoint"
)
```

The alias `httptransport` is idiomatic because the package path is long and the name `http` is already taken.

**Predict-then-answer A**

Question: does `NewServer` call your `Service` directly?

- Predict: “yes, you pass svc.”
- Answer: no. `NewServer` takes `endpoint.Endpoint`, decode, and encode. The service is already closed over in the factory (07.07).

### Step 1 — decode (thin)

```go
func decodeUppercaseRequest(_ context.Context, r *http.Request) (interface{}, error) {
	var req uppercaseRequest
	// body limit — see Step 5
	if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
		return nil, err
	}
	return req, nil
}

func decodeCountRequest(_ context.Context, r *http.Request) (interface{}, error) {
	var req countRequest
	if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
		return nil, err
	}
	return req, nil
}
```

Decode rules:

1. Only parsing + (optional) trivial wire check.
2. **Do not** call `svc`.
3. Return the **same dynamic type** the endpoint asserts (value vs pointer!).
4. Decode error goes as `error` return → ErrorEncoder / default error response.

If DTO lives in the `endpoint` package and is unexported, decode can be in the same package, or you export DTO, or you keep decode in `endpoint` with HTTP types (a compromise). Common course layout:

```
internal/transport/http/
  server.go      // NewServer mounting
  decode.go
  encode.go
```

then DTOs must be exported or shared. Alternative: all HTTP functions in `internal/endpoint` — less clean, fewer files. The team chooses; **what matters is that decode does no business**.

### Step 2 — encode (thin)

```go
func encodeResponse(_ context.Context, w http.ResponseWriter, response interface{}) error {
	w.Header().Set("Content-Type", "application/json; charset=utf-8")
	return json.NewEncoder(w).Encode(response)
}
```

For Err-in-response style this is enough: the response already carries the `Err` string.

Custom encode that reads a field and sets status (optional):

```go
func encodeUppercaseResponse(ctx context.Context, w http.ResponseWriter, response interface{}) error {
	if resp, ok := response.(uppercaseResponse); ok && resp.Err != "" {
		w.WriteHeader(http.StatusBadRequest) // example — team agreement
	}
	return encodeResponse(ctx, w, response)
}
```

That is *manual* joining of Err field and status — document it. Cleaner path for status: ErrorEncoder + error return from the endpoint.

### Step 3 — NewServer

```go
func NewHTTPHandler(eps endpoint.Endpoints) http.Handler {
	mux := http.NewServeMux()

	mux.Handle("POST /uppercase", httptransport.NewServer(
		eps.Uppercase,
		decodeUppercaseRequest,
		encodeResponse,
	))

	mux.Handle("POST /count", httptransport.NewServer(
		eps.Count,
		decodeCountRequest,
		encodeResponse,
	))

	return mux
}
```

`httptransport.NewServer` returns `*httptransport.Server` which implements `http.Handler`.

Go **1.22** method routing: `"POST /uppercase"` rejects GET automatically. On older Go use a separate method check.

**Predict-then-answer B**

Question: can the same `eps.Uppercase` value sit on two routes?

- Predict: “no, the endpoint is consumed.”
- Answer: yes. Endpoint is a function; it can be shared. Rarely useful for two routes, but technically yes.

### Step 4 — ErrorEncoder

```go
import (
	"errors"
	"net/http"

	"example.com/stringsvc/internal/service"
)

func encodeError(_ context.Context, err error, w http.ResponseWriter) {
	w.Header().Set("Content-Type", "application/json; charset=utf-8")
	code := http.StatusInternalServerError
	if errors.Is(err, service.ErrEmpty) {
		code = http.StatusBadRequest
	}
	w.WriteHeader(code)
	_ = json.NewEncoder(w).Encode(map[string]string{
		"error": err.Error(),
	})
}

// when mounting:
uppercase := httptransport.NewServer(
	eps.Uppercase,
	decodeUppercaseRequest,
	encodeResponse,
	httptransport.ServerErrorEncoder(encodeError),
)
```

ErrorEncoder is called when the endpoint (or decode) returns a **non-nil error**. If you use Err-in-response and always `return resp, nil`, ErrorEncoder **does not see** domain errors — only programming/decode ones.

**Predict-then-answer C**

Question: `ErrEmpty` in `uppercaseResponse.Err` — does `encodeError` set 400?

- Predict: “yes, it knows about ErrEmpty.”
- Answer: no. ErrorEncoder did not look at the response body. Either custom encode reads the field, or switch to `return nil, err` in the endpoint.

### Step 5 — MaxBytesReader

```go
const maxBody = 1 << 20 // 1 MiB

func decodeUppercaseRequest(_ context.Context, r *http.Request) (interface{}, error) {
	r.Body = http.MaxBytesReader(nil, r.Body, maxBody)
	defer r.Body.Close()

	var req uppercaseRequest
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields() // optionally stricter
	if err := dec.Decode(&req); err != nil {
		return nil, err
	}
	return req, nil
}
```

Note: the first argument to `MaxBytesReader` is `http.ResponseWriter` when you want it to write 413; in decode context often `nil` + map the error in ErrorEncoder. Adapt to the team's 04.05 practice.

Without a limit: client sends a gigabyte of JSON → memory pressure.

### Step 6 — main + graceful shutdown reminder

```go
func main() {
	svc := service.New()
	eps := endpoint.MakeEndpoints(svc)
	handler := transporthttp.NewHTTPHandler(eps)

	srv := &http.Server{
		Addr:              ":8080",
		Handler:           handler,
		ReadHeaderTimeout: 5 * time.Second,
		ReadTimeout:       10 * time.Second,
		WriteTimeout:      10 * time.Second,
		IdleTimeout:       60 * time.Second,
	}

	go func() {
		if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
			log.Fatal(err)
		}
	}()

	stop := make(chan os.Signal, 1)
	signal.Notify(stop, os.Interrupt, syscall.SIGTERM)
	<-stop

	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()
	_ = srv.Shutdown(ctx)
}
```

Kit does not replace `http.Server` lifecycle — you still do 04.02 shutdown. NewServer is only a Handler.

### Step 7 — test via httptest

```go
func TestUppercaseHTTP(t *testing.T) {
	svc := service.New()
	eps := endpoint.MakeEndpoints(svc)
	handler := NewHTTPHandler(eps)

	body := bytes.NewBufferString(`{"s":"go"}`)
	req := httptest.NewRequest(http.MethodPost, "/uppercase", body)
	req.Header.Set("Content-Type", "application/json")
	rr := httptest.NewRecorder()
	handler.ServeHTTP(rr, req)

	if rr.Code != http.StatusOK {
		t.Fatalf("code %d", rr.Code)
	}
	// assert JSON {"v":"GO"} ...
}
```

Also test bad JSON (expect non-2xx or error body, depending on style).

### Step 8 — gRPC sketch (same endpoint)

```go
// pseudocode — names depend on your pb package
import grpctransport "github.com/go-kit/kit/transport/grpc"

func decodeGRPCUppercase(_ context.Context, grpcReq interface{}) (interface{}, error) {
	r := grpcReq.(*pb.UppercaseRequest)
	return uppercaseRequest{S: r.GetS()}, nil
}

func encodeGRPCUppercase(_ context.Context, response interface{}) (interface{}, error) {
	res := response.(uppercaseResponse)
	return &pb.UppercaseReply{V: res.V, Err: res.Err}, nil
}

// grpctransport.NewServer(eps.Uppercase, decodeGRPCUppercase, encodeGRPCUppercase)
```

Pedagogy point: the **same** `eps.Uppercase`. Do not copy the `svc.Uppercase` call into a gRPC handler.

Kit does not mandate one listener: often HTTP `:8080` and gRPC `:9090` separately.

### Step 9 — ServerBefore / After (preview)

```go
httptransport.NewServer(
	eps.Uppercase,
	decodeUppercaseRequest,
	encodeResponse,
	httptransport.ServerBefore(func(ctx context.Context, r *http.Request) context.Context {
		// request ID from header → context
		return ctx
	}),
	httptransport.ServerErrorEncoder(encodeError),
)
```

Request ID / logging details: 07.10+. Here know that options exist — do not stuff them into decode business.

### Step 10 — content-type discipline

Encode sets `Content-Type`. Decode can reject non-JSON:

```go
if ct := r.Header.Get("Content-Type"); ct != "" && !strings.HasPrefix(ct, "application/json") {
	return nil, fmt.Errorf("unsupported Content-Type %q", ct)
}
```

Optional; some teams tolerate empty CT in an internal API.

### Step 11 — PathValue (Go 1.22) + kit

If the route has `{id}`:

```go
mux.Handle("GET /items/{id}", httptransport.NewServer(
	eps.GetItem,
	decodeGetItemRequest, // reads r.PathValue("id")
	encodeResponse,
))
```

```go
func decodeGetItemRequest(_ context.Context, r *http.Request) (interface{}, error) {
	return getItemRequest{ID: r.PathValue("id")}, nil
}
```

The StringService example uses body JSON — PathValue is a bridge to richer APIs.

### Step 12 — complete HTTP transport file (course)

```go
package transporthttp

import (
	"context"
	"encoding/json"
	"net/http"

	httptransport "github.com/go-kit/kit/transport/http"

	"example.com/stringsvc/internal/endpoint"
)

const maxBody = 1 << 20

func NewHTTPHandler(eps endpoint.Endpoints) http.Handler {
	mux := http.NewServeMux()
	opts := []httptransport.ServerOption{
		httptransport.ServerErrorEncoder(encodeError),
	}

	mux.Handle("POST /uppercase", httptransport.NewServer(
		eps.Uppercase,
		decodeUppercaseRequest,
		encodeResponse,
		opts...,
	))
	mux.Handle("POST /count", httptransport.NewServer(
		eps.Count,
		decodeCountRequest,
		encodeResponse,
		opts...,
	))
	return mux
}

func decodeUppercaseRequest(_ context.Context, r *http.Request) (interface{}, error) {
	r.Body = http.MaxBytesReader(nil, r.Body, maxBody)
	var req endpoint.UppercaseRequest // if you export; otherwise local type
	if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
		return nil, err
	}
	return req, nil
}

// decodeCountRequest, encodeResponse, encodeError — as above
```

Adapt exported DTO names to your layout from 07.06/07.07.

### Step 13 — error order (map)

| Error source | Who catches |
|--------------|-------------|
| bad JSON | decode → ErrorEncoder |
| wrong type in ep | ep error return → ErrorEncoder |
| `ErrEmpty` (error-return style) | ep → ErrorEncoder → 400 |
| `ErrEmpty` (Err-in-response style) | ep `nil` error → encode body with `err` |
| encode JSON fail | kit Server finalizer / error path |

### Step 14 — what transport must not do

1. Domain validation instead of service (except wire).
2. Direct SQL.
3. Ignoring ctx (NewServer passes request context — do not lose it).
4. Another encode “manually” after NewServer on the same writer.
5. Gin/Echo handler that calls svc without a bridge to endpoint (except temporary — avoid).

### Step 15 — Health outside kit endpoint

```go
mux.HandleFunc("GET /healthz", func(w http.ResponseWriter, _ *http.Request) {
	w.WriteHeader(http.StatusOK)
	_, _ = w.Write([]byte("ok"))
})
```

Health is often **not** a kit endpoint — no DTO/MW need. Do not force `makeHealthEndpoint` without reason. Liveness ≠ business use-case.

### Step 17 — walkthrough from scratch to Handler

1. `service.New()` (07.05).
2. `endpoint.MakeEndpoints(svc)` (07.07).
3. `decode*` + `encodeResponse` (+ optional ErrorEncoder).
4. `httptransport.NewServer` × N on mux.
5. `httptest` test of the whole Handler.
6. `http.Server` + timeout + `Shutdown` in `main`.
7. (Optional) gRPC NewServer with the **same** `eps` fields.

### Step 18 — predict: who closes Body

```go
defer r.Body.Close()
```

In decode: does kit already close the body? Practice differs by version/options — **verify** in a test that there is no leak; many teams close explicitly in decode after reading. Do not rely on “someone will”.

**Predict-then-answer D**

Question: may encode read `r.Body` again?

- Predict: “yes, for log.”
- Answer: not reliably — the body was consumed in decode. For audit log use ServerBefore / middleware that tees the body into a buffer **before** decode (advanced topic).

## Rules and syntax

1. Decode/encode **thin** — wire only.
2. `httptransport.NewServer(ep, dec, enc, opts...)`.
3. `ServerErrorEncoder` for error-return style.
4. **Do not** call `svc` from decode/encode.
5. gRPC: `kit/transport/grpc` similar pattern; same ep.
6. `MaxBytesReader` on body.
7. Go 1.22 `"METHOD /path"` on mux.
8. Test `httptest` + unit decode of bad JSON.
9. Timeouts on `http.Server`; graceful `Shutdown`.
10. Content-Type on encode.
11. Same endpoints object for multiple transports.
12. No generic kit Endpoint — still `interface{}` through dec/enc.

## Examples

### Example 1 — ErrorEncoder for ErrEmpty

```go
if errors.Is(err, service.ErrEmpty) {
	code = http.StatusBadRequest

```

### What happens here

Transport maps the sentinel from 07.05 to an HTTP status. Service still does not know about 400.

### Example 2 — gRPC decode sketch

```go

```

### What happens here

Proto → DTO → same endpoint. Service does not see proto.

### Example 3 — content-type

```go

### What happens here

Clients and intermediaries interpret the body correctly. Without the header tools “guess”.

```

### What happens here

## Decision analysis

| Option | Advantage | Drawback |
|--------|-----------|----------|
| HTTP only | Faster start | Later gRPC = new transport file (ep stays) |
| HTTP + gRPC | Polyglot | Two listeners, two encode/decode |
| Err-in-response + plain encode | Fewer options | Weak status |
| ErrorEncoder | Clear statuses | Endpoint must `return nil, err` |
| DTO in transport package | Clear edge | Mapping to endpoint types |
| Decode in endpoint package | Shared unexported DTO | HTTP dependency closer to ep |

## Trade-offs

- More encode/decode boilerplate = less coupling.
- Strict `DisallowUnknownFields` breaks tolerant clients; loose decode hides typo fields.
- One ErrorEncoder for all routes vs per-route — simplicity vs precision.
- MaxBytes too small breaks legitimate payloads; too large protects weakly.

## Common mistakes

1. Business in decode (`ToUpper` in decode).
2. Forgotten `Content-Type`.
3. No ErrorEncoder while endpoint returns `err` — generic 500 without mapping.
4. Large body without `MaxBytesReader`.
5. Mixing gin without a bridge.
6. Double encode (manual Write + Encode).
7. Ignoring ctx / losing request context.
8. Mixing Err-in-response and expecting ErrorEncoder for `ErrEmpty`.
9. Forgotten graceful shutdown.
10. GET route for a JSON body use-case without agreement.
11. `ListenAndServe` without timeout fields.
12. Service imported in decode “temporarily”.

## Idiomatic Go

- Alias `httptransport`.
- Thin decode/encode functions.
- `main` mounts mux + `http.Server`.
- `errors.Is` in ErrorEncoder.
- `httptest` for handler tests.
- Signal + `Shutdown` for the process.

## Practical scenario

The same `Endpoints` mounted on `POST /uppercase` and gRPC `Strings.Uppercase`. FE uses HTTP; an internal service uses gRPC. Incident: empty string. HTTP clients see 400 via ErrorEncoder; gRPC sees `InvalidArgument` via gRPC status map — the **same** `ErrEmpty` from service. Transports differ; domain does not.

## Going deeper: transport communication

Fourteen real insights — without filler loops.

### 1. insight — ServerBefore for request ID

Put request ID into `context` before the endpoint (`ServerBefore`). Logging MW reads ctx — do not read the header from service.

**Check:** does service import `net/http` because of a header? (must not)

### 2. insight — Finalizer for HTTP status metrics

`ServerFinalizer` sees status code after encode — useful for Prometheus HTTP metrics (07.12) without touching service.

**Check:** do status metrics live outside ErrorEncoder?

### 3. insight — graceful shutdown

Kit does not do shutdown for you. SIGTERM → `Shutdown` → drain in-flight. Link to 04.02.

**Check:** do k8s preStop and `Shutdown` timeout match?

### 4. insight — choose one error style

Err field **or** ErrorEncoder as the primary domain signal. Mixing breaks dashboards (all 200).

**Check:** one sentence in the transport package README?

### 5. insight — CORS is not kit

CORS is separate HTTP middleware around Handler, not part of `NewServer` decode.

**Check:** does CORS logic sit in `uppercase` decode?

### 6. insight — HTTP/2 and gRPC listeners

Often separate ports/processes. Do not shove everything on :8080 without a plan (h2c/gateway).

**Check:** does the ops chart show two ports when needed?

### 7. insight — OpenAPI is not free with kit

Kit does not generate OpenAPI magically. Manually, oapi-codegen, or an external description. DTO tags help, they do not replace the spec.

**Check:** does the API contract live somewhere outside code?

### 8. insight — test bad JSON

Mandatory negative test. Decode fail must not then call service (mock/spy).

**Check:** does the stub service call counter stay 0?

### 9. insight — PathValue + decode

Document path + query + body combinations. One decode reads everything the endpoint DTO needs.

**Check:** is there a PathValue test when you use `{id}`?

### 10. insight — document routes

Table: method, path, endpoint field, decode fn. Onboarding and incident response.

**Check:** does `GET /uppercase` accidentally work?

### 11. insight — rate limit on transport MW

Rate limit / IP allow list = around Handler or ServerBefore. Not in `Uppercase` service.

**Check:** does the limit also apply to gRPC separately?

### 12. insight — compression optional

Gzip middleware around Handler. Encode stays JSON; do not mix compression into `json.Encoder` unless deliberate.

**Check:** Content-Encoding agreement with the client?

### 13. insight — same request ID as 04.06

Propagate ID through HTTP header → ctx → log. Kit ServerBefore is the entry point.

**Check:** does trace/log correlation work through the endpoint?

### 14. insight — gRPC status map

Table: `ErrEmpty` → `codes.InvalidArgument`; unknown → `Internal`. Analog to ErrorEncoder.

**Check:** do gRPC and HTTP map the same sentinel consistently?

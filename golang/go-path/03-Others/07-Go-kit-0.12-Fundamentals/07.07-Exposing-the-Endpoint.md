# 07.07 Exposing the Endpoint

> **Go Path - Zero to Gopher** / **03 Others → Go kit 0.12 Fundamentals** / Lesson 07.07

## Lesson goals

After this lesson you should be able to:

- write **`make*Endpoint`** factory functions that return `endpoint.Endpoint`
- close over (**closure**) `Service` inside the endpoint function
- **type assert** the request (the `ok` form in production)
- call `svc.Uppercase` / `svc.Count` and return response DTOs
- assemble an **`Endpoints` struct** as the wire point for transport
- test the endpoint **without HTTP** (direct call with `uppercaseRequest`)
- remember: kit v0.12 `endpoint.Endpoint` is **non-generic** (`interface{}`)

## Prerequisite

- 07.06 — request/response DTO, Err-in-response vs ErrorEncoder
- 07.05 — `Service` interface
- 07.04 — `Endpoint`, `Middleware`, `Chain` signatures
- Import: `github.com/go-kit/kit/endpoint`

## Problem this lesson solves

Without endpoint factories, transport often calls the service directly:

```go
// anti-pattern in kit architecture
r.HandleFunc("/uppercase", func(w http.ResponseWriter, r *http.Request) {
	// decode...
	v, err := svc.Uppercase(...)
	// encode...
})
```

Consequences: no place for an `endpoint.Middleware` chain; gRPC must duplicate the business call; testing “endpoint behavior” means HTTP tests. The factory pulls use-case invocation into a transport-agnostic layer.

## Mental model

```
makeUppercaseEndpoint(svc Service) endpoint.Endpoint
        │
        ▼
func(ctx, request interface{}) (interface{}, error)
        │
        ├─ assert → uppercaseRequest
        ├─ svc.Uppercase(ctx, req.S)
        └─ return uppercaseResponse{...}
```

```
Endpoints{
  Uppercase: makeUppercaseEndpoint(svc),
  Count:     makeCountEndpoint(svc),
}
        │
        ▼
httptransport.NewServer(endpoints.Uppercase, dec, enc)  // 07.08
```

Layers: Transport → **Endpoint (here)** → Service.

## Mechanism

### Step 0 — canonical type (learn by heart)

```go
import "github.com/go-kit/kit/endpoint"

// Kit v0.12 — NOT Endpoint[Req, Res]
type Endpoint func(ctx context.Context, request interface{}) (response interface{}, err error)
```

Your factory **must** return exactly this shape. A generic wrapper that *you* write can exist in your code, but that **is not** the kit API — do not teach colleagues that `kit/endpoint` exports `Endpoint[T]`.

**Predict-then-answer A**

Question: may `makeUppercaseEndpoint` return `func(ctx, uppercaseRequest) (uppercaseResponse, error)` as an “Endpoint”?

- Predict: “yes, Go 1.18 generics.”
- Answer: that is not `endpoint.Endpoint`. `httptransport.NewServer` expects the kit signature with `interface{}`. An adapter must bridge.

### Step 1 — makeUppercaseEndpoint (Err-in-response style)

```go
package endpoint

import (
	"context"

	"github.com/go-kit/kit/endpoint"

	"example.com/stringsvc/internal/service"
)

func makeUppercaseEndpoint(svc service.Service) endpoint.Endpoint {
	return func(ctx context.Context, request interface{}) (interface{}, error) {
		req := request.(uppercaseRequest)
		v, err := svc.Uppercase(ctx, req.S)
		if err != nil {
			return uppercaseResponse{Err: err.Error()}, nil
		}
		return uppercaseResponse{V: v}, nil
	}
}
```

Note:

- the factory takes `svc` → closes over it in a closure
- service errors go in a **response field**, and the `error` return is `nil` (style A from 07.06)
- transport encode always receives `uppercaseResponse`

### Step 2 — production assert (`ok` form)

```go
func makeUppercaseEndpoint(svc service.Service) endpoint.Endpoint {
	return func(ctx context.Context, request interface{}) (interface{}, error) {
		req, ok := request.(uppercaseRequest)
		if !ok {
			return nil, fmt.Errorf("uppercase: want uppercaseRequest, got %T", request)
		}
		v, err := svc.Uppercase(ctx, req.S)
		if err != nil {
			return uppercaseResponse{Err: err.Error()}, nil
		}
		return uppercaseResponse{V: v}, nil
	}
}
```

Panic assert stays in short slides; handbook and production use `ok`.

**Predict-then-answer B**

Question: if the assert returns `nil, err`, which error style is that for transport?

- Predict: “Err field.”
- Answer: **error return** — typically ErrorEncoder / default 500. That is a *programmer* error (wrong type), not `ErrEmpty`. Distinguish from domain errors in the response field.

### Step 3 — makeCountEndpoint

```go
func makeCountEndpoint(svc service.Service) endpoint.Endpoint {
	return func(ctx context.Context, request interface{}) (interface{}, error) {
		req, ok := request.(countRequest)
		if !ok {
			return nil, fmt.Errorf("count: want countRequest, got %T", request)
		}
		return countResponse{V: svc.Count(ctx, req.S)}, nil
	}
}
```

No Err field — the service does not return an error.

### Step 4 — Endpoints struct

```go
type Endpoints struct {
	Uppercase endpoint.Endpoint
	Count     endpoint.Endpoint
}

func MakeEndpoints(svc service.Service) Endpoints {
	return Endpoints{
		Uppercase: makeUppercaseEndpoint(svc),
		Count:     makeCountEndpoint(svc),
	}
}
```

Why a struct?

- `main` / transport gets one object
- middleware can wrap fields before mounting
- tests build `Endpoints` with a stub service

Later (07.10+):

```go
eps := MakeEndpoints(svc)
eps.Uppercase = endpoint.Chain(loggingMW, instrumentingMW)(eps.Uppercase)
```

### Step 5 — alternative: error return style

If the team chooses ErrorEncoder:

```go
func makeUppercaseEndpoint(svc service.Service) endpoint.Endpoint {
	return func(ctx context.Context, request interface{}) (interface{}, error) {
		req, ok := request.(uppercaseRequest)
		if !ok {
			return nil, fmt.Errorf("uppercase: want uppercaseRequest, got %T", request)
		}
		v, err := svc.Uppercase(ctx, req.S)
		if err != nil {
			return nil, err // ErrorEncoder in 07.08
		}
		return uppercaseResponse{V: v}, nil
	}
}
```

Then `uppercaseResponse` can omit the `Err` field. **Do not mix** style A and B in the same service without documentation.

### Step 6 — test without HTTP

```go

	// or export MakeEndpoints + use exported DTOs for tests.
```

With unexported DTOs, put the test in `package endpoint`:

```go
package endpoint

import (
	"context"
	"testing"

	"example.com/stringsvc/internal/service"
)

func TestMakeUppercaseEndpoint(t *testing.T) {
	ep := makeUppercaseEndpoint(service.New())
	resp, err := ep(context.Background(), uppercaseRequest{S: "go"})
	if err != nil {
		t.Fatal(err)
	}
	ur, ok := resp.(uppercaseResponse)
	if !ok {
		t.Fatalf("got %T", resp)
	}
	if ur.V != "GO" || ur.Err != "" {
		t.Fatalf("got %#v", ur)
	}
}

func TestMakeUppercaseEndpointEmpty(t *testing.T) {
	ep := makeUppercaseEndpoint(service.New())
	resp, err := ep(context.Background(), uppercaseRequest{S: ""})
	if err != nil {
		t.Fatal(err) // Err-in-response style: err is nil
	}
	ur := resp.(uppercaseResponse)
	if ur.Err == "" {
		t.Fatal("want Err set")
	}
}

func TestMakeUppercaseEndpointBadType(t *testing.T) {
	ep := makeUppercaseEndpoint(service.New())
	_, err := ep(context.Background(), "not-a-request")
	if err == nil {
		t.Fatal("want type error")
	}
}
```

**Predict-then-answer C**

Question: does this test start a server on `:8080`?

- Predict: “it must, because the endpoint is part of HTTP.”
- Answer: no. The endpoint is an ordinary function. HTTP comes in 07.08.

### Step 7 — passing `ctx`

```go
v, err := svc.Uppercase(ctx, req.S) // same ctx from transport
```

Do not replace with `context.Background()` inside the endpoint except for deliberate isolation (rare). Timeout/cancel from the HTTP request must reach the service/repo layer.

### Step 8 — what the endpoint does not do

| Do not | Why |
|--------|-----|
| `json.Decode` | that is transport decode |
| `w.WriteHeader` | no `http.ResponseWriter` |
| log every call “by hand” if you have MW | duplicate; use Chain |
| open DB connections | service/repo |

Endpoint = **thin glue**: assert → service → response.

### Step 9 — middleware preview (without a full lesson)

```go
logging := func(name string) endpoint.Middleware {
	return func(next endpoint.Endpoint) endpoint.Endpoint {
		return func(ctx context.Context, request interface{}) (interface{}, error) {
			// log name, duration...
			return next(ctx, request)
		}
	}
}

ep := endpoint.Chain(logging("uppercase"))(makeUppercaseEndpoint(svc))
```

The factory stays clean; Chain is applied at `MakeEndpoints` or in `main`. Details in 07.10–07.12.

### Step 10 — concurrency

One `svc` is shared across all endpoints and all requests. That is why 07.05 insisted on a race-free service. The endpoint itself does not hold mutable state (the closure captures the `svc` reference).

### Step 11 — complete file skeleton

```go
package endpoint

import (
	"context"
	"fmt"

	"github.com/go-kit/kit/endpoint"

	"example.com/stringsvc/internal/service"
)

type Endpoints struct {
	Uppercase endpoint.Endpoint
	Count     endpoint.Endpoint
}

func MakeEndpoints(svc service.Service) Endpoints {
	return Endpoints{
		Uppercase: makeUppercaseEndpoint(svc),
		Count:     makeCountEndpoint(svc),
	}
}

func makeUppercaseEndpoint(svc service.Service) endpoint.Endpoint {
	return func(ctx context.Context, request interface{}) (interface{}, error) {
		req, ok := request.(uppercaseRequest)
		if !ok {
			return nil, fmt.Errorf("uppercase: want uppercaseRequest, got %T", request)
		}
		v, err := svc.Uppercase(ctx, req.S)
		if err != nil {
			return uppercaseResponse{Err: err.Error()}, nil
		}
		return uppercaseResponse{V: v}, nil
	}
}

func makeCountEndpoint(svc service.Service) endpoint.Endpoint {
	return func(ctx context.Context, request interface{}) (interface{}, error) {
		req, ok := request.(countRequest)
		if !ok {
			return nil, fmt.Errorf("count: want countRequest, got %T", request)
		}
		return countResponse{V: svc.Count(ctx, req.S)}, nil
	}
}
```

(DTO types from 07.06 in the same package.)

### Step 12 — gRPC reuse idea

The same `Endpoints.Uppercase` can be passed to:

- `httptransport.NewServer(...)`
- `grpctransport.NewServer(...)` (kit transport/grpc)

So the factory must not know about `*http.Request`. If you see HTTP types in the endpoint file — wrong layer.

### Step 13 — naming

| Name | Role |
|------|------|
| `makeUppercaseEndpoint` | unexported factory |
| `MakeEndpoints` | exported assembler |
| `Endpoints` | group |
| field `Uppercase` | mounted on a route |

The `make*Endpoint` convention is readable in kit examples — keep it.

### Step 14 — predict-then-answer: call chain

Question: who sees JSON bytes first — endpoint or decode?

- Predict: “endpoint, because it is the use case.”
- Answer: **decode** in transport. The endpoint sees an already built `uppercaseRequest` as `interface{}`.

### Step 15 — stub service in endpoint test

```go
type stub struct{}

func (stub) Uppercase(context.Context, string) (string, error) {
	return "STUB", nil
}
func (stub) Count(context.Context, string) int { return -1 }

func TestEndpointUsesService(t *testing.T) {
	ep := makeUppercaseEndpoint(stub{})
	resp, err := ep(context.Background(), uppercaseRequest{S: "x"})
	if err != nil {
		t.Fatal(err)
	}
	if resp.(uppercaseResponse).V != "STUB" {
		t.Fatalf("endpoint did not call stub")
	}
}
```

This proves the factory really closes over the passed `svc`, not a hidden global.

### Step 16 — nil request

```go
_, err := ep(context.Background(), nil)
// ok assert → err != nil
```

Decode rarely returns `nil` successfully, but the test guards. Panic assert on `nil` is a classic crash.

### Step 17 — MakeEndpoints with Chain (template)

```go
func MakeEndpoints(svc service.Service, mws ...endpoint.Middleware) Endpoints {
	upper := makeUppercaseEndpoint(svc)
	count := makeCountEndpoint(svc)
	if len(mws) > 0 {
		ch := endpoint.Chain(mws...)
		upper = ch(upper)
		count = ch(count)
	}
	return Endpoints{Uppercase: upper, Count: count}
}
```

Same MW chain on all methods — starting point. Later you can use different chains per field (auth only on write routes).

### Step 18 — anti-pattern: transport in factory

```go
// BAD
func makeUppercaseEndpoint(svc service.Service) endpoint.Endpoint {
	return func(ctx context.Context, request interface{}) (interface{}, error) {
		r := request.(*http.Request) // transport leaks into endpoint
		// ...
	}
}
```

If you see `*http.Request` in the factory, decode did not do its job. Go back to the 07.06/07.08 boundary.

### Step 19 — walkthrough

1. DTOs from 07.06 in the same package.
2. `makeUppercaseEndpoint` + `makeCountEndpoint` with `ok` assert.
3. `MakeEndpoints`.
4. Tests: happy, empty (Err style), bad type, stub svc.
5. `go test ./internal/endpoint -race`.
6. Only then 07.08 `NewServer(eps.Uppercase, ...)`.

### Step 20 — what the anonymous function captures

The closure captures `svc` by reference (interface value). If `MakeEndpoints` gets another `svc` later, the old endpoint still holds the old one. So construct endpoints **once** at startup (or rebuild deliberately).

**Predict-then-answer D**

Question: if fields inside the service implementation change (when it has state), does an already built endpoint see that?

- Predict: “no, the closure copies.”
- Answer: the interface value points at the same concrete object if you use a pointer receiver / pointer in `New`. For `stringService{}` value with no fields — no state. For `New(repo)` with a pointer struct — yes, you share the same svc.

## Rules and syntax

1. Import `github.com/go-kit/kit/endpoint` — type `endpoint.Endpoint`.
2. Factory closes over `svc` (closure).
3. Production: `ok` type assert; panic only in throwaway demo.
4. Document Err-in-response vs `return nil, err`.
5. `Endpoints` struct groups factory results.
6. `endpoint.Chain` for MW — not inside a service method.
7. Test the endpoint without HTTP.
8. Pass the same `ctx`.
9. No `net/http` in the endpoint package (ideal).
10. No fake `Endpoint[T]` from kit.
11. One factory per use-case method.
12. Same `Endpoints` value for multiple transports.

## Decision analysis

| Option | When | Cost |
|--------|------|------|
| Err in response, `nil` error | Kit HTTP demo, simple encode | Status 200 + err field |
| `return nil, err` | You want ErrorEncoder / gRPC status | Custom transport options |
| unexported `make*` | Encapsulation | Test in same package |
| exported factory | Test from `_test` package | Larger API |
| Endpoints struct | Multiple methods | A little boilerplate |
| Map[string]Endpoint | Dynamic routes | Loses typed fields |

## Trade-offs

- **`interface{}` loses types** — the factory localizes assert as the only “unsafe” point.
- **Err-in-response** simplifies encode, complicates HTTP semantics.
- **MW in Chain** vs log in factory — Chain scales; log in factory duplicates per method.
- **One svc for all eps** — simple; requires thread-safe service.

## Common mistakes

1. Panic type assert in production.
2. Ignoring `ctx` (`Background()` in factory).
3. Transport calls `svc` directly — factory bypassed.
4. Duplicate factory with different error styles.
5. MW logic embedded in service instead of `endpoint.Chain`.
6. Mixing `countRequest` into uppercase endpoint.
7. No endpoint tests.
8. HTTP types in endpoint package.
9. Invented generic kit `Endpoint[T]`.
10. Returning service error both in `Err` field and as `error` return at once (double).
11. Storing `request` in a global map without sync.
12. `MakeEndpoints` creates a new service inside instead of taking `svc`.

## Idiomatic Go

- Closure factory per method.
- `Endpoints` aggregate.
- `fmt.Errorf("... %T", request)` for bad type.
- Test in same package when DTOs are unexported.
- `endpoint.Chain` for cross-cutting.
- Package comment: which error style applies.

## Practical scenario

The team adds gRPC. HTTP already works via `eps.Uppercase`. A new `transport/grpc` file mounts the **same** `endpoint.Endpoint`. Zero changes in `makeUppercaseEndpoint`. PR review: “Was HTTP decode added to the endpoint?” — if yes, reject. The endpoint stays the use-case port.

## Going deeper: exposing endpoint

Fourteen real insights — no filler loops.

### 1. insight — Chain order

`endpoint.Chain(mw1, mw2)(ep)` — the first argument is outermost. Wrong order = logging without latency or auth after work.

**Check:** does the team have an agreed order (auth → logging → metrics → ep)?

### 2. insight — metrics label from name

Use-case name (`uppercase`) often goes in the label. Factory name / Chain wrapper carries the string — do not guess from runtime request type.

**Check:** do all routes have a stable `method=` label?

### 3. insight — do not log in factory if you have MW

Duplicate logs spam. Factory stays thin; MW logs.

**Check:** how many times does the same request ID appear in the log per call?

### 4. insight — document error style

One comment on `MakeEndpoints`: “domain errors in response.Err; program errors as error return.”

**Check:** does every new endpoint follow the same style?

### 5. insight — parallelism: shared svc

Load test hits the same `svc` in parallel. Service from 07.05 must be safe.

**Check:** `-race` on endpoint + service tests.

### 6. insight — concurrency note in review

If the factory also closes over a `map` cache besides svc — that is new state. Prefer state in service with sync.

**Check:** does the closure capture something mutable besides svc?

### 7. insight — fuzz assert paths

Fuzz cannot easily build arbitrary `interface{}`, but testing bad types (string, nil, wrong struct) is a cheap table row.

**Check:** is there a `bad_type` test?

### 8. insight — generic helper carefully

`func Make[T any](...)` in *your* code can reduce boilerplate. Do not claim it is kit. Keep an escape hatch for special methods.

**Check:** does README mix your generic with kit API?

### 9. insight — read stringsvc example

Upstream example remains the best “did we drift?” compass alongside v0.12.

**Check:** diff your factory vs example — names only or architecture too?

### 10. insight — Endpoint = use-case port

Hexagonal: endpoint is adapter to application service. Method name = use case.

**Check:** does `makeDoStuffEndpoint` smell?

### 11. insight — NewServer in the next lesson

`httptransport.NewServer(ep, dec, enc)` consumes exactly this `ep`. If ep is not clean, transport cannot save it.

**Check:** does ep compile without `net/http`?

### 12. insight — do not mix gin handler with endpoint without a bridge

Gin `c.Bind` + `svc` directly bypasses kit endpoint. If you must use gin, bridge: gin → decode DTO → `ep(ctx, req)` → encode.

**Check:** is there a “temporary” gin handler that calls svc?

### 13. insight — code review: is factory clean?

Checklist: assert, svc call, map response. Anything else = suspect.

**Check:** factory line count > 40 without reason?

### 14. insight — timeout from transport ctx

HTTP server cancel → ctx → ep → svc. Do not swallow cancel error into Err field as “empty string”.

**Check:** does a canceled ctx test distinguish `context.Canceled` from `ErrEmpty`?

### Quick recap

- `make*Endpoint` → `endpoint.Endpoint` (non-generic).
- Closure over `Service`; assert DTO; call; response.
- `Endpoints` for wire; Chain for MW.
- Test without HTTP; stub `Service` proves closure captures the right dependency.
- Same ep for HTTP and gRPC.
- `nil` / wrong type → error return, not panic.
- Next: transport decode/encode.

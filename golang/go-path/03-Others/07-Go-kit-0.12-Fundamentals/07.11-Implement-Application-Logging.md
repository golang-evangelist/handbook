# 07.11 Implement Application Logging

> **Go Path - Zero to Gopher** / **03 Others → Go kit 0.12 Fundamentals** / Lesson 07.11

## Lesson goals

After this lesson you should be able to:

- write a **LoggingMiddleware** that wraps your `Service` interface (`ServiceMiddleware` shape)
- use `defer` + **named returns** to reliably log `method`, `took`, `err` after the call
- wire `svc = LoggingMiddleware(logger)(svc)` in `main` (decorator order clear)
- truncate / shorten sensitive or long inputs in the log
- **not** introduce transport imports (`net/http`) in the service logging layer
- **not** duplicate the transport access log (path/code) — that stays 07.10

## Prerequisite

- 07.09 — core green
- 07.10 — transport logger, request id in context, Finalizer access log
- 07.05 — `Service` interface + implementation
- 07.04 — difference ServiceMiddleware vs EndpointMiddleware

## Problem this lesson solves

Transport log sees the edge (status, path). It does not reliably see **which service method**, how long the **domain call** took, or the business `error` when style A hides the error in the body with HTTP 200. Application logging closes that gap **around the Service interface**, without mixing HTTP into the domain package.

## Mental model

```
svc := service.New()
svc = LoggingMiddleware(appLogger)(svc)   // decorator
svc = Instrumenting...(metrics)(svc)      // later 07.12

transport → endpoint → svc.Uppercase(...)
                           │
                           ▼
              loggingMiddleware.Uppercase
                 defer log(method, took, err)
                 return next.Uppercase(...)
```

- **App log** = use-case event (`method=uppercase took=… err=…`).
- **Transport log** = wire event (`path=… code=…`).
- Same `request_id` from ctx (07.10) joins lines in Loki.

## Mechanism

### Step 0 — `ServiceMiddleware` shape

```go
type Middleware func(Service) Service
```

LoggingMiddleware is a higher-order function:

```go
func LoggingMiddleware(logger log.Logger) Middleware {
    return func(next Service) Service {
        return &loggingMiddleware{
            next:   next,
            logger: logger,
        }
    }
}
```

You do not change `stringService`; you wrap it. Tests can still test `New()` without MW; wiring in main adds MW.

**Predict-then-answer A**

Question: must LoggingMiddleware live in `package service`?

- Predict: “yes, because it implements Service”.
- Answer: often yes (same package sees unexported next, or exports Middleware). Can also be `service` + a small `logging.go` file. Important: do **not** import `net/http` / kit transport here.

### Step 1 — wrapper struct

```go
type loggingMiddleware struct {
    next   Service
    logger log.Logger
}
```

Implement **every** method of the `Service` interface. When you add `Count`, you add a logging method too — the compiler forces you (advantage of the interface).

### Step 2 — `defer` + named returns (key pattern)

```go
func (mw loggingMiddleware) Uppercase(ctx context.Context, s string) (v string, err error) {
    defer func(begin time.Time) {
        _ = mw.logger.Log(
            "method", "uppercase",
            "input", truncate(s, 64),
            "output", truncate(v, 64),
            "err", err,
            "took", time.Since(begin),
        )
    }(time.Now())
    return mw.next.Uppercase(ctx, s)
}
```

Why named returns (`v`, `err`)?

- `defer` closes over the **named** results after `return`.
- Without names, a local `err` in defer does not see the return value reliably the same way.

**Predict-then-answer B**

Question: log *before* calling `next` instead of defer?

- Predict: “before + after = clear”.
- Answer: defer at the end catches the panic-free return path and one line; took measurement is more natural. If you need an “entered” log, that is another level (usually too much noise for the course).

### Step 3 — truncate input

```go
func truncate(s string, n int) string {
    if n <= 0 || len(s) <= n {
        return s
    }
    // caution: rune vs byte; for pedagogy byte OK with a note
    return s[:n] + "…"
}
```

Rules:

- never log full tokens / PII fields — better `input_len` than raw
- for StringService pedagogy, truncating the string is OK
- truncate output too (large uppercase result is rare, but discipline)

**Predict-then-answer C**

Question: may app log log full `s` because “it is not an HTTP body”?

- Predict: “yes, that is domain”.
- Answer: domain can still be PII (email in a string). Truncate + policy. App log ≠ permission for secrets.

### Step 4 — wiring: `svc = LoggingMiddleware(logger)(svc)`

```go
logger := newLogger() // from 07.10 root
appLogger := log.With(logger, "component", "service")

var svc service.Service
svc = service.New()
svc = service.LoggingMiddleware(appLogger)(svc)
```

Decorator order (important when you add 07.12):

```go
svc = service.New()
svc = service.LoggingMiddleware(appLogger)(svc)
svc = service.InstrumentingMiddleware(count, hist)(svc) // example order — document
```

What is “outside”: the first MW that sees the call depends on wrapping order. Document in README: “logging outside / instrumenting inside” or the reverse — team agreement.

### Step 5 — request id from context (without transport import)

```go
func (mw loggingMiddleware) Uppercase(ctx context.Context, s string) (v string, err error) {
    defer func(begin time.Time) {
        _ = mw.logger.Log(
            "request_id", requestIDFrom(ctx), // same key contract as 07.10
            "method", "uppercase",
            "err", err,
            "took", time.Since(begin),
        )
    }(time.Now())
    return mw.next.Uppercase(ctx, s)
}
```

`requestIDFrom` lives in a shared small package (`internal/ctxkey`) **or** a duplicated typed key by agreement — better one key package. Do **not** import `transport/http` to read a header here; the id must already be in ctx (07.10 Before).

### Step 6 — walkthrough: happy path through layers (transport + app)

1. Before: request_id in ctx.
2. decode → endpoint → `svc.Uppercase` (logging MW).
3. defer start = now.
4. next (real service) returns `"GO", nil`.
5. defer log: `method=uppercase err=null took=… request_id=…`.
6. encode 200.
7. Finalizer: `path=/uppercase code=200 request_id=…`.

Two lines, **different fields**, same request_id. That is the goal.

### Step 7 — walkthrough: `ErrEmpty`

1. Service returns `("", ErrEmpty)`.
2. App log: `err=empty string` (or `err=empty string` via `%v`), `method=uppercase`.
3. Transport: depends on style A/B — maybe `code=400` or `code=200` + body err.
4. Do not log path again in the app line.

### Step 8 — walkthrough: wire fail (bad JSON)

1. Decode error → endpoint/service **not** called.
2. App log has **no** line for this request (correct!).
3. Transport ErrorLogger + Finalizer carry the story.

If “no app log” confuses on-call — that is expected: there was no use-case call.

### Step 9 — do not duplicate transport log

App MW does **not** log:

- `path`, `code`, `http_method` (unless you have no transport log — but on this path you do)
- raw headers
- remote IP

App MW **logs**:

- `method` (use-case name)
- `took` (service call)
- `err`
- truncated input/output per policy
- `request_id`

**Predict-then-answer D**

Question: why not log `code` in Service MW?

- Predict: “completeness”.
- Answer: Service does not know HTTP code. Leakage would pull transport concepts downward or fake values.

### Step 10 — EndpointMiddleware logging? (contrast)

You can also log at the endpoint level (`endpoint.Middleware`). The course focuses on **Service** LoggingMiddleware because:

- typed arguments (string), easier truncate
- closer to the domain
- same MW works for HTTP and future gRPC (same svc)

Endpoint log makes sense for `interface{}` request debug — but easily slides into dump. Prefer service level here.

### Step 11 — errors and the `err` field in logfmt

```go
"err", err,
```

`kit/log` typically prints `err=null` or empty / string — check how your logger formats a `nil` error. Consistency > beauty.

Do not log `err.Error()` manually if `Log` already accepts `error` — double processing.

### Step 12 — testing MW (without log-as-test idol)

Approach:

1. Unit test the real service still without MW.
2. Optional: MW test with a `logger` that writes to a buffer — assert that the *call* to next works and that defer ran (presence of `method=uppercase`), not a brittle full-string match of the whole line.
3. Do not replace service table tests with log asserts (07.09).

### Step 13 — more methods: Count shape example

```go
func (mw loggingMiddleware) Count(ctx context.Context, s string) (n int, err error) {
    defer func(begin time.Time) {
        _ = mw.logger.Log(
            "method", "count",
            "input", truncate(s, 64),
            "n", n,
            "err", err,
            "took", time.Since(begin),
        )
    }(time.Now())
    return mw.next.Count(ctx, s)
}
```

Same form; different `method` label. Stable names → 07.12 metrics.

### Step 14 — order with future instrumenting MW

Two common patterns:

| Order (wrapping) | Effect |
|------------------|--------|
| log then instrument | log sees took including metrics overhead (small) |
| instrument then log | metrics “closer” to next; log outside |

Both OK if you **document**. Horror: different orders per env.

### Step 15 — anti-pattern: log inside `stringService.Uppercase` itself

```go
func (stringService) Uppercase(...) (string, error) {
    log.Println("uppercase called") // anti
    ...
}
```

Why bad: test noise, no truncate policy, hard to turn off, mixes concerns. MW keeps the core clean.

### Step 16 — anti-pattern: import transport because of request id

```go
import httptransport "github.com/go-kit/kit/transport/http"
// reading the header here — anti
```

Request id already in ctx. If it is not — 07.10 Before is missing, not a “fix” in service.

### Step 17 — walkthrough: panic? (boundary)

If `next` panics, defer still runs, but the named return `err` may stay nil while the process crashes — recover MW is a *different* topic. Do not treat logging MW as panic recovery. (Kit / your recover MW separately.)

2. Wire it in main.
3. One curl: confirm **two** log lines (transport + app) same request_id.
4. One bad JSON: confirm **no** app line.
5. Truncate: send a long string, verify the log is not infinite.

### Step 19 — mechanism wrap-up

You have Service LoggingMiddleware, wiring by decorator, truncate, ctx request_id, no transport import, no duplicate access log. Next: metrics middleware shape (07.12).

### Step 20 — field comparison: one table for the handbook

| Field | Transport (07.10) | App (07.11) |
|-------|-------------------|-------------|
| request_id | yes | yes (same key) |
| path | yes | no |
| code | yes | no |
| method (HTTP) | yes | no |
| method (use-case) | no | yes (`uppercase`) |
| took | request (optional) | service call |
| err | wire/encode | business err |
| input truncate | no (avoid body) | yes with policy |

Paste the table next to the code while reviewing the PR.

### Step 21 — walkthrough: slow service (diagnosis)

Symptom: clients timeout.

1. Transport `took_ms` large + `code=499/504`.
2. App `took` large + `err=null` (still working, but slow) *or* ctx err.
3. Conclusion: slow domain / downstream, not decode.

Without app log you only see the edge; without transport you do not see status. Both floors.

### Step 22 — when *not* to add an app log field

Do not add:

- `goroutine_id` (noise)
- full stack on every success
- random debug flag left on
- duplicate `ts` if root `With` already has ts

Fewer fields, clearer signal.

### Step 23 — walkthrough: two use cases in the same request? (no)

One HTTP request → one endpoint → one service method in the typical kit pattern. If orchestration calls two methods inside one service method, app log sees **one** outer method — measure internals separately if needed (later).

Do not expect two app lines `uppercase` + `count` for one `/uppercase` call.

### Step 24 — what about the `output` field

Uppercase output is often benign; still:

- truncate
- or `output_len` instead of raw
- never password/token fields if the domain grows

StringService pedagogy ≠ permission for prod dump.

### Step 25 — linking with Endpoint Chain (reminder)

You can also have `endpoint.Chain(Logging...)`. In this lesson the **primary** app log is Service MW. If you add endpoint log, mark it `component=endpoint` and do not make three lines for the same event without need.

## Rules and syntax

1. `LoggingMiddleware(logger) Middleware` — `Middleware func(Service) Service`.
2. `defer` + named returns for `took` / `err`.
3. `svc = LoggingMiddleware(logger)(svc)` in wiring.
4. Truncate / do not log PII.
5. No `net/http` in the logging MW package.
6. Do not duplicate path/code (07.10).
7. Same `request_id` ctx key as transport.
8. `component=service` (or app) via `log.With`.
9. Stable `method` names (`uppercase`, `count`).
10. Do not replace unit tests with log asserts.
11. Document MW order when there are several.
12. Every Service method → logging method (interface discipline).

## Decision analysis

| Option | When | Risk |
|--------|------|------|
| Service LoggingMiddleware | course default | low |
| Endpoint logging | debug interface{} | dump / PII |
| Log in core method | never (path) | mixing concerns |
| Transport log only | small demo | gap for style A |
| Log + metrics MW | after 07.12 | document order |
| Buffer logger in test | optional | not an idol |

## Trade-offs

- One app line per method = I/O cost; negligible on the exercise; at extreme QPS → sampling.
- Truncate loses data for debug — hence staging levels / temporary flag, not prod body.
- Named returns less “clean” to some — here they are a tool for defer.
- Duplicate took (transport vs app) requires documenting meaning.

## Common mistakes

1. Log without named returns → fake nil err.
2. Transport import in service MW.
3. Duplicating path/code.
4. Body/PII in the input field.
5. Println in core service.
6. Log-as-test instead of table test.
7. Different request_id key name.
8. MW only for Uppercase, forgotten Count.
9. Undocumented order with metrics.
10. Logging before next without took.
11. Panic recovery “hidden” in logging MW.
12. App log on decode fail (should not exist).

## Idiomatic Go

- Small `logging.go` next to service.
- Typed ctx keys shared.
- `log.With` component.
- Interface-driven: compiler forces new methods.
- Clean `New()` without a global logger.

## Practical scenario

Style A: HTTP 200 + `"err":"empty string"`. Transport Finalizer says success. App log says `err=empty string`. On-call filters `component=service err!=null` and sees the truth. Without 07.11, you would trust only the access log — wrongly.

## Deepening: application logging

### 1. insight

**`took` type.** `time.Duration` in logfmt often becomes the string `1.2ms` — OK. For metrics later use float seconds (07.12), do not mix.

Practical check: one app log line — how does `took` look?

### 2. insight

**Nil interface vs nil error.** If you wrap err, Log still sees non-nil. Keep the sentinel clean.

Practical check: does `errors.Is` still work after MW? (MW must not swallow.)

### 3. insight

**Do not log ctx deadline as PII.** You can log `ctx.Err()` after cancel — useful; not body.

Practical check: cancel test — does app see err?

### 4. insight

**Sampling success.** Log all err; sample ok — advanced ops topic; on the course log everything.

Practical check: do you need sampling on the exercise? Probably not.

### 5. insight

**Logger injection vs global.** MW carries a logger field — more testable than package `var Log`.

Practical check: is there a global mutable logger?

### 6. insight

**Dual MW on endpoint and service.** Rarely need both for the same event. Choose one primary (service).

Practical check: number of log lines per success request now?

### 7. insight

**Output logging caution.** Uppercase output can be huge. Truncate or `output_len`.

Practical check: truncate limit n agreed (64/128)?

### 8. insight

**Same method names as metrics.** `uppercase` string same in the 07.12 label.

Practical check: method name list in README.

### 9. insight

**Do not catch err just to “log nicer”.**

```go
v, err := mw.next.Uppercase(...)
if err != nil { mw.logger.Log(...); return "", err } // redundant with defer
```

Defer already works.

Practical check: is there a duplicate Log call?

### 10. insight

**Context values documentation.** Table key → who sets (Before) → who reads (MW).

Practical check: one table in a handbook note.

### 11. insight

**Log level.** kit/log often has no levels like slog; filtering outside. Do not fake level in every field without agreement.

Practical check: does the team use a level field?

### 12. insight

**Windows/dev SyncWriter.** Already from 07.10; app logger shares the same writer stack.

Practical check: do app and transport share root `With` ts?

### 13. insight

**Fail open.** If `Log` returns an error (disk full), do not break the request — hence `_ =`. Ops alert on the log pipeline separately.

Practical check: does Log error ever fail the request? It should not.

### 14. insight

**Preparation 07.12:** same wrapper shape; Counter/Histogram instead of Log. Logging remains the event; metrics the aggregate.

### Appendix: `logging.go` file template

```go
package service

import (
    "context"
    "time"

    "github.com/go-kit/log"
)

func LoggingMiddleware(logger log.Logger) Middleware {
    return func(next Service) Service {
        return &loggingMiddleware{next: next, logger: logger}
    }
}

type loggingMiddleware struct {
    next   Service
    logger log.Logger
}

func (mw loggingMiddleware) Uppercase(ctx context.Context, s string) (v string, err error) {
    defer func(begin time.Time) {
        _ = mw.logger.Log(
            "method", "uppercase",
            "input", truncate(s, 64),
            "err", err,
            "took", time.Since(begin),
        )
    }(time.Now())
    return mw.next.Uppercase(ctx, s)
}

func truncate(s string, n int) string {
    if len(s) <= n {
        return s
    }
    return s[:n] + "…"
}
```

Add `request_id` when the `ctxkey` package exists.

### Appendix: named returns — mini diagram

```
Uppercase(...) (v string, err error) {
    defer func(begin) {
        // reads v and err *after* return assignment
        Log(..., v, err, since(begin))
    }(now)
    return next.Uppercase(...)  // writes v, err
}
```

Without names `(string, error)`, defer closes over local shadows — a common trap.

### Appendix: decorator order example (document one)

```
Call enters: Instrumenting → Logging → core
because you wrapped: core = New()
             core = Logging(core)
             core = Instrumenting(core)
```

Outer MW = last wrap. If you need the reverse — swap the `=` line order and update README.

### Appendix: anti-pattern “log then change err”

```go
v, err := mw.next.Uppercase(ctx, s)
if err != nil {
    _ = mw.logger.Log("err", err)
    err = nil // anti: you swallow the error so you “do not scare” transport
}
return v, err
```

Logging MW **must not** swallow errors. It only observes.

After 07.11 it still holds: the table test for `ErrEmpty` remains. MW test (optional) proves that Log is called; it does not prove the domain.

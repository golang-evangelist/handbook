# 10.04 Querying the database: First, Find, Where, Scan

> **Go Path - Zero to Gopher** / **03 Others → GORM: An Object Relational Mapper for Go** / Lesson 10.04

## Lesson goals

After this lesson you should be able to:

- use `First`, `Take`, `Last`, `Find` with clear error expectations
- build conditions with `Where`, `Order`, `Limit`, `Offset` via safe placeholders
- use `Scan` / `Select` / `Pluck` for DTOs and aggregations
- distinguish `ErrRecordNotFound` from other errors
- avoid the N+1 preview and “load everything then filter in Go”
- read the SQL log / DryRun to confirm the query (predict-then-verify)

## Prerequisite

- Lessons 10.01–10.03
- Basic SQL WHERE / ORDER / LIMIT
- Understanding soft delete scope if the model has `DeletedAt`

## Problem this lesson solves

`Find(&slice)` without Where on a large table = production incident (memory, IO, lock).  
`First` returns `gorm.ErrRecordNotFound` — that is not “other errors”.  
`Where("name = " + userInput)` = SQL injection path.  

GORM offers placeholders, struct and map conditions — use them. This lesson teaches you to build a predictable SELECT and never concatenate values into a SQL string.

## Mental model

The chain is a builder:

```go
db.WithContext(ctx).
	Where("active = ?", true).
	Order("id desc").
	Limit(20).
	Find(&products)
```

Each step adds a part of the SQL. Execution is with `First` / `Find` / `Scan` / `Count` / `Pluck`.

| Method | Semantics when there are no rows |
|--------|----------------------------------|
| `First` | error `ErrRecordNotFound` |
| `Take` | error `ErrRecordNotFound` (without the default order by PK like First) |
| `Last` | error `ErrRecordNotFound` |
| `Find` | empty slice, usually **without** ErrRecordNotFound |

## Mechanism

### 1. `First` — one row or an error

When you call `First`, GORM expects exactly one row. If the row does not exist (or is soft-deleted and the scope hides it), you get `gorm.ErrRecordNotFound`. That is a domain signal for 404, not for retry.

```go
var p model.Product
err := db.WithContext(ctx).First(&p, id).Error
```

**Predict SQL before the Logger:**

```sql
SELECT * FROM "products"
WHERE "products"."id" = 42
ORDER BY "products"."id"
LIMIT 1
```

If the model has `DeletedAt`, **also predict**:

```sql
AND "products"."deleted_at" IS NULL
```

Variants of the same goal:

```go
db.First(&p, "sku = ?", sku)
db.Where("sku = ?", sku).First(&p)
```

Both should generate WHERE on `sku` with a placeholder. Compare Vars in DryRun.

### 2. `Find` — zero or more

`Find` fills a slice. An empty result is success with `len==0`, not `ErrRecordNotFound`. Mixing this semantics with First is a common bug in handlers.

```go
var list []model.Product
err := db.Where("cents >= ?", 1000).Find(&list).Error
```

**Predict:**

```sql
SELECT * FROM "products"
WHERE cents >= 1000
AND "deleted_at" IS NULL
```

Check `len(list)` in the test; do not look for ErrRecordNotFound.

### 3. `Where` with placeholder `?`

This is the basic security line. GORM translates `?` to `$1` (Postgres) or the dialect’s corresponding placeholder. The value travels separately from the SQL text.

```go
db.Where("name = ?", name)
```

**BAD — never in production:**

```go
db.Where("name = " + name)
```

**GOOD:**

```go
db.Where("name = ?", name)
```

**Predict attack** if the bad variant: the user sends `x' OR '1'='1` and widens the result. The placeholder prevents that because the value is not part of the query code.

### 4. `Where` with a map

A map is convenient for dynamic equality filters when you assemble conditions from an optional filter object.

```go
db.Where(map[string]interface{}{
	"active": true,
	"sku":    sku,
}).Find(&list)
```

**Predict:** `WHERE active = true AND sku = $1` (key order may vary).

For operators `>=`, `LIKE`, `IN` — a string with `?`, not a map.

### 5. `Where` with a struct

```go
db.Where(model.Product{SKU: sku, Active: true}).Find(&list)
```

Zero value fields in a struct condition are typically **ignored**. That is why `Active: false` often **does not** enter the WHERE.

**Predict the trap:** you think you are filtering inactive, but GORM ignores `false`. Use a map or:

```go
db.Where("active = ?", false)
```

### 6. `Order`, `Limit`, `Offset`

```go
db.Where("active = ?", true).
	Order("id DESC").
	Limit(limit).
	Offset(offset).
	Find(&list)
```

**Predict complete SELECT:**

```sql
SELECT * FROM "products"
WHERE active = true
AND deleted_at IS NULL
ORDER BY id DESC
LIMIT 20 OFFSET 40
```

Offset on huge sets becomes slow because the database must “skip” rows. Keyset (`WHERE id < ?`) is often better for an API feed.

### 7. Cap on Limit

Without an upper bound, the client sends millions. Cap is part of the API contract, not an “optimization later”.

```go
if limit <= 0 || limit > 100 {
	limit = 50
}
```

**Predict incident** without a cap: Find 500k rows, OOM or a huge GC pause.

### 8. `Select` — narrow columns

```go
db.Model(&model.Product{}).
	Select("id", "sku", "cents").
	Where("active = ?", true).
	Find(&list)
```

**Predict:** no `SELECT *`. On rows with large TEXT/JSONB columns this reduces IO and memory.

### 9. `Scan` into a DTO / aggregate

Do not pull the whole table into Go to sum. The database does aggregation; Scan reads the projection.

```go
type sumRow struct{ Cents int }
var s sumRow
err := db.Model(&model.Product{}).
	Select("COALESCE(SUM(cents),0) as cents").
	Where("active = ?", true).
	Scan(&s).Error
```

**Predict:**

```sql
SELECT COALESCE(SUM(cents),0) as cents
FROM "products"
WHERE active = true
AND deleted_at IS NULL
```

### 10. `Count` and exists

```go
var n int64
err := db.Model(&model.Product{}).Where("active = ?", true).Count(&n).Error
```

**Predict:** `SELECT count(*) FROM "products" WHERE ...`

Exists pattern:

```go
var n int64
db.Model(&model.Product{}).Where("sku = ?", sku).Limit(1).Count(&n)
exists := n > 0
```

Or `First` + `errors.Is(..., ErrRecordNotFound)`. Both are legitimate; choose by readability and index.

### 11. `Pluck`

```go
var skus []string
db.Model(&model.Product{}).Where("active = ?", true).Pluck("sku", &skus)
```

**Predict:** `SELECT "sku" FROM "products" WHERE active = true ...`

Useful for batch operations without the whole model in memory.

### 12. `IN` list — not a First loop

The anti-pattern generates N queries:

```go
for _, id := range ids {
	db.First(&p, id)
}
```

Correct:

```go
db.Where("id IN ?", ids).Find(&list)
```

**Predict:** one `WHERE id IN ($1,$2,...)`. The Logger must show **one** SELECT.

### 13. Like / ILIKE caution

```go
db.Where("name ILIKE ?", "%"+escapeLike(user)+"%")
```

Escape `%` and `_` in user input. Otherwise the user intentionally widens the match. `ILIKE` is Postgres-specific.

**Predict** without escape: input `%` matches everything.

### 14. DryRun for learning and tests

```go
stmt := db.Session(&gorm.Session{DryRun: true}).
	Where("active = ?", true).Find(&model.Product{})
sql := stmt.Statement.SQL.String()
vars := stmt.Statement.Vars
```

Predict SQL on paper, compare with `sql` and `vars`. This is the only reliable way to learn the generator without a side effect.

### 15. Raw when the builder hurts

```go
err := db.Raw(`
	SELECT sku, SUM(cents) AS total
	FROM products
	WHERE active = ? AND deleted_at IS NULL
	GROUP BY sku
	HAVING SUM(cents) > ?
`, true, 10_000).Scan(&rows).Error
```

Still **placeholders**. Raw is not permission to concatenate.

### 16. Soft delete and queries

The default scope hides soft-deleted. Admin:

```go
db.Unscoped().Where("sku = ?", sku).Find(&list)
```

**Predict the difference:** with Unscoped there is no `deleted_at IS NULL`; without Unscoped there is.

### 17. Errors — decision map

```go
err := db.First(&p, id).Error
switch {
case errors.Is(err, gorm.ErrRecordNotFound):
	// 404
case err != nil:
	// 500 / retry / log
default:
	// ok
}
```

`Find` with an empty result goes to `default` with `len==0`.

### 18. N+1 preview (bridge to 10.05)

```go
db.Find(&orders)
for i := range orders {
	db.Where("order_id = ?", orders[i].ID).Find(&orders[i].Items)
}
```

SQL count = 1 + N. Solution: `Preload` in 10.05. Already here: if the Logger shows a loop of the same SELECT — stop.

### 19. Indexes and Explain

```sql
EXPLAIN ANALYZE
SELECT * FROM products
WHERE active = true
ORDER BY id DESC
LIMIT 20;
```

The ORM does not remove DBA work. Add an index via migration (10.06).

### 20. Session and request DB

```go
reqDB := db.WithContext(ctx)
err := reqDB.Where("active = ?", true).Find(&list).Error
```

### 21. Dynamic filter without string building

```go
q := db.WithContext(ctx).Model(&model.Product{})
if f.SKU != "" {
	q = q.Where("sku = ?", f.SKU)
}
if f.MinCents != nil {
	q = q.Where("cents >= ?", *f.MinCents)
}
err := q.Limit(limit).Find(&list).Error
```

Every condition still uses `?`. Never join values into a string.

### 22. Group by projection

```go
type agg struct {
	SKU   string
	Total int
}
var rows []agg
err := db.Model(&model.Product{}).
	Select("sku, SUM(cents) as total").
	Where("active = ?", true).
	Group("sku").
	Scan(&rows).Error
```

**Predict:**

```sql
SELECT sku, SUM(cents) as total
FROM products
WHERE active = true AND deleted_at IS NULL
GROUP BY sku
```

### 23. Take and Last — briefly

```go
db.Take(&p)  // one row, ErrRecordNotFound if none
db.Last(&p)  // order by PK desc typically
```

Read docs for exact order. Do not mix with Find.

### 24. Step-by-step predict-then-verify (mandatory)

1. Write `First` by ID — predict SQL — Logger.
2. Write `Find` with Where — predict — Logger.
3. Write BAD Where with `+` locally — see why it is dangerous — replace with `?`.
4. Write struct Where with `Active:false` — predict the filter disappears — confirm.
5. Write map Where with `active:false` — predict it works — confirm.

### 25. Checklist before merging a query

- [ ] Placeholders, no value concatenation
- [ ] Limit + cap on lists
- [ ] First errors mapped
- [ ] Empty Find treated as empty, not a DB 404 error
- [ ] Soft delete scope understood
- [ ] No First-by-ID loop
- [ ] Aggregations in SQL where needed
- [ ] Logger/DryRun reviewed for the new chain

## Rules and syntax

1. Placeholder `?` (or map/struct API) — never concatenate user input into SQL.
2. `First` → always think about `ErrRecordNotFound`.
3. Empty `Find` ≠ error.
4. Cap on `Limit`.
5. `Select` only needed columns on large rows.
6. Aggregations in the database (`Scan`), not in a Go loop over the whole table.
7. `IN` instead of a `First` loop.
8. Predict SQL, verify Logger/DryRun.
9. Soft-deleted: `Unscoped` intentionally.
10. Offset vs cursor — choose consciously.

### Syntax patterns

```go
db.WithContext(ctx).First(&p, id)
db.WithContext(ctx).Where("active = ?", true).Order("id DESC").Limit(20).Find(&list)
db.Where(map[string]interface{}{"sku": sku}).First(&p)
db.Model(&model.Product{}).Select("sku, cents as total").Scan(&rows)
```

## Examples

### Example 1 — Get by ID

```go
func (r *Repo) ByID(ctx context.Context, id uint) (model.Product, error) {
	var p model.Product
	err := r.db.WithContext(ctx).First(&p, id).Error
	return p, err
}
```

#### Predict the result

SELECT … WHERE id = ? … LIMIT 1; error if none.

#### What happens here

The handler maps `ErrRecordNotFound` to 404.

### Example 2 — List with filter and pagination

```go
func (r *Repo) ListActive(ctx context.Context, limit, offset int) ([]model.Product, error) {
	if limit <= 0 || limit > 100 {
		limit = 50
	}
	var out []model.Product
	err := r.db.WithContext(ctx).
		Where("active = ?", true).
		Order("id DESC").
		Limit(limit).
		Offset(offset).
		Find(&out).Error
	return out, err
}
```

### Example 3 — Scan aggregate

```go
type sumRow struct{ Cents int }
var s sumRow
err := db.Model(&model.Product{}).
	Select("COALESCE(SUM(cents),0) as cents").
	Where("active = ?", true).
	Scan(&s).Error
```

### Example 4 — Injection anti-example

```go
// BAD
db.Where("name = " + name).Find(&list)
// GOOD
db.Where("name = ?", name).Find(&list)
```

### Example 5 — Pluck

```go
var skus []string
db.Model(&model.Product{}).Where("active = ?", true).Pluck("sku", &skus)
```

### Example 6 — IN list

```go
err := db.Where("id IN ?", ids).Find(&list).Error
```

### Example 7 — Filter struct in repo

```go
type ListFilter struct {
	Active *bool
	Limit  int
	Offset int
}

func (r *Repo) List(ctx context.Context, f ListFilter) ([]model.Product, error) {
	q := r.db.WithContext(ctx).Model(&model.Product{})
	if f.Active != nil {
		q = q.Where("active = ?", *f.Active)
	}
	limit := f.Limit
	if limit <= 0 || limit > 100 {
		limit = 50
	}
	var out []model.Product
	err := q.Order("id DESC").Limit(limit).Offset(f.Offset).Find(&out).Error
	return out, err
}
```

### Example 8 — Keyset pagination

```go
db.Where("active = ? AND id < ?", true, lastID).
	Order("id DESC").Limit(20).Find(&list)
```

### Example 9 — DryRun assert

```go
stmt := db.Session(&gorm.Session{DryRun: true}).

```

## Decision analysis

### Offset vs cursor

Offset is simple, bad deep. Keyset is more stable under inserts.

### Find in a loop by ID

Anti-pattern → `Where("id IN ?", ids)`.

### Builder vs Raw

Builder for CRUD lists. Raw for CTE/window — still with `?`.

### First vs Take

First orders by PK by default. Take does not impose the same order. Docs for your version.

## Trade-offs

| Approach | Gain | Cost |
|----------|------|------|
| Builder | Readable, safe | Complex SQL harder |
| Raw | Full power | More discipline |
| Load everything | “quick to write” | Production fire |
| Scan DTO | Thin payload | More types |
| Offset | Simple | Slow deep |
| Keyset | Stable | API cursor |
| Struct Where | Short | Zero trap for false |

## Common mistakes

1. `Find` of the whole table without Limit.
2. Ignoring the First vs Find error difference.
3. String-built Where (injection).
4. N+1 loop instead of IN/Preload.
5. Order without an index on large tables.
6. Scan into the wrong type → silent zero.
7. Struct Where with `Active: false` then the filter disappears.
8. Offset without a cap.
9. Expecting ErrRecordNotFound on empty Find.
10. LIKE pattern without escaping `%`/`_`.

## Idiomatic Go

```go
type ProductRepo struct{ db *gorm.DB }

func (r *ProductRepo) BySKU(ctx context.Context, sku string) (model.Product, error) {
	var p model.Product
	err := r.db.WithContext(ctx).Where("sku = ?", sku).First(&p).Error
	return p, err
}
```

Repo methods with ctx and a filter struct. Max limit cap at the API edge. Tests against a real database.

## Practical scenario

Admin endpoint `GET /products` without a limit. Table 500k. OOM. Fix: limit default 50 max 100, index on `active`. SQL log in staging PR checklist.

Search with concatenation — security review. Move to `?` + escape LIKE.

### One more predict-then-answer (queries)

```go
var list []Product
err := db.Where("sku = ?", sku).First(&list).Error
```

**What is not OK?** `First` expects one struct, not a slice. Use `Find` for a slice or `First` for a `Product` value or pointer to one.

### Mini query checklist

1. Placeholders, not Sprintf SQL
2. Limit on lists
3. First error = ErrRecordNotFound
4. Empty Find = len 0, not an error
5. Soft delete conscious
6. DryRun in review of suspicious chains

### Closing sentence

Every `Where` with user input goes through a placeholder. If you write a SQL string by concatenation, stop — that is not the GORM idiom.

## Summary

GORM queries are a chain that must stay predictable: placeholders (`?`, map, struct with caution), limits, correct errors for `First`, `Scan` for projections. Avoid loading whole tables and string-built SQL. `ErrRecordNotFound` is a signal for First/Take/Last, not for empty Find. The next lesson adds relations and `Preload` — where N+1 most often arises and where it is solved.

# 09.04 Embedding Static Resources with go:embed

> **Go Path - Zero to Gopher** / **03 Others → Docker for Software Development: Go Apps** / Lesson 09.04

## Lesson goals

After this lesson you should be able to:

- use the `//go:embed` directive for HTML, CSS, migrations, i18n, OpenAPI, and similar files
- explain the difference: **embed into the binary** versus **`COPY` static files into the image**
- serve static content via `embed.FS` and `http.FileServer` / `http.FS`
- know the limits: binary size, a change requires a rebuild, no secrets in embed
- decide what to embed and what to mount as a volume (uploads, runtime config)

## Prerequisite

- Go 1.22+ (`embed` exists since 1.16; here we work on 1.22+)
- Multi-stage Dockerfile from 09.01 / 08.02
- Basic `net/http`
- Understanding that a Go binary is one file on disk

## Problem this lesson solves

Classic Dockerfile:

```dockerfile
COPY ordersvc /app/ordersvc
COPY static /static
COPY migrations /migrations
COPY templates /templates
```

Works, but:

- the runtime image must carry a file tree beside the binary;
- it is easy to forget a `COPY` and the container starts without CSS;
- paths differ locally (`./static`) and in the container (`/static`);
- scratch/distroless deploy becomes “binary + manually added files.”

`go:embed` packages files **into** the binary at compile time. Docker then often only does:

```dockerfile
COPY --from=build /out/ordersvc /ordersvc
```

One artifact. Fewer ways to forget a resource.

## Mental model

```text
static/app.css  ──┐
static/index.html─┼── //go:embed ──►  part of the ordersvc binary
migrations/*.sql ─┘         │
                            ▼
                     go build
                            │
                            ▼
              Docker COPY only ordersvc
```

Embed is not a “magic volume.” Those are bytes stuck into the executable. Changing `app.css` = new `go build` = new image layer for the binary.

A volume is still needed for **runtime** data (user uploads, secrets mounted as a file, cache).

## Mechanism

### The `//go:embed` directive

Must sit immediately above a variable of type `string`, `[]byte`, or `embed.FS`:

```go
package web

import "embed"

//go:embed static/*
var staticFS embed.FS
```

Rules:

- the comment starts with `//go:embed` (no space between `//` and `go`);
- paths are relative to the file that contains the directive;
- do not embed `..` outside the module in a way the tool does not allow;
- empty directories are not included the way you might expect — focus on files.

### `embed.FS` vs `string` vs `[]byte`

| Type | When |
|-----|-----|
| `string` | one text file (e.g. one SQL schema) |
| `[]byte` | one binary file |
| `embed.FS` | tree / glob (static/*, migrations/*.sql) |

For a web UI usually `embed.FS`.

### Serving over HTTP

```go
mux.Handle("/static/", http.FileServer(http.FS(staticFS)))
```

Watch the prefix: if the embed root is `static/app.css`, the URL must match the `http.FS` root. Often:

```go
//go:embed static
var staticFS embed.FS

// URL /static/app.css → opens static/app.css in the FS
mux.Handle("/static/", http.FileServer(http.FS(staticFS)))
```

Or `fs.Sub` to strip the prefix:

```go
sub, err := fs.Sub(staticFS, "static")
if err != nil {
	log.Fatal(err)
}
mux.Handle("/assets/", http.StripPrefix("/assets/", http.FileServer(http.FS(sub))))
```

### Trace: local vs Docker

Locally:

```text
go run ./cmd/ordersvc
# reads embedded bytes from the binary in process memory
```

In Docker after embed:

```dockerfile
COPY --from=build /out/ordersvc /ordersvc
# NO COPY static/
```

**Predict then verify:** you remove the `static/` folder from disk **after** `go build`, then run the binary. Does `/static/app.css` still work?

**Answer:** Yes — the files are in the binary. (As long as you did embed before the build.)

### Embed vs COPY — decision table

| Resource | Embed | COPY into image | Volume |
|--------|-------|--------------|--------|
| HTML/CSS/JS admin UI (small) | yes | possible | no |
| Large video / ML model 2 GB | no | rarely | yes / CDN |
| SQL migrations | often yes | yes | no |
| User upload | no | no | yes |
| TLS cert / secrets | no | no | secret mount |
| Small `robots.txt` | yes | yes | no |

Rule: **what is part of the application version** and is small — embed. **What is data or a secret** — do not embed.

### Impact on Docker layer cache

With embed, a CSS change changes a Go package → the `go build` layer is invalidated. That is OK.

With a separate `COPY static/`, you can imagine a separate layer for static — but you lose single-binary simplicity and scratch-friendly deploy.

In practice for a Go API + small UI: embed wins.

### Migrations and embed

```go
//go:embed migrations/*.sql
var migrationsFS embed.FS
```

A migration tool can read from `fs.FS`. Do not bake a DB password into a SQL file in embed.

### Limits that hurt

1. **Size:** embed 50 MB assets → binary +50 MB → image +50 MB.
2. **Rebuild:** a designer changes a color → you need a new build (not just refreshing a volume).
3. **Secrets:** never `//go:embed secrets/prod.json`.
4. **Tests:** `*_test.go` cannot embed arbitrarily outside package rules — keep test fixtures in `testdata/` (Go convention).

### Predict then answer: `embed` and `go test`

**Question:** `//go:embed static/*` in package `web`. A test in the `web` package runs `go test`. Does the test see the same files?

**Answer:** Yes — embed happens during the test build of that package too. If `static/` is missing, package compilation fails, not runtime.

### Line-by-line: mini UI

```go
package main

import (
	"embed"
	"io/fs"
	"log"
	"net/http"
	"os"
)

//go:embed static/*
var staticRoot embed.FS

func main() {
	static, err := fs.Sub(staticRoot, "static")
	if err != nil {
		log.Fatal(err)
	}
	mux := http.NewServeMux()
	mux.Handle("/static/", http.StripPrefix("/static/", http.FileServer(http.FS(static))))
	mux.HandleFunc("/healthz", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
		_, _ = w.Write([]byte("ok"))
	})
	addr := os.Getenv("ADDR")
	if addr == "" {
		addr = ":8080"
	}
	log.Fatal(http.ListenAndServe(addr, mux))
}
```

What happens:

1. The compiler embeds everything under `static/`.
2. `fs.Sub` moves the root to the contents of `static`.
3. FileServer serves without opening the host filesystem for those files.
4. The Docker image copies only the binary.

### Combination: embed + one runtime config

```text
binary (embed UI + migrations)
+ env (ADDR, DATABASE_URL)
+ volume /data (upload)
```

That is a healthy split.

### Scratch image and embed

Scratch + static binary with embed = no need for `COPY static`. You still need CA if there is an HTTPS client. Embed does not replace the CA bundle.

### `.dockerignore` and embed

Embed reads files from the host **at `go build` time inside the build stage**. So the files must be in the build context (not ignored if they need to enter the builder).

```text
# .dockerignore
.git
# do NOT ignore static/ if you embed it in the build
```

If `.dockerignore` excludes `static/`, `go build` in Docker fails on embed.

### Error trace: wrong pattern

```go
//go:embed /absolute/path
var x embed.FS
```

Does not work — paths are relative. The compiler reports an error.

```go
// go:embed static/*
var x embed.FS
```

A space after `//` breaks the directive — it becomes an ordinary comment; `x` stays an empty FS or does not compile as you expect. It **must** be `//go:embed`.

## Rules and syntax

- `//go:embed` immediately above a `var` of type `string` | `[]byte` | `embed.FS`.
- Prefer `embed.FS` for multiple files.
- Do not embed secrets or user data.
- In the Docker prod image after embed you often do not need `COPY static/`.
- Do not put `static/` in `.dockerignore` if the build embeds it.
- Large files → CDN/volume, not embed.
- Changing embedded files = new build + new image tag.

## Examples

### Example 1 — Embed + distroless

```dockerfile
FROM golang:1.22.5-alpine AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -ldflags="-s -w" -o /out/app ./cmd/app

FROM gcr.io/distroless/static-debian12:nonroot
COPY --from=build /out/app /app
USER nonroot:nonroot
ENTRYPOINT ["/app"]
```

#### What happens here

No `COPY static`. The UI is in the `/app` binary.

### Example 2 — Reading one file as a string

```go
//go:embed banners/welcome.txt
var welcome string
```

#### What happens here

`welcome` is the file contents at build time. The zero value is not used — embed initializes it.

### Example 3 — Migrations

```go
//go:embed migrations/*.sql
var migFS embed.FS

entries, err := fs.ReadDir(migFS, "migrations")
```

#### What happens here

List of SQL files from the FS; the tool applies them in order. No dependency on the container working directory.

### Example 4 — When COPY still wins

Marketing wants to change `landing.html` without redeploying the binary — they mount a ConfigMap/volume on `/content`. Embed is not a good fit; `http.FileServer(http.Dir("/content"))` is.

### Example 5 — Wrong embed of a secret

```go
//go:embed .env
var envFile string // BAD
```

#### What happens here

A secret in the binary = a secret in the image = an incident. Use runtime env.

### Example 6 — Test `testdata`

```go
//go:embed testdata/fixture.json
var fixture []byte
```

in `*_test.go` or a test helper package — Go convention `testdata/` for fixtures.

## Decision analysis

| Decision | For | Against |
|--------|----|--------|
| embed all static | one artifact | fat binary |
| COPY static into image | changes without a Go rebuild (with re-COPY) | more moving parts |
| CDN for assets | global speed | infra complexity |
| volume for UI | hot change in dev | prod drift |

## Trade-offs

- **Design iteration speed vs single binary:** how often the UI changes picks the strategy.
- **Image size vs simplicity:** embed 5 MB OK; 500 MB not.
- **DevUX:** local `go run` with embed requires a rebuild for CSS; some teams in dev use `http.Dir` behind a build tag, in prod embed — advanced, but real.

## Common mistakes

1. **Wrong:** `// go:embed` (space).  
   **Effect:** not a directive; empty FS / error.  
   **Why:** wrong comment form.  
   **Fix:** `//go:embed`.

2. **Wrong:** embed `.env`.  
   **Effect:** secret leak.  
   **Why:** binary = public artifact in the registry.  
   **Fix:** runtime env.

3. **Wrong:** `.dockerignore` excludes `static/`.  
   **Effect:** Docker build fails on embed.  
   **Why:** files are not in the context.  
   **Fix:** allow `static/` in the context.

4. **Wrong:** expecting a CSS change on a volume to change embedded content.  
   **Effect:** old styles.  
   **Why:** embed is frozen in the binary.  
   **Fix:** rebuild or do not use embed for that resource.

5. **Wrong:** wrong URL vs FS root.  
   **Effect:** 404.  
   **Why:** `StripPrefix` / `fs.Sub` misaligned.  
   **Fix:** align the root.

6. **Wrong:** embed a 2 GB model.  
   **Effect:** unacceptable binary/image.  
   **Why:** wrong transport.  
   **Fix:** volume/S3/CDN.

7. **Wrong:** `COPY static/` and embed of the same — confusion about which is served.  
   **Effect:** you change the wrong source.  
   **Why:** two sources of truth.  
   **Fix:** pick one.

8. **Wrong:** relative path wrong relative to the package file.  
   **Effect:** compile error.  
   **Why:** paths are relative to the source file.  
   **Fix:** correct the glob.

## Idiomatic Go

- Package `web` or `static` keeps the embed `var` close to use.
- `http.FS` + `fs.Sub` for a clean URL space.
- `testdata/` for test fixtures.
- Do not export huge `embed.FS` without need.
- Document in README: “UI is embedded; change → rebuild.”

## Practical scenario

The team had a distroless image and forgot `COPY templates/` in one release — prod served 500 on every page. Hotfix: emergency `COPY`. Structural fix: `//go:embed templates/*.tmpl` + `html/template.ParseFS`. The next release has no way to “forget” templates.

Another time: they embedded `geoip.mmdb` (120 MB). Image pull slowed; they moved to a volume mount with an init container. Embed stayed for 200 KB of HTML.

## Check questions

1. **What does `//go:embed` do?**  
   Embeds files into the binary at compile time.

2. **Does scratch need `COPY static/` with embed?**  
   Not for those files — they are already in the binary.

3. **May a secret go in embed?**  
   No.

4. **Which type for a file tree?**  
   `embed.FS`.

5. **What if `.dockerignore` removes static?**  
   The build in Docker does not see the files for embed.

6. **Does a CSS change require a rebuild?**  
   Yes, with embed.

7. **What is `fs.Sub` for?**  
   Moves the FS root for cleaner URLs.

8. **When does a volume beat embed?**  
   Runtime data, large files, hot-change without a rebuild.

When you get a 404 in the UI after switching to embed, first check `fs.Sub` and the prefix. When the image “has no CSS,” check whether you are still in `http.Dir` mode reading an empty disk in scratch.

Embed is a version contract: UI and API line up in the same SHA. That is an advantage for small admin UIs and a pain for heavy asset pipelines.

### Additional mechanism: build tags for dev vs prod assets

Advanced, but a real pattern:

```go
//go:build !dev

package web

import "embed"

//go:embed static/*
var Static embed.FS
```

```go
//go:build dev

package web

import (
	"os"
	"net/http"
)

// in dev you read from disk for hot reload of CSS
func StaticHandler() http.Handler {
	return http.FileServer(http.Dir("static"))
}
```

Do not mix this with a Docker `target`. Idea: local `go run -tags dev` without an embed rebuild for every color; prod binary always embeds. Document the tags in README.

### Trace: binary size

```text
go build -o app.unembed ./cmd/app   # without large assets
go build -o app.embed ./cmd/app     # with embed 3 MB CSS/JS
ls -lh app.*
```

Difference ≈ size of embedded files (plus a little overhead). If the difference is not ≈ expected, the embed pattern is not hitting those files (wrong glob).

### Predict then answer: embed and module cache

**Question:** You change only `static/app.css`. Does the `go mod download` Docker layer invalidate?

**Answer:** No. The `COPY . .` and `go build` layers invalidate. The module layer stays CACHED — another reason for the order from 08.01/09.01.

### HTTP caching headers with embed

Embedded assets are version-tied to the binary. You can give a long `Cache-Control` with a fingerprint in the URL (`/static/app.f00dcafe.css`) or a short cache if the URL stays put. Do not mix with CDN invalidation — that is an ops topic.

### Security: XSS and embedded HTML

Embed does not make HTML safe. You still escape in templates (`html/template`). Embed only transports bytes.

### Embed checklist before merge

1. No secrets in embed paths
2. Glob covers expected files (`go list` / a test that reads the FS)
3. Dockerfile does not forget context for static
4. Distroless/scratch has no superfluous `COPY static`
5. Measured binary size before/after
6. README says “UI changes with a rebuild”

### Mini exercise in the text

Imagine three files: `static/a.css` (10 KB), `models/weights.bin` (800 MB), `.env` (secret). Which do you embed?

**Answer:** only `a.css`. Weights → volume/S3. `.env` → never.

### Workbook: from COPY static to embed

1. The starting Dockerfile has `COPY static /static` and code `http.Dir("/static")`.
2. Move to `//go:embed static/*` + `http.FS`.
3. Remove `COPY static` from the runtime stage.
4. Build scratch/distroless — UI still works.
5. Change CSS, rebuild, new digest — confirm the style changes only after rebuild.
6. Measure `ls -lh` of the binary before/after a large PNG — decide whether the PNG goes to a CDN.

### Trace: template + embed

```go
//go:embed templates/*.tmpl
var tmplFS embed.FS

t, err := template.ParseFS(tmplFS, "templates/*.tmpl")
```

`html/template` + ParseFS is the real API. Escape remains mandatory. Embed does not change the XSS model.

### Predict then answer: embed in another package

**Question:** `//go:embed` in package `web`, and `main` only imports `web`. Does `main` need an embed directive?

**Answer:** No. Embed is per package that compiles those files. Importing `web` pulls in the embedded FS.

### Dev hot reload trade-off

Option A: always embed (simple, slower CSS feedback).  
Option B: build tag `dev` + `http.Dir` (faster feedback, two modes).  
Option C: Air/live reload tool out of scope — do not invent one.

Choose A until the UI is heavy; B when design iterates daily.

### Additional trace: MIME and FileServer

`http.FileServer` itself sets Content-Type by extension for many types. For nonstandard extensions check the response header. Embed does not change MIME logic — it only changes the byte source (FS instead of disk).

### Predict: two embeds

```go
//go:embed migrations/*.sql

```

Two FS, two roots. Do not mix Put into the same var without reason. Test both FS.Open paths.

### Why this matters for a Docker course

Single binary + embed = fewer Dockerfile moving parts = fewer prod incidents like “forgotten COPY.” That is an operational win, not just a language convenience.

### More on testdata

```go
//go:embed testdata/*
var testData embed.FS
```

in a `_test.go` package — fixtures travel with the tests. Do not mix `testdata` into production embed without intent.

### Predict: embed and go:generate

Some generators write files that you then embed. Order in CI: generate → test → build. If generate fails, embed sees old or no files.

### Closing note 09.04

If UI and API share the same SHA binary, “works on my CSS, not on the server” disappears as a bug class — as long as you do not forget a rebuild.

### Extended mechanism: embed.FS Open trace

```go
f, err := staticFS.Open("static/app.css")
if err != nil {
	log.Fatal(err) // no file in embed — wrong glob or dockerignore
}
defer f.Close()
st, _ := f.Stat()
log.Println("size", st.Size())
```

**Predict:** the path in Open must match the path inside the FS (with or without a `static/` prefix depending on the directive). If embed reads `//go:embed static/*`, keys usually include `static/...`.

### Table: error → cause

| Symptom | Cause | Fix |
|---------|-------|-----|
| compile: pattern matches no files | empty/missing dir | add a file or fix the glob |
| 404 on /static/... | Sub/StripPrefix | align |
| old CSS in prod | you did not rebuild | new image |
| build fail in Docker | dockerignore | allow static |
| huge image | embed too large | CDN/volume |

`go:embed` is a bridge between Go binary discipline and Docker thinness. Use it deliberately.

If after this lesson the Dockerfile still does `COPY static` alongside embed of the same tree — you will have two sources of truth. Pick one.

Once more: secrets do not go into embed. Large files do not go into embed. Small versioned assets — yes.

## Summary

`go:embed` packages static files into the binary, which simplifies Docker (`COPY` only the artifact) and reduces “forgotten static” incidents. It is not used for secrets or huge files. `embed.FS` + `http.FS` serves the UI; migrations can use the same mechanism. Changing embedded content = a new build and a new image.

# 06.04 Working with the Time Package

> **Go Path - Zero to Gopher** / **01 Basics → The Go Standard Library** / Lesson 06.04

## Lesson goals

After this lesson you should be able to:

- create and compare `time.Time` values (`Before`, `After`, `Equal`);
- compute with `time.Duration` and parse durations (`ParseDuration`);
- explain why `Time` also carries a monotonic clock part and how that helps `Since`/`Until`;
- parse and format via the reference layout template `Mon Jan 2 15:04:05 MST 2006` — as a **mnemonic**, not as “now”;
- work with `time.Location` (time zones) and separate storage (UTC) from display;
- distinguish `Timer` and `Ticker`, know why `Stop` is required, and why `time.After` in a loop is dangerous.

## Prerequisite

- Basic Go types and errors.
- 06.02–06.03 preferred.
- Go 1.22+.

## Problem this lesson solves

Time in software breaks at known places:

- date strings in a local format without a zone specification;
- comparing wall time after an NTP clock jump;
- `time.Parse` with a layout from another language (`YYYY-MM-DD`) that in Go is **not** a valid template;
- a ticker that was never stopped → goroutine leak;
- mixing the server’s local zone and UTC in an API (“invoice shifted a day back”).

This lesson builds a disciplined model: instant, duration, zone, signal schedule.

## Mental model

Three concepts:

1. **Instant** — `time.Time` (an absolute point on the time axis + zone information for display)
2. **Duration** — `time.Duration` (nanoseconds as an `int64` definition type in package `time`)
3. **Signal schedule** — `Timer` / `Ticker` / `time.After` / `context` timeout

### Reference time is a layout mnemonic, not “now”

In Go, format and parse do **not** use `YYYY`, `dd`, `HH` as in many other languages. Instead you use parts of one fixed reference instant:

```text
Mon Jan 2 15:04:05 MST 2006
```

That is **not** your laptop’s current time. It is not “an example that changes”. It is a **template** the Go authors chose because the numbers 1–7 line up nicely in it:

| Part of the reference instant | Meaning in the layout | Example in your format |
|--------------------------|---------------------|------------------------|
| `1` (month: January → 01 in other forms) | month | `01` or `1` or `Jan` |
| `2` (day of month) | day | `02` or `2` |
| `3` (hour in 12h form; in the reference it is 15 for 24h) | hour | `15` (24h) or `03` + `PM` |
| `4` (minute: 04) | minute | `04` |
| `5` (second: 05) | second | `05` |
| `6` (year: 2006) | year | `2006` or `06` |
| `7` (zone: MST) | zone | `MST` or `-0700` |

Remember the sentence: **you write the layout as if you were formatting that famous instant January 2, 2006 at 15:04:05 MST** — not as if you were formatting “today”.

Example: you want ISO date `2026-09-25`. The layout is not `YYYY-MM-DD`. The layout is `2006-01-02`, because in the reference instant year=2006, month=01, day=02.

### Monotonic clock

`time.Now()` returns a `Time` that internally also carries **wall** time (what the wall clock says) and a **monotonic** measurement (how many nanoseconds passed since some start, resistant to clock moves). That is why `time.Since` and `time.Until` are more reliable for measuring duration than manually subtracting wall clocks after an NTP correction.

## Mechanism

### Creating an instant

```go
now := time.Now()
utc := time.Now().UTC()
t := time.Date(2026, 9, 25, 22, 0, 0, 0, time.UTC)
```

- `Now` — instant according to the machine clock (with local location in display).
- `UTC()` — the same instant, display/zone UTC.
- `Date` — explicit construction; **always** name a `Location` (here `time.UTC`).

### Duration

```go
d := 2*time.Second + 500*time.Millisecond
time.Sleep(d)
deadline := time.Now().Add(5 * time.Minute)
elapsed := time.Since(start)
```

`Duration` is a type with methods `Seconds()`, `Milliseconds()`, etc. Addition and multiplication by a number work because the underlying type is `int64` nanoseconds.

Parsing a human record: `time.ParseDuration("1h30m")` → a duration. Do not mix this with `time.Parse` for calendar strings.

### Parse / Format — layout from the 2006 template

```go
const layout = "2006-01-02 15:04:05"
t, err := time.Parse(layout, "2026-09-25 22:15:00")
s := t.Format(layout)
```

- `Parse` interprets the input string **by the same layout**.
- `Parse` without a zone in the layout treats the time as UTC.
- `ParseInLocation(layout, value, loc)` interprets the digits in the given zone.
- `Format` does the reverse: instant → string by layout.

Constants in the package: `time.RFC3339`, `time.RFC3339Nano`, `time.Kitchen`, etc. — ready-made layout strings.

### Location

```go
loc, err := time.LoadLocation("Europe/Belgrade")
local := time.Now().In(loc)
```

`LoadLocation` reads the IANA zone database (on Windows Go carries a built-in copy in newer versions). The same absolute instant in another zone changes the **display** of hour/date (DST included).

API idiom: **store UTC**, localize at the edge (UI, PDF, email).

### Timer vs Ticker

| Tool | Behavior |
|------|-----------|
| `time.NewTimer(d)` | sends once on `C` after `d` |
| `time.NewTicker(d)` | periodically sends on `C` |
| `time.After(d)` | returns a channel that fires once; suitable for `select`, not for a tight loop |
| `time.Sleep(d)` | blocks the current goroutine |

Always `Stop()` when you no longer need it. For a ticker: `defer ticker.Stop()`.

`time.After` in an infinite loop allocates a new timer every round that lives until it expires — under load it leaks memory. Better: one `Timer` + `Reset`, or `context.WithTimeout`.

## Rules and syntax

### Layout rules (memorize)

| You want | You write in the layout |
|-------|------------------|
| year 4 digits | `2006` |
| month number | `01` or `1` |
| day | `02` or `2` |
| hour 24h | `15` |
| minute | `04` |
| second | `05` |
| AM/PM hour | `03` + `PM` |
| numeric zone | `-0700` or `Z07:00` |

Do **not** use `YYYY-MM-DD` — that is not the Go layout language. If you see `YYYY` in Go code, that is a bug or another ecosystem.

### Comparison

```go
t1.Before(t2)
t1.After(t2)
t1.Equal(t2) // prefer for “same instant”, not always ==
```

`Equal` compares the instant on the axis, even if the Locations differ (same absolute instant).

### JSON and API

Often RFC3339:

```go
t.Format(time.RFC3339)
time.Parse(time.RFC3339, s)
```

## Examples

### Example 1 — Duration and deadline

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	start := time.Now()
	deadline := start.Add(150 * time.Millisecond)
	for time.Now().Before(deadline) {
		time.Sleep(40 * time.Millisecond)
	}
	fmt.Println("elapsed:", time.Since(start))
}
```

#### What happens here

1. `start` records the entry instant.
2. `Add(150ms)` makes a deadline on the time axis.
3. The loop runs while “now” is before the deadline; each round sleeps 40ms — a work simulation.
4. `Since(start)` returns the elapsed `Duration`. It uses monotonic measurement where possible, so the number is more reliable than `Now().Sub(start)` after a wall-clock jump.

Expected print: elapsed around 150ms+ (sleep granularity is not perfect).

### Example 2 — Parse/Format with the reference layout

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	const inLayout = "02.01.2006 15:04"
	const outLayout = "2006-01-02T15:04:05Z07:00"

	t, err := time.Parse(inLayout, "25.09.2026 22:40")
	if err != nil {
		panic(err)
	}
	fmt.Println(t.Format(outLayout))
	fmt.Println(t.Format(time.RFC3339))
}
```

#### What happens here

1. `inLayout` uses `02` (day), `01` (month), `2006` (year), `15` (hour), `04` (minute) — all from the reference template, not “today”.
2. Input `"25.09.2026 22:40"` maps: day=25, month=9, year=2026, hour=22, minute=40.
3. Because the layout has no zone, `Parse` interprets as UTC.
4. `Format(outLayout)` and `RFC3339` give an ISO-ish string suitable for log and API.

If someone wrote layout `"DD.MM.YYYY"`, Parse would **wrongly** interpret or throw an error — because `Y` and `D` are not Go layout tokens in that sense.

### Example 3 — Location Europe/Belgrade

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	loc, err := time.LoadLocation("Europe/Belgrade")
	if err != nil {
		panic(err)
	}
	utc := time.Date(2026, 3, 29, 0, 30, 0, 0, time.UTC)
	fmt.Println("UTC     :", utc)
	fmt.Println("Belgrade:", utc.In(loc))
}
```

#### What happens here

1. `LoadLocation` loads zone rules (including DST).
2. `Date(..., UTC)` makes the absolute instant 29.3.2026 00:30 UTC.
3. `In(loc)` does not change the instant on the axis — it changes the **display** in Belgrade local time.
4. Around a DST transition the UTC↔local difference is not always the same offset — that is why an API stores UTC.

### Example 4 — Ticker with Stop

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	ticker := time.NewTicker(200 * time.Millisecond)
	defer ticker.Stop()

	timeout := time.After(1 * time.Second)
	n := 0
	for {
		select {
		case <-ticker.C:
			n++
			fmt.Println("tick", n)
		case <-timeout:
			fmt.Println("done")
			return
		}
	}
}
```

#### What happens here

1. The ticker sends on `C` roughly every 200ms.
2. `defer Stop()` guarantees cleanup when `main` exits — no leak.
3. `time.After(1s)` once closes the timeout branch after a second.
4. `select` waits for the first ready channel. The tick count will be around 5 (depends on scheduling).
5. After `"done"` the function returns; `Stop` runs.

### Example 5 — caution around `time.After` in a loop

```go
package main

import (
	"context"
	"fmt"
	"time"
)

func loose(ctx context.Context) {
	// bad pattern in a long loop:
	// for {
	//   select {
	//   case <-time.After(time.Second):
	//   case <-ctx.Done():
	//     return
	//   }
	// }
}

func better(ctx context.Context) {
	t := time.NewTimer(time.Second)
	defer t.Stop()
	for {
		select {
		case <-t.C:
			fmt.Println("tick-once-pattern")
			if !t.Stop() {
				select {
				case <-t.C:
				default:
				}
			}
			t.Reset(time.Second)
		case <-ctx.Done():
			return
		}
	}
}
```

#### What happens here

1. The commented bad pattern: every round makes a new timer via `After`. If `ctx` lives long and the other branch often “wins”, old timers still live until expiry → memory pressure.
2. `better` keeps **one** `Timer`, resets it, and listens to `ctx.Done()`.
3. In production for HTTP often `context.WithTimeout` instead of raw sleep/after — cancellation propagates.

(`Stop`/`Reset` details are thin ice — in real code check `Timer.Reset` documentation for your Go version and prefer `context` where you can.)

## Decision analysis

| Need | Choice |
|---------|-------|
| storage / API | UTC + RFC3339 |
| UI for the user | `In(loc)` |
| measuring latency | `Since` / `Duration` |
| one-shot timeout | `Timer` or `context.WithTimeout` |
| periodic work | `Ticker` + `Stop` |
| human date input | layout from the 2006 template, never `YYYY` |

## Trade-offs

| Approach | Plus | Minus |
|---------|------|-------|
| always UTC | less confusion | need localization at the edge |
| local everywhere | “natural” for desktop | hell in distributed systems |
| string dates without zone | short | ambiguous |
| ticker forever | simple | leak if you forget Stop |
| `After` in `select` once | short | dangerous in a tight loop |

## Common mistakes

1. **Wrong:** layout like `YYYY-MM-DD` (language from another ecosystem).  
   **Effect:** wrong parse or confusing result.  
   **Why:** Go expects reference numbers from the 2006 template.  
   **Fix:** `2006-01-02` for an ISO date.

2. **Wrong:** treating the reference time as “the example’s current time”.  
   **Effect:** the developer changes the layout “to today’s date” and everything breaks.  
   **Why:** it is a fixed mnemonic, not a sample of Now().  
   **Fix:** always the same `Mon Jan 2 15:04:05 MST 2006` parts.

3. **Wrong:** ticker without `Stop`.  
   **Effect:** goroutine / timer leak on restarts.  
   **Why:** a ticker lives until you stop it.  
   **Fix:** `defer ticker.Stop()`.

4. **Wrong:** `time.After` in a tight infinite loop.  
   **Effect:** memory growth under load.  
   **Why:** every call allocates a timer.  
   **Fix:** one `Timer`+`Reset` or `context`.

5. **Wrong:** ignoring the error from `Parse`.  
   **Effect:** zero-value time (`0001-01-01`) goes on as a “valid” date.  
   **Why:** `Parse` returns `(Time, error)`.  
   **Fix:** always check `err`.

6. **Wrong:** sending local server time without a zone in an API.  
   **Effect:** clients in other zones see shifted days.  
   **Why:** the same wall clock means different calendar dates.  
   **Fix:** UTC + RFC3339; localize in the UI.

## Idiomatic Go

- Store UTC, display locally.
- Layout exclusively from the 2006 reference time.
- `Equal` for comparing instants when needed.
- Stop tickers/timers.
- For an HTTP deadline use `context`, not only raw sleep.
- `ParseDuration` for “1h30m”; `Parse` for calendar strings — do not mix.

## Practical scenario

Invoices were “shifted a day back” for users in the US because the API sent local server time without a zone. Moving to UTC + RFC3339 in JSON, and `Europe/Belgrade` only in PDF render, settled the dispute. Another incident: a ticker in a connection-pool health check was not stopped on shutdown — the goroutine count grew. `defer ticker.Stop()` + a shutdown signal fixes it. Third: a junior wrote `YYYY-MM-DD` in the layout because “that’s how SQL works” — parse gave nonsense dates until they switched to `2006-01-02`.

## Deeper pass: layout as a mnemonic (once more, slower)

Beginners remember wrongly: “the reference time is an example of the present”. Correction:

You **never** change the layout to be “today’s date”. The layout is always composed of parts of a fixed instant:

```text
Mon Jan 2 15:04:05 MST 2006
 |   |   | |  |  |  |   |
day  mon day hr min sec zone year
Sun  Jan  2 15  04 05 MST 2006
```

You want format “day.month.year hour:minute” as often written on paper in Serbia → layout `"02.01.2006 15:04"`.  
You want only the year → `"2006"`.  
You want RFC3339 → use `time.RFC3339` (already a ready layout string).

### Trace: Parse then Format

Input: `"25.09.2026 22:40"`  
Layout: `"02.01.2006 15:04"`

1. `02` place → reads `25` as day.
2. `01` place → reads `09` as month.
3. `2006` place → reads `2026` as year.
4. `15` → hour 22; `04` → minute 40.
5. No zone in the layout → UTC.
6. `Format(time.RFC3339)` → string with `Z` or an offset.

If the layout wrongly becomes `"YYYY-MM-DD"`, Go does not interpret `Y` as year the way other languages do — you get an error or a nonsense result. That is why the 2006 mnemonic is not decoration: it **is** the layout language.

### Monotonic vs wall — mini thought experiment

1. `start := time.Now()`
2. An administrator moves the system clock back 1 hour.
3. `time.Since(start)` still tends to show real elapsed (monotonic), while naive subtraction of wall clocks could give a negative or strange result.

That is why you measure latencies with `Since`/`Until`/`Duration`, not with string dates.

### Quick layout example reference

```go
time.Now().Format("2006-01-02")            // date
time.Now().Format("15:04:05")              // time of day
time.Now().Format("02 Jan 06 15:04 MST") // style close to RFC822
```

### Measuring a function

```go
func timed(name string, fn func()) {
	start := time.Now()
	fn()
	fmt.Println(name, time.Since(start))
}
```

Use in rough sketches before `testing.B`.

2. API: UTC + RFC3339.
3. UI: `In(loc)`.
4. Ticker/Timer: `Stop`.
5. No `After` in a tight infinite loop.

### Exercise R1 — Parse then Format (Serbian input → RFC3339)

```go
package main

import (
	"fmt"
	"time"
)

func main() {
	layout := "02.01.2006 15:04"
	input := "25.09.2026 22:40"
	t, err := time.Parse(layout, input)
	if err != nil {
		panic(err)
	}
	fmt.Println(t.UTC().Format(time.RFC3339))
}
```

#### What happens here

1. The layout is not “today’s date” — parts come from the fixed mnemonic `Mon Jan 2 15:04:05 MST 2006`.
2. `02` reads day, `01` month, `2006` year, `15` hour, `04` minute.
3. Without a zone in the layout, `Parse` interprets as UTC.
4. `Format(time.RFC3339)` gives an interoperable string for an API.
5. A wrong layout like `YYYY-MM-DD` is **not** the Go layout language — you get an error or nonsense.

### Exercise R2 — deliberate bad layout

```go
_, err := time.Parse("YYYY-MM-DD", "2026-09-25")
fmt.Println(err)
t2, err2 := time.Parse("2006-01-02", "2026-09-25")
fmt.Println(t2, err2)
```

#### What happens here

1. The first call shows why you do not carry SQL/JS habits into Go.
2. The second call uses the correct mnemonic — parsing succeeds.
3. In code review look for `2006` in the layout string as a health signal.

### Exercise R3 — Location: same instant, two calendars

```go
utc := time.Date(2026, 9, 25, 22, 0, 0, 0, time.UTC)
loc, err := time.LoadLocation("America/New_York")
if err != nil {
	panic(err)
}
fmt.Println(utc.Format(time.RFC3339))

```

#### What happens here

1. `Time` stores the instant; `Location` changes the **display**.
2. `In(loc)` does not “move” the absolute instant — it changes the wall clock in that zone.
3. The API stores UTC + RFC3339; the UI localizes via `In`.
4. A `LoadLocation` error must be checked (wrong zone name).

| Layer | What you store | Example |
|------|-----------|--------|
| DB / API | UTC instant | RFC3339 with `Z` |
| UI / PDF | local display | `Europe/Belgrade` |
| Latency measurement | `Duration` | `time.Since` |

### Exercise R4 — Duration and Since

```go
start := time.Now()
// ... work ...
fmt.Println("took", time.Since(start))

d, err := time.ParseDuration("1h30m")
if err != nil {
	panic(err)
}
fmt.Println(d, d.Minutes())
```

#### What happens here

1. `Since` measures elapsed time with the monotonic clock where possible — resistant to wall-clock moves.
2. `ParseDuration` understands `h`, `m`, `s` — it is not calendar `Parse`.
3. Do not mix `Parse` (calendar) and `ParseDuration` (span).

### Exercise R5 — Ticker with Stop

```go
ticker := time.NewTicker(200 * time.Millisecond)
defer ticker.Stop()

for i := 0; i < 5; i++ {
	<-ticker.C
	fmt.Println("tick", i)
}
```

#### What happens here

1. `NewTicker` sends on channel `C` periodically.
2. `Stop` stops the ticker — without that a goroutine / resource leaks in a long-lived process.
3. `defer ticker.Stop()` is the idiom at function scope.
4. `time.After` in an infinite loop allocates new timers — prefer `Ticker` or `Timer` + `Reset`.

### Decision table — Timer vs Ticker vs After

| Need | API | Note |
|---------|-----|----------|
| Once after N | `Timer` / `After` | `After` handy in `select` |
| Periodically | `Ticker` | always `Stop` |
| Request deadline | `context` + timeout | not only `Sleep` |
| Rough measurement | `Since` / `Until` | monotonic |

### Workshop FAQ

**Q: Why specifically 2006?**  
A: A fixed mnemonic with numbers 1–7 that map date/time parts. It is not “an example of the present”.

**Q: `Equal` or `==` for Time?**  
A: `Equal` compares the instant ignoring Location display; read the docs when comparing wall vs monotonic.

**Q: How do I parse with a local zone?**  
A: `ParseInLocation(layout, value, loc)` — digits are interpreted in that `Location`.

**Q: Does `Sleep` kill tests?**  
A: Slow tests. Prefer short durations or a fake clock in more serious packages.

**Q: RFC3339Nano?**  
A: When you need higher precision in the string; for most APIs RFC3339 is enough.

**Q: What if `LoadLocation` does not find the zone?**  
A: Return an error to the user / document a fallback; do not swallow `err`.

**Q: Monotonic clock — when does it matter?**  
A: When measuring latency while NTP/admin can move the wall clock.

### Extra pass — API date without “day shift”

Scenario: server in `Europe/Belgrade`, client in `America/New_York`. An invoice “for 25.09.” must not become 24.09. because of the zone.

```go
// GOOD: store the instant in UTC
t := time.Date(2026, 9, 25, 12, 0, 0, 0, time.UTC)
payload := t.Format(time.RFC3339)

// UI localization
loc, err := time.LoadLocation("America/New_York")
if err != nil {
	return err
}
display := t.In(loc).Format("02.01.2006")
```

#### What happens here

1. `Date(..., time.UTC)` builds an instant without the server’s local shift.
2. RFC3339 in the payload carries zone/offset — interoperable.
3. `In(loc)` only in display — the calendar day depends on the zone on purpose.
4. Bad path: `time.Now()` locally without a zone in JSON — clients “see” the wrong day.

### Exercise R6 — Equal and Location

a := time.Date(2026, 1, 1, 0, 0, 0, 0, time.UTC)

### Exercise R7 — context deadline instead of blind Sleep

```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel()

select {
case <-ctx.Done():
	fmt.Println("timeout", ctx.Err())
case <-time.After(5 * time.Second):
	fmt.Println("too long — should not arrive")
}
```

#### What happens here

1. `context` carries a deadline through calls — better than a local `Sleep` in a library.
2. `cancel` frees timer resources — `defer cancel()` idiom.
3. In a tight loop still avoid repeated `time.After` without need.

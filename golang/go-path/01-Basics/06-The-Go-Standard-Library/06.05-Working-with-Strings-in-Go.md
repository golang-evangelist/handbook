# 06.05 Working with Strings in Go

> **Go Path - Zero to Gopher** / **01 Basics → The Go Standard Library** / Lesson 06.05

## Lesson goals

After this lesson you should be able to:

- explain that a `string` is an **immutable** sequence of bytes (often UTF-8), that `len` counts **bytes**, and that `range` yields **runes**;
- illustrate that with a concrete multi-byte example (e.g. Cyrillic / diacritics);
- choose between `string` and `[]byte` deliberately;
- use `strings` tools including `Cut` and `Clone`;
- convert types via `strconv` with error checking;
- build strings efficiently with `strings.Builder`.

## Prerequisite

- Basic arrays and `for` / `range`.
- Go 1.22+ (`strings.Clone` exists since 1.18).
- Preferred 06.02 for formatting.

## Problem this lesson solves

Strings in Go are not a “character array” as in some languages. Typical mistakes:

- indexing `s[i]` yields a **byte**, not a “letter”;
- `len(s)` counts bytes — UI “text length” lies for Cyrillic;
- concatenation `+=` in a loop makes many allocations;
- `ParseInt` errors are ignored;
- a small substring keeps a huge buffer alive (memory hold);
- `Split` then immediately `[1]` without a check — panic.

## Mental model

```text
string  = immutable sequence of bytes — often UTF-8 text
rune    = Unicode code point (alias for int32)
[]byte  = mutable sequence of bytes
```

Three operations, three meanings:

| Expression | What it measures / returns |
|-------|------------------|
| `len(s)` | number of **bytes** |
| `for i, r := range s` | `i` = byte-offset of the rune start; `r` = rune |
| `s[i]` | one byte (`byte`), not necessarily a whole letter |

`strings.Builder` reduces allocations when assembling.  
`strings.Cut` splits on the first separator.  
`strings.Clone` copies a string to release a large backing buffer.

## Mechanism

### Concrete multi-byte example

Take the string:

```go
s := "Go čaj"
```

In UTF-8:

- `'G'`, `'o'`, `' '` — one byte each;
- `'č'` — **two** bytes (e.g. `0xC4 0x8D`);
- `'a'`, `'j'` — one byte each.

Therefore:

```go
len(s)                      // not 6 “letters” — counts bytes (here 7)
utf8.RuneCountInString(s)   // 6 runes: G o space č a j
```

`range` over `s`:

```text
i=0  r='G'
i=1  r='o'
i=2  r=' '
i=3  r='č'   // i jumps by 2 because č occupies 2 bytes
i=5  r='a'
i=6  r='j'
```

If you do `s[3]` you get the **first byte** of `č`, not the rune `'č'`. That is why “cutting” by indexes without UTF-8 awareness breaks text.

A `string` is immutable: there is no `s[0] = 'x'`. Change means making a new string (or working in `[]byte` then converting).

### strings basics

```go
strings.Contains(s, sub)
strings.HasPrefix(s, p)
strings.HasSuffix(s, p)
strings.Split(s, ",")
strings.Join(parts, ",")
strings.ToLower(s)
strings.TrimSpace(s)
strings.ReplaceAll(s, old, new)
```

### Cut

```go
before, after, ok := strings.Cut(s, "=")
```

Cleaner than `SplitN` when you need “key=value”. If the separator is missing, `ok == false`. If there are more `=`, `after` keeps the remainder — often desirable for values.

### Clone

```go
small := strings.Clone(big[:10]) // caution: big[:10] cuts bytes!
```

Useful when a small string comes from a large one and must not keep the whole buffer alive. For text cut by runes / `Cut`, not blindly by bytes.

### strconv

```go
n, err := strconv.Atoi(s)
s = strconv.Itoa(n)
f, err := strconv.ParseFloat(s, 64)
b, err := strconv.ParseBool(s)
n64, err := strconv.ParseInt(s, 0, 64) // base 0 = auto 0x, 0o…
```

Always check `err`. A silent error makes bugs far from the parsing site.

### utf8

```go
utf8.RuneCountInString(s)
r, size := utf8.DecodeRuneInString(s)
utf8.ValidString(s)
```

### Builder

```go
var b strings.Builder
b.Grow(64)
b.WriteString("hello")
b.WriteByte(' ')
b.WriteString("world")
out := b.String()
```

`Grow` requests capacity up front. `+=` in a loop of N parts does O(N²) copying in the worst case; Builder is more linear.

### bytes vs strings

| You work with | Package |
|----------|-------|
| text, UTF-8 words | `strings` |
| I/O buffers, protocol | `bytes` |
| number conversions | `strconv` |
| counting runes | `unicode/utf8` |

`string` ↔ `[]byte` conversion generally **copies**. Do not go into `unsafe` for “zero copy” in ordinary application code.

## Rules and syntax

- For “letter count” in UI: `utf8.RuneCountInString` (or `range`), not `len`.
- For protocols and hashes: often `[]byte` and `len` in bytes — that is correct.
- Do not change a string via indexes.
- After `Builder.Reset` do not keep an old reference to the internal buffer — use `String()`.
- `Cut` for one separator; `Split` when you need a list of parts.

## Examples

### Example 1 — byte vs rune (multi-byte trace)

```go
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "Go ćirilica"
	fmt.Println("bytes:", len(s))
	fmt.Println("runes:", utf8.RuneCountInString(s))
	for i, r := range s {
		fmt.Printf("offset=%d rune=%c U+%04X\n", i, r, r)
	}
	fmt.Printf("s[0]=%c s[3]=%x (first byte after 'Go ')\n", s[0], s[3])
}
```

#### What happens here

1. `s` contains ASCII `"Go "` then letters with diacritics / Cyrillic that occupy multiple bytes in UTF-8.
2. `len(s)` prints the byte count — **larger** than the number of “letters” you see with your eyes.
3. `RuneCountInString` counts Unicode code points — closer to “character count” for this text.
4. `range` prints the byte-offset of the start of each rune. After a multi-byte rune `i` jumps by 2 or 3, not by 1.
5. `s[3]` is not the third letter — it is the byte at index 3. For a multi-byte character that may be only part of a UTF-8 sequence.

Remember this trace: **immutable bytes + range yields runes + len counts bytes**.

### Example 2 — Cut for env style

```go
package main

import (
	"fmt"
	"strings"
)

func main() {
	line := "PORT=8080"
	k, v, ok := strings.Cut(line, "=")
	if !ok {
		fmt.Println("no separator")
		return
	}
	fmt.Println(k, "->", v)

	line2 := "DSN=host=local;db=app"
	k2, v2, _ := strings.Cut(line2, "=")
	fmt.Println(k2, "->", v2)
}
```

#### What happens here

1. The first `Cut` splits on the first `=`: `PORT` and `8080`, `ok=true`.
2. Second example: `DSN` and `host=local;db=app` — the remainder keeps embedded `=`. That is often the correct behavior for a connection string.
3. If there is no `=`, `ok` is false and you must not interpret `v` as a value.

### Example 3 — Builder in a loop

```go
package main

import (
	"fmt"
	"strings"
)

func joinLines(lines []string) string {
	var b strings.Builder
	b.Grow(len(lines) * 16)
	for i, line := range lines {
		if i > 0 {
			b.WriteByte('\n')
		}
		b.WriteString(line)
	}
	return b.String()
}

func main() {
	fmt.Println(joinLines([]string{"first", "second", "third"}))
}
```

#### What happens here

1. `Grow` requests rough capacity — fewer reallocations while `WriteString` adds.
2. The loop writes lines and `\n` between them **into the same buffer**.
3. `String()` at the end gives the finished `string`. There is no `s = s + line` in the loop.

Compare mentally with `out += line + "\n"`: every assignment makes a new string and copies the previous content.

### Example 4 — strconv and errors

```go
package main

import (
	"fmt"
	"strconv"
)

func main() {
	values := []string{"42", "0x10", "three", "3.14"}
	for _, v := range values {
		n, err := strconv.ParseInt(v, 0, 64)
		if err != nil {
			fmt.Printf("%q is not int: %v\n", v, err)
			continue
		}
		fmt.Printf("%q -> %d\n", v, n)
	}
}
```

#### What happens here

1. Base `0` allows an auto prefix: `"0x10"` → 16.
2. `"42"` → 42.
3. `"three"` and `"3.14"` return an error — the `continue` branch does not “convert” them to 0 silently.
4. `%q` in the error message shows the exact input with boundaries.

### Example 5 — Clone and memory (illustration)

```go
package main

import (
	"fmt"
	"strings"
)

func firstWord(s string) string {
	w, _, _ := strings.Cut(s, " ")
	return strings.Clone(w)
}

func main() {
	big := strings.Repeat("word ", 10000) + "end"
	w := firstWord(big)
	fmt.Println(w, len(w))
}
```

#### What happens here

1. `big` is a large string on the heap.
2. `Cut` gives the first word as a substring that **may** share the backing byte array with `big`.
3. Without `Clone`, keeping only `w` in a map/cache can keep the whole `big` alive (GC sees the whole field).
4. `Clone` makes a fresh copy of the small bytes — `big` can be freed when it is no longer referenced.

## Decision analysis

| Task | Tool |
|---------|------|
| search/prefix | `strings` |
| number ↔ text | `strconv` |
| Unicode length | `utf8.RuneCountInString` / `range` |
| assembling in a loop | `Builder` |
| key=value | `Cut` |
| release a large buffer | `Clone` |
| I/O buffer without copy to string | `bytes` |

## Trade-offs

| Choice | Plus | Minus |
|-------|------|-------|
| `string` | immutable, suitable for map keys | copies on “change” |
| `[]byte` | in-place processing | mutability, aliasing |
| `+=` in a loop | short | slow on large N |
| Builder | fast | a little more code |
| cutting by `len` indexes | simple | breaks UTF-8 |

## Common mistakes

1. **Wrong:** `for i := range s` then expecting “character index” 0,1,2… for multi-byte text.  
   **Effect:** `i` jumps; cutting `s[i:i+1]` breaks runes.  
   **Why:** `i` is a byte-offset.  
   **Fix:** use `r` from `range`, or `utf8.DecodeRuneInString`.

2. **Wrong:** `len(s)` as letter count for UI.  
   **Effect:** “tea” looks longer/shorter than the user sees.  
   **Why:** `len` counts bytes.  
   **Fix:** `utf8.RuneCountInString` (with awareness that a grapheme cluster can be even more complex).

3. **Wrong:** ignoring a `strconv` error.  
   **Effect:** zero value `0` goes on as a “parsed” number.  
   **Why:** `(n, err)` — `n` is not magically valid.  
   **Fix:** check `err` immediately.

4. **Wrong:** `parts := strings.Split(...); x := parts[1]` without a check.  
   **Effect:** panic when the separator is missing.  
   **Why:** the slice may have one element.  
   **Fix:** `Cut` + `ok`, or check `len(parts)`.

5. **Wrong:** substring hold on a large buffer.  
   **Effect:** RSS grows, a cache of “small” keys holds megabytes.  
   **Why:** a string header can share the backing store.  
   **Fix:** `strings.Clone` when you keep a small part.

6. **Wrong:** mixing `bytes` and `strings` functions without conversion.  
   **Effect:** compiler error or unnecessary copies in a loop.  
   **Why:** the types are not the same.  
   **Fix:** stay in one world (`[]byte` or `string`) as long as possible.

## Idiomatic Go

- `Cut` instead of manual `Index`+cutting where needed.
- `Builder` for loops.
- Explicit `strconv` errors.
- UTF-8-aware code for user text; byte-aware for protocols.
- `bytes` package when you already work with I/O buffers.
- Do not treat `string` as a mutable rune array.

## Practical scenario

A service parsed the `Authorization` header with `Split(" ")` and crashed when the format was wrong (panic on `[1]`). Moving to `Cut` + checking `ok` gave a clean 401 message. Second case: caching small keys cut from megabyte payloads held memory — `Clone` on the key lowered RSS. Third: “max 20 characters” validation used `len` — users with Cyrillic were cut off earlier; fix `RuneCountInString`.

## Check questions

1. What does `len(string)` return?  
   **Answer:** The number of bytes, not the number of Unicode characters.

2. Difference `string` vs `[]byte`?  
   **Answer:** `string` is immutable; `[]byte` is mutable. Conversion usually copies.

3. What does `strings.Cut` do?  
   **Answer:** Splits on the first separator; returns before, after, and `ok`.

4. When `strings.Clone`?  
   **Answer:** When a small string comes from a large one and must not hold the large buffer.

5. Why `Builder` instead of `+=`?  
   **Answer:** Fewer allocations and copies when assembling in a loop.

6. What does base `0` do in `ParseInt`?  
   **Answer:** Automatically chooses the base from the prefix (`0x`, `0o`, …).

7. How does `range` over a string walk?  
   **Answer:** By runes; the index is the byte-offset of the rune start.

## Deeper pass: UTF-8 on the table

Take `"čaša"` and compute expectations before running:

| Question | Answer |
|---------|---------|
| How many letters do you see? | 4 (č a š a) — roughly |
| `len(s)`? | more than 4 because `č` and `š` are multi-byte |
| `range` how many times? | 4 iterations (4 runes) |
| `s[0]`? | first byte of `č`, not the whole rune |

Run:

```go
s := "čaša"
fmt.Println(len(s), utf8.RuneCountInString(s))
for i, r := range s {
	fmt.Printf("%d %c %x\n", i, r, []byte(string(r)))
}
```

Watch that `i` does not go 0,1,2,3 but jumps. That is the whole point of the lesson on one screen.

### Builder vs `+=` — small proof

```go
func slow(n int) string {
	s := ""
	for i := 0; i < n; i++ {
		s += "x"
	}
	return s
}

func fast(n int) string {
	var b strings.Builder
	b.Grow(n)
	for i := 0; i < n; i++ {
		b.WriteByte('x')
	}
	return b.String()
}
```

For small `n` the difference is unimportant. For tens of thousands, `Builder` + `Grow` is clearly better. Do not micro-optimize before you measure — but do not `+=` in a loop out of habit.

### Cut vs SplitN

```go
before, after, ok := strings.Cut(s, "=")
// similar:
parts := strings.SplitN(s, "=", 2)
```

`Cut` better communicates intent (“first separator”) and returns `ok`. Prefer it for key=value.

### bytes package — briefly

```go
buf := []byte("content-type: application/json")
fmt.Println(bytes.Contains(buf, []byte("json")))
```

Same algorithms as `strings`, without an unnecessary conversion to `string` when you already have a buffer from the network/file.

### String checklist

1. UI length → runes, not `len`.
2. Protocol/hash → bytes OK.
3. Assembly loop → Builder.
4. `strconv` → always `err`.
5. Small part of a large string that lives long → `Clone`.
6. `Cut` + `ok` instead of `Split`[1].

### Exercise R1 — `čaša` on the table

```go
package main

import (
	"fmt"
	"unicode/utf8"
)

func main() {
	s := "čaša"
	fmt.Println("bytes", len(s))
	fmt.Println("runes", utf8.RuneCountInString(s))
	for i, r := range s {
		fmt.Printf("i=%d r=%c hex=%x\n", i, r, []byte(string(r)))
	}
	fmt.Printf("s[0]=%x (not the whole letter č)\n", s[0])
}
```

#### What happens here

1. `len(s)` counts UTF-8 bytes, not “letters on screen”.
2. `range` over a string walks by runes; index `i` is the byte-offset of the rune start.
3. Indexes do not go 0,1,2,3 — they jump because `č` and `š` are multi-byte.
4. `s[0]` is the first byte, not the whole rune — indexing by byte breaks Unicode.
5. For UI length use rune count; for protocol/hash bytes are OK.

### Exercise R2 — Cut for `k=v`

```go
lines := []string{"host=localhost", "port=8080", "broken"}
cfg := map[string]string{}
for _, ln := range lines {
	k, v, ok := strings.Cut(ln, "=")
	if !ok {
		fmt.Println("skipping", ln)
		continue
	}
	cfg[k] = v
}
fmt.Println(cfg)
```

#### What happens here

1. `Cut` splits on the first separator and returns `ok`.
2. Without `ok` you do not touch `v` — no panic from `Split`[1].
3. A map collects configuration; the key must be comparable (string is).
4. `Cut` communicates intent more clearly than `SplitN(..., 2)` for this pattern.

### Exercise R3 — Builder vs `+=`

```go
func slow(n int) string {
	s := ""
	for i := 0; i < n; i++ {
		s += "x"
	}
	return s
}

func fast(n int) string {
	var b strings.Builder
	b.Grow(n)
	for i := 0; i < n; i++ {
		b.WriteByte('x')
	}
	return b.String()
}
```

Measure both with `time.Since` for `n := 20000`.

#### What happens here

1. `+=` in a loop copies an ever larger string — quadratic allocation pressure.
2. `Builder` accumulates in a buffer; `Grow` reserves capacity up front.
3. For small `n` the difference is irrelevant; the habit of `Builder` in a loop still pays off.
4. Do not micro-optimize before measuring — but do not `+=` out of inertia on a hot path.

### Exercise R4 — strconv with an error

```go
n, err := strconv.Atoi("12")
if err != nil {
	fmt.Println("bad number:", err)
	return
}
fmt.Println(n)

_, err = strconv.Atoi("12x")
fmt.Println(err)
```

#### What happens here

1. `Atoi` returns `(int, error)` — zero value `0` is not a success signal.
2. Swallowing `err` makes a silent bug (e.g. port 0).
3. `ParseInt` with base `0` chooses the base from the prefix (`0x`, `0o`).

### Exercise R5 — Clone when a small string lives long

```go
big := strings.Repeat("A", 1<<20) + "tail"
small := big[len(big)-3:]
copy := strings.Clone(small)
_ = copy
```

#### What happens here

1. A substring may share the backing array with the large string (hold).
2. `Clone` makes an independent copy — the large buffer can be freed.
3. Use when a small part lives in a map/cache long after discarding the large one.

### Decision table

| Task | Tool | Note |
|---------|------|----------|
| Length for UI | rune / `utf8` | not `len` |
| Assembling in a loop | `Builder` | + `Grow` |
| First separator | `Cut` | + `ok` |
| Number from text | `strconv` | always `err` |
| Bytes from the network | `bytes` | without superfluous `string` |
| Small hold | `Clone` | when needed |

### Workshop FAQ

**Q: Is a string mutable?**  
A: No — immutable. Change means a new string (or work over `[]byte`).

**Q: Does `string` ↔ `[]byte` copy?**  
A: Usually yes. That is why on a hot path you stay on one representation.

**Q: When `Fields` and when `Split`?**  
A: `Fields` splits on Unicode whitespace and drops empties; `Split` on an exact separator.

**Q: How do I replace all occurrences?**  
A: `strings.ReplaceAll` (or `Replace` with a count).

**Q: Does `Builder` need a pointer receiver?**  
A: Methods are on `*Builder` — do not copy Builder by value after first use.

**Q: What is a rune?**  
A: Type `rune` is an alias for `int32` — a Unicode code point. First time: rune = one Unicode “letter” in this sense, not always a “grapheme cluster”.

**Q: bytes or strings package?**  
A: Same algorithms; choose based on whether you already have `[]byte` or `string`.

### Extra pass — from byte to configuration

Input:

```text
# demo
host = localhost
port=8080
broken-line
```

Target parser trace:

1. Split lines (`Split` / `Scanner`).
2. Trim each line.
3. Skip empty ones and those that start with `#`.
4. `Cut` on `=`; if `!ok` → error or skip (deliberately).
5. Trim key and value.
6. Put into `map[string]string`.
7. `Atoi` for port — check `err`.

```go
func parseKV(text string) (map[string]string, error) {
	out := make(map[string]string)
	for _, ln := range strings.Split(text, "\n") {
		ln = strings.TrimSpace(ln)
		if ln == "" || strings.HasPrefix(ln, "#") {
			continue
		}
		k, v, ok := strings.Cut(ln, "=")
		if !ok {
			return nil, fmt.Errorf("no = in %q", ln)
		}
		out[strings.TrimSpace(k)] = strings.TrimSpace(v)
	}
	return out, nil
}
```

#### What happens here

1. `make` gives an empty map ready for writes (a nil map would panic on write).
2. Trim removes `" host "` and `" 8080 "` traps.
3. `Cut` + `ok` is clearer than `Split` then index `[1]`.
4. An error on `broken-line` prevents a silent bug later.

### Exercise R6 — Fields vs manual range

```go
s := "  alpha\tbeta  gama "
fmt.Println(strings.Fields(s)) // [alpha beta gama]
```

#### What happens here

1. `Fields` treats all Unicode whitespace as separators.
2. For a word-count basic case — faster and fewer bugs than manual state.
3. For an exact separator (comma) use `Split` / `Cut`, not Fields.

## Summary

A `string` is an immutable sequence of bytes; `len` counts bytes; `range` yields runes — that shows on every multi-byte letter. `strings`, `strconv`, and `utf8` cover most text. `Builder`, `Cut`, and `Clone` are modern idioms for efficiency and clarity.

# 06.02 Using the fmt Package

> **Go Path - Zero to Gopher** / **01 Basics → The Go Standard Library** / Lesson 06.02

## Lesson goals

After this lesson you should be able to:

- choose the correct print verb (`%v`, `%+v`, `%#v`, `%s`, `%d`, `%q`, `%T`, `%w`, …) and explain what each does;
- distinguish the `Print` / `Sprint` / `Fprint` families (where they write and what they return);
- read simple input via `Scan` variants and know their limits;
- implement `fmt.Stringer` for a domain display of a type;
- build errors with `fmt.Errorf` and `%w` so that `errors.Is` / `errors.As` still work;
- avoid the trap of a “format string from the user”.

## Prerequisite

- 06.01 preferred (feel for stdout/stderr).
- Basic types, struct, interface, `error`.
- Go 1.22+.

## Problem this lesson solves

`fmt` looks trivial until you:

- print a struct as a useless `%v` instead of `%+v` and in the log you do not see field names;
- mix up `Print` and `Sprint` and expect a side-effect or the reverse;
- make an error by string concatenation instead of `Errorf`, and lose wrapping;
- forget that `String()` changes the default display for `%v` / `%s`;
- do `fmt.Printf(userInput)` and a user `%` triggers unexpected verbs.

This lesson systematizes the function family, verbs, and idioms around errors and display.

## Mental model

Three axes of the `fmt` world:

1. **Where it writes** — stdout (`Print*`), a new string (`Sprint*`), any `io.Writer` (`Fprint*`)
2. **How it formats** — verbs in the format string (`%d`, `%q`, …)
3. **How it reads** — the `Scan*` family (small demos; a production CLI more often uses `bufio` + `strconv`)

`Stringer` is a hook: if a type implements `String() string`, `%v` and `%s` often use that display instead of a generic dump.

Think of the format string as a **template with holes**. Each hole (`%…`) consumes the next argument. The number of holes and the number of arguments must match; a wrong type for a verb gives a readable but ugly output like `%!d(string=...)`, not always a compiler error.

## Mechanism

### Print verbs — what the engine exactly does

When you call `fmt.Printf("x=%d y=%s", 3, "a")`, the engine:

1. Reads the literal up to the first `%`.
2. Parses the verb `%d`, takes the next argument (`3`), formats it as a decimal integer.
3. Continues the text (` y=`), then `%s` with argument `"a"`.
4. Writes the finished byte sequence to the destination (here stdout).

Most common verbs:

| Verb | Input | Typical use |
|------|------|------------------|
| `%v` | anything | default display |
| `%+v` | struct | with field names |
| `%#v` | anything | Go-syntax display (debug / copy-paste) |
| `%T` | anything | value type |
| `%s` | string / `[]byte` | raw text |
| `%q` | string / number | quoted, escaped — good in a log |
| `%d` | integers | decimal |
| `%x` / `%X` | int / `[]byte` | hex |
| `%f` | float | decimal notation |
| `%w` | `error` | only in `Errorf` — wrap |
| `%p` | pointer | address |
| `%%` | — | literal `%` character |

Width and precision (e.g. `%6d`, `%.2f`, `%-6d`) align columns and control decimals — useful for CLI tables without a framework.

### Function families — same semantics, different destination

```go
fmt.Printf(format, a...)           // writes to os.Stdout, returns (n, err)
fmt.Sprintf(format, a...)          // returns a string; writes nowhere
fmt.Fprintf(w, format, a...)       // writes to w (file, buffer, network…)
```

The same applies to `Print` / `Println` / `Sprint` / `Sprintln` / `Fprint` / `Fprintln` without a format string.

Differences that must enter muscle memory:

| Family | Side-effect on stdout? | Result |
|----------|------------------------|----------|
| `Print*` | yes (stdout) | `(int, error)` byte count |
| `Sprint*` | no | `string` |
| `Fprint*` | not necessarily — depends on `Writer` | `(int, error)` |

`Println` adds a space between operands **and** a newline at the end. `Print` does not add a newline by itself. `Printf` adds exactly what you write in the format (including `\n` if you put it).

### Scan — reading

```go
var a, b int
fmt.Scan(&a, &b)                 // from stdin, splits on whitespace
fmt.Sscanf("3+4", "%d+%d", &a, &b)
```

`Scan` requires **pointers** to the variables it fills. It returns the number of successfully scanned items and an `error`.

For a robust CLI more often: `bufio.Scanner` + `strconv.Atoi`. `Scan` is handy for demos and small interactive scripts, brittle for complex expression languages and poor UX input.

### Stringer

```go
type Novcic int

func (n Novcic) String() string {
	return fmt.Sprintf("%d RSD", int(n))
}
```

When `fmt` sees a type that satisfies:

```go
type Stringer interface {
	String() string
}
```

for `%v` / `%s` (in typical cases) it calls `String()`. That is why domain types look readable in the log without manual formatting everywhere.

Rule: `String()` must be **cheap** — no network, no heavy I/O, no panic. Display is not the place for business logic.

### Errorf and `%w`

```go
return fmt.Errorf("loading %s: %w", path, err)
```

- `%v` or `%s` on an `error` embeds the error **text** into the new message, but does not keep the chain for `errors.Is`.
- `%w` **wraps** the error: the new value implements `Unwrap()`, so `errors.Is(err, errSentinel)` and `errors.As` work through the chain.

That is the idiomatic way to add context (“where” and “what you were doing”) without losing the cause.

### Format string safety

Never:

```go
fmt.Printf(userInput) // DANGEROUS
```

If `userInput` contains `%s` or `%d`, the engine looks for arguments that are not there or interprets wrongly. Always:

```go
fmt.Printf("%s", userInput)
```

## Rules and syntax

- `Println` = spaces between + `\n` at the end.
- `Print` = without an automatic newline.
- For CLI errors to the user: often `fmt.Fprintf(os.Stderr, ...)`.
- Do not implement `String()` with side-effects.
- Number of verbs ≈ number of arguments; surplus/shortfall gives messages in the output, not always a compile error.
- `%w` only in `Errorf` (and related that build an `error`), not in ordinary `Printf` as a substitute for printing an error in a log — for a log use `%v` or a slog attribute.

## Examples

### Example 1 — verbs on a struct

```go
package main

import "fmt"

type Korisnik struct {
	Ime     string
	God     int
	Aktivan bool
}

func main() {
	k := Korisnik{"Ana", 30, true}
	fmt.Printf("v : %v\n", k)
	fmt.Printf("+v: %+v\n", k)
	fmt.Printf("#v: %#v\n", k)
	fmt.Printf("T : %T\n", k)
}
```

#### What happens here

1. `k` is a value of type `Korisnik` with fields Ana / 30 / true.
2. `%v` gives a compact display without field names — fast, but harder to read in a log.
3. `%+v` adds field names (`Ime:Ana` …) — better for debugging a struct.
4. `%#v` prints a form close to a Go composite literal — useful when you want to see type and values for copy-paste into a test.
5. `%T` reveals the type: `main.Korisnik` (with the package name). It does not print the value.

Trace: the same data, four purposes. Choose the verb by the reader (a human in the log vs a developer in a debug session).

### Example 2 — Sprint vs Fprint

```go
package main

import (
	"fmt"
	"os"
	"strings"
)

func main() {
	msg := fmt.Sprintf("status=%s code=%d", "ok", 200)
	var b strings.Builder
	fmt.Fprintf(&b, "len=%d\n", len(msg))
	fmt.Fprint(os.Stdout, b.String())
	fmt.Println(msg)
}
```

#### What happens here

1. `Sprintf` builds `msg` in memory. Nothing goes to the screen in that step. `msg` is e.g. `status=ok code=200`.
2. `strings.Builder` is an `io.Writer`. `Fprintf(&b, ...)` writes the length text into the builder — still without stdout.
3. `Fprint(os.Stdout, b.String())` sends the builder contents to standard output.
4. `Println(msg)` adds the message and a newline on stdout.

Point: the same format engine; you choose the destination. That is why there are three families instead of one “print everywhere”.

### Example 3 — Stringer + Errorf

```go
package main

import (
	"errors"
	"fmt"
)

type Kod int

func (k Kod) String() string {
	return fmt.Sprintf("code(%d)", int(k))
}

var errPrazno = errors.New("empty input")

func obradi(s string) error {
	if s == "" {
		return fmt.Errorf("obradi %s: %w", Kod(1), errPrazno)
	}
	return nil
}

func main() {
	err := obradi("")
	fmt.Println(err)
	fmt.Println(errors.Is(err, errPrazno))
}
```

#### What happens here

1. `Kod` satisfies `Stringer`. When `Errorf` inserts `Kod(1)` via `%s`/`%v` into the message, you see `code(1)`, not a raw int.
2. `%w` wraps `errPrazno`. The new error has context text **and** a chain.
3. `fmt.Println(err)` calls `Error()` on the wrapped error — you read a readable message.
4. `errors.Is(err, errPrazno)` walks through `Unwrap` and returns `true`. Had it been `%v` instead of `%w`, Is would often be `false` even though the text looks alike.

### Example 4 — Scan mini calculator

```go
package main

import "fmt"

func main() {
	var a, b int
	var op string
	fmt.Print("expression (e.g. 3 + 4): ")
	_, err := fmt.Scan(&a, &op, &b)
	if err != nil {
		fmt.Println("error:", err)
		return
	}
	switch op {
	case "+":
		fmt.Println(a + b)
	case "-":
		fmt.Println(a - b)
	default:
		fmt.Println("unknown operation")
	}
}
```

#### What happens here

1. `Print` (without `ln`) writes the prompt and leaves the cursor on the same line.
2. `Scan` reads from stdin three tokens separated by whitespace into `&a`, `&op`, `&b`. Input `3 + 4` gives a=3, op="+", b=4.
3. If the input is not three tokens of the expected shape, `err != nil` — the error branch.
4. `switch` chooses the operation. An unknown op does not panic — it prints a message.

Limit: no operator precedence, no parentheses, poor UX for `3+4` without spaces (depends on the scanner). For a real parser use another approach.

### Example 5 — width, precision, and Fprint to a file

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	fmt.Printf("|%6d|\n", 42)
	fmt.Printf("|%-6d|\n", 42)
	fmt.Printf("|%8.2f|\n", 3.14159)

	f, err := os.Create("output.txt")
	if err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	defer f.Close()
	fmt.Fprintf(f, "line=%d\n", 1)
}
```

#### What happens here

1. `%6d` aligns `42` to the right in width 6 — useful for columns.
2. `%-6d` aligns to the left.
3. `%8.2f` prints a float with 2 decimals in width 8.
4. `Create` opens a file; `Fprintf` uses the **same** format engine as `Printf`, but writes to the file. `defer Close` closes on exit from `main`.

## Decision analysis

| Need | Tool | Why |
|---------|------|-------|
| log for a human | `Printf` / `%+v` | field names, readability |
| string for further processing | `Sprintf` | no I/O side-effect |
| writing to file/network | `Fprintf` | any `Writer` |
| stable error with context | `Errorf` + `%w` | `errors.Is`/`As` |
| nice domain type display | `Stringer` | one format, everywhere |
| user text in a log | `%q` | escaped, boundaries visible |

## Trade-offs

| Practice | Plus | Minus |
|--------|------|-------|
| everything `%v` | fast typing | weak struct readability |
| always `%#v` | rich for debug | noisy in UX messages |
| `Scan` | short | brittle for real input |
| rich `String()` | nice debug | can hide raw data |
| `fmt` on a hot path | convenient | slower than a specialized logger |

## Common mistakes

1. **Wrong:** `%d` on a string / wrong verb.  
   **Effect:** output like `%!d(string=abc)` instead of a useful value.  
   **Why:** verb and dynamic type do not match; `fmt` does not reject at compile-time for an `any`-like path.  
   **Fix:** align the verb (`%s` for string) or convert the type before printing.

2. **Wrong:** forgotten `\n` with `Printf`.  
   **Effect:** the next print sticks to the same line; CI logs unreadable.  
   **Why:** `Printf` does not add a newline by itself.  
   **Fix:** put `\n` or use `Println` when you need a simple line.

3. **Wrong:** `Errorf` with `%s`/`%v` on an `error` instead of `%w` when you need a chain.  
   **Effect:** `errors.Is` does not find the sentinel; the type for `As` is lost.  
   **Why:** without `%w` there is no `Unwrap` chain.  
   **Fix:** `fmt.Errorf("...: %w", err)` when wrapping.

4. **Wrong:** a `String()` that panics or does network I/O.  
   **Effect:** printing in a log kills the process or slows a hot path.  
   **Why:** `fmt` calls `String()` implicitly during formatting.  
   **Fix:** cheap, pure display; heavy things in a separate method.

5. **Wrong:** mixing `Print` and `Sprint` expectations.  
   **Effect:** “nothing prints” because you called `Sprintf` and discarded the result.  
   **Why:** `Sprint*` only returns a string.  
   **Fix:** `Printf`/`Println` for the screen; `Sprintf` when you need the value.

6. **Wrong:** `fmt.Printf(userInput)` — format string from the user.  
   **Effect:** unexpected verbs, empty arguments, confusing output.  
   **Why:** `%` in the input becomes format control.  
   **Fix:** `fmt.Printf("%s", userInput)`.

## Idiomatic Go

- `%w` for wrapping errors.
- `%q` when displaying a user string in a log.
- `%T` in diagnostics of unknown values.
- `Stringer` for domain types you often print.
- Do not use `fmt` as the only logger on a service hot path — there `log/slog` (next lesson) or a specialized logger.
- Errors to a CLI user often short; detail in the log.

## Practical scenario

A service printed `User{...}` in the log with `%v` without field names; on-call did not see which field was missing with a `nil` pointer inside. Moving to `%+v` and a `Stringer` for a `Money` type reduced debug time. Errors moved to `Errorf("%w")` so `errors.Is(err, errNotFound)` worked in the handler instead of comparing message strings. Notably: one endpoint did `Printf(req.URL.Path)` — a path with `%` in a test corrupted the output; a `%s` fix eliminated the flaky log.

## Check questions

1. Difference `Printf` / `Sprintf` / `Fprintf`?  
   **Answer:** stdout / returns a string / writes to an `io.Writer`; same format engine.

2. When `%+v`, and when `%#v`?  
   **Answer:** `%+v` for a readable struct with field names; `%#v` for a Go-like dump of type and values.

3. What does `fmt.Stringer` require?  
   **Answer:** method `String() string` on the type.

4. What is `%w` for in `Errorf`?  
   **Answer:** wraps the error so `errors.Is` / `errors.As` / `Unwrap` work.

5. Why is `Scan` often weak for a production CLI?  
   **Answer:** splits only on whitespace, weak diagnostics, bad for complex formats; better `bufio`+`strconv`.

6. What does `%q` do?  
   **Answer:** displays the value as a Go quoted literal (escaped), useful in a log.

7. Why must `String()` not do heavy I/O?  
   **Answer:** it is called implicitly during formatting; I/O would slow things and could throw an error/panic at an unexpected moment.

## Deeper pass: verbs, errors, and Writer

### Trace of one `Printf` call with mixed types

```go
ime := "Ana"
god := 30
fmt.Printf("%s has %d years (type of god: %T)\n", ime, god, god)
```

1. The engine reads `%s` → consumes `ime` → writes `Ana`.
2. Text ` has ` goes literally.
3. `%d` → consumes `god` → `30`.
4. `%T` → type of `god` → `int`.
5. `\n` ends the line.

If you swap the argument order (`god, ime, god`), `%s` on an `int` gives `%!s(int=30)` — the program does not panic, but the output is format-error diagnostics.

### Why `Sprintf` exists alongside `+`

```go
a, b := "x", 3
s1 := a + strconv.Itoa(b)           // manual conversion
s2 := fmt.Sprintf("%s%d", a, b)     // one engine, more types
```

`Sprintf` scales when you have five fields, widths, `%q`. Concatenation quickly becomes unreadable and forces manual conversions.

### Errorf chain — values, not only text

```go
var errNema = errors.New("none")

func slojA() error { return errNema }
func slojB() error { return fmt.Errorf("slojB: %w", slojA()) }
func slojC() error { return fmt.Errorf("slojC: %w", slojB()) }

err := slojC()
fmt.Println(err)                    // slojC: slojB: none
fmt.Println(errors.Is(err, errNema)) // true
```

Each `%w` adds context. `Is` walks through `Unwrap`. Had it been `%v`, the text would look alike, but `Is` often would not find the sentinel.

### Stringer and priority order in fmt

When `fmt` formats a value, a typical order (simplified):

1. If the type (or pointer) implements specialized interfaces (`Formatter`, `GoStringer`, `Stringer`, `error`) — use them where the verb asks.
2. Otherwise a generic display by kind.

That is why `String()` changes everyday printing. That is why it must be cheap and panic-free.

### Writer mental model

All `Fprint*` require an `io.Writer`:

```go
type Writer interface {
	Write(p []byte) (n int, err error)
}
```

`os.Stdout`, `os.Stderr`, `*os.File`, `*bytes.Buffer`, `*strings.Builder` — all write bytes. That is why the same `Fprintf` works to a file and to memory.

### Mini exercise with the answer in your head

What does this print:

```go
fmt.Printf("%q\n", "a\tb")
fmt.Printf("%s\n", "a\tb")
```

First: quoted form with escape (`"a\tb"`). Second: the tab is “executed” in the terminal. In a log for user input choose `%q`.

### Checklist before merging formatting

1. The format string is controlled by the program, not the user.
2. Errors that need `Is`/`As` use `%w`.
3. Struct in a log: `%+v` or `Stringer`, not always raw `%v`.
4. CLI errors on stderr via `Fprintf(os.Stderr, ...)`.
5. `String()` without I/O and panic.

### Exercise R1 — three destinations, same format

Write a program that with the same format sends a message to stdout, into a string, and into a `bytes.Buffer`.

```go
package main

import (
	"bytes"
	"fmt"
)

func main() {
	ime := "Mila"
	god := 28

	fmt.Printf("hello %s (%d)\n", ime, god)

	s := fmt.Sprintf("hello %s (%d)\n", ime, god)
	fmt.Print("Sprint: ", s)

	var buf bytes.Buffer
	fmt.Fprintf(&buf, "hello %s (%d)\n", ime, god)
	fmt.Print("Fprint: ", buf.String())
}
```

#### What happens here

1. `Printf` uses the same format engine, but writes to `os.Stdout`.
2. `Sprintf` builds a new `string` in memory — no side-effect on the console until you print it yourself.
3. `Fprintf` requires an `io.Writer`; `*bytes.Buffer` implements that interface.
4. Three calls consume the same arguments in the same order: first `%s` → `ime`, then `%d` → `god`.
5. If you swap the argument order, you get diagnostic output like `%!s(int=…)`, not a panic.

**Check:** all three texts must be identical (including `\n`).

```go
type Artikal struct {
```

| `%w` | wrap error | only in `Errorf` |

### Exercise R3 — Stringer changes the default display

```go
type Temperatura float64

func (t Temperatura) String() string {
	return fmt.Sprintf("%.1f°C", float64(t))
}

func main() {
	t := Temperatura(23.5)
	fmt.Printf("%v\n", t)
	fmt.Printf("%s\n", t)
```

#### What happens here

1. `Temperatura` is a definition type (new type) over `float64`.
2. Method `String() string` satisfies `fmt.Stringer`.
3. `%v` and `%s` call `String()` — you see `23.5°C`, not a raw float.
4. `%#v` often bypasses the “nice” Stringer display and shows type/value for debug.
5. `String()` must be cheap: no network, no panic, no heavy I/O.

### Exercise R4 — Errorf chain with `%w`

```go
package main

import (
	"errors"
	"fmt"
)

var errNema = errors.New("no data")

func slojA() error { return errNema }

func slojB() error {
	if err := slojA(); err != nil {
		return fmt.Errorf("slojB: %w", err)
	}
	return nil
}

func slojC() error {
	if err := slojB(); err != nil {
		return fmt.Errorf("slojC: %w", err)
	}
	return nil
}

func main() {
	err := slojC()
	fmt.Println(err)
	fmt.Println(errors.Is(err, errNema))

	los := fmt.Errorf("slojC: %v", slojB())
	fmt.Println(los)
	fmt.Println(errors.Is(los, errNema)) // often false
}
```

#### What happens here

1. Sentinel `errNema` is a value you can compare with `errors.Is`.
2. Each `%w` wraps the previous error and keeps the chain for `Unwrap`.
3. `errors.Is(err, errNema)` walks the chain — returns `true` when wrap was done.
4. `%v` instead of `%w` often keeps only the text; `Is` then does not find the sentinel.
5. The error message grows “outside in”: caller context + cause.

### Exercise R5 — the trap of a format string from the user

```go
user := "%s%s%s" // imagined user input
fmt.Printf(user)                    // BAD: verbs without arguments
fmt.Printf("%s\n", user)            // GOOD: fixed format
fmt.Printf("%q\n", user)            // GOOD: escaped in a log
```

#### What happens here

1. `Printf(user)` treats user text as a format — `%` starts the verb engine.
2. Without matching arguments you get strange diagnostic fragments.
3. A fixed format `"%s"` or `"%q"` keeps control in the program.
4. In production: never build a format string by concatenating user input.

### Decision table — which Print do I choose?

| Need | API | Why |
|---------|-----|-------|
| Quick print to console | `Print` / `Printf` | stdout, simple |
| Message for return / field | `Sprint` / `Sprintf` | no Writer |
| File, buffer, HTTP body | `Fprint` / `Fprintf` | any `io.Writer` |
| Error with context | `Errorf` + `%w` | chain for `Is`/`As` |
| Nice type display | `Stringer` | `%v`/`%s` use the method |

### Mini project — CLI “echo-safe”

Write a `main` that:

1. Reads all CLI arguments after the program name.
2. Joins them with a space via `Sprintf` or `strings.Join` + a fixed format.
3. Prints on stdout with `%s`, and in parallel on stderr with `%q` (diagnostics).
4. If there are no arguments, writes usage on stderr and returns exit code 2 (`os.Exit(2)` only in `main`).

#### What happens here (target trace)

1. `os.Args[1:]` is the argument slice — the zero value of an empty slice has `len` 0.
2. Usage goes to stderr so stdout stays clean for piping.
3. `%q` on stderr shows escape sequences — you see tabs and quotes.
4. Exit code ≠ 0 signals to scripts that the input is invalid.

### Workshop FAQ

**Q: Why does `Print` exist alongside `Printf`?**  
A: `Print` adds spaces between arguments and has no format engine; faster for a simple dump. `Printf` when you need display control.

**Q: Does `Stringer` affect JSON?**  
A: Not directly. `encoding/json` has its own rules (`MarshalJSON`, tags). `Stringer` is mainly for `fmt` and some log paths.

**Q: What if the number of verbs ≠ the number of arguments?**  
A: The program compiles; at runtime you get diagnostic fragments in the output. Treat that as a bug, not a feature.

**Q: When `Sprint` and when `+`?**  
A: For two strings `+` is readable. As soon as a number, width, `%q`, or five fields enter — `Sprintf` is clearer.

**Q: Does `Errorf` always allocate?**  
A: Yes, it builds a new error value. That is OK on the error path; do not call it on a hot path “for every success”.

**Q: How do I test `Fprintf` without a file?**  
A: Write into a `bytes.Buffer` or `strings.Builder` and compare `String()` in the test.

**Q: What is the difference between `%v` and `%s` for a type with Stringer?**  
A: Both often call `String()`. For types without Stringer `%s` expects a string-like value; `%v` has a generic fallback.

### Edge cases you must break by hand

1. `fmt.Printf("%d", "x")` — read the diagnostics.
2. `fmt.Errorf("%w", nil)` — understand what `Is` sees.
3. Pointer to a struct with `String()` on a value receiver — confirm `%v` still works.
4. `Fprint` into a closed `os.File` — check the returned `error`.

2. When do you choose `%+v` instead of `%v`?
3. Why does `%w` exist alongside `%v` in `Errorf`?
4. How do you safely print a user string?
5. Why must `String()` not panic?

## Summary

`fmt` is a universal formatting layer: verbs control display, function families choose the destination, `Stringer` customizes the type, `Errorf` builds errors. Keep the format string under program control, not the user’s. The next lesson moves from ad-hoc printing to `log` and modern `log/slog`.

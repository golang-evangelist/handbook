# 07.05 Switching on Types

> **Go Path - Zero to Gopher** / **01 Basics → Creating Custom Data Types With Go** / Lesson 07.05

## Lesson goals

After this lesson you should be able to:

- use a type assertion with the comma-ok form;
- write a type switch over `any` / an interface;
- avoid a panic from a failed assert;
- recognize when an interface is better than branching on type;
- maintain a type switch without a “god” switch that grows forever;
- understand a multi-case branch where `v` has the interface type.

## Prerequisite

- 07.01 (interfaces, type+value box).
- Go 1.22+.
- Preferred 06.06 (why reflect is not a substitute for this).

## Problem this lesson solves

Code often looks like this:

```go
switch x.(type) { case *A: ... case *B: ... case *C: ... }
```

and grows with every new type. That scatters logic and causes merge conflicts. Sometimes a type switch is legitimate (decode, a closed set of events), but often it is a sign that an interface is missing. Another trap: `x.(T)` without `ok` → panic.

## Mental model

Type assert: “open the interface box and check the dynamic type”.

```text
i.(T)           → panic if not T
v, ok := i.(T)  → safe (comma-ok)
switch v := i.(type) { ... } → multiple check
```

An interface says: “call the method, do not ask who you are”.  
A type switch says: “who are you, then I will decide”.

Prefer the first. Use the second at system boundaries (JSON `any`, plugin decode, sum types in one package).

## Mechanism

### Comma-ok assert

```go
if s, ok := x.(string); ok {
	fmt.Println(s)
}
```

If it is not `string`, `ok` is false, `s` is the zero value `""` — without a panic.

The single form `s := x.(string)` panics if the type does not match. Use it only when the invariant is guaranteed (rarely outside tests / right after a check).

### Type switch

```go
switch v := x.(type) {
case string:
	fmt.Println("str", v) // v is string
case int:
	fmt.Println("int", v) // v is int
case nil:
	fmt.Println("nil")
default:
	fmt.Printf("other %T\n", v)
}
```

- `case nil` catches a nil interface.
- In each branch `v` has that branch’s type (except multi-case).
- `default` for unknown — log `%T`.

### Multi-case

```go
case int, int64:
	// v has the interface type (e.g. any), not int
```

Do not treat `v` as a concrete `int` without a further assert.

### Preferring an interface

```go
type Poruka interface{ Render() string }

func Show(p Poruka) { fmt.Println(p.Render()) }
```

Instead of a switch over `Email`, `SMS`, `Push` — a new type adds `Render`, `Show` is not touched.

### JSON trap

`encoding/json` into `any` / `map[string]any` for numbers often gives **`float64`**, not `int`. A type switch that expects only `int` misses. Log `%T` at the boundary.

## Rules and syntax

- Never `x.(T)` without `ok` if the input is not guaranteed.
- `case nil` catches a nil interface.
- Always think about `default` for unknown types.
- Keep the switch close to the edge (parse, adapter), not in the middle of the domain.
- An expression switch on a string discriminator (`Kind`) is often better than a type switch when data comes from JSON.

## Examples

### Example 1 — dangerous vs safe assert

```go
package main

import "fmt"

func main() {
	var x any = 42
	// s := x.(string) // panic: interface conversion …
	s, ok := x.(string)
	fmt.Println(s, ok) // "" false
	n, ok := x.(int)
	fmt.Println(n, ok) // 42 true
}
```

#### What happens here

1. `x` holds `int` 42.
2. Assert to `string` with comma-ok gives the zero value and false — the program lives.
3. Assert to `int` succeeds. The single form without `ok` would panic on the string branch.

### Example 2 — type switch for decode

```go
package main

import "fmt"

func opis(x any) string {
	switch v := x.(type) {
	case string:
		return "text:" + v
	case float64:
		return fmt.Sprintf("number:%g", v)
	case bool:
		return fmt.Sprintf("bool:%v", v)
	case nil:
		return "nil"
	default:
		return fmt.Sprintf("unknown:%T", v)
	}
}

func main() {
	fmt.Println(opis("Go"))
	fmt.Println(opis(3.14))
	fmt.Println(opis(nil))
}
```

#### What happens here

1. Each branch gets `v` of a concrete type.
2. `float64` is deliberate — JSON numbers.
3. `nil` and `default` close the edge cases.

### Example 3 — interface instead of switch

```go
package main

import "fmt"

type Notif interface {
	Posalji() error
}

type Email struct{ To string }
type SMS struct{ Broj string }

func (e Email) Posalji() error { fmt.Println("email", e.To); return nil }
func (s SMS) Posalji() error   { fmt.Println("sms", s.Broj); return nil }

func dispatch(n Notif) { _ = n.Posalji() }

func main() {
	dispatch(Email{To: "a@b.rs"})
	dispatch(SMS{Broj: "+381..."})
}
```

#### What happens here

1. A new channel = a new type with `Posalji`.
2. `dispatch` is not touched — open for additions without changing a switch.
3. That scales better than a growing type switch in the domain.

### Example 4 — when a switch still makes sense

```go
package main

import "fmt"

type Event any

type Login struct{ User string }
type Logout struct{ User string }

func handle(e Event) {
	switch v := e.(type) {
	case Login:
		fmt.Println("login", v.User)
	case Logout:
		fmt.Println("logout", v.User)
	default:
		fmt.Printf("ignore %T\n", v)
	}
}

func main() {
	handle(Login{User: "ana"})
	handle(Logout{User: "ana"})
}
```

#### What happens here

1. A closed set of events in one package — the switch is readable.
2. If the set grows across package boundaries, consider an interface `Handle()`.

### Example 5 — multi-case

```go
package main

import "fmt"

func main() {
	var x any = int64(5)
	switch v := x.(type) {
	case int, int64:
		fmt.Printf("integer (%T) %v\n", v, v)
	default:
		fmt.Println("other")
	}
}
```

#### What happens here

1. The branch catches both `int` and `int64`.
2. The type of `v` inside is an interface (`any`), not `int64` — `%T` shows the real dynamic type.
3. You do not do `v + 1` without a further assert / conversion.

### Example 6 — helper and string discriminator

```go
package main

import "fmt"

func asString(x any) (string, bool) {
	s, ok := x.(string)
	return s, ok
}

type PluginConfig struct {
	Kind string
	Raw  map[string]any
}

func build(c PluginConfig) string {
	switch c.Kind {
	case "http":
		return "http plugin"
	case "grpc":
		return "grpc plugin"
	default:
		return "unknown"
	}
}

func main() {
	s, ok := asString(42)
	fmt.Println(s, ok)
	fmt.Println(build(PluginConfig{Kind: "http"}))
}
```

#### What happens here

1. `asString` encapsulates comma-ok — fewer panics across the code.
2. An expression switch on `Kind` is often better than a type switch when the discriminator arrives as a string from JSON.

## Decision analysis

| Signal | Decision |
|--------|--------|
| 2–3 types at a decode boundary | type switch OK |
| behavior grows with types | interface |
| assert without `ok` | only if invariant |
| rich switch in the domain | smell of bad design |
| JSON discriminator string | expression switch |

## Trade-offs

| | Type switch | Interface |
|--|-------------|-----------|
| closed set | excellent | overhead |
| open set | bad | excellent |
| evolution | must touch the switch | add a type |
| JSON any | common | does not replace decode |

## Common mistakes

1. **Wrong:** assert without `ok`.  
   **Effect:** panic `interface conversion…`.  
   **Why:** the dynamic type does not match.  
   **Fix:** comma-ok; log `%T` when debugging.

2. **Wrong:** forgotten `float64` from JSON.  
   **Effect:** the `int` branch never hits.  
   **Why:** JSON numbers → float64 in `any`.  
   **Fix:** case `float64` or `json.Decoder.UseNumber`.

3. **Wrong:** a growing switch instead of methods.  
   **Effect:** every PR touches the same file.  
   **Why:** behavior tied to a type should live on the type.  
   **Fix:** interface + methods.

4. **Wrong:** multi-case then treating `v` as a concrete type.  
   **Effect:** does not compile or wrong cast.  
   **Why:** `v` is an interface.  
   **Fix:** a further assert or separate case branches.

5. **Wrong:** ignoring `default`.  
   **Effect:** silent no-op for new types.  
   **Why:** forgotten edge.  
   **Fix:** default with a `%T` log or an error.

6. **Wrong:** a type switch in the middle of the domain instead of at the edge.  
   **Effect:** the domain knows about transport types.  
   **Why:** wrong layer.  
   **Fix:** the adapter/parse layer does the switch; the domain takes an interface.

## Idiomatic Go

- Comma-ok always on unreliable boundaries.
- Interface for polymorphic behavior.
- Type switch for data inspection / sum types in one module.
- Keep the switch close to the edge.

## Practical scenario

A notification service had a type switch with 12 channels. Every PR added a case and conflicts. Refactor: `Notifier` interface + registration in a map `map[string]Notifier`. The type switch remained only when reading configuration JSON into `any` fields. A panic assert in production on the wrong type was replaced with comma-ok + a 400 response.

## Check questions

1. Difference `x.(T)` vs `x.(type)` in a switch?  
   **Answer:** the first is an assert to one type; the second starts a type switch over possible types.

2. Why comma-ok?  
   **Answer:** avoids a panic; returns success in `ok`.

3. When does an interface beat a type switch?  
   **Answer:** when behavior expands with new types beyond a closed set.

4. What is the type of `v` in multi-case?  
   **Answer:** the interface type (shared), not a concrete branch type.

5. How do you catch nil in a type switch?  
   **Answer:** `case nil:`.

6. Why do JSON numbers confuse?  
   **Answer:** in `any` they often arrive as `float64`.

7. Where do you keep a switch in the architecture?  
   **Answer:** close to the edge (decode/adapter), not deep in the domain.

## Deeper pass: panic diagnostics and checklist

If you see:

```text
interface conversion: interface {} is int, not string
```

that is a failed assert. Find a place without `ok` or a wrong assumption about the dynamic type. Temporarily log `%T` before the assert.

### Helper near the parse layer

```go
func asString(x any) (string, bool) {
	s, ok := x.(string)
	return s, ok
}
```

Keep helpers near the package that parses external data — do not scatter asserts through the domain.

### Last guideline

If you change a type switch every other PR, the design is screaming for an interface. If it sits quietly for months on a decode edge — it is fine to leave it.

### Checklist

1. Is the assert with ok?  
2. Does default exist?  
3. Would an interface remove the switch?  
4. Does JSON bring float64?  
5. Is multi-case `v` treated as an interface?

### Exercise R1 — assert with and without ok

```go
package main

import "fmt"

func main() {
	var x any = "hello"
	s := x.(string)
	fmt.Println(s)

	n, ok := x.(int)
	fmt.Println(n, ok) // 0 false — without panic

	// x.(int) without ok → panic
}
```

#### What happens here

1. `x.(string)` opens the interface box; success returns the value.
2. Without `ok`, failure = panic at runtime.
3. With comma-ok, failure = zero value + `ok=false`.
4. In production / over external data always comma-ok.

### Exercise R2 — type switch

```go
func opisi(x any) string {
	switch v := x.(type) {
	case nil:
		return "nil"
	case int:
		return fmt.Sprintf("int=%d", v)
	case string:
		return fmt.Sprintf("string=%q", v)
	case error:
		return "error:" + v.Error()
	default:
		return fmt.Sprintf("other:%T", v)
	}
}
```

#### What happens here

1. `x.(type)` is allowed only in a type switch.
2. In each `case`, `v` has that branch’s type.
3. `case nil` catches a nil interface.
4. `default` must exist for unknown input from JSON/API.

### Exercise R3 — multi-case type of `v`

```go
switch v := x.(type) {
case int, int64:
	fmt.Printf("%T %v\n", v, v) // v is any (shared interface)
}
```

#### What happens here

1. When a case groups multiple types, `v` has the interface type (here `any`), not a concrete type.
2. If you need a concrete API, split the cases or assert inside.
3. Common trap: expecting `int` methods on `v` in multi-case.

### Exercise R4 — JSON number as float64

```go
import (
	"encoding/json"
	"fmt"
)

func main() {
	var x any
	_ = json.Unmarshal([]byte(`{"n":42}`), &x)
	m := x.(map[string]any)
	switch n := m["n"].(type) {
	case float64:
		fmt.Println("float64", int(n))
	case int:
		fmt.Println("int", n)
	default:
		fmt.Printf("unexpected %T\n", n)
	}
}
```

#### What happens here

1. `encoding/json` into `any` often puts numbers as `float64`.
2. `case int` will not hit — that is why IDs “disappear” in a switch.
3. Either use `json.Decoder.UseNumber`, or typed structs instead of `any`.
4. The decode edge is the right place for a type switch; the domain should see `int`/`Cents`.

### Decision table — assert, switch, or interface?

| Situation | Tool |
|-----------|------|
| One expected type | assert + ok |
| Closed set of types at the edge | type switch |
| Behavior grows with new types | interface + methods |
| JSON → domain | decode into a struct; switch only adapter |
| Panic OK (test/Must) | assert without ok (rarely) |

### Exercise R5 — rewrite to an interface

```go
type Notifier interface {
	Notify(msg string) error
}

type Email struct{}
type SMS struct{}

func (Email) Notify(msg string) error { fmt.Println("email", msg); return nil }
func (SMS) Notify(msg string) error   { fmt.Println("sms", msg); return nil }

func send(n Notifier, msg string) error { return n.Notify(msg) }
```

Instead of `switch kanal.(type) { case Email: ... case SMS: ... }` in the domain.

#### What happens here

1. A new channel = a new type + method; the switch in the domain does not grow.
2. A type switch remains when reading configuration (`"email"` string → factory).
3. That is an architectural boundary: adapter vs domain.

### Workshop FAQ

**Q: Difference `x.(T)` and `switch x.(type)`?**  
A: The first is an assert to one type; the second branches on possible types.

**Q: Can you assert to a pointer?**  
A: Yes — `x.(*T)`. A nil pointer inside can still be a non-nil interface (typed nil).

**Q: Type switch on a non-interface?**  
A: No — the left expression must be an interface type.

**Q: Why not panic in a CLI?**  
A: Bad UX and hard testing; return an error/exit code.

**Q: `.(type)` outside a switch?**  
A: Syntax error — only in a type switch header.

**Q: How do I log before an assert?**  
A: `%T` and `%#v` — quick diagnostics of the dynamic type.

**Q: Do generics reduce the need?**  
A: Yes for internal polytyping; external `any` with JSON still needs assert/switch at the edge.

### Edge cases

1. Assert to an interface: `x.(io.Reader)` — success if the dynamic type satisfies.
2. Nil of a concrete type in the box — `case nil` does not catch typed nil; it catches a nil interface.
3. Empty interface vs typed — `%T` before the switch.
4. Map value `any` — every lookup then assert.

### Extra pass — from JSON any to the domain

```go
package main

import (
	"encoding/json"
	"fmt"
)

type Komanda struct {
	Tip  string
	Iznos int
}

func parseKomanda(raw []byte) (Komanda, error) {
	var m map[string]any
	if err := json.Unmarshal(raw, &m); err != nil {
		return Komanda{}, err
	}
	tip, ok := m["tip"].(string)
	if !ok {
		return Komanda{}, fmt.Errorf("tip is not string (%T)", m["tip"])
	}
	var iznos int
	switch v := m["iznos"].(type) {
	case float64:
		iznos = int(v)
	case int:
		iznos = v
	default:
		return Komanda{}, fmt.Errorf("iznos type %T", v)
	}
	return Komanda{Tip: tip, Iznos: iznos}, nil
}
```

#### What happens here

1. Type assert / switch live in `parseKomanda` — the adapter edge.
2. The domain gets `Komanda` with real fields, without `any`.
3. A JSON number arrives as `float64` — the case covers that.
4. Wrong type → `error`, not panic.

### Exercise R6 — assert to an interface

```go
package main

import (
	"bytes"
	"fmt"
	"io"
)

func citajDva(x any) error {
	r, ok := x.(io.Reader)
	if !ok {
		return fmt.Errorf("not Reader (%T)", x)
	}
	buf := make([]byte, 2)
	_, err := r.Read(buf)
	if err != nil && err != io.EOF {
		return err
	}
	fmt.Printf("%q\n", buf)
	return nil
}

func main() {
	_ = citajDva(bytes.NewBufferString("hi"))
}
```

#### What happens here

1. An assert can target an interface: success if the dynamic type satisfies the method set.
2. Comma-ok is still required over unreliable `any`.
3. After success you work with a small contract (`Reader`), not with a concrete buffer.

### Exercise R7 — typed nil vs case nil

```go
var p *int = nil
var x any = p
switch x.(type) {
case nil:
	fmt.Println("nil interface")
default:
	fmt.Printf("not a nil box: %T\n", x) // *int
}
```

#### What happens here

1. `case nil` catches a nil **interface**, not a typed nil inside.
2. The same trap as with `error` — the box is not empty.
3. For a pointer check separately or do not pack a typed nil.

### Exercise R8 — factory instead of a giant switch in the domain

```go
var factories = map[string]func() Notifier{
	"email": func() Notifier { return Email{} },
	"sms":   func() Notifier { return SMS{} },
}

func newNotifier(kind string) (Notifier, error) {
	f, ok := factories[kind]
	if !ok {
		return nil, fmt.Errorf("unknown channel %q", kind)
	}
	return f(), nil
}
```

#### What happens here

1. Configuration string → factory; the domain calls `Notify`.
2. A new channel = a new map entry + type, without growing a type switch through the service.
3. A type switch remains an option for a very closed set of 2–3 types.

### FAQ — more questions

**Q: Does `json.Number` help?**  
A: Yes with `Decoder.UseNumber` — you get `json.Number` instead of float64; still an assert.

**Q: Switch on pointer types?**  
A: `case *T:` works; watch for a nil pointer value.

**Q: Can default log `%#v`?**  
A: Yes — good diagnostics at the edge.

**Q: Assert in a loop over `[]any`?**  
A: OK with ok; consider a typed slice earlier in the pipeline.

**Q: Why not reflect instead of a switch?**  
A: Switch/assert are clearer for a closed set; leave reflect to tools.

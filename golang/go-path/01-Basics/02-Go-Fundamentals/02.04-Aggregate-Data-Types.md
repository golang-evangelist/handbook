# 02.04 Aggregate Data Types

> **Go Path - Zero to Gopher** / **01 Basics → Go Fundamentals** / Lesson 02.04

## Lesson goals

After this lesson you should be able to:

- distinguish **array** and **slice** (length, capacity, backing array, growth on `append`)
- use `copy` and the full slice expression (`a[low:high:max]`) deliberately
- understand **map**: the **zero value** is `nil`, comma-ok, iteration order is not defined
- work with **struct** and **composite literal**
- use **embedding** at an introductory level — without mixing it with inheritance
- know what comparable means and why it matters for map keys and `==`

## Prerequisite

- 01.04 (introduction to collections) or equivalent
- 02.02 (scope, types, **zero value**)
- Go 1.22+

## Problem this lesson solves

01.04 gave the basics. In practice it hurts: unexpected allocation on `append`, capacity leaking through reslice, bugs from assuming **map** order, and trying to use `==` on slices. **Embedding** confuses when mixed with class inheritance.

Without a precise model of the slice header (pointer + len + cap) programmers “fix” bugs by copying code instead of understanding memory. This lesson deepens the mechanisms.

## Mental model

**Array** `[N]T` is a fixed-length value: length is part of the type. `[3]int` and `[4]int` are different types.

**Slice** `[]T` is a small header over (usually) some array in memory:

```text
slice header:  { pointer → backing array, len, cap }
```

- `len` — how many elements you see
- `cap` — how many elements sit from the start of the slice to the end of the backing capacity
- `append` when `len == cap` → a new larger backing array, a copy, a new header

**Map** is a hash table. The zero value is `nil`. Reading from a `nil` map gives the zero value of the value type; writing to a `nil` map → `panic`. The order of `range` is **not** guaranteed.

**Struct** aggregates named fields. A **composite literal** `T{...}` builds a value.

**Embedding**: a nested field without an explicit name; fields/methods are **promoted**. That is composition, not inheritance. **Go has no inheritance.**

## Mechanism

### Array — fixed value

```go
var a [3]int           // [0 0 0]
b := [3]int{10, 20, 30}
c := [...]int{1, 2}    // type [2]int — compiler counts
```

Assignment `a2 := a` **copies** the whole array. A function `func f(x [1000]int)` copies 1000 elements — that is why APIs more often see a slice or a **pointer** to an array.

### Slice header — len, cap, backing array

```go
s := make([]int, 2, 4) // len=2, cap=4, elements 0,0
```

Memory model (simplified):

```text
header s →  ptr ──→ [ 0 | 0 | _ | _ ]
            len=2      ^-- used
            cap=4      ^----------- capacity
```

`s[0] = 7` changes the backing array. `s = append(s, 9)`:

1. `len` (2) < `cap` (4) → there is room
2. writes `9` at index 2
3. new header: `len=3`, same `cap=4`, same ptr

When `append` has no room:

1. the runtime allocates a new array (usually larger cap)
2. copies the old elements
3. adds the new one
4. returns a header that points to the **new** array

That is why you **must** keep the result: `s = append(s, x)`.

**Predict the result:**

```go
s := make([]int, 0, 2)
s = append(s, 1, 2)
fmt.Println(len(s), cap(s))
s = append(s, 3)
fmt.Println(len(s), cap(s))
```

**Answer:** first `2 2`; after the third append `len=3`, and `cap` grows (often to 4) — the exact new cap depends on the runtime, but is **≥ 3** and strictly larger than the old one when it was full.

### Sharing the backing array — the trap

```go
base := []int{1, 2, 3, 4, 5}
a := base[:2]          // len=2, cap=5 (to the end of base)
a = append(a, 99)
fmt.Println(base)      // [1 2 99 4 5] — overwrote base[2]!
```

Why? `a` and `base` share the same array; `cap(a)==5` so `append` does not allocate a new one.

### Full slice expression — cutting cap

```go
base := []int{1, 2, 3, 4, 5}
safe := base[:2:2]     // len=2, cap=2
safe = append(safe, 99)
fmt.Println(base)      // [1 2 3 4 5] — untouched
fmt.Println(safe)      // [1 2 99] — new backing
```

`a[low:high:max]` sets `cap = max-low`. Condition: `0 ≤ low ≤ high ≤ max ≤ cap(a)`.

### `copy`

```go
dst := make([]int, 2)
n := copy(dst, []int{10, 20, 30}) // n=2; dst=[10 20]
```

`copy` does not change `len(dst)`. It copies `min(len(dst), len(src))` elements. For a full independent copy: `dst := make([]int, len(src)); copy(dst, src)` or `slices.Clone(src)` (Go 1.21+).

### Map — zero value, make, comma-ok

```go
var m map[string]int  // nil
// m["a"] = 1         // panic: assignment to entry in nil map
m = make(map[string]int)
m["a"] = 1
v := m["b"]           // 0 — zero value, does not panic
v, ok := m["b"]       // 0, false
v, ok = m["a"]        // 1, true
```

**Predict the result:** what does `fmt.Println(len(m))` print for `var m map[string]int`?

**Answer:** `0`. `len` on a `nil` map is 0; reading is safe; **writing** is not.

Iteration:

```go
for k, v := range m {
	// order is NOT guaranteed
}
```

For stable output: collect keys, `slices.Sort`, then iterate.

Deletion: `delete(m, "a")` — safe even when the key does not exist.

### Struct and composite literal

```go
type User struct {
	Name string
	Age  int
}

u := User{Name: "Ana", Age: 30} // composite literal
var z User                       // zero value: Name="", Age=0
```

Fields with a capital letter are **exported**. Assignment `u2 := u` copies all fields (shallow copy: if a field contains a slice/map/pointer, the reference is shared).

### Embedding — composition, not inheritance

```go
type Engine struct {
	PowerKW int
}

func (e Engine) Describe() string {
	return fmt.Sprintf("%d kW", e.PowerKW)
}

type Car struct {
	Engine // embedding — field without a name
	Model  string
}
```

```go
c := Car{Engine: Engine{PowerKW: 110}, Model: "Urban"}
fmt.Println(c.PowerKW)    // promoted field
fmt.Println(c.Describe()) // promoted method
fmt.Println(c.Engine.PowerKW) // explicit still works
```

**Important:** `Car` is **not** a subtype of `Engine`. This does not compile:

```go
var e Engine = c // type error
```

Embedding is sugar for composition: “Car has an Engine”, not “Car is an Engine”. Go has no inheritance.

### Comparable

Types that may be **map** keys and operands of `==`:

- basic types, pointers, channel, interface, struct/array **if** all fields/elements are comparable

Not comparable: slice, map, function.

```go
type Point struct{ X, Y int }      // OK as a map key
type Bad struct{ Data []byte }     // not comparable
```

## Rules and syntax

1. Always keep the `append` result (`s = append(s, ...)`).
2. `copy` does not extend `dst` — first `make` enough length.
3. Full slice `a[i:j:k]` requires `0 ≤ i ≤ j ≤ k ≤ cap(a)`.
4. Do not rely on map order even in tests without sorting.
5. Writing to a `nil` map → `panic`; reading → zero value.
6. An embedded field can be a pointer (`*Base`) — zero is `nil`, be careful.
7. `==` on a struct compares fields; if any field is not comparable, the struct is not.
8. Prefer `slices.Clone` / `slices.Equal` (Go 1.21+) where it fits.
9. Array length is part of the type; slice length is not.

## Examples

### Example 1 — Slice growth and copy

```go
package main

import "fmt"

func main() {
	s := make([]int, 0, 2)
	show := func(tag string) {
		fmt.Printf("%s len=%d cap=%d %v\n", tag, len(s), cap(s), s)
	}
	show("start")
	s = append(s, 10)
	show("1")
	s = append(s, 20)
	show("2")
	s = append(s, 30)
	show("3")

	dst := make([]int, 2)
	n := copy(dst, s)
	fmt.Println("copy n=", n, "dst=", dst)

	dst2 := make([]int, len(s))
	copy(dst2, s)
	dst2[0] = -1
	fmt.Println("s", s, "dst2", dst2)
}
```

#### What happens here

Capacity jumps when the limit is crossed — you see a new `cap` after the third append. `copy` into a shorter `dst` copies only 2 elements. A full copy into `dst2` gives independent elements — a change does not touch `s`.

### Example 2 — Full slice prevents overwriting

```go
package main

import "fmt"

func main() {
	base := []int{1, 2, 3, 4, 5}
	unsafe := base[:2]
	unsafe = append(unsafe, 99)
	fmt.Println("without cap limit, base=", base)

	base = []int{1, 2, 3, 4, 5}
	safe := base[:2:2]
	safe = append(safe, 99)
	fmt.Println("with full slice, base=", base, "safe=", safe)
}
```

#### What happens here

The first `append` has cap to the end of `base`, so it writes over `base[2]`. The second uses `[:2:2]` — `cap=2` — so `append` allocates a new array; `base` stays intact. An idiomatic technique when a function returns a subslice that the caller may `append` to.

### Example 3 — Map, sorting keys, comparable

```go
package main

import (
	"fmt"
	"slices"
)

func main() {
	m := map[string]int{"b": 2, "a": 1, "c": 3}
	fmt.Println("random print:")
	for k, v := range m {
		fmt.Println(k, v)
	}

	keys := make([]string, 0, len(m))
	for k := range m {
		keys = append(keys, k)
	}
	slices.Sort(keys)
	fmt.Println("stable print:")
	for _, k := range keys {
		fmt.Println(k, m[k])
	}

	type P struct{ X, Y int }
	set := map[P]bool{}
	set[P{1, 2}] = true
	fmt.Println("point in set?", set[P{1, 2}])
}
```

#### What happens here

Two `range` passes can give a different order — that is why tests that compare `fmt.Sprint(map)` flake. Sorted keys give stability. A struct without a slice field can be a map key.

### Example 4 — Embedding preview

```go
package main

import "fmt"

type Timestamped struct {
	Unix int64
}

func (t Timestamped) Label() string {
	return fmt.Sprintf("t=%d", t.Unix)
}

type Event struct {
	Timestamped
	Name string
}

func main() {
	e := Event{Timestamped: Timestamped{Unix: 1_700_000_000}, Name: "login"}
	fmt.Println(e.Name, e.Unix, e.Label())

	var e2 Event
	fmt.Printf("zero embedded: %#v\n", e2)

	// Predict: does this compile?
	// var t Timestamped = e
	// Answer: no — Event is not Timestamped
}
```

#### What happens here

`e.Unix` and `e.Label()` work via promotion. The zero value of the nested struct is zero — there is no “inherited constructor”. Embedding reduces boilerplate; it is not is-a inheritance.

### Example 5 — Array vs slice in an API

```go
package main

import "fmt"

func sumArray(a [3]int) int {
	return a[0] + a[1] + a[2]
}

func sumSlice(s []int) int {
	total := 0
	for _, v := range s {
		total += v
	}
	return total
}

func main() {
	arr := [3]int{1, 2, 3}
	fmt.Println(sumArray(arr))      // copy of the array
	fmt.Println(sumSlice(arr[:]))   // slice view
	fmt.Println(sumSlice([]int{1, 2, 3, 4}))
}
```

#### What happens here

`sumArray` takes exactly 3 elements — the contract is in the type. `sumSlice` takes any length. `arr[:]` makes a slice header over the same backing array without copying elements.

### Example 6 — nil map vs empty map

```go
package main

import "fmt"

func main() {
	var nilMap map[string]int
	empty := map[string]int{}

	fmt.Println(nilMap == nil, empty == nil) // true false
	fmt.Println(len(nilMap), len(empty))     // 0 0
	fmt.Println(nilMap["x"], empty["x"])     // 0 0

	empty["x"] = 1 // OK
	// nilMap["x"] = 1 // panic
	_ = empty
}
```

#### What happens here

Both have `len` 0 and the same reading, but only `make` / composite literal allow writing. Prefer `make` when you know you will write.

## Decision analysis

| Decision | Motive | Alternative |
|----------|--------|-------------|
| Slice in a public API | Flexible length | Array when N is part of the contract |
| Full slice `[:n:n]` | Caller may append without corruption | Document “do not append” |
| `copy` / `Clone` | True isolation | Shared buffer + discipline |
| Sort keys | Deterministic output | Accept random order |
| Embedding | Less boilerplate | Explicit field + delegation |
| `map[T]struct{}` | Set | Slice + linear search |

## Trade-offs

- **Larger cap ahead** — fewer allocations, more memory.
- **Full slice** — safer API, possibly more allocations on append.
- **Sorting keys** — stability, O(n log n).
- **Embedding** — shorter code, less obvious call path.
- **`[N]T` in JSON** — sometimes more awkward than a slice.

## Common mistakes

1. **Append on a reslice corrupts the original**
   ```go
   a := base[:2]
   a = append(a, 99) // may overwrite base[2]
   ```
   What happens: silent data corruption.  
   Why: shared backing + large cap.  
   Fix: `a := base[:2:2]` or `slices.Clone(base[:2])`.

2. **Writing to a nil map**
   ```go
   var m map[string]int
   m["a"] = 1 // panic
   ```
   Why: the zero value map is `nil`.  
   Fix: `m = make(map[string]int)` before writing.

3. **`copy` into a zero-len dst**
   ```go
   var dst []int
   copy(dst, src) // n=0
   ```
   Why: `len(dst)==0`.  
   Fix: `dst = make([]int, len(src))` then `copy`.

4. **Test dependent on map order**
   ```go
   if fmt.Sprint(m) != "map[a:1 b:2]" { t.Fatal(...) }
   ```
   What happens: flaky test.  
   Fix: sort keys or compare by key.

5. **`==` on a slice**
   ```go
   if s1 == s2 { } // does not compile (except nil)
   ```
   Fix: `slices.Equal(s1, s2)`.

6. **Embedding = inheritance**
   ```go
   var e Engine = car // does not work
   ```
   Why: no subtypes. Embedding is composition.

7. **Forgotten `s = append(...)`**
   ```go
   append(s, x) // result discarded
   ```
   What happens: `s` stays old.  
   Fix: `s = append(s, x)`.

## Idiomatic Go

- Document whether a function retains/aliases a slice argument.
- Return `slices.Clone` when isolation is needed.
- For a set: `map[T]struct{}` where T is comparable.
- Sort keys for deterministic output.
- Embedding for small, orthogonal parts — not deep hierarchies.
- `make(map[K]V, hint)` when you know the approximate number of keys.
- Choose an array when the width is a contract; otherwise a slice.

## Practical scenario

A log pipeline sends `[]byte` chunks through a chain of filters. One filter does `return b[:n]` without cutting cap; the next does `append` and overwrites the next chunk in a pool buffer — log corruption. Fix: `return b[:n:n]`. Second problem: a dashboard test compares a JSON object as a string; the map changes field order — flaky. Fix: sort or structural comparison. An event type embeds `Tenant` for an `ID()` method — composition, not “extends Tenant”.

### Diagnosing shared buffers (step by step)

When you suspect two slice variables share memory:

1. Print `len` and `cap` of both headers.
2. If `len > 0`, compare `&s[0]` and `&t[0]` — the same address means the same backing array.
3. Do `append` on one and see whether the other changes.
4. If you need isolation: `slices.Clone(s)` or `append([]T(nil), s...)`.

**Predict the result:**

```go
s := []int{1, 2, 3}
t := s[:2]
t = append(t, 9)
fmt.Println(s)
```

**Answer:** often `[1 2 9]` because `cap(t)` reaches to the end of the original. With `t := s[:2:2]`, `s` would stay `[1 2 3]`.

### Prealloc pattern

```go
func filterEven(in []int) []int {
	out := make([]int, 0, len(in)/2+1)
	for _, v := range in {
		if v%2 == 0 {
			out = append(out, v)
		}
	}
	return out
}
```

`make` with an estimated cap reduces reallocations without insisting on an exact count. Measure before you preallocate huge slices “just in case”.

### Struct with a slice field — shallow copy

```go
type Bag struct {
	Items []string
}

a := Bag{Items: []string{"x"}}
b := a          // copies the slice header, not the elements
b.Items[0] = "y"
fmt.Println(a.Items[0]) // y — shared backing
```

That is why you document lifetime and ownership. If an API returns an inner slice, either clone or clearly say it is a view.

## Check questions

1. **What does `a[i:j:k]` do?**  
   A slice with `len=j-i` and `cap=k-i`.

2. **Why is a map alone not good for deterministic output?**  
   Iteration has no guaranteed order.

3. **Is a slice comparable?**  
   No (except comparison with `nil`).

4. **What does `copy` return?**  
   The number of elements actually copied.

5. **Does embedding mean Event is a subtype of Timestamped?**  
   No — only promotion of fields/methods; Go has no inheritance.

6. **What is the zero value for a map?**  
   `nil`. Reading OK; writing panic.

7. **Why `s = append(s, x)`?**  
   Because `append` may return a new header (new backing).

### One more mechanism: `append` and a nil slice

```go
var s []int          // nil, len=0, cap=0
s = append(s, 1)     // OK — append accepts nil
fmt.Println(s)       // [1]
```

**Predict:** does `var m map[string]int; m["a"]=1` work the same “friendly” way?

**Answer:** No — writing to a nil **map** panics. Slice and map have different zero-value contracts.

### Capacity growth — typical pattern

Although the exact growth factor depends on the runtime version, the behavior you learn:

1. While there is room (`len < cap`) — same backing.
2. When there is not — new array, copy, often larger cap.
3. The old array remains while other slice headers hold it.

That is why sharing + append without a full slice = corruption.

### Example 7 — Set with `map[T]struct{}`

```go
package main

import "fmt"

func main() {
	seen := make(map[string]struct{})
	for _, w := range []string{"a", "b", "a"} {
		seen[w] = struct{}{}
	}
	_, ok := seen["a"]
	fmt.Println(ok, len(seen)) // true 2
}
```

#### What happens here

`struct{}` takes no memory as a value. An idiomatic set for comparable types.

### Example 8 — Embedding a pointer field (caution)

```go
type Inner struct{ N int }
type Outer struct{ *Inner }

func main() {
	var o Outer
	// fmt.Println(o.N) // panic: nil pointer
	o.Inner = &Inner{N: 3}
	fmt.Println(o.N) // 3 via promotion
}
```

#### What happens here

An embedded `*Inner` zero value is `nil`. Accessing a promoted field before initialization panics. Document a constructor.

### Aggregate checklist

- [ ] `s = append(s, ...)` always kept
- [ ] public subslice: `[:n:n]` or Clone
- [ ] map: `make` before write; comma-ok when zero value is valid
- [ ] tests do not depend on map order
- [ ] embedding is not treated as inheritance
- [ ] do not pass a large array by value without reason

### Recap: array vs slice in one table

| | Array `[N]T` | Slice `[]T` |
|---|-------------|-------------|
| Length | part of the type | in the header (`len`) |
| Capacity | = length | `cap` ≥ `len` |
| Assignment | copies elements | copies the header |
| `append` | no (not a slice) | yes, keep the result |
| Typical use | fixed contract (digest) | buffers, lists |

### Recap: map nil vs empty

| | `var m map[K]V` | `m := map[K]V{}` / `make` |
|---|----------------|---------------------------|
| `m == nil` | true | false |
| `len(m)` | 0 | 0 |
| reading | zero value | zero value |
| writing | **panic** | OK |

Remember this table — it saves hours of debugging.

One sentence to take away: **a slice is a header; map zero value is nil for writing; embedding is not inheritance.**

If you remember only those three, most bugs from this lesson become predictable instead of mysterious.

Before you move on: do the `[:n:n]` exercise at least once with your eyes — the shared-buffer theory “clicks” only after you print a corrupted `base`.

Then do the exercise with writing to a `nil` map — the panic message sticks in your head longer than any table.

Aggregates require a precise memory model: array vs slice (len/cap/backing), growth and full slice, map (`nil`, comma-ok, undefined order), struct + composite literal, comparable rules, and careful embedding as composition.

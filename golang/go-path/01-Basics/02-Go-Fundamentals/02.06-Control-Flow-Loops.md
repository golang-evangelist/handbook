# 02.06 Control Flow Loops

> **Go Path - Zero to Gopher** / **01 Basics → Go Fundamentals** / Lesson 02.06

## Lesson goals

After this lesson you should be able to:

- use every form of `for` (classic, while-style, infinite)
- iterate with `range` over slice, **map**, and string
- use Go 1.22 integer `range` (`for i := range n`)
- manage `break` / `continue` and labels
- understand Go 1.22 **per-iteration** loop variables and how that affects **closure**

## Prerequisite

- 01.06 and 02.05
- Go 1.22+ (because of `for i := range n` and per-iteration semantics)
- basic introduction to function literal / closure (02.08 or 01.05)

## Problem this lesson solves

Loops look simple and produce bugs: wrong `range` over a map, a `break` that exits a `switch` instead of the loop, infinite spin, and older code where a **closure** in a loop captures the wrong variable. Go 1.22 changes loop variable semantics and adds integer range — you need to know what holds today.

## Mental model

One keyword: `for`. All loops are forms of it.

`range` produces values from a container. For integer `range n` (1.22+): iterates `0..n-1` if `n > 0`.

Labels mark a loop so `break Label` / `continue Label` can jump past a nested `switch`/`for`.

**Go 1.22 rule:** a loop variable (`i`, `v`, `k`…) gets a **new** variable on each iteration. Closures that capture it see that iteration's value. Before 1.22 all iterations shared one variable — a historical trap; the course assumes 1.22+.

## Mechanism

### Three (+1) forms

```go
for i := 0; i < n; i++ { } // classic
for cond { }               // while-style
for { }                    // forever
for i := range n { }       // Go 1.22+ integer range
```

### `range` over slice

```go
for i, v := range nums {
	// v is a COPY of the element
}
for i := range nums {
	nums[i] *= 2 // mutate via index
}
```

Trace for `nums := []int{10, 20}`:

| Iteration | `i` | `v` |
|-----------|-----|-----|
| 1 | 0 | 10 |
| 2 | 1 | 20 |

Mutating `v` does not change `nums`. Mutating `nums[i]` does.

### `range` over map

Order is **not** guaranteed. `range` over a `nil` map — 0 iterations.

### `range` over string

The index is a **byte** offset; the value is `rune`. For `"Goč"` you see the index jump after a multi-byte character.

### Integer range (1.22+)

```go
for i := range 5 {
	// i = 0,1,2,3,4
}
for range 5 {
	// counter only, no i
}
```

For `n <= 0` — zero iterations. Requires `go 1.22` in `go.mod`.

### `break` / `continue` and labels

```go
Outer:
for _, cmd := range commands {
	switch cmd {
	case "skip":
		continue Outer
	case "stop":
		break Outer
	}
}
```

Without a label, `break` in a `switch` exits only the `switch`.

**Predict the result:**

```go
for _, cmd := range []string{"stop", "run"} {
	switch cmd {
	case "stop":
		break
	}
	fmt.Println("after", cmd)
}
```

**Answer:** prints `after stop` and `after run` — `break` did not stop the `for`.

### Closure in a loop — Go 1.22 per-iteration

```go
var fns []func()
for i := range 3 {
	fns = append(fns, func() { fmt.Println(i) })
}
for _, f := range fns {
	f()
}
```

In **1.22+** output: `0`, `1`, `2`. Each iteration has its own `i`; the function literal captures exactly that one.

**Historical trap (pre 1.22):** all three functions captured one `i` (the last value), so output was often `2 2 2`. A manual copy `i := i` inside the loop was the workaround. On the course: 1.22+; read legacy code carefully.

What the compiler/runtime does (1.22): for each iteration it creates a new loop variable and links the closure to *that* variable. If the closure outlives the loop, the variable stays on the heap.

### Mutation during range

Deleting the current key from a map during `range` is OK. Adding new keys can be confusing (a new key may or may not be visited). Prefer: collect changes, then apply after the loop.

## Rules and syntax

1. No `while` / `do-while` keywords.
2. `range` over nil slice/map — 0 iterations.
3. `range` over a nil **channel** — blocks forever (02.11); do not do that by mistake.
4. Integer `range` requires Go 1.22+.
5. `continue` jumps to the next iteration (or labeled one).
6. `v` from `range` is a copy — to mutate use an index or a pointer element.
7. On 1.22+ you do not need `i := i` for a closure in a loop; on older Go you do.

## Examples

### Example 1 — Three forms of for

```go
package main

import "fmt"

func main() {
	for i := 0; i < 3; i++ {
		fmt.Println("A", i)
	}
	n := 3
	for n > 0 {
		fmt.Println("B", n)
		n--
	}
	tries := 0
	for {
		tries++
		if tries >= 3 {
			fmt.Println("C done")
			break
		}
		fmt.Println("C attempt", tries)
	}
}
```

#### What happens here

Classic, while-style, infinite with an exit. All are `for`. In servers `for { select { ... } }` is common (channel later).

### Example 2 — range: slice, map, string

```go
package main

import "fmt"

func main() {
	nums := []int{10, 20, 30}
	for i, v := range nums {
		fmt.Println("slice", i, v)
	}
	for i := range nums {
		nums[i] *= 2
	}
	fmt.Println("doubled", nums)

	m := map[string]int{"x": 1, "y": 2}
	for k, v := range m {
		fmt.Println("map", k, v)
	}

	s := "Goč"
	for i, r := range s {
		fmt.Printf("string i=%d r=%c\n", i, r)
	}
}
```

#### What happens here

`v` is a copy; `nums[i]` mutates the slice. Map: order is random. String: `i` is a byte index.

### Example 3 — Integer range

```go
package main

import "fmt"

func main() {
	for i := range 5 {
		fmt.Println("i", i)
	}
	sum := 0
	for range 5 {
		sum++
	}
	fmt.Println("sum", sum) // 5
	for i := range 0 {
		fmt.Println("wont", i)
	}
}
```

#### What happens here

`for i := range n` replaces the classic counter. For `n<=0` there are no iterations.

### Example 4 — Labels and the switch trap

```go
package main

import "fmt"

func main() {
	commands := []string{"run", "skip", "run", "stop", "run"}
Outer:
	for _, cmd := range commands {
		switch cmd {
		case "skip":
			continue Outer
		case "stop":
			break Outer
		case "run":
			fmt.Println("executing")
		}
	}
	fmt.Println("end of loop")
}
```

#### What happens here

`continue Outer` skips. `break Outer` leaves the loop on `stop`. Without a label, `break` would only leave the switch.

### Example 5 — Closure in a loop (1.22+)

```go
package main

import "fmt"

func main() {
	var fns []func() int
	for i := range 3 {
		fns = append(fns, func() int { return i })
	}
	for _, f := range fns {
		fmt.Println(f())
	}
}
```

#### What happens here

Expected output: `0 1 2`. Per-iteration variables (Go 1.22+). Pre 1.22 without `i := i` it would typically be `2 2 2`.

### Example 6 — Retry with integer range

```go
package main

import (
	"errors"
	"fmt"
)

func attempt(n int) error {
	if n < 3 {
		return fmt.Errorf("attempt %d failed", n)
	}
	return nil
}

func runWithRetry(max int) error {
	for i := range max {
		err := attempt(i + 1)
		if err == nil {
			fmt.Println("success on attempt", i+1)
			return nil
		}
		fmt.Println(err)
	}
	return errors.New("retry limit exhausted")
}

func main() {
	_ = runWithRetry(5)
}
```

#### What happens here

Integer range reads as “repeat up to max times”. Success on attempt 3; then `return nil`.

## Decision analysis

| Decision | Recommendation |
|----------|----------------|
| `range` vs index | `range` for reading; index for replacement / reverse |
| Integer range | Shorter for “repeat n times” on 1.22+ |
| Labels | Only when needed; often better to extract a function + `return` |
| Closure in a loop | OK on 1.22+; legacy: `i := i` or an argument |

## Trade-offs

- **Infinite for** — flexible, easy to forget an exit.
- **Labels** — powerful, reduce readability.
- **Range copies the element** — expensive for large structs; range `[]*T` or use an index.
- **Integer range** — clean, older toolchains will not compile.
- **Mutation during range** — defined for some cases, confusing for others.

## Common mistakes

1. **`break` in switch thinking it stops for**
   ```go
   for {
   	switch {
   	case done:
   		break // only switch!
   	}
   }
   ```
   Fix: `break Outer` or `return`.

2. **Relying on map order** — sort the keys.

3. **Mutating `v` from range expecting the slice to change**
   ```go
   for _, v := range nums { v *= 2 } // nums untouched
   ```
   Fix: `for i := range nums { nums[i] *= 2 }`.

4. **`for range ch` on a nil channel** — deadlock (02.11).

5. **Busy loop without blocking** — 100% CPU.

6. **Integer range on Go < 1.22** — does not compile.

7. **Legacy closure in a loop** — you expect 0,1,2 on old Go, you get 2,2,2.

## Idiomatic Go

- `for _, v := range` when you do not need the index.
- Guard `continue` to skip invalid elements.
- Extract nested loops into functions before three labels.
- Put `go 1.22` (or newer) in `go.mod` if you use the new loops.
- Document why an infinite loop exists (server loop).
- Test off-by-one at boundaries (`n==0`, empty slice).

## Practical scenario

An agent processes a batch of IDs. Inside `switch status` — without a label, `break` was not stopping the batch. Fix: `break Batch` or `return` from `processBatch`. The service moves to Go 1.22; the old “loop variable capture” test no longer fails — they remove manual `i := i`. Integer `for range 10` in a retry loop — shorter in review.

## Check questions

1. **Which keyword covers while?**  
   `for` with only a condition.

2. **What does `for i := range n` do in Go 1.22?**  
   `i = 0..n-1` for `n > 0`.

3. **Why a label with break?**  
   So you exit the loop, not only the inner switch.

4. **Does mutating `v` in range change the slice?**  
   No — copy; use an index.

5. **What does range over a nil slice do?**  
   Zero iterations, no panic.

6. **How does Go 1.22 change closure in a loop?**  
   Per-iteration variables — each iteration its own; pre 1.22 shared.

### Deeper trace: off-by-one and empty input

Imagine a spec: “sum the first `n` natural numbers starting from 1”.

```go
func sumN(n int) int {
	sum := 0
	for i := range n { // 0..n-1
		sum += i + 1
	}
	return sum
}
```

Trace for `n=3`: `i` goes 0,1,2 → adds 1,2,3 → `sum=6`.  
For `n=0`: zero iterations → `0`.  
For `n=1`: one iteration → `1`.

**Predict the result:** what does `sumN(-1)` return?

**Answer:** `0` — integer `range` for `n <= 0` has no iterations. If the spec requires `error` for negative `n`, you must check explicitly before the loop.

### Deeper trace: range over string “č”

```go
s := "ač"
for i, r := range s {
	fmt.Printf("i=%d r=%c U+%04X\n", i, r, r)
}
```

Expect roughly:

- `i=0`, `r='a'`
- `i=1`, `r='č'` (multiple bytes; the next index jumps)

If you do `for i := 0; i < len(s); i++ { s[i] }` you get **bytes**, not runes. That is not a bug — those are two different models. For text use `range` or the `utf8`/`unicode` packages.

### When to extract a function instead of a label

```go
func processAll(ids []string) error {
	for _, id := range ids {
		if err := processOne(id); err != nil {
			return err // clearer than break Outer
		}
	}
	return nil
}

func processOne(id string) error {
	if id == "" {
		return nil // or error — by contract
	}
	// ...
	return nil
}
```

Labels make sense in a small scope. Once the loop + switch grow, `return` from a helper reads better in review.

### Checklist before merge (loops)

- [ ] `break` in a switch inside for does what you think
- [ ] empty slice / `n==0` does not panic
- [ ] closure in a loop on 1.22+ (or an explicit copy on old Go)
- [ ] `go.mod` allows integer range if you use it
- [ ] no busy loop without blocking
- [ ] map iteration is not asserted by order in a test

### Example 7 — Reverse and swap elements

```go
package main

import "fmt"

func reverseInPlace(s []int) {
	for i, j := 0, len(s)-1; i < j; i, j = i+1, j-1 {
		s[i], s[j] = s[j], s[i]
	}
}

func main() {
	s := []int{1, 2, 3, 4}
	reverseInPlace(s)
	fmt.Println(s) // [4 3 2 1]
}
```

#### What happens here

Classic `for` with two indices. For `len==0` or `1` the loop does not run / does not change.

Trace for `[1,2,3,4]`:

| i | j | after swap |
|---|---|------------|
| 0 | 3 | [4,2,3,1] |
| 1 | 2 | [4,3,2,1] |
| 2 | 1 | stop |

### Comparison: three ways to “repeat 5 times”

```go
for i := 0; i < 5; i++ { }
for i := range 5 { }          // 1.22+
i := 0
for i < 5 { i++ }
```

All three are valid. Integer range is shortest when you only need a counter. While-style is used when the condition is not a pure counter (e.g. “while there is work”).

### Closure + goroutine note

When in a loop you do `go func(){ ... i ... }()`, on Go 1.22+ per-iteration `i` is correct. It is still readable to pass `go func(i int){ ... }(i)`. Concurrency details in 02.11 — here remember that loop and closure are no longer an automatic trap on 1.22+.

### Example 8 — Filtering with continue (production style)

```go
package main

import "fmt"

func activeIDs(ids []string) []string {
	out := make([]string, 0, len(ids))
	for _, id := range ids {
		if id == "" {
			continue
		}
		if id[0] == '#' {
			continue // comment
		}
		out = append(out, id)
	}
	return out
}

func main() {
	fmt.Println(activeIDs([]string{"a", "", "#x", "b"}))
}
```

#### What happens here

Two `continue`s keep the body shallow. An alternative with nested `if` quickly becomes a pyramid. Prealloc `cap=len(ids)` reduces reallocations.

### Example 9 — Infinite loop with a clear exit

```go
func drain(cmds []string) {
	i := 0
	for {
		if i >= len(cmds) {
			return
		}
		cmd := cmds[i]
		i++
		if cmd == "quit" {
			return
		}
		if cmd == "" {
			continue
		}
		fmt.Println("cmd", cmd)
	}
}
```

#### What happens here

`for { }` + `return`/`continue` is a valid server/worker shape. There must always be an obvious exit — otherwise busy loop.

### Example 10 — Range index only

```go
for i := range slice {
	slice[i] = 0
}
```

When you do not need the value, do not write `for i, _ := range` — `for i := range` is enough.

### Historical note (only for reading old code)

Before Go 1.22:

```go
for i := 0; i < 3; i++ {
	i := i // manual per-iteration copy
	go func() { fmt.Println(i) }()
}
```

If you see `i := i` in a loop in old code — that is a workaround, not “magic”. On 1.22+ it is not needed for per-iteration semantics. Do not remove it in code that must run on Go < 1.22 without checking `go.mod`.

### Compact map of forms

| Form | When |
|------|------|
| `for i := 0; i < n; i++` | you need classic / step ≠ 1 |
| `for cond` | while-condition |
| `for { }` | server loop / until signal |
| `for i := range n` | repeat n times (1.22+) |
| `for i, v := range xs` | reading elements |
| `for i := range xs` | indices / mutation |

### Example 11 — Summing with early continue

```go
func sumPositive(xs []int) int {
	sum := 0
	for _, v := range xs {
		if v <= 0 {
			continue
		}
		sum += v
	}
	return sum
}
```

Trace `[1,-2,3]`: +1, skip, +3 → `4`.

### Example 12 — Label continue in nested for

```go
Outer:
for i := range 3 {
	for j := range 3 {
		if i == j {
			continue Outer
		}
		fmt.Println(i, j)
	}
}
```

#### What happens here

When `i==j`, the **outer** loop continues, not the inner one. Without a label, `continue` would only affect the inner `for`.

### Example 13 — while-style with a scanner (conceptual)

```go
// Pattern pseudocode (valid Go with bufio.Scanner):
// for scanner.Scan() {
//     line := scanner.Text()
//     if line == "" { continue }
//     process(line)
// }
// if err := scanner.Err(); err != nil { return err }
```

Pattern: the loop reads while there is data; `continue` skips empty; `error` after the loop. Same mental model as `for cond`.

### Example 14 — Integer range in a test helper

```go
func repeat(n int, fn func(i int)) {
	for i := range n {
		fn(i)
	}
}
```

Useful in tests: `repeat(3, func(i int){ ... })`. Requires Go 1.22+.

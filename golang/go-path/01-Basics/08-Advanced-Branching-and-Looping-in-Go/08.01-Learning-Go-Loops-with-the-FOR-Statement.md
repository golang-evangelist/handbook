# 08.01 Learning Go Loops with the FOR Statement

> **Go Path - Zero to Gopher** / **01 Basics → Advanced Branching and Looping in Go** / Lesson 08.01

## Lesson goals

After this lesson you should be able to:

- write the **three classic forms** of a `for` loop in Go (init/condition/post, condition only, infinite);
- use `range` over slice, map, string, and channel and know exactly what it returns;
- understand that from **Go 1.22** loop variables exist **per iteration** (important for a closure);
- control `break` / `continue` with labels;
- avoid traps (map order, copy of `v`, `len` of a string);
- build a small scanner that counts words.

## Prerequisite

- Basic arrays, strings, maps.
- Go 1.22+ (`range` over int from 1.22; per-iteration variables from 1.22).
- 06.05 preferred for string/rune.

## Problem this lesson solves

Go has no `while` or `do-while` as separate keywords — everything is `for`. Without a clear model:

- people write C-style where `range` is needed;
- they break on map iteration (order is not guaranteed);
- closures in a loop capture the “last” index on old Go — and on 1.22 the rules are different;
- they do not know labels for break from a nested level;
- they count bytes instead of words in text.

## Mental model

One statement, multiple forms:

```text
for init; condition; post { }   // 1) classic counter
for condition { }               // 2) while-style
for { }                     // 3) infinite (with break/return/select)
for i, v := range X { }     // collection iteration
for i := range n { }        // Go 1.22: 0..n-1
```

From Go 1.22: in each iteration `i` and `v` (and classic `for i := 0; ...`) get **new variables**. A closure that captures `i` no longer shares one `i` with all iterations. Older code (before 1.22) shared one variable — that is why tutorials still show `i := i`.

A label is a name in front of the loop: `Outer:` — `break Outer` jumps out of multiple levels.

## Mechanism

### Form 1 — classic for

```go
for i := 0; i < 10; i++ {
	fmt.Println(i)
}
```

1. `i := 0` — init once.
2. Check `i < 10` before each body.
3. After the body `i++`.
4. In Go 1.22+ each iteration has its own `i` for capturing in a closure.

### Form 2 — conditional for (while-style)

```go
for !done {
	done = step()
}
```

No init/post. Equivalent to `while` in other languages.

### Form 3 — infinite for

```go
for {
	if done() {
		break
	}
}
```

Common in servers: `for { select { ... } }`. There must always be an exit (`break`, `return`, `context` cancellation).

### `range` semantics

| Collection | First value | Second value | Note |
|-----------|---------------|----------------|----------|
| slice/array | index | **copy** of the element | changing `v` does not change the slice |
| map | key | value | **order is not guaranteed** |
| string | byte-offset | rune | see 06.05 |
| channel | element | — | until the channel is closed |
| int (1.22+) | 0..n-1 | — | `for i := range n` |

To change slice elements: `s[i] = ...` or range over pointers / indexes.

### Labels

```go
Outer:
for i := 0; i < n; i++ {
	for j := 0; j < m; j++ {
		if bad(i, j) {
			break Outer
		}
	}
}
```

`continue Outer` goes to the next iteration of the outer loop. Use rarely; often a cleaner `return` from a helper function.

### Closure in a loop (Go 1.22+)

```go
var fns []func()
for i := range 3 {
	fns = append(fns, func() { fmt.Println(i) })
}
for _, fn := range fns {
	fn() // 0 1 2 on Go 1.22+
}
```

On Go ≥ 1.22 the print is 0,1,2. On older runtime often 2,2,2. This course targets 1.22+ — but read old code consciously.

## Rules and syntax

- `range` on a map: do not rely on order; sort keys if you need stable output.
- The value from range over a slice is a copy.
- `continue` / `break` with a label target the labeled loop.
- `for sc.Scan() { }` is a conditional for hidden behind methods.

## Examples

### Example 1 — three forms of for

```go
package main

import "fmt"

func main() {
	sum := 0
	for i := 1; i <= 5; i++ {
		sum += i
	}
	fmt.Println("sum:", sum) // 15

	n := 1
	for n < 100 {
		n *= 2
	}
	fmt.Println("first >=100 power of two:", n)

	c := 0
	for {
		c++
		if c >= 3 {
			break
		}
	}
	fmt.Println("c:", c)
}
```

#### What happens here

1. Classic for sums 1..5 → 15.
2. Conditional for doubles while `n < 100` → 128.
3. Infinite for increments `c` to 3 then `break`. There is no `while` keyword — everything is `for`.

### Example 2 — range over slice and string

```go
package main

import "fmt"

func main() {
	brojevi := []int{10, 20, 30}
	for i, v := range brojevi {
		v = 999 // does not change the slice
		fmt.Printf("%d -> %d\n", i, brojevi[i])
	}

	s := "ćao"
	for i, r := range s {
		fmt.Printf("byte %d rune %c\n", i, r)
	}
}
```

#### What happens here

1. `v = 999` changes a copy; `brojevi[i]` stays 10,20,30.
2. String range walks by runes; `ć` moves the byte-offset by more than 1.
3. To change: `brojevi[i] = 999`.

### Example 3 — labels, map, range over int

```go
package main

import "fmt"

func main() {
	grid := [][]int{{1, 0, 3}, {4, 5, 6}}
FindZero:
	for i, red := range grid {
		for j, v := range red {
			if v == 0 {
				fmt.Println("zero at", i, j)
				break FindZero
			}
		}
	}

	m := map[string]int{"a": 1, "b": 2}
	for k, v := range m {
		fmt.Println(k, v) // order is not guaranteed
	}

	for i := range 3 {
		fmt.Println(i) // 0 1 2
	}
}
```

#### What happens here

1. The label breaks **both** loops at once when it finds a zero.
2. The map loop prints pairs without a guaranteed order — run it several times.
3. `range 3` is Go 1.22’s short replacement for `for i := 0; i < 3; i++`.

### Example 4 — per-iteration and closure

```go
package main

import "fmt"

func main() {
	var out []func()
	for i := 0; i < 3; i++ {
		out = append(out, func() { fmt.Print(i, " ") })
	}
	for _, f := range out {
		f()
	}
	fmt.Println()
}
```

#### What happens here

1. On Go 1.22+ each iteration has its own `i`; closures print `0 1 2`.
2. On older Go the same loop often prints `2 2 2` because all closures share one `i`.
3. If you maintain old code: `i := i` inside the loop or an explicit parameter `func(i int) func() {...}(i)`.

## Mini project — text scanner that counts words

Goal: a program reads stdin or an argument-file, counts lines, words, and bytes, prints a summary.

```go
package main

import (
	"bufio"
	"fmt"
	"os"
	"strings"
	"unicode"
)

func main() {
	in := os.Stdin
	if len(os.Args) > 1 {
		f, err := os.Open(os.Args[1])
		if err != nil {
			fmt.Fprintln(os.Stderr, err)
			os.Exit(1)
		}
		defer f.Close()
		in = f
	}

	linije, reci, bajtovi := skeniraj(in)
	fmt.Printf("lines=%d words=%d bytes=%d\n", linije, reci, bajtovi)
}

func skeniraj(f *os.File) (linije, reci, bajtovi int) {
	sc := bufio.NewScanner(f)
	for sc.Scan() {
		line := sc.Text()
		linije++
		bajtovi += len(line) + 1 // roughly: + newline
		reci += brojReci(line)
	}
	if err := sc.Err(); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	return linije, reci, bajtovi
}

func brojReci(s string) int {
	n := 0
	uReci := false
	for _, r := range s {
		if unicode.IsSpace(r) {
			uReci = false
			continue
		}
		if !uReci {
			n++
			uReci = true
		}
	}
	return n
}

func brojReciFields(s string) int {
	return len(strings.Fields(s))
}
```

```bash
echo "hello world from Go" | go run .
go run . input.txt
```

#### What happens here (mini project)

1. Input: stdin or a file via `os.Args` — CLI pattern from 06.01.
2. `for sc.Scan()` — conditional for: each iteration one line.
3. `brojReci`: `range` by runes + state `uReci` — entering a word counts once.
4. `len(line)` counts UTF-8 **bytes** (wc-like), not runes — a deliberate decision.
5. Errors on stderr + exit 1; result on stdout.
6. `brojReciFields` is a shorter alternative for a comparison exercise.

## Decision analysis

| Task | Loop |
|---------|--------|
| index math | classic for |
| walk a collection | range |
| wait for a condition | for condition |
| server loop | for { select ... } |
| exit from 2 levels | label or function + return |

## Trade-offs

| | Classic for | range |
|--|--------------|-------|
| index control | full | data-driven |
| readability for collections | weaker | better |
| map order | N/A | random |

## Common mistakes

1. **Wrong:** relying on map order.  
   **Effect:** flaky tests / unstable output.  
   **Why:** the specification does not guarantee order.  
   **Fix:** sort keys before printing.

2. **Wrong:** changing `v` from range expecting to change a slice element.  
   **Effect:** slice unchanged.  
   **Why:** `v` is a copy.  
   **Fix:** `s[i] = ...`.

3. **Wrong:** `len(string)` as word/letter count.  
   **Effect:** wrong metrics for Unicode.  
   **Why:** `len` counts bytes.  
   **Fix:** range / `utf8.RuneCountInString` / word scanner.

4. **Wrong:** infinite for without an exit.  
   **Effect:** deadlock / CPU spin.  
   **Why:** no `break`/`return`/`ctx.Done`.  
   **Fix:** an explicit exit condition.

5. **Wrong:** nested `break` without a label when you need to leave both.  
   **Effect:** exits only the inner loop.  
   **Why:** `break` applies to the nearest for/switch.  
   **Fix:** label or `return`.

6. **Wrong:** forgotten `sc.Err()` after `Scan`.  
   **Effect:** an I/O error passes silently.  
   **Why:** end of input is not an error; a real error is in `Err()`.  
   **Fix:** always check.

## Idiomatic Go

- `range` by default for collections.
- Labels rarely, but clearly when needed.
- Scanners via `bufio`.
- Go 1.22 `range n` for simple counters.
- Early `return` instead of deep labels where you can.
- Write for 1.22+ per-iteration semantics; document if you target an older runtime.

## Practical scenario

A log processor used a map “level → count” and tested the exact print order — flaky tests. Fix: sorting keys before printing. Word count in a pipeline moved to `bufio.Scanner` instead of `ReadAll` because of large files. An old service on Go 1.20 had a closures-in-loop bug (`2 2 2`); after upgrading to 1.22 the behavior fixed without `i := i`.

## Workshop

Goal: forms of `for`, `range` (slice/map/string), labels, Go 1.22 per-iteration and closure in a loop.

### Exercise R1 — three forms of for

```go
package main

import "fmt"

func main() {
	for i := 0; i < 3; i++ {
		fmt.Println("classic", i)
	}

	n := 3
	for n > 0 {
		fmt.Println("condition", n)
		n--
	}

	i := 0
	for {
		if i >= 3 {
			break
		}
		fmt.Println("infinite", i)
		i++
	}
}
```

#### What happens here

1. Classic for: init; condition; post — like C, but without parentheses around the condition.
2. Condition only = while pattern.
3. Infinite `for { }` requires `break`/`return` or a blocking channel.
4. There are no `while` / `do-while` keywords — everything is `for`.

### Exercise R2 — range over slice and string

```go
brojevi := []int{10, 20, 30}
for i, v := range brojevi {
	fmt.Println(i, v)
}

s := "čaša"
for i, r := range s {
	fmt.Printf("%d %c\n", i, r)
}
```

#### What happens here

1. Range over a slice gives index and a copy of the element.
2. Range over a string gives byte-offset and rune — indexes jump on UTF-8.
3. Ignore the index with the blank identifier: `for _, v := range ...`.
4. Changing `v` does not change the slice — you need `brojevi[i] = ...` or range over indexes.

### Exercise R3 — map order

```go
m := map[string]int{"b": 2, "a": 1, "c": 3}
for k, v := range m {
	fmt.Println(k, v) // order is not guaranteed
}
```

For stable output: collect keys, sort, then iterate.

#### What happens here

1. The language deliberately does not guarantee map order.
2. Tests that expect an exact print order are flaky.
3. Sorting keys is the idiom for deterministic output.

### Exercise R4 — label for break

```go
mat := [][]int{{1, 2}, {0, 4}, {5, 6}}
nadjeno := false
outer:
for i := range mat {
	for j := range mat[i] {
		if mat[i][j] == 0 {
			nadjeno = true
			break outer
		}
	}
}
fmt.Println(nadjeno)
```

#### What happens here

1. Ordinary `break` exits only the inner loop.
2. A label targets the outer loop — clean for “find and exit”.
3. Do not abuse labels for goto-style control flow.

### Exercise R5 — closure in a loop (Go 1.22+)

```go
var fns []func()
for i := range 3 {
	fns = append(fns, func() { fmt.Println(i) })
}
for _, fn := range fns {
	fn()
}
// Go 1.22+: 0 1 2
// Older: often 2 2 2 without i := i
```

#### What happens here

1. A function literal captures variables from the environment — that is a closure.
2. From Go 1.22 the loop makes a new variable per iteration.
3. On older Go all closures shared the same `i` — the “all last” bug.
4. In code review: check the language version before you delete `i := i`.

### Exercise R6 — `for i := range n`

```go
for i := range 5 {
	fmt.Println(i) // 0..4
}
```

#### What happens here

1. Go 1.22+ allows range over an integer.
2. A replacement for `for i := 0; i < n; i++` in simple counters.
3. Do not mix with range over a slice of length n — the semantics are “numbers 0..n-1”.

### Decision table — which for?

| Need | Form |
|---------|-------|
| Index + element | `for i, v := range` |
| Elements only | `for _, v := range` |
| Indexes only | `for i := range` |
| While condition | `for condition` |
| Event loop / select | `for { select ... }` |
| Counter 0..n-1 | `for i := range n` (1.22+) |

### Workshop FAQ

**Q: Does `range` copy?**  
A: Element `v` is a copy; for large structs consider an index or pointer.

**Q: Can `continue` take a label?**  
A: Yes — `continue outer` jumps to the next iteration of the outer loop.

**Q: Why is there no `foreach`?**  
A: `range` covers that job idiomatically.

**Q: Concurrent map modification during range?**  
A: Undefined / panic possible — do not mutate a map carelessly during iteration from another goroutine without synchronization.

**Q: `range` over a channel?**  
A: Reads until the channel is closed — important in concurrency patterns.

**Q: Init in for and shadowing?**  
A: `for i := 0; ...` makes a new scope for `i` in the loop.

**Q: When classic instead of range?**  
A: When you need a nonstandard step (`i += 2`) or mutate the index in the body.

### Edge cases

1. Range over a nil slice — zero iterations, no panic.
2. Range over a nil map — same.
3. Break in a switch inside for — break goes to the switch, not the loop (label/return).
4. Large file: Scanner instead of `ReadAll`.

### Extra pass — word counter with a frequency map

```go
package main

import (
	"bufio"
	"fmt"
	"os"
	"sort"
	"strings"
)

func frekvencija(r *bufio.Scanner) map[string]int {
	m := make(map[string]int)
	for r.Scan() {
		for _, w := range strings.Fields(r.Text()) {
			m[strings.ToLower(w)]++
		}
	}
	return m
}

func stampajSortirano(m map[string]int) {
	keys := make([]string, 0, len(m))
	for k := range m {
		keys = append(keys, k)
	}
	sort.Strings(keys)
	for _, k := range keys {
		fmt.Println(k, m[k])
	}
}

func main() {
	sc := bufio.NewScanner(os.Stdin)
	m := frekvencija(sc)
	if err := sc.Err(); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
	stampajSortirano(m)
}
```

#### What happens here

1. Outer `for Scan` reads lines; inner `Fields` splits words.
2. The map collects frequencies — key order is not guaranteed.
3. Sorting keys gives deterministic CLI output / test.
4. `sc.Err()` after the loop catches I/O errors separately from EOF.

### Exercise R7 — break from for+switch

```go
loop:
for _, v := range []int{1, 2, 3} {
	switch v {
	case 2:
		break loop // exits the for, not only the switch
	}
	fmt.Println(v)
}
```

#### What happens here

1. `break` without a label in a switch exits the switch; the loop continues.
2. Label `loop` targets the loop — a common trap in code review.

### Exercise R8 — range over a channel (sketch)

```go
ch := make(chan int)
go func() {
	for i := range 3 {
		ch <- i
	}
	close(ch)
}()
for v := range ch {
	fmt.Println(v)
}
```

#### What happens here

1. Range over a channel reads until the channel is closed.
2. Forgotten `close` → infinite wait (deadlock in this example).
3. Concurrency: closure in a goroutine and channel idioms come together later in the curriculum — here only a feel for `for range ch`.

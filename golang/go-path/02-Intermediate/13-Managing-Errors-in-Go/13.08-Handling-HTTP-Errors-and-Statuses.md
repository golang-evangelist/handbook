# 13.08 Handling HTTP Errors and Statuses

> **Go Path - Zero to Gopher** / **02 Intermediate → Managing Errors in Go** / Lesson 13.08

## Lesson goals

After this lesson you should:

- map domain errors to correct HTTP status codes (404 vs 400 vs 500)
- log internal detail while sending the client a generic body for 5xx
- distinguish client errors (4xx) from server / dependency errors (5xx)
- keep one mapping function instead of copy-paste in every handler
- connect this with `errors.Is` / `errors.As` and errors from goroutine / errgroup flows

## Prerequisite

- `net/http` basics (handler, `ResponseWriter`, status)
- lessons 13.02–13.07 (error types, wrap, channel, errgroup)
- Go 1.22+ (`ServeMux` patterns, `PathValue` as needed)
- high-level idea of problem details / JSON error responses

## Problem this lesson solves

All errors as `500`, or `200` with `{"ok":false}`, break clients, cache, and alerts. Wrong `404` instead of `403` reveals or hides resources. Internal SQL / stack in JSON body is a security and operations problem. You need a clear map: **error value → status + public code**, with a log that preserves truth for on-call.

## Mental model

1. **4xx** — client can fix the request, auth, or input.
2. **5xx** — server or dependency; client retries per policy.
3. **Not found (404)** — resource does not exist (or “does not exist for you” per security policy).
4. **Bad request (400)** / **Unprocessable (422)** — syntax / input validation.
5. **Internal (500)** / **Bad gateway (502)** / **Unavailable (503)** — internal; body generic.
6. **Log internally, body publicly** — never the reverse.
7. **One map** — handler calls `WriteError(w, r, err)`, not manual `http.Error` with string from DB.

## Mechanism

### Typical status map

| Domain situation | HTTP status | Public body |
|--------------------|-------------|------------|
| validation / bad JSON | 400 or 422 | short detail |
| not logged in | 401 | generic |
| no permission | 403 | generic |
| no resource | 404 | “not found” |
| version conflict | 409 | conflict code |
| rate limit | 429 | retry hint |
| bug / unexpected | 500 | generic |
| dependency down | 502 / 503 / 504 | generic |

### Trace 1 — sentinel and As types

```go
package apperr

import (
	"errors"
	"fmt"
)

var (
	ErrNotFound   = errors.New("not found")
	ErrValidation = errors.New("validation")
	ErrConflict   = errors.New("conflict")
	ErrUnauthorized = errors.New("unauthorized")
	ErrForbidden  = errors.New("forbidden")
)

type ValidationError struct {
	Fields map[string]string
}

func (e *ValidationError) Error() string { return "validation failed" }
func (e *ValidationError) Is(target error) bool { return target == ErrValidation }

func WrapNotFound(entity, id string) error {
	return fmt.Errorf("%s id=%s: %w", entity, id, ErrNotFound)
}
```

### Trace 2 — mapping to status

```go
package httpmap

import (
	"errors"
	"net/http"

	"example.com/app/apperr"
)

func Status(err error) int {
	switch {
	case err == nil:
		return http.StatusOK
	case errors.Is(err, apperr.ErrNotFound):
		return http.StatusNotFound
	case errors.Is(err, apperr.ErrValidation):
		return http.StatusBadRequest
	case errors.Is(err, apperr.ErrUnauthorized):
		return http.StatusUnauthorized
	case errors.Is(err, apperr.ErrForbidden):
		return http.StatusForbidden
	case errors.Is(err, apperr.ErrConflict):
		return http.StatusConflict
	default:
		return http.StatusInternalServerError
	}
}
```

### Trace 3 — log internally, body generic

```go
package httpmap

import (
	"encoding/json"
	"errors"
	"log/slog"
	"net/http"

	"example.com/app/apperr"
)

type publicError struct {
	Code    string `json:"code"`
	Message string `json:"message"`
}

func WriteError(w http.ResponseWriter, r *http.Request, err error) {
	status := Status(err)
	reqID := r.Header.Get("X-Request-ID")

	// INTERNAL: full err + stack policy in slog
	if status >= 500 {
		slog.Error("request failed",
			"err", err,
			"status", status,
			"request_id", reqID,
			"path", r.URL.Path,
			"method", r.Method,
		)
	} else {
		slog.Info("client error",
			"err", err,
			"status", status,
			"request_id", reqID,
			"path", r.URL.Path,
		)
	}

	pub := publicError{Code: codeFor(status), Message: publicMessage(status, err)}
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	_ = json.NewEncoder(w).Encode(pub)
}

func publicMessage(status int, err error) string {
	switch status {
	case http.StatusBadRequest:
		var ve *apperr.ValidationError
		if errors.As(err, &ve) {
			return "invalid request"
		}
		return "bad request"
	case http.StatusNotFound:
		return "resource not found"
	case http.StatusUnauthorized:
		return "unauthorized"
	case http.StatusForbidden:
		return "forbidden"
	case http.StatusConflict:
		return "conflict"
	default:
		// 5xx — NEVER err.Error() to client
		return "internal error"
	}
}

func codeFor(status int) string {
	switch status {
	case 400:
		return "bad_request"
	case 401:
		return "unauthorized"
	case 403:
		return "forbidden"
	case 404:
		return "not_found"
	case 409:
		return "conflict"
	default:
		return "internal"
	}
}
```

### What happens here

- `Status` classifies.
- `slog` gets the real `err` (wrap chain, entity ID).
- JSON to client for 500 is always `"internal error"` — no SQL, no file paths.
- 4xx can be slightly more specific (`not found`), but still without internal detail.

### Trace 4 — not found vs bad request vs internal

```go
package classify

import (
	"encoding/json"
	"errors"
	"net/http"
	"strconv"

	"example.com/app/apperr"
)

func GetUser(w http.ResponseWriter, r *http.Request, load func(id int) (any, error)) {
	id, err := strconv.Atoi(r.PathValue("id"))
	if err != nil {
		// bad input → 400, not 500
		WriteError(w, r, apperr.ErrValidation)
		return
	}
	u, err := load(id)
	if err != nil {
		WriteError(w, r, err) // load already wraps ErrNotFound or internal
		return
	}
	w.Header().Set("Content-Type", "application/json")
	_ = json.NewEncoder(w).Encode(u)
}

// load simulation
func Load(id int) (any, error) {
	if id == 0 {
		return nil, errors.New("sql: connection reset") // BUG if this leaks to client
	}
	if id < 0 {
		return nil, apperr.WrapNotFound("user", strconv.Itoa(id))
	}
	return map[string]int{"id": id}, nil
}
```

Fix for `id==0`: wrap in repository layer as internal, map → 500 + generic body; log sees `connection reset`.

### Trace 5 — dependency: 502 vs 500

```go
package deps

import (
	"context"
	"errors"
	"net/http"
)

var ErrDependency = errors.New("dependency")

func StatusWithDeps(err error) int {
	switch {
	case errors.Is(err, ErrDependency):
		return http.StatusBadGateway
	case errors.Is(err, context.DeadlineExceeded):
		return http.StatusGatewayTimeout
	default:
		return Status(err) // from httpmap
	}
}
```

500 = “our bug / unclassified”. 502/504 = “neighbor”. Alert rules often split these two.

### Trace 6 — handler + errgroup

```go
package handlers

import (
	"context"
	"net/http"

	"golang.org/x/sync/errgroup"
)

func Dashboard(w http.ResponseWriter, r *http.Request, a, b func(ctx context.Context) error) {
	g, ctx := errgroup.WithContext(r.Context())
	g.Go(func() error { return a(ctx) })
	g.Go(func() error { return b(ctx) })
	if err := g.Wait(); err != nil {
		WriteError(w, r, err)
		return
	}
	w.WriteHeader(http.StatusNoContent)
}
```

Error from parallel calls goes through the same map — no special “goroutine status”.

### Trace 7 — do not write body before status in wrong order

```go
// bad: Write then WriteHeader
fmt.Fprint(w, `{`)
w.WriteHeader(500) // too late — status already 200

// good:
w.Header().Set("Content-Type", "application/json")
w.WriteHeader(status)
json.NewEncoder(w).Encode(pub)
```

Once body starts, status is locked in.

### Trace 8 — 404 vs 403 policy

Some systems return **404** instead of **403** for someone else’s resource so existence is not revealed. That is a product/security decision; the map must be **one** and documented. Do not use 403 in one handler and 404 in another for the same case.

### Trace 9 — middleware that catches panic → 500

```go
package mw

import (
	"log/slog"
	"net/http"
	"runtime/debug"
)

func Recover(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				slog.Error("panic", "recover", rec, "stack", string(debug.Stack()))
				http.Error(w, `{"code":"internal","message":"internal error"}`, http.StatusInternalServerError)
			}
		}()
		next.ServeHTTP(w, r)
	})
}
```

Client sees generic 500; log sees stack.

### Trace 10 — map tests

```go
package httpmap_test

import (
	"encoding/json"
	"net/http"
	"net/http/httptest"
	"testing"

	"example.com/app/apperr"
	"example.com/app/httpmap"
)

func TestNotFound(t *testing.T) {
	t.Parallel()
	rr := httptest.NewRecorder()
	req := httptest.NewRequest(http.MethodGet, "/x", nil)
	httpmap.WriteError(rr, req, apperr.WrapNotFound("user", "1"))
	if rr.Code != http.StatusNotFound {
		t.Fatalf("status=%d", rr.Code)
	}
	var body map[string]string
	_ = json.Unmarshal(rr.Body.Bytes(), &body)
	if body["message"] == "" || body["code"] != "not_found" {
		t.Fatalf("body=%v", body)
	}
}

func TestInternalHidesDetail(t *testing.T) {
	t.Parallel()
	rr := httptest.NewRecorder()
	req := httptest.NewRequest(http.MethodGet, "/x", nil)
	httpmap.WriteError(rr, req, errors.New("sql: secret schema"))
	if rr.Code != 500 {
		t.Fatalf("status=%d", rr.Code)
	}
	if strings.Contains(rr.Body.String(), "sql") {
		t.Fatal("internal detail leaked")
	}
}
```

## Rules and syntax

1. Classify with `errors.Is` / `errors.As`, not string contains.
2. `WriteHeader(status)` before JSON encode.
3. 5xx body: fixed message; detail only in log.
4. 4xx: allowed limited detail (validation field), no internal infrastructure IDs.
5. Repository returns wrapped sentinels; handler does not parse SQL.
6. Same `WriteError` for sync and errgroup paths.
7. Do not return `200` with error flag for REST API that uses status.
8. `http.StatusText(code)` is not a substitute for your `code` enum in JSON.

## Examples

### Example A — Predict the result (status)

```go
package main

import (
	"errors"
	"fmt"
	"net/http"
)

var ErrNotFound = errors.New("not found")

func status(err error) int {
	if errors.Is(err, ErrNotFound) {
		return http.StatusNotFound
	}
	return http.StatusInternalServerError
}

func main() {
	fmt.Println(status(fmt.Errorf("user: %w", ErrNotFound)))
	fmt.Println(status(errors.New("disk full")))
}
```

**Answer:**

```
404
500
```

### What happens here

Wrap preserves `ErrNotFound` for `Is`. Unknown error falls through to 500.

### Example B — Predict the result (public message)

```go
package main

import "fmt"

func publicMsg(status int, internal string) string {
	if status >= 500 {
		return "internal error"
	}
	return internal
}

func main() {
	fmt.Println(publicMsg(500, "sql: connection reset"))
	fmt.Println(publicMsg(400, "email required"))
}
```

**Answer:**

```
internal error
email required
```

### What happens here

5xx strips internal string from response; 4xx may pass safe validation text.

### Example C — Predict the result (Atoi)

```go
package main

import (
	"fmt"
	"strconv"

func main() {
	_, err := strconv.Atoi("abc")

```

**Answer:**

### What happens here

### Example D — Predict the result (WriteHeader order)

```go
package main

import (
	"fmt"
	"net/http"
	"net/http/httptest"
)

func main() {
	rr := httptest.NewRecorder()
	fmt.Fprint(rr, "x")
	rr.WriteHeader(http.StatusNotFound)
	fmt.Println(rr.Code)
}
```

**Answer:**

```
200
```

### What happens here

First `Write` implicitly sends 200; later `WriteHeader` does not change status in recorder / real server as you expect. So status goes first.

### Example E — conflict

```go
package main

import (
	"errors"
	"fmt"
	"net/http"
)

var ErrConflict = errors.New("conflict")

func st(err error) int {
	if errors.Is(err, ErrConflict) {
		return http.StatusConflict
	}
	return 500
}

func main() {
	fmt.Println(st(ErrConflict))
}
```

**Answer:**

```
409
```

### What happens here

Version conflict / unique constraint mapped to 409, not 400 and not 500.

## Decision analysis

| Decision | Option | Consequence |
|--------|--------|-----------|
| Unknown err | 500 | safer than guessing 400 |
| Someone else’s resource | 404 or 403 | security policy |
| Dependency timeout | 504 | retry semantics |
| Validation | 400 vs 422 | API consistency |
| Problem+JSON vs {code,message} | team standard | one shape |

## Trade-offs

- Generic 5xx body reduces leakage, makes client debug harder — hence request ID in header/log.
- Rich 4xx detail helps UX but may reveal business rules — keep allowlist of fields.
- Too many sentinels → map grows; too few → everything 500.
- 502 vs 500 requires wrap discipline at client boundary to dependency.

## Common mistakes

1. `http.Error(w, err.Error(), 500)` — leakage.
2. Everything mapped to 500.
3. Validation as 500.
4. Not found as 400 or the reverse.
5. Body before `WriteHeader`.
6. String match instead of `errors.Is`.
7. Different JSON shapes per handler.
8. Logging only status without `err`.
9. 200 + `{error: ...}`.
10. Panic without recover middleware → empty / broken response.

## Idiomatic Go

- Package `apperr` + `httpmap` separate from handler.
- `slog` with `request_id`, `method`, `path`, `err`.
- Tests: table `err → status` + assert 500 body has no “sql”.
- Wrap at repository boundary, not randomly in SQL driver wrapper.
- Same mapper for CLI? No — HTTP map stays in HTTP layer; domain stays clean.

## Practical scenario

Mobile client gets 500 with text `pq: duplicate key`. Users see schema; attacker learns unique indexes. Team introduces `WriteError`, unique → `ErrConflict` → 409, real `pq` goes to slog. At the same time, “user not found” stops being 500 from `sql.ErrNoRows` — repository does `errors.Join` / wrap to `ErrNotFound`. Support tickets drop because client now correctly shows “not found” vs “try again”.

## Summary

HTTP layer maps domain errors to status: 404 for not found, 400 for bad input, 500/502 for internal and dependencies. Log keeps detail; client gets generic body on 5xx. One `WriteError` function keeps API consistent. Next lesson: **closure** — how a function literal captures variables (including `err`) in loops, defer, and middleware factories.

### Additional mechanism — problem details (sketch)

```go
type Problem struct {

	Status   int    `json:"status"`
	Detail   string `json:"detail,omitempty"`
```

For 500, `Detail` stays empty or generic; `Instance` can be request path; `Type` is documentation URI, not stack.

### Additional mechanism — Retry-After header

```go
if status == http.StatusTooManyRequests || status == http.StatusServiceUnavailable {
	w.Header().Set("Retry-After", "30")
}
```

Clients and gateways use this; body still does not leak internal quotas.

### Example G — Forbidden vs NotFound

```go
package main

import (
	"errors"
	"fmt"
	"net/http"
)

var (
	ErrNotFound  = errors.New("not found")
	ErrForbidden = errors.New("forbidden")
)

func st(err error) int {
	switch {
	case errors.Is(err, ErrForbidden):
		return http.StatusForbidden
	case errors.Is(err, ErrNotFound):
		return http.StatusNotFound
	default:
		return 500
	}
}

func main() {
	fmt.Println(st(ErrForbidden), st(ErrNotFound))
}
```

**Answer:**

```
403 404
```

### What happens here

Order in `switch` matters: first more specific / security branches as team agrees. Here forbidden has priority if error ever carried both (rare).

### Extended dependency map

| Dependency error | Status | Retry? |
|-------------------|--------|--------|
| timeout | 504 | yes, with backoff |
| connection refused | 502 | cautiously |
| 429 from upstream | 503/429 | per policy |
| 400 from upstream | 502 or map | not blindly |

Do not forward upstream 400 as your 400 without checking — that mixes your API contract.

### Scenario — mobile offline

Client sees generic 500 and shows “try again”. Request ID in support form leads on-call to slog line with real `err`. Without request ID, status map still helps but forensics take longer.

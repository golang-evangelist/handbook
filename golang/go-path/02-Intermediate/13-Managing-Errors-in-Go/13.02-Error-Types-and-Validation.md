# 13.02 Error types and validation

> **Go Path - Zero to Gopher** / **02 Intermediate → Managing Errors in Go** / Lesson 13.02

## Lesson goals

After this lesson you should:

- use sentinel errors (`var ErrX = errors.New(...)`) for stable outcomes the caller checks with `errors.Is`
- define typed errors (`struct` + method `Error() string`) for richer context and `errors.As`
- wrap errors with `fmt.Errorf("...: %w", err)` so the cause chain stays visible
- understand the difference between `%w` and `%v` and why string comparison breaks the API
- return lists of validation errors per field (UX: multiple problems in one response)
- choose the right error shape for the API boundary (sentinel vs type vs validation list)

## Prerequisite

- lesson 13.01 (error as a value, check immediately, nil interface)
- Go 1.22+ packages `errors` and `fmt`
- basic HTTP/JSON (for validation responses at the boundary)
- you know what `map`, `slice`, and `struct` are

If you have only seen `return errors.New("failed")`, here you learn why that is not enough when the caller must branch behavior.

## Problem this lesson solves

Only `errors.New("failed")` is not enough when the caller must distinguish:

- “not found” → HTTP 404
- “no permission” → 403
- “email invalid” → 422 with a field list
- “version conflict” → 409

Without sentinels and types you are left with brittle string comparison (`err.Error() == "not found"`). A message text change, translation, or wrap prefix — and branching breaks. This lesson builds a spectrum of shapes: sentinel, type, wrap, validation list — and shows when to use which.

## Mental model

1. **Sentinel** — one immutable package value (`var ErrNotFound = errors.New("not found")`) for `errors.Is`.
2. **Type** — `struct` with fields (code, field, ID, cause) for `errors.As`.
3. **Wrap** — adds layer context, keeps the cause via `%w` and `Unwrap`.
4. **Validation list** — multiple problems at once; better UX than fail-fast of one error.
5. **Stability** — public codes and exported sentinels are part of the API contract; do not change them lightly.
6. **Message ≠ code** — the `Error()` string is for humans/logs; the program branches via Is/As/Code.

## Mechanism

### 1. Sentinel errors — what they are and are not

A sentinel is the **same** value every time:

```go
package users

import "errors"

var (
	ErrNotFound = errors.New("user not found")
	ErrConflict = errors.New("user conflict")
)
```

Caller:

```go
if errors.Is(err, users.ErrNotFound) {
	// 404 branch
}
```

**Trace with values**

| Step | What happens | Note |
|-------|---------------|----------|
| package loads | `ErrNotFound` gets an address in memory | one value |
| `return ErrNotFound` | the same value goes out | |
| wrap `fmt.Errorf("get: %w", ErrNotFound)` | new outer error, Unwrap → sentinel | |
| `errors.Is(err, ErrNotFound)` | walks the chain, finds sentinel | true |

**Anti-pattern — “sentinel” in a loop:**

```go
// BAD: every time a NEW value
return errors.New("user not found")
```

`errors.Is` compares by equality / `Is` method. Two `errors.New("user not found")` are not the same value — `Is` returns false between them (unless you compare with the same variable). So the sentinel lives in `var` at package level.

**Even worse anti-pattern:**

```go
return errors.New(fmt.Sprintf("user %s not found", id)) // not a sentinel
```

That is an ordinary dynamic message. For an ID use a typed error.

### 2. Typed error — `struct` + `Error()`

```go
type NotFoundError struct {
	Resource string
	ID       string
}

func (e NotFoundError) Error() string {
	return fmt.Sprintf("%s %s not found", e.Resource, e.ID)
}
```

When to use a type instead of a sentinel?

| Need | Sentinel | Type |
|---------|----------|-----|
| only “which kind of outcome” | yes | can |
| need ID/path in log without parsing the string | no | yes |
| HTTP mapping + fields for JSON | rarely | yes |
| stable small set | yes | optional |

**Pointer vs value:** if the error carries `Unwrap() error` or you want a unique identity, you often return `*NotFoundError`. Be consistent — mixing `NotFoundError` and `*NotFoundError` breaks `errors.As` (see 13.04).

### 3. Wrap with `%w` — cause chain

```go
b, err := os.ReadFile(path)
if err != nil {
	return nil, fmt.Errorf("load avatar: %w", err)
}
```

What the runtime does conceptually:

1. Creates a new error whose `Error()` string includes the formatted text.
2. Sets `Unwrap() error` to return the original `err`.
3. `errors.Is` / `errors.As` walk that chain.

**Trace — concrete values**

Assume `os.ReadFile` returns an error that “contains” `os.ErrNotExist`.

| Layer | error value | Unwrap |
|------|----------------|--------|
| OS/fs | (internal, e.g. `*fs.PathError`) | may lead to `os.ErrNotExist` |
| your wrap | `"load avatar: ..."` | → PathError |
| `errors.Is(err, os.ErrNotExist)` | walks to the sentinel | **true** |

**Difference `%w` vs `%v`:**

```go
fmt.Errorf("x: %w", err) // chain lives
fmt.Errorf("x: %v", err) // string only; Is often does NOT find the inner ones
```

### 4. `errors.Is` — semantic equality through the chain

```go
if errors.Is(err, os.ErrNotExist) { ... }
if errors.Is(err, users.ErrNotFound) { ... }
```

Does not work:

```go
if err == users.ErrNotFound // breaks after wrap
if err.Error() == "user not found" // brittle
```

Is is also a topic of 13.04; here remember: **sentinel + %w + Is** is the basic idiom.

### 5. `errors.As` — extracting a type from the chain

```go
var nf NotFoundError
if errors.As(err, &nf) {
	slog.Info("missing", "id", nf.ID)
}
```

As looks for the first type in the chain that fits the target. Details of a custom `As` method — 13.04.

### 6. Validation list — multiple errors at once

Fail-fast:

```go
if emailInvalid { return fmt.Errorf("email") }
if nameInvalid { return fmt.Errorf("name") } // user never sees this in the same response
```

List:

```go
type FieldError struct {
	Field string
	Code  string
	Msg   string
}

func (f FieldError) Error() string {
	return f.Field + ": " + f.Msg
}

type ValidationError struct {
	Errors []FieldError
}

func (v ValidationError) Error() string {
	return fmt.Sprintf("%d validation errors", len(v.Errors))
}

func (v ValidationError) Unwrap() []error {
	out := make([]error, len(v.Errors))
	for i, fe := range v.Errors {
		out[i] = fe
	}
	return out
}
```

From Go 1.20, `Unwrap() []error` lets `errors.Is` / `errors.As` also look at multiple causes. For the API: encode `Errors` into JSON 422.

**Trace — ValidateEmailName("x", "")**

| Check | Result | Action |
|---------|----------|--------|
| email | no `@` | append FieldError email |
| name | length 0 | append FieldError name |
| end | len=2 | return ValidationError |

One round-trip, both fields marked in the UI.

### 7. When which shape — decision tree

```
Does the caller branch behavior?
  no → ordinary fmt.Errorf / errors.New (local)
  yes → do you need fields (ID, path, code)?
        no → sentinel + Is
        yes → type + As
Does UX need multiple fields at once?
  yes → ValidationError list
Are you raising a layer (repo→service)?
  yes → wrap %w
```

### 8. Exporting and semver

- Exported `ErrNotFound`, `ValidationError`, `Code` strings = public contract.
- Internal `Error()` text may change if Is/As/Code stay.
- Do not export twenty sentinels “just in case” — you lock the API.

### 9. Validation vs authorization vs “not found”

Do not mix into the same type without clarity:

| Outcome | Typical shape | HTTP (preview) |
|-------|---------------|---------------|
| bad input | ValidationError | 422 |
| not found | ErrNotFound / NotFoundError | 404 |
| conflict | ErrConflict | 409 |
| no permission | ErrForbidden | 403 |
| unknown | wrap internally | 500 |

Centralize status mapping later (13.08); here keep clean types.

### 10. Link to the nil-interface rule from 13.01

```go
func Find(...) error {
	var e *NotFoundError
	if !ok {
		e = &NotFoundError{ID: id}
	}
	return e // BUG if !ok is not true — returns typed nil
}
```

Fix:

```go
if !ok {
	return &NotFoundError{ID: id}
}
return nil
```

### 11. Step by step: from raw I/O to API response

1. `os.ReadFile` → raw error  
2. `fmt.Errorf("load avatar: %w", err)` → context  
3. service sees `errors.Is(err, os.ErrNotExist)` → turns into `ErrNotFound` or a type  
4. handler does `errors.As` on ValidationError / Is on sentinel  
5. client gets a JSON code, not an OS string  

Each layer adds semantics; none swallows.

## Rules and syntax

1. Do not compare `err.Error() == "..."`.
2. Sentinels are `var` at package level; not `errors.New` in a loop for the same outcome.
3. Wrap only when you add a layer of context; use `%w`.
4. Validation: collect multiple errors where UX makes sense; otherwise fail-fast is OK.
5. Document which errors the package exports (`// ErrNotFound is returned when...`).
6. Separate `Code` (stable) from `Msg` / `Error()` (may change).
7. Do not mix authz and validation in the same type without a field that distinguishes them.
8. With typed errors be consistent: pointer or value, not both.
9. Test Is/As after wrap (13.05).
10. Public API codes are versioned as part of the contract.

Sentinel template:

```go
var ErrNotFound = errors.New("user not found")
```

Wrap template:

```go
return fmt.Errorf("get user %s: %w", id, err)
```

As template:

```go
var ve ValidationError
if errors.As(err, &ve) { ... }
```

## Examples

### Example 1 — sentinel + Find

```go
package users

import "errors"

var (
	ErrNotFound = errors.New("user not found")
	ErrConflict = errors.New("user conflict")
)

func Find(id string, db map[string]string) (string, error) {
	v, ok := db[id]
	if !ok {
		return "", ErrNotFound
	}
	return v, nil
}
```

### What happens here

`db` is a simple `map` instead of a real store. If the key is missing, the **same** `ErrNotFound` value is returned. The caller does `errors.Is(err, users.ErrNotFound)`. The message is stable enough for Is, not for UI text.

### Predict the result

`Find("u1", map[string]string{})` — what are the return values? Does `errors.Is(err, ErrNotFound)`?

**Answer:** `""`, `ErrNotFound`. Yes — `errors.Is` is true (even without wrap, directly).

---

### Example 2 — typed NotFoundError

```go
package users

import "fmt"

type NotFoundError struct {
	ID string
}

func (e NotFoundError) Error() string {
	return fmt.Sprintf("user %s not found", e.ID)
}

func FindTyped(id string, db map[string]string) (string, error) {
	v, ok := db[id]
	if !ok {
		return "", NotFoundError{ID: id}
	}
	return v, nil
}
```

### What happens here

`errors.As` extracts `ID` for the log without regex over the string. Later you can add an `Is` method (13.04) so the type also behaves like a sentinel.

### Predict the result

After `FindTyped("42", map[string]string{})`, if you do `var n NotFoundError; errors.As(err, &n)`, what is `n.ID`?

**Answer:** `"42"`.

---

### Example 3 — wrap keeps `os.ErrNotExist`

```go
package users

import (
	"fmt"
	"os"
)

func LoadAvatar(path string) ([]byte, error) {
	b, err := os.ReadFile(path)
	if err != nil {
		return nil, fmt.Errorf("load avatar: %w", err)
	}
	return b, nil
}
```

### What happens here

The “load avatar” context helps the log. `errors.Is(err, os.ErrNotExist)` still works through the wrap.

### Predict the result

If you replace `%w` with `%v`, must `errors.Is(err, os.ErrNotExist)` still be true?

**Answer:** Not necessarily — with `%v` the chain is lost; Is typically returns false. That is why `%w` is the rule.

### Example 4 — validation list

```go
package users

import (
	"fmt"
	"strings"
	"unicode/utf8"
)

type FieldError struct {
	Field string
	Code  string
	Msg   string
}

type ValidationError struct {
	Errors []FieldError
}

func (v ValidationError) Error() string {
	return fmt.Sprintf("%d validation errors", len(v.Errors))
}

func (v ValidationError) Unwrap() []error {
	out := make([]error, len(v.Errors))
	for i, fe := range v.Errors {
		out[i] = fe
	}
	return out
}

func (f FieldError) Error() string {
	return f.Field + ": " + f.Msg
}

func ValidateEmailName(email, name string) error {
	var errs []FieldError
	email = strings.TrimSpace(email)
	if email == "" || !strings.Contains(email, "@") {
		errs = append(errs, FieldError{Field: "email", Code: "email_invalid", Msg: "invalid email"})
	}
	if n := utf8.RuneCountInString(name); n < 1 || n > 80 {
		errs = append(errs, FieldError{Field: "name", Code: "name_length", Msg: "invalid name length"})
	}
	if len(errs) > 0 {
		return ValidationError{Errors: errs}
	}
	return nil
}
```

### What happens here

One round-trip returns both errors. The API can encode `ValidationError` into 422 JSON. `Code` is a stable contract for the frontend.

### Predict the result

`ValidateEmailName("x", "")` — how many `FieldError` elements? Which `Code` strings?

**Answer:** 2 elements; `email_invalid` and `name_length`. `Error()` on ValidationError typically `"2 validation errors"`.

### Example 5 — As at the HTTP boundary

```go
package users

import (
	"encoding/json"
	"errors"
	"net/http"
)

func WriteValidate(w http.ResponseWriter, err error) bool {
	var ve ValidationError
	if errors.As(err, &ve) {
		w.Header().Set("Content-Type", "application/json")
		w.WriteHeader(http.StatusUnprocessableEntity)
		_ = json.NewEncoder(w).Encode(ve)
		return true
	}
	return false
}
```

### What happens here

If it is validation — a special 422 response. Otherwise the function returns false and the caller maps further (404/409/500). `_ = Encode` here: if encode fails, rare; in production log that error.

### Predict the result

Input `err = ValidationError{Errors: []FieldError{{Field:"email", Code:"email_invalid", Msg:"invalid email"}}}`. Status code?

**Answer:** 422. Body is JSON with field `Errors` (depends on field export — here they are exported).

### Example 6 — sentinel + wrap in a service

```go
package users

import "fmt"

func GetEmail(id string, db map[string]string) (string, error) {
	v, err := Find(id, db)
	if err != nil {
		return "", fmt.Errorf("get email: %w", err)
	}
	return v, nil
}
```

### What happens here

Outside still `errors.Is(..., ErrNotFound)`. Wrap does not break the sentinel. The message gets prefix `get email:`.

### Predict the result

After `GetEmail("x", map[string]string{})`, is `err == ErrNotFound` true or false? And `errors.Is`?

**Answer:** `err == ErrNotFound` is **false** (wrapped value). `errors.Is(err, ErrNotFound)` is **true**.

### Example 7 — bad “sentinel” every time

```go
package users

import (
	"errors"
	"fmt"
)

func FindBroken(id string, db map[string]string) (string, error) {
	v, ok := db[id]
	if !ok {
		return "", errors.New("user not found") // NEW value
	}
	return v, nil
}

func DemoIsBroken() {
	_, err := FindBroken("x", map[string]string{})
	fmt.Println(errors.Is(err, ErrNotFound)) // false!
}
```

### What happens here

Same message text ≠ same sentinel. Is with package `ErrNotFound` fails.

### Predict the result

Output of `DemoIsBroken`?

**Answer:** `false`.

---

### Example 8 — combining type and wrap

```go
package users

import "fmt"

func GetEmailTyped(id string, db map[string]string) (string, error) {
	v, err := FindTyped(id, db)
	if err != nil {
		return "", fmt.Errorf("get email typed: %w", err)
	}
	return v, nil
}
```

### What happens here

As still finds `NotFoundError` through wrap. Is on a sentinel does **not** work unless the type implements `Is` toward the sentinel (13.04).

### Predict the result

`var n NotFoundError; errors.As(GetEmailTyped(...) err, &n)` — does it work?

**Answer:** Yes, As walks the chain and finds `NotFoundError`.

### Example 9 — decision tree in a handler (skeleton)

```go
package users

import (
	"errors"
	"net/http"
)

func MapErr(w http.ResponseWriter, err error) {
	if err == nil {
		return
	}
	if WriteValidate(w, err) {
		return
	}
	if errors.Is(err, ErrNotFound) {
		http.Error(w, "not found", http.StatusNotFound)
		return
	}
	if errors.Is(err, ErrConflict) {
		http.Error(w, "conflict", http.StatusConflict)
		return
	}
	http.Error(w, "internal error", http.StatusInternalServerError)
}
```

### What happens here

One place for mapping. Default fail closed to 500. Validation has priority if As hit.

### Predict the result

`err = fmt.Errorf("svc: %w", ErrConflict)` — which status?

**Answer:** 409 Conflict.

## Decision analysis

| Decision | Why |
|--------|-------|
| Sentinel | cheap, stable Is; small set of outcomes |
| Type | richer context (ID, path, code) |
| `%w` wrap | cause chain and Is/As through layers |
| Validation list | better UX; fewer round-trips |
| As at the boundary | status mapping and JSON shape |
| Code separate from Msg | semver-stable contract for clients |
| No string compare | messages change; semantics stay |

When **not** to introduce a type: a local helper error that is never branched outside — ordinary `fmt.Errorf` is enough.

## Trade-offs

- Too many exported sentinels lock the API and semver.
- Too many types for tiny things → noise and harder onboarding.
- Validation list vs fail-fast: UX vs brevity and CPU; for CLI fail-fast is often enough.
- Rich messages in `Error()` help the log, but can leak if someone sends them to the client.
- Multi `Unwrap() []error` makes Is “wider” — document what a hit means.

## Common mistakes

1. String compare on `Error()`.
2. Wrap with `%v` instead of `%w` — Is/As break.
3. Returning only the first validation error when UX wants all.
4. `errors.New(fmt.Sprintf(...))` every time as a “sentinel”.
5. Mixing validation and authz in the same type without clarity.
6. Exporting an internal type you change every sprint.
7. Pointer/value chaos for the same error type.
8. Returning typed nil `*ValidationError` (13.01 trap).
9. Parsing ID from the `Error()` string with regex.
10. Changing `Code` strings without an API version.

## Idiomatic Go

- `var ErrX = errors.New("...")` at package level.
- Lowercase error strings; no trailing period.
- `Unwrap() []error` for multi from Go 1.20 when you have a list.
- Tests for Is/As behavior after wrap.
- Comments on exported sentinels.
- JSON tags on FieldError for a stable wire format.
- One `MapErr` / `WriteError` function per HTTP service.

## Practical scenario

The signup endpoint returns only `{"error":"invalid"}`. The frontend does not know whether it is email or name. After introducing `ValidationError` with `Code` per field, the UI marks both. Internal `ErrConflict` on duplicate email maps to 409. Support tickets “I don’t know what is invalid” drop. A month later someone changes the English `Msg` text — tests on `Code` and Is still pass; string tests would fail.

Second case: avatar upload wraps I/O with `%v`. The operator cannot separate “no file” from “permission denied” via Is. Fix to `%w` + metric per `errors.Is` branch.

### Additional trace: what the caller sees after three wraps

```go
err := ErrNotFound
err = fmt.Errorf("repo get %s: %w", "u9", err)
err = fmt.Errorf("service GetEmail: %w", err)
err = fmt.Errorf("http layer: %w", err)
```

`err.Error()` (conceptually) looks like:

```
http layer: service GetEmail: repo get u9: user not found
```

`errors.Is(err, ErrNotFound)` is still true. The log reads the chain as a human; code branches semantically. If every layer adds a 200-character novel, the log becomes unreadable — so context short: operation + key ID.

### Mini exercise — choose the shape

For each outcome write: sentinel / type / list / ordinary fmt.

1. User is not in the database.  
2. Email and phone invalid in the same form.  
3. Disk I/O failed in `LoadAvatar`.  
4. Internal invariant “this enum does not exist” in a private helper.  

**Answer:** (1) sentinel or type with ID; (2) ValidationError list; (3) wrap `%w` around the OS error, maybe mapping to a “not found” sentinel if NotExist; (4) ordinary `fmt.Errorf` or panic if truly impossible (13.03) — do not export.

### Checklist before merging API errors

- [ ] Exported sentinel documented  
- [ ] No `errors.New` in a loop for the same outcome  
- [ ] Wrap uses `%w`  
- [ ] Validation `Code` stable  
- [ ] Test Is/As at least one per public outcome  

## Summary

Sentinel, types, wrap with `%w`, and validation lists give a precise error language. The program branches via `errors.Is` / `errors.As`, not via text. Next lesson: when panic is allowed, how `defer` cleans up, and where `recover` belongs — only at the boundary.

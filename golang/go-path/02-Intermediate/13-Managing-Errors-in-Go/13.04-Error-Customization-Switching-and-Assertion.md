# 13.04 Error customization, Is/As, and assertions

> **Go Path - Zero to Gopher** / **02 Intermediate → Managing Errors in Go** / Lesson 13.04

## Lesson goals

After this lesson you should:

- use `errors.Is` for sentinel and wrap chains instead of `err == ErrX`
- use `errors.As` for typed errors instead of fragile type assertion on the outer type
- understand `errors.Unwrap` and what `%w` sets up under the hood
- implement custom `Is` / `As` methods when a type needs to “represent” a sentinel or another shape
- choose switch/pattern that does not break wrap
- reinforce the nil-interface lesson from 13.01 in the context of custom types and type assertion

## Prerequisite

- lessons 13.02–13.03 (sentinel, types, wrap; panic is not the topic here except at the boundary)
- Go 1.22+ `errors` package
- experience with `fmt.Errorf` and `%w`
- understanding of interface values (type + data) from 13.01

## Problem this lesson solves

After wrap, `err == ErrNotFound` no longer works — the left side is a *new* error object. String compare (`err.Error() == "not found"`) is fragile: wrap prefix, translation, tiny text change. Direct type assertion `err.(*PathError)` sees only the **outer** type, not what is under the wrap.

You need a standard protocol: `errors.Is`, `errors.As`, `Unwrap`. Custom methods let your type participate in that protocol (e.g. `StatusError{Code:404}` behaves like `ErrNotFound` for Is).

## Mental model

1. **Is** — whether the chain contains this sentinel / satisfies this equality (including custom `Is`).
2. **As** — whether the chain contains a type that fits in `*T`; fills the target.
3. **Unwrap** — one step down (`Unwrap() error`) or multi (`Unwrap() []error` since Go 1.20).
4. **Custom Is/As** — your type controls comparison or extraction.
5. **Switch** — on outcomes via Is/As, not on `Error()` text.
6. **Type assertion** — local tool; for wrapped errors prefer As.
7. **Nil reinforcement** — `var e *T; err = e` is still not `err == nil`.

## Mechanism

### 1. What `%w` does exactly

```go
inner := ErrNotFound
outer := fmt.Errorf("service get: %w", inner)
```

Conceptually:

| Property | `outer` |
|----------|---------|
| `Error()` string | includes text + string of inner |
| `Unwrap()` | returns `inner` |
| `outer == ErrNotFound` | **false** |
| `errors.Is(outer, ErrNotFound)` | **true** |

Without `%w` (`%v` or manual string) — no `Unwrap` to inner; Is does not find the sentinel.

**Trace with three layers**

```go
e0 := ErrNotFound
e1 := fmt.Errorf("repo: %w", e0)
e2 := fmt.Errorf("service: %w", e1)
```

| Call | Result |
|------|--------|
| `e2 == ErrNotFound` | false |
| `errors.Unwrap(e2) == e1` | true (same as e1) |
| `errors.Is(e2, ErrNotFound)` | true |
| `errors.Unwrap(errors.Unwrap(e2))` | e0 |

### 2. `errors.Is` algorithm (simplified)

1. If `err == nil` and `target == nil` → true; otherwise if one is nil → false.
2. Walk the chain starting from `err`.
3. For each node: if it implements `Is(target error) bool` and returns true → true.
4. Otherwise if equal to `target` (same type/value by equality rules) → true.
5. Go to `Unwrap()` (or all from `Unwrap() []error`).
6. If chain exhausted → false.

That is why custom `Is` can say: “I represent ErrNotFound”.

### 3. `errors.As` algorithm (simplified)

1. `target` must be a non-nil pointer to a type that can hold an error (e.g. `**PathError` or `*NotFoundError`).
2. Walk the chain.
3. If a node can be assigned into the target → write and return true.
4. If the node has `As(any) bool` and returns true → true.
5. Otherwise Unwrap further.
6. Nothing → false.

**Pointer vs value — critical**

If you put `*PathError` in the chain, the target must be `**PathError` / `var pe *PathError; errors.As(err, &pe)`.
If you put `PathError` (value), the target is `*PathError` value receiver: `var pe PathError; errors.As(err, &pe)`.

Mixing = As does not find. Standardize on pointer for rich types.

### 4. Type assertion vs As

```go
// WEAK after wrap:
if pe, ok := err.(*PathError); ok { ... }

// GOOD:
var pe *PathError
if errors.As(err, &pe) { ... }
```

Type assertion looks at the **dynamic type of the current** interface. Wrap creates a new type (`*fmt.wrapError` or similar) — assert fails even though PathError is below.

### 5. Custom `Is`

```go
type StatusError struct {
	Code int
	Msg  string
}

func (e StatusError) Error() string { return e.Msg }

func (e StatusError) Is(target error) bool {
	if target == ErrNotFound {
		return e.Code == 404
	}
	var t StatusError
	if errors.As(target, &t) {
		return e.Code == t.Code
	}
	return false
}
```

**Trace**

| `e` | `target` | `e.Is(target)` / Is result |
|-----|----------|----------------------------|
| `{404,"x"}` | `ErrNotFound` | true |
| `{404,"x"}` | `{404,"y"}` | true (same code) |
| `{500,"x"}` | `ErrNotFound` | false |

Document the magic. Too “smart” an Is surprises the caller.

### 6. Custom `As` (rarer)

Use when a type wants to be extracted as **another** type (adapter). Most code only needs As on its own type + Unwrap. If you write custom As, cover it with tests.

### 7. Manual Unwrap — when

```go
func Root(err error) error {
	for {
		u := errors.Unwrap(err)
		if u == nil {
			return err
		}
		err = u
	}
}
```

Useful for “root cause type” metrics. For control flow prefer Is/As — they respect custom methods and multi-unwrap.

### 8. Switch with Is

```go
func HTTPStatus(err error) int {
	switch {
	case err == nil:
		return http.StatusOK
	case errors.Is(err, ErrNotFound):
		return http.StatusNotFound
	case errors.Is(err, ErrConflict):
		return http.StatusConflict
	default:
		return http.StatusInternalServerError
	}
}
```

Not:

```go
switch err.(type) { // breaks wrap
```

nor:

```go
switch err.Error() { // fragile
```

### 9. Repeat nil-interface trap (from 13.01)

```go
func maybeErr(ok bool) error {
	var e *StatusError
	if !ok {
		e = &StatusError{Code: 500, Msg: "fail"}
	}
	return e
}
```

When `ok == true`, `return e` returns type `*StatusError` + nil value → `err != nil` is true!

**Fix:**

```go
if !ok {
	return &StatusError{Code: 500, Msg: "fail"}
}
return nil
```

or `var err error` then conditional assignment.

**Type assertion on typed nil:**

```go
err := maybeErr(true) // non-nil interface hiding nil pointer
if err != nil {
	// enters here — surprise
	se := err.(*StatusError) // ok=true, se==nil
	_ = se.Error() // panic on nil receiver if method is not nil-safe
}
```

Therefore: real `nil` interface + As/Is discipline + nil-safe `Error()` or do not return typed nil.

### 10. Multi-error Unwrap

```go
func (v ValidationError) Unwrap() []error { ... }
```

`errors.Is(err, someFieldErr)` can pass through the list. Know that a “hit” means “any of the causes”, not “all”.

### 11. Exported contract

The library should say in documentation:

> We return `ErrNotFound` (possibly wrapped). Use `errors.Is`. Do not compare strings.

That is part of the semver contract of a public module.

### 12. Step-by-step: from repo to HTTP status

1. Repo: `return ErrNotFound`
2. Service: `return fmt.Errorf("get user %s: %w", id, err)`
3. Handler: `errors.Is(err, ErrNotFound)` → 404
4. Log: full `err` value (chain of messages)
5. Test: wrap + Is (13.05)

If step 2 uses `%v`, step 3 breaks.

## Rules and syntax

1. Wrap with `%w` if you want Is/As through the layer.
2. Is for sentinel; As for data in the type.
3. Do not use type assert directly on wrapped err as a substitute for As.
4. Custom Is should be deterministic, cheap, no I/O and no panic.
5. Document behavior of exported types and sentinels.
6. Standardize pointer or value for error types; test As.
7. Switch on `errors.Is` / `errors.As`, not on text.
8. Never return typed nil as `error`.
9. For root-cause metrics you can Unwrap loop; for branching — Is/As.
10. `%v` in wrap = deliberate chain cut (rare; document).

Is:

```go
if errors.Is(err, ErrNotFound) { ... }
```

As:

```go
var pe *PathError
if errors.As(err, &pe) { use(pe.Path) }
```

Unwrap:

```go
inner := errors.Unwrap(err)
```

## Examples

### Example 1 — Is through double wrap

```go
package errswitch

import (
	"errors"
	"fmt"
)

var ErrNotFound = errors.New("not found")

func RepoGet(id string) error {
	return fmt.Errorf("repo get %s: %w", id, ErrNotFound)
}

func ServiceGet(id string) error {
	if err := RepoGet(id); err != nil {
		return fmt.Errorf("service get: %w", err)
	}
	return nil
}

func Handle(err error) string {
	if errors.Is(err, ErrNotFound) {
		return "missing"
	}
	return "other"
}
```

### What happens here

Double wrap; Is still finds the sentinel. `err == ErrNotFound` would be false.

### Predict the result

`Handle(ServiceGet("u1"))` — return value? `ServiceGet("u1") == ErrNotFound`?

**Answer:** `"missing"`. Equality `==` is false; Is inside Handle is true.

---

### Example 2 — As with PathError + Unwrap

```go
package errswitch

import (
	"errors"
	"fmt"
)

type PathError struct {
	Op   string
	Path string
	Err  error
}

func (e *PathError) Error() string {
	return fmt.Sprintf("%s %s: %v", e.Op, e.Path, e.Err)
}

func (e *PathError) Unwrap() error { return e.Err }

func OpenFake(path string) error {
	return &PathError{Op: "open", Path: path, Err: ErrNotFound}
}

func PathOf(err error) (string, bool) {
	var pe *PathError
	if errors.As(err, &pe) {
		return pe.Path, true
	}
	return "", false
}
```

### What happens here

As extracts a pointer to PathError even from an extra wrap. Path goes into the log. Unwrap enables Is on `ErrNotFound`.

### Predict the result

`err := fmt.Errorf("svc: %w", OpenFake("/a")); PathOf(err)` and `errors.Is(err, ErrNotFound)`?

**Answer:** `"/a", true` and Is also true.

### Example 3 — custom Is for StatusError

```go
package errswitch

import "errors"

type StatusError struct {
	Code int
	Msg  string
}

func (e StatusError) Error() string { return e.Msg }

func (e StatusError) Is(target error) bool {
	var t StatusError
	if errors.As(target, &t) {
		return e.Code == t.Code
	}
	if target == ErrNotFound {
		return e.Code == 404
	}
	return false
}
```

### What happens here

StatusError with Code 404 behaves like ErrNotFound for Is. Careful — document it.

### Predict the result

`errors.Is(StatusError{Code:404, Msg:"x"}, ErrNotFound)`?

**Answer:** true.

### Example 4 — switch with Is

```go
package errswitch

import (
	"errors"
	"net/http"
)

func HTTPStatus(err error) int {
	switch {
	case err == nil:
		return http.StatusOK
	case errors.Is(err, ErrNotFound):
		return http.StatusNotFound
	default:
		return http.StatusInternalServerError
	}
}
```

### What happens here

Switch on conditions. Default fail closed to 500.

### Predict the result

`HTTPStatus(fmt.Errorf("x: %w", ErrNotFound))`?

**Answer:** 404.

### Example 5 — manual Root Unwrap

```go
package errswitch

import "errors"

func Root(err error) error {
	for {
		u := errors.Unwrap(err)
		if u == nil {
			return err
		}
		err = u
	}
}
```

### What happens here

Strips layers to the bottom. Prefer Is/As for control flow.

### Predict the result

`Root(fmt.Errorf("a: %w", fmt.Errorf("b: %w", ErrNotFound))) == ErrNotFound`?

**Answer:** true (same sentinel at the bottom).

### Example 6 — wrong type assert

```go
package errswitch

import (
	"fmt"
)

func PreferAs(err error) string {
	// WEAK:
	// if pe, ok := err.(*PathError); ok { return pe.Path }
	// GOOD: errors.As
	var pe *PathError
	if errors.As(err, &pe) {
		return pe.Path
	}
	return fmt.Sprintf("%v", err)
}
```

### What happens here

Direct assert sees only the outer type. As walks the chain.

### Predict the result

`err := fmt.Errorf("w: %w", OpenFake("/z")); pe, ok := err.(*PathError)` — what is `ok`?

**Answer:** `ok == false`. As would succeed.

### Example 7 — nil interface reinforcement

```go
package errswitch

import "fmt"

func BrokenReturn(fail bool) error {
	var e *StatusError
	if fail {
		e = &StatusError{Code: 500, Msg: "fail"}
	}
	return e
}

func FixedReturn(fail bool) error {
	if fail {
		return &StatusError{Code: 500, Msg: "fail"}
	}
	return nil
}

func DemoNil() {
	fmt.Println(BrokenReturn(false) == nil) // false!
	fmt.Println(FixedReturn(false) == nil)  // true
}
```

### What happens here

Same trap as 13.01, now with StatusError. BrokenReturn lies “there is an error”.

### Predict the result

Output of `DemoNil`?

**Answer:**

```
false
true
```

### Example 8 — As target type must match

```go
package errswitch

import (
	"errors"
	"fmt"
)

func AsValueVsPointer() {
	err := OpenFake("/p") // *PathError in chain

	var ptr *PathError
	fmt.Println("as ptr", errors.As(err, &ptr), ptr != nil)

	var val PathError
	fmt.Println("as val", errors.As(err, &val)) // false — chain has *PathError
}
```

### What happens here

As looks for the exact shape. Value target does not accept pointer type from the chain.

### Predict the result

First `as ptr` true; `as val`?

**Answer:** false (unless there is a value copy somewhere in the chain — here there is not).

### Example 9 — `%v` cuts the chain

```go
package errswitch

import (
	"errors"
	"fmt"
)

func WrapV(err error) error {
	return fmt.Errorf("x: %v", err)
}

func WrapW(err error) error {
	return fmt.Errorf("x: %w", err)
}
```

### What happens here

Only W preserves Unwrap.

### Predict the result

`errors.Is(WrapV(ErrNotFound), ErrNotFound)` vs `WrapW`?

**Answer:** false for V; true for W.

### Example 10 — type switch on wrapped (anti-pattern)

```go
package errswitch

func BadSwitch(err error) string {
	switch err.(type) {
	case *PathError:
		return "path"
	default:
		return "other"
	}
}
```

### What happens here

After `fmt.Errorf("%w", pathErr)` you get `"other"`.

### Predict the result

`BadSwitch(fmt.Errorf("z: %w", OpenFake("/q")))`?

**Answer:** `"other"`. With As it would be path.

## Decision analysis

| Decision | Why |
|--------|-------|
| Is | stable sentinel outcomes through wrap |
| As | data from type without parsing string |
| `%w` | preserving the chain |
| Custom Is | semantic mapping (e.g. code→sentinel) |
| Switch + Is | readable status mapping |
| As instead of assert | works after wrap |
| Real nil return | avoids typed nil bug |

## Trade-offs

- Custom Is can surprise if too magical — document and test.
- Deep chains make messages harder to read — balance context (2–3 layers often enough).
- Multi-error Unwrap widens Is — means “any”, not “all”.
- Standardizing on pointer requires team discipline.
- Manual Root Unwrap loses custom Is semantics if you abuse it for branching.

## Common mistakes

1. `err == ErrX` after wrap.
2. `%v` instead of `%w`.
3. Type assert instead of As.
4. String switch on `err.Error()`.
5. Custom Is that does I/O or panics.
6. Mixing pointer/value receiver / As target.
7. Returning typed nil `*T` as error.
8. Relying on `Unwrap` loop instead of Is when custom Is exists.
9. Undocumented custom Is in public API.
10. Test only on `err != nil` without Is/As.

## Idiomatic Go

- Export sentinels you want someone to Is.
- Prefer pointer receivers for rich error types; be consistent.
- Tests: wrap then Is/As (13.05).
- Centralize HTTP mapping in one function.
- Comment on type: “Is reports true for ErrNotFound when Code==404”.
- Do not export `fmt.Errorf` strings as contract.

## Practical scenario

Service wraps driver errors. Old code does `err.Error() == "not found"`. After introducing sentinel + Is, driver refactor does not break handlers. As on `PathError` gives path in log without parsing string. One bug remains: helper returns typed nil; monitoring sees false 500. Fix from 13.01 + test `FixedReturn(false) == nil`.

### Additional trace: Is and sentinel equality

`errors.New` returns a pointer to an internal type. Sentinel equality works because it is the **same** variable / same value in the chain, not because the text is the same.

Therefore:

```go
a := errors.New("x")
b := errors.New("x")
errors.Is(a, b) // false
```

and:

```go
var ErrX = errors.New("x")
errors.Is(fmt.Errorf("w: %w", ErrX), ErrX) // true
```

### Mini exercise — write As test in your head

Chain: `fmt.Errorf("h: %w", &PathError{Path: "/t", Err: ErrNotFound})`.

1. `errors.Is(err, ErrNotFound)` → ?  
2. `var pe *PathError; errors.As(err, &pe); pe.Path` → ?  
3. `err.(*PathError)` → ?

**Answer:** (1) true; (2) `"/t"`; (3) panic or ok=false — does not work on wrapped.

### Repeat type assertion syntax

```go
pe, ok := err.(*PathError) // assert to concrete type
```

vs

```go
var pe *PathError
ok := errors.As(err, &pe) // walks chain
```

Remember: assert is fast and narrow; As is slower by a negligible amount in a handler and **correct** with wrap.

### Table: which tool for which job

| Goal | Tool |
|------|------|
| Is it “not found” | `errors.Is` |
| Need ID/path from error | `errors.As` |
| Strip one layer | `errors.Unwrap` |
| Map HTTP | switch + Is/As |
| Local type without wrap | assert OK, As still fine |

## Summary

`errors.Is`, `errors.As`, and `Unwrap` are the protocol for errors as values through wrap. Custom Is/As extend semantics; type assertion and `==` remain traps. Reinforce nil-interface discipline. Next lesson: how to lock all of this down with tests.

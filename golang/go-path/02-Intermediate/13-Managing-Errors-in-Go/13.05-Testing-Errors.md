# 13.05 Testing errors

> **Go Path - Zero to Gopher** / **02 Intermediate → Managing Errors in Go** / Lesson 13.05

## Lesson goals

After this lesson you should:

- write table-driven tests for error paths as seriously as for the happy path
- use `errors.Is` / `errors.As` in assertions instead of fragile `err.Error()` comparisons
- test wrap behavior: service error still Is-es repo sentinel
- write negative tests (`!errors.Is`) to prevent mixing related sentinels
- cover the security contract: HTTP body does not leak internal details
- use `t.Helper()` helpers and optionally fuzz for anti-panic on validation

## Prerequisite

- lessons 13.02 and 13.04 (sentinel, types, Is/As, wrap)
- `go test`, table tests from Basics/Intermediate
- Go 1.22+
- desirable: `httptest` basics

## Problem this lesson solves

Teams often test only success. Error branches stay dead code until production: wrong HTTP status, lost sentinel after wrap refactor, SQL leaking into body. Coverage “looks green” because the happy path dominates lines.

Table tests for errors catch regressions in validation, status mapping, and wrap/Is behavior — before merge, not after an incident.

## Mental model

1. **Same importance** — error path is a feature, not an “else”.
2. **Table** — case name → input → expected type/sentinel/status/len.
3. **Is/As** — semantic assertion; stable when message changes.
4. **Message** — check `Error()` string only when it is an **explicit** public contract.
5. **Helpers** — `t.Helper()` for readable assertions and correct call-site in fail message.
6. **Negative case** — prove Conflict is not NotFound.
7. **Leak test** — body has no `sql:`, stack, machine path.

## Mechanism

### 1. Shape of table test for errors

```go
tests := []struct {
	name    string
	in      Input
	wantErr error // sentinel for Is; or nil
	wantAs  bool  // expect ValidationError
	wantLen int   // number of field errors
}{ ... }

for _, tc := range tests {
	t.Run(tc.name, func(t *testing.T) {
		err := Call(tc.in)
		// assertions
	})
}
```

**Why `t.Run`:** isolated fail by name; parallelization later; readable CI log.

### 2. Semantic assertion — Is

```go
if !errors.Is(err, users.ErrNotFound) {
	t.Fatalf("got %#v want Is(ErrNotFound)", err)
}
```

`%#v` shows type — useful when you get wrap or typed nil.

**Trace — wrap regression**

| Change in production | String test | Is test |
|----------------------|-------------|---------|
| wrap message “get → fetch” | may fail | passes |
| `%w` → `%v` | may pass | **fails** (good!) |
| new message language | fails | passes |

Is tests preserve semantics; catch chain cutting.

### 3. Semantic assertion — As

```go
var ve users.ValidationError
if !errors.As(err, &ve) {
	t.Fatalf("got %T %v", err, err)
}
if len(ve.Errors) != tc.wantLen {
	t.Fatalf("len=%d want %d", len(ve.Errors), tc.wantLen)
}
```

Also check `Code` per field when that is the contract:

```go
if ve.Errors[0].Code != "email_invalid" { ... }
```

### 4. Helper with `t.Helper`

```go
func MustIs(t *testing.T, err, target error) {
	t.Helper()
	if !errors.Is(err, target) {
		t.Fatalf("got %#v want Is(%#v)", err, target)
	}
}
```

Without `t.Helper()`, fail shows the line inside the helper — you lose call-site.

### 5. Happy + error in same table

```go
{"ok", validIn, nil, 0},
{"bad_email", badEmail, nil /*as*/, 1},
```

For ok case: `if err != nil { t.Fatal }`.
For error case: Is/As + details.
Do not write separate tests just because one is “success” — the table documents the input space.

### 6. Negative Is

```go
err := fmt.Errorf("x: %w", users.ErrConflict)
if errors.Is(err, users.ErrNotFound) {
	t.Fatal("false positive")
}
```

Prevents accidentally `return ErrNotFound` everywhere or overly broad custom Is.

### 7. HTTP + httptest without leaking

```go
req := httptest.NewRequest(http.MethodGet, "/", nil)
rr := httptest.NewRecorder()
h.ServeHTTP(rr, req)
if rr.Code != 503 { ... }
if strings.Contains(rr.Body.String(), "sql:") {
	t.Fatal("leaked sql")
}
```

Extend forbidden substring list: `panic:`, `goroutine `, `C:\\`, `/home/`, `password`.

### 8. Typed nil regression (tie-in with 13.01/13.04)

```go
func TestFixedReturnNil(t *testing.T) {
	if FixedReturn(false) != nil {
		t.Fatal("want nil interface")
	}
}
```

Simple test; expensive in production if missing.

### 9. Fuzz — anti-panic, not table replacement

```go
func FuzzValidateEmailName(f *testing.F) {
	f.Add("a@b.com", "Ana")
	f.Add("", "")
	f.Fuzz(func(t *testing.T, email, name string) {
		_ = users.ValidateEmailName(email, name) // must not panic
	})
}
```

Fuzz does not prove exact `Code` values — table proves that. Fuzz hunts crash.

### 10. Parallel and isolation

```go
t.Parallel()
```

Only if case does not share global `map`, file, port. Otherwise flaky. For error tests often not needed — correctness first.

### 11. Coverage lies — what to look at

`go test -cover` can be 80%+ while no Is branch is hit correctly. In PR checklist:

- new sentinel → Is test
- new type → As test
- new wrap layer → Is through layer
- new HTTP code → status + anti-leak

### 12. Black-box `foo_test` package

```go
package users_test
```

Tests exported API as external user — exactly what HTTP layer does with Is on exported sentinels. White-box `package users` when testing unexported helper.

### 13. Step-by-step writing first error test

1. Pick a function that returns `error`.
2. Write case `ok` and one `want ErrNotFound`.
3. Run — fails if implementation still string-compares in handler.
4. Add wrap layer in production; test still passes if `%w`.
5. Add negative Conflict case.
6. Add HTTP anti-leak if boundary is public.

## Rules and syntax

1. Name cases clearly: `empty_email`, `wrap_not_found`, `conflict_not_notfound`.
2. Prefer Is/As over string; string only for documented contract.
3. Test wrap: Service error Is on Repo sentinel.
4. Negative tests for false positive.
5. Parallelize only with isolated state.
6. `t.Helper()` in every assert helper.
7. Do not snapshot whole error strings with local path.
8. Anti-leak list of forbidden substrings.
9. Typed nil: `want err == nil` where function claims success.
10. CI: `go test ./...` mandatory; fuzz in nightly job optional.

MustIs template:

```go
func MustIs(t *testing.T, err, target error) {
	t.Helper()
	if !errors.Is(err, target) {
		t.Fatalf("got %#v want Is(%#v)", err, target)
	}
}
```

## Examples

### Example 1 — table for validation

```go
package users_test

import (
	"errors"
	"testing"

	"example.com/shop/users"
)

func TestValidateEmailName(t *testing.T) {
	tests := []struct {
		name    string
		email   string
		uname   string
		wantLen int
	}{
		{"ok", "a@b.com", "Ana", 0},
		{"bad_email", "x", "Ana", 1},
		{"bad_name", "a@b.com", "", 1},
		{"both", "x", "", 2},
	}
	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			err := users.ValidateEmailName(tc.email, tc.uname)
			if tc.wantLen == 0 {
				if err != nil {
					t.Fatalf("err=%v", err)
				}
				return
			}
			var ve users.ValidationError
			if !errors.As(err, &ve) {
				t.Fatalf("got %T %v", err, err)
			}
			if len(ve.Errors) != tc.wantLen {
				t.Fatalf("len=%d want %d", len(ve.Errors), tc.wantLen)
			}
		})
	}
}
```

### What happens here

Four cases cover boundaries. As confirms type. Number of field errors is the contract.

### Predict the result

Case `both` — `wantLen`? Is `err == nil`?

**Answer:** `wantLen=2`; `err != nil`; As succeeds.

### Example 2 — Is after wrap

```go
package users_test

import (
	"errors"
	"testing"

	"example.com/shop/users"
)

func TestGetEmailNotFound(t *testing.T) {
	_, err := users.GetEmail("missing", map[string]string{})
	if !errors.Is(err, users.ErrNotFound) {
		t.Fatalf("got %v", err)
	}
}
```

### What happens here

Service wrap must not hide sentinel. This test locks that contract.

### Predict the result

If someone changes wrap to `%v`, what does this test do?

**Answer:** Fails — Is no longer finds ErrNotFound. That is desired protection.

### Example 3 — helper package

```go
package testutil

import (
	"errors"
	"testing"
)

func MustIs(t *testing.T, err, target error) {
	t.Helper()
	if !errors.Is(err, target) {
		t.Fatalf("got %#v want Is(%#v)", err, target)
	}
}

func MustNoErr(t *testing.T, err error) {
	t.Helper()
	if err != nil {
		t.Fatalf("unexpected err: %v", err)
	}
}

func MustAs[T any](t *testing.T, err error) T {
	t.Helper()
	var want T
	if !errors.As(err, &want) {
		t.Fatalf("got %T %v want As %T", err, err, want)
	}
	return want
}
```

### What happens here

Less boilerplate. `t.Helper` shows call-site line. Generic MustAs (Go 1.18+) reduces copy-paste.

### Predict the result

Fail in `MustIs` — which line does `go test` report as fail: inside MustIs or in TestXxx?

**Answer:** the call line in TestXxx, thanks to `t.Helper()`.

### Example 4 — HTTP anti-leak

```go
package api_test

import (
	"net/http"
	"net/http/httptest"
	"strings"
	"testing"
)

func TestInternalDoesNotLeak(t *testing.T) {
	h := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		http.Error(w, "unavailable", http.StatusServiceUnavailable)
	})
	req := httptest.NewRequest(http.MethodGet, "/", nil)
	rr := httptest.NewRecorder()
	h.ServeHTTP(rr, req)
	if rr.Code != 503 {
		t.Fatalf("status=%d", rr.Code)
	}
	body := rr.Body.String()
	for _, leak := range []string{"sql:", "panic:", "goroutine "} {
		if strings.Contains(body, leak) {
			t.Fatalf("leaked %q in %q", leak, body)
		}
	}
}
```

### What happens here

Security contract from 10.14 becomes a test. Prevents future `Write([]byte(err.Error()))`.

### Predict the result

If handler does `http.Error(w, err.Error(), 500)` where err contains `sql:`, what does the test catch?

**Answer:** Fatal with `leaked "sql:"`.

### Example 5 — negative Is

```go
package users_test

import (
	"errors"
	"fmt"
	"testing"

	"example.com/shop/users"
)

func TestConflictIsNotNotFound(t *testing.T) {
	err := fmt.Errorf("x: %w", users.ErrConflict)
	if errors.Is(err, users.ErrNotFound) {
		t.Fatal("false positive")
	}
}
```

### What happens here

Preserves sentinel semantics. Useful with custom Is that could be too broad.

### Predict the result

Does wrap change negative test result (with correct sentinels)?

**Answer:** No — Is still distinguishes Conflict from NotFound.

package users_test

import (

If `ValidateEmailName` does `panic` on emoji name, what does fuzz do?

### Example 7 — typed nil regression

```go
package errswitch_test

import "testing"

func TestBrokenVsFixedNil(t *testing.T) {
	// assume FixedReturn / BrokenReturn from 13.04
	if FixedReturn(false) != nil {
		t.Fatal("fixed must return nil interface")
	}
	if BrokenReturn(false) == nil {
		t.Fatal("broken example unexpectedly nil — demo changed?")
	}
}
```

### What happens here

Documents the trap. In production code test only the correct function: `want == nil`.

### Predict the result

Which call must pass in production package?

**Answer:** `FixedReturn(false) == nil` (or equivalent of your function).

### Example 8 — table for HTTP status mapping

```go
package api_test

import (
	"fmt"
	"net/http"
	"testing"

	"example.com/shop/users"
)

func TestHTTPStatus(t *testing.T) {
	tests := []struct {
		name string
		err  error
		code int
	}{
		{"nil", nil, http.StatusOK},
		{"not_found", users.ErrNotFound, http.StatusNotFound},
		{"wrapped_not_found", fmt.Errorf("svc: %w", users.ErrNotFound), http.StatusNotFound},
		{"other", fmt.Errorf("nope"), http.StatusInternalServerError},
	}
	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			got := HTTPStatus(tc.err) // function from production
			if got != tc.code {
				t.Fatalf("got %d want %d", got, tc.code)
			}
		})
	}
}
```

### What happens here

Status mapping is contract. Wrapped case is mandatory — without it `%w` refactor stays unprotected.

### Predict the result

Without case `wrapped_not_found`, which regression passes unnoticed?

**Answer:** replacing `%w` → `%v` or `err == ErrNotFound` in mapping implementation.

### Example 9 — check Code in ValidationError

```go
package users_test

import (
	"errors"
	"testing"

	"example.com/shop/users"
)

func TestEmailCode(t *testing.T) {
	err := users.ValidateEmailName("x", "Ana")
	var ve users.ValidationError
	if !errors.As(err, &ve) {
		t.Fatalf("got %v", err)
	}
	if len(ve.Errors) != 1 || ve.Errors[0].Code != "email_invalid" {
		t.Fatalf("codes=%v", ve.Errors)
	}
}
```

### What happens here

Frontend depends on `Code`, not English `Msg`. Test locks wire contract.

### Predict the result

Change `Msg` to “Email is not valid” — does this test fail?

**Answer:** No. Fails only if `Code` changes.

---

### Example 10 — anti-pattern string snapshot

```go
// WEAK:
if err.Error() != "open /home/ci/project/file: no such file" {
	t.Fatal(err)
}
```

### What happens here

Machine path and OS text break CI. Replace with Is on `os.ErrNotExist` + As on `*fs.PathError` if Path field needed.

### Predict the result

Why does test pass locally and fail in CI (or vice versa)?

**Answer:** different paths / OS messages in `Error()` string.

## Decision analysis

| Decision | Why |
|--------|-------|
| Table tests | boundary coverage, documentation |
| Is/As assertions | semantic stability |
| Helper + t.Helper | readability and correct fail line |
| Leak test | API security |
| Negative Is | prevents mixing sentinels |
| Fuzz | anti-panic on input |
| Wrapped case in table | preserves `%w` contract |
| Code instead of Msg | stable wire format |

## Trade-offs

- String assertions on messages are fragile — use only for public contract.
- Too many cases without clear names → unmaintainable; group by function.
- Parallel tests require isolation — flaky costs more than sequential.
- Fuzz consumes CPU; keep in scheduled job if CI budget is tight.
- Generic MustAs requires Go 1.18+ (here 1.22+ OK).

## Common mistakes

1. Test only `err == nil` happy path.
2. `if err.Error() != "not found"`.
3. No test after introducing wrap.
4. Shared global state with `t.Parallel`.
5. Ignoring As type (only `err != nil`).
6. Snapshot of whole error string with machine path.
7. Helper without `t.Helper()`.
8. No negative Is — custom Is becomes too broad unnoticed.
9. Coverage satisfaction without PR checklist for error branches.
10. Fuzz as only validation test — no table for Code.

## Idiomatic Go

- `t.Run` per case; clear names.
- Clear messages in `Fatalf` with got/want.
- Test packages `foo_test` for black-box where needed.
- CI runs `go test ./...`.
- Shared `testutil.MustIs` in larger repos.
- PR checklist: sentinel / type / wrap / HTTP.

## Practical scenario

Refactor changes wrap message; UI string test breaks, Is test does not. Team moves to Is/As. Later validation gets third field — table catches `wantLen`. A month later someone in handler does `w.Write([]byte(err.Error()))` — anti-leak test in CI blocks merge. Fewer regressions in release; on-call fewer false 500 from typed nil thanks to `TestFixedReturnNil`.

### Additional trace: how CI shows table fail

When `t.Run("wrapped_not_found", ...)` fails, output looks like:

```
--- FAIL: TestHTTPStatus (0.00s)
    --- FAIL: TestHTTPStatus/wrapped_not_found (0.00s)
        status_test.go:42: got 500 want 404
```

Case name immediately says what broke. Without `t.Run`, you only see iteration number — that is why names are not decoration.

### Mini exercise — write assertions

Function `Login` returns `ErrNotFound` or `ErrForbidden` (wrapped). Write two `t.Run` skeletons (without full file) that lock both.

**Answer (skeleton):**

```go
t.Run("missing", func(t *testing.T) {
	_, err := Login("nope", "x")
	MustIs(t, err, ErrNotFound)
})
t.Run("forbidden", func(t *testing.T) {
	_, err := Login("bob", "bad")
	MustIs(t, err, ErrForbidden)
})
```

### What to measure besides coverage

- Number of tests that call `errors.Is` / `errors.As`  
- Existence of at least one HTTP anti-leak test on public 5xx boundaries  
- Whether new sentinel in PR has test in same PR  

### Refactor guide

When you change error message for log readability — tests **must not** fail. If they fail, they were string-based: replace with Is/As before or during refactor.

### Quick self-check

1. Does your last PR have at least one error-path test?  
2. Does HTTP 5xx branch have anti-leak check?  
3. Does wrap layer have Is test through layer?

If answer is “no” to any — add before next feature branch. Error testing discipline is cheaper than a night incident.

### What you carry into 13.06

In the next lesson errors move into the concurrent world: channel, multiple goroutines, who “wins” when several workers report failure. Is/As and table habits from this lesson stay — transport changes.

### One sentence for PR description

“Add error-path tests (Is/As + wrap + anti-leak where needed) in the same PR as error behavior change.”

Paste into team checklist. Reduces “we’ll add tests later” debate.

### Last reminder

Happy path without error test is not a finished feature. If you do not know which sentinel or type to expect — document error API first, then write handler. Without that Is/As tests have no contract to fail against.

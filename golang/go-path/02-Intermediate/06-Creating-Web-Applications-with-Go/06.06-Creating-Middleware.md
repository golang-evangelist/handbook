# 06.06 Creating middleware: Handler chain

> **Go Path - Zero to Gopher** / **02 Intermediate → Creating Web Applications with Go** / Lesson 06.06

## Lesson goals

After this lesson you should be able to:

- write middleware as `func(http.Handler) http.Handler`
- compose a **chain** (logging, recover, request ID) and understand “onion” order
- understand that calling `next` is **optional** — short-circuit (e.g. 401) without entering the handler
- use `recover` in middleware so a panic does not crash the process uncontrollably
- log status via a `statusWriter` wrapper around `http.ResponseWriter`
- pass a request ID through `context` and the response header
- use a `chain` helper and middleware on a mux **subgroup**
- test panic and the chain with `httptest`

## Prerequisite

- 06.01 (chain concept), 06.03 (context values caution)
- `http.Handler` / `HandlerFunc`
- basic `defer` and `panic` / `recover`

## Problem this lesson solves

Without middleware every handler repeats:

```go
log.Println(r.Method, r.URL.Path)
defer func() {
	if rec := recover(); rec != nil { /* ... */ }
}()
```

That breaks DRY, gets forgotten on new routes, and the order “log then auth then handler” becomes inconsistent. Middleware centralizes **cross-cutting** concerns: log, panic, correlation, later auth.

Instead of copy-paste `defer` in every handler, you wrap the mux once (or a route subtree) and all routes share the same behavior.

## Mental model

Middleware is a **higher-order** function: it takes `http.Handler`, returns `http.Handler`. Visually — an **onion** around the next handler:

```text
request → log → recover → requestID → mux/handler → ... back through the layers
```

Each layer can:

- do something **before** `next.ServeHTTP`
- **not** call `next` (short-circuit) — e.g. 401, 403, 429
- do something **after** `next` (duration measurement, status log)

Wrapping order: the first wrapper is the outermost.

```go
handler = withLog(withRecover(withReqID(mux)))
```

Here `withLog` sees the request first and logs last (after the inner layers).

```text
withLog                ← outside
  withRecover
    withRequestID
      mux / handler    ← inside
```

## Mechanism

The longest part: signature, onion order, short-circuit, `statusWriter`, recover, request ID, `chain`, mux subgroup, `httptest` traces.

### Signature — higher-order Handler

```go
func Middleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// before
		next.ServeHTTP(w, r)
		// after
	})
}
```

- Input: `next` — the rest of the chain.
- Output: a new `http.Handler` that optionally calls `next`.
- Idiom: `type Middleware func(http.Handler) http.Handler`

### next is optional — short-circuit

```go
func withAuth(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.Header.Get("X-Token") != "demo" {
			http.Error(w, "forbidden", http.StatusUnauthorized)
			return // deliberately WITHOUT next.ServeHTTP
		}
		next.ServeHTTP(w, r)
	})
}
```

If you do not call `next`, the inner handler **does not run**. That is correct for auth, rate limit, maintenance mode. The mistake is forgetting `next` when you meant to let the request through — routes look “dead”.

### Onion and order

```go
var h http.Handler = mux
h = withRequestID(h)
h = withRecover(h)
h = withLog(h)
```

Equivalent:

```go
h := withLog(withRecover(withRequestID(mux)))
```

**Inbound (request) trace:**

1. Enters `withLog` (before).
2. Enters `withRecover` (before, sets `defer recover`).
3. Enters `withRequestID` (before, fills context).
4. Mux picks a handler; handler runs.
5. Return through request ID → recover → log (after: duration, status).

**Panic trace:**

1. Handler does `panic`.
2. `withRecover` `defer` catches; log + 500.
3. `withLog` can still log status/duration — depending on whether the wrapper was passed through and whether header/status was set.

Document the order choice in one sentence in the code.

### statusWriter — logging the status code

`http.ResponseWriter` does not expose status after `WriteHeader` in a way convenient for an access log. Wrapper:

```go
type statusWriter struct {
	http.ResponseWriter
	code int
}

func (w *statusWriter) WriteHeader(statusCode int) {
	w.code = statusCode
	w.ResponseWriter.WriteHeader(statusCode)
}
```

Use in log middleware:

```go
sw := &statusWriter{ResponseWriter: w, code: http.StatusOK}
next.ServeHTTP(sw, r)
log.Printf("%s %s %d %s", r.Method, r.URL.Path, sw.code, time.Since(start))
```

Default `code: 200` covers the case when the handler only writes a body without an explicit `WriteHeader` (net/http treats that as 200).

Note: a full wrapper sometimes also overrides `Write` (the first `Write` implicitly sends 200). For this lesson, tracking `WriteHeader` is a sufficient start; in production check flush/hijack needs.

### Recover middleware

```go
func withRecover(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				log.Printf("recover: %v\n%s", rec, debug.Stack())
				http.Error(w, "internal error", http.StatusInternalServerError)
			}
		}()
		next.ServeHTTP(w, r)
	})
}
```

- `recover` works **only** in `defer` in the same goroutine where the panic happened.
- The client gets 500 instead of a dropped connection with no body.
- If the response has already started, `http.Error` can be problematic — advanced recover tracks whether `WriteHeader` was already called (via a wrapper).

Do not swallow a panic without a log. Do not use panic as flow control instead of `return`.

### Request ID and context

```go
type ctxKey int

const keyRID ctxKey = 1

func withRequestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id := r.Header.Get("X-Request-ID")
		if id == "" {
			id = strconv.FormatInt(time.Now().UnixNano(), 36)
		}
		ctx := context.WithValue(r.Context(), keyRID, id)
		w.Header().Set("X-Request-ID", id)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

func rid(ctx context.Context) string {
	s, _ := ctx.Value(keyRID).(string)
	return s
}
```

- Respect an incoming ID behind a proxy; otherwise generate.
- Same ID in the response (support) and in context (log in the handler).
- Private key type (`ctxKey`) — not string keys (package collision).

### chain helper

Manual nesting becomes unreadable. Helper:

```go
type Middleware func(http.Handler) http.Handler

func chain(h http.Handler, mws ...Middleware) http.Handler {
	for i := len(mws) - 1; i >= 0; i-- {
		h = mws[i](h)
	}
	return h
}

// first in the list = outermost layer
h := chain(mux, withLog, withRecover, withRequestID)
```

The loop goes **backward** so the argument order reads left→right as onion outside→inside.

**chain call trace:**

1. Start: `h = mux`.
2. `i` on the last mw: `h = withRequestID(mux)`.
3. Middle: `h = withRecover(h)`.
4. First: `h = withLog(h)`.
5. Result: log(recover(requestID(mux))).

### Mux subgroup

Auth does not have to cover the whole site:

```go
api := http.NewServeMux()
api.HandleFunc("GET /api/items", listItems)
api.HandleFunc("GET /api/items/{id}", getItem)
var apiH http.Handler = withAuth(api)

root := http.NewServeMux()
root.Handle("/api/", apiH) // or Go 1.22+ patterns as needed
root.HandleFunc("GET /{$}", home)
root.HandleFunc("GET /health", health)

var h http.Handler = chain(root, withLog, withRecover, withRequestID)
```

- `/health` stays public (LB checks).
- `/api/...` goes through `withAuth`.
- The global trio still sees every request.

### httptest — panic test

```go
func TestRecover(t *testing.T) {
	h := withRecover(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		panic("x")
	}))
	rec := httptest.NewRecorder()
	req := httptest.NewRequest(http.MethodGet, "/", nil)
	h.ServeHTTP(rec, req)
	if rec.Code != http.StatusInternalServerError {
		t.Fatalf("code=%d", rec.Code)
	}
}
```

**Test trace:**

1. `NewRecorder` captures status/body without a network.
2. `ServeHTTP` enters `withRecover`.
3. Inner handler panics.
4. `defer recover` catches → `http.Error` → status 500.
5. Assert on `rec.Code`.

Additional tests: request ID roundtrip (incoming header → outgoing); auth short-circuit without calling next (spy handler).

### Logging middleware — complete skeleton

```go
func withLog(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		sw := &statusWriter{ResponseWriter: w, code: http.StatusOK}
		next.ServeHTTP(sw, r)
		log.Printf("%s %s %d %s rid=%s",
			r.Method, r.URL.Path, sw.code, time.Since(start), rid(r.Context()))
	})
}
```

Watch: if `withRequestID` sits **inside** log, `r.Context()` on the log line *after* `next` needs to be the one with the ID — so either read the ID from the response header, or save `id` locally, or ensure the `r` that log uses has context (often you log from the `r` passed into next; context on that outer `r` variable does not change — that is why request ID middleware does `r.WithContext` only for the inside). Practically: log `sw` status and duration; read the ID from the value request ID middleware puts on the response header, or pass context deliberately.

A cleaner pattern: request ID middleware closest to the mux; log after next reads `w.Header().Get("X-Request-ID")` if the ID was set before next, or:

```go
id := rid(r.Context()) // if ID middleware is outside — reverse the order
```

Recommendation for this lesson: `chain(mux, withLog, withRecover, withRequestID)` and in the log after next use the header:

```go
log.Printf("... rid=%s", w.Header().Get("X-Request-ID"))
```

because request ID middleware sets it on `w` before calling next.

### What to log (and what not)

Log: method, path, status, duration, request ID.

Do not log: passwords, full form bodies, cookie values, tokens. An access log is not a request dump.

### Middleware and timeout

If middleware runs long *before* `next` (slow auth check against an external service), that enters latency and the `WriteTimeout`/`ReadHeaderTimeout` story. Prefer a fast local check on the hot path; bound external calls with a `context` deadline.

### Short-circuit auth trace

1. Request without `X-Token`.
2. `withAuth` writes 401, `return`.
3. `listItems` is **not** called.
4. Outer `withLog` still sees status if `statusWriter` was passed through auth — so auth should use the same `w` (wrapper) from log.

### Happy-path GET / trace

1. Log: start, wrap writer.
2. Recover: defer armed.
3. Request ID: generate/take, context, header.
4. `ok` handler writes body + ID from context.
5. Return; log: 200 + duration.

### Why the chain loop goes backward — proof

You want the API:

```go
chain(mux, A, B, C) == A(B(C(mux)))
```

If the loop goes from `0` upward:

```go
h = A(mux); h = B(h); h = C(h)  // → C(B(A(mux)))  WRONG
```

From the end:

```go
h = C(mux); h = B(h); h = A(h)  // → A(B(C(mux)))  CORRECT
```

That is why `for i := len(mws) - 1; i >= 0; i--`. Document that in a comment next to `chain` — otherwise someone “fixes” the loop and inverts the onion.

### Context values — caution reminder

Request ID in context is **operational** metadata, not a substitute for auth. Do not put whole user structs in context without team agreement (06.03). The key must be an unexported type in your package:

```go
type ctxKey int
const keyRID ctxKey = 1
```

String `"request_id"` as a key risks colliding with another package that uses the same string.

### Flusher / Hijacker note

A minimal `statusWriter` holds the inner `http.ResponseWriter` via **struct embedding** (official Go term; do not confuse with the `embed` package). Methods that are not overridden are forwarded. If inner code does an `http.Flusher` type assert on `w`, a wrapper without an extra method can break SSE/stream. For an access log on ordinary HTML/JSON routes that rarely hurts; for streaming routes extend the wrapper or isolate them outside the log wrapper.

### Trace: double WriteHeader

1. Handler calls `WriteHeader(404)`.
2. `statusWriter` stores `code=404` and forwards.
3. Later someone calls `WriteHeader(500)` again — net/http ignores the second call; your wrapper must decide whether it overwrites the local `code`.
4. The simple lesson wrapper overwrites the `code` field even when the inner writer ignores — it can lie in the log. More advanced: remember `wroteHeader bool` and do not change `code` after the first time.

For a start the simple wrapper is enough, with awareness of the limitation.

### Where the code lives

```text
internal/middleware/
  chain.go      // Middleware type, chain()
  log.go        // withLog, statusWriter
  recover.go    // withRecover
  requestid.go  // withRequestID, rid()
  auth.go       // withAuthToken (optional)
```

Tests alongside: `recover_test.go`, `requestid_test.go`. Handlers do not import implementation details — only the finished `http.Handler` from `chain`.

## Rules and syntax

- Always call `next` **except** when you deliberately break the chain.
- Do not swallow a panic without a log and (optionally) a metric.
- Private key type for context.
- Keep middleware thin; business rules in the handler/service.
- Test the chain with `httptest` (panic → 500; ID roundtrip; auth short-circuit).
- Do not put auth on `/health` if the LB depends on a public health check.
- Go 1.22+ mux patterns still apply inside the wrapped handler.

### Example 1: Logging + duration

```go
func withLog(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		start := time.Now()
		sw := &statusWriter{ResponseWriter: w, code: http.StatusOK}

```

#### What happens here

- Before: record start, wrap writer.
- After: log with status.
- Default 200 covers “Write only”.

### Example 2: Recover middleware

```go
import "runtime/debug"

func withRecover(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				log.Printf("recover: %v\n%s", rec, debug.Stack())
				http.Error(w, "internal error", http.StatusInternalServerError)
			}
		}()
		next.ServeHTTP(w, r)
	})
}
```

#### What happens here

- A panic in the handler does not crash the whole process (it is caught in this goroutine).
- Stack goes to the log.
- Client gets 500.

### Example 4: Assembling the chain and panic for demo

```go
func boom(w http.ResponseWriter, r *http.Request) {
	panic("boom")
}

func ok(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintf(w, "ok rid=%s\n", rid(r.Context()))
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /{$}", ok)
	mux.HandleFunc("GET /boom", boom)

	h := chain(mux, withLog, withRecover, withRequestID)

	srv := &http.Server{
		Addr:              ":8080",
		Handler:           h,
		ReadHeaderTimeout: 5 * time.Second,
	}
	log.Fatal(srv.ListenAndServe())
}
```

#### What happens here

- `/boom` → recover → 500; process lives.
- `/` prints request ID from context.
- Log sees method, path, status, duration.

#### GET /boom trace

1. Log start.
2. Recover defer.
3. Request ID set.
4. `boom` panics.
5. Recover → 500 + stack log.
6. Log line with status (ideal case with wrapper).

### Example 5: Middleware only on a route subset

```go
func withAuthToken(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.Header.Get("X-Token") != "demo" {
			http.Error(w, "forbidden", http.StatusUnauthorized)
			return
		}
		next.ServeHTTP(w, r)
	})
}

func mount() http.Handler {
	api := http.NewServeMux()
	api.HandleFunc("GET /api/items", listItems)
	apiH := withAuthToken(api)

	root := http.NewServeMux()
	root.Handle("GET /api/", apiH)
	root.HandleFunc("GET /{$}", home)
	root.HandleFunc("GET /health", func(w http.ResponseWriter, r *http.Request) {
		io.WriteString(w, "ok")
	})

	return chain(root, withLog, withRecover, withRequestID)
}
```

#### What happens here

- Auth does not burden public HTML or health.
- Composition of muxes + middleware on a subtree.
- Same pattern later in framework groups.

### Example 6: httptest panic + ID roundtrip

```go
func TestRecover(t *testing.T) {
	h := withRecover(http.HandlerFunc(func(http.ResponseWriter, *http.Request) {
		panic("x")
	}))
	rec := httptest.NewRecorder()
	req := httptest.NewRequest(http.MethodGet, "/", nil)
	h.ServeHTTP(rec, req)
	if rec.Code != http.StatusInternalServerError {
		t.Fatalf("code=%d", rec.Code)
	}
}

func TestRequestIDRoundTrip(t *testing.T) {
	h := withRequestID(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if rid(r.Context()) != "abc-123" {
			t.Fatalf("ctx id=%q", rid(r.Context()))
		}
		w.WriteHeader(http.StatusNoContent)
	}))
	rec := httptest.NewRecorder()
	req := httptest.NewRequest(http.MethodGet, "/", nil)
	req.Header.Set("X-Request-ID", "abc-123")
	h.ServeHTTP(rec, req)
	if got := rec.Header().Get("X-Request-ID"); got != "abc-123" {
		t.Fatalf("header=%q", got)
	}
}
```

#### What happens here

- Panic → 500 without a live server.
- Incoming ID is respected and returned.

### Example 7: Spy short-circuit

```go
func TestAuthShortCircuit(t *testing.T) {
	called := false
	inner := http.HandlerFunc(func(http.ResponseWriter, *http.Request) {
		called = true
	})
	h := withAuthToken(inner)
	rec := httptest.NewRecorder()
	req := httptest.NewRequest(http.MethodGet, "/api/items", nil)
	h.ServeHTTP(rec, req)
	if called {
		t.Fatal("next must not be called")
	}
	if rec.Code != http.StatusUnauthorized {
		t.Fatalf("code=%d", rec.Code)
	}
}
```

#### What happens here

- Without a token `next` is not called — proof of short-circuit.
- Status 401.

## Decision analysis

| Decision | Choice | Why |
|----------|--------|-----|
| Recover globally | yes for HTTP server | resilience |
| Auth globally | often no | public `/health`, static |
| Request ID | yes | ops / support |
| Fat middleware | no | hard to test |
| Status wrapper | yes for access log | otherwise always 200 in the log |
| `chain` helper | yes | readable order |
| httptest | yes | panic and short-circuit without a port |

## Trade-offs

- **Recover** — process lives; a bug can stay hidden if there is no alarm on 500/panic log.
- **Outer log** — sees everything; also measures auth errors.
- **Many layers** — clear separation; negligible cost versus I/O.
- **Generating ID in app** vs proxy — pick one source of truth.
- **Minimal statusWriter** — simple; does not cover every `ResponseWriter` interface method (Hijacker, Flusher) until you explicitly forward them.

## Common mistakes

1. Forgotten `next.ServeHTTP` — routes “dead”.
2. `recover` outside `defer` — does not catch.
3. Auth middleware on `/health` — LB thinks the instance is dead.
4. Log without status wrapper — always 200 in the access log.
5. String keys in context — collisions.
6. Panic as flow control instead of `return`.
7. recover/log order without understanding what you measure.
8. Swallowing panic without log/stack.
9. Fat middleware with business logic — untestable.
10. Testing panic only manually on a live server instead of `httptest`.

## Idiomatic Go

- Type: `type Middleware func(http.Handler) http.Handler`
- Helper `chain(h, mids ...Middleware) http.Handler`
- Package `internal/middleware`
- Test: panic handler + expect 500; ID header roundtrip; auth short-circuit
- Go 1.22+ `ServeMux` patterns inside the wrapped tree
- Thin middleware; fat handler/service

### Middleware and WriteTimeout

If middleware runs long *before* `next` (e.g. slow auth check against an external service), count that in latency and timeouts. Prefer a fast local token check on the hot path; bound external calls with a context deadline.

### When not to call next — reminder

| Situation | next? |
|-----------|-------|
| Auth fail | no (401/403) |
| Maintenance | no (503) |
| All OK | yes |
| Log-only wrapper | yes (always) |
| Recover wrapper | yes (always; catches afterward) |

## Practical scenario

API without recover: one nil pointer in a rare branch crashes a pod in Kubernetes (depending on settings). After `withRecover` + metric `panics_total`, the team sees a spike and fixes the root cause.

Request ID saves support: the user sends the ID from the response, logs are found in 10 seconds instead of 10 minutes.

Later they add auth on the whole mux and `GET /health` starts returning 401 — LB ejects pods. They move auth only onto `/api/`. Health stays public. Chain: `chain(root, withLog, withRecover, withRequestID)` and the API subtree additionally `withAuth`.

QA introduces `TestRecover` and `TestAuthShortCircuit` in CI — regressions of “forgotten next” and “recover outside defer” are caught before merge.

The access log always showed 200 until they introduced `statusWriter` — a false sense of health. After the wrapper they see real 4xx/5xx rates.

- Middleware = `func(http.Handler) http.Handler`; an onion chain solves cross-cutting concerns.
- `next` is optional — short-circuit is a valid tool.
- Logging + `statusWriter`, recover, request ID are the basic trio; `chain` makes order readable.
- Mux subgroup for auth; `httptest` for panic and roundtrip tests.
- Next: handler + DB in the same request scope.

### Brief order overview (visual)

```text
withLog             ← sees the request first, logs after
  withRecover       ← catches panic from inside
    withRequestID   ← fills context before the handler
      mux           ← routes
```

If you invert recover and log, a panicking request can still be logged — but watch what you measure as duration. Document the choice in the code in one sentence.

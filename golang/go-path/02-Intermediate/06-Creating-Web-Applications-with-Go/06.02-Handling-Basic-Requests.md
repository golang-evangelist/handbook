# 06.02 Handling basic requests: routes, static files, redirects

> **Go Path - Zero to Gopher** / **02 Intermediate → Creating Web Applications with Go** / Lesson 06.02

## Lesson goals

After this lesson you should be able to:

- register routes on `http.ServeMux` using Go 1.22+ patterns (HTTP method + path)
- understand the difference between exact match, prefix, `{$}` end, and `{id}` wildcard
- read path parameters via `r.PathValue`
- serve **static files** via `http.FileServer` and `http.StripPrefix`
- do **HTTP redirects** (`http.Redirect`, status 301/302/303/307/308) consciously
- apply **PRG** (Post/Redirect/Get) after forms
- avoid open redirect with an allow-list (defensively)
- manage **trailing slash** consistently

## Prerequisite

- Lesson 06.01 (handler, lifecycle, `http.Server`, `ReadHeaderTimeout`, middleware as a higher-order function)
- Go 1.22+ because of the improved `ServeMux`
- basic HTML/CSS files for the exercise (e.g. `static/app.css`)

## Problem this lesson solves

A beginner web server quickly becomes chaos:

- all routes on `/` with manual `if r.URL.Path != "/"`
- CSS “does not work” because the path is `/static/app.css` while FileServer expects a different prefix
- `http.Redirect` to a user-supplied URL without a check (open redirect)
- old `ServeMux` that treats `/images/` as a prefix in an unexpected way
- `/about` and `/about/` as two different “pages” in analytics
- a POST form that repeats on refresh (no PRG)

The lesson teaches the **basic traffic** of a web application: where each path goes, how static content lives next to dynamic handlers, how to redirect the client safely, and how `PathValue` replaces manual URL slicing.

## Mental model

`ServeMux` is a **distribution board**:

1. A request arrives with an HTTP method and path.
2. The mux chooses the **most specific** pattern that matches (in 1.22+ with clear rules).
3. The handler for that route does the work — or FileServer reads a file from disk.
4. A redirect is not “magic”: it is a response with a `Location` header and a 3xx status; the client then sends a **new** request.

```text
  request: METHOD + PATH
       │
       ▼
  ┌────────────┐     match           ┌──────────────────┐
  │  ServeMux  │ ──────────────────► │ Handler / FS     │
  └────────────┘                     └──────────────────┘
       │ no match
       ▼
     404 (Not Found)
```

Static files are still HTTP responses. FileServer is a Handler that maps a URL path to a path in the file system. Your responsibility is the **prefix map** (`/static/` → `./static/`) and what is allowed to be read.

Wildcard `{id}` is not “regex magic” in the handler — the mux extracts the segment and you read it with `PathValue("id")`.

## Mechanism

### ServeMux in Go 1.22+ — patterns

Patterns can include an HTTP method:

```text
GET /page
GET /page/{$}
POST /login
GET /item/{id}
GET /files/{path...}
/images/          # any HTTP method, prefix (with mux rules)
```

Important syntax parts:

| Part | Meaning | Match example |
|------|---------|---------------|
| `{$}` | end of path | `GET /{$}` → only `/` |
| `{name}` | one segment | `GET /item/{id}` → `/item/42` |
| `{name...}` | rest of path | `GET /files/{path...}` → `/files/a/b` |
| ends with `/` | prefix style | depends on mux rules |

Older code often does:

```go
mux.HandleFunc("/", home) // catches a lot
```

Better: explicit HTTP methods and `{$}` where exactness is needed.

#### Trace — `{$}` versus `/`

```text
Registered: GET /{$} → home

GET /        → matches → home
GET /about   → does NOT match /{$}
GET /index   → does NOT match /{$}
POST /       → does NOT match (HTTP method is not GET)
```

#### Trace — `{id}`

```text
Registered: GET /item/{id} → item

GET /item/42
  mux match
  PathValue("id") = "42"
  item handler prints "item 42"

GET /item/42/edit
  does NOT match {id} (more segments) → 404 unless another pattern

GET /item/
  does NOT match (empty segment usually not)
```

**Predict, then answer:** What does `r.PathValue("id")` return if the handler was *not* matched via a pattern with `{id}`?

Answer: Empty string (`""`). PathValue is not magic for any URL — it is filled from the matched pattern.

**Predict, then answer:** Does `GET /item/{id}` match `POST /item/42`?

Answer: No. The HTTP method is part of the pattern. POST goes to another route or 404.

### PathValue

```go
func item(w http.ResponseWriter, r *http.Request) {
	id := r.PathValue("id")
	fmt.Fprintf(w, "item %s\n", id)
}
```

Validation is still on you: `PathValue` returns a string from the URL — check the format (UUID, number) before putting it into SQL.

#### Mini checklist after PathValue

```text
1) id := r.PathValue("id")
2) if id == "" → 404/400 (unexpected for a matched pattern)
3) validate alphabet / length / parse UUID|int
4) only then service layer / DB
5) never concatenate id directly into a SQL string — use a placeholder
```

**Predict, then answer:** Does an empty `PathValue` mean the mux did not match the pattern?

Answer: Often yes — or you missed the name (`"ID"` vs `"id"`). Names must match `{id}` in the pattern exactly.

#### Trace — validation

```text
GET /item/42     → id="42"   → OK if you expect digits
GET /item/abc    → id="abc"  → your handler decides: 400 or 404
GET /item/../../ → mux/FS rules; do NOT blindly trust the path for the filesystem
```

**Predict, then answer:** Why not use `strings.Split(r.URL.Path, "/")` instead of PathValue in new code?

Answer: The mux already parses by pattern; PathValue is aligned with registration, fewer off-by-one mistakes, clearer contract.

### Prefixes and FileServer + StripPrefix

```go
fs := http.FileServer(http.Dir("static"))
mux.Handle("GET /static/", http.StripPrefix("/static/", fs))
```

- `http.Dir("static")` — root on disk
- `StripPrefix` strips `/static/` so FileServer looks for `app.css`, not wrongly `static/app.css` inside Dir
- Without StripPrefix, paths do not match and you get 404

#### Trace — with StripPrefix

```text
Disk:  static/app.css

Request: GET /static/app.css
  1) mux matches GET /static/
  2) StripPrefix("/static/") → path FS sees: "app.css"
  3) Dir("static") + "app.css" → static/app.css
  4) 200 + CSS body
```

#### Trace — without StripPrefix (classic)

```text
Request: GET /static/app.css
  1) mux → FileServer directly
  2) FS looks for relative path "static/app.css" INSIDE Dir("static")
  3) real path: static/static/app.css
  4) 404
```

**Predict, then answer:** What if you do `http.Dir(".")` and `Handle("GET /files/", ...)` without strict control?

Answer: Risk of reading too many files from the working directory (sources, `.env`). Keep Dir narrow (`static`), not the whole project.

**Predict, then answer:** Does FileServer automatically forbid directory listing?

Answer: Not always — if there is no `index.html`, the default FileServer may list the directory. In production limit content, use a custom Handler, or CDN/proxy.

### Redirects — 301/302/303/307/308

```go
http.Redirect(w, r, "/login", http.StatusSeeOther) // 303
```

`Redirect` sets `Location` and status. The client then sends a **new** request to that location.

| Code | Constant | Typical purpose | HTTP method after redirect |
|------|----------|-----------------|----------------------------|
| 301 | `StatusMovedPermanently` | Permanent URL change | often GET (cache!) |
| 302 | `StatusFound` | Temporary (historically loose) | often GET |
| 303 | `StatusSeeOther` | After POST go to GET (PRG) | GET |
| 307 | `StatusTemporaryRedirect` | Temporary, keep HTTP method | same HTTP method |
| 308 | `StatusPermanentRedirect` | Permanent, keep HTTP method | same HTTP method |

#### Trace — 303 PRG

```text
1) Browser: POST /contact  (form body)
2) Server:  303 Location: /contact/thanks
3) Browser: GET /contact/thanks
4) User presses Refresh
5) Browser: GET /contact/thanks  (does NOT repeat POST)
```

#### Trace — 307 after POST

```text
1) POST /old-endpoint
2) 307 Location: /new-endpoint
3) Browser: POST /new-endpoint  (same HTTP method + body, per spec)
```

**Predict, then answer:** Why for PRG do you choose 303 and not 301?

Answer: 301 is “permanent” and is cached aggressively; PRG needs “after this POST go to a GET page”, not an SEO/permanent move. 303 explicitly says See Other → GET.

**Predict, then answer:** What if after `Redirect` you still do `fmt.Fprintln(w, "ok")`?

Answer: Do not treat the redirect response body as a 200 page. `Redirect` already writes a short body; an extra write confuses. End the handler after Redirect.

### PRG (Post/Redirect/Get)

Pattern:

1. `GET` shows the form
2. `POST` processes data (validation, write)
3. Success → `303` to a `GET` result/thank-you page
4. Refresh does not resubmit the form

#### Trace — without PRG

```text
POST /subscribe → 200 HTML "thanks"
Refresh → browser asks "submit form again?" → duplicate write
```

**Predict, then answer:** Where do you write to the database — in POST or in GET after the redirect?

Answer: In POST (before the redirect). GET after that only shows the result. GET should be safe to refresh.

### Open redirect — allow-list (defensive)

Never do:

```go
// DANGEROUS: the user controls Location
http.Redirect(w, r, r.URL.Query().Get("next"), http.StatusSeeOther)
```

Because `?next=https://evil.example` can lead the victim to a fake site after login.

Defensive pattern — **allow-list** of internal paths:

```go
var allowedNext = map[string]bool{
	"/dashboard": true,
	"/profile":   true,
}

func safeNext(raw string) string {
	if allowedNext[raw] {
		return raw
	}
	return "/dashboard"
}
```

#### Trace — open redirect cut off

```text
Login OK, ?next=/dashboard     → allow → Location: /dashboard
Login OK, ?next=/profile       → allow → Location: /profile
Login OK, ?next=https://evil   → rejected → Location: /dashboard
Login OK, ?next=//evil.example → rejected (not in the map)
```

**Predict, then answer:** Is it enough to check `strings.HasPrefix(next, "/")`?

Answer: Not reliably. `//evil.example` starts with `/` and the browser may treat it as a scheme-relative URL. An allow-list of exact paths is clearer defense. (Extra path checks are possible, but allow-list is the simplest lesson.)

### Trailing slash

`/about` and `/about/` are **not** automatically the same routes in the Go 1.22+ mux if you do not define them that way.

Strategies:

1. **One canonical path** + redirect from the other
2. Explicitly register both (rare)
3. Prefix resources (`/static/`) for FileServer; dynamic routes outside that prefix

#### Trace — canonical slash

```text
Registered:
  GET /about      → about
  GET /about/{$}  → 301 → /about

GET /about/  → 301 Location: /about → GET /about → 200
GET /about   → 200 directly
```

**Predict, then answer:** Why does analytics “break” without a slash policy?

Answer: The same content on two paths is counted as two pages. Redirect + canonical URL merges metrics.

## Rules and syntax

### Registration

```go
mux := http.NewServeMux()
mux.HandleFunc("GET /{$}", home)
mux.HandleFunc("GET /about", about)
mux.HandleFunc("POST /login", loginPost)
mux.HandleFunc("GET /item/{id}", itemByID)
mux.Handle("GET /static/", http.StripPrefix("/static/", fs))
```

### PathValue — continued

```go
id := r.PathValue("id")
```

### FileServer without directory listing (caution)

The default FileServer may list a directory if there is no `index.html`. For production often:

- keep only needed files
- or a custom Handler that rejects directories
- or CDN / reverse proxy for static

### Redirect

- Always use **relative** paths you control (`/dashboard`), not raw `r.FormValue("next")` without an allow-list
- After `Redirect`, do not build an extra “200 HTML” body
- Choose status consciously: PRG → 303; permanent move → 301/308 with cache awareness

### Method not allowed vs 404

When a pattern has an HTTP method (`GET /x`), the wrong HTTP method will not match that pattern. The client may get 404 instead of 405 — depending on other patterns. For an HTML site 404 is often acceptable; for an API consider an explicit 405.

## Examples

### Example 1: Exact root, about, and path parameter

```go
package main

import (
	"fmt"
	"log"
	"net/http"
	"time"
)

func home(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "home")
}

func about(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "about us")
}

func item(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintf(w, "item %s\n", r.PathValue("id"))
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /{$}", home)
	mux.HandleFunc("GET /about", about)
	mux.HandleFunc("GET /item/{id}", item)

	srv := &http.Server{
		Addr:              ":8080",
		Handler:           mux,
		ReadHeaderTimeout: 5 * time.Second,
	}
	log.Fatal(srv.ListenAndServe())
}
```

#### What happens here

- `GET /` does not catch `/about` because of `{$}`.
- `/item/42` fills `PathValue("id")` with `"42"`.
- HTTP methods are part of the pattern: `POST /about` does not enter the `about` handler.

#### Trace

```text
GET /           → home → "home"
GET /about      → about → "about us"
GET /item/7     → item → PathValue id="7" → "item 7"
GET /item/7/x   → 404
POST /item/7    → 404 (no POST pattern)
```

**Predict, then answer:** Does `GET /` match a handler registered as `GET /about`?

Answer: No.

### Example 2: FileServer with StripPrefix

Structure:

```text
static/
  app.css
  logo.png
```

```go
func mountStatic(mux *http.ServeMux) {
	fs := http.FileServer(http.Dir("static"))
	mux.Handle("GET /static/", http.StripPrefix("/static/", fs))
}
```

HTML:

```html
<link rel="stylesheet" href="/static/app.css">
```

#### Trace

```text
GET /static/app.css
  StripPrefix → "app.css"
  open static/app.css → 200 text/css

GET /static/missing.css
  → 404

Forgotten StripPrefix:
  looks for static/static/app.css → 404
```

**Predict, then answer:** Do you need `StripPrefix` if you mount FileServer on `/` with `Dir("static")`?

Answer: If the URL is exactly `/app.css` mapped to `static/app.css`, strip for `/static/` is not needed — but then static “eats” the root space. Prefix `/static/` + StripPrefix is clearer for an app with dynamic routes.

### Example 3: PRG redirect after POST

```go
func showForm(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/html; charset=utf-8")
	fmt.Fprint(w, `<form method="POST" action="/contact"><button>Send</button></form>`)
}

func postContact(w http.ResponseWriter, r *http.Request) {
	// ... form processing ...
	http.Redirect(w, r, "/contact/thanks", http.StatusSeeOther)
}

func thanks(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, "thanks")
}

func mount(mux *http.ServeMux) {
	mux.HandleFunc("GET /contact", showForm)
	mux.HandleFunc("POST /contact", postContact)
	mux.HandleFunc("GET /contact/thanks", thanks)
}
```

#### Trace

```text
GET /contact        → HTML form
POST /contact       → 303 Location: /contact/thanks
GET /contact/thanks  → "thanks"
Refresh             → GET /contact/thanks again
```

**Predict, then answer:** Which status do you use instead of `StatusSeeOther` if you want to keep the POST HTTP method on the new URL (rare for forms)?

Answer: 307 or 308. For HTML forms after success you almost always want GET → 303.

### Example 4: Safe redirect (allow-list)

```go
var allowedNext = map[string]bool{
	"/dashboard": true,
	"/profile":   true,
}

func loginOK(w http.ResponseWriter, r *http.Request) {
	next := r.URL.Query().Get("next")
	if !allowedNext[next] {
		next = "/dashboard"
	}
	http.Redirect(w, r, next, http.StatusSeeOther)
}
```

#### Trace

```text
?next=/profile           → /profile
?next=/dashboard         → /dashboard
?next=https://phish.test → /dashboard
?next=                  → /dashboard
```

**Predict, then answer:** Why a `bool` map instead of `switch`?

Answer: Both work; a map grows more easily when you have more allowed targets and can be loaded from configuration. What matters is the *allow-list policy*, not the collection type.

### Example 5: Trailing slash redirect

```go
func mountAbout(mux *http.ServeMux) {
	mux.HandleFunc("GET /about", about)
	mux.HandleFunc("GET /about/{$}", func(w http.ResponseWriter, r *http.Request) {
		http.Redirect(w, r, "/about", http.StatusMovedPermanently)
	})
}
```

#### Trace

```text
GET /about/  → 301 Location: /about
GET /about   → 200 about handler
```

**Predict, then answer:** Why 301 here, and not 303?

Answer: This is a canonical resource path (permanent URL correction), not PRG after POST. 301/308 are for “this path forever lives there”. Caution: a wrong 301 is hard to “uncache”.

### Example 6: {path...} remainder

```go
mux.HandleFunc("GET /docs/{path...}", func(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, r.PathValue("path"))
})
```

#### Trace

```text
GET /docs/a        → path="a"
GET /docs/a/b/c    → path="a/b/c"
GET /docs/         → depends on matching; test explicitly
```

Use carefully with filesystem mapping — always clean / validate before `os.Open`.

### Example 7: 301 cache trap

```go
// temporary marketing campaign — BAD status choice:
http.Redirect(w, r, "/promo-v2", http.StatusMovedPermanently) // 301

// while the URL is not stable — better:
http.Redirect(w, r, "/promo-v2", http.StatusFound) // 302
// later, when it is forever canonical:
// http.Redirect(..., http.StatusMovedPermanently)
```

#### Trace

```text
Day 1: 301 /action → /promo-wrong  (error in Location)
Browser/proxy caches 301 aggressively
Day 2: you fix the server to /promo-correct
Client WITH CACHE still goes to /promo-wrong
```

**Predict, then answer:** When is 308 better than 301?

Answer: When you must keep the original HTTP method (e.g. POST stays POST). For ordinary GET pages the difference is smaller; for API migrations 308 can be more precise.

### Example 8: Test PathValue and HTTP method with httptest

```go
func TestItem(t *testing.T) {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /item/{id}", item)

	req := httptest.NewRequest(http.MethodGet, "/item/9", nil)
	rr := httptest.NewRecorder()
	mux.ServeHTTP(rr, req)

	if rr.Code != 200 {
		t.Fatalf("code=%d", rr.Code)
	}
	if !strings.Contains(rr.Body.String(), "9") {
		t.Fatalf("body=%q", rr.Body.String())
	}

	bad := httptest.NewRequest(http.MethodPost, "/item/9", nil)
	rr2 := httptest.NewRecorder()
	mux.ServeHTTP(rr2, bad)
	if rr2.Code != 404 {
		t.Fatalf("POST should not match GET pattern, got %d", rr2.Code)
	}
}
```

#### Trace

```text
GET /item/9  → 200, PathValue id="9"
POST /item/9 → 404 (no POST pattern)
```

**Predict, then answer:** Why test POST if you “will never send POST”?

Answer: Regression — someone later adds a broad pattern or removes the HTTP method from the pattern. The test documents the contract.

### Example 9: StripPrefix + wrong Dir

```go
// BAD: Dir is parent, URL assumes static/
fs := http.FileServer(http.Dir("."))
mux.Handle("GET /static/", http.StripPrefix("/static/", fs))
// GET /static/../go.mod → depends on path cleaning; design risk
```

#### Trace — safer mount contract

```text
Dir("static") + StripPrefix("/static/")
  URL space: only under /static/
  disk space: only under static/
  ../ attempts break against Dir root (FileServer/Dir clean the path)
Still: do not serve secret files *inside* static/
```

**Predict, then answer:** Does path cleaning mean you may keep `.env` in `static/`?

Answer: No. What is in the Dir root can be read if the URL hits the name. Do not put secrets in the static folder.

## Decision analysis

| Decision | Recommendation | Reason |
|----------|----------------|--------|
| HTTP method in the pattern | Yes (1.22+) | Fewer manual checks |
| Everything on `/` | No | Hard maintenance, collisions |
| `{$}` for root | Yes | Exact `/` without swallowing everything |
| PathValue vs Split | PathValue | Contract with the mux pattern |
| Static in the same process | OK for small/medium app | CDN later if scale needed |
| 302 for PRG | Prefer 303 | Clear “go to GET” |
| Redirect to query param | Allow-list only | Open redirect |
| Trailing slash | One canonical + redirect | Clean metrics and cache |

## Trade-offs

- **FileServer from the process** — simple; spends workers on I/O. For large traffic CDN/nginx is better.
- **Strict patterns** — more registration lines, fewer surprises.
- **301** — aggressive client/proxy cache; a wrong 301 is hard to “uncache”.
- **Directory listing** — handy in development, risky in production.
- **Allow-list next** — safest; less flexible than “any internal path”.
- **308 vs 301** — 308 keeps the HTTP method; for GET pages often no practical difference.

## Common mistakes

1. Forgotten `StripPrefix` with FileServer.
2. `Handle("/", ...)` that “eats” other routes (depending on pattern and rules).
3. Mixing `http.Dir(".")` with an overly wide root (file leakage outside `static/`).
4. Open redirect via `next` / `returnUrl`.
5. Writing an HTML body with a redirect instead of a clean 3xx flow.
6. Expecting `GET /page` to match `GET /page/` without an explicit pattern or redirect.
7. Serving `.go` sources or `.env` because Dir is too wide.
8. PRG with 302 “because everyone does that” instead of a conscious 303.
9. `PathValue` without validation inserted into a database query.
10. Mixing `{$}` and prefix routes while static and dynamic paths collide.

## Idiomatic Go

- Local `mux := http.NewServeMux()` in `main` / `NewServer()`.
- Group mount functions: `routes(mux)`, `static(mux)`.
- For trailing slash: either explicit routes, or one redirect handler — be consistent.
- In tests use `httptest.NewRecorder` and paths exactly as in production.
- Do not use `http.DefaultServeMux` in library packages.
- Keep the allow-list for external “next” targets next to auth/login code, not scattered across handlers.

## More on trailing slash and prefixes

Browsers and users often mix `/about` and `/about/`. In the Go 1.22+ mux those are **not** automatically the same routes if you do not define them that way. Strategies:

1. **Only one canonical path** — register `GET /about` and add `GET /about/` → 301/308 to `/about`.
2. **Explicitly both** — if you truly want both (rare).
3. **Prefix resources** — `GET /assets/` for FileServer; keep dynamic routes outside that prefix.

Canonical slash example:

```go
mux.HandleFunc("GET /about/{$}", func(w http.ResponseWriter, r *http.Request) {
	http.Redirect(w, r, "/about", http.StatusMovedPermanently)
})
mux.HandleFunc("GET /about", about)
```

For static files also check **mime type**: `FileServer` uses `mime.TypeByExtension`. An unknown extension may get a generic type — then set the type manually in a custom Handler or rename the file.

### http.NotFound and your own 404 page

```go
mux.HandleFunc("/", func(w http.ResponseWriter, r *http.Request) {
	http.NotFound(w, r)
})
```

Better for a web app: HTML 404 template (later) or:

```go
func notFound(w http.ResponseWriter, r *http.Request) {
	w.WriteHeader(http.StatusNotFound)
	fmt.Fprintln(w, "page does not exist")
}
```

In Go 1.22+ you can register a catch-all carefully; do not let it “eat” the static prefix.

### Method not allowed

When a pattern has an HTTP method (`GET /x`), the wrong HTTP method will not match that pattern. The client may get 404 instead of 405 — depending on what else exists on the mux. If you need a strict 405, explicitly register other HTTP methods or use a small wrapper that checks the HTTP method. For an HTML site 404 is often acceptable; for an API consider 405.

#### Trace — 404 instead of 405

```text
Registered only: GET /about

POST /about → no match → 404
(not necessarily 405 Method Not Allowed)
```

**Predict, then answer:** How do you get 405 on purpose?

Answer: Register `POST /about` (or all HTTP methods) on a handler that returns 405, or middleware/wrapper that knows allowed HTTP methods for that path.

## Practical scenario

The shop “Cup & Bread” (demo e-shop) has HTML pages and a `static/` folder. The designer reports that CSS works locally when they open the file, but not through the server.

**Cause:** `mux.Handle("/static/", http.FileServer(http.Dir("static")))` without `StripPrefix`. After the fix, marketing wants the old URL `/action` → new `/promo`. The team puts 301. A week later they realize they cached the wrong target — next time they use 302 until the URL is stable, then 301.

**Special incident:** login `?next=` leads to an external site. They introduce an allow-list of internal paths. Lesson for the team: router + static + redirect are the “boring” parts — but that is where the first security and UX bugs appear.

**Third incident:** mobile clients cache `/about/` (with slash) while the canonical is `/about`. Analytics splits into two paths. They introduce a slash redirect and `rel=canonical` in HTML. After a week metrics merge.

**Fourth incident:** `GET /product/{id}` without validation — `id` with unexpected characters ends up in logs and brittle queries. They introduce a strict check before using `PathValue` in the service layer.

## Summary

- Go 1.22+ `ServeMux` patterns with HTTP method and `{$}` / `{name}` give predictable routing; `PathValue` reads segments.
- Static content goes through `FileServer` + careful `StripPrefix`.
- Redirects are 3xx + `Location`; PRG uses 303; filter user targets with an allow-list.
- Trailing slash and prefixes need an explicit policy.
- Basic traffic (routes, static, redirect) must be correct before templates and the database.

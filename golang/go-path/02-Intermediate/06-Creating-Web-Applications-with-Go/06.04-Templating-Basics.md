# 06.04 Template basics: html/template actions, pipeline, variables

> **Go Path - Zero to Gopher** / **02 Intermediate → Creating Web Applications with Go** / Lesson 06.04

## Lesson goals

After this lesson you should be able to:

- distinguish `text/template` from `html/template` (auto-escape and contextual escaping)
- use actions `{{ }}`, `if`, `range`, `with` and understand how the dot `.` moves
- build a **pipeline** and define **variables** (`$name := ...`) to keep the root context
- parse templates with `ParseFiles` / `Must` and render with `Execute`
- send data via a struct with **exported** fields, without mixing HTML string concatenation and user input

**Remember:** `html/template` escapes; `text/template` does not.

## Prerequisite

- 06.01–06.03 (handler, forms, basic HTTP flow)
- Go struct, slice, methods
- awareness that a user string in HTML must be escaped (XSS mitigation, defensively)

## Problem this lesson solves

The first impulse in a handler often looks like this:

```go
fmt.Fprintf(w, "<h1>Hello, %s</h1>", userName)
```

That quickly becomes unsustainable: layout is duplicated, loops and conditions grow inside Go strings, and XSS risk rises as soon as `userName` (or any user text) enters HTML without escape.

`html/template` gives **declarative HTML**: text outside `{{ }}` goes literally, and values from data pass through **auto-escape** by context (element, attribute, …). That is a defensive layer — it does not replace input validation, but it prevents mild markup like `A < B` or angle brackets from “breaking” the HTML structure.

This lesson teaches the **template language** (`if`, `range`, pipeline, `$`) before layout inheritance in the next lesson.

## Mental model

A template is a small **printing program**:

1. It receives **data** (struct, map, slice) as the starting dot `.`
2. It executes **actions** in `{{ ... }}`
3. It writes text outside actions literally to the output
4. In `html/template` it escapes values by context before writing

The dot (`.`) is the “current context”. `range` and `with` **move** `.`. Variables `$x` hold values you do not want to lose when `.` changes — often at the top:

```html
{{ $ := . }}
```

Pipeline `{{ .Name | printf "%q" }}` passes the value through a chain; in `html/template` the escape policy still applies at the end.

```text
data (struct)
    │
    ▼
Parse → *template.Template
    │
    ▼
Execute(w, data)
    │
    ├─ text outside {{ }}  →  literally
    └─ {{ .Field }}        →  escape then write
```

## Mechanism

This is the longest part of the lesson: from parsing to escape, through actions, traces, and risky types.

### text/template versus html/template

Both packages share the **same action language**. The difference is in the output:

| Package | Auto-escape | Typical use |
|---------|-------------|-------------|
| `text/template` | no | email body, config, plain text |
| `html/template` | yes (contextual) | HTML pages and fragments |

`html/template` looks at where the action sits: inside an element, in an attribute, in a URL, and chooses the matching escape. That is **XSS mitigation** in the sense of “do not write raw angle brackets and similar markup into HTML without escape”. It is not magic that sanitizes everything; `template.HTML` and a bad context can still bypass protection.

### Contextual escaping — defensive example

Input you want to show as text:

```text
A < B and brackets: <tag>
```

In element context `html/template` typically writes entities instead of raw `<` / `>`:

```text
A &lt; B and brackets: &lt;tag&gt;
```

The browser shows `A < B and brackets: <tag>` as text, not as a new HTML node. Compare with `fmt.Fprintf` without escape: the same string could break the document structure.

Do **not** demonstrate attack script payloads in the lesson or in tests “for fun” — mild markup and angle brackets are enough to see the difference.

### ParseFiles and Execute

```go
t, err := template.ParseFiles("templates/home.html")
if err != nil {
	// fail at startup or return 500 — depending on strategy
	return err
}
err = t.Execute(w, data)
```

- `ParseFiles` reads the file(s), builds `*template.Template`.
- `Execute` writes the render to an `io.Writer` (often `http.ResponseWriter`) using `data` as the starting `.`.
- Alternative: `template.New("home").Parse(templateString)` for tests and short in-memory templates.

Template name: with `ParseFiles("templates/home.html")` the default name is often the base file name (`home.html`). Be explicit with `{{ define "..." }}` when you move to layout (next lesson).

### template.Must

```go
var homeTmpl = template.Must(template.ParseFiles("templates/home.html"))
```

`Must` panics if `err != nil`. At application startup that is often desired: a broken template → the process does not start. On the request path `Must` is dangerous — prefer an explicit `if err`.

### Actions: if, range, with

```html
{{ .Title }}
{{ if .OK }}yes{{ else }}no{{ end }}
{{ range .Items }}{{ . }}{{ end }}
{{ with .User }}{{ .Name }}{{ else }}guest{{ end }}
{{ /* comment */ }}
```

- `if` treats zero value as false (empty string, `nil` pointer, `0`, `false`, empty slice/map).
- `range` over slice/map: `.` becomes the element (or value); optional `else` when empty.
- `with` sets `.` to the pipeline if it is not a zero value; otherwise `else`.

### Dot, dollar, and losing context

```html
{{ $root := . }}
{{ range .Products }}
  <li>{{ .Name }} in {{ $root.Title }}</li>
{{ end }}
```

Inside `range`, `.` is `Product`. Without `$root`, `{{ .Title }}` looks for `Title` on the product — often empty output, without a dramatic error.

### Pipeline

```html
{{ .Price | printf "%.2f" }}
{{ .Name | printf "%q" }}
```

The value flows left → right. Built-in functions include `printf`, `len`, `index`, `and`, `or`, `not`, …

In `html/template` escape still applies to the result by context (except for special types like `template.HTML`).

### Exported fields and methods

The template sees only **exported** fields (`Title`, not `title`) and exported methods. An unexported field → empty output, often without an error in `Execute` — a silent trap.

```go
type Product struct {
	Name  string
	cents int // unexported — the template does not see it
}

func (p Product) PriceRSD() string {
	return fmt.Sprintf("%d RSD", p.cents/100)
}
```

```html
{{ .PriceRSD }}
```

The method (receiver on value or pointer, per Go rules) must be exported. Keep it light: display format, not network I/O in a `range` loop.

### template.HTML — conscious risk

```go
safe := template.HTML("<em>trusted</em>") // only if you truly control the source
```

`template.HTML` (and related types) **turn off** auto-escape for that value. A user comment, query string, or “temporarily so bold works” must **not** go here. The only reasonable path: a trusted CMS/sanitizer pipeline you control end-to-end.

### Execution trace: Parse then Execute

Assume `home.html`:

```html
<h1>{{ .Title }}</h1>
<p>{{ .Note }}</p>
```

and data:

```go
data := struct {
	Title string
	Note  string
}{
	Title: "Catalog",
	Note:  "A < B",
}
```

**Step 1 — ParseFiles**

1. Reads file bytes.
2. Tokenizes text and actions.
3. Builds a node tree (text + action).
4. Returns `*template.Template` or an error (syntax, uncovered `end`, …).

**Step 2 — Execute(w, data)**

1. Sets `.` = `data`.
2. Writes `<h1>` literally.
3. Evaluates `.Title` → `"Catalog"` → escape (here no special characters) → `Catalog`.
4. Writes `</h1><p>` literally.
5. Evaluates `.Note` → `"A < B"` → escape → `A &lt; B`.
6. Writes `</p>`.
7. Returns `nil` or an error (e.g. error in a pipeline function).

**Step 3 — what the client sees**

In the HTML source: `A &lt; B`. On screen: `A < B` as text.

### Trace: range and $root

Data:

```go
type Catalog struct {
	Title    string
	Products []struct{ Name string }
}
```

Template:

```html
{{ $root := . }}
{{ range .Products }}
{{ $root.Title }}: {{ .Name }}
{{ end }}
```

1. `$root` ← the whole `Catalog`.
2. `range` sets `.` to the first element.
3. `$root.Title` still reads the catalog; `.Name` reads the product.
4. Next element; at the end `.` returns (per template engine rules after `end`).

### Trace: with on a nil pointer

```go
type View struct {
	User *struct{ Display string }
}
```

```html
{{ with .User }}
  {{ .Display }}
{{ else }}
  guest
{{ end }}
```

1. `.User` is `nil` → zero value for pointer → `with` goes to `else`.
2. If `User != nil`, `.` becomes `*struct{...}` (dereference per template rules) and `.Display` works.

### Content-Type before writing

```go
w.Header().Set("Content-Type", "text/html; charset=utf-8")
if err := t.Execute(w, data); err != nil {
	log.Printf("execute: %v", err)
}
```

The first write to `ResponseWriter` often “locks” status and headers. So: header → then `Execute`. An error mid-`Execute` can leave partial HTML — so validate data earlier and log the error.

### Parsing once vs per request

| Strategy | When | Effect |
|----------|------|--------|
| `Must` / parse in `main`/`init` | production | fast request; bad template kills start |
| parse per request | demo/dev only | CPU + late error discovery |

Production: parse once. Dev reload leave for the next lesson (flag).

### index, and, or, not

```html
{{ index .Products 0 }}
{{ if and .OK .Ready }}ready{{ end }}
{{ if not .Hidden }}visible{{ end }}
```

`index` over slice/map; a wrong index can panic during `Execute` → 500 if there is no recover middleware (06.06).

### Attribute context (defensive)

Escape is not the same in every place. In element body `<` becomes `&lt;`. In an attribute the engine chooses rules suitable for an attribute (quotes, entities). So keep data in `{{ }}` instead of pasting it manually into an attribute string in Go.

```html
<!-- data goes through an action; do not build href manually with a raw query in a Go string -->
<a title="{{ .Hint }}">link</a>
```

If `Hint` contains quotes or angle brackets, `html/template` processes them for attribute context. Manual `fmt.Fprintf(w, "<a title=\"%s\">", hint)` easily breaks markup.

### Comparative trace: Fprintf vs template

Same input `note := "A < B"`:

**A — Fprintf**

```go
fmt.Fprintf(w, "<p>%s</p>", note)
// source: <p>A < B</p>  → browser may treat '<' as start of a tag
```

**B — html/template**

```go
_ = tmpl.Execute(w, note) // template: <p>{{ . }}</p>
// source: <p>A &lt; B</p> → stable text display
```

That is the whole point of the lesson in one pair of outputs — without attack payloads.

### Map as data (when allowed)

A struct is the default. `map[string]any` works:

```html
{{ index . "Title" }}
<!-- or, for map[string]string / maps with string keys in some forms: -->
{{ .Title }}
```

For `map[string]string`, `.Title` often works as a key. Downside: no compiler check of names; refactor hurts. Use a map for quick prototypes, a struct for lasting code.

### range with index

```html
{{ range $i, $p := .Products }}
  <li>#{{ $i }} {{ $p.Name }}</li>
{{ end }}
```

Here `$p` holds the element; `.` may also be the element depending on the form — explicit `$` variables reduce confusion. `$i` is the index (0-based).

### What an Execute error means in practice

| Error moment | Typical cause | Consequence |
|--------------|---------------|-------------|
| Parse | syntax, `end`, unknown function | no `*Template` / `Must` panic at start |
| Execute early | bad type in pipeline | little or no body |
| Execute late | error in `range` / method / `index` | partial HTML already sent |

So: validate data before render; tests on a buffer; recover middleware later for panic.

### Mini package map

```text
html/template
  ├─ action language (shared with text/template)
  ├─ contextual escaping
  ├─ types that turn off escape (template.HTML, ...)
  └─ API: New, Parse, ParseFiles, Must, Execute, ExecuteTemplate
```

For now stay on `ParseFiles` + `Execute`. `ExecuteTemplate`, `Funcs`, `define` — 06.05.

## Rules and syntax

- For HTML pages use **`html/template`**, not `text/template`.
- Export fields and methods the template reads.
- Keep the root with `$root := .` (or `$ := .`) before `range`/`with`.
- `Funcs` and layout come in 06.05; here stay on the action language.
- Do not pass user HTML through `template.HTML`.
- Set `Content-Type: text/html; charset=utf-8` before `Execute`.
- Log the `Execute` error; do not assume the whole response is valid if `err != nil`.
- Prefer a per-page data struct over an endless `map[string]any` without need.

## Examples

### Example 1: Simple page with a struct

```go
package main

import (
	"html/template"
	"log"
	"net/http"
	"time"
)

type Page struct {
	Title string
	Name  string
}

func home(w http.ResponseWriter, r *http.Request) {
	t, err := template.ParseFiles("templates/home.html")
	if err != nil {
		http.Error(w, "template", http.StatusInternalServerError)
		return
	}
	data := Page{
		Title: "Home",
		Name:  r.URL.Query().Get("n"),
	}
	w.Header().Set("Content-Type", "text/html; charset=utf-8")
	if err := t.Execute(w, data); err != nil {
		log.Printf("execute: %v", err)
	}
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /{$}", home)
	srv := &http.Server{
		Addr:              ":8080",
		Handler:           mux,
		ReadHeaderTimeout: 5 * time.Second,
	}
	log.Fatal(srv.ListenAndServe())
}
```

`templates/home.html`:

```html
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>{{ .Title }}</title>
</head>
<body>
  <h1>{{ .Title }}</h1>
  {{ if .Name }}
    <p>Hello, {{ .Name }}</p>
  {{ else }}
    <p>Hello, guest</p>
  {{ end }}
</body>
</html>
```

#### What happens here

- Query `?n=` empty → `if .Name` is false → “guest” branch.
- `?n=Ana` → escape then print the name in `<p>`.
- `?n=A < B` → in the HTML source you see `A &lt; B`, not raw `<`.
- The demo parses per request; in a real service move `ParseFiles` to `main` + `Must`.

#### Trace of request GET /?n=A%20%3C%20B

1. `ServeMux` chooses `home`.
2. `Name` = `"A < B"` (after query unescape).
3. Parse (demo) → `Execute`.
4. `if .Name` true.
5. Prints the escaped name.
6. Response 200 with HTML body.

### Example 2: range product list

```go
type Product struct {
	Name  string
	Price int
}

type Catalog struct {
	Title    string
	Products []Product
}
```

Template:

```html
<h1>{{ .Title }}</h1>
{{ if .Products }}
<ul>
{{ range .Products }}
  <li>{{ .Name }} — {{ .Price }} RSD</li>
{{ else }}
  <li>No products</li>
{{ end }}
</ul>
{{ end }}
```

#### What happens here

- `range` changes `.` to `Product`.
- `range` with `else` covers an empty slice.
- `Name` / `Price` must be exported; otherwise empty cells in the list.

#### Trace with two products

1. `.` = `Catalog`.
2. `if .Products` true.
3. Iteration 1: `.Name`/`Price` of the first.
4. Iteration 2: of the second.
5. End of `range` / `if`.

### Example 3: pipeline and variables

```html
{{ $root := . }}
{{ $count := len .Products }}
<p>Count: {{ $count }}</p>
{{ range .Products }}
  <p>{{ .Name | printf "%s" }} in catalog “{{ $root.Title }}”</p>
{{ end }}
```

#### What happens here

- `$count` is computed once before the loop.
- `$root` keeps the catalog while `.` is a product.
- Without `$root`, `.Title` inside `range` would not be on `Product`.

### Example 4: with for an optional pointer

```go
type User struct {
	Display string
}

type View struct {
	User *User
}
```

```html
{{ with .User }}
  <p>Signed in: {{ .Display }}</p>
{{ else }}
  <p><a href="/login">Sign in</a></p>
{{ end }}
```

#### What happens here

- `User == nil` → `else`.
- Otherwise `.` becomes the user; `.Display` in element context still escapes special characters.

### Example 5: Must at startup + test in a buffer

```go
package main

import (
	"bytes"
	"html/template"
	"testing"
)

var hello = template.Must(template.New("t").Parse(`Hello, {{ . }}`))

func TestEscapeAngle(t *testing.T) {
	var buf bytes.Buffer
	if err := hello.Execute(&buf, "A < B"); err != nil {
		t.Fatal(err)
	}
	got := buf.String()
	want := "Hello, A &lt; B"
	if got != want {
		t.Fatalf("got %q want %q", got, want)
	}
}
```

#### What happens here

- No HTTP: pure unit test of escape behavior.
- Input with `<` does not stay raw in the buffer.
- `Must` at `Parse` is fail-fast if the template is broken.

### Example 6: silent error of an unexported field

```go
type Row struct {
	name string // deliberately lowercase
}

// template: {{ .name }} or {{ .Name }} — both problematic in different ways
```

```html
<!-- .Name does not exist; .name is not exported -->
<p>{{ .Name }}</p>
```

#### What happens here

- Output stays empty; `Execute` often returns `nil`.
- Debug: temporarily log `fmt.Sprintf("%+v", data)` in Go or export the field.

## Decision analysis

| Decision | Choice | Why |
|----------|--------|-----|
| `html/template` vs `text/template` | html for HTML | contextual auto-escape |
| Parse per request | demo only | production: once + `Must` |
| Struct vs `map[string]any` | struct more often | types, refactor, export clarity |
| `template.HTML` | very rarely | turns off escape — XSS surface |
| String building HTML | avoid | you lose escape and structure |
| Method on the model for display | yes, light | format; not I/O |

## Trade-offs

- **Templates on disk** — easy to change; need agreement on reload in dev.
- **`embed.FS`** (next lessons / later) — one binary; change needs rebuild.
- **Rich logic in the template** — quickly unreadable; keep `if`/`range` simple, compute in Go.
- **Parse at startup** — faster request; bad template kills start (often desired).
- **Strict escape** — safer display; “trusted HTML” needs a separate, conscious path (`template.HTML` + sanitizer).

## Common mistakes

1. `text/template` for HTML with user data — no auto-escape.
2. Unexported fields — empty output, without a clear error.
3. Losing context in `range` without a `$` variable.
4. `ParseFiles` on every request in production (CPU + late errors).
5. Ignoring the `Execute` error after a partial write.
6. `{{ . }}` on a complex struct expecting pretty HTML.
7. Manual “escape” + `template.HTML` “just in case” — contradiction and a hole.
8. Content-Type after the first `Write` — wrong response type.
9. Expecting the template to see an unexported method or field.
10. Mixing `fmt.Fprintf` HTML and a template on the same route — inconsistent escape.

## Idiomatic Go

- `var templates = template.Must(template.ParseFiles(...))` at `init`/`main`.
- Data struct per page (`HomePageData`), not one giant `map[string]any` without need.
- `Content-Type` `text/html; charset=utf-8` before `Execute`.
- Test render in `bytes.Buffer` without the network.
- Go 1.22+ `ServeMux` patterns (`GET /{$}`) as in the example.
- Log `Execute` errors with enough context (route, template name).

## Methods and functions in the template

A template can call a **method** on the value in context. Receiver and export must be correct per Go rules:

```go
type Product struct {
	Name  string
	cents int
}

func (p Product) PriceRSD() string {
	return fmt.Sprintf("%d RSD", p.cents/100)
}
```

```html
{{ .PriceRSD }}
```

This is handy for display. Do not put heavy I/O in methods that `range` calls hundreds of times per request — prepare fields in the handler.

### Built-in functions (reminder)

```html
{{ index .Products 0 }}
{{ if and .OK .Ready }}ready{{ end }}
{{ if or .Draft .Hidden }}hidden{{ end }}
{{ if not .Hidden }}visible{{ end }}
{{ len .Products }}
{{ printf "%.2f" .Price }}
```

Custom functions (`FuncMap`) come in 06.05 — here stay on the built-in set.

### Parsing a string in a test

```go
tpl := template.Must(template.New("t").Parse(`Hello, {{ . }}`))
var buf bytes.Buffer
_ = tpl.Execute(&buf, "A < B")
// buf: Hello, A &lt; B
```

The fastest way to firmly verify escape and `range` without starting a server.

### Content-Type and charset — once more

```go
w.Header().Set("Content-Type", "text/html; charset=utf-8")
```

Always before `Execute`. If you write to `w` first, the header may be locked with the default type.

### Mini checklist before merge

1. Is the package `html/template`?
2. Are the fields exported?
3. Does `range` use `$root` where needed?
4. Is there a test with `A < B` → `&lt;`?
5. Is parse off the hot path?

## Practical scenario

The team renders user comments via `fmt.Fprintf`. On the profile, angle brackets and mild markup break the layout. They move to `html/template`; comments are escaped and the page stays stable.

Then someone marks “trusted HTML” from the CMS as `template.HTML` without sanitization — the hole returns another way. Rule: only a sanitized, trusted pipeline may go into `template.HTML`; a user comment never.

Second problem: in `range` they try `.SiteName` — empty. They learn `$root := .`. The catalog page becomes readable.

Third problem: `ParseFiles` on every request on a promo page during a campaign — CPU spike. They move parse to `main` with `Must`; a deploy with a broken template fails immediately, not under load.

Fourth: QA writes a table test with input `A < B` and expectation `&lt;` in the buffer — escape regressions are caught in CI before production.

## Predict, then answer

Work in order: read the question, **write a prediction**, then open the answer.

### 1) Escape in an element

**Question:** The template is `{{ . }}`, data `"A < B"`, package `html/template`. What is in the buffer after `Execute`?

**Predict:** (e.g. does `<` remain or become an entity?)

**Answer:** Typically `A &lt; B` (plus any surrounding template text). Raw `<` does not remain in the HTML source in that context.

### 2) text/template

**Question:** Same template and data, but `text/template`. What changes?

**Predict:**

**Answer:** No HTML auto-escape — the output keeps `A < B` with raw `<`. That is why `text/template` is not for HTML pages with data.

### 3) Dot in range

**Question:** After `{{ range .Items }}`, what is `.`?

**Predict:**

**Answer:** The current slice element (or value in a map range, depending on the form). The root is kept via a `$` variable if you need it.

### 4) Unexported field

**Question:** The struct has `title string` (lowercase). Template `{{ .title }}` or `{{ .Title }}`. What do you see?

**Predict:**

**Answer:** Empty output / inaccessible field. The template does not read unexported fields; a wrong name also does not “hit” a private field.

### 5) template.HTML

**Question:** Why is `template.HTML(userInput)` dangerous?

**Predict:**

**Answer:** That type turns off auto-escape. User input as “HTML” bypasses the defensive layer `html/template` otherwise provides.

### 6) Must in the handler

**Question:** Why is `template.Must(template.ParseFiles(...))` inside every request a bad idea?

**Predict:**

**Answer:** `Must` panics on error; plus you parse constantly (CPU). Parse + `Must` belong at startup; in the handler an explicit `err` or an already parsed `*Template`.

### 7) with and nil

**Question:** `{{ with .User }}...{{ else }}guest{{ end }}` when `User` is a `nil` pointer — which branch?

**Predict:**

**Answer:** `else` — a `nil` pointer is a zero value; `with` does not enter the main branch.

### 8) Partial Execute

**Question:** `Execute` returns an error halfway through the page. What is the problem for the client?

**Predict:**

**Answer:** Partial HTML may already have gone to `ResponseWriter`; status is often already 200. So validation before render and logging; do not rely on a “clean” rollback of the HTTP response.

## Summary

- `html/template` separates HTML from data and does contextual auto-escape — defensive XSS mitigation for display. **html/template escapes; text/template does not.**
- Actions `if`/`range`/`with`, pipeline and `$` variables make the template expressive without Go concatenation.
- Keep the dot context; export fields; parse templates once; `Must` at startup.
- Mild markup (`A < B`) in a test proves escape; `template.HTML` remains a privilege of a trusted pipeline.
- Next lesson: `define`/`block`/`template` and `FuncMap` for layout.

# 06.05 Smart templates: define, block, FuncMap, layout

> **Go Path - Zero to Gopher** / **02 Intermediate → Creating Web Applications with Go** / Lesson 06.05

## Lesson goals

After this lesson you should be able to:

- use `{{ define }}`, `{{ template }}`, and `{{ block }}` for the **layout** pattern
- understand how `ParseFiles` / `ParseGlob` / `ParseFS` assemble **one** set of named templates
- register a **FuncMap** *before* `Parse` (date format, display helpers)
- call the exact name via `ExecuteTemplate` and avoid redefine collisions
- use `Clone`, set-per-page, and (optionally) a reload flag only in development
- organize `layouts/` + `pages/` (+ `partials/`) in a maintainable structure

## Prerequisite

- 06.04 (actions, pipeline, `.`, `$`, auto-escape)
- `html/template` basics
- `template.Must` and parsing at startup

## Problem this lesson solves

Copying `<html><head>...` into every file leads to:

- an inconsistent CSS link
- forgotten escape on one page
- conflicts when changing navigation (12 files, 12 PRs)

You need **one layout** and pages that fill the “holes” (title, content). Go does this through named templates (`define`) and `block` with default content — it is not class inheritance from OOP engines, but the effect for layout is the same: a shared skeleton, local content.

`FuncMap` shortens repeated formatting (`rsd`, `date`). It is not the place for SQL, Redis, or authentication.

## Mental model

Picture a **catalog of named molds** in one `*template.Template` (or multiple sets per page):

1. `layout` defines the skeleton: doctype, nav, `{{ block "content" . }}` or `{{ template "content" . }}`.
2. Page `home` **defines** `title` / `content` (and an entry point `home` or directly `layout`).
3. When all relevant files are parsed together, the names merge.
4. The handler calls `ExecuteTemplate(w, "home", data)` — or `ExecuteTemplate(w, "layout", data)` with set-per-page.

```text
Parse (Funcs → ParseFiles/ParseFS)
        │
        ▼
  *template.Template
   ├─ "layout"
   ├─ "title"
   ├─ "content"
   └─ "home"  →  template "layout"
        │
        ▼
ExecuteTemplate(w, "home", data)
```

`Clone` copies the set (including FuncMap) so you can add a page define without colliding with another page.

## Mechanism

The longest part: from `define`/`block` through `Clone`, `ParseFS`, and reload strategy, with traces.

### define and template

```html
{{ define "layout" }}
<!doctype html>
<html>
<body>
  {{ template "content" . }}
</body>
</html>
{{ end }}
```

```html
{{ define "content" }}default{{ end }}

{{ define "home" }}
  {{ template "layout" . }}
{{ end }}
```

- `define "name"` registers a named template in the set.
- `template "name" pipeline` executes that template; the pipeline becomes `.` inside.
- Names must be visible in the **same** parsed set.

### block

```html
{{ block "title" . }}Application{{ end }}
```

`block "name" pipeline`:

1. Defines template `name` **if it does not already exist**, with the body between `block` and `end`.
2. Immediately executes it with the given pipeline.

A page parsed in the same set can do `{{ define "title" }}...{{ end }}` and thereby replace the default content — depending on order and set strategy. If overwrite behavior feels “magical”, switch to an explicit `template "content"` or **set per page** (clearer in larger apps).

### FuncMap — order is law

```go
funcs := template.FuncMap{
	"upper": strings.ToUpper,
	"rsd": func(n int) string {
		return fmt.Sprintf("%d RSD", n)
	},
}
t := template.New("root").Funcs(funcs)
t, err = t.ParseGlob("templates/**/*.html")
```

**Important:** `Funcs` must come **before** `Parse` / `ParseFiles` / `ParseFS` that use those names. Functions added after parse do not “slip into” already-parsed actions the way you expect.

FuncMap may: formatting, small pure transformations of string/number/time.

FuncMap must not: DB queries, HTTP calls, reading files per request, auth decisions.

### ExecuteTemplate

```go
err := t.ExecuteTemplate(w, "home", data)
```

- `Execute` without a name uses the root / default name — often wrong when you have multiple `define`s.
- `ExecuteTemplate` requires the exact name that exists as a `define` (or a file name in some conventions — be explicit with `define`).

### ParseFiles, ParseGlob, ParseFS

| API | Input | Note |
|-----|-------|------|
| `ParseFiles` | paths | explicit list |
| `ParseGlob` | pattern | convenient; watch redefine |
| `ParseFS` | `fs.FS` + patterns | `embed.FS` in the binary |

```go
//go:embed templates/*
var templateFS embed.FS

t := template.Must(
	template.New("root").
		Funcs(funcMap()).
		ParseFS(templateFS, "templates/*.html", "templates/pages/*.html"),
)
```

`embed` keeps templates in the binary artifact — no dependency on the working directory in production.

### Clone and set per page

Problem with one global set: two pages both do `{{ define "content" }}` → the last parse wins or you get a collision.

**Pattern A — set per page:**

```go
func mustPage(page string) *template.Template {
	return template.Must(
		template.New("layout").
			Funcs(funcMap()).
			ParseFiles("templates/layout.html", page),
	)
}

var pages = map[string]*template.Template{
	"home":  mustPage("templates/home.html"),
	"about": mustPage("templates/about.html"),
}
```

Each page has its own `*Template` with the same layout and local `content`/`title`.

**Pattern B — Clone:**

```go
base := template.Must(
	template.New("base").Funcs(funcMap()).ParseFiles("templates/layout.html", "templates/partials/nav.html"),
)

func page(name, file string) *template.Template {
	t := template.Must(base.Clone())
	return template.Must(t.ParseFiles(file))
}
```

`Clone` copies already-parsed templates and FuncMap; then you add the page file. Useful when the base (layout + partials + funcs) is large.

### Reload flag (development only)

```go
func load(page string) *template.Template {
	if os.Getenv("TEMPLATES_RELOAD") == "1" {
		return mustPage(page) // parse per request — slow, fresh
	}
	return pages[page] // production: once at startup
}
```

Do not mix modes without an explicit flag. In production the flag is **off**.

### Trace: ExecuteTemplate "home"

Files in one set:

- `layout` with `block "title"` and `block "content"`
- `home` = `{{ template "layout" . }}`
- `define "title"` / `define "content"` from `home.html`

**Step by step:**

1. Handler: `ExecuteTemplate(w, "home", data)`.
2. Engine enters `home`.
3. `home` calls `template "layout" .` — `.` stays `data` (or the passed pipeline).
4. `layout` writes doctype, head; `block "title"` executes the defined `title`.
5. `block "content"` executes the defined `content`.
6. Finishes the `body`/`html` part of the layout.
7. Return; `err` if something breaks in an action/function.

### Trace: FuncMap before Parse

```go
t := template.New("root")
t, err = t.Parse(`{{ rsd 100 }}`) // error: rsd is not defined
```

Correct:

```go
t := template.New("root").Funcs(template.FuncMap{
	"rsd": func(n int) string { return fmt.Sprintf("%d RSD", n) },
})
t, err = t.Parse(`{{ rsd 100 }}`)
```

1. `Funcs` registers the name `rsd`.
2. `Parse` binds the action call to the function.
3. `Execute` calls the Go function, then escapes the result in the HTML context.

### Trace: define "content" collision

One set, `ParseFiles(layout, home, about)` where both home and about do `define "content"`:

1. Parse `home` — registers `content` (home version).
2. Parse `about` — **redefines** `content` (about version).
3. `ExecuteTemplate(..., "home", ...)` may show about content — depending on order.

Therefore: set per page, or unique names (`home_content`), or strict order discipline (fragile).

### Trace: Clone

1. `base` has layout + nav + FuncMap.
2. `Clone()` → new structure, same names, independent for further parse.
3. `ParseFiles("home.html")` on the clone adds/overwrites only in the clone.
4. Another clone for `about.html` does not see home’s `content`.

### Partial (nav/footer)

```html
{{ define "nav" }}
<nav>
  <a href="/">Home</a>
  <a href="/about">About</a>
</nav>
{{ end }}
```

In the layout:

```html
{{ template "nav" . }}
```

The partial file must enter the same `Parse*` (or `base` before `Clone`).

### Names — checklist before ExecuteTemplate

1. Does the `define "name"` you call exist?
2. Did that file enter the same `Parse*` / `Clone` chain?
3. Does `Funcs` precede parse?
4. Does Content-Type go before writing?
5. Does production use the parsed set, not reload per request?

### block vs define — when which

| Tool | Defines a name? | Executes immediately? | Typical role |
|------|-----------------|----------------------|--------------|
| `define` | yes | no (only when called) | registering layout/page/partial |
| `template` | no | yes (calls existing) | including layout/partial |
| `block` | yes if absent | yes | hole with default content |

Practical rule:

- Layout skeleton → `define "layout"` + `block` for title/content **or** `template "content"`.
- Page entry → `define "home"` that calls layout, **or** `ExecuteTemplate(..., "layout", ...)` with page define in the same set.
- Repeated pieces → `define "nav"` + `template "nav"`.

### Trace: wrong name in ExecuteTemplate

```go
err := t.ExecuteTemplate(w, "hme", data) // typo
```

1. Engine looks for `define "hme"`.
2. Does not find it → `err != nil`.
3. If you ignore `err`, the client may get an empty/partial response with Content-Type already sent.

Always log `err` from `ExecuteTemplate`. In a test: a deliberate typo must fail.

### ParseGlob pitfalls

```go
template.Must(template.New("root").Funcs(funcMap()).ParseGlob("templates/**/*.html"))
```

- Convenient for a small project.
- The order of files a glob returns is **not** a contract you rely on for overwrite semantics.
- One stray `define "content"` in a partials folder can overwrite page content.

Therefore: explicit lists or set-per-page when the set grows.

### Data struct per page

```go
type HomeData struct {
	Shop    string
	Products []Product
}

type AboutData struct {
	Text string
}
```

Do not shove everything into one `map[string]any` “because typing is faster”. Then `.Shop` on the About page stays silent — a quiet bug similar to an unexported field.

### Trace: reload flag in one request

1. `TEMPLATES_RELOAD=1`.
2. `getPage("home")` calls `mustPage` → disk read + parse + FuncMap.
3. Handler `ExecuteTemplate`.
4. Next request parses again — CPU + possibly different content after a file edit.

In production step 2 disappears: map lookup on an already-parsed `*Template`.

### When Clone is not needed

If you have 2–3 pages and a short layout, `mustPage(layout, page)` is clearer. Introduce Clone when:

- partials grow (nav, footer, alerts, breadcrumbs),
- FuncMap is the same everywhere,
- you do not want to repeat a long `ParseFiles` list.

## Rules and syntax

- Parse layout + page (+ partials) **together** (same set or base + Clone).
- `Funcs` **before** parse.
- Prefer `ExecuteTemplate` with an explicit name.
- Avoid two `define`s of the same name with different meaning in the same set.
- Keep FuncMap clean: formatting, not I/O.
- For binary deploy: `ParseFS` + `embed.FS`.
- Reload flag only locally; document it in the README.

## Examples

### Example 1: Layout with block title/content

`templates/layout.html`:

```html
{{ define "layout" }}
<!doctype html>
<html lang="sr">
<head>
  <meta charset="utf-8">
  <title>{{ block "title" . }}Application{{ end }}</title>
  <link rel="stylesheet" href="/static/app.css">
</head>
<body>
  <header><a href="/">Home</a></header>
  <main>
    {{ block "content" . }}{{ end }}
  </main>
</body>
</html>
{{ end }}
```

`templates/home.html`:

```html
{{ define "home" }}
{{ template "layout" . }}
{{ end }}

{{ define "title" }}Home — {{ .Shop }}{{ end }}

{{ define "content" }}
  <h1>{{ .Shop }}</h1>
  <p>Welcome.</p>
{{ end }}
```

Go:

```go
t := template.Must(template.ParseFiles(
	"templates/layout.html",
	"templates/home.html",
))

func home(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/html; charset=utf-8")
	if err := t.ExecuteTemplate(w, "home", map[string]string{"Shop": "Šolja Market"}); err != nil {
		log.Printf("tmpl: %v", err)
	}
}
```

#### What happens here

- Entry is `home` → includes `layout`.
- `title` and `content` are in the same set.
- Changing navigation in the layout changes every page that shares it.

#### Render trace

1. `ExecuteTemplate(..., "home", data)`.
2. `home` → `layout`.
3. `block "title"` → “Home — Šolja Market” (escape as needed).
4. `block "content"` → `<h1>…`.
5. End.

Note: if overwriting `block` does not work as you expect due to parse order, use the explicit pattern from example 2 or set per page.

### Example 2: Explicit content template

```html
{{ define "layout" }}
<!doctype html>
<html>
<body>
{{ template "content" . }}
</body>
</html>
{{ end }}

{{ define "about" }}
{{ template "layout" . }}
{{ end }}

{{ define "content" }}
<section>
  <h1>About</h1>
  <p>{{ .Text }}</p>
</section>
{{ end }}
```

#### What happens here

- `ExecuteTemplate(..., "about", data)` → `about` → `layout` → `content`.
- Downside of one global `content`: collision between pages. In larger apps — set per page.

### Example 3: Separate set per page

```go
func funcMap() template.FuncMap {
	return template.FuncMap{
		"rsd":  func(n int) string { return fmt.Sprintf("%d RSD", n) },
		"date": func(t time.Time) string { return t.Format("2006-01-02") },
	}
}

func mustPage(files ...string) *template.Template {
	files = append([]string{"templates/layout.html"}, files...)
	return template.Must(template.New("layout").Funcs(funcMap()).ParseFiles(files...))
}

var pages = map[string]*template.Template{
	"home":  mustPage("templates/home.html"),
	"about": mustPage("templates/about.html"),
}

func render(w http.ResponseWriter, name string, data any) {
	w.Header().Set("Content-Type", "text/html; charset=utf-8")
	t := pages[name]
	if t == nil {
		http.Error(w, "template", http.StatusInternalServerError)
		return
	}
	if err := t.ExecuteTemplate(w, "layout", data); err != nil {
		log.Printf("render %s: %v", name, err)
	}
}
```

`home.html`:

```html
{{ define "title" }}Home{{ end }}
{{ define "content" }}
  <h1>Home</h1>
{{ end }}
```

#### What happens here

- Each page: its own `*Template` — no `content` collision.
- FuncMap shared via `funcMap()`.
- Cost: a bit more memory; gain: clarity.

### Example 4: FuncMap in a list

```html
<li>{{ .Name }} — {{ rsd .Price }} ({{ date .Added }})</li>
```

#### What happens here

- Format consistent across all templates.
- VAT and business rules stay in the Go handler / service.
- `Funcs` registered before `ParseFiles`.

### Example 5: Clone base + page

```go
var base = template.Must(
	template.New("base").
		Funcs(funcMap()).
		ParseFiles(
			"templates/layout.html",
			"templates/partials/nav.html",
			"templates/partials/footer.html",
		),
)

func mustCloned(page string) *template.Template {
	t := template.Must(base.Clone())
	return template.Must(t.ParseFiles(page))
}
```

#### What happens here

- Partials and layout parsed once in the base.
- Each page gets a clone then its own file.
- Changing `nav` in the base + rebuilding sets (at startup) changes every page.

### Example 6: ParseFS + embed

```go
package web

import (
	"embed"
	"html/template"
)

//go:embed templates/*.html templates/pages/*.html templates/partials/*.html
var templateFS embed.FS

func load() *template.Template {
	return template.Must(
		template.New("root").
			Funcs(funcMap()).
			ParseFS(templateFS,
				"templates/*.html",
				"templates/pages/*.html",
				"templates/partials/*.html",
			),
	)
}
```

#### What happens here

- Templates in the binary; the server’s CWD does not matter.
- Still true: watch for `define` collisions if it is one large set.

### Example 7: Reload flag in dev

```go
func getPage(name string) *template.Template {
	path := "templates/" + name + ".html"
	if os.Getenv("TEMPLATES_RELOAD") == "1" {
		return mustPage(path)
	}
	p, ok := pages[name]
	if !ok {
		return nil
	}
	return p
}
```

#### What happens here

- Designer changes HTML without restarting the process.
- Production: env is not `"1"` → parsed map.

## Decision analysis

| Decision | Choice | Why |
|----------|--------|-----|
| One global set | small site | simple |
| Set per page | medium+ | no define collision |
| Clone base | many partials | DRY base parse |
| FuncMap | formatting | DRY display |
| Logic in template | minimal | testability |
| `embed.FS` | production often | one artifact |
| Reload flag | only dev | fresh HTML without restart |

## Trade-offs

- **block vs explicit template** — block is short; explicit is clearer when debugging.
- **ParseGlob everything** — convenient; redefine risk.
- **Rich FuncMap** — powerful; becomes a hidden language.
- **Must at startup** — fail-fast; needs CI/smoke that starts the binary.
- **Clone vs mustPage** — Clone saves repeating the base; mustPage is more obvious for beginners.
- **embed** — stable deploy; slower HTML iteration without a reload strategy in dev.

## Common mistakes

1. `Execute` instead of `ExecuteTemplate` — wrong root.
2. `Funcs` after `Parse` — functions “do not exist”.
3. Pages parsed separately from layout — `template "layout"` is not found.
4. `define "content"` collision between pages in one set.
5. FuncMap does a DB call — slow, hard to test, hidden.
6. Wrong file order expecting overwrite without understanding.
7. Mixing habits from `text/template` with HTML escape assumptions.
8. Reload on in production — CPU and late discovery of a bad template.
9. `Clone` then forgotten `ParseFiles` of the page file — always the same empty content.
10. Wrong name in `ExecuteTemplate` — error only at runtime request.

## Idiomatic Go

- `template.Must` for static templates at startup.
- Named data struct per page.
- Small `render(w, name, data)` helper: Content-Type + log errors.
- In a test: `ExecuteTemplate` into `bytes.Buffer`, contains / exact string.
- Go 1.22+ server and mux as in previous lessons; templates are independent of routing.
- `embed.FS` + `ParseFS` for the production artifact.

## Clone and sharing sets

`template.Must(t.Clone())` helps when you want a base set (FuncMap + layout + partials) then add a page define without collision. To start, **set per page** (`ParseFiles(layout, page)`) is clear enough; enter Clone when the base grows.

### Names and ExecuteTemplate checklist

1. Does the `define "name"` you call exist?
2. Did that file enter the same `Parse*` call (or clone)?
3. Does `Funcs` precede parse?
4. Does Content-Type go before writing?
5. Does a test cover at least one happy-path render?

### Dev reload (sketch)

In development you can parse per request (slow, but fresh). In production — once. Do not mix modes without a feature flag:

```go
func load(page string) *template.Template {
	if os.Getenv("TEMPLATES_RELOAD") == "1" {
		return mustPage(page)
	}
	return pages[page]
}
```

### Example: shared partial (nav)

`templates/partials/nav.html`:

```html
{{ define "nav" }}
<nav>
  <a href="/">Home</a>
  <a href="/about">About</a>
</nav>
{{ end }}
```

In the layout:

```html
{{ template "nav" . }}
```

Include the partial in each set’s `ParseFiles` list or in a shared `base` before `Clone`.

### Why not SQL in FuncMap — mini trace

1. Template in `range` calls `{{ stock .ID }}`.
2. Each row = network/DB call.
3. HTML latency jumps; timeouts are harder to debug; template tests need a network mock.
4. Fix: handler loads stock into a slice/struct; template only prints the field.

## Practical scenario

A shop has 12 HTML pages with copy-pasted heads. They change the favicon — 12 conflicts. They introduce `layout.html` + set per page. FuncMap `rsd` removes `fmt.Sprintf` from 8 handlers.

Later someone adds `{{ stock .ID }}` to FuncMap that hits Redis — HTML latency jumps. They put stock back into the handler data struct. Rule: template formats, handler gathers.

Design wants the same footer: partial `footer` instead of another copy-paste. Reload flag in dev speeds iteration — off in production.

Then they move to `embed.FS`: “works on my laptop because I’m in the project folder” disappears as a class of bugs on the server.

Finally they introduce a `Clone` base because partials grow to 8 files — the `mustPage` list becomes noise; base + clone reduces the noise.

## Predict, then answer

Write a prediction before the answer.

### 1) FuncMap order

**Question:** `Parse` then only afterward `Funcs` with `rsd`. What happens when the template calls `{{ rsd 1 }}`?

**Predict:**

**Answer:** Parse does not know `rsd` at analysis time — error at parse (or the function is not available as you expect). `Funcs` goes before `Parse`.

### 2) Execute vs ExecuteTemplate

**Question:** You have `define "home"` and `define "layout"`. You call `t.Execute(w, data)` without a name. What is the risk?

**Predict:**

**Answer:** The default/root template runs — often not the one you think. `ExecuteTemplate(w, "home", data)` is explicit.

### 3) content collision

**Question:** One set, home and about both `define "content"`, parse order home then about. What does `ExecuteTemplate(..., "home", ...)` see for content?

**Predict:**

**Answer:** Often about’s definition (last overwrite), not home. Therefore set per page or unique names.

### 4) Clone isolation

**Question:** Two clones of the same base; each parses its own page with `define "content"`. Does one clone see the other’s content?

**Predict:**

**Answer:** No — `Clone` gives a separate set; the page define stays local.

### 5) What belongs in FuncMap

**Question:** `FuncMap{"q": func(id int) (Item, error) { return db.Get(id) }}` — for or against?

**Predict:**

**Answer:** Against. I/O and errors belong to the handler/service; the template gets already-prepared data.

### 6) ParseFS paths

**Question:** `//go:embed templates/*` and you call `ParseFS(fs, "templates/home.html")` but the embed root is not what you think. Where do you look first?

**Predict:**

**Answer:** Exact paths inside `fs.FS` (often with the `templates/...` prefix as embed sees them). Compare `fs.ReadDir` / the parse error.

### 7) Reload in production

**Question:** Why does `TEMPLATES_RELOAD=1` on a production pod hurt?

**Predict:**

**Answer:** Parse per request burns CPU; template errors surface late under traffic instead of at startup.

### 8) Partial outside the set

**Question:** Layout calls `{{ template "nav" . }}` but `nav.html` is not in `ParseFiles`. Outcome?

**Predict:**

**Answer:** Error at execution / parse dependency — `nav` does not exist in the set. Include the partial in the same parse or base.

## Summary

- Layout in Go templates is built with named `define`/`block`/`template`, not classes.
- Shared parse (or set per page / Clone) + `ExecuteTemplate` are the core of the pattern.
- `Funcs` before `Parse`; FuncMap only for display; data and I/O in the handler.
- `ParseFS`/`embed` for the artifact; reload flag only in development.
- Next: middleware chain around these handlers.

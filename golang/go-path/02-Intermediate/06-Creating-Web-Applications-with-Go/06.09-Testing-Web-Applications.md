# 06.09 Testing web applications: httptest, NewServer, table tests

> **Go Path - Zero to Gopher** / **02 Intermediate → Creating Web Applications with Go** / Lesson 06.09

## Lesson goals

After this lesson you should be able to:

- test handlers with `httptest.NewRequest` and `httptest.NewRecorder`
- start a short integration server with `httptest.NewServer` and always `defer ts.Close()`
- write **table-driven** tests for status codes, headers, and body
- understand that Recorder **does not follow** redirects — you check 303 + `Location` directly
- send POST forms with `url.Values` + `Content-Type`
- test `PathValue` **through ServeMux** (Go 1.22+), not with a bare function without a mux
- use a fake store instead of a real database; avoid `DefaultServeMux` and a hardcoded port

## Prerequisite

- 06.01–06.08 (handler, mux, middleware, store DI, shutdown concepts)
- `go test`, `t.Run`, `t.Fatalf`, `t.Helper`
- basic table test pattern in Go
- 06.07 store / `sql.ErrNoRows` mapping — useful for the fake store example

## Problem this lesson solves

Manual “start the server, open the browser” does not catch regressions. Common antipatterns:

1. tests depend on port `:8080` occupied on CI
2. no status code check — only “did not panic”
3. one huge test for all routes
4. a real DB in a handler unit test without a fake store
5. expecting `ResponseRecorder` to automatically follow redirects
6. `PathValue` test without `ServeMux` — empty string, false fail
7. the package uses `http.DefaultServeMux` — tests interfere with each other

`net/http/httptest` gives **fast, deterministic** in-process handler tests.

## Mental model

Three levels:

```text
1. Recorder  — fake ResponseWriter; handler.ServeHTTP(rec, req) in the same process
2. NewServer — real TCP on 127.0.0.1:0; ts.URL; real http.Client
3. E2E       — whole binary + real database / browser (out of focus; more expensive)
```

Most handler logic lives at level 1. Level 2 when you need client redirect follow, cookies, or a slightly wider transport. Level 3 for smoke before release — not for every PR commit on a handler branch.

```text
Table test
  ├─ setup mux / Server{store: fake}
  └─ for each case:
       NewRequest → NewRecorder → ServeHTTP
       assert Code / Header / Body
```

## Mechanism

Core of the lesson: from `NewRequest` to fake store, with traces and “Predict, then answer”.

### 1. NewRequest + NewRecorder

```go
req := httptest.NewRequest(http.MethodGet, "/item/1", nil)
rec := httptest.NewRecorder()
mux.ServeHTTP(rec, req)

if rec.Code != http.StatusOK {
	t.Fatalf("code=%d", rec.Code)
}
body := rec.Body.String()
```

What you get:

- `rec.Code` — status (default 200 if the handler only writes a body)
- `rec.Header()` — headers
- `rec.Body` — `*bytes.Buffer` of the body

No network, no port, no TLS — pure unit level for the HTTP semantics of the handler.

#### Execution trace — one GET

```text
1. NewRequest builds *http.Request (URL, method, empty body)
2. NewRecorder builds ResponseRecorder
3. mux.ServeHTTP picks a handler by pattern
4. handler writes to rec (WriteHeader / Write)
5. test reads rec.Code and rec.Body
```

#### Predict, then answer

Handler only calls `fmt.Fprint(w, "ok")` without `WriteHeader`. What is `rec.Code`?

<details>
<summary>Answer</summary>

**200** — the first `Write` implicitly sends 200. Use explicit `WriteHeader` when you need another status (404, 303, 201, …).
</details>

### 2. NewServer + defer Close

```go
ts := httptest.NewServer(mux)
defer ts.Close()

res, err := http.Get(ts.URL + "/")
if err != nil {
	t.Fatal(err)
}
defer res.Body.Close()
```

What differs from Recorder:

- a real listener on `127.0.0.1:0` (OS picks a free port)
- `ts.URL` includes scheme and port — no hardcoded `:8080`
- you go through a real client (`http.Get` / `http.Client`)
- the default `http.Client` **follows** redirects (unlike Recorder)

Always `defer ts.Close()` — otherwise a listener leak in a long suite.

#### Execution trace — NewServer

```text
1. NewServer → listen 127.0.0.1:ephemeral
2. http.Get(ts.URL+"/") → real TCP + HTTP round-trip
3. server goroutine calls mux.ServeHTTP
4. test reads res.StatusCode / Body
5. defer Close → shuts down the listener
```

#### Predict, then answer

Two parallel tests (`t.Parallel`) both call `ListenAndServe(":8080", ...)`. What happens on CI?

<details>
<summary>Answer</summary>

Port collision — flaky fail. Solution: `httptest.NewServer` (port 0) or Recorder without a network. Never a hardcoded production port in unit/integration tests.
</details>

### 3. Table-driven tests

```go
tests := []struct {
	name   string
	method string
	path   string
	want   int
}{
	{"home", http.MethodGet, "/", http.StatusOK},
	{"missing", http.MethodGet, "/nope", http.StatusNotFound},
}
for _, tc := range tests {
	t.Run(tc.name, func(t *testing.T) {
		req := httptest.NewRequest(tc.method, tc.path, nil)
		rec := httptest.NewRecorder()
		mux.ServeHTTP(rec, req)
		if rec.Code != tc.want {
			t.Fatalf("code=%d want=%d", rec.Code, tc.want)
		}
	})
}
```

Why table:

- one setup, many cases
- case name in `t.Run` — clear fail in CI
- easy to add 400/401/404/303 without a new file

#### Predict, then answer

You have 12 routes and 12 separate `TestXxx` with copy-paste setup. Refactor?

<details>
<summary>Answer</summary>

One `TestRoutes` (or by group: `TestPublicRoutes`, `TestAuthRoutes`) + a table. A `doReq` helper shortens boilerplate.
</details>

### 4. Recorder does not follow redirects

```go
http.Redirect(w, r, "/me", http.StatusSeeOther)
// rec.Code == 303
// rec.Header().Get("Location") == "/me"
// body often empty / minimal — status + Location matter
```

That is **desired** for a PRG (Post-Redirect-Get) test: you verify that POST does not return 200 with HTML.

For follow redirect:

```go
ts := httptest.NewServer(mux)
defer ts.Close()
client := &http.Client{
	// follows by default; or CheckRedirect for control
}
res, err := client.PostForm(ts.URL+"/login", url.Values{"user": {"marko"}})
```

#### Trace — PRG with Recorder

```text
POST /login (valid)
  → handler: Redirect 303 Location=/me
  → Recorder stops here
  → test assert Code=303, Location=/me
  → do NOT expect the /me page body in the same rec
```

#### Predict, then answer

A test with Recorder expects `rec.Code == 200` after a successful login POST that does PRG. Why does it fail?

<details>
<summary>Answer</summary>

PRG returns **303** (or 302), not 200. 200 after POST often means “render the form again” and a risk of double submit on refresh. Assert 303 + `Location`.
</details>

### 5. POST form

```go
form := url.Values{"user": {"marko"}, "pass": {"x"}}.Encode()
req := httptest.NewRequest(http.MethodPost, "/login", strings.NewReader(form))
req.Header.Set("Content-Type", "application/x-www-form-urlencoded")
```

Without `Content-Type`, `ParseForm` / `PostForm` often do not see fields — the test falsely passes in the “bad request” branch or the reverse.

#### Trace — form

```text
1. Encode Values → "user=marko&pass=x"
2. Body = strings.NewReader(...)
3. Header Content-Type = application/x-www-form-urlencoded
4. handler: ParseForm → PostForm.Get("user")
```

#### Predict, then answer

You forget `Content-Type` in the test; the handler does `r.PostForm.Get("user")` after `ParseForm`. What do you often see?

<details>
<summary>Answer</summary>

Empty `user` → validation 400, even though you “sent” a body. Symptom: form test fails without an obvious reason in the assert message — check the header first.
</details>

### 6. PathValue needs a mux (Go 1.22+)

```go
mux.HandleFunc("GET /item/{id}", s.getItem)
// inside: id := r.PathValue("id")
```

Correct test:

```go
req := httptest.NewRequest(http.MethodGet, "/item/9", nil)
rec := httptest.NewRecorder()
mux.ServeHTTP(rec, req) // mux fills PathValue
```

Wrong pattern:

```go
s.getItem(rec, req) // directly — PathValue often ""
```

#### Trace — with and without mux

```text
Through mux:
  ServeMux matches GET /item/{id}
  → sets path value id=9
  → getItem sees PathValue("id")=="9"

Without mux:
  getItem(rec, req) with URL /item/9
  → PathValue("id") == "" (no pattern match happened)
  → false 404 or empty id
```

#### Predict, then answer

A unit test calls `getItem(rec, req)` directly because it is “faster”. PathValue is always empty. What do you do?

<details>
<summary>Answer</summary>

Test through `ServeMux` with the same pattern as in production. Alternative (rarer): manually set path values if the API allows — the mux path is clearer and closer to reality.
</details>

### 7. Fake store + DI

```go
type ItemStore interface {
	FindItem(ctx context.Context, id string) (Item, error)
}

type fakeStore struct {
	item Item
	err  error
}

func (f fakeStore) FindItem(ctx context.Context, id string) (Item, error) {
	return f.item, f.err
}

func TestGetItemNotFound(t *testing.T) {
	s := &Server{store: fakeStore{err: sql.ErrNoRows}}
	mux := http.NewServeMux()
	mux.HandleFunc("GET /item/{id}", s.getItem)

	req := httptest.NewRequest(http.MethodGet, "/item/9", nil)
	rec := httptest.NewRecorder()
	mux.ServeHTTP(rec, req)
	if rec.Code != http.StatusNotFound {
		t.Fatalf("code=%d", rec.Code)
	}
}
```

No Postgres, no Docker, no flaky network — a clean HTTP map `ErrNoRows` → 404.

#### Predict, then answer

The handler package in the test opens a real SQLite file on disk for every `t.Run`. The suite takes 2 minutes. Alternative?

<details>
<summary>Answer</summary>

Fake store (or a short in-memory fake) for handler unit tests. Leave a real database for a smaller number of integration tests of the store package.
</details>

### 8. Not DefaultServeMux, not a hardcoded port

```go
// BAD in a library / app package:
http.HandleFunc("/x", h)          // DefaultServeMux
log.Fatal(http.ListenAndServe(":8080", nil))

// GOOD:
mux := http.NewServeMux()
mux.HandleFunc("GET /x", h)
srv := &http.Server{Addr: addr, Handler: mux, ReadHeaderTimeout: 5 * time.Second}
```

In the test: inject `mux` / `Server` dependencies. For network smoke: `NewServer`, not `:8080`.

### Mechanism — choice map

```text
Need only status/body/header?
  → NewRequest + NewRecorder + mux.ServeHTTP

Need a real client / follow redirect / cookie jar?
  → NewServer + defer Close

Many similar cases?
  → table + t.Run

PathValue?
  → always through ServeMux

DB branch?
  → fake store (interface)

Port?
  → never hardcode 8080 in a test
```

## Rules and syntax

- Do not use `http.DefaultServeMux` in packages you test — inject a mux.
- For POST forms: `strings.NewReader(url.Values{...}.Encode())` + `Content-Type`.
- Test `PathValue` (Go 1.22+) through a mux with a pattern.
- JSON: `json.Unmarshal` or golden; HTML: often `strings.Contains`.
- `t.Parallel` OK if there is no shared mutable global state.
- Always `defer res.Body.Close()` and `defer ts.Close()` in NewServer tests.
- Helper with `t.Helper()` for `doReq`.

## Examples

### Example 1: Table test of status codes

```go
func TestRoutes(t *testing.T) {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /{$}", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "home")
	})
	mux.HandleFunc("GET /about", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "about")
	})

	tests := []struct {
		name string
		path string
		code int
		body string
	}{
		{"root", "/", http.StatusOK, "home"},
		{"about", "/about", http.StatusOK, "about"},
		{"missing", "/x", http.StatusNotFound, ""},
	}

	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			req := httptest.NewRequest(http.MethodGet, tc.path, nil)
			rec := httptest.NewRecorder()
			mux.ServeHTTP(rec, req)
			if rec.Code != tc.code {
				t.Fatalf("code=%d want=%d", rec.Code, tc.code)
			}
			if tc.body != "" && !strings.Contains(rec.Body.String(), tc.body) {
				t.Fatalf("body=%q", rec.Body.String())
			}
		})
	}
}
```

#### What happens here

- One mux setup, multiple cases.
- The 404 path checks default mux NotFound behavior.
- Fast — no network.

### Example 2: POST form and redirect (PRG)

```go
func TestLoginPRG(t *testing.T) {
	mux := http.NewServeMux()
	mux.HandleFunc("POST /login", func(w http.ResponseWriter, r *http.Request) {
		_ = r.ParseForm()
		if r.PostForm.Get("user") == "" {
			http.Error(w, "bad", http.StatusBadRequest)
			return
		}
		http.Redirect(w, r, "/me", http.StatusSeeOther)
	})

	form := url.Values{"user": {"marko"}}.Encode()
	req := httptest.NewRequest(http.MethodPost, "/login", strings.NewReader(form))
	req.Header.Set("Content-Type", "application/x-www-form-urlencoded")
	rec := httptest.NewRecorder()
	mux.ServeHTTP(rec, req)

	if rec.Code != http.StatusSeeOther {
		t.Fatalf("code=%d", rec.Code)
	}
	if loc := rec.Header().Get("Location"); loc != "/me" {
		t.Fatalf("Location=%s", loc)
	}
}
```

#### What happens here

- Recorder **does not follow** redirect — you see 303 and Location.
- For follow use NewServer + `http.Client`.

### Example 3: NewServer + client

```go
func TestNewServerHome(t *testing.T) {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /{$}", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, "ok")
	})
	ts := httptest.NewServer(mux)
	defer ts.Close()

	res, err := http.Get(ts.URL + "/")
	if err != nil {
		t.Fatal(err)
	}
	defer res.Body.Close()
	if res.StatusCode != http.StatusOK {
		t.Fatalf("status=%d", res.StatusCode)
	}
	b, err := io.ReadAll(res.Body)
	if err != nil {
		t.Fatal(err)
	}
	if string(b) != "ok" {
		t.Fatalf("body=%q", b)
	}
}
```

#### What happens here

- Real HTTP round-trip on localhost.
- OS picks the port — no collision on CI.
- `defer ts.Close()` is mandatory.

### Example 4: Middleware recover test

```go
func TestRecoverMiddleware(t *testing.T) {
	h := withRecover(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		panic("boom")
	}))
	rec := httptest.NewRecorder()
	req := httptest.NewRequest(http.MethodGet, "/", nil)
	h.ServeHTTP(rec, req)
	if rec.Code != http.StatusInternalServerError {
		t.Fatalf("code=%d", rec.Code)
	}
}
```

#### What happens here

- Panic does not crash `go test`.
- Status 500 confirms the middleware.
- You can extend by checking that the body is not empty / has no stack for the client.

### Example 5: Fake store for a handler with a DB branch

```go
type fakeStore struct {
	item Item
	err  error
}

func (f fakeStore) FindItem(ctx context.Context, id string) (Item, error) {
	return f.item, f.err
}

func TestGetItemNotFound(t *testing.T) {
	s := &Server{store: fakeStore{err: sql.ErrNoRows}}
	mux := http.NewServeMux()
	mux.HandleFunc("GET /item/{id}", s.getItem)

	req := httptest.NewRequest(http.MethodGet, "/item/9", nil)
	rec := httptest.NewRecorder()
	mux.ServeHTTP(rec, req)
	if rec.Code != http.StatusNotFound {
		t.Fatalf("code=%d", rec.Code)
	}
}

func TestGetItemOK(t *testing.T) {
	s := &Server{store: fakeStore{item: Item{ID: "1", Name: "tea"}}}
	mux := http.NewServeMux()
	mux.HandleFunc("GET /item/{id}", s.getItem)

	req := httptest.NewRequest(http.MethodGet, "/item/1", nil)
	rec := httptest.NewRecorder()
	mux.ServeHTTP(rec, req)
	if rec.Code != http.StatusOK {
		t.Fatalf("code=%d", rec.Code)
	}

		t.Fatalf("body=%q", rec.Body.String())
	}

```

#### What happens here

- No real database.
- `ErrNoRows` → 404 and happy path covered.
- Store must be an interface in production code for this to work cleanly.

### Example 6: PathValue through mux

```go
func TestPathValue(t *testing.T) {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /w/{id}", func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, r.PathValue("id"))
	})
	req := httptest.NewRequest(http.MethodGet, "/w/42", nil)
	rec := httptest.NewRecorder()
	mux.ServeHTTP(rec, req)
	if rec.Body.String() != "42" {
		t.Fatalf("got %q", rec.Body.String())
	}
}
```

#### What happens here

- PathValue is filled when the mux matches the pattern.
- Direct `getItem(rec, req)` without a mux often does **not** fill PathValue.

### Example 7: Helper doReq

```go
func doReq(t *testing.T, mux http.Handler, method, path string, body io.Reader, contentType string) *httptest.ResponseRecorder {
	t.Helper()
	req := httptest.NewRequest(method, path, body)
	if contentType != "" {
		req.Header.Set("Content-Type", contentType)
	}
	rec := httptest.NewRecorder()
	mux.ServeHTTP(rec, req)
	return rec
}
```

#### What happens here

- Less noise in table tests.
- `t.Helper()` moves the fail line to the caller.

### Example 8: Table for validation + PRG + 404

```go
func TestCartPOST(t *testing.T) {
	mux := newCartMux() // mux factory with fake store

	tests := []struct {
		name string
		form url.Values
		code int
		loc  string
	}{
		{"ok", url.Values{"sku": {"A1"}}, http.StatusSeeOther, "/cart"},
		{"empty", url.Values{}, http.StatusBadRequest, ""},
	}
	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			rec := doReq(t, mux, http.MethodPost, "/cart",
				strings.NewReader(tc.form.Encode()),
				"application/x-www-form-urlencoded")
			if rec.Code != tc.code {
				t.Fatalf("code=%d want=%d", rec.Code, tc.code)
			}
			if tc.loc != "" && rec.Header().Get("Location") != tc.loc {
				t.Fatalf("Location=%s", rec.Header().Get("Location"))
			}
		})
	}
}
```

#### What happens here

- One table covers happy and validation branches.
- PRG stays explicit (303), not “200 and HTML”.

### Example 9: NewServer without follow redirect (client control)

```go
func TestLoginNoFollow(t *testing.T) {
	mux := http.NewServeMux()
	mux.HandleFunc("POST /login", func(w http.ResponseWriter, r *http.Request) {
		http.Redirect(w, r, "/me", http.StatusSeeOther)
	})
	ts := httptest.NewServer(mux)
	defer ts.Close()

	client := &http.Client{
		CheckRedirect: func(req *http.Request, via []*http.Request) error {
			return http.ErrUseLastResponse
		},
	}
	res, err := client.PostForm(ts.URL+"/login", url.Values{"user": {"marko"}})
	if err != nil {
		t.Fatal(err)
	}
	defer res.Body.Close()
	if res.StatusCode != http.StatusSeeOther {
		t.Fatalf("status=%d", res.StatusCode)
	}
}
```

#### What happens here

- Default `http.Client` follows redirects — here you deliberately turn that off.
- You get the same insight as Recorder (303), but through a real transport.
- Useful when you also test cookies / Set-Cookie with PRG.

### More detailed trace: from table row to fail message

```text
t.Run("empty")
  → doReq POST /cart with empty form
  → handler: ParseForm → sku == "" → 400
  → assert code==400 OK
t.Run("ok")
  → doReq with sku=A1
  → handler: Redirect 303 Location=/cart
  → assert code and Location
If someone changes Redirect to 200:
  → t.Fatalf("code=200 want=303") with name "ok"
  → CI exactly shows which case breaks
```

#### Predict, then answer

The suite uses one package-level `var mux = http.NewServeMux()` initialized in `init`, plus `t.Parallel` in every test. Risk?

<details>
<summary>Answer</summary>

Races and state leaking between tests (e.g. `HandleFunc` panics on duplicate, or a shared fake store). Better: a local mux per test / per `t.Run`, or `t.Parallel` only with isolated copies.
</details>

### Mini-lab: what Recorder does not test

```text
Recorder COVERS:
  status, header, body, middleware chain, PathValue (with mux), PRG codes

Recorder does NOT COVER:
  TLS / HTTP/2 framing
  real TCP timeout
  DNS / proxy behavior
  browser cookie jar without an extra client

For that: NewServer (partially) or a separate staging smoke — not every unit test.
```

## Decision analysis

| Decision | Choice | Why |
|----------|--------|-----|
| Recorder for handler | Default | Speed, determinism |
| NewServer | Redirect follow / client | More realistic transport |
| Table tests | Yes | Many cases, clear CI |
| Real DB in unit handler test | No | Slow / flaky |
| Test via DefaultServeMux | No | Prevents isolation |
| Hardcoded `:8080` | No | Collisions on CI |
| PathValue without mux | No | Empty values |
| Fake store | Yes | Status mapping without DB |

## Trade-offs

- **Recorder** — does not test TLS/HTTP2 framing.
- **NewServer** — slower than Recorder; still faster than browser E2E.
- **Golden HTML** — catches regressions; brittle on whitespace.
- **Parallel tests** — faster CI; require state isolation.
- **Broad E2E** — confidence; slower feedback loop.

## Common mistakes

1. Forgotten `Content-Type` on a POST form in the test.
2. Expecting Recorder to follow redirects.
3. Testing PathValue without ServeMux.
4. Shared global mux + `t.Parallel` → races.
5. Comparing whole HTML to an exact string without stabilization.
6. Ignoring `res.Body.Close()` in a NewServer test.
7. Port hardcoded instead of NewServer.
8. `http.Handle` / `DefaultServeMux` in the production package.
9. Real DB in every handler unit test.
10. One test file that “checks everything” without `t.Run` names.

## Idiomatic Go

- `t.Run` per case.
- Helper `doReq(t, mux, method, path, body) *httptest.ResponseRecorder` with `t.Helper()`.
- Interface for store; fake in the test.
- Name tests by behavior (`not_found`, `validation_error`, `prg_redirect`).
- Factory `newTestMux(t, fake)` to share setup without globals.

## Practical scenario

Team “Šolja Market” has manual QA lists before release. Regression: POST `/cart` returns 200 instead of 303 — refresh duplicates items. After a table test on PRG, CI goes red on the wrong status.

Another flaky test uses `:8080` — parallel jobs collide. They switch to `httptest.NewServer`.

Fake store shortens the suite from 2 minutes to 3 seconds for the handler package. PathValue bug: the test called the handler directly — always 404; after the mux the test caught the real regression in `FindItem` mapping.

## Summary

- `httptest` is the basic tool for testing the web layer in Go.
- Recorder for fast handler tests; NewServer when you need a real client — always `defer Close`.
- Table tests cover status/body/headers systematically.
- Recorder does not follow redirects; POST forms need `Content-Type`; PathValue goes through mux; fake store instead of DB.
- Avoid `DefaultServeMux` and a hardcoded port.

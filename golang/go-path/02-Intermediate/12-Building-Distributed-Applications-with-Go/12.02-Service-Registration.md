# 12.02 Service registration: a simple HTTP registry

> **Go Path - Zero to Gopher** / **02 Intermediate → Building Distributed Applications with Go** / Lesson 12.02

## Lesson goals

After this lesson you should:

- understand why instances **register** themselves (address, name, meta);
- implement a **small HTTP registry** (without a proprietary SDK) as a teaching model;
- use heartbeat / TTL (*time to live* — record lifetime) so dead instances drop out;
- register and deregister an instance at start and graceful shutdown;
- prepare the data that discovery (12.03) reads;
- connect the moment of registration with readiness (12.04) — not before you may take traffic;
- defend the registry defensively: body limit, timeout, field validation, awareness of the auth boundary.

## Prerequisite

- 12.01 (partial failure, timeout, no shared memory).
- `net/http`, JSON encode/decode (09.xx).
- Concurrent map + `sync.Mutex` (08.xx).
- `context` for the lifetime of the register loop.
- Basic signal handling / shutdown pattern (09.01 optional).

## Problem this lesson solves

A hardcoded `http://orders:8080` in configuration does not scale when you have N replicas that come and go. Deploy, crash, scale-out — addresses change. The registry stores **currently known** instances.

In production that is done by Consul, etcd, Kubernetes Endpoints / Service. Here you build a **teaching** HTTP registry to see the contract (fields, TTL, heartbeat, deregistration), not to replace the platform. The mental model stays the same when you move to K8s DNS.

## Mental model

```text
orders-pod-1  --register-->  registry (:8500)
orders-pod-2  --heartbeat->  registry
orders-pod-2  --DELETE---->  registry   (graceful stop)
checkout      --lookup---->  registry   (next lesson)
```

Each instance carries: `service` name + `id` + `URL` + `expiresAt`. The registry deletes expired ones. Discovery reads only fresh ones. If a pod dies without DELETE, TTL still cleans — slower, but reliable with a good heartbeat < TTL ratio.

The lab registry is **one process, in-memory map**. That is an intentional SPOF for pedagogy. In production you need an HA store; the field contract remains.

## Mechanism

### Why self-registration

Two schools:

1. **Self-registration** — the instance itself reports “I am here” (this lesson).
2. **Platform registration** — orchestrator / kubelet knows the pod IP and fills Endpoints.

Self-registration teaches you the contract and edge cases (TTL, race, deregistration). The platform removes operational burden. In both cases the client still does discovery + selection.

### API contract (teaching)

| Method | Path | Input | Semantics |
|--------|-----|------|-----------|
| `POST` | `/register` | service, id, url, ttlSeconds | upsert instance, set Expire |
| `POST` | `/heartbeat` | service, id, ttlSeconds | extend Expire |
| `DELETE` | `/register` | service, id | explicit deregistration |
| `GET` | `/services/{name}` | — | list of fresh ones (for 12.03) |

Idempotency: a repeated `POST /register` with the same `service`+`id` **overwrites** URL and TTL. That is desired (pod restart, new address).

### Heartbeat and TTL

If a pod dies without DELETE, TTL expires. Rule:

```text
heartbeat interval  <  TTL
example: 5 s heartbeat, 15 s TTL
```

If interval ≥ TTL, instances “flicker”: they drop from the list between beats. Discovery sees empty or an unstable set → false 503.

### Store: map under Mutex

```text
data: map[serviceName]map[instanceID]Instance
```

- `Upsert` — insert/update.
- `Touch` — extend Expire if it exists.
- `Remove` — DELETE path.
- `ListFresh(now)` — return non-expired; lazily delete expired.

For an HA registry you need raft/quorum (etcd) — out of scope. Focus is the contract and concurrent correctness of one process.

### When to register (link to 12.04)

Register **only when the instance is ready** to receive traffic (readiness / gate). If you register during warm-up, discovery sends traffic to a half-ready instance — that is partial failure you created yourself.

Order:

1. Listen HTTP (at least `/livez`).
2. Warm (DB ping, cache).
3. `SetReady(true)` / ready probe 200.
4. `Register` + heartbeat loop.
5. On SIGTERM: ready false → drain → DELETE → server shutdown.

### Deregistration vs TTL

| Path | Speed | Reliability |
|-----|--------|------------|
| DELETE | disappears from the list immediately | requires shutdown to reach the registry |
| TTL expiry | after Expire | works even after hard kill |

Always implement both. DELETE is a UX optimization; TTL is correctness.

### Validation and defense

- Limit JSON body (`io.LimitReader`).
- Reject empty service/id/url, TTL ≤ 0, oversized TTL (memory DoS if someone sets 10 years — in the lab cap e.g. 60 s).
- Timeout on the registry server (`ReadHeaderTimeout`).
- Do not blindly trust a URL from registration on a shared network: SSRF risk if someone else calls that URL. In the lab local hosts; in prod policy (allowlist CIDR) or platform endpoints instead of a user URL.
- Auth: shared secret header at least on a shared network. Teaching registry without auth = localhost only.

### Meta fields

`Meta map[string]string` — version, zone, weight. Discovery can filter. Do not turn meta into an infinite config dump; keep small, stable fields.

### Background cleanup

`ListFresh` lazily cleans on read. If nobody does lookup for hours, the map holds dead ones. A periodic ticker walks services and cleans — keeps memory under control.

### Multiple registry nodes (course boundary)

For production: consensus (etcd/Consul) or K8s. This course stops at one process. When you move to the platform, keep the same fields: service, id, url, health/TTL semantics.

### Testing the store without the network

Pass `now time.Time` into `ListFresh` instead of always `time.Now()` — deterministic tests. Handler tests with `httptest`. Do not mock time with a global patch if you can inject.

### Metrics that matter on the registry

- `register_total` / `deregister_total`
- `heartbeat_fail` (on the client side)
- `instances{service=}` gauge
- `expired_total`
- latency of `ListFresh`

Without a gauge you do not see whether TTL “flickers”.

### Concurrent store rules

- Keep `Mutex` short: copy the result slice, release the lock.
- Do not call the network under the lock.
- `Touch` on a nonexistent id → false → client should `Register` again (pod restarted, map empty after registry restart).

### Registry restart (lab truth)

In-memory restart empties the map. Instances discover that through failed heartbeat/Touch and Register again. So the heartbeat loop must handle “you are not registered” without panic — re-register.

### Relation to 12.01 principles

- Timeout on every registry HTTP call.
- Register upsert is idempotent for the same id.
- No shared memory: the registry is the external store for locations.
- Partial failure: registry down → discovery empty → 503, not an infinite hang.

## Rules and syntax

1. The registry itself must have timeout and body limits.
2. Do not blindly trust a URL from registration in prod without a policy.
3. Instance id: UUID or stable `hostname+port` while the process lives.
4. Shutdown: try DELETE, also rely on TTL.
5. Heartbeat interval < TTL (e.g. ⅓ TTL).
6. `json.Marshal` for the body — not `fmt.Sprintf` JSON in production.
7. Context of the register loop = process lifetime; on cancel → deregistration.
8. Registration after ready, not before.

## Examples

### Example 1 — Model and store

**Predict the result:** Two instances of the same `orders` service — how many inner maps and keys do you expect after two Upserts?

```go
package registry

import (
	"sync"
	"time"
)

type Instance struct {
	Service string            `json:"service"`
	ID      string            `json:"id"`
	URL     string            `json:"url"`
	Expire  time.Time         `json:"expire"`
	Meta    map[string]string `json:"meta,omitempty"`
}

type Store struct {
	mu   sync.Mutex
	data map[string]map[string]Instance // service -> id -> inst
}

func NewStore() *Store {
	return &Store{data: make(map[string]map[string]Instance)}
}

func (s *Store) Upsert(inst Instance) {
	s.mu.Lock()
	defer s.mu.Unlock()
	if s.data[inst.Service] == nil {
		s.data[inst.Service] = make(map[string]Instance)
	}
	s.data[inst.Service][inst.ID] = inst
}
```

#### What happens here

`Instance` records the service name, id, URL, expiry, and an optional meta map, with the JSON names from the struct tags. `Store` keeps them in a map of service name to a map of id to `Instance`, guarded by `mu`. `NewStore` allocates the outer map. `Upsert` locks, creates the inner map the first time a service appears, and stores `inst` under `inst.ID`, replacing any earlier record with that id.

**Answer:** One outer map with key `"orders"`, inside two keys (two ids). Upsert of the same id changes URL/Expire, does not create a third record.

### Example 2 — Register handler

**Predict the result:** What does the handler return on bad JSON, and what on a valid upsert?

```go
type registerReq struct {
	Service    string `json:"service"`
	ID         string `json:"id"`
	URL        string `json:"url"`
	TTLSeconds int    `json:"ttlSeconds"`
}

func (h *Handler) Register(w http.ResponseWriter, r *http.Request) {
	var in registerReq
	if err := json.NewDecoder(io.LimitReader(r.Body, 1<<16)).Decode(&in); err != nil {
		http.Error(w, "bad JSON", http.StatusBadRequest)
		return
	}
	if in.Service == "" || in.ID == "" || in.URL == "" || in.TTLSeconds <= 0 || in.TTLSeconds > 60 {
		http.Error(w, "invalid input", http.StatusBadRequest)
		return
	}
	h.Store.Upsert(Instance{
		Service: in.Service,
		ID:      in.ID,
		URL:     in.URL,
		Expire:  time.Now().Add(time.Duration(in.TTLSeconds) * time.Second),
	})
	w.WriteHeader(http.StatusNoContent)
}
```

#### What happens here

The handler decodes JSON from a body limited to `1<<16` bytes. Bad JSON, an empty service, id, or URL, or a `TTLSeconds` outside 1 through 60, writes status 400. Accepted input is stored with `Expire` set to `time.Now()` plus `TTLSeconds`. Success writes status 204 and an empty body.

**Answer:** 400 on bad input; 204 No Content on success. No persistence — registry restart empties memory (lab OK).

### Example 3 — Heartbeat and ListFresh

**Predict the result:** If `Expire` has passed, does `ListFresh` still return that instance?

```go
func (s *Store) Touch(service, id string, ttl time.Duration) bool {
	s.mu.Lock()
	defer s.mu.Unlock()
	m := s.data[service]
	if m == nil {
		return false
	}
	inst, ok := m[id]
	if !ok {
		return false
	}
	inst.Expire = time.Now().Add(ttl)
	m[id] = inst
	return true
}

func (s *Store) ListFresh(service string, now time.Time) []Instance {
	s.mu.Lock()
	defer s.mu.Unlock()
	var out []Instance
	for id, inst := range s.data[service] {
		if !inst.Expire.After(now) {
			delete(s.data[service], id)
			continue
		}
		out = append(out, inst)
	}
	return out
}

func (s *Store) Remove(service, id string) {
	s.mu.Lock()
	defer s.mu.Unlock()
	if m := s.data[service]; m != nil {
		delete(m, id)
	}
}
```

#### What happens here

`Touch` returns false when the service map or the id is absent. When the id is present, it sets `Expire` to `time.Now()` plus `ttl` and writes the struct back, because the local `inst` is a copy. `ListFresh` appends instances whose `Expire` is after `now` and deletes the others under the same lock. `Remove` deletes one id when that service map exists.

**Answer:** No — it expires and is deleted on list. `Touch` on an unknown id returns false (signal to re-register).

### Example 4 — Client: RegisterLoop

**Predict the result:** What happens on `ctx` cancel — and what if DELETE does not arrive?

```go
func RegisterLoop(ctx context.Context, registryURL, service, id, selfURL string) {
	client := &http.Client{Timeout: 2 * time.Second}
	ticker := time.NewTicker(5 * time.Second)
	defer ticker.Stop()

	payload := func(ttl int) ([]byte, error) {
		return json.Marshal(map[string]any{
			"service": service, "id": id, "url": selfURL, "ttlSeconds": ttl,
		})
	}

	send := func(path string) {
		body, err := payload(15)
		if err != nil {
			log.Println("marshal:", err)
			return
		}
		req, err := http.NewRequestWithContext(ctx, http.MethodPost, registryURL+path, bytes.NewReader(body))
		if err != nil {
			return
		}
		req.Header.Set("Content-Type", "application/json")
		res, err := client.Do(req)
		if err != nil {
			log.Println("registry:", err)
			return
		}
		res.Body.Close()
		if res.StatusCode >= 300 {
			log.Println("registry status", res.StatusCode)
		}
	}

	send("/register")
	for {
		select {
		case <-ctx.Done():
			body, _ := json.Marshal(map[string]string{"service": service, "id": id})
			req, err := http.NewRequestWithContext(context.Background(), http.MethodDelete, registryURL+"/register", bytes.NewReader(body))
			if err != nil {
				return
			}
			req.Header.Set("Content-Type", "application/json")
			cli := &http.Client{Timeout: 2 * time.Second}
			res, err := cli.Do(req)
			if err == nil {
				res.Body.Close()
			}
			return
		case <-ticker.C:
			send("/heartbeat")
		}
	}
}
```

#### What happens here

`RegisterLoop` uses an HTTP client with a two-second timeout and a ticker of five seconds. Each POST body is JSON for this service, id, URL, and a TTL of 15 seconds, sent first to `/register` and then to `/heartbeat` on each tick. Inside `send`, marshal and transport errors are logged, a status of 300 or higher is logged, and a failed `NewRequest` returns without a POST. The loop keeps going. When `ctx` is cancelled, the function sends `DELETE /register` with service and id on `context.Background()` through a separate two-second client, then returns.

**Answer:** On cancel it sends DELETE with a short Background timeout. If DELETE does not arrive (network, kill -9), TTL still cleans within ≤15 s. The loop does not panic on transient errors — it logs and continues.

### Example 5 — main of the registry process

**Predict the result:** Which routes must the mux expose so that 12.03 can do lookup?

```go
func main() {
	store := registry.NewStore()
	h := &registry.Handler{Store: store}
	mux := http.NewServeMux()
	mux.HandleFunc("POST /register", h.Register)
	mux.HandleFunc("POST /heartbeat", h.Heartbeat)
	mux.HandleFunc("DELETE /register", h.Deregister)
	mux.HandleFunc("GET /services/{name}", h.List)

	srv := &http.Server{
		Addr:              ":8500",
		Handler:           mux,
		ReadHeaderTimeout: 5 * time.Second,
	}
	go func() {
		t := time.NewTicker(30 * time.Second)
		defer t.Stop()
		for range t.C {
			_ = store.ListFresh("orders", time.Now())
			// in real code: iterate known services
		}
	}()
	log.Fatal(srv.ListenAndServe())
}
```

#### What happens here

`main` keeps instances in an in-memory `Store` and registers `POST /register`, `POST /heartbeat`, `DELETE /register`, and `GET /services/{name}`. The server listens on `:8500` with a five-second `ReadHeaderTimeout`. A background ticker calls `ListFresh` for `"orders"` every 30 seconds, which removes expired records of that service. `ListenAndServe` blocks on the main goroutine, and `log.Fatal` exits if it returns an error.

**Answer:** At least `GET /services/{name}` for the list. The other three for the instance lifetime. `ReadHeaderTimeout` is defense; the background ticker cleans memory.

### Example 6 — Heartbeat handler with re-register signal

**Predict the result:** Client gets 404 on heartbeat — what should it do?

```go
func (h *Handler) Heartbeat(w http.ResponseWriter, r *http.Request) {
	var in registerReq
	if err := json.NewDecoder(io.LimitReader(r.Body, 1<<16)).Decode(&in); err != nil {
		http.Error(w, "bad JSON", http.StatusBadRequest)
		return
	}
	ttl := time.Duration(in.TTLSeconds) * time.Second
	if in.TTLSeconds <= 0 {
		ttl = 15 * time.Second
	}
	if !h.Store.Touch(in.Service, in.ID, ttl) {
		http.Error(w, "unknown instance", http.StatusNotFound)
		return
	}
	w.WriteHeader(http.StatusNoContent)
}
```

#### What happens here

The handler decodes the body with the same `1<<16` limit. A `TTLSeconds` of zero or less becomes a 15-second TTL. A positive value is passed to `Touch` as that many seconds. `Touch` returning true finishes with status 204. `Touch` returning false writes status 404 and the text `unknown instance`.

**Answer:** Call `/register` again. Typical after registry restart or TTL expiry. RegisterLoop can on non-2xx heartbeat send register.

### Example 7 — Unit test ListFresh

**Predict the result:** Why does an injected `now` make the test stable?

```go
func TestListFreshExpires(t *testing.T) {
	s := NewStore()
	s.Upsert(Instance{Service: "orders", ID: "a", URL: "http://127.0.0.1:1", Expire: time.Unix(10, 0)})
	got := s.ListFresh("orders", time.Unix(11, 0))
	if len(got) != 0 {
		t.Fatalf("got %d", len(got))
	}
}
```

#### What happens here

The test upserts one `orders` instance whose `Expire` is Unix second 10. `ListFresh` is called with `now` at Unix second 11, so `Expire.After(now)` is false and the record is deleted. The test calls `t.Fatalf` if the returned slice is not empty.

**Answer:** No race with the wall clock. `Expire` in the past relative to `now` → empty list, determinism in CI.

## Decision analysis

| Decision | Why |
|--------|--------|
| HTTP + JSON | Simple, language-agnostic |
| TTL + heartbeat | Self-healing after crash |
| In-memory store | Focus on contract, not HA |
| Explicit DELETE | Faster removal on graceful stop |
| Service name + instance id | Multiple replicas of the same name |
| Cap TTL (e.g. 60 s) | Memory limits / stale risk |
| Re-register on 404 heartbeat | Survives registry restart |

## Trade-offs

- **Short TTL** — faster eviction of dead ones, more heartbeat traffic.
- **Long TTL** — less chattiness, slower death detection.
- **Push registry (this lesson)** vs **platform endpoints** — control vs operational simplicity.
- **One registry node** — SPOF in the lab; in prod you need HA.
- **Meta filters** — more powerful routing, more complex client.
- **Lazy cleanup** — simple; without a ticker the map grows if there is no read.

## Common mistakes

1. Heartbeat interval ≥ TTL — instances “flicker”.
2. Hardcoded IP that changes after pod restart.
3. No timeout on the registry client.
4. Trusting the registry as a security boundary without auth.
5. Registration before the server is ready to receive traffic (readiness — 12.04).
6. `fmt.Sprintf` for JSON (breaks on special characters in the URL).
7. Ignoring 404 on heartbeat (stays “silent” after registry restart).
8. Storing sensitive secrets in Meta.
9. List under Mutex returns the same slice that another goroutine later mutates without a copy.
10. TTL of several hours “so we don’t need heartbeat” — dead ones live forever in practice.

## Idiomatic Go

- Context for the register loop tied to process lifetime.
- `json.Marshal` for request bodies.
- Metrics: registration count, heartbeat fail, instance gauge.
- Log instance id on every event.
- `http.Server{ReadHeaderTimeout: ...}` on the registry.
- Package `registry` with Store + Handler — tested without `main`.

## Practical scenario

A team learns microservices locally. Instead of Consul immediately, they stand up this registry and three `orders` instances. Checkout learns discovery from a list of URLs. One student sets heartbeat 10 s and TTL 10 s — the list flickers, flaky tests. After fixing to 5/15, stable.

When they later move to K8s Service, the mental model remains: **name → set of endpoints → choice**. The registry lesson is not a waste of time — it is the contract. Second incident: they registered in `init` before DB migrate — discovery sent traffic during migration. Fix: gate + register after ready (12.04).

HA: one process = SPOF. Pedagogically OK. Production = etcd/Consul/K8s Endpoints.

## Deeper Mechanism: lifetime of one record

```text
Register (Expire = now+TTL)
    │
    ├─ Heartbeat ──► Expire = now+TTL   (repeat)
    │
    ├─ ListFresh ──► if Expire <= now → delete (lazy)
    │
    ├─ DELETE ──► remove immediately
    │
    └─ nothing ──► TTL expires ──► disappears from the list
```

Every branch must work. If you omit heartbeat, TTL saves you from eternal zombies. If you omit DELETE, deploy is slower but correct. If you omit ListFresh cleanup and ticker, memory grows.

### Capacity and DoS awareness (defense, not attack)

A teaching registry on a shared network without limits:

- an attacker (or bug) can register millions of ids;
- memory grows;
- ListFresh becomes slow.

Defense in lab/prod direction:

1. Auth (shared secret).
2. Max TTL.
3. Max instances per service (e.g. 100) — reject new register.
4. Rate limit on `/register`.
5. JSON body limit (you already have it).

This is hardening of your own service, not instructions for abuse.

### Example — max instances per service

**Predict the result:** Already has 100 instances; new Upsert with a **new** id — what?

```go
func (s *Store) UpsertLimited(inst Instance, max int) error {
	s.mu.Lock()
	defer s.mu.Unlock()
	m := s.data[inst.Service]
	if m == nil {
		m = make(map[string]Instance)
		s.data[inst.Service] = m
	}
	if _, exists := m[inst.ID]; !exists && len(m) >= max {
		return errTooMany
	}
	m[inst.ID] = inst
	return nil
}
```

#### What happens here

The method locks and creates the inner map when the service is new. A new id returns `errTooMany` when `len(m)` is already greater than or equal to `max`, and that id is left unstored. An id that is already in the map is updated even at that cap. Every path that stores the instance returns nil.

**Answer:** Error `errTooMany` (handler → 429/503). Upsert of an **existing** id still passes (heartbeat/register refresh).

### Example — Deregister handler

**Predict the result:** DELETE with an unknown id — is that an error?

```go
func (h *Handler) Deregister(w http.ResponseWriter, r *http.Request) {
	var in struct {
		Service string `json:"service"`
		ID      string `json:"id"`
	}
	if err := json.NewDecoder(io.LimitReader(r.Body, 1<<16)).Decode(&in); err != nil {
		http.Error(w, "bad JSON", http.StatusBadRequest)
		return
	}
	h.Store.Remove(in.Service, in.ID)
	w.WriteHeader(http.StatusNoContent)
}
```

#### What happens here

The handler decodes `service` and `id` from a body limited to `1<<16` bytes. Invalid JSON writes status 400. `Remove` then drops that id when the service map contains it, and the handler writes status 204.

**Answer:** Typically 204 even when it did not exist — idempotent deregistration. Desirable for retry DELETE on shutdown.

### Example — auth header (teaching)

**Predict the result:** Wrong token — status?

```go
func withToken(token string, next http.HandlerFunc) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		if r.Header.Get("X-Registry-Token") != token {
			http.Error(w, "unauthorized", http.StatusUnauthorized)
			return
		}
		next(w, r)
	}
}
```

#### What happens here

`withToken` returns a handler that reads the `X-Registry-Token` header and compares it with `token`. A different value writes status 401 and the text `unauthorized`, then returns. An equal value calls `next` with the same `ResponseWriter` and request.

**Answer:** 401. In the lab token from env; do not commit the secret. This is not production IAM — only awareness that the registry is not a public address pastebin.

### Clock skew and Expire

Registry and instances do not share an ideal clock. A 15 s TTL with 1–2 s skew still works if heartbeat is 5 s. Do not build logic on “Expire exactly in the same millisecond on all nodes”. ListFresh uses the **registry process clock** — that is the authority for that store.

### Observability of the register loop (client)

Log:

- register ok / fail
- heartbeat ok / 404 / transport error
- deregister ok / fail
- loop duration until first successful register

Metric `registry_heartbeat_fail` rises → either network, or registry restart, or TTL flickering.

### Frequently asked questions (FAQ)

**Why not a gRPC registry?**  
HTTP+JSON is readable with curl. The contract matters more than the transport.

**Why not embed etcd?**  
Ops and pedagogical noise. Contract first.

**Can the registry be an in-process library?**  
For one binary yes, but then there is no shared store between processes — you return to 12.01 “no shared memory”.

**What about IPv6 / hostname?**  
The URL must be reachable by the discovery client. `localhost` from pod A does not mean the same on pod B — a common lab trap.

## Summary

An HTTP registry remembers instances with TTL and heartbeat. A service registers and deregisters; crash is cleaned by TTL. Upsert is idempotent for the same id; 404 on heartbeat means re-register. Registration goes after ready. That is the skeleton for discovery.

# 10.14 Error Handling and Logging

> **Go Path - Zero to Gopher** / **02 Intermediate → Secure Coding in Go** / Lesson 10.14

## Lesson goals

After this lesson you should:

- log **internal detail** server-side (`slog`), and send the client a **generic** message
- not log secrets, passwords, tokens, full card numbers
- tie requests with a **request ID** for forensics without PII leakage
- map `error` to HTTP status consciously (400/401/403/404/409/500)
- connect this with confidentiality of operational detail and availability (no panic for expected cases)

## Prerequisite

- 10.01–10.13 vocabulary; `log/slog`; `error` values
- preferably 13.xx Managing Errors (later in the path)

## Problem this lesson solves

`http.Error(w, err.Error(), 500)` leaks connection string hints, SQL, paths. Conversely: swallowing error without log makes incidents blind. You need two channels: rich internal, poor public.

## Mental model

1. **error** — value for control flow.
2. **Log** — operators; may have detail + request ID.
3. **Client** — stable, generic message / code.
4. **Classification** — validation vs auth vs internal.
5. **No secrets in log** — defense in depth with redaction.

```text
err → slog.Error(..., "err", err, "req_id", id) → client: "request failed"
```

## Mechanism

### Two channels

| Channel | Content |
|-------|---------|
| slog | error type, stack per policy, SQL state without data, req_id |
| HTTP body | `bad request` / `unauthorized` / `request failed` |

### Request ID

Middleware generates ID (`crypto/rand` or ULID), puts in context and response header `X-Request-Id`. Support searches log by ID — no need for user to send stack.

### Mapping

| Situation | Status |
|-----------|--------|
| validation | 400 |
| no session | 401 |
| authz | 403 |
| not found (policy) | 404 |
| conflict | 409 |
| bug/DB down | 500/503 |

### Panic

`recover` in middleware — log + generic 500. Panic is not business validation.

### Trace

```text
handler err → classify → log with req_id → write generic body + status
```

## Rules

1. Never raw `err.Error()` to client in prod.
2. Always log server errors with req_id.
3. Do not log secrets/PII raw.
4. Map status consciously.
5. recover at HTTP boundary.
6. Same generic text for 500 where policy says.
7. SafeErr helper if string is required.

## Examples

### Example 1 — safe write

```go
func WriteInternal(w http.ResponseWriter, log *slog.Logger, reqID string, err error) {
	log.Error("internal", "err", err, "req_id", reqID)
	http.Error(w, "request failed", http.StatusInternalServerError)
}
```

#### What happens here

Two channels separated.

### Example 2 — req ID middleware

```go
func RequestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id, _ := NewToken(16) // from 10.05 style
		ctx := context.WithValue(r.Context(), ctxReqID, id)
		w.Header().Set("X-Request-Id", id)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}
```

#### What happens here

Correlation without stack in UI.

### Example 3 — SafeErr

```go
func SafeErr(err error) string {
	if err == nil {
		return ""
	}
	return "request failed"
}
```

#### What happens here

If API requires string, do not pass Error().

### Example 4 — recover

```go
defer func() {
	if rec := recover(); rec != nil {
		log.Error("panic", "rec", rec, "req_id", id)
		http.Error(w, "request failed", 500)
	}
}()
```

#### What happens here

Process lives; client does not see panic string.

## Decision analysis

| Decision | Why |
|--------|-------|
| Generic 500 | confidentiality |
| slog + req_id | operational integrity |
| Status classification | UX + no leakage |
| recover | process availability |

## Trade-offs

- **Generic messages** make client debug harder — req_id compromise.
- **More logging** = PII retention risk — mask (10.09).
- **404 vs 403** privacy vs clarity.

## Common mistakes

1. err.Error() to client.
2. Authorization in log.
3. No req_id.
4. Swallow err without log.
5. Panic for validation.
6. Different 500 texts that reveal branch.
7. Log entire Request.
8. Stack in JSON API prod.
9. Wrong slog level (Error for expected 401 spam).
10. Duplicate log without structure.

## Idiomatic Go

- `log/slog` structured.
- Middleware RequestID + Recover.
- Wrap `fmt.Errorf("repo: %w", err)` internally.
- Test that handler body does not contain "sql:".

## Practical scenario

API returns pq: detail password. WAF/log scraper collects. Team introduces WriteInternal, req_id, redaction. Incidents resolved faster via ID; clients no longer see SQL.

### `errors.Unwrap` in slog

Internal slog may use `fmt.Errorf("repo: %w", err)` chain; client still sees only generic message.

### API focus: log/slog Error

Structured log with Error level for failures — fields without PII.

```go
slog.Error("order create failed",
	slog.String("request_id", reqID),
	slog.String("op", "CreateOrder"),
	slog.Any("err", err),
)
```

### API focus: errors.Is map

Map sentinel errors to HTTP status internally.

```go
if errors.Is(err, ErrNotFound) {
	http.Error(w, "not found", 404)
	return
}
if errors.Is(err, ErrForbidden) {
	http.Error(w, "forbidden", 403)
	return
}
http.Error(w, "internal error", 500)
```

### API focus: recover middleware

```go
func Recover(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if rec := recover(); rec != nil {
				slog.Error("panic", "request_id", RequestID(r), "recover", rec)
				WriteInternal(w)
			}
		}()
		next.ServeHTTP(w, r)
	})
}
```

### API focus: X-Request-Id

```go
func RequestID(r *http.Request) string {
	id := r.Header.Get("X-Request-Id")
	if id == "" {
		id = uuid.New().String()
	}
	return id
}
```

### API focus: redact log fields

```go
func Redact(key, val string) slog.Attr {
	if key == "password" || key == "token" {
		return slog.String(key, "[REDACTED]")
	}
	return slog.String(key, val)
}
```

### API focus: errors.Join batch

```go
func validateAll(in Batch) error {
	var errs []error
	for i, row := range in.Rows {
		if err := row.Validate(); err != nil {
			errs = append(errs, fmt.Errorf("row %d: %w", i, err))
		}
	}
	return errors.Join(errs...)
}
```

Client still gets stable code — not raw join string.

### API focus: 401 vs 403 map (handler)

```go
func writeAuthError(w http.ResponseWriter, err error) {
	if errors.Is(err, ErrUnauthorized) {
		http.Error(w, "unauthorized", http.StatusUnauthorized)
		return
	}
	if errors.Is(err, ErrForbidden) {
		http.Error(w, "forbidden", http.StatusForbidden)
		return
	}
	WriteInternal(w)
}
```

### API focus: panic log only

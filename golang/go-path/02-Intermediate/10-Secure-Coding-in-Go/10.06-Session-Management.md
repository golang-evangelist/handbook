# 10.06 Session Management

> **Go Path - Zero to Gopher** / **02 Intermediate → Secure Coding in Go** / Lesson 10.06

## Lesson goals

After this lesson you should:

- issue **unpredictable** session IDs from `crypto/rand` and keep state on the server
- set cookie attributes: `HttpOnly`, `Secure`, `SameSite`
- **rotate** session ID after successful login (no fixation recipe — defense only)
- implement proper logout (store + cookie)
- connect TTL / idle timeout with confidentiality and least privilege of time

## Prerequisite

- 10.05 (login, crypto/rand); `net/http` cookie API
- understanding HTTPS in production (Secure flag)

## Problem this lesson solves

Authentication without good session management leaves “logged in” proof in a predictable cookie or in a JWT you cannot revoke. Session management closes: who is the principal after login, how long it is valid, how it is turned off, and how the cookie does not leak to JS without need.

## Mental model

1. **Opaque ID** — random string; server maps ID → userID + meta.
2. **Server-side store** — Redis/DB/memory; revoke = delete record.
3. **Cookie flags** — HttpOnly (not readable from JS), Secure (HTTPS only), SameSite (limit cross-site sending).
4. **Rotation after login** — new ID, old invalid; reduces risk of a taken pre-login ID.
5. **Logout** — delete store + expire cookie.

```text
login OK → NewToken → store[sid]=session → Set-Cookie (flags) → later Resolve(sid)
logout → delete store → MaxAge=-1
```

## Mechanism

### Cookie attributes

```go
http.SetCookie(w, &http.Cookie{
	Name:     "sid",
	Value:    sid,
	Path:     "/",
	HttpOnly: true,
	Secure:   true, // true in production with HTTPS
	SameSite: http.SameSiteLaxMode, // or Strict per UX
	MaxAge:   int(ttl.Seconds()),
})
```

| Attribute | Role |
|---------|-------|
| HttpOnly | JS does not read cookie → smaller XSS impact on sid theft |
| Secure | cookie only over HTTPS → confidentiality in transit |
| SameSite | limits sending from another site → reduces CSRF surface |
| MaxAge/Expires | TTL |

SameSite is not a replacement for CSRF token on all mutations — defense in depth.

### Why server-side store

JWT-only in localStorage: harder revoke before expiry; XSS reads token. Opaque sid + store: support deletes all sid for account immediately. Integrity “who is logged in” stays on server.

### Rotation after login

Before login the browser may have a sid. After successful login:

1. issue **new** sid
2. save session bound to authenticated user
3. invalidate old sid if it existed

That closes the class of problem where someone plants a known pre-auth ID — without offensive recipe: you learn only the server habit of rotation.

### Resolve trace

```text
1. Read cookie sid
2. Bounds on length
3. Lookup store
4. Check ExpiresAt / idle
5. WithPrincipal(ctx, ...)
6. next handler
```

### Idle vs absolute TTL

- Absolute: max lifetime from login.
- Idle: extend on activity, with absolute ceiling.

Least privilege of time: shorter TTL for admin sessions.

### Session fixation — impact and defense only

Impact if you do not rotate: an attacker who pre-sets sid for victim may stay bound after login. **Defense you learn:** always new sid after authentication; delete old. No attack steps.

### CSRF and SameSite

SameSite=Lax covers many cross-site POST cases in modern browsers, but forms and API with custom header policy still need CSRF strategy for cookie sessions. Do not rely on one flag alone.

### Store interface

```go
type Store interface {
	Put(ctx context.Context, sid string, s Session) error
	Get(ctx context.Context, sid string) (Session, error)
	Delete(ctx context.Context, sid string) error
}
```

In-memory for test; Redis for prod. Least privilege Redis ACL.

### Link to 10.05 and 10.07

Login (10.05) → CreateRotated session → middleware Resolve → Principal → authz (10.07).

## Rules

1. Sid from crypto/rand, long enough.
2. HttpOnly + Secure (prod) + SameSite explicit.
3. Rotation after login.
4. Logout deletes store and cookie.
5. TTL mandatory; idle if needed.
6. Do not put userID as cookie value.
7. Do not log sid in full if you can hash/prefix.

## Examples

### Example 1 — Session and memory store

```go
package session

import (
	"context"
	"crypto/rand"
	"encoding/base64"
	"fmt"
	"sync"
	"time"
)

type Session struct {
	UserID    string
	ExpiresAt time.Time
}

type MemoryStore struct {
	mu sync.Mutex
	m  map[string]Session
}

func NewMemoryStore() *MemoryStore {
	return &MemoryStore{m: make(map[string]Session)}
}

func newSID() (string, error) {
	b := make([]byte, 32)
	if _, err := rand.Read(b); err != nil {
		return "", err
	}
	return base64.RawURLEncoding.EncodeToString(b), nil
}

func (s *MemoryStore) Create(ctx context.Context, userID string, ttl time.Duration) (string, error) {
	sid, err := newSID()
	if err != nil {
		return "", err
	}
	s.mu.Lock()
	defer s.mu.Unlock()
	s.m[sid] = Session{UserID: userID, ExpiresAt: time.Now().Add(ttl)}
	return sid, nil
}

func (s *MemoryStore) Get(_ context.Context, sid string) (Session, error) {
	s.mu.Lock()
	defer s.mu.Unlock()
	sess, ok := s.m[sid]
	if !ok || time.Now().After(sess.ExpiresAt) {
		return Session{}, fmt.Errorf("not found")
	}
	return sess, nil
}

func (s *MemoryStore) Delete(_ context.Context, sid string) error {
	s.mu.Lock()
	defer s.mu.Unlock()
	delete(s.m, sid)
	return nil
}
```

#### What happens here

Opaque sid; TTL in store; Delete for logout. Mutex protects map in test store.

### Example 2 — SetCookie and rotation

```go
func (h *Handler) establish(w http.ResponseWriter, r *http.Request, userID string) error {
	if old, err := r.Cookie("sid"); err == nil && old.Value != "" {
		_ = h.store.Delete(r.Context(), old.Value)
	}
	sid, err := h.store.Create(r.Context(), userID, 12*time.Hour)
	if err != nil {
		return err
	}
	http.SetCookie(w, &http.Cookie{
		Name:     "sid",
		Value:    sid,
		Path:     "/",
		HttpOnly: true,
		Secure:   h.cfg.SecureCookies,
		SameSite: http.SameSiteLaxMode,
		MaxAge:   int((12 * time.Hour).Seconds()),
	})
	return nil
}
```

#### What happens here

Old sid deleted; new issued; flags explicit. Secure from config (prod true).

func (h *Handler) RequireSession(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		c, err := r.Cookie("sid")
		if err != nil || len(c.Value) < 16 || len(c.Value) > 128 {
			http.Error(w, "unauthorized", http.StatusUnauthorized)
			return

### Example 4 — logout

```go
func (h *Handler) Logout(w http.ResponseWriter, r *http.Request) {
	if c, err := r.Cookie("sid"); err == nil {
		_ = h.store.Delete(r.Context(), c.Value)
	}
	http.SetCookie(w, &http.Cookie{Name: "sid", Value: "", Path: "/", MaxAge: -1, HttpOnly: true, Secure: h.cfg.SecureCookies, SameSite: http.SameSiteLaxMode})
	w.WriteHeader(http.StatusNoContent)
}
```

#### What happens here

Store and cookie. Stolen sid after logout does not Resolve.

## Decision analysis

| Decision | Why |
|--------|-------|
| Opaque sid + store | revoke, server truth |
| HttpOnly Secure SameSite | reduced blast radius |
| Login rotation | defense against pre-auth ID |
| TTL | least privilege of time |
| Bounds sid | 10.03 hygiene |

## Trade-offs

- **Strict SameSite** breaks some OAuth redirect flows — choose Lax/Strict deliberately.
- **Server store** = infrastructure; sticky session less important if store is shared.
- **Short TTL** more logins (UX) vs smaller theft window.
- **Secure false** locally vs prod config — configuration mistake is common.

## Common mistakes

1. userID in cookie value.
2. No HttpOnly.
3. Logout only deletes cookie.
4. No rotation after login.
5. Infinite TTL.
6. Logging full sid.
7. Secure false in production.
8. Session in global map without mutex/TTL.
9. Believing SameSite replaces all CSRF controls.
10. One sid shared across all devices without per-device revoke.

## Idiomatic Go

- `http.Cookie` explicit fields.
- interface `Store` for test double.
- Context principal, not goroutine-local hack.
- Test: Create → Get → Delete → Get fail.

## Practical scenario

E-commerce “remember me” with plain userID. Transition: opaque sid, Redis TTL 12h, flags, rotation on login. On device theft report support deletes all sid for account — access drops immediately.

### API focus: http.Cookie HttpOnly

Session cookie with `HttpOnly` prevents JavaScript access — reduces sid theft risk via XSS (output encoding still required).

```go
func sessionCookie(sid string, maxAge int) *http.Cookie {
	return &http.Cookie{
		Name:     "sid",
		Value:    sid,
		Path:     "/",
		MaxAge:   maxAge,
		HttpOnly: true,
		Secure:   true,
		SameSite: http.SameSiteLaxMode,
	}
}
```

### API focus: http.Cookie Secure

`Secure` flag sends cookie only over HTTPS. In local dev document exception — in staging/prod fail closed without TLS.

### API focus: http.SameSite

`SameSite=Lax` or `Strict` reduces CSRF surface. `None` requires `Secure` — use only if cross-site flow truly must.

### API focus: server store Resolve

Server-side session — state in Redis/DB, cookie carries only opaque ID.

```go
type SessionStore interface {
	Create(ctx context.Context, p Principal, ttl time.Duration) (sid string, err error)
	Resolve(ctx context.Context, sid string) (Principal, error)
	Revoke(ctx context.Context, sid string) error
}
```

### API focus: session TTL

Absolute TTL + optional idle timeout in store logic.

```go
func (s *RedisStore) Resolve(ctx context.Context, sid string) (Principal, error) {
	rec, err := s.get(ctx, sid)
	if err != nil || rec.ExpiresAt.Before(time.Now()) {
		return Principal{}, ErrSessionExpired
	}
	if time.Since(rec.LastSeen) > s.idleLimit {
		_ = s.Revoke(ctx, sid)
		return Principal{}, ErrSessionExpired
	}
	_ = s.touch(ctx, sid)
	return rec.Principal, nil
}
```

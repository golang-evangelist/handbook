# 10.12 Database Security

> **Go Path - Zero to Gopher** / **02 Intermediate → Secure Coding in Go** / Lesson 10.12

## Lesson goals

After this lesson you should:

- use **parameterized queries** (`database/sql` placeholders), not SQL concatenation
- give the runtime DB account **least privilege** (no DDL)
- separate the migration account from the runtime account
- use an allow-list for dynamic identifiers (SORT columns)
- set `context` timeout on queries
- explain the impact of string-embedded SQL: the database interprets user text as command

## Prerequisite

- 10.03, 10.07; `database/sql` or pgx
- basic SQL

## Problem this lesson solves

When user text is embedded in an SQL string, the database may interpret it as part of the command — query integrity and data confidentiality fail. An overly broad DB account turns one bug into DROP TABLE. Defense: placeholder + narrow rights + timeout + authz filter.

## Mental model

1. **Query is a template in code** — structure fixed.
2. **Data are arguments** — `$1`, `?`.
3. **Runtime ≠ migrator**.
4. **Authz before / in query** — `owner_id=$2`.
5. **Timeout** — availability.

## Mechanism

### Parameterization

```go
db.QueryContext(ctx, `SELECT id, email FROM users WHERE id = $1`, id)
```

The driver sends structure and data separately. User quotes do not close a string literal in SQL.

### Impact of concatenation (without payloads)

`fmt.Sprintf("... WHERE name='%s'", name)` — if `name` contains SQL metacharacters, the meaning of the command changes. Fix: `$1` + argument.

### Allow-list identifiers

```go
switch sort {
case "created_at", "updated_at":
default:
	return err
}
```

### Least privilege

| Account | Rights |
|-------|-------|
| app_runtime | SELECT/INSERT/UPDATE as needed |
| migrator | DDL on deploy |
| analytics_ro | SELECT view |

### Trace


### TLS to database

`sslmode=require` (or equivalent) — confidentiality in transit to DB (10.10 spirit).

## Rules

1. Placeholders only for values.
2. Allow-list for dynamic column names.
3. Context timeout on queries.
4. Runtime without DDL.
5. TLS to database where supported.
6. Do not log DSN with password.
7. owner_id in query where needed.

## Examples

### Example 1 — correct Query

```go
func (r *Repo) EmailByID(ctx context.Context, id string) (string, error) {
	ctx, cancel := context.WithTimeout(ctx, 3*time.Second)
	defer cancel()
	var email string
	err := r.db.QueryRowContext(ctx,
		`SELECT email FROM users WHERE id=$1`, id).Scan(&email)
	return email, err
}
```

#### What happens here

Placeholder + timeout. id is an argument.

### Example 2 — insert

```go
_, err := db.ExecContext(ctx,
	`INSERT INTO orders (id, owner_id, total) VALUES ($1,$2,$3)`,
	id, owner, total)
```

#### What happens here

All values parameterized.

### Example 3 — sort allow-list

```go
col, err := sortColumn(userInput)
```

#### What happens here

## Decision analysis

| Decision | Why |
|--------|-------|
| Placeholders | SQL integrity |
| Separate accounts | least privilege |
| Timeout | availability |
| owner in SQL | defense in depth |

## Trade-offs

- **Allow-list sort** limits UX flexibility.
- **Narrow GRANT** requires privilege migrations.
- **Short timeout** breaks slow reports — separate account/queue.

## Common mistakes

1. Sprintf SQL with input.
2. Superuser runtime.
3. No timeout.
4. Dynamic ORDER BY without allow-list.
5. Log DSN.
6. sslmode=disable in prod.
7. One account for all services.
8. Believing validation replaces placeholder.
9. String build IN (...) lists without placeholder per element.
10. Migrations from app start with runtime account.

## Idiomatic Go

- `QueryContext` / `ExecContext` always.
- Repo package; SQL in constants.
- Tests with sqlmock or test container — verify arguments are sent.

## Practical scenario

Search by name with concatenation. Move to `$1`, runtime account without DROP, migrator in CI. Catalog integrity and availability timeout improved.

### Statement timeout on DB side

Besides `QueryContext`, Postgres `statement_timeout` on the runtime account is a second availability layer — prevents a runaway query from holding connections.

### API focus: db.QueryContext

All queries with `context` — timeout and cancel propagate to the DB call.

```go
func (r *Repo) GetOrder(ctx context.Context, id uuid.UUID, ownerID string) (Order, error) {
	const q = `SELECT id, amount_cents FROM orders WHERE id = $1 AND owner_id = $2`
	row := r.db.QueryRowContext(ctx, q, id, ownerID)
	var o Order
	err := row.Scan(&o.ID, &o.AmountCents)
	return o, err
}
```

### API focus: db.ExecContext

Mutations also parameterized — never `fmt.Sprintf` with user string in SQL.

```go
const ins = `INSERT INTO orders (id, owner_id, status) VALUES ($1, $2, $3)`
_, err := r.db.ExecContext(ctx, ins, id, ownerID, status)
```

### API focus: allow-list ORDER BY

```go
func orderClause(sort string) (string, error) {
	switch sort {
	case "created_at":
		return "ORDER BY created_at DESC", nil
	case "amount":
		return "ORDER BY amount_cents DESC", nil
	default:
		return "", fmt.Errorf("sort_invalid")
	}
}
```

### Example: repo with always owner filter

```go
func (r *Repo) ListNotes(ctx context.Context, ownerID string, limit int) ([]Note, error) {
	const q = `SELECT id, body FROM notes WHERE owner_id = $1 ORDER BY created_at DESC LIMIT $2`
	rows, err := r.db.QueryContext(ctx, q, ownerID, limit)
	if err != nil {
		return nil, err
	}
	defer rows.Close()
	var out []Note
	for rows.Next() {
		var n Note
		if err := rows.Scan(&n.ID, &n.Body); err != nil {
			return nil, err
		}
		out = append(out, n)
	}
	return out, rows.Err()
}
```

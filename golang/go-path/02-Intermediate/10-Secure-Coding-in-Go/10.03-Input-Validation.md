# 10.03 Input Validation

> **Go Path - Zero to Gopher** / **02 Intermediate → Secure Coding in Go** / Lesson 10.03

## Lesson goals

After this lesson you should:

- validate input with an **allow-list** approach instead of ad-hoc “strip dangerous characters”
- use `strconv` and strict types instead of blindly passing `string` values through
- enforce maximum lengths and ranges; reject overflow instead of “silently truncating” without policy
- structure validation to return clear, stable per-field errors
- understand where validation sits relative to output encoding (10.04) and authorization (10.07)
- connect validation to input integrity and availability (request body limits)

## Prerequisite

- Go 1.22+, `net/http`, JSON decode into struct
- lessons 10.01 and 10.02
- `error` as value; table-driven tests desirable

## Problem this lesson solves

Untrusted input arrives from HTTP body, query string, headers, path values, file names, and queue messages. If you pass it on unchecked, later controls (SQL, HTML, paths) operate under bad assumptions. Validation is the first defensive line at the trust boundary to the client.

Common mistake: “sanitize” with a series of `strings.Replace` that removes parts of text. That is brittle, incomplete, and creates a false sense of security. Correct pattern: **define what is allowed**, check type/range/length, **reject** if it does not match.

## Mental model

Input is **data + claim**. Your job is to verify the claim:

1. **Type** — is the number really a number (`strconv`), not “123abc” silently?
2. **Range** — age 13–120, not negative price amount?
3. **Length** — body and string fields have upper bound?
4. **Allow-list** — status only `pending|paid|canceled`?
5. **Format semantics** — UUID / canonical ID, not arbitrary blob?
6. **Separate from authz** — “valid UUID” ≠ “you may see that row.”

```text
bytes from network
   → MaxBytesReader (availability)
   → decode to type (syntax integrity)
   → domain validation allow-list/range (semantic integrity)
   → authz (10.07)
   → storage / template
```

## Mechanism

### Why allow-list, not deny-list

Deny-list (“block some characters”) always lags new input shapes and is easily bypassed with other encoding. Allow-list says: *only these values / this character class / this range*. Everything else is error.

Enumeration example:

```go
var allowedStatus = map[string]struct{}{
	"pending":  {},
	"paid":     {},
	"canceled": {},
}

func validStatus(s string) bool {
	_, ok := allowedStatus[s]
	return ok
}
```

`map[string]struct{}` is idiomatic set; zero value lookup is `false` — deny by default.

### strconv instead of silent conversion

`strconv.Atoi`, `ParseInt`, `ParseUint`, `ParseBool`, `ParseFloat` return `error`. Ignoring error turns garbage into zero and hides the problem—integrity fails and the bug looks like a “business zero.”

```go
n, err := strconv.Atoi(raw)
if err != nil {
	return fmt.Errorf("count: %w", err)
}
if n < 0 || n > 1000 {
	return fmt.Errorf("count out of range")
}
```

### Layers of checks

1. **Transport** — `http.MaxBytesReader` / limit at reverse proxy.
2. **Syntax** — `json.Decoder` into strict struct; `DisallowUnknownFields` per policy.
3. **Domain** — allow-list, regex only when must (and length before regex).
4. **Authz** — separate layer; validation is not permission.

### Reject, do not “clean” with replace

Ad-hoc `Replace(s, "<", "", -1)` does not make HTML safe (that is 10.04) and does not make SQL safe (10.12). Validation decides *whether we accept*; encoding and placeholders protect *context*.

### Trace: JSON order validation

```text
1. MaxBytesReader 1 MiB
2. Decoder.Decode(&CreateOrder)
3. TrimSpace on fields where policy says
4. len(Email) bounds + format
5. AmountCents Parse/range
6. Status allow-list (if client may send)
7. if any field fails → 400 + stable error code
8. only then servis.Create
```

```go

```

### Predict, then check (2)

```go
func clean(s string) string {
	s = strings.ReplaceAll(s, "'", "")
	s = strings.ReplaceAll(s, ";", "")
	return s
}
// then: query = "SELECT ... WHERE name='" + clean(name) + "'"
```

<details>
<summary>Answer</summary>

That is not validation or safe SQL. Removing some characters does not close the problem class and breaks legitimate names. Fix: placeholder in `database/sql` (10.12) + allow-list / length for `name` as data.

</details>

### Path value and query

Go 1.22+ `r.PathValue("id")` still returns string. Check length and format before putting it in query as argument (argument yes—concatenation no).

### Normalization

Trim, lowercase local part of email policy, Unicode normalization—do **before** comparison, but check bounds on *normalized* form so oversized input does not pass after transform.

### Structured error

```go
type FieldError struct {
	Field string `json:"field"`
	Code  string `json:"code"`
}

type ValidationError struct {
	Fields []FieldError `json:"fields"`
}

func (e ValidationError) Error() string { return "validation failed" }
```

Client gets stable `code` values (`email_invalid`), not stack. Detail for log stays internal (10.14).

### Availability: body limit

```go
r.Body = http.MaxBytesReader(w, r.Body, 1<<20) // 1 MiB
```

Without limit, large body consumes memory and time—availability. After limit, `Decode` returns error you map to 413/400 per policy.

### Predict, then check (3)

```go
var m map[string]any
_ = json.NewDecoder(r.Body).Decode(&m)
email, _ := m["email"].(string)
```

<details>
<summary>Answer</summary>

You lose type check; assertion silently gives zero value; unknown fields pass. Prefer struct + explicit field validation.

</details>

### Regex caution

Regex for email or URL often accepts wrong or rejects wrong and can be expensive (availability). Prefer: length + `net/mail.ParseAddress` or simple allow for local ID format. If regex must: first `len`, then regex, with timeout policy where relevant.

### Link to CIA

| Check | Goal |
|---------|------|
| Type and range | integrity of domain data |
| Max bytes | availability |
| Allow-list status | integrity of state machine |
| Stable error without internals | confidentiality of detail |

### Length: bytes versus runes

`len(s)` counts bytes. For user text limits often mean characters:

```go
if utf8.RuneCountInString(s) > 100 {
	return fmt.Errorf("too_long")
}
```

For ID that must be ASCII hex, byte `len` + allowed charset is fine.

### Predict, then check (4) — silent truncate

```go
if len(bio) > 200 {
	bio = bio[:200]
}
```

<details>
<summary>Answer</summary>

Silent truncation can keep partial Unicode (panic on later slice) or hide that client sent too much. Better policy: return `too_long` and let client shorten. If truncate must, document and cut by runes safely.

</details>

### Predict, then check (5) — boolean from string

```go
active := r.URL.Query().Get("active") == "true"
```

<details>
<summary>Answer</summary>

`"TRUE"`, `"1"`, `"yes"` become false without error—or the opposite when extended. Use `strconv.ParseBool` and 400 on error, or allow-list exactly `true|false`.

</details>

### Headers as input

`Authorization`, `Content-Type`, `Idempotency-Key`, custom `X-*` — all untrusted input. Bounds on header value length; do not log full Authorization. Authn middleware parses token after length check.

### Multipart / file name

Client file name is not disk path (see 10.13). Validation: length, allowed extension per policy, server generates storage key. Never use raw name as relative path.

### Trace: query pagination

```text
page raw → Atoi → err? 400
page < 1? 400
page > 1000? 400
limit raw → Atoi → [1,100]
offset = (page-1)*limit  // now int, no string SQL
```

### Error encoder to JSON API

```go
func writeValidation(w http.ResponseWriter, fields []FieldError) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusBadRequest)
	_ = json.NewEncoder(w).Encode(ValidationError{Fields: fields})
}
```

Response integrity: always JSON object, not mix of plain text and JSON.

### Fuzz as defensive ally (brief)

`testing.F` / fuzz on `Validate` helps find panics and unexpected passes. Fuzz is not attack on production—local test. Add seeds at edges: empty, max len, unicode.

### Link validation and least privilege

Valid `role=admin` in JSON body **does not** grant admin. That is only a field authz ignores or rejects. Least privilege: server derives roles from session store, not from body allow-list the client picks.

## Rules

1. Decode to type; do not keep `map[string]any` longer than needed.
2. Cap string lengths and slice sizes.
3. `strconv` / decode with `error` check.
4. Allow-list for enumerations; reject everything else.
5. Do not “sanitize” with replace as substitute for SQL/HTML controls.
6. Validation at boundary; inner code receives already checked DTO.
7. `MaxBytesReader` on body before decode.
8. Authz is separate step after format validation.

## Examples

### Example 1 — DTO and Validate method

```go
package orders

import (
	"fmt"
	"strings"
	"unicode/utf8"
)

type CreateOrder struct {
	Email       string
	AmountCents int
	Status      string
}

func (c CreateOrder) Validate() error {
	email := strings.TrimSpace(c.Email)
	if email == "" || utf8.RuneCountInString(email) > 254 {
		return fmt.Errorf("email_invalid")
	}
	if !strings.Contains(email, "@") { // rough check; production: stricter parser
		return fmt.Errorf("email_invalid")
	}
	if c.AmountCents < 1 || c.AmountCents > 100_000_00 {
		return fmt.Errorf("amount_out_of_range")
	}
	switch c.Status {
	case "pending", "paid":
	default:
		return fmt.Errorf("status_invalid")
	}
	return nil
}
```

#### What happens here

Allow-list status, amount range, email length. Errors are codes—suitable for mapping to JSON fields. No replace “cleaning.”

### Example 2 — HTTP handler with MaxBytesReader and strconv

```go
package httpapi

import (
	"encoding/json"
	"net/http"
	"strconv"
)

func (h *Handler) List(w http.ResponseWriter, r *http.Request) {
	raw := r.URL.Query().Get("limit")
	if raw == "" {
		raw = "20"
	}
	limit, err := strconv.Atoi(raw)
	if err != nil || limit < 1 || limit > 100 {
		http.Error(w, "bad request", http.StatusBadRequest)
		return
	}
	// ... use limit as int in query with placeholder
	_ = limit
	w.WriteHeader(http.StatusNoContent)
}

func (h *Handler) Create(w http.ResponseWriter, r *http.Request) {
	r.Body = http.MaxBytesReader(w, r.Body, 1<<20)
	defer r.Body.Close()

	var in CreateOrder
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()
	if err := dec.Decode(&in); err != nil {
		http.Error(w, "bad request", http.StatusBadRequest)
		return
	}
	if err := in.Validate(); err != nil {
		http.Error(w, "bad request", http.StatusBadRequest)
		return
	}
	w.WriteHeader(http.StatusCreated)
}
```

#### What happens here

Query `limit` becomes strict int with range. Body is limited. Unknown JSON fields fail when that is policy. Client sees generic 400; log may record `err` internally.

### Example 3 — allow-list sort column (before SQL)

```go
func sortColumn(user string) (string, error) {
	switch user {
	case "created_at", "updated_at", "amount_cents":
		return user, nil
	default:
		return "", fmt.Errorf("sort_invalid")

```

#### What happens here

Identifiers in SQL are often not parameterized like values. So allow-list returns *only* known string from code. User text never enters `ORDER BY` concatenation outside this function (see 10.12).

## Decision analysis

| Decision | Why |
|--------|-------|
| Allow-list | predictable set; deny by default |
| strconv + range | integrity of numeric filters |
| MaxBytesReader | availability |
| Reject instead of replace | no false security |
| Error codes | stable API, no internal leak |
| Validate on DTO | single source of truth for domain |

## Trade-offs

- **Strict validation** can break legacy clients—version API or transitional period.
- **DisallowUnknownFields** protects from type mistakes but complicates forward-compatible fields—team policy.
- **Regex** for rich formats adds CPU and maintenance.
- **Collecting all FieldError** better UX, more code than fail-fast on first field.

## Common mistakes

1. Deny-list characters as “sanitize.”
2. Ignoring `strconv` / `Decode` error.
3. Everything as `string` to database.
4. No length / body size limit.
5. Mixing validation and authorization.
6. Silently truncating string without error.
7. Validation only on frontend.
8. User string in SQL identifier without allow-list.
9. Returning raw `err.Error()` from parser to client.
10. Regex without prior length check.

## Idiomatic Go

- `Validate() error` on DTO in same package as domain.
- Table-driven tests for range boundaries.
- `json.Decoder` over `r.Body`, not `ReadAll` + `Unmarshal` without limit.
- `utf8.RuneCountInString` when limits mean user characters, not bytes.
- Stable sentinels/codes handler maps to HTTP 400.

## Practical scenario

CSV import API accepts “any” row then pushes into SQL by concatenation. After database integrity incident, team adds: MaxBytes on upload, parse into typed rows, allow-list columns, `strconv` for quantities, reject row with error instead of replacing quotes. Availability rises because 200 MB upload no longer passes; row integrity rises because status is no longer free text.

### API focus: net/http.MaxBytesReader

`MaxBytesReader` prevents unbounded request body from exhausting process memory—availability control before any `json.Decoder`. Fail closed: exceeding limit stops read; handler returns generic `400 Bad Request`.

```go
package validatehttp

import (
	"encoding/json"
	"net/http"
)

const maxCreateBody = 1 << 20 // 1 MiB

type CreateOrder struct {
	Email       string `json:"email"`
	AmountCents int64  `json:"amount_cents"`
	Status      string `json:"status"`
}

func (h *Handler) CreateOrder(w http.ResponseWriter, r *http.Request) {
	r.Body = http.MaxBytesReader(w, r.Body, maxCreateBody)
	defer r.Body.Close()

	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()
	var in CreateOrder
	if err := dec.Decode(&in); err != nil {
		http.Error(w, "bad request", http.StatusBadRequest)
		return
	}
	if err := in.Validate(); err != nil {
		http.Error(w, "bad request", http.StatusBadRequest)
		return
	}
	w.WriteHeader(http.StatusCreated)
}
```

### API focus: encoding/json.Decoder

Decoder streams JSON instead of loading whole body into memory. `DisallowUnknownFields` protects API contract integrity—unknown field fails immediately instead of silently passing into map.

```go
func decodeStrict(r *http.Request, dst any) error {
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()
	return dec.Decode(dst)
}
```

### API focus: strconv.ParseInt

Numeric query parameters must pass `ParseInt`/`ParseUint` with explicit range. Ignoring `err` turns `"abc"` into zero and breaks business logic and SQL filters.

```go
func parseLimit(raw string) (int, error) {
	if raw == "" {
		return 20, nil
	}
	n, err := strconv.ParseInt(raw, 10, 32)
	if err != nil {
		return 0, fmt.Errorf("limit_invalid")
	}
	if n < 1 || n > 100 {
		return 0, fmt.Errorf("limit_out_of_range")
	}
	return int(n), nil
}
```

### API focus: strconv.ParseBool

Boolean from form is not `"true"`/`"false"` string in Go until parser runs. Allow-list approach: only known representations or strict `ParseBool`.

```go
func parseActive(raw string) (bool, error) {
	switch strings.ToLower(strings.TrimSpace(raw)) {
	case "1", "true", "yes":
		return true, nil
	case "0", "false", "no", "":
		return false, nil
	default:
		return false, fmt.Errorf("active_invalid")
	}
}
```

### API focus: path/filepath.Base

```go
func safeBaseName(user string) (string, error) {

		return "", fmt.Errorf("filename_too_long")
```

```go
		return fmt.Errorf("ids_too_many")
	}
	for _, id := range r.IDs {
		if _, err := uuid.Parse(id); err != nil {
			return fmt.Errorf("id_invalid")
		}
	}
	return nil
}
```

### API focus: validate content-type

Fail closed when client sends wrong `Content-Type` for JSON endpoint.

```go
func requireJSON(r *http.Request) bool {
	ct := r.Header.Get("Content-Type")
	return strings.HasPrefix(strings.ToLower(strings.TrimSpace(ct)), "application/json")
}
```

# 10.11 System Configuration

> **Go Path - Zero to Gopher** / **02 Intermediate → Secure Coding in Go** / Lesson 10.11

## Lesson goals

After this lesson you should:

- load configuration from the environment with **fail closed** on required fields
- keep **closed by default**: debug off, narrow listen, timeouts enabled
- not run as root unless necessary (process least privilege)
- separate prod/dev config without secrets in VCS
- connect boot checks with availability and confidentiality

## Prerequisite

- 10.02 (env, secrets); 10.10 (TLS/timeout)

## Problem this lesson solves

Open-by-default debug, `0.0.0.0` with pprof, empty admin password “for install” — classic configuration flaws. The Go process should refuse to start when production is misconfigured.

## Mental model

1. **Config is a trust boundary** at boot.
2. **Explicit > implicit** — timeouts, Secure cookie, debug flag.
3. **Env per environment** — same key schemes, different values.
4. **Least privilege OS** — non-root user in the container.
5. **Fail closed** — do not Listen without valid config.

## Mechanism

### Load pattern

See 10.02 `config.Load`: required DSN/session key; debug forbidden in production.

### Feature flags

### Boot trace

```text

each error → Exit(1)
```

## Rules

1. Required fields without silent default secrets.
2. Debug off in prod.
3. Server timeouts always.
4. Non-root when possible.
5. Secrets are not in config files in git.
6. Document listen and proxy.
7. Separate migrator and runtime config.

## Examples

### Example 1 — prod guard

```go
func (c Config) Validate() error {
	if c.Env == "production" && c.Debug {
		return fmt.Errorf("debug forbidden in production")

	if c.Env == "production" && !c.SecureCookies {
		return fmt.Errorf("SecureCookies required in production")

	return nil
```

## Decision analysis

| Decision | Why |
|--------|-------|
| Fail closed boot | does not run wrongly “on” |
| Prod guards | prevents copy-paste dev |
| Non-root | OS least privilege |
| Timeout in config | availability |

## Trade-offs

- **Strict boot** vs quick hotfix — hotfix still through valid config.
- **Many env vars** vs one file — file without secrets + env for secrets.
- **Read-only FS** complicates local write temp — use /tmp explicitly.

## Common mistakes

1. Default admin password.
2. Debug in prod.
3. Secrets in ConfigMap plain in git.
4. Root container without reason.
5. No timeout.
6. Same config for migrator and app.
7. pprof always enabled.
8. SecureCookies false in prod.
9. Ignoring Load error.
10. “Temporary” flag left for months.

## Idiomatic Go

- `internal/config` package.
- `Validate()` separate from Load.
- Table tests for forbidden combinations.
- Thin `main`.

## Practical scenario

Staging with Debug=true and pprof on 0.0.0.0. After review: Validate(), non-root, profiler only with auth on localhost. Boot fail if SecureCookies false in prod.

### Readiness vs liveness

`/healthz` liveness must not hit the database with a heavy query. `/ready` checks DB ping — fail closed: kube does not send traffic until ready passes.

### API focus: os.Getenv required

Required values have no dangerous default. Empty string = fail at boot.

```go
func requireEnv(key string) (string, error) {
	v, ok := os.LookupEnv(key)
	if !ok || strings.TrimSpace(v) == "" {
		return "", fmt.Errorf("missing %s", key)
	}
	return v, nil
}
```

### API focus: config Validate prod

```go
func (c Config) Validate(env string) error {
```

### API focus: ready vs liveness

Ready checks DB; liveness is process only — do not mix into one endpoint without documentation.

```go
func ready(w http.ResponseWriter, r *http.Request, db *sql.DB) {
	ctx, cancel := context.WithTimeout(r.Context(), 2*time.Second)
	defer cancel()
	if err := db.PingContext(ctx); err != nil {
		http.Error(w, "not ready", 503)
		return
	}
	w.WriteHeader(200)
}
```

### API focus: graceful shutdown signal

```go
func run(ctx context.Context, srv *http.Server) error {
	stop := make(chan os.Signal, 1)
	signal.Notify(stop, syscall.SIGINT, syscall.SIGTERM)
	errCh := make(chan error, 1)
	go func() { errCh <- srv.ListenAndServe() }()
	select {
	case <-stop:
		shCtx, cancel := context.WithTimeout(ctx, 15*time.Second)
		defer cancel()
		return srv.Shutdown(shCtx)
	case err := <-errCh:
		return err
	}
}
```

Include shutdown in integration test — endpoint readiness must drop before the process disappears.

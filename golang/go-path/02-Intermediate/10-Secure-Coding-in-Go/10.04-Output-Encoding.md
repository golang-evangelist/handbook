# 10.04 Output Encoding

> **Go Path - Zero to Gopher** / **02 Intermediate → Secure Coding in Go** / Lesson 10.04

## Lesson goals

After this lesson you should:

- use `html/template` for HTML because it performs **contextual** escaping
- encode JSON via `encoding/json`, not manual string concatenation
- explain why `text/template` is the wrong choice for HTML responses (it does not escape HTML)
- separate data from markup and from JSON structure
- set correct `Content-Type` headers
- connect encoding to display integrity and error confidentiality (no raw internals in UI)

## Prerequisite

- Go 1.22+, basic HTTP handlers
- lesson 10.03 (input validation)
- HTML and JSON at reading level

## Problem this lesson solves

Even after validation, data returned to the client can be interpreted as *code* if embedded in the wrong context. Classic impact: user name inserted into HTML without escape changes page meaning in the browser—display integrity and often session confidentiality (if script reads data on the page) suffer.

In Go the standard library covers most HTML cases through `html/template`—if you use it correctly and do not disable protection via `template.HTML` without reason.

## Mental model

Encoding is **adapting data to the receiving context**:

| Context | Tool | What it does |
|----------|------|----------|
| HTML body / attribute | `html/template` | contextual escape |
| JSON API | `encoding/json` | correct JSON string/structure |
| text log | agreed rules | not HTML escape |
| CSV | separate rules | not HTML escape |

Data stays data. Markup stays markup. Mixing without encoding breaks that boundary.

```text
domain object
   → view model (string fields)
   → html/template OR encoding/json
   → bytes + Content-Type
   → client interprets by type
```

## Mechanism

### html/template versus text/template

- `html/template` — same action language as text, but **aware** of HTML/CSS/JS context; escapes automatically in usual contexts.
- `text/template` — same template language, **without** HTML security escape.

For HTML responses in browser: **always** `html/template`. If you use `text/template` for HTML, the browser may interpret user text as markup—that is exactly the failure mode this lesson names, without payload examples.

### Contextual escaping

`html/template` picks rules depending on place: text node, attribute value, etc. So `{{.Name}}` in body is not the same as manual escape “just in case” with one `Replace`. The library knows context; your ad-hoc replace does not.

### template.HTML and related types

`template.HTML`, `template.JS`, `template.CSS` mark: “this is already safe markup/code.” Use rarely, only for constant, reviewed content from *your* code—not user input. Wrong use disables control.

### JSON

`json.Marshal` / `Encoder` properly encodes strings (quotes, control characters). Manual `fmt.Sprintf(`{"name":"%s"}`, name)` breaks as soon as name has quote or special character—JSON integrity fails, clients fail or parse wrong.

### Content-Type

Browsers and clients decide how to interpret body. `application/json` and `text/html; charset=utf-8` must match actual content. Wrong type can force browser to interpret JSON as HTML or vice versa.

### Do not mix layers

- Validation (10.03) reduces garbage and enforces type.
- Encoding (this lesson) protects display/API context.
- Authorization (10.07) decides who may see.
No layer replaces another. “Valid string” still must be escaped in HTML.

### Trace: HTML profile

```text
1. Authz: may caller see profile?
2. Load DisplayName, City from DB (data)
3. view := ProfileView{...}  // plain strings
4. html/template Execute
5. Header Content-Type: text/html; charset=utf-8
6. Browser shows text, does not execute user string as markup
```

### Predict, then check (1)

```go
fmt.Fprintf(w, "<h1>Hello, %s</h1>", user.DisplayName)
```

<details>
<summary>Answer</summary>

`Fprint` does not HTML escape. If `DisplayName` contains markup characters, browser may change page meaning. Fix: `html/template` with `{{.DisplayName}}`.

</details>

### Predict, then check (2)

```go
t := texttemplate.Must(texttemplate.New("x").Parse("<p>{{.}}</p>"))
_ = t.Execute(w, userInput)
```

<details>
<summary>Answer</summary>

`text/template` does not escape HTML. Same template with `html/template` closes that risk for usual contexts. For HTML always `html/template`.

</details>

### Predict, then check (3)

```go
body := `{"email":"` + email + `"}`
w.Header().Set("Content-Type", "application/json")
_, _ = w.Write([]byte(body))
```

<details>
<summary>Answer</summary>

Manual concatenation breaks JSON when email contains quote or escape sequences. Use `json.NewEncoder(w).Encode(struct{ Email string `json:"email"` }{email})`.

</details>

### Autoescape and pipeline

In `html/template`, pipeline `{{. | printf "%s"}}` still goes through escape when context is HTML. Deliberate disable requires type like `template.HTML`. Review every conversion to that type.

### JSON and HTML in same service

Same domain may have:

- `GET /api/profile` → `encoding/json`
- `GET /profile` → `html/template`

Do not share “escaped for HTML” string in JSON (client gets double escape). Encode *for that* response.

### CSP and encoding

Content-Security-Policy is additional layer (defense in depth) at HTTP level. It does not replace `html/template`. This lesson does not configure CSP in detail; remember escape and CSP work together.

### Template availability

`template.Must` at init panics if template does not parse—fail fast at boot (good). On Execute, check `error` (e.g. closed client) and log internally.

### Link to CIA

| Practice | Goal |
|--------|------|
| html/template escape | display integrity |
| encoding/json | API contract integrity |
| no text/template for HTML | prevents wrong interpretation |
| no err.Error in HTML | internal confidentiality |

### URL in href attribute

`html/template` has special rules for URL contexts. Still: do not insert untrusted string as `javascript:` URL. Prefer allow-list schemes (`https`, `http`, relative path starting with `/`) before putting link in view model—that is validation (10.03) *plus* template escape.

```go
func safeLink(u string) (string, error) {
	if strings.HasPrefix(u, "/") && !strings.HasPrefix(u, "//") {
		return u, nil
	}
	if strings.HasPrefix(u, "https://") || strings.HasPrefix(u, "http://") {
		return u, nil
	}
	return "", fmt.Errorf("link_invalid")
}
```

### Test without offense

```go
func TestProfileEscapesAngle(t *testing.T) {
	var buf bytes.Buffer
	view := ProfileView{DisplayName: "a<b", City: "X"}
	if err := profileTmpl.Execute(&buf, view); err != nil {
		t.Fatal(err)
	}
	out := buf.String()
	if strings.Contains(out, "<b") && !strings.Contains(out, "&lt;") {
		// expect '<' is not raw start of tag in name
		t.Fatalf("expected escaped name in output")
	}
}
```

Test goal: confirm escape, not construct attack.

### Streaming JSON

`json.Encoder` writes directly to `w`. Do not collect giant `[]byte` if unnecessary—availability. For HTML, `Execute` also streams; log error mid-write, do not mix Content-Type.

### Partial HTML and HTMX/fragments

Fragment must still come from `html/template`. Do not return “raw string from DB” as `text/html` fragment.

### Decision diagram

```text
Is response HTML for browser?
  yes → html/template (+ Content-Type text/html)
  no → is it JSON API?
         yes → encoding/json
         no → text? text/template OK for plain text
              CSV? separate rules / library
```

### Confidentiality in view model

Do not pass whole `User` struct from DB into template—password hash, internal flags, tokens must not reach HTML. Build `ProfileView` with explicit fields (least privilege of data in display).

## Rules

1. HTML → `html/template`.
2. JSON → `encoding/json`.
3. Avoid `template.HTML` / `JS` / `CSS` except with strong reason and review.
4. Never build HTML by concatenating user fields.
5. Set `Content-Type` explicitly.
6. Do not use `text/template` for browser HTML.
7. Do not “pre-escape” for JSON; do not share HTML-escaped string as API field.
8. Authz before rendering sensitive view model.

```go
import (
	"encoding/json"
	"html/template"
)
```

## Examples

### Example 1 — safe HTML profile

```go
package outenc

import (
	"html/template"
	"net/http"
)

var profileTmpl = template.Must(template.New("profile").Parse(`
<!DOCTYPE html>
<html lang="en">
<head><meta charset="utf-8"><title>Profile</title></head>
<body>
  <h1>Hello, {{.DisplayName}}</h1>
  <p>City: {{.City}}</p>
</body>
</html>
`))

type ProfileView struct {
	DisplayName string
	City        string
}

func (h *Handler) Profile(w http.ResponseWriter, r *http.Request) {
	view := ProfileView{DisplayName: h.name, City: h.city}
	w.Header().Set("Content-Type", "text/html; charset=utf-8")
	if err := profileTmpl.Execute(w, view); err != nil {
		h.log.Error("template", "err", err)
		return
	}
}
```

#### What happens here

`DisplayName` and `City` are plain strings. `html/template` writes them with escape in HTML context. Browser shows text; markup characters do not become page structure.

### Example 2 — JSON encoder

```go
type profileDTO struct {
	DisplayName string `json:"display_name"`
	City        string `json:"city"`
}

func (h *Handler) ProfileJSON(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	enc := json.NewEncoder(w)
	if err := enc.Encode(profileDTO{DisplayName: h.name, City: h.city}); err != nil {
		h.log.Error("json", "err", err)
	}
}
```

#### What happens here

`Encode` guarantees syntactically correct JSON. Quotes in name do not break object. Content-Type matches body.

### Example 3 — contrast text/template (wrong for HTML)

```go
// INTENTIONAL: contrast for learning — do not use for HTML response.
import texttemplate "text/template"

func wrong(w http.ResponseWriter, name string) {
	t := texttemplate.Must(texttemplate.New("x").Parse("<p>{{.}}</p>"))
	_ = t.Execute(w, name) // no HTML escape
}
```

#### What happens here

Same `{{.}}` language, but without HTML protection. Impact: user text can change HTML document meaning. Fix: replace import and template type with `html/template`.

### Example 4 — rare safe literal

```go
const footer = template.HTML(`<footer><a href="/help">Help</a></footer>`)

var page = template.Must(template.New("page").Parse(`
{{.Body}}
{{.Footer}}
`))

type pageView struct {
	Body   string
	Footer template.HTML
}
```

#### What happens here

`Footer` is constant from code, reviewed. `Body` stays `string` and escapes. Never: `template.HTML(userInput)`.

### Example 5 — predict double escape

```go
escaped := template.HTMLEscapeString(name)
_ = json.NewEncoder(w).Encode(map[string]string{"name": escaped})
```

<details>
<summary>Answer</summary>

JSON client sees HTML entities instead of real name. Escape for HTML context in `html/template`, not upfront for JSON. For JSON—raw string through `encoding/json`.

</details>

### Example 6 — layout with nested template

```go
var pages = template.Must(template.New("root").Parse(`
{{define "layout"}}<!DOCTYPE html><html><body>{{template "content" .}}</body></html>{{end}}
`))

func init() {
	template.Must(pages.New("content").Parse(`<h1>{{.Title}}</h1><p>{{.Msg}}</p>`))
}
```

#### What happens here

Nested define still uses same escape engine. `Title` and `Msg` remain data.

## Decision analysis

| Decision | Why |
|--------|-------|
| html/template for HTML | contextual escape in stdlib |
| encoding/json for API | correct JSON without manual assembly |
| Rare template.HTML | do not disable protection for user data |
| Explicit Content-Type | correct client interpretation |
| Separate view / DTO | no mixing escape contexts |

## Trade-offs

- **html/template** is stricter and sometimes surprises around attribute/URL context—read docs for advanced cases.
- **Rich WYSIWYG HTML from user** needs separate *HTML* sanitize pipeline (allow-list tags)—different problem, not `text/template`.
- **Must at init** crashes process on bad template—intentional fail fast.
- **One template engine for mail+HTML+text** often leads to wrong import; split packages.

## Common mistakes

1. `text/template` for HTML pages.
2. `fmt.Fprintf` HTML with user fields.
3. `template.HTML(userInput)`.
4. Manual JSON string build.
5. Wrong or missing Content-Type.
6. Pre-escape for JSON.
7. Believing validation removes need for escape.
8. Sharing same “escaped” field between HTML and JSON.
9. Logging full rendered HTML with PII without control.
10. Ignoring `Execute` / `Encode` error.

## Idiomatic Go

- `template.Must` for static templates at init.
- Separate `ProfileView` / DTO instead of passing whole DB model (prevents field leak).
- `json.NewEncoder(w).Encode` directly on ResponseWriter.
- Test: render template to `bytes.Buffer` and verify markup characters in input are not raw special tags in output—without offensive payload tutorial; character `<` as data is enough.
- Package `outenc` or `web` separate from `jsonapi`.

## Practical scenario

Support tool shows “user note” through `text/template` in internal HTML. Note with markup characters changes page layout and inserts unwanted content into display of other tickets. Team moves to `html/template`, removes `template.HTML` around note, JSON API for same text stays on `encoding/json` without HTML escape. Display integrity returns; API clients no longer see `&lt;` in field.

### API focus: html/template

`html/template` automatically encodes data in HTML context. Used for server-side render; user string goes through struct fields, not `text/template` for HTML pages.

```go
package render

import (
	"html/template"
	"net/http"
)

var page = template.Must(template.New("profile").Parse(`<!doctype html>
<html><body><h1>{{.Title}}</h1><p>{{.Bio}}</p></body></html>`))

type ProfilePage struct {
	Title string
	Bio   string
}

func WriteProfile(w http.ResponseWriter, p ProfilePage) {
	w.Header().Set("Content-Type", "text/html; charset=utf-8")
	if err := page.Execute(w, p); err != nil {
		http.Error(w, "internal error", http.StatusInternalServerError)
	}
}
```

### Trace: JSON API response

```text
1. Handler gathers data (after authz)
2. json.NewEncoder(w).Encode(dto)
3. Content-Type: application/json; charset=utf-8
4. never manually join JSON string + user input
5. for HTML fragment in JSON — client still needs JS encoding
```

### API focus: text/template (HTML forbidden)

`text/template` **does not** encode HTML. Suitable for plain-text email or config generation—not web page with user data.

```go
// WRONG for HTML with user input:
// tpl := template.Must(template.New("x").Parse(`<div>` + user + `</div>`))

// CORRECT: html/template or explicit HTMLEscapeString before embedding in text template
```

### API focus: encoding/json.Encoder

Encoder writes directly to `ResponseWriter`—fewer allocations. `SetEscapeHTML(true)` (default) protects `<`, `>`, `&` in JSON string values in HTML `<script>` embedding.

```go
func writeJSON(w http.ResponseWriter, status int, v any) {
	w.Header().Set("Content-Type", "application/json; charset=utf-8")
	w.WriteHeader(status)
	enc := json.NewEncoder(w)
	enc.SetEscapeHTML(true)
	if err := enc.Encode(v); err != nil {
		// log internally; body may already be sent
	}
}
```

### API focus: template.HTMLEscapeString

When you must manually build HTML attribute or small fragment, escape before concatenation.

```go
import "html/template"

func attrEscape(s string) string {
	return template.HTMLEscapeString(s)
}
```

### API focus: template.JS

JavaScript context needs special type—only for values you generated from trusted source (e.g. constant), not raw user string.

### API focus: Content-Type header

Without accurate MIME type browser may misinterpret body (sniffing). Always set charset explicitly for text formats.

```go
w.Header().Set("Content-Type", "text/html; charset=utf-8")
w.Header().Set("X-Content-Type-Options", "nosniff")
```

### API focus: csv.Writer

```go
func writeUsersCSV(w http.ResponseWriter, rows []UserRow) error {
	w.Header().Set("Content-Type", "text/csv; charset=utf-8")
	w.Header().Set("Content-Disposition", `attachment; filename="export.csv"`)
	cw := csv.NewWriter(w)
	_ = cw.Write([]string{"id", "email"})
	for _, row := range rows {
		if err := cw.Write([]string{row.ID, row.Email}); err != nil {
			return err
		}
	}
	cw.Flush()
	return cw.Error()
}
```

Encode output for context: `html/template` for HTML, `encoding/json` for API. `text/template` does not escape HTML—so it is wrong for browser pages. Next lesson: authentication and passwords (bcrypt/argon2id, `crypto/rand`).

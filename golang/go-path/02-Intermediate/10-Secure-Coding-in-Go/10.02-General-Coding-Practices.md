# 10.02 General Secure Coding Practices

> **Go Path - Zero to Gopher** / **02 Intermediate → Secure Coding in Go** / Lesson 10.02

## Lesson goals

After this lesson you should:

- choose simple solutions over complex abstractions that hide trust boundaries
- maintain dependency hygiene: `go.mod`, `go.sum`, pinned versions, `go mod tidy`
- interpret what **govulncheck** reports (call path to vulnerable symbol), not as a lab against a live target
- keep secrets out of source code — environment or secret store; do not invent a cloud API
- tie fail closed boot, HTTP timeouts, and CI checklist into a defensive flow
- connect these practices to confidentiality, integrity, availability, and least privilege from 10.01

## Prerequisite

- Go 1.22+, knowledge of `go.mod` / `go.sum` and `go get`
- completed lesson 10.01 (CIA, least privilege, trust boundaries, fail closed)
- basic git and CI concepts (PR, pipeline step)

## Problem this lesson solves

Many security failures are not exotic crypto mistakes. They are: a dependency with a known vulnerability entry point, a secret in the repo, an overly complex parser, a debug endpoint left in production, or an HTTP server without timeouts. General practices close that class of problems before specialized controls (validation, sessions, SQL).

If the module pulls twenty transitive libraries “because a convenient ORM wrapper exists,” your risk surface grows even when *your* code looks clean. This lesson teaches hygiene: less code, fewer dependencies, secrets outside source, measurable CI checks.

## Mental model

Secure code is first **small, clear, and measurable**:

1. **Simplicity** — fewer branches, less hidden state, fewer places for mistakes in review.
2. **Dependency hygiene** — every import is part of your risk surface and your update decision.
3. **Secrets outside code** — source, image layer, and CI log are not a secret store.
4. **Pinning and verification** — `go.sum` protects integrity of downloaded code; `govulncheck` links CVEs to *your* calls.
5. **Fail closed defaults** — missing config → process does not listen; no “temporary” admin in production.
6. **Timeout as availability control** — untrusted peer does not hold goroutine forever.

```text
source code  -->  go.mod/go.sum  -->  binary  -->  runtime (env/secrets)
     ^                 ^                  ^                    ^
  review           integrity          supply chain         least privilege
  simplicity    govulncheck         reproducible         secrets outside VCS
```

## Mechanism

### Simplicity reduces surface

Every `if` branch, every parser, every “generic” plugin point is a place input can get unexpected meaning. That is not a call for spaghetti copy-paste—it is a call not to introduce DSL, reflection, and magic where an explicit type is enough.

In Go simplicity looks like: small interface, explicit `error`, standard `net/http` instead of five wrapper layers nobody on the team understands. Confidentiality and integrity often suffer when “smart” middleware silently changes the request.

### go.mod, go.sum, and module integrity

- `go.mod` — what you require (module path + version).
- `go.sum` — cryptographic fingerprints of content the toolchain saw; protects **integrity** of downloads.
- `go mod tidy` — removes unused, adds needed; reduces noise and transitive bloat.
- `go mod download` / build — uses sum database; do not “fix” sum by manual delete without understanding.

If someone substitutes a different zip of the same version tag, sum verification fails. That is supply-chain control at toolchain level, not magic.

### What govulncheck reports

`govulncheck` (official tool from the Go security team) analyzes **your code and dependencies** and reports vulnerabilities that are **reachable** via the call graph—not only “CVE exists somewhere in the lockfile.”

A typical report contains:

- vulnerability ID (e.g. GO-… / related CVE)
- package and symbol (function) affected
- whether the vulnerability is in code *your* module actually calls (reachable), or only in a module sitting in the graph
- suggested fixed version

**What you do with the report (defensively):**

1. Read impact description (e.g. “unbounded read in parser X”).
2. If reachable — plan dependency bump or remove call.
3. If not reachable — still document; tidy may change the graph later.
4. Do not use the report as instructions to reproduce an attack.

Running in CI:

```text
go install golang.org/x/vuln/cmd/govulncheck@latest
govulncheck ./...
```

That is not a lab against a live target. It is static hygiene of the same order as `go test`.

### Trace: from import to bump decision

```text
1. go get example.com/foo@v1.2.3
2. go.sum gets fingerprints
3. code calls foo.Parse
4. govulncheck says: Parse is reachable + GO-xxxx
5. read advisory: impact on input integrity
6. bump to v1.2.4 or replace API
7. tests + tidy + govulncheck again
```

### Secrets outside source code

A secret in git stays in history even after deleting the file. Therefore:

- do not commit API keys, passwords, private key PEM, session signing keys
- load from **environment** variables or **secret store** ops already uses
- on leak: **rotate** the secret, do not only delete the line in a new commit

This lesson does not invent a cloud SDK. Loading from env is enough, real pattern:

```go
func mustSecret(name string) (string, error) {
	v := os.Getenv(name)
	if v == "" {
		return "", fmt.Errorf("%s not set", name)
	}
	return v, nil
}
```

Fail closed: without secret no Listen. That protects confidentiality better than “default demo key” in source.

### Predict, then check (2)

```go

```

**Predict:** which CIA pillar suffers?

<details>
<summary>Answer</summary>

Availability: slow or malicious clients hold connections. Use `&http.Server{ReadHeaderTimeout: ...}`. That is not an “attack tutorial”—it is a defensive default of the standard library.

### Surface: what not to bind on public mux

- pprof without authentication on `0.0.0.0`
- debug/echo header endpoint in production
- “temporary” migrate button on HTTP
- admin UI without authz

Least privilege applies to *feature flags* too: if a route exists, someone will call it.

### CI as integrity control of the process

Minimal defensive steps in pipeline:

1. `go test ./...`
2. `go vet ./...` (or wider linter the team agrees on)
3. `govulncheck ./...`
4. secret scanner (tool of ops choice) — do not commit `.env`
5. build with locked sum (`go build -mod=readonly` where appropriate)

### Timeouts and resource limits

```go
srv := &http.Server{
	Addr:              cfg.Addr,
	Handler:           mux,
	ReadHeaderTimeout: 5 * time.Second,
	ReadTimeout:       15 * time.Second,
	WriteTimeout:      30 * time.Second,
	IdleTimeout:       60 * time.Second,
}
```

Availability control on trust boundary to network. Combine with `http.MaxBytesReader` on body (more in 10.03).

### go.mod replace and fork risk

`replace` directive is powerful for local dev. In production module:

- document why replace exists
- do not replace to an opaque fork without review
- integrity: still need sum and govulncheck on actual code the build uses

### Trace: boot with secrets

```text
LoadConfig
  ├─ APP_DATABASE_URL  (required) → error if empty
  ├─ APP_SESSION_KEY   (required, min length)
  ├─ APP_DEBUG=true    (forbidden in prod)
  └─ Listen Addr
Ping DB with timeout
ListenAndServeTLS or behind proxy (documented assumption)
```

Every “optional with default” for a secret is potential fail open.

### Dependencies: when to write yourself, when to take a module

| Situation | Preference |
|-----------|--------------|
| JWT parse + verify | known library + govulncheck, not homemade crypto |
| 20 lines for trim + allowlist | standard library, no new module |
| ORM with plugin magic | assess surface; sometimes `database/sql` + thin layer |
| “Utility kitchen sink” module | often not worth transitive graph |

### Predict, then check (3)

```go
func main() {
	db, _ := sql.Open("pgx", os.Getenv("DSN"))
	_ = http.ListenAndServe(":8080", api(db))
}
```

<details>
<summary>Answer</summary>

Ignored Open/Ping error; DSN may be empty; no Server timeout; fail open at boot. Fix: check env, ping with context timeout, `log.Fatal` / `os.Exit(1)` on error, `&http.Server{...}`.

</details>

### Link to 10.01 principles

| Practice | Principle |
|--------|---------|
| Secret in env | confidentiality, least privilege of secret access |
| go.sum | supply chain integrity |
| govulncheck | reduce known risk in dependencies |
| Timeouts | availability |
| Remove unused module | smaller blast radius / smaller surface |
| No pprof on public | least privilege of exposure |

### Detailed trace: reading govulncheck report

Imagine output (schematic, without reproducing attack):

```text
Vulnerability #1: GO-2024-XXXX
  Module: example.com/oldxml@v1.0.0
  Symbol: oldxml.Parse
  Your code calls:
    main.register -> ingest.Load -> oldxml.Parse
  Fixed in: example.com/oldxml@v1.0.1
```

Defense steps:

1. Confirm symbol is really in your graph (report already says reachable).
2. Read *impact* in advisory (e.g. excessive memory → availability; bad parse → integrity).
3. Bump to fixed version or remove call / replace API.
4. `go test ./...` then `govulncheck ./...` again.
5. If bump breaks API, plan small adapter—do not ignore finding.

What you **do not** do: use advisory as a lab to attack someone else’s system.

### Secrets: env versus secret store

| Approach | Advantage | Drawback |
|---------|----------|------|
| Env var | simple, universal | weaker rotation audit; easy leak in child process env dump |
| Secret store (ops) | rotation, ACL, audit | operational dependency; need client team already uses |

Course does not mandate a specific cloud. Rule: **source is not place for secret**; boot fail closed if missing.

### Predict, then check (4) — Docker COPY .env

```dockerfile
COPY .env /app/.env
```

<details>
<summary>Answer</summary>

`.env` enters image layer—secret stays in registry history. Confidentiality. Fix: mount/env at runtime from secret mechanism; never COPY real secrets.

</details>

### Predict, then check (5) — log entire os.Environ

```go
slog.Info("boot", "env", os.Environ())
```

<details>
<summary>Answer</summary>

Leaks all secrets from environment into log sink. Forbidden. Log only non-secret config fields (addr, feature flags).

</details>

### Minimal .gitignore fragment (hygiene)

```text
.env
.env.*
*.pem
*.key
id_rsa
```

That does not replace discipline—only reduces accidental commit.

### go get and minimum version

When introducing a module, pick version with reason (changelog, govulncheck clean). Avoid chain: “add huge framework for one helper.”

### Shutdown and availability

```go
ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt)
defer stop()
go srv.ListenAndServe()
<-ctx.Done()
shutdownCtx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
_ = srv.Shutdown(shutdownCtx)
```

Controlled shutdown protects integrity of in-flight requests better than hard kill. Link to 10.01 availability.

### Checklist for PR (copy into CONTRIB)

```text
[ ] go test ./...
[ ] go vet ./...
[ ] govulncheck ./...
[ ] no new secrets in diff
[ ] http.Server has ReadHeaderTimeout
[ ] new routes have authz where needed
[ ] go.mod tidy done intentionally
```

## Rules

1. Do not commit secrets; rotate if they were ever in history.
2. `go mod tidy` regularly; do not keep dead dependencies.
3. Run `govulncheck ./...` in CI; treat reachable findings as work, not noise.
4. Pin versions; avoid `@latest` in production go.mod without intent.
5. Fail closed at boot if required configuration or secret is missing.
6. Always set `ReadHeaderTimeout` (and other timeouts) on `http.Server`.
7. Do not expose debug/pprof on public address without authz.
8. Prefer standard library when it covers the need.
9. `go build -mod=readonly` in release CI where team agrees locked module mode.
10. Document `replace` directives.

## Examples

### Example 1 — config from env with fail closed

```go
package config

import (
	"fmt"
	"os"
	"strconv"
	"strings"
)

type Config struct {
	Addr            string
	DatabaseURL     string
	SessionKey      string
	Debug           bool
	ReadHeaderTimeoutSec int
}

func Load() (Config, error) {
	var c Config
	c.Addr = os.Getenv("APP_ADDR")
	if c.Addr == "" {
		c.Addr = ":8080"
	}
	c.DatabaseURL = os.Getenv("APP_DATABASE_URL")
	if c.DatabaseURL == "" {
		return Config{}, fmt.Errorf("APP_DATABASE_URL required")
	}
	c.SessionKey = os.Getenv("APP_SESSION_KEY")
	if len(c.SessionKey) < 32 {
		return Config{}, fmt.Errorf("APP_SESSION_KEY missing or too short")
	}
	c.Debug = strings.EqualFold(os.Getenv("APP_DEBUG"), "true")
	if c.Debug && strings.EqualFold(os.Getenv("APP_ENV"), "production") {
		return Config{}, fmt.Errorf("APP_DEBUG not allowed in production")
	}
	rhs := os.Getenv("APP_READ_HEADER_TIMEOUT_SEC")
	if rhs == "" {
		c.ReadHeaderTimeoutSec = 5
	} else {
		n, err := strconv.Atoi(rhs)
		if err != nil || n < 1 || n > 60 {
			return Config{}, fmt.Errorf("invalid APP_READ_HEADER_TIMEOUT_SEC")
		}
		c.ReadHeaderTimeoutSec = n
	}
	return c, nil
}
```

#### What happens here

Required secrets and DSN have no silent default. Debug in production fails at start—availability is consciously chosen below confidentiality/integrity of debug surface. Timeout comes from config with bounds (link to 10.03 validation style).

### Example 2 — main with Server timeouts

```go
package main

import (
	"log"
	"net/http"
	"os"
	"time"

	"example.com/app/config"
)

func main() {
	cfg, err := config.Load()
	if err != nil {
		log.Fatalf("config: %v", err)
	}
	mux := http.NewServeMux()
	mux.HandleFunc("GET /healthz", func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	})
	srv := &http.Server{
		Addr:              cfg.Addr,
		Handler:           mux,
		ReadHeaderTimeout: time.Duration(cfg.ReadHeaderTimeoutSec) * time.Second,
		ReadTimeout:       15 * time.Second,
		WriteTimeout:      30 * time.Second,
		IdleTimeout:       60 * time.Second,
	}
	log.Printf("listening on %s", cfg.Addr)
	if err := srv.ListenAndServe(); err != nil && err != http.ErrServerClosed {
		log.Println(err)
		os.Exit(1)
	}
}
```

#### What happens here

Process does not listen until config is valid. Timeouts protect availability. `/healthz` is a conscious exception—it still must not leak secrets or stack.

### Example 3 — checklist script as documented CI steps

```go
package main

import (
	"fmt"
	"os"
	"os/exec"
)

func run(name string, args ...string) error {
	cmd := exec.Command(name, args...)
	cmd.Stdout = os.Stdout
	cmd.Stderr = os.Stderr
	return cmd.Run()
}

func main() {
	steps := [][]string{
		{"go", "test", "./..."},
		{"go", "vet", "./..."},
		{"govulncheck", "./..."},
	}
	for _, s := range steps {
		fmt.Println("==>", s)
		if err := run(s[0], s[1:]...); err != nil {
			os.Exit(1)
		}
	}
}
```

#### What happens here

Same order as CI: test, vet, govulncheck. Fail closed—first failure stops. This is not an offensive tool; it is pipeline integrity.

### Example 4 — detect obvious secret leak in string (local guard)

```go
package secretdetect

import (
	"fmt"
	"strings"
)

// RejectObviousSecrets blocks obvious patterns in values you would log.
// Not a replacement for real secret scanner in CI.
func RejectObviousSecrets(label, v string) error {
	lower := strings.ToLower(v)
	if strings.Contains(lower, "private key") || strings.Contains(label, "password") && v != "" {
		return fmt.Errorf("%s looks sensitive; refuse to log", label)
	}
	if strings.HasPrefix(v, "sk_") && len(v) > 10 {
		return fmt.Errorf("%s looks like an API key; refuse to log", label)
	}
	return nil
}
```

#### What happens here

Defense in depth on log path: even if someone passes wrong argument to slog, guard rejects. Real CI scanner still needed. We do not try to “sanitize” secrets with replace—we refuse to emit.

### Example 5 — predict go.sum drama

Team deletes `go.sum` to “resolve conflict,” then runs `go build` on another machine.

<details>
<summary>Answer</summary>

Shared integrity fingerprint is lost. Build may pull different content in race with compromised proxy or cache error. Fix: resolve conflict carefully; do not train team to delete sum as first reflex.

</details>

## Decision analysis

| Decision | Why |
|--------|-------|
| Env for secrets | universal pattern; without invented cloud API |
| govulncheck in CI | reports reachable symbols, not only lockfile noise |
| Server timeouts | availability at network boundary |
| Debug forbidden in prod | reduces exposure |
| tidy + fewer dependencies | smaller surface and less bump work |
| -mod=readonly in release | integrity: CI must not silently change graph |

## Trade-offs

- **Fewer dependencies** sometimes means more own code—review load grows, but graph is smaller.
- **govulncheck fail CI** can block deploy for transitive finding; need severity policy + deadline.
- **Strict boot** extends “time to first listen” on misconfig incident—that is intentional.
- **Secret store** (ops) adds operational dependency; env on VM is simpler but harder for rotation audit.
- **Pinning** requires regular bump rhythm; otherwise you stagnate on old CVE.

## Common mistakes

1. Secret in repo or Docker layer `ENV` with real value in image history.
2. Deleting file with secret without rotation.
3. Ignoring `govulncheck` because “that is not our code.”
4. `@latest` in production go.mod without control.
5. `ListenAndServe` without `ReadHeaderTimeout`.
6. pprof / debug on public address.
7. Default demo credentials in `docker-compose` that reach staging.
8. `replace` to personal fork without review.
9. Logging whole config struct that contains keys.
10. Leaving `APP_DEBUG=true` in production “temporarily.”

## Idiomatic Go

- `os.Getenv` / `LookupEnv` + explicit validation in `config` package.
- `log/slog` with selective fields; never whole request dump with Authorization.
- `&http.Server{...}` instead of bare helpers when timeouts needed.
- `context.Context` for boot ping and shutdown.
- Small `main` that wires; logic in `internal/`.
- Test `Load()` table-driven: empty env → error; short session key → error.

## Practical scenario

Team discovers staging DSN was in `config.yaml` in git for two years. After incident response: rotate DB password, move to `APP_DATABASE_URL`, add `govulncheck` in CI, remove unused image resize module that pulled parser with more advisories. `ReadHeaderTimeout` enters all services as copy-paste standard. Availability false alarms during deploy drop because boot now fails fast on misconfig instead of “working” without DB.

## Check questions

1. Why does simpler code often mean lower security risk?
2. What does `govulncheck` do that plain “list CVE from lockfile” does not?
3. Why does secret in git history require rotation, not only file delete?
4. What is `go.sum` for?
5. Name two things that should not be on public HTTP mux.
6. What does fail closed mean for loading configuration?
7. Why does `ReadHeaderTimeout` protect availability?
8. How does least privilege enter choice of DB URL account from env?

### Answers

1. Fewer branches and dependencies → fewer mistake points and smaller review surface.
2. Links vulnerability to reachable symbols in *your* call graph.
3. Old clones and forks still have secret; attacker with history can still use it while valid.
4. Fingerprints of module content for integrity check on download.
5. Unauthenticated pprof; debug echo of secrets/headers.
6. If required field missing → error and process does not listen.
7. Limits how long you read headers from one peer.
8. Env carries DSN for *runtime* account with narrow rights, not migration superuser.

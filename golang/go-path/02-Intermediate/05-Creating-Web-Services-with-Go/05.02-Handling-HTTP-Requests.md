# 05.02 Handling HTTP requests: HTTP method, PathValue, query, headers, JSON

> **Go Path - Zero to Gopher** / **02 Intermediate → Creating Web Services with Go** / Lesson 05.02

## Lesson goals

After this lesson you can:

- read **HTTP method**, **path** values (`r.PathValue`), **query**, and **headers** without manually `Split`-ting the path;
- decode a JSON body with **`encoding/json`**, struct tags, **`Decoder` vs `Unmarshal`**, **`Encoder`**;
- enable **`DisallowUnknownFields`** and understand exactly what it does (and what it does not);
- limit body size with **`http.MaxBytesReader`**;
- choose status codes **400 / 401 / 403 / 404 / 405 / 409 / 415 / 500** consciously;
- check **Content-Type** before decode;
- return a consistent **JSON error envelope**;
- thread a **request ID** through `context` (carefully, typed key).

## Prerequisite

- 05.01: `ServeMux` 1.22 patterns, `Handler`, `Routes()`, basic timeouts.
- Basic `encoding/json` (marshal/unmarshal vision) — here you go deeper on the request path.
- `context.Context` at the level of “carries deadline/values” (cancel details in concurrency lessons).

## Problem this lesson solves

Without discipline on input:

1. Manual `strings.Split(r.URL.Path, "/")` — breaks on trailing slash, encoding, new segments.
2. `json.Unmarshal` of the whole file into memory without a limit — OOM on a huge body.
3. Silently ignoring unknown JSON fields — the client thinks the field was saved; the server discarded it.
4. `200 OK` with `{"error":"..."}` in the body — clients and proxies do not see failure.
5. Wrong Content-Type yet still attempting decode — weird errors instead of **415**.
6. Mixing path id and query id without a rule — non-deterministic API.
7. Decode error mapped to **500** instead of **400** — false “server bug” alarms.

This lesson teaches layer-by-layer request handling: path → query → header → body → status + envelope.

## Mental model

Five parts of one HTTP request — each has a job:

| Part | Example | Semantics |
|------|---------|-----------|
| **Path** | `/products/{id}` | Resource identity |
| **Query** | `?limit=10&q=milk` | Filter, sort, page — not identity |
| **Header** | `Content-Type`, `Authorization` | Metadata about the message / client |
| **Body** | JSON object | State for create/update |
| **Status** | 201, 400, 404… | Machine outcome; body = detail |

Flow in the handler (idiom):

```text
1) PathValue + shape validation
2) Query parse + ranges
3) Header checks (Content-Type, auth…)
4) MaxBytesReader on Body
5) Decoder (+ DisallowUnknownFields) → struct
6) Domain validation
7) Work (store) → error mapping → status + JSON
```

One sentence: **never trust the client — path, query, header, and body are input you validate before a side effect.**

## Mechanism

### PathValue — value from the ServeMux pattern

Registered: `"GET /products/{id}"`.

```go
id := r.PathValue("id")
```

- The value is a **string** (e.g. `"42"`, `"a1b2"`).
- If the name does not exist in the matched pattern → `""`.
- PathValue does **not** validate UUID/int — you do that.

**Predict, then answer.** Pattern `GET /products/{id}`, request `GET /products/007`. What is `PathValue("id")`?

> **Answer:** `"007"` (string with leading zeros). If you need a number, `strconv` + a decision whether leading zeros are allowed.

**Predict, then answer.** Same handler on `GET /products` and `GET /products/{id}`. On the list, what is `PathValue("id")`?

> **Answer:** Empty string — the list pattern has no `{id}`.

### Query string

```go
q := r.URL.Query()           // url.Values = map[string][]string
limitStr := q.Get("limit")   // first value or ""
```

`Get` returns the first value; duplicates `?limit=1&limit=2` — choose a policy consciously (usually first or 400).

Range validation:

```go
limit := 20
if s := r.URL.Query().Get("limit"); s != "" {
	n, err := strconv.Atoi(s)
	if err != nil || n < 1 || n > 100 {
		// 400 — bad input
		return
	}
	limit = n
}
```

**Predict, then answer.** `?limit=0` with the rule above — status?

> **Answer:** **400** — `n < 1`.

### Headers

```go
ct := r.Header.Get("Content-Type")
auth := r.Header.Get("Authorization")
```

`Header.Get` is case-insensitive for the name (HTTP spec). Values are case-sensitive where the spec says so (e.g. Bearer token).

For a JSON endpoint often:

```go
if !strings.HasPrefix(r.Header.Get("Content-Type"), "application/json") {
	// 415 Unsupported Media Type
}
```

`HasPrefix` allows `application/json; charset=utf-8`. Strict equality `== "application/json"` rejects a legitimate charset — so HasPrefix (or a real MIME parse).

**Predict, then answer.** Content-Type is `Application/JSON`. Does `HasPrefix(..., "application/json")` pass?

> **Answer:** No — string comparison is case-sensitive. In practice clients send lowercase; if you want robustness, normalize with `strings.ToLower` on the media type before the check.

### encoding/json — struct tags

```go
type createProduct struct {
	Name  string `json:"name"`
	Price int64  `json:"price_minor"`
}
```

- Tag `json:"name"` maps the JSON key onto the field.
- Exported fields (capital letter) take part in encode/decode; unexported are ignored.
- `json:"-"` excludes a field.

### Decoder vs Unmarshal

| Approach | Input | When |
|----------|-------|------|
| `json.Unmarshal(bytes, &v)` | `[]byte` already in memory | Small buffer you already have |
| `json.NewDecoder(r.Body).Decode(&v)` | `io.Reader` stream | **HTTP body** — you do not need `ReadAll` first |

For a request body prefer **Decoder**:

```go
dec := json.NewDecoder(r.Body)
err := dec.Decode(&in)
```

### Encoder for the response

```go
w.Header().Set("Content-Type", "application/json")
w.WriteHeader(http.StatusCreated)
_ = json.NewEncoder(w).Encode(out)
```

`Encode` adds a trailing newline — usual and harmless for an API. Set the header **before** `WriteHeader` / the first write.

### DisallowUnknownFields — exact meaning

```go
dec := json.NewDecoder(r.Body)
dec.DisallowUnknownFields()
err := dec.Decode(&in)
```

After the call, `Decode` returns an **error** if the JSON object contains a key that has **no** matching field in the destination struct (including via a tag).

**Predict, then answer.** Struct has `Name` with tag `name`. JSON: `{"name":"x","hack":true}`. With DisallowUnknownFields — what?

> **Answer:** `Decode` returns an error (unknown field `hack`). Without the option, `hack` is silently ignored, `Name="x"`.

What it does **not** do:

- does not validate types beyond JSON types (string into an int field is still an error);
- does not replace your domain validation (`Name != ""`);
- on nested structs it also applies to their fields during decode;
- does not know “optional fields in a future API version” — so it is a trade-off (see Trade-offs).

### MaxBytesReader

```go
r.Body = http.MaxBytesReader(w, r.Body, 1<<20) // 1 MiB
```

Wraps `r.Body` so that reading past the limit returns an error (and can signal the connection). Do it **before** `Decode` / `ReadAll`.

**Predict, then answer.** Limit 1 MiB, body 2 MiB JSON. With Decoder — what do you expect?

> **Answer:** `Decode` (or reading) returns an error due to overrun; map to **400** (or 413 if you explicitly detect `MaxBytesError` — newer Go has `http.MaxBytesError`). For this course: at least not 500 and not OOM.

Without MaxBytesReader, `ReadAll` or Decoder can try to consume huge memory (with ReadTimeout as a coarse network brake — not a substitute for a body limit).

### Status codes — decision map

| Code | Constant | When |
|------|----------|------|
| **400** | `StatusBadRequest` | Bad JSON, validation, bad query/path shape |
| **401** | `StatusUnauthorized` | Missing / invalid auth (who are you?) |
| **403** | `StatusForbidden` | Auth ok, but no permission (may you?) |
| **404** | `StatusNotFound` | Resource does not exist (domain) or unknown path (mux) |
| **405** | `StatusMethodNotAllowed` | Wrong HTTP method (usually mux, 05.01) |
| **409** | `StatusConflict` | State conflict (duplicate key, version conflict) |
| **415** | `StatusUnsupportedMediaType` | Wrong Content-Type |
| **500** | `StatusInternalServerError` | Unexpected server / DB error without mapping |

**Predict, then answer.** Token is missing. 401 or 403?

> **Answer:** **401** — identity was not established. **403** when you know who it is, but they have no right to the action.

**Predict, then answer.** Insert into the DB fails on UNIQUE. Which code?

> **Answer:** Often **409 Conflict** (or 400 if you treat it as bad input — document one policy and stick to it).

### Content-Type check — order

1. Check Content-Type → otherwise **415** (do not attempt decode).
2. MaxBytesReader.
3. Decoder + DisallowUnknownFields.
4. Domain validation → **400**.
5. Store → mapping.

For GET without a body do not force JSON Content-Type.

### JSON error envelope

Instead of mixing `text/plain` (`http.Error`) and JSON success:

```go
type Problem struct {
	Error string `json:"error"`
	Code  string `json:"code,omitempty"`
}

func writeJSON(w http.ResponseWriter, status int, v any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	_ = json.NewEncoder(w).Encode(v)
}

func writeError(w http.ResponseWriter, status int, msg string) {
	writeJSON(w, status, Problem{Error: msg})
}
```

The client always parses JSON; the status code carries the outcome. **Never** `200` + `{"error":...}` as the only error signal.

### Request ID through context (carefully)

```go
type ctxKey int

const keyReqID ctxKey = 1

func withRequestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id := r.Header.Get("X-Request-ID")
		if id == "" {
			id = "generated-demo-id" // in production: ULID/UUID
		}
		w.Header().Set("X-Request-ID", id)
		ctx := context.WithValue(r.Context(), keyReqID, id)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

func requestID(ctx context.Context) string {
	v, _ := ctx.Value(keyReqID).(string)
	return v
}
```

Rules:

- **typed key** (`ctxKey`), not a plain `string` key — fewer collisions;
- do not put large structs in context;
- request ID is for **log correlation**, not for auth;
- do not blindly trust a client ID for security — you may accept it for tracing, but generate your own if missing / if the format is suspicious.

### Decoder.More() — one JSON value

After a successful `Decode`, if you want strictly **one** JSON value in the body:

```go
if dec.More() {
	// more tokens remain — 400
}
```

Prevents `{"a":1}{"b":2}` in the same body.

### Empty body on POST

`Decode` on an empty body → `EOF` / error. Map to **400**, not **500**. Test in `httptest` with a `nil` body.

### Unmarshal vs Decoder for the same JSON

```go
data, _ := io.ReadAll(http.MaxBytesReader(w, r.Body, limit))
err := json.Unmarshal(data, &in)
```

Works, but you hold the whole buffer. Decoder reads a stream; with MaxBytesReader you still have a limit. For HTTP prefer Decoder + MaxBytesReader.

### Accept header (brief)

If the API speaks only JSON, you have two policies:

1. **Always return JSON** (including errors) — simple; ignore `Accept` or log it.
2. **Respect Accept** — if the client asks only for `text/html`, return **406 Not Acceptable** (rarer in pure JSON APIs).

Be consistent: mixing `text/plain` errors (`http.Error`) and JSON success confuses clients. That is why the envelope from this lesson.

**Predict, then answer.** Success is JSON, error goes through `http.Error` (text/plain). What must the client do?

> **Answer:** Branch by Content-Type / status — two parsers. Bad contract; better always JSON Problem.

### GET idempotency

HTTP method **GET** must not change state (no create/update/delete in a GET handler). Cache and reverse proxy assume that. Put side effects in POST/PUT/PATCH/DELETE.

**Predict, then answer.** `GET /jobs/{id}/run` starts a job. Why is that a problem?

> **Answer:** Preload, crawler, or retry can start the job more than once. Use `POST /jobs/{id}/run`.

### Headers you often read

| Header | Typical role |
|--------|--------------|
| `Content-Type` | Type of the request body |
| `Authorization` | Auth scheme (Bearer …) |
| `X-Request-ID` / `X-Correlation-ID` | Tracing |
| `If-Match` / `If-None-Match` | Optimistic concurrency (more advanced) |
| `Accept` | What the client wants as a response |

Do not build auth on custom headers without TLS and a clear threat model; Bearer in `Authorization` is a common pattern.

### httptest check of the Decode path

```go
func TestCreateUnknownField(t *testing.T) {
	body := strings.NewReader(`{"name":"x","price_minor":1,"hack":true}`)
	req := httptest.NewRequest(http.MethodPost, "/products", body)
	req.Header.Set("Content-Type", "application/json")
	rec := httptest.NewRecorder()
	CreateProduct(rec, req)
	if rec.Code != http.StatusBadRequest {
		t.Fatalf("got %d", rec.Code)
	}
}
```

Without starting a server you verify 400 for an unknown field — the same motivation as `Routes()` in 05.01.

### 413 vs 400 for an oversized body

When `MaxBytesReader` cuts:

- in newer Go you can `errors.As(err, &http.MaxBytesError{})` and return **413 Request Entity Too Large**;
- if you do not distinguish, **400** is an acceptable minimum — what matters is it is not **500** and you do not read forever.

**Predict, then answer.** Limit 1 KiB, body 2 KiB, you do not check `MaxBytesError`. Which status is allowed, which is not?

> **Answer:** 400 is allowed (or 413 if you detect); 500 is not.

### Query arrays and repeated keys

`url.Values` is `map[string][]string`. `Get("tag")` returns only the first value. For `?tag=a&tag=b`:

- either document “first wins”;
- or `q["tag"]` and process the slice;
- or **400** if `len > 1` when the API does not allow repetition.

### Null vs absent field in JSON

For **create** (POST) use ordinary value types (`string`, `int64`) and check required fields after Decode (`Name != ""`).

For **PATCH** (partial update) pointer fields (`*string`) often signal “the field was sent”, but `encoding/json` for `*string` treats both **absence** and JSON `null` as a `nil` pointer — it does not distinguish them by default. If you need that distinction, use `json.RawMessage`, a custom type, or a map. That is an advanced topic; in this lesson the focus is strict create decode.

### What does not go in context

Do not put in `context.Value`:

- whole user profile structs “just in case”;
- mutable maps that the handler changes;
- auth secrets.

Put a small ID / subject string; load the rest from the store as needed.

## Rules and syntax

1. Path = identity; query = filter/page; do not mix without documentation.
2. Validate `PathValue` shape (length, charset, UUID) before the store call.
3. Parse numbers from the query string with a range; bad input → **400**.
4. For JSON write endpoints check Content-Type → **415**.
5. `r.Body = http.MaxBytesReader(w, r.Body, N)` before reading.
6. `json.NewDecoder(r.Body)` + optionally `DisallowUnknownFields()`.
7. Decode/validation error → **400**; unknown store error → **500** (log internally).
8. Respond with a JSON envelope + the correct status; no 200-with-error.
9. Request ID: typed context key; header on the response for tracing.
10. Use `http.Status*` constants.

## Examples

### Example 1 — PathValue and query on list/get

```go
package main

import (
	"fmt"
	"net/http"
	"strconv"
)

func listOrGet(w http.ResponseWriter, r *http.Request) {
	id := r.PathValue("id")
	if id != "" {
		if len(id) > 64 {
			http.Error(w, "id", http.StatusBadRequest)
			return
		}
		fmt.Fprintf(w, "get id=%s\n", id)
		return
	}
	limit := 20
	if s := r.URL.Query().Get("limit"); s != "" {
		n, err := strconv.Atoi(s)
		if err != nil || n < 1 || n > 100 {
			http.Error(w, "limit", http.StatusBadRequest)
			return
		}
		limit = n
	}
	fmt.Fprintf(w, "list limit=%d\n", limit)
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /products", listOrGet)
	mux.HandleFunc("GET /products/{id}", listOrGet)
	http.ListenAndServe(":8080", mux)
}
```

#### What happens here

- The same handler serves list and get; on the list `PathValue` is empty.
- `limit` outside 1..100 → 400.
- Id too long → 400 before “store” logic.
- (In production this `main` would be thin + Server timeouts from 05.01.)

**Predict, then answer.** `GET /products?limit=abc` — status?

> **Answer:** **400** (`Atoi` error).

### Example 2 — Strict JSON create (Content-Type, MaxBytes, DisallowUnknownFields)

```go
package httpapi

import (
	"encoding/json"
	"net/http"
	"strings"
)

type createProduct struct {
	Name  string `json:"name"`
	Price int64  `json:"price_minor"`
}

func CreateProduct(w http.ResponseWriter, r *http.Request) {
	if !strings.HasPrefix(r.Header.Get("Content-Type"), "application/json") {
		http.Error(w, "content-type", http.StatusUnsupportedMediaType)
		return
	}
	r.Body = http.MaxBytesReader(w, r.Body, 1<<20) // 1 MiB

	var in createProduct
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()
	if err := dec.Decode(&in); err != nil {
		http.Error(w, "json", http.StatusBadRequest)
		return
	}
	if strings.TrimSpace(in.Name) == "" || in.Price < 0 {
		http.Error(w, "validation", http.StatusBadRequest)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusCreated)
	_ = json.NewEncoder(w).Encode(map[string]any{
		"status": "created",
		"name":   in.Name,
	})
}
```

#### What happens here

- Wrong CT → **415** before decode.
- Body limit 1 MiB.
- Unknown JSON field → Decode error → **400**.
- Domain validation separate from JSON parse.
- Success → **201** + JSON Encoder.

**Predict, then answer.** Body `{"name":"x","price_minor":1,"extra":0}` — status?

> **Answer:** **400** because of `DisallowUnknownFields` (`extra`).

**Predict, then answer.** Body `{"name":"x","price_minor":-1}` — status?

> **Answer:** **400** (price validation), JSON is syntactically fine.

### Example 3 — Authorization header sketch (401)

```go
package httpapi

import (
	"net/http"
	"strings"
)

func requireBearer(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		h := r.Header.Get("Authorization")
		if !strings.HasPrefix(h, "Bearer ") || len(h) < 8 {
			http.Error(w, "unauthorized", http.StatusUnauthorized)
			return
		}
		token := strings.TrimPrefix(h, "Bearer ")
		if token != "demo-token" { // illustration — replace with a real verifier
			http.Error(w, "unauthorized", http.StatusUnauthorized)
			return
		}
		next.ServeHTTP(w, r)
	})
}
```

#### What happens here

- Middleware reads the header before the handler.
- Missing/invalid token → **401**, `next` is not called (05.01 onion).
- Hardcoded token is **demo only** — production: JWT/OIDC/introspection.

**Predict, then answer.** Token valid, but the user has no role for DELETE. Which code in the handler?

> **Answer:** **403 Forbidden** — identity known, permission missing.

### Example 4 — Status mapping + JSON envelope

```go
package httpapi

import (
	"encoding/json"
	"errors"
	"net/http"
)

type Problem struct {
	Error string `json:"error"`
}

func writeJSON(w http.ResponseWriter, status int, v any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	_ = json.NewEncoder(w).Encode(v)
}

var (
	ErrNotFound = errors.New("not found")
	ErrConflict = errors.New("conflict")
)

func mapError(w http.ResponseWriter, err error) {
	switch {
	case errors.Is(err, ErrNotFound):
		writeJSON(w, http.StatusNotFound, Problem{Error: "not found"})
	case errors.Is(err, ErrConflict):
		writeJSON(w, http.StatusConflict, Problem{Error: "conflict"})
	default:
		// log err internally — generic message to the client
		writeJSON(w, http.StatusInternalServerError, Problem{Error: "internal error"})
	}
}
```

#### What happens here

- Domain `error` values map to HTTP status.
- The client reads the code + a short JSON body.
- 500 does not leak the internal `err.Error()` string (it may contain SQL/paths).

**Predict, then answer.** Store returns `fmt.Errorf("get: %w", ErrNotFound)`. Which status?

> **Answer:** **404** — `errors.Is` follows the wrap.

### Example 6 — Complete POST with envelope and More()

```go
package httpapi

import (
	"encoding/json"
	"net/http"
	"strings"
)

type createProduct struct {
	Name  string `json:"name"`
	Price int64  `json:"price_minor"`
}

type Problem struct {
	Error string `json:"error"`
}

func writeErr(w http.ResponseWriter, status int, msg string) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	_ = json.NewEncoder(w).Encode(Problem{Error: msg})
}

func CreateProductJSON(w http.ResponseWriter, r *http.Request) {
	ct := strings.ToLower(r.Header.Get("Content-Type"))
	if !strings.HasPrefix(ct, "application/json") {
		writeErr(w, http.StatusUnsupportedMediaType, "expected application/json")
		return
	}
	r.Body = http.MaxBytesReader(w, r.Body, 1<<20)

	var in createProduct
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()
	if err := dec.Decode(&in); err != nil {
		writeErr(w, http.StatusBadRequest, "invalid json")
		return
	}
	if dec.More() {
		writeErr(w, http.StatusBadRequest, "only one json object allowed")
		return
	}
	if strings.TrimSpace(in.Name) == "" || in.Price < 0 {
		writeErr(w, http.StatusBadRequest, "validation")
		return
	}
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusCreated)
	_ = json.NewEncoder(w).Encode(in)
}
```

#### What happens here

- CT normalized to lower before HasPrefix.
- One object (`More()`).
- All errors through the same JSON envelope — consistent client code.

**Predict, then answer.** Two JSON objects in the body, first valid — status?

> **Answer:** **400** (`dec.More()` true after the first Decode).

## Decision analysis

| Decision | Motive |
|----------|--------|
| PathValue instead of Split | Mux is the source of truth for segments |
| Decoder + MaxBytesReader | Stream + memory limit |
| DisallowUnknownFields | Strict contract, fewer silent bugs |
| 415 before Decode | Clear media type error |
| JSON envelope | Predictable client, ops, portal |
| errors.Is mapping | One place for status policy |
| Typed context key | No collision of string keys |

## Trade-offs

- **Strict JSON (DisallowUnknownFields) vs forward-compat:** strict catches client mistakes; breaks clients that send new fields before the server knows them. Document the API version; for public APIs sometimes tolerate unknown fields.
- **`http.Error` (text/plain) vs JSON Problem:** text is faster for sketches; public API — always JSON.
- **Manual validation vs library** (ozzo, go-playground): start manual; library when rules grow.
- **400 vs 422:** Go/ecosystem often uses 400 for validation; 422 (Unprocessable) if you explicitly follow some style guide — be consistent.
- **Accepting X-Request-ID from the client:** useful for tracing through a gateway; spoof risk in log aggregation — combine with your own ID or a trust boundary at the edge.

## Common mistakes

1. **200 with `{"error":...}`** — client and monitor do not see fail.
2. **No MaxBytesReader** — memory pressure on a large body.
3. **PathValue without validation** — `../../`-style strings or oversized id in logs/DB.
4. **Content-Type `==` instead of HasPrefix** — rejects `charset=utf-8`.
5. **Decode error → 500** — false server alarms; should be **400**.
6. **Mixing query id and path id** without a rule — “who wins?”
7. **Ignoring DisallowUnknownFields** then wondering why a meta field “does not work”.
8. **Leaking `err.Error()` in 500 JSON** — internal details to the client.
9. **String key in context** — package collision.
10. **GET with a side effect** — breaks cache/proxy assumptions.

## Idiomatic Go

- `json.NewDecoder(r.Body)` / `json.NewEncoder(w)`.
- `http.MaxBytesReader` before reading the body.
- `errors.Is` / `errors.As` for mapping.
- `r.Context()` passed into the store (05.03).
- `http.Status*` constants.
- Middleware for cross-cutting (auth, request ID); input validation near the handler or a shared decode helper.

## Practical scenario

A mobile client adds a `meta` field to POST `/products`. The old server without `DisallowUnknownFields` ignores `meta`; the mobile team thinks it was saved — a production bug for weeks. Enabling `DisallowUnknownFields` on staging immediately returns **400** — the contract is fixed (or the field is added to the struct).

Second incident: a partner “accidentally” sends 2 GiB JSON. Without `MaxBytesReader` workers grow memory until OOMKill. After the limit — fast **400**, other requests live.

Third: support asks “what happened to the user”. Without a request ID in the logs there is no correlation. Middleware puts the ID in context and the response — the error in the log and the ticket share the same key.

## Check questions

1. **What is `DisallowUnknownFields` for?**  
   `Decode` returns an error if JSON has keys outside the destination struct.

2. **What does `PathValue` read?**  
   The value of a wildcard segment from the matched ServeMux pattern.

3. **Why `MaxBytesReader`?**  
   Limits how much of the body may be read — protects memory.

4. **Which status for wrong Content-Type?**  
   **415** Unsupported Media Type.

5. **Path vs query?**  
   Path identifies the resource; query filters / pages / sorts.

6. **Decoder or Unmarshal for `r.Body`?**  
   Prefer `Decoder` (stream); Unmarshal when you already have `[]byte`.

7. **401 vs 403?**  
   401 = not authenticated; 403 = authenticated without permission.

8. **Why a typed key in context?**  
   Reduces collision with other packages that would use the same string.

9. **What does `dec.More()` do after Decode?**  
   Detects whether the reader still has more JSON tokens (more than one value).

10. **Why not 200 + error in the body?**  
    The status code is the contract for clients, proxies, and monitoring — failure must be visible in the code.

## Summary

You handle a request layer by layer: **PathValue**, **query**, **header** (Content-Type, auth), **body** (`MaxBytesReader` + `Decoder` + optional `DisallowUnknownFields`), then domain rules and **status + JSON envelope**. Map known `error` to 404/409; unknown to 500 without leaking internals. Request ID through `context` helps tracing. The API becomes predictable — ready for persistence in 05.03.

# 05.04 Templates in Go: html/template vs text/template, ParseFS, Execute

> **Go Path - Zero to Gopher** / **02 Intermediate → Creating Web Services with Go** / Lesson 05.04

## Lesson goals

After this lesson you can:

- distinguish **`html/template`** (automatic escape) from **`text/template`** (no escape);
- explain why contextual escape in `html/template` reduces XSS risk (defensively);
- use **`ParseFS`** with `embed.FS` or a disk `fs.FS`;
- parse templates **once** at startup, and per request only `Execute` / `ExecuteTemplate`;
- organize a layout via `{{define}}` / `{{template}}`;
- attach a **`FuncMap` before `Parse`**;
- use `template.HTML` **only** for trusted content;
- set `Content-Type: text/html; charset=utf-8` and handle an Execute error.

## Prerequisite

- 05.01 HTTP handlers and `ResponseWriter`.
- Preferably 04.x on the `embed` package (files packed into the binary via `//go:embed`).
- Basic HTML: elements, attributes, lists.

You do not need a frontend framework. The server renders an HTML string into the response.

## Problem this lesson solves

Three common mistakes in the same week:

1. **`text/template` for HTML** “because it is shorter” — a user name with `<` and `>` ends up as raw markup in the browser.
2. **Parse on every request** — CPU cost and late discovery of a broken template (500 instead of fail at startup).
3. **`template.HTML(userInput)`** “so bold works” — turns off escape exactly where protection is needed.

Extra pain: `ExecuteTemplate` with the wrong name; data as bare `map` then production bugs; mixing layout files without clear `define` names.

## Mental model

1. **`html/template`** knows **context** (element text, attribute, URL…) and escapes specially for that context.
2. **`text/template`** does **not** escape — for plain email, config, text generation. **Not** for browser HTML.
3. **Parse once** (startup) → cached `*template.Template`; **Execute per request**.
4. Data = any `any`; a **`struct` is better than a bare map** (clear fields, refactor).
5. Names: `{{define "home"}}` + `ExecuteTemplate(w, "home", data)` connect the parts.
6. `FuncMap` must be registered **before** Parse — otherwise the function “does not exist” in the template.
7. `template.HTML` is a marker “this is already safe HTML” — only for a trusted source.

```text
embed.FS / disk FS
      │ ParseFS (+ FuncMap before that)
      ▼
 *template.Template  (once)
      │ ExecuteTemplate per Request
      ▼
 ResponseWriter (HTML bytes)
```

## Mechanism

### html/template vs text/template

The same action language (`{{.}}`, `{{range}}`, `{{if}}`). The difference is **output safety**.

`html/template` at execution looks at where the action sits:

- inside an element → HTML escape (`<` → `&lt;`);
- in an attribute → attribute escape;
- in a URL context — extra rules.

`text/template` writes the string **as-is**.

**Important fact:** `html/template` escapes; `text/template` does not.

### Trace 1 — mild input with angle brackets

Field input `Name`: `Ada <Dev>`

With `html/template` and template `<p>{{.Name}}</p>` expect output similar to:

```html
<p>Ada &lt;Dev&gt;</p>
```

The browser shows the text `Ada <Dev>`, does not interpret new tags. That is the **defensive** effect of contextual escape.

With `text/template` the same template would write raw `<` and `>` — the browser may treat that as markup. So HTML pages → **only** `html/template`.

### Predict, then answer — which package?

**Question.** You are doing a plain-text email: `Hello {{.User}}, link: {{.Link}}`. Which package?

**Answer.** `text/template` — you do not want `&lt;` in the mail body. Still **validate** the link before inserting (open redirect is not XSS, but it is abuse).

**Question.** You send the same content as an HTML email body in a browser / HTML client. Which package?

**Answer.** `html/template` (or HTML already sanitized by another tool). Do not mix.

### ParseFS and embed

```go
//go:embed templates/*.html
var tplFS embed.FS

t, err := template.ParseFS(tplFS, "templates/*.html")
```

`ParseFS` reads from `fs.FS`. `embed.FS` packs files into the binary — deploy without a separate `templates/` folder on the server (content is in the binary).

The pattern `"templates/*.html"` must match paths **inside** the FS (including the `templates/` prefix).

### Execute vs ExecuteTemplate

- `Execute(w, data)` — executes the **default** (often first / root) template.
- `ExecuteTemplate(w, "home", data)` — executes a named `define` / file name.

In most HTTP apps: `ExecuteTemplate` + clear names.

### Trace 2 — request to HTML

```text
GET /
  → Server.Home
  → pageData{Title, Items}
  → t.ExecuteTemplate(w, "home.html", data)
  → Writer gets escaped HTML
  → 200 text/html
```

### Trace 3 — name error

```text
ExecuteTemplate(w, "hom", data)  // typo
  → err != nil
  → log + 500 generic page
```

So parse at startup + a test that calls the real name.

### Predict, then answer — Parse in the handler

**Question.** In every `Home` handler: `template.ParseFS(...)` then `ExecuteTemplate`. What hurts?

**Answer.** CPU on every request; an HTML error is seen only under traffic; harder to share the same `*Template`. Parse **once** in `New()` / `main`.

### define / template layout

```html
{{define "layout"}}
<!DOCTYPE html>
<html lang="en">
<head><title>{{template "title" .}}</title></head>
<body>{{template "content" .}}</body>
</html>
{{end}}
```

Page:

```html
{{define "home"}}
{{template "layout" .}}
{{end}}
{{define "title"}}Home{{end}}
{{define "content"}}<p>{{.User}}</p>{{end}}
```

`{{template "content" .}}` inserts the block; `.` passes the same data (or choose another).

`{{block "content" .}}...{{end}}` is a related pattern (default content + override) — the idea of sharing a shell remains.

### FuncMap before Parse

```go
t, err := template.New("root").Funcs(template.FuncMap{
	"upper": strings.ToUpper,
}).ParseFS(tplFS, "templates/*.html")
```

Order:

1. `template.New`
2. `.Funcs(...)`
3. `.Parse` / `.ParseFS`

Reversed: Parse does not see the function → template error.

Functions: pure, fast, no hidden I/O on the render hot path.

### Predict, then answer — FuncMap after Parse

**Question.** `t, _ := template.ParseFS(...); t.Funcs(m)` — does `upper` work in an already parsed tree?

**Answer.** `Funcs` on an existing tree applies to **subsequent** Parse calls on that tree; it does not “magically” fill already compiled actions as you expect in all cases. Idiom: **Funcs then Parse**. Keep one construction chain.

### template.HTML — trusted only

```go
type pageData struct {
	Title string
	Body  template.HTML // already sanitized HTML from an internal renderer
}
```

If you do `template.HTML(r.FormValue("bio"))`, you turned off escape for user input. **Do not do that.**

Trusted sources (examples):

- static HTML from your repo;
- output of a sanitizer you trust;
- an internal markdown→HTML pipeline with a tag whitelist.

### Contextual escape (defense, without a payload)

The lesson goal is not “how to attack”, but **how not to let raw markup through**.

Mild example in a test:

```go
data := pageData{Title: "A < B"}
// after Execute, the body should contain &lt; and not a raw < next to Title
```

Attributes: `html/template` escapes there too, but do **not** put an untrusted string into a `javascript:` URL or into event handler attributes. Escape is not a substitute for validating the URL scheme.

### Parse once — immutability

After a successful Parse, `*template.Template` is shared across requests (read-only Execute). Do not mutate the global template per request. Reload from disk only with an explicit dev flag, off in production.

### Predict, then answer — unexported field

**Question.** The struct has `title string` (lowercase t). The template writes `{{.Title}}` and `{{.title}}`. What does the user see?

**Answer.** Empty for both in the typical case: the template does **not** see unexported fields. Fix: `Title string` and `{{.Title}}`.

### Predict, then answer — mixing packages in the same file

**Question.** You import `html/template` as `template` and `text/template` as `texttemplate`. For an HTML page you mistakenly call `texttemplate.Parse`. Which signal in code review?

**Answer.** For any `Content-Type: text/html` response — only `html/template`. Name imports clearly and do not treat a “similar” Parse API as an excuse.

### Multiple files, one ParseFS

```go
t, err := template.New("root").Funcs(funcs).ParseFS(tplFS,
	"templates/layout.html",
	"templates/home.html",
	"templates/about.html",
)
```

Or glob `"templates/*.html"`. All `define`s enter the same tree. That is why name collision hurts — two `{{define "content"}}` in different files: the last one wins.

### Method on the data

A template can call an exported method with no arguments (or with arguments under template rules):

```go
func (p pageData) ItemCount() int { return len(p.Items) }
```

```html
<p>Count: {{.ItemCount}}</p>
```

The method must not change shared state during Execute from multiple requests without synchronization — prefer pure calculations.

### Trace 4 — layout chain

```text
ExecuteTemplate("home")
  → define "home" calls template "layout"
  → layout calls template "title" and "content"
  → HTML assembled, escape on every {{.Field}}
```

## Rules and syntax

1. Browser HTML → **only** `html/template`.
2. Plain text → `text/template`; do not mix with HTML responses.
3. `ParseFS` / `Parse` **once** at startup; `ExecuteTemplate` per request.
4. `FuncMap` **before** Parse.
5. `template.HTML` / `JS` / `CSS` markers — only trusted content.
6. Data as a `struct` with exported fields (`Title`, not `title` if the template reads `.Title`).
7. Execute error: log detail; generic 500 page to the client.
8. `Content-Type: text/html; charset=utf-8`.
9. `template.Must` allowed on the `main`/init path where fail at startup is desired.
10. `define` names unique in the set — collision on ParseFS overwrites silently.

Note on fields: the template sees only **exported** struct fields (capital initial letter).

## Examples

### Example 1 — html/template escape (mild input)

```go
package main

import (
	"html/template"
	"os"
)

func main() {
	t := template.Must(template.New("x").Parse(`<p>{{.Name}}</p>`))
	_ = t.Execute(os.Stdout, map[string]string{
		"Name": `Ada <Dev> & Co`,
	})
}
```

#### What happens here

Output escapes `<`, `>`, `&` into entities (`&lt;`, `&gt;`, `&amp;`). The user sees text, not new HTML elements. With `text/template` the angle brackets would stay raw.

### Example 2 — text/template same input (contrast)

```go
package main

import (
	"os"
	"text/template"
)

func main() {
	t := template.Must(template.New("x").Parse(`<p>{{.Name}}</p>`))
	_ = t.Execute(os.Stdout, map[string]string{
		"Name": `Ada <Dev>`,
	})
}
```

#### What happens here

Output contains raw `<Dev>`. For an HTML page this is the wrong package. For a plain text email (without HTML tags in the template) `text/template` is fine.

### Example 3 — ParseFS + embed + ExecuteTemplate

```go
package web

import (
	"embed"
	"html/template"
	"net/http"
)

//go:embed templates/*.html
var tplFS embed.FS

type Server struct {
	t *template.Template
}

func New() (*Server, error) {
	t, err := template.ParseFS(tplFS, "templates/*.html")
	if err != nil {
		return nil, err
	}
	return &Server{t: t}, nil
}

type pageData struct {
	Title string
	Items []string
}

func (s *Server) Home(w http.ResponseWriter, r *http.Request) {
	data := pageData{
		Title: "Shop",
		Items: []string{"Milk", "Bread"},
	}
	w.Header().Set("Content-Type", "text/html; charset=utf-8")
	if err := s.t.ExecuteTemplate(w, "home.html", data); err != nil {
		http.Error(w, "template", http.StatusInternalServerError)
	}
}
```

`templates/home.html`:

```html
{{define "home.html"}}
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>{{.Title}}</title>
</head>
<body>
  <h1>{{.Title}}</h1>
  <ul>
  {{range .Items}}
    <li>{{.}}</li>
  {{end}}
  </ul>
</body>
</html>
{{end}}
```

#### What happens here

Templates in the binary via `embed`, parsed in `New`. Per request only ExecuteTemplate with struct data. `range` prints the list; empty `Items` → empty `<ul>`.

### Example 4 — Layout with define/template

`templates/layout.html`:

```html
{{define "layout"}}
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>{{template "title" .}}</title>
</head>
<body>
<header>Shop</header>
<main>
{{template "content" .}}
</main>
</body>
</html>
{{end}}
```

`templates/home.html`:

```html
{{define "home"}}
{{template "layout" .}}
{{end}}
{{define "title"}}Home — {{.Title}}{{end}}
{{define "content"}}
<p>Hello, {{.User}}</p>
{{end}}
```

Handler:

```go
func (s *Server) Home(w http.ResponseWriter, r *http.Request) {
	w.Header().Set("Content-Type", "text/html; charset=utf-8")
	_ = s.t.ExecuteTemplate(w, "home", pageData{Title: "X", User: "Marko"})
}
```

#### What happens here

`home` pulls `layout`; layout inserts `title` and `content`. Same shell for multiple pages. Make sure all files enter the same `ParseFS` call.

### Example 5 — FuncMap

```go
package web

import (
	"embed"
	"html/template"
	"strings"
)

//go:embed templates/*.html
var tplFS embed.FS

func parse() (*template.Template, error) {
	return template.New("root").Funcs(template.FuncMap{
		"upper": strings.ToUpper,
	}).ParseFS(tplFS, "templates/*.html")
}
```

In the template: `{{upper .Title}}`.

#### What happens here

`Funcs` before `ParseFS`. `upper` is deterministic and fast. Keep heavy logic in Go code before Execute, not in the template.

### Example 6 — Test escape behavior

```go
package web_test

import (
	"bytes"
	"html/template"
	"strings"
	"testing"
)

func TestTitleEscaped(t *testing.T) {
	tpl := template.Must(template.New("t").Parse(`<h1>{{.Title}}</h1>`))
	var buf bytes.Buffer
	err := tpl.Execute(&buf, struct{ Title string }{Title: "A < B"})
	if err != nil {
		t.Fatal(err)
	}
	out := buf.String()
	if strings.Contains(out, "A < B") {
		t.Fatalf("raw < in output: %q", out)
	}
	if !strings.Contains(out, "&lt;") {
		t.Fatalf("expected escape entity, got %q", out)
	}
}
```

#### What happens here

The test locks the defensive contract: an angle bracket becomes an entity. Without exploit strings — mild `A < B` is enough.

### Example 7 — WRONG: template.HTML from a form

```go
// WRONG
bio := r.FormValue("bio")
data := pageData{Body: template.HTML(bio)}

// CORRECT — ordinary string, html/template escapes
data := pageData{Bio: bio} // field of type string; in the template {{.Bio}}
```

#### What happens here

`template.HTML` turns off protection. For user input leave `string`.

### Example 8 — text/template for plain email

```go
package mailtpl

import (
	"bytes"
	"text/template"
)

func PlainReset(user, link string) (string, error) {
	const body = `Hello {{.User}},
reset your password: {{.Link}}
`
	t := template.Must(template.New("reset").Parse(body))
	var buf bytes.Buffer
	err := t.Execute(&buf, map[string]string{"User": user, "Link": link})
	return buf.String(), err
}
```

#### What happens here

Plain text does not need HTML escape. Do not use this package for an HTML body. Link validation remains yours.

### Example 9 — nil slice vs empty slice

```go
type pageData struct {
	Items []string
}

// Prefer:
data := pageData{Items: []string{}}

// nil Items: range does not panic, but sometimes JSON/debug confuses; empty slice is a clearer UI contract.
```

#### What happens here

Templates tolerate nil in `range`, but an explicit empty slice makes intent obvious in Go code and tests.

### Example 10 — Execute error and partial write

```go
func (s *Server) Home(w http.ResponseWriter, r *http.Request) {
	var buf bytes.Buffer
	if err := s.t.ExecuteTemplate(&buf, "home", data); err != nil {
		http.Error(w, "template", http.StatusInternalServerError)
		return
	}
	w.Header().Set("Content-Type", "text/html; charset=utf-8")
	_, _ = w.Write(buf.Bytes())
}
```

#### What happens here

Render into a buffer prevents “half HTML then 500”. Fine for small admin pages; for large streams measure memory. Alternative: log and return a generic page before writing.

## Decision analysis

| Decision | Motive | Alternative |
|----------|--------|-------------|
| `html/template` for UI | Contextual escape | `text/template` for HTML |
| Parse at startup | Less latency; fail-fast | Parse on the hot path |
| Struct data | Types, refactor, exported fields | Bare `map[string]any` |
| `embed.FS` | Simple deploy | Disk only in production |
| Thin FuncMap | Template stays readable | Mini-language in templates |
| Buffer before Write | No partial response | Direct Write with risk |

## Trade-offs

- Server templates vs SPA: choose by team and SEO/admin needs; escape principles also apply separately to JSON APIs.
- `template.HTML` power vs hole — default forbidden in review.
- A large FuncMap becomes a DSL — keep it thin; compute in Go.
- Dev reload from disk speeds UI iteration; off in production.
- One large ParseFS vs multiple template sets — multiple sets when authorization grows (public vs admin).

## Common mistakes

1. **`text/template` for HTML** in the browser.
2. **Parse on every request.**
3. **Execute name that does not exist** — silent 500 in production.
4. **`template.HTML` from user input.**
5. **Unexported fields** (`title` instead of `Title`) — empty output, confusing.
6. **Forgotten charset** in Content-Type.
7. **FuncMap after Parse** then “the function does not work”.
8. **`define` name collision** on ParseFS — silent overwrite.
9. **Untrusted URL in `href`** without checking the scheme (`javascript:`).
10. **HTML comments for secret notes** — use `{{/* ... */}}`.

## Idiomatic Go

- `template.Must` on the startup path; in libraries return `error`.
- `ParseFS` + `embed` for services with static HTML.
- Exported fields in the view model struct.
- Pipeline (`{{.Name | upper}}`) for small transforms; heavier work in the handler.
- Shared `*template.Template` without a mutex after Parse (Execute is safe for concurrent read).

## Practical scenario

An admin panel shows a supplier name. Someone enters `Ada <Dev> & Co`. With `html/template` the page shows text with entities — no surprising tags. Earlier the team briefly used `text/template` “temporarily” for a faster prototype — caught in review before production. They introduce a test like Example 6 and a ban on `template.HTML` on form fields in the linter/review checklist.

## Check questions

1. **Key difference html vs text template?**  
   `html/template` automatically escapes by context; `text/template` does not.

2. **When `ParseFS`?**  
   When templates live in an `fs.FS` (`embed` or disk).

3. **What does `ExecuteTemplate` do?**  
   Executes a named template with data into a `Writer`.

4. **Why a struct instead of a map?**  
   Clearer fields, easier refactor, exported contract.

5. **When may `template.HTML` be used?**  
   Only for content you trust (sanitized / static).

6. **Why FuncMap before Parse?**  
   So the template sees function names at Parse.

7. **Why parse once?**  
   Performance and fail-fast at startup.

## Mini XSS checklist (defense)

1. `html/template` for all HTML responses
2. No `text/template` for browser HTML
3. No `template.HTML(userInput)`
4. `Content-Type: text/html; charset=utf-8`
5. Test with mild `A < B` in a field
6. URL fields: allow only `https:` / relative paths

## Caching and reload in development

Production: Parse once. Development: optional flag that reads from disk per request — faster UI turnaround. Never leave reload on in production.

## Comments in templates

- HTML `<!-- -->` reaches the client.
- Template `{{/* ... */}}` does not.

Use template comments for developer notes.

## Whitespace

`{{-` and `-}}` trim whitespace around actions. Useful around `if`/`range`. Do not overdo it — template readability still matters.

## Partials and names

Consistent names: `layout`, `nav`, `footer`, `home`, `about`. Prefix by area when the file count grows (`admin/layout`). Name collision = silent overwrite.

## Escape in attributes

```html
<input value="{{.Name}}">
```

`html/template` escapes the attribute value. Still do not put untrusted input into `onclick="..."` or `href="{{.UserURL}}"` without checking the scheme.

## What to do after the first template

1. Escape test like Example 6.
2. Layout for two pages.
3. One FuncMap helper.
4. Checklist in the PR: package, parse-once, no HTML marker from a form.

## Diagnosing empty output

When the page “has no data” but the Go struct looks full:

1. Check **exported** fields (`Title` vs `title`).
2. Check the name in `ExecuteTemplate` (does it hit the `define`).
3. Check whether the template uses `.User` while you send `Name`.
4. Check whether you hit the wrong `*template.Template` (two sets in the app).

## Separate view model

Do not send a DB struct with sensitive fields straight into the template. Map into `pageData`:

```go
type pageData struct {
	Title string
	User  string
	Items []string
}
```

Less leakage, clearer UI contract, easier test.

## Parse errors at startup

```go
t, err := parse()
if err != nil {
	log.Fatal(err) // fail closed
}
```

Broken HTML must not “start and then see”. A red deploy is better than a silent 500 for every user.

## html/template and concurrency

One `*template.Template` after Parse: multiple goroutines may call `Execute` / `ExecuteTemplate` at the same time. Do not call `Parse` on a shared tree from the request path without a local copy / mutex discipline — in practice: parse only at startup.

## Mapping errors to the user

| Situation | HTTP | Client message |
|-----------|------|----------------|
| Parse at startup | process does not start | — |
| Execute error | 500 | generic |
| Unknown template name | 500 | generic |
| Input validation before render | 400 | clear validation |

Never write `err.Error()` from the template package directly into HTML without escape — that message can contain paths too.

## Example: URL validation before href

```go
func safeHTTPURL(s string) (string, bool) {
	u, err := url.Parse(s)
	if err != nil {
		return "", false
	}
	if u.Scheme != "http" && u.Scheme != "https" {
		return "", false
	}
	return u.String(), true
}
```

In the handler: if not safe, do not put it in `href` — show text without a link. Escape in `html/template` does not replace this scheme check.

## Order in New()

```text
1. FuncMap
2. ParseFS
3. save *template.Template in Server
4. only then ListenAndServe
```

Any other order on the request path returns you to Common mistakes.

## Summary

For HTML use **`html/template`**, parse **once** (`ParseFS` + `embed`), send a **struct** into **`ExecuteTemplate`**. `text/template` stays for plain text. `FuncMap` before Parse. `template.HTML` only trusted. Escape is part of the contract, not an option. Remember: **html/template escapes; text/template does not.**

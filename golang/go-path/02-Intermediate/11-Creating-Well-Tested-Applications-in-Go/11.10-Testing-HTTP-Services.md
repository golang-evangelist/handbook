# 11.10 Testing HTTP services: `httptest.Server`, client, and caution with golden files

> **Go Path - Zero to Gopher** / **02 Intermediate → Creating Well-Tested Applications in Go** / Lesson 11.10

## Lesson goals

- Spin up an **`httptest.Server`** that listens on local loopback for the duration of the test.
- Test code that uses `http.Client` (SDK, upstream calls) against that server.
- Use `ts.URL` instead of a hardcoded port.
- Know when the Server level is better than `ResponseRecorder` alone (11.09).
- Inject base URL / `http.Client` for testability.
- Use **golden files** carefully — or deliberately avoid them when they are brittle.
- Test `context` cancel / timeout against a controlled stub.
- Always close the server (`Close` / `t.Cleanup`).

## Prerequisite

- Lesson 11.09 (`httptest` handlers, recorder).
- `http.Client`, URL, basic JSON over HTTP.
- `context.Context` basics (cancel, timeout).
- Understanding that a test still needs to be deterministic.

## Problem this lesson solves

You have client code:

```go
func (c *APIClient) GetUser(ctx context.Context, id string) (User, error) {
	req, err := http.NewRequestWithContext(ctx, http.MethodGet, c.base+"/users/"+id, nil)
	if err != nil {
		return User{}, err
	}
	res, err := c.http.Do(req)
	// ...
}
```

`ResponseRecorder` does not help directly — this code **opens an HTTP client** toward a URL. Options:

1. Hit staging (slow, flaky, secrets).
2. Mock the whole `http.RoundTripper` (good, but another abstraction level).
3. **`httptest.Server`** with a stub or real handler — the client speaks real HTTP, the server dies at the end of the test.

This lesson covers (3), compares with (2), and warns about golden snapshot abuse.

## Mental model

```text
  Test process
┌────────────────────────────────────────────┐
│  http.Client  ──HTTP──►  httptest.Server   │
│       ▲                      │             │
│       │                   Handler          │
│   APIClient               stub or mux      │
│   (base = ts.URL)                          │
└────────────────────────────────────────────┘
         ts.Close() / t.Cleanup(ts.Close)
```

| 11.09 Recorder | 11.10 Server |
|----------------|--------------|
| Direct `ServeHTTP` | Real HTTP round-trip |
| No TCP listener | Local listener, dynamic port |
| Test handlers | Test the **client** or a thin client+server pair |
| A bit faster | Still fast, a bit more setup |

## Mechanism

### Starting the server

```go
ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintln(w, `{"ok":true}`)
}))
t.Cleanup(ts.Close)

res, err := http.Get(ts.URL + "/x")
```

`NewServer` picks a free port. `ts.URL` looks like `http://127.0.0.1:PORT`. **Never** hardcode `:8080` in parallel tests.

### TLS variant

```go
ts := httptest.NewTLSServer(handler)
t.Cleanup(ts.Close)
client := ts.Client() // trusts the test certificate
res, err := client.Get(ts.URL + "/secure")
```

Plain `http.Get` against a `NewTLSServer` URL often fails TLS verification — use `ts.Client()`.

### Base URL injection — a testability requirement

```go
type APIClient struct {
	base string
	http *http.Client
}

func NewAPIClient(base string, httpClient *http.Client) *APIClient {
	if httpClient == nil {
		httpClient = http.DefaultClient
	}
	return &APIClient{base: strings.TrimRight(base, "/"), http: httpClient}
}
```

Test:

```go
c := NewAPIClient(ts.URL, ts.Client())
```

Without injection (`const base = "https://api.prod..."`) the test cannot redirect the client — a design smell.

### Stub handler vs real mux

| Stub | Real mux / `app.Routes()` |
|------|---------------------------|
| Fixed JSON / status | Real routes + handlers |
| Focus: parsing, retry, client errors | Focus: thin in-process integration |
| Faster isolation | More signal, more setup |

### Trace: what happens in a GetUser test

1. `NewServer` listens.
2. `APIClient{base: ts.URL}` builds a request to `ts.URL/users/1`.
3. Real TCP (loopback) + HTTP.
4. Stub writes JSON.
5. Client decodes into `User`.
6. `Close` shuts down the listener.

**Predict-then-answer:** you forget `ts.Close()` in a long test package. What do you risk?

Answer: leaking fds/listeners, slower tests, in extremes “too many open files.” So `t.Cleanup(ts.Close)`.

### context cancel

```go
ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
	select {
	case <-r.Context().Done():
		return
	case <-time.After(5 * time.Second):
		fmt.Fprint(w, "late")
	}
}))
```

In the test: a short timeout / cancel before 5s → the client sees an error. Do not sleep 5s in CI — cancel right after `Do` in a goroutine or use `context.WithTimeout` of 50ms with a stub that waits on `Done`.

### RoundTripper alternative (brief)

```go
type roundTripFunc func(*http.Request) (*http.Response, error)

func (f roundTripFunc) RoundTrip(r *http.Request) (*http.Response, error) {
	return f(r)
}

client := &http.Client{Transport: roundTripFunc(func(r *http.Request) (*http.Response, error) {
	return &http.Response{
		StatusCode: 200,
		Body:       io.NopCloser(strings.NewReader(`{"ok":true}`)),
		Header:     make(http.Header),
	}, nil
})}
```

No TCP. Good for pure client logic. Choose `httptest.Server` when you want wire fidelity + handler stack.

### Golden files — what they are

“Golden” / snapshot: the expected response (or body) lives in `testdata/want.json`. The test compares got vs file.

**Useful:** stable, complex structural output; rare changes.

**Dangerous:** every whitespace fails CI; update becomes a reflex (abused `-update` flag); unreadable diff; false confidence.

Prefer structural asserts (`User.ID == "1"`) until golden proves its value.

## Rules and syntax

1. `ts := httptest.NewServer(...)` + `t.Cleanup(ts.Close)`.
2. The client gets `ts.URL` (and `ts.Client()` for TLS).
3. Do not hardcode the port.
4. Stub only the needed routes; 404 for unexpected can catch a wrong path.
5. Prefer struct fields over the whole body string.
6. Golden only with a clear update protocol.
7. Cancel/timeout tests without a long `Sleep` in the happy path.
8. Parallel tests: each its own `Server` (or careful sharing — usually its own).

## Examples

### Example 1 — Basic stub + client

```go
type User struct {
	ID   string `json:"id"`
	Name string `json:"name"`
}

type APIClient struct {
	base string
	http *http.Client
}

func NewAPIClient(base string, hc *http.Client) *APIClient {
	if hc == nil {
		hc = http.DefaultClient
	}
	return &APIClient{base: strings.TrimRight(base, "/"), http: hc}
}

func (c *APIClient) GetUser(ctx context.Context, id string) (User, error) {
	req, err := http.NewRequestWithContext(ctx, http.MethodGet, c.base+"/users/"+id, nil)
	if err != nil {
		return User{}, err
	}
	res, err := c.http.Do(req)
	if err != nil {
		return User{}, err
	}
	defer res.Body.Close()
	if res.StatusCode != http.StatusOK {
		return User{}, fmt.Errorf("status %d", res.StatusCode)
	}
	var u User
	if err := json.NewDecoder(res.Body).Decode(&u); err != nil {
		return User{}, err
	}
	return u, nil
}
```

```go
func TestAPIClient_GetUser(t *testing.T) {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.URL.Path != "/users/7" {
			http.NotFound(w, r)
			return
		}
		_ = json.NewEncoder(w).Encode(User{ID: "7", Name: "Ana"})
	}))
	t.Cleanup(ts.Close)

	c := NewAPIClient(ts.URL, nil)
	u, err := c.GetUser(context.Background(), "7")
	if err != nil {
		t.Fatal(err)
	}
	if u.ID != "7" || u.Name != "Ana" {
		t.Fatalf("got %#v", u)
	}
}
```

#### What happens here

The client does not know the server is “fake.” A path bug in the client (`/user/` instead of `/users/`) yields 404 and fail — good protection.

### Example 2 — 404 → clear error

```go
func TestAPIClient_GetUser_NotFound(t *testing.T) {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		http.NotFound(w, r)
	}))
	t.Cleanup(ts.Close)

	c := NewAPIClient(ts.URL, nil)
	_, err := c.GetUser(context.Background(), "missing")
	if err == nil {
		t.Fatal("expected error")
	}
}
```

#### What happens here

You check that the client does not “swallow” 404 as an empty User. Improve later to `errors.Is` / typed errors.

### Example 3 — Timeout

```go
func TestAPIClient_GetUser_Timeout(t *testing.T) {
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		<-r.Context().Done()
	}))
	t.Cleanup(ts.Close)

	c := NewAPIClient(ts.URL, nil)
	ctx, cancel := context.WithTimeout(context.Background(), 30*time.Millisecond)
	defer cancel()

	_, err := c.GetUser(ctx, "1")
	if err == nil {
		t.Fatal("expected timeout error")
	}
}
```

#### What happens here

The stub does not always Sleep 30ms blindly in a production handler — it waits for cancel. The test stays short. `NewRequestWithContext` is required so cancel reaches the transport.

### Example 4 — Thin integration with a real mux

```go
func TestRoutes_GetUser_Integration(t *testing.T) {
	mux := http.NewServeMux()
	mux.HandleFunc("GET /users/{id}", func(w http.ResponseWriter, r *http.Request) {
		_ = json.NewEncoder(w).Encode(User{ID: r.PathValue("id"), Name: "x"})
	})
	ts := httptest.NewServer(mux)
	t.Cleanup(ts.Close)

	c := NewAPIClient(ts.URL, nil)
	u, err := c.GetUser(context.Background(), "9")
	if err != nil {
		t.Fatal(err)
	}
	if u.ID != "9" {
		t.Fatalf("%#v", u)
	}
}
```

#### What happens here

Same process, real routing + client. Still not staging. A good bridge between unit and deploy.

### Example 5 — Golden (caution)

```go
func TestGetUser_Golden(t *testing.T) {
	// ... call client, get body bytes ...
	wantPath := filepath.Join("testdata", "user7.golden.json")
	if *update { // flag.Bool("update", false, "update golden")
		_ = os.WriteFile(wantPath, body, 0o644)
	}
	want, err := os.ReadFile(wantPath)
	if err != nil {
		t.Fatal(err)
	}
	if !bytes.Equal(bytes.TrimSpace(body), bytes.TrimSpace(want)) {
		t.Fatalf("golden mismatch")
	}
}
```

#### What happens here

The update flag is powerful and dangerous. In a PR the reviewer must **read** the golden file diff, not just click green. Often `json.Unmarshal` + fields is better.

### Example 6 — Checking the request the client sends

```go
func TestAPIClient_SendsAccept(t *testing.T) {
	var gotAccept string
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		gotAccept = r.Header.Get("Accept")
		fmt.Fprint(w, `{}`)
	}))
	t.Cleanup(ts.Close)

	c := NewAPIClient(ts.URL, nil)
	// assume GetUser sets Accept
	_, _ = c.GetUser(context.Background(), "1")
	if gotAccept != "application/json" && gotAccept != "" {
		// adapt to your client's expectation
		t.Logf("Accept=%q", gotAccept)
	}
}
```

#### What happens here

The server stub is an excellent request **spy**: path, header, method. A recorder does not see that when you test the client.

### Example 7 — Parallel and isolation

```go
func TestParallelClients(t *testing.T) {
	t.Parallel()
	ts := httptest.NewServer(http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		fmt.Fprint(w, `{"id":"1","name":"a"}`)
	}))
	t.Cleanup(ts.Close)

	c := NewAPIClient(ts.URL, nil)
	_, err := c.GetUser(context.Background(), "1")
	if err != nil {
		t.Fatal(err)
	}
}
```

#### What happens here

Each parallel test spins up its own server — no port collision. A shared global server needs synchronization; usually not worth it.

## Decision analysis

| Need | Recorder | Server | RoundTripper fake |
|---------|----------|--------|-------------------|
| Handler status/body | yes | overkill | no |
| SDK Get/Decode | no | yes | yes |
| TLS client | no | NewTLSServer | harder |
| Zero TCP | yes | no | yes |
| Spy path/header | partial | yes | yes |

**Decision:** if the function takes `http.ResponseWriter`, start from 11.09. If it takes a `base URL` and calls `Do`, start from 11.10.

## Trade-offs

| | httptest.Server | Staging | RoundTripper |
|--|----------------|---------|--------------|
| HTTP fidelity | high locally | highest + data | medium |
| Speed | high | low | highest |
| Flaky | low | high | low |
| Setup | small | large | small + manual Response |

Golden vs structural assert: golden saves typing, costs more to maintain.

## Common mistakes

1. **Hardcoded port** instead of `ts.URL`.
2. **Forgotten Close** — resource leak.
3. **Client without injected base** — test impossible.
4. **`http.Get` against a TLS server without `ts.Client()`**.
5. **Long Sleep** instead of ctx cancel.
6. **Golden update without review**.
7. **Asserting the whole body string** with unstable whitespace.
8. **One global Server for all tests** + parallel.
9. **Mixing** a recorder test of a client (does not work the way you think).
10. **Ignoring `res.Body.Close()`** in the production client — the test does not always catch it; use tools / care.

## Idiomatic Go

- `NewX(base string, hc *http.Client)` constructors.
- `t.Cleanup(ts.Close)`.
- A stub that checks `r.URL.Path` and method.
- Typed errors for 4xx/5xx.
- Stdlib `httptest` before heavy frameworks.

## Practical scenario

A mobile SDK team mocks with JSON files on disk. After changing the path from `/v1/user` to `/v1/users/{id}`, unit tests with RoundTripper stay green (they do not check path), and production 404s. They add an `httptest.Server` stub that fails on the wrong path — CI catches the next breaking change.

## Check questions

1. **When to use `httptest.Server`?**  
   When the code under test uses a real HTTP client toward a base URL.

2. **Why `ts.URL`?**  
   Dynamic port; no collisions and no hardcoding.

3. **Recorder or Server?**  
   Recorder for a direct handler; Server for client/round-trip.

4. **Risk of golden files?**  
   Brittleness on insignificant changes; hard diffs; easily abused update.

5. **How to test cancel?**  
   Pass ctx into the client; stub waits on `Done`; cancel/timeout from the test.

6. **Why `t.Cleanup(ts.Close)`?**  
   Reliable listener shutdown even when the test fails.

7. **What does `ts.Client()` solve?**  
   HTTPS against `NewTLSServer` with trust in the test certificate.

8. **Why inject base URL?**  
   Without it the test cannot point the client at the local stub.

### Additional trace — request spy

A stub can assert the method, path, and header the client sends:

```go
if r.Method != http.MethodGet || r.Header.Get("Accept") == "" {
	t.Errorf("unexpected request")
}
```

A recorder client test does not see that — hence the Server level.


### More on client tests

Minimal client contract for testing:

1. Injected base URL.
2. Injected *http.Client (or default).
3. context in Do.
4. Close body in production.

Without 1 and 2, the Server stub cannot be targeted.

**Predict-then-answer:** you use http.DefaultClient globally with Timeout changes in the test. Risk?

Answer: state leaking between tests — better a new Client per test / constructor.

## Summary

`httptest.Server` gives local HTTP for testing clients and thin mux integrations. Inject base URL, close the server, prefer structural checks. Golden files are a tool with sharp edges — use them rarely and deliberately. Next: what coverage actually proves (11.11).

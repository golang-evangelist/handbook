# 11.09 Testing web applications: handlers and templates with `httptest`

> **Go Path - Zero to Gopher** / **02 Intermediate → Creating Well-Tested Applications in Go** / Lesson 11.09

## Lesson goals

- Test `http.Handler` / `HandlerFunc` without a real TCP port using `net/http/httptest`.
- Build requests with `httptest.NewRequest` / `NewRequestWithContext` and read the response from `ResponseRecorder`.
- Check status code, headers, cookies, and body (JSON or HTML).
- Include `html/template` rendering in a test in a controlled way.
- Test query / form parameters and a simple middleware chain.
- Distinguish testing **handlers** (this lesson) from testing an **HTTP client** against `httptest.Server` (11.10).
- Keep business logic out of handlers for easier unit testing.

## Prerequisite

- Lessons 11.04–11.08.
- Basic `net/http`: handler, mux, status codes, headers.
- A preferred intro to `encoding/json` and `html/template`.
- Go 1.22+ (routing in `ServeMux` is richer; examples also work with classic patterns).

## Problem this lesson solves

The web layer often stays untested because “you need a server.” Teams then:

- spin up `:8080` and click manually;
- write flaky scripts against staging;
- test only the service layer and **skip** the HTTP contract (status 404 vs 400, headers, JSON shape).

`httptest` packages **in-process** HTTP: the same `ServeHTTP` contract, no network, no port, deterministic. This lesson shows how to test handlers and templates at that level — fast and close enough to production for most regressions in the web layer.

## Mental model

A handler is a function over a contract:

```text
Request → Handler.ServeHTTP(ResponseWriter, *Request) → Response
```

In production the transport is TCP. In a test:

```text
httptest.NewRequest  →  handler.ServeHTTP  →  ResponseRecorder
         (input)                              (captures status/body/header)
```

```text
┌──────────────┐     ServeHTTP      ┌──────────────────┐
│ *http.Request│ ─────────────────► │ ResponseRecorder │
└──────────────┘                    └──────────────────┘
        ▲                                   │
   NewRequest                    Code, HeaderMap, Body
```

You are not testing the browser, CSS, or “whether the user sees a button.” You are testing the **handler contract**: code, headers, body, and optionally cookies.

## Mechanism

### ResponseRecorder — what it remembers

`httptest.ResponseRecorder` implements `http.ResponseWriter`:

| Field / method | Meaning |
|---------------|----------|
| `Code` | status; if the handler never calls `WriteHeader`, you often see 200 after the first `Write` |
| `HeaderMap` / `Result().Header` | headers |
| `Body` | `*bytes.Buffer` of the body |
| `Result()` | assembled `*http.Response` (useful for cookies) |

**Predict-then-answer:** the handler only does `fmt.Fprint(w, "ok")` without `WriteHeader`. What is `rr.Code`?

Answer: **200**. The first write to the body implicitly sends 200 if status was not set — the same behavior as a real server.

### NewRequest

```go
req := httptest.NewRequest(http.MethodGet, "/hello", nil)
req = httptest.NewRequest(http.MethodPost, "/items", strings.NewReader(`{"n":1}`))
req.Header.Set("Content-Type", "application/json")
```

Notes:

- The URL in `NewRequest` can be a path (`/hello`) — enough for most handler tests.
- Body must be an `io.Reader`; after the handler reads it the stream is consumed (as in production).
- For context: `httptest.NewRequestWithContext(ctx, method, target, body)`.

`NewRequest` returns `(*http.Request, error)` in older signatures — in modern Go, `httptest.NewRequest` panics on URL parse error in a test-helper style; check the docs for your version and use `NewRequestWithContext` when you pass a `ctx`.

> In Go 1.17+ `httptest.NewRequest` has a signature that returns only `*http.Request` and panics if the URL cannot be parsed — convenient for tests. For production code still use `http.NewRequest`.

### Trace of one test (step by step)

```go
func TestHello(t *testing.T) {
	rr := httptest.NewRecorder()                         // 1. empty recorder
	req := httptest.NewRequest(http.MethodGet, "/hello", nil) // 2. input
	HelloHandler().ServeHTTP(rr, req)                   // 3. same code as the server

	if rr.Code != http.StatusOK {                       // 4. assert status
		t.Fatalf("status %d", rr.Code)
	}
	if got := rr.Body.String(); got != "zdravo\n" {     // 5. assert body
		t.Fatalf("body %q", got)
	}
}
```

No `ListenAndServe`. No port. No race with other tests over `:8080`.

### Mux and routes — two levels

1. **Handler alone** — `h.ServeHTTP(rr, req)` with the path the handler expects (unit focus).
2. **Mux** — `mux.ServeHTTP(rr, req)` to also check **routing** (404 vs wrong handler).

```go
mux := http.NewServeMux()
mux.HandleFunc("GET /hello", Hello) // Go 1.22+ pattern
// or classic: mux.HandleFunc("/hello", Hello)

req := httptest.NewRequest(http.MethodGet, "/hello", nil)
mux.ServeHTTP(rr, req)
```

**Predict-then-answer:** you test only `Hello` directly, but the mux wrongly registers `/helo`. Which test catches the bug?

Answer: only the mux-level test. So for critical routes keep at least one test through the mux.

### JSON API flow

1. Send a body reader with JSON.
2. Set `Content-Type`.
3. Check `rr.Code`.
4. `json.Unmarshal(rr.Body.Bytes(), &got)`.
5. Compare fields — not the whole string if key order is not stable (encoding/json is stable for structs, but softer field asserts are more readable).

### HTML / template

```go
tmpl := template.Must(template.New("hi").Parse(`<h1>{{.Name}}</h1>`))
// handler runs Execute into ResponseWriter
```

Assert strategy:

- status 200;
- `strings.Contains(body, "Marko")`;
- optionally absence of `{{` (not rendered).

Avoid comparing the entire HTML document unless you must — brittleness (11.10 golden).

### Query and form

```go
req := httptest.NewRequest(http.MethodGet, "/search?q=go", nil)
q := req.URL.Query().Get("q") // "go"
```

POST form:

```go
form := url.Values{"q": {"go"}}
req := httptest.NewRequest(http.MethodPost, "/search", strings.NewReader(form.Encode()))
req.Header.Set("Content-Type", "application/x-www-form-urlencoded")
```

If the handler calls `ParseForm`, body + Content-Type must be correct — otherwise the test falsely claims “the form does not work” when the setup is wrong.

### Middleware chain

```go
func withRequestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("X-Request-Id", "test-id")
		next.ServeHTTP(w, r)
	})
}
```

Test: `withRequestID(inner).ServeHTTP(rr, req)` → check the header on `rr`.

### Path values (Go 1.22+)

```go
mux.HandleFunc("GET /items/{id}", func(w http.ResponseWriter, r *http.Request) {
	id := r.PathValue("id")
	fmt.Fprint(w, id)
})

req := httptest.NewRequest(http.MethodGet, "/items/42", nil)
mux.ServeHTTP(rr, req)
// expect body "42"
```

For a direct handler call without a mux, `PathValue` may be empty — so test path parameters **through the mux**.

### What `httptest` does not replace

- A real TLS handshake with a client cert (see `NewTLSServer` in 11.10).
- Load / real network latency.
- Browser behavior (CORS preflight in a full stack — you can unit-test partially, but E2E is another layer).

## Rules and syntax

```go
func TestHello(t *testing.T) {
	rr := httptest.NewRecorder()
	req := httptest.NewRequest(http.MethodGet, "/hello", nil)
	HelloHandler().ServeHTTP(rr, req)

	if rr.Code != http.StatusOK {
		t.Fatalf("status %d, want 200", rr.Code)
	}
	if !strings.Contains(rr.Body.String(), "zdravo") {
		t.Fatalf("body = %q", rr.Body.String())
	}
}
```

Rules:

1. A new `ResponseRecorder` per test / `t.Run` subtest.
2. Do not share `rr` across cases — state mixes.
3. Assert status **before** or alongside body; body on 500 often explains the fail.
4. For JSON: Unmarshal + fields, not only `Contains` if you validate structure.
5. For HTML: soft substrings.
6. Inject dependencies (store interface) — do not hit a real database from a handler unit test.
7. Table-driven for status × input matrices.
8. Handler test ≠ client test (11.10).

## Examples

### Example 1 — Thinnest GET handler

```go
package web

import "net/http"

func HelloHandler() http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Content-Type", "text/plain; charset=utf-8")
		_, _ = w.Write([]byte("zdravo\n"))
	})
}
```

```go
package web_test

import (
	"net/http"
	"net/http/httptest"
	"testing"

	"example.com/app/web"
)

func TestHelloHandler(t *testing.T) {
	rr := httptest.NewRecorder()
	req := httptest.NewRequest(http.MethodGet, "/hello", nil)
	web.HelloHandler().ServeHTTP(rr, req)

	if rr.Code != http.StatusOK {
		t.Fatalf("status %d", rr.Code)
	}
	if ct := rr.Header().Get("Content-Type"); ct != "text/plain; charset=utf-8" {
		t.Fatalf("Content-Type %q", ct)
	}
	if rr.Body.String() != "zdravo\n" {
		t.Fatalf("body %q", rr.Body.String())
	}
}
```

#### What happens here

A full Request→Response round trip in memory. You check the contract that both browser and API client see: status, Content-Type, body.

### Example 2 — JSON POST table-driven

```go
func CreateItem(w http.ResponseWriter, r *http.Request) {
	if r.Method != http.MethodPost {
		http.Error(w, "method", http.StatusMethodNotAllowed)
		return
	}
	var in struct {
		Name string `json:"name"`
	}
	if err := json.NewDecoder(r.Body).Decode(&in); err != nil || in.Name == "" {
		http.Error(w, "bad request", http.StatusBadRequest)
		return
	}
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusCreated)
	_ = json.NewEncoder(w).Encode(map[string]string{"name": in.Name})
}
```

```go
func TestCreateItem(t *testing.T) {
	tests := []struct {
		name   string
		body   string
		want   int
		wantN  string
	}{
		{name: "ok", body: `{"name":"x"}`, want: http.StatusCreated, wantN: "x"},
		{name: "empty", body: `{"name":""}`, want: http.StatusBadRequest},
		{name: "bad json", body: `{`, want: http.StatusBadRequest},
	}
	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			rr := httptest.NewRecorder()
			req := httptest.NewRequest(http.MethodPost, "/items", strings.NewReader(tc.body))
			req.Header.Set("Content-Type", "application/json")
			CreateItem(rr, req)
			if rr.Code != tc.want {
				t.Fatalf("status %d, want %d, body %q", rr.Code, tc.want, rr.Body.String())
			}
			if tc.want == http.StatusCreated {
				var out struct{ Name string `json:"name"` }
				if err := json.Unmarshal(rr.Body.Bytes(), &out); err != nil {
					t.Fatal(err)
				}
				if out.Name != tc.wantN {
					t.Fatalf("name %q", out.Name)
				}
			}
		})
	}
}
```

#### What happens here

An input matrix covers the happy path and validation. A new `rr` per `t.Run` prevents body leakage across cases.

### Example 3 — html/template

```go
func GreetingPage(tmpl *template.Template) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		name := r.URL.Query().Get("name")
		if name == "" {
			name = "svete"
		}
		w.Header().Set("Content-Type", "text/html; charset=utf-8")
		_ = tmpl.Execute(w, struct{ Name string }{Name: name})
	}
}
```

```go
func TestGreetingPage(t *testing.T) {
	tmpl := template.Must(template.New("g").Parse(`<h1>Zdravo, {{.Name}}!</h1>`))
	rr := httptest.NewRecorder()
	req := httptest.NewRequest(http.MethodGet, "/?name=Marko", nil)
	GreetingPage(tmpl)(rr, req)

	if rr.Code != 200 {
		t.Fatalf("status %d", rr.Code)
	}
	body := rr.Body.String()
	if !strings.Contains(body, "Marko") {
		t.Fatalf("body %q", body)
	}
	if strings.Contains(body, "{{") {
		t.Fatal("template not executed")
	}
}
```

#### What happens here

The template is injected — the test does not depend on the filesystem. Soft Contains asserts stay resilient if a CSS class is later added around `<h1>`.

### Example 4 — Middleware X-Request-Id

```go
func TestWithRequestID(t *testing.T) {
	inner := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusNoContent)
	})
	rr := httptest.NewRecorder()
	req := httptest.NewRequest(http.MethodGet, "/", nil)
	withRequestID(inner).ServeHTTP(rr, req)

	if rr.Header().Get("X-Request-Id") == "" {
		t.Fatal("missing X-Request-Id")
	}
	if rr.Code != http.StatusNoContent {
		t.Fatalf("status %d", rr.Code)
	}
}
```

#### What happens here

The chain is tested from the outside — as in production. Inner is a stub; focus is the middleware contract.

### Example 5 — Auth middleware blocks

```go
func requireToken(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if r.Header.Get("Authorization") == "" {
			http.Error(w, "unauthorized", http.StatusUnauthorized)
			return
		}
		next.ServeHTTP(w, r)
	})
}
```

```go
func TestRequireToken(t *testing.T) {
	ok := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.WriteHeader(http.StatusOK)
	})

	t.Run("missing", func(t *testing.T) {
		rr := httptest.NewRecorder()
		req := httptest.NewRequest(http.MethodGet, "/", nil)
		requireToken(ok).ServeHTTP(rr, req)
		if rr.Code != http.StatusUnauthorized {
			t.Fatalf("status %d", rr.Code)
		}
	})

	t.Run("present", func(t *testing.T) {
		rr := httptest.NewRecorder()
		req := httptest.NewRequest(http.MethodGet, "/", nil)
		req.Header.Set("Authorization", "Bearer x")
		requireToken(ok).ServeHTTP(rr, req)
		if rr.Code != http.StatusOK {
			t.Fatalf("status %d", rr.Code)
		}
	})
}
```

#### What happens here

No user database — only the HTTP boundary. Extract business token checking into a function / interface and test it separately.

### Example 6 — Store interface in the handler

```go
type Store interface {
	Get(id string) (string, error)
}

func GetItem(s Store) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		id := r.URL.Query().Get("id")
		v, err := s.Get(id)
		if err != nil {
			http.Error(w, "not found", http.StatusNotFound)
			return
		}
		_, _ = io.WriteString(w, v)
	}
}

type fakeStore map[string]string

func (f fakeStore) Get(id string) (string, error) {
	v, ok := f[id]
	if !ok {
		return "", fmt.Errorf("missing")
	}
	return v, nil
}
```

```go
func TestGetItem(t *testing.T) {
	h := GetItem(fakeStore{"1": "apple"})
	rr := httptest.NewRecorder()
	req := httptest.NewRequest(http.MethodGet, "/item?id=1", nil)
	h.ServeHTTP(rr, req)
	if rr.Body.String() != "apple" {
		t.Fatalf("body %q", rr.Body.String())
	}
}
```

#### What happens here

The handler test stays fast. The fake store controls the 200/404 branches. This is idiomatic Go web design under test.

### Example 7 — Cookie via Result()

```go
func TestSetSessionCookie(t *testing.T) {
	h := http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		http.SetCookie(w, &http.Cookie{Name: "sid", Value: "abc", Path: "/"})
		w.WriteHeader(http.StatusNoContent)
	})
	rr := httptest.NewRecorder()
	req := httptest.NewRequest(http.MethodPost, "/login", nil)
	h.ServeHTTP(rr, req)

	res := rr.Result()
	defer res.Body.Close()
	cookies := res.Cookies()
	if len(cookies) != 1 || cookies[0].Name != "sid" || cookies[0].Value != "abc" {
		t.Fatalf("cookies %#v", cookies)
	}
}
```

#### What happens here

`Result()` gives an `*http.Response` suited for `Cookies()`. More reliable than manually parsing the `Set-Cookie` string.

### Example 8 — Common trap: shared recorder

```go
// BAD
rr := httptest.NewRecorder()
for _, tc := range tests {
	req := httptest.NewRequest(http.MethodGet, tc.path, nil)
	h.ServeHTTP(rr, req) // body appends!
}
```

#### What happens here

The body buffer grows; status may stick from the first WriteHeader. Always a new `rr` per case.

## Decision analysis

| Question | Choose |
|---------|--------|
| Regression on JSON fields? | handler + Unmarshal |
| Regression on route 404? | mux.ServeHTTP |
| HTML copy? | Contains / small fragment |
| Real DB? | not in this layer — fake |
| Client with base URL? | 11.10 Server |
| E2E browser? | another tool (not httptest) |

## Trade-offs

| | `httptest` handler | Real server + curl | E2E browser |
|--|-------------------|---------------------|--------------|
| Speed | high | medium | low |
| Flaky | low | medium | high |
| TCP fidelity | low | higher | highest UI |
| Feedback in CI | excellent | OK | slow |

Course trade-off: **handler unit + occasional mux test** cover most regressions cheaply. Server client (11.10) when the code really speaks HTTP.

## Common mistakes

1. **Spinning up `:8080` in a unit test** — slower, port collisions, flaky.
2. **Shared `ResponseRecorder`** in a loop.
3. **Asserting only body**, forgetting status (200 with an error in JSON).
4. **Full HTML golden** without need.
5. **Handler closed over a global database** — slow, test order.
6. **Testing path parameters without a mux** (empty `PathValue`).
7. **Forgotten Content-Type** in POST JSON / form setup.
8. **Mixing a client test with a recorder** — wrong level.
9. **Reading the body twice** without restarting the reader.
10. **`http.Error` body + assuming JSON** — check what the handler actually writes.

## Idiomatic Go

- Small handlers; logic in a service / store interface.
- `httptest` from stdlib — no heavy framework mock to start.
- Table-driven status matrices.
- `t.Parallel` carefully if you share global state (better not to share).
- Go 1.22+ method-aware routes: test through the mux.

## Practical scenario

A checkout form “sometimes” returns 500. Without handler tests, the team reproduces only on staging. After adding table-driven `TestCheckout` with a fake store that returns an error, they discover the handler sends 500 instead of 422 for a validation error — and that the client does not show the message.

Fix + test shorten MTTR: the next similar bug fails in CI in 2 seconds, not after 2 hours on staging.

## Check questions

1. **What does `ResponseRecorder` do?**  
   It captures status, headers, and body instead of a real network response.

2. **Why `httptest` for handlers?**  
   In-process, fast, no port and no network.

3. **How to test a JSON API?**  
   Send a body reader, check code, `json.Unmarshal` the response.

4. **What to assert in HTML?**  
   Key content parts and status, not the whole document without need.

5. **Handler vs server test?**  
   Handler: `ServeHTTP` + recorder. Server/client: `httptest.Server` (11.10).

6. **Why a new recorder per case?**  
   So body and status do not mix across scenarios.

7. **How to test path `{id}` in Go 1.22+?**  
   Through a mux that parses the pattern, not a bare handler without a mux.

8. **What does a middleware test check?**  
   That the chain sets a header / status before or instead of the inner handler.

## Summary

`httptest` makes web handlers and templates unit-testable: `NewRequest` + `ServeHTTP` + `ResponseRecorder`. Check status, headers, and a meaningful part of the body. Keep business logic out of handlers; keep HTML asserts soft. Next step is a real client against `httptest.Server`.

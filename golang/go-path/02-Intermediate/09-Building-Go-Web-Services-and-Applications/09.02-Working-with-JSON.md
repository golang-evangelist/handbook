# 09.02 Working with JSON: encoding/json in services

> **Go Path - Zero to Gopher** / **02 Intermediate → Building Go Web Services and Applications** / Lesson 09.02

## Lesson goals

After this lesson you can:

- distinguish `Marshal`/`Encode` from `Unmarshal`/`Decode` and choose the right tool at the HTTP boundary;
- write `struct` tags: name, `omitempty`, `json:"-"`;
- recognize **zero value** traps with `false`/`0` and `omitempty`;
- prefer a concrete `struct` at the boundary over `map[string]any`;
- decode a body with `json.Decoder` + `io.LimitReader` + `DisallowUnknownFields` + a trailing-bytes check;
- understand that an `Encoder` error after `WriteHeader` cannot change the status;
- avoid the `float64` trap for IDs (`UseNumber` / `json.Number` / string ID / minor units);
- use **pointer** fields for PATCH (distinguishing “not sent” from zero value);
- work with a `json.RawMessage` envelope;
- map status `400`/`404`/`409` with a clear JSON body;
- write golden JSON contract tests.

## Prerequisite

- Lesson 09.01: thin handler, `writeJSON`/`writeErr`, `Store` `interface`.
- `struct`, tags, `io.Reader` / `io.Writer`.
- Go 1.22+.

## Problem this lesson solves

JSON looks simple until you hit:

- silent loss of precision for large integers in `float64`;
- fields that “disappear” because of a wrong tag or `omitempty`;
- unknown fields that `encoding/json` ignores — the client thinks the setting was accepted;
- a huge body loaded into memory without a limit;
- an `Encode` error after a `200` header already sent;
- PATCH where `false` and “not sent” look the same.

This lesson establishes disciplines for API input/output on the same REST skeleton from 09.01.

## Mental model

```text
HTTP body (bytes)
    │
    ▼
Decoder (+ LimitReader, DisallowUnknownFields)
    │
    ▼
DTO struct  ──validation──►  domain / service
    │
    ▼
Encoder / Marshal
    │
    ▼
HTTP response (status + JSON)
```

| Operation | Input | Output | Typical use |
|-----------|-------|--------|-------------|
| `json.Marshal` | Go value | `[]byte` | small responses, tests |
| `json.NewEncoder(w).Encode` | Go value | stream into `Writer` | handler response |
| `json.Unmarshal` | `[]byte` | Go value | when you already have bytes |
| `json.NewDecoder(r).Decode` | `Reader` | Go value | HTTP body |

The tag ``json:"name,omitempty"`` controls the name and when a field is omitted. The default number type on decode into `any`/`interface{}` is `float64` — be careful.

The **handler** should:

1. limit body size;
2. decode into a concrete type;
3. reject unknown fields when the contract is strict;
4. validate business rules (in the service);
5. encode the response after it knows the status.

### Terminology

| Term | Gloss (first time) |
|------|--------------------|
| composite literal | literal value of a type (`Order{...}`) |
| zero value | zero value of a type |
| pointer | pointer |
| exported / unexported | exported / unexported name (`Email` vs `email`) |

## Mechanism

### 1. Marshal/Encode vs Unmarshal/Decode

`Marshal` builds `[]byte` in memory. `Encode` writes to an `io.Writer` and appends a newline at the end. For handlers usually `Encoder` on `ResponseWriter`. For tests often `Marshal` + byte comparison.

`Unmarshal` needs the whole document in memory. `Decode` reads **one** JSON value from a stream — natural for `r.Body`.

**Predict:** what does a second `Decode` on the same `Decoder` do after a successful first?

**Answer:** It tries to read the next JSON value. If the body has trailing junk, the second `Decode` can return an error — we use that to check “exactly one object”.

### 2. Tags

```go
type User struct {
	ID    string `json:"id"`
	Email string `json:"email"`
	Pass  string `json:"-"`              // never in JSON
	Nick  string `json:"nick,omitempty"` // omit zero value
}
```

- `json:"-"` — the field is ignored on encode/decode.
- `omitempty` — omits zero value: `""`, `0`, `false`, `nil`, empty `slice`/`map`.
- Field name without a tag: the **exported** name goes to JSON; **unexported** is ignored.

### 3. Zero value traps with omitempty

```go
type Patch struct {
	Active bool `json:"active,omitempty"`
}
```

`Active: false` is **not** sent in JSON because of `omitempty`. The client cannot tell “turned off” from “not in the response”. For PATCH input use `*bool` (pointer): `nil` = not sent, `&false` = explicitly false.

The same applies to `0` for counters and amounts.

### 4. Struct at the boundary > map[string]any

`map[string]any` loses types, makes validation and documentation harder. A concrete DTO `struct`:

- the compiler and IDE help;
- tags are the contract;
- tests compare known fields.

Leave `map` for truly dynamic envelopes, not for every endpoint.

### 5. Decoder discipline

```go
const maxBody = 1 << 20 // 1 MiB

func decodeJSON(w http.ResponseWriter, r *http.Request, dst any) error {
	r.Body = http.MaxBytesReader(w, r.Body, maxBody)
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()
	if err := dec.Decode(dst); err != nil {
		return err
	}
	// trailing: there must not be another JSON value in the body
	if dec.More() {
		return errors.New("trailing data")
	}
	return nil
}
```

Alternative with `io.LimitReader` (without the `MaxBytesError` type):

```go
limited := io.LimitReader(r.Body, maxBody)
dec := json.NewDecoder(limited)
```

- `MaxBytesReader` / `LimitReader` — memory protection.
- `DisallowUnknownFields` — unknown field → error (good for a strict contract).
- `More` / second `Decode` — reject `{}{}` or junk after the object.
- Prefer `MaxBytesReader(w, ...)` in handlers: you get `*http.MaxBytesError` and can return `413`.

### 6. Encoder and late error

```go
func writeJSON(w http.ResponseWriter, status int, v any) {
	w.Header().Set("Content-Type", "application/json; charset=utf-8")
	w.WriteHeader(status)
	if err := json.NewEncoder(w).Encode(v); err != nil {
		// status is already 200/201/... — you cannot switch to 500
		// log; the client may see truncated JSON
		return
	}
}
```

**Execution trace (bad order):**

```text
1. WriteHeader(200)
2. Encode fails (e.g. a channel in a struct, or broken pipe)
3. Impossible to send 500
```

Therefore: validate/prepare the DTO **before** `WriteHeader`, or `Marshal` into a buffer then `Write` if you need a more atomic response for small payloads.

```go
b, err := json.Marshal(v)
if err != nil {
	writeErr(w, http.StatusInternalServerError, "encode failed")
	return
}
w.Header().Set("Content-Type", "application/json; charset=utf-8")
w.WriteHeader(status)
_, _ = w.Write(b)
_ = w.Write([]byte("\n")) // optional alignment with Encode
```

### 7. float64 ID trap

JSON numbers in `interface{}` / `any` become `float64`. A large integer ID (snowflake) loses precision.

Options:

| Approach | When |
|----------|------|
| ID as `string` in JSON | most often the cleanest |
| `dec.UseNumber()` + `json.Number` | when it must be a number in JSON |
| minor units (`int64`) for money | not binary float |
| explicit `int64` in struct | decode directly into the type |

```go
dec := json.NewDecoder(r.Body)
dec.UseNumber()
```

`json.Number` is a `string` underneath — you parse with `Int64()`/`Float64()` deliberately.

### 8. Pointer fields for PATCH

```go
type OrderPatch struct {
	Item   *string `json:"item"`
	Status *string `json:"status"`
	Active *bool   `json:"active"`
}

func applyPatch(o *Order, p OrderPatch) {
	if p.Item != nil {
		o.Item = *p.Item
	}
	if p.Status != nil {
		o.Status = *p.Status
	}
	if p.Active != nil {
		o.Active = *p.Active
	}
}
```

`nil` pointer = field not in JSON (or it is `null` — check the contract: often you treat `null` as clear; document it).

### 9. json.RawMessage envelope

```go
type Envelope struct {
	Type string          `json:"type"`
	Data json.RawMessage `json:"data"`
}
```

First decode the wrapper, then `json.Unmarshal(env.Data, &concrete)` by `Type`. Useful for webhooks and message versions — does not replace a DTO for ordinary CRUD.

### 10. Status codes with JSON

| Situation | Status | Body (example) |
|-----------|--------|----------------|
| Bad JSON / unknown field / trailing | 400 | `{"error":"bad json"}` |
| Not found | 404 | `{"error":"not found"}` |
| Conflict (duplicate ID) | 409 | `{"error":"conflict"}` |
| Success Create | 201 | resource |
| Success Get/List | 200 | resource / list |

Do not mix: a JSON validation error is `400`; business “does not exist” is `404`.

### 11. Golden JSON contract tests

Keep the expected JSON in a file or string constant. Encode DTO → compare with golden (often via `cmp` or `bytes.Equal` after `json.Compact`).

```go
func TestOrderJSONContract(t *testing.T) {
	o := Order{ID: "ord_1", Item: "book", Status: "new"}
	got, err := json.Marshal(o)
	if err != nil {
		t.Fatal(err)
	}
	want := []byte(`{"id":"ord_1","item":"book","status":"new"}`)
	var a, b any
	_ = json.Unmarshal(got, &a)
	_ = json.Unmarshal(want, &b)
	if !reflect.DeepEqual(a, b) {
		t.Fatalf("contract drift:\n got %s\nwant %s", got, want)
	}
}
```

Goal: an accidental tag or `omitempty` change fails the test — the contract with the client stays explicit.

## Rules and syntax

- At the API boundary: DTO `struct`, not `map[string]any` (except a deliberate envelope).
- Input: `MaxBytesReader`/`LimitReader` + `Decoder` + `DisallowUnknownFields` + trailing check.
- Output: set status deliberately; an `Encode` error after `WriteHeader` is only logged — or `Marshal` then `Write`.
- Secrets: `json:"-"`; do not log full payloads with passwords.
- IDs: prefer `string` or `json.Number`, not blind `float64`.
- Money: minor units (`int64`) or string decimal — not `float64`.
- PATCH: pointer fields for “not sent”.
- Document `omitempty` in the API contract — watch `false`/`0`.
- Golden tests for critical response shapes.

## Examples

### Example 1 — Tags, omitempty, and json:"-"

```go
package main

import (
	"encoding/json"
	"fmt"
)

type User struct {
	ID       string `json:"id"`
	Email    string `json:"email"`
	Password string `json:"-"`
	Nick     string `json:"nick,omitempty"`
	Active   bool   `json:"active,omitempty"`
}

func main() {
	u := User{
		ID:       "u1",
		Email:    "a@b.c",
		Password: "secret",
		Nick:     "",
		Active:   false,
	}
	b, _ := json.Marshal(u)
	fmt.Println(string(b))
	// {"id":"u1","email":"a@b.c"} — Pass hidden; Nick and Active omitted
}
```

#### What happens here

- `Password` never goes into JSON.
- Empty `Nick` and `Active: false` disappear because of `omitempty`.
- If the API must send `"active": false`, remove `omitempty` or use `*bool`.

### Example 2 — Decoder in a handler with limit and DisallowUnknownFields

```go
package httpapi

import (
	"encoding/json"
	"errors"
	"io"
	"net/http"
)

const maxBody = 1 << 20

type createOrderIn struct {
	Item string `json:"item"`
}

func decodeJSON(w http.ResponseWriter, r *http.Request, dst any) error {
	r.Body = http.MaxBytesReader(w, r.Body, maxBody)
	dec := json.NewDecoder(r.Body)
	dec.DisallowUnknownFields()
	if err := dec.Decode(dst); err != nil {
		return err
	}
	if dec.More() {
		return errors.New("trailing data")
	}
	return nil
}

func (h OrderHandler) Create(w http.ResponseWriter, r *http.Request) {
	var in createOrderIn
	if err := decodeJSON(w, r, &in); err != nil {
		var maxErr *http.MaxBytesError
		if errors.As(err, &maxErr) {
			writeErr(w, http.StatusRequestEntityTooLarge, "body too large")
			return
		}
		writeErr(w, http.StatusBadRequest, "bad json")
		return
	}
	o, err := h.Svc.Create(r.Context(), in.Item)
	if err != nil {
		mapDomainErr(w, err)
		return
	}
	writeJSON(w, http.StatusCreated, o)
}
```

#### What happens here

- Unknown field (`{"item":"x","hack":1}`) → `400`.
- Body too large → `413` via `MaxBytesError`.
- Trailing second object → `400`.
- A business error still goes through `mapDomainErr` from 09.01.

### Example 3 — float64 trap and json.Number

```go
package main

import (
	"encoding/json"
	"fmt"
	"strings"
)

func main() {
	raw := `{"id": 9007199254740993}` // > 2^53

	var loose map[string]any
	_ = json.Unmarshal([]byte(raw), &loose)
	fmt.Printf("float64 id: %.0f\n", loose["id"]) // may round

	dec := json.NewDecoder(strings.NewReader(raw))
	dec.UseNumber()
	var strict map[string]any
	_ = dec.Decode(&strict)
	num := strict["id"].(json.Number)
	fmt.Println("Number:", num.String())
	i, _ := num.Int64()
	fmt.Println("Int64:", i)

	// Even better in an API:
	var typed struct {
		ID string `json:"id"`
	}
	_ = json.Unmarshal([]byte(`{"id":"9007199254740993"}`), &typed)
	fmt.Println("string id:", typed.ID)
}
```

#### What happens here

- Without `UseNumber`, a large ID in `map[string]any` goes to `float64` and loses digits.
- `json.Number` keeps the textual form of the number.
- A string ID in the contract removes the whole class of problems.

### Example 4 — PATCH with pointer fields and RawMessage

```go
package order

import "encoding/json"

type Patch struct {
	Item   *string `json:"item"`
	Status *string `json:"status"`
}

type Order struct {
	ID     string
	Item   string
	Status string
}

func Apply(o *Order, p Patch) {
	if p.Item != nil {
		o.Item = *p.Item
	}
	if p.Status != nil {
		o.Status = *p.Status
	}
}

type Envelope struct {
	Type string          `json:"type"`
	Data json.RawMessage `json:"data"`
}

func DecodeEnvelope(b []byte) (Envelope, error) {
	var e Envelope
	err := json.Unmarshal(b, &e)
	return e, err
}
```

Handler part:

```go
func (h OrderHandler) Patch(w http.ResponseWriter, r *http.Request) {
	var p order.Patch
	if err := decodeJSON(w, r, &p); err != nil {
		writeErr(w, http.StatusBadRequest, "bad json")
		return
	}
	o, err := h.Svc.Patch(r.Context(), r.PathValue("id"), p)
	if err != nil {
		mapDomainErr(w, err)
		return
	}
	writeJSON(w, http.StatusOK, o)
}
```

#### What happens here

- `{"status":"done"}` sets only status; `Item` pointer stays `nil`.
- Envelope enables later message types without breaking the outer shape.
- The service still returns `ErrNotFound` → `404`, conflict → `409`.

### Example 5 — Golden contract and Marshal-then-Write

```go
package httpapi

import (
	"encoding/json"
	"net/http"
)

func writeJSONBuffered(w http.ResponseWriter, status int, v any) {
	b, err := json.Marshal(v)
	if err != nil {
		writeErr(w, http.StatusInternalServerError, "encode failed")
		return
	}
	w.Header().Set("Content-Type", "application/json; charset=utf-8")
	w.WriteHeader(status)
	_, _ = w.Write(b)
	_, _ = w.Write([]byte("\n"))
}
```

Test:

```go
func TestCreateResponseGolden(t *testing.T) {
	o := Order{ID: "ord_1", Item: "book", Status: "new"}
	got, _ := json.Marshal(o)
	const golden = `{"id":"ord_1","item":"book","status":"new"}`
	assertJSONEqual(t, got, []byte(golden))
}
```

#### What happens here

- The buffer prevents “half JSON with 200” when `Marshal` fails.
- The golden test catches unwanted tag changes.

## Decision analysis

| Decision | Why |
|----------|-----|
| DTO `struct` at the boundary | Types, tags, documentation |
| `DisallowUnknownFields` | Strict contract; fewer silent bugs |
| Body limit | Memory protection / DoS class |
| String ID | No `float64` precision issues |
| `*T` for PATCH | Distinguishes absence from zero value |
| `Marshal` then `Write` for critical responses | Correct status if encode fails |
| Golden tests | Contract drift shows up in CI |
| `json:"-"` for secrets | Password does not leak into log/response |

## Trade-offs

- **`DisallowUnknownFields`** — stricter, better; harder for advanced clients that send extra fields (versions).
- **`omitempty`** — smaller JSON; traps with `false`/`0`.
- **`Encoder` directly on `w`** — simple; late error.
- **`Marshal` buffer** — more atomic status; more memory (OK for small API responses).
- **`map[string]any`** — fast prototyping; bad long-term contract.
- **`UseNumber` everywhere** — safer for numbers; more manual parsing.
- **Pointer PATCH** — expressive; `null` semantics must be documented.

## Common mistakes

1. **Wrong:** `json.Unmarshal(wholeBody, &map[string]any)` for every endpoint.  
   **Effect:** `float64` ID, weak validation, silent type errors.  
   **Fix:** DTO `struct` + `UseNumber` when needed.

2. **Wrong:** no limit on `r.Body`.  
   **Effect:** memory pressure from a huge body.  
   **Fix:** `http.MaxBytesReader` or `io.LimitReader`.

3. **Wrong:** ignoring unknown fields when the contract must be strict.  
   **Effect:** the client thinks the field was saved.  
   **Fix:** `DisallowUnknownFields`.

4. **Wrong:** `omitempty` on `bool` / amounts in a PATCH response.  
   **Effect:** `false`/`0` disappear; the client misreads state.  
   **Fix:** remove `omitempty` or use a pointer / explicit contract.

5. **Wrong:** `WriteHeader(200)` then `Encode` that fails.  
   **Effect:** the client sees success with a broken body.  
   **Fix:** `Marshal` before the header, or log + monitoring.

6. **Wrong:** money in `float64`.  
   **Effect:** rounding errors.  
   **Fix:** minor units (`int64`) or string decimal.

7. **Wrong:** returning a password because there is no `json:"-"`.  
   **Effect:** secret leak in the API response.  
   **Fix:** `json:"-"` or a separate response DTO without the secret.

8. **Wrong:** the same status `200` for all errors with a JSON body.  
   **Effect:** clients and alerts do not work.  
   **Fix:** `400`/`404`/`409`/`500` by error class.

## Idiomatic Go

- Concrete types at the boundary; a small DTO separate from the DB model when needed.
- One `decodeJSON` helper for all handlers.
- `errors.As` for `*http.MaxBytesError`.
- Response DTO ≠ internal domain type if secrets/fields differ.
- Table-driven tests for decode errors (unknown field, trailing, too large).
- Golden JSON for the public contract.
- Document `null` vs field absence in PATCH.

## Practical scenario

A mobile client sends large snowflake IDs as JSON numbers. The backend puts them in `map[string]any`, then into a string via `fmt.Sprint` — IDs are wrong for ~1% of users. The team switches to `string` ID in the contract, introduces `DisallowUnknownFields`, golden tests, and `MaxBytesReader`. PATCH for “deactivate” stops using `bool` with `omitempty` — introduces `*bool`. The count of “mysterious” boundary bugs drops; the contract test catches an accidental tag rename in CI.

## Check questions

1. **Encode vs Marshal?**  
   `Encode` writes to a `Writer` (+ newline); `Marshal` returns `[]byte`.

2. **Why `DisallowUnknownFields`?**  
   So an unknown field does not pass silently when the contract is strict.

3. **Why a pointer in PATCH?**  
   `nil` = not sent; a value (including zero value) = explicit.

4. **What is dangerous about JSON number → `any`?**  
   It becomes `float64` and loses precision for large integers.

5. **What if `Encode` fails after `WriteHeader`?**  
   Status cannot be changed; log / prefer `Marshal` before the header.

6. **What is `json:"-"` for?**  
   Excludes the field from JSON (e.g. password).

7. **Why not `float64` for money?**  
   Binary float is not exact for decimals; use minor units or string.

8. **What does a golden test protect?**  
   Unintentional drift of the JSON contract (tags, omitempty, names).

### Encoder SetIndent in debug

```go
enc := json.NewEncoder(w)
enc.SetIndent("", "  ") // only for local debug — often not in a production API
_ = enc.Encode(v)
```

Pretty JSON increases the response; contract tests better compare the compact form (`json.Compact`).

### Time and JSON

`time.Time` is encoded by default as an RFC3339 string. Document timezone (usually UTC in an API). Do not send “local laptop time” as the contract.

## Deeper trace: from bytes to 409

```text
POST /v1/orders  body={"item":"book","extra":true}
1. MaxBytesReader OK
2. Decode + DisallowUnknownFields → unknown field error
3. writeErr 400  (do not call Service)

POST /v1/orders  body={"item":"book"}
1. Decode OK, More() false
2. Service.Create → Store.Create
3. Store sees duplicate ID → ErrConflict
4. mapDomainErr → 409 {"error":"conflict"}

GET response with password in the same struct without json:"-"
1. Encode puts password into JSON
2. leak — that is why response DTO ≠ storage model
```

### Response DTO separate from the domain

```go
type orderResponse struct {
	ID     string `json:"id"`
	Item   string `json:"item"`
	Status string `json:"status"`
}

func toOrderResponse(o order.Order) orderResponse {
	return orderResponse{ID: o.ID, Item: o.Item, Status: o.Status}
}
```

Do not export an internal field just because `Marshal` “works”. Export the **contract**.

### Checklist before merging a JSON handler

- [ ] body limit
- [ ] `DisallowUnknownFields` (if the contract is strict)
- [ ] trailing / `More` check
- [ ] DTO `struct`, not `map[string]any`
- [ ] `json:"-"` on secrets
- [ ] ID strategy without blind `float64`
- [ ] status `400`/`404`/`409` mapped
- [ ] at least one golden or contract test

## Summary

`encoding/json` in a service is not just `Marshal`/`Unmarshal`. At the boundary: DTO `struct`, body limit, strict decode, deliberate status, care with zero value and `float64`, pointer for PATCH, golden contract. The next lesson puts persistence behind the same `Store` `interface` — JSON discipline stays the same.

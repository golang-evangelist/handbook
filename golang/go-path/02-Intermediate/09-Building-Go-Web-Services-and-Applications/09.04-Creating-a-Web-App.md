# 09.04 Web application: the same domain as HTML and API

> **Go Path - Zero to Gopher** / **02 Intermediate → Building Go Web Services and Applications** / Lesson 09.04

## Lesson goals

After this lesson you can:

- run **one** `Service` with two adapters: HTML and JSON;
- split routes: `/`, `/app`, `/v1`, `/static`, `/healthz`;
- choose `ParseForm` for HTML forms versus JSON `Decoder` for the API;
- return success as `303` PRG (Post/Redirect/Get) in the UI, and `201` in JSON;
- not blindly mix session/CSRF auth with a Bearer token;
- keep separate handler `struct`s that share the same `CreateInput` / `List` on the service;
- serve static files via `FileServer` / `FileServerFS` with `Cache-Control` (static ≠ HTML);
- map errors differently for HTML and JSON;
- not put SQL in the UI layer and not build huge `if wantsJSON` branches — the course prefers path split (alternative: `Accept` negotiation).

## Prerequisite

- 09.01–09.03: thin handler, JSON discipline, `Store` behind the service.
- Basic HTML form (`method`, `action`).
- Go 1.22+ `ServeMux` or chi.
- Details of `html/template` come in 09.05 — here “render page” is enough.

## Problem this lesson solves

Teams often copy business rules: once for a React/JSON API, once for a server-rendered admin. Or one handler with `if Accept == json` of 200 lines. Auth for the browser (cookie + CSRF) gets mixed with a Bearer token for a mobile client. SQL ends up in a template helper.

Goal: **same domain**, two thin adapters, clear routes.

## Mental model

```text
                 ┌─ httpui  (HTML, forms, session) ─┐
client ──mux────┤                                  ├──► Service ──► Store
                 └─ httpapi (JSON, Bearer/API key) ─┘
```

| Adapter | Input | Create success | Error |
|---------|-------|----------------|-------|
| HTML | `ParseForm` / `multipart` | `303` to list (PRG) | HTML page / flash |
| JSON | `Decoder` | `201` + body | JSON `writeErr` |

Same `Service.Create(ctx, CreateInput)` — different translations.

### Path split (course recommendation)

```text
GET  /           → marketing / redirect
GET  /app/...    → HTML UI
GET  /v1/...     → JSON API
GET  /static/... → FileServer
GET  /healthz    → liveness
```

Alternative: same path + `Accept` negotiation. It works, but easily slides into a `wantsJSON` monolith. This course chooses **path split**.

### Terminology

| Term | Gloss |
|------|-------|
| `method` | HTTP method / Go method — from context |
| `package` | package (`httpui` vs `httpapi`) |
| concurrency | concurrency — the same `context` through both adapters |

## Mechanism

### 1. One Service, two adapters

```go
type CreateInput struct {
	Item string
}

func (s *Service) Create(ctx context.Context, in CreateInput) (Order, error)
func (s *Service) List(ctx context.Context) ([]Order, error)
```

```go
// internal/httpapi
type OrderAPI struct{ Svc *order.Service }

// internal/httpui
type OrderUI struct{
	Svc *order.Service
	Tpl *template.Template // details in 09.05
}
```

Do not share one `struct` with 40 methods “for everything”. What is shared are **input types** and the service, not HTTP details.

### 2. Routes — map

```go
mux := http.NewServeMux()
mux.HandleFunc("GET /healthz", health)
mux.Handle("GET /static/", http.StripPrefix("/static/", static))

mux.HandleFunc("GET /{$}", ui.Home)          // exactly /
mux.HandleFunc("GET /app/orders", ui.List)
mux.HandleFunc("POST /app/orders", ui.Create)
mux.HandleFunc("GET /app/orders/new", ui.NewForm)

mux.HandleFunc("GET /v1/orders", api.List)
mux.HandleFunc("POST /v1/orders", api.Create)
mux.HandleFunc("GET /v1/orders/{id}", api.Get)
```

Go 1.22 `{$}` matches exactly `/`. Groups on chi: `r.Route("/app", ...)` and `r.Route("/v1", ...)`.

### 3. ParseForm vs JSON Decoder

**HTML:**

```go
func (h OrderUI) Create(w http.ResponseWriter, r *http.Request) {
	if err := r.ParseForm(); err != nil {
		h.renderError(w, r, http.StatusBadRequest, "bad form")
		return
	}
	in := order.CreateInput{Item: r.FormValue("item")}
	_, err := h.Svc.Create(r.Context(), in)
	if err != nil {
		h.renderDomainErr(w, r, err)
		return
	}
	http.Redirect(w, r, "/app/orders", http.StatusSeeOther) // 303
}
```

**JSON:**

```go
func (h OrderAPI) Create(w http.ResponseWriter, r *http.Request) {
	var body struct {
		Item string `json:"item"`
	}
	if err := decodeJSON(w, r, &body); err != nil {
		writeErr(w, http.StatusBadRequest, "bad json")
		return
	}
	o, err := h.Svc.Create(r.Context(), order.CreateInput{Item: body.Item})
	if err != nil {
		mapDomainErr(w, err)
		return
	}
	writeJSON(w, http.StatusCreated, o) // 201
}
```

**Predict:** why not `200` + HTML after a form POST?

**Answer:** refresh would send POST again (duplicate). PRG: `303` to a GET list.

### 4. Auth: do not mix blindly

| Client | Typical auth | CSRF |
|--------|--------------|------|
| Browser HTML | session cookie | yes (for state-changing) |
| API (mobile / SPA server) | `Authorization: Bearer ...` | usually no (no cookie session) |

If HTML and API share a cookie session without CSRF protection on forms — vulnerability. If the JSON API expects Bearer and the UI only sends a cookie, do not “fix” it with one middleware that guesses. Split middleware by `/app` and `/v1` groups.

### 5. Error mapping: HTML vs JSON

```go
func (h OrderUI) renderDomainErr(w http.ResponseWriter, r *http.Request, err error) {
	switch {
	case errors.Is(err, order.ErrInvalid):
		h.renderForm(w, r, http.StatusBadRequest, "Invalid input", r.Form)
	case errors.Is(err, order.ErrNotFound):
		h.renderError(w, r, http.StatusNotFound, "Not found")
	case errors.Is(err, order.ErrConflict):
		h.renderForm(w, r, http.StatusConflict, "Conflict", r.Form)
	default:
		h.renderError(w, r, http.StatusInternalServerError, "Server error")
	}
}
```

JSON still uses `mapDomainErr` + `writeErr`. The **same** `errors.Is`, different rendering.

### 6. Static files

```go
static := http.FileServer(http.Dir("static"))
// or embed:
// static := http.FileServerFS(staticFS)

mux.Handle("GET /static/",
	http.StripPrefix("/static/",
		cacheControl(static, "public, max-age=86400"),
	),
)
```

- `Cache-Control` for CSS/JS/images: long cache with a fingerprint in the file name.
- HTML pages: usually `no-store` or short cache — do not treat HTML as immutable static.
- Do not serve `.go` / `.env` from the project root via `FileServer` — root = the `static/` directory.

### 7. Why not a huge wantsJSON

```go
// Anti-pattern (the course avoids it as primary design)
func (h Handler) Create(w http.ResponseWriter, r *http.Request) {
	if wantsJSON(r) {
		// 80 lines JSON
	} else {
		// 80 lines HTML
	}
}
```

Better: `OrderAPI.Create` and `OrderUI.Create`. Shared are `CreateInput` and service tests. `Accept` negotiation remains a valid alternative for small endpoints, but path split scales more readably.

### 8. Execution trace — same order, two paths

```text
Browser: POST /app/orders  item=book
  ParseForm → CreateInput → Service.Create → Store
  → 303 Location: /app/orders
  → GET /app/orders → List → HTML

API: POST /v1/orders  {"item":"book"}
  Decoder → CreateInput → Service.Create → Store
  → 201 {"id":"...","item":"book",...}
```

One check “item must not be empty” lives in the service — both paths see it.

## Rules and syntax

- One `Service`; adapters `httpui` and `httpapi`.
- Path split: `/app` HTML, `/v1` JSON, `/static` files, `/healthz` live.
- Form: `ParseForm` + `303` PRG. API: `Decoder` + `201`.
- Auth middleware per route group; CSRF for cookie forms; Bearer for API — do not mix blindly.
- Separate handler `struct`s; shared input types.
- `FileServer`/`FileServerFS` only over the static root; Cache-Control for assets ≠ HTML.
- Errors: same `errors.Is`, different renderer.
- No SQL in the UI. No fat `wantsJSON` monolith handlers as the default style.

## Examples

### Example 1 — Wiring two adapters

```go
package main

import (
	"net/http"
	"time"
)

func newMux(svc *order.Service, tpl *template.Template, staticFS fs.FS) http.Handler {
	api := httpapi.OrderAPI{Svc: svc}
	ui := httpui.OrderUI{Svc: svc, Tpl: tpl}

	mux := http.NewServeMux()
	mux.HandleFunc("GET /healthz", func(w http.ResponseWriter, _ *http.Request) {
		writeJSON(w, http.StatusOK, map[string]string{"status": "ok"})
	})

	mux.Handle("GET /static/", http.StripPrefix("/static/",
		cacheControl(http.FileServerFS(staticFS), "public, max-age=86400")))

	mux.HandleFunc("GET /{$}", ui.Home)
	mux.HandleFunc("GET /app/orders", ui.List)
	mux.HandleFunc("GET /app/orders/new", ui.NewForm)
	mux.HandleFunc("POST /app/orders", ui.Create)

	mux.HandleFunc("GET /v1/orders", api.List)
	mux.HandleFunc("POST /v1/orders", api.Create)
	mux.HandleFunc("GET /v1/orders/{id}", api.Get)

	return mux
}

func cacheControl(next http.Handler, value string) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		w.Header().Set("Cache-Control", value)
		next.ServeHTTP(w, r)
	})
}

func main() {
	// store, svc, tpl, embed FS — wiring
	srv := &http.Server{
		Addr:              ":8080",
		Handler:           newMux(svc, tpl, staticFS),
		ReadHeaderTimeout: 5 * time.Second,
	}
	_ = srv
}
```

#### What happens here

- The same `svc` in both adapters.
- Static separated by cache policy.
- Routes readable: UI vs API at a glance.

### Example 2 — HTML Create (PRG) and JSON Create (201)

```go
package httpui

func (h OrderUI) Create(w http.ResponseWriter, r *http.Request) {
	if err := r.ParseForm(); err != nil {
		http.Error(w, "bad form", http.StatusBadRequest)
		return
	}
	in := order.CreateInput{Item: strings.TrimSpace(r.FormValue("item"))}
	if _, err := h.Svc.Create(r.Context(), in); err != nil {
		h.renderDomainErr(w, r, err)
		return
	}
	http.Redirect(w, r, "/app/orders", http.StatusSeeOther)
}

func (h OrderUI) List(w http.ResponseWriter, r *http.Request) {
	list, err := h.Svc.List(r.Context())
	if err != nil {
		h.renderError(w, r, http.StatusInternalServerError, "Error")
		return
	}
	_ = h.Tpl.ExecuteTemplate(w, "orders_list", list)
}
```

```go
package httpapi

func (h OrderAPI) Create(w http.ResponseWriter, r *http.Request) {
	var body struct {
		Item string `json:"item"`
	}
	if err := decodeJSON(w, r, &body); err != nil {
		writeErr(w, http.StatusBadRequest, "bad json")
		return
	}
	o, err := h.Svc.Create(r.Context(), order.CreateInput{Item: body.Item})
	if err != nil {
		mapDomainErr(w, err)
		return
	}
	writeJSON(w, http.StatusCreated, o)
}
```

#### What happens here

- Form and JSON build the same `CreateInput`.
- UI redirect `303`; API `201` + JSON.
- Template execute is a UI detail (deepened in 09.05).

### Example 3 — Middleware per group (chi sketch)

```go
r := chi.NewRouter()
r.Use(middleware.RequestID, middleware.Recoverer)

r.Get("/healthz", health)

r.Route("/v1", func(r chi.Router) {
	r.Use(BearerAuth(tokens))
	r.Get("/orders", api.List)
	r.Post("/orders", api.Create)
})

r.Route("/app", func(r chi.Router) {
	r.Use(SessionAuth(sessions))
	r.Use(CSRF(csrfKey))
	r.Get("/orders", ui.List)
	r.Post("/orders", ui.Create)
})
```

#### What happens here

- Bearer only on `/v1`.
- Session + CSRF only on `/app`.
- No single global auth that guesses the client type.

### Example 4 — List on both adapters, same service

```go
func (h OrderAPI) List(w http.ResponseWriter, r *http.Request) {
	list, err := h.Svc.List(r.Context())
	if err != nil {
		writeErr(w, http.StatusInternalServerError, "internal error")
		return
	}
	writeJSON(w, http.StatusOK, list)
}

func TestServiceCreate_UsedByBothAdapters(t *testing.T) {
```

### 9. Shared input types — where they live

Prefer the domain package:

```go
// internal/order/input.go
package order

type CreateInput struct {
	Item string
}

func (in CreateInput) Validate() error {
	if strings.TrimSpace(in.Item) == "" {
		return ErrInvalid
	}
	return nil
}
```

`httpui` does `CreateInput{Item: r.FormValue("item")}`.  
`httpapi` does `CreateInput{Item: body.Item}`.  
`Service.Create` calls `in.Validate()` once.

Do not define `UICreate` and `APICreate` with the same fields — drift is inevitable.

### 10. Execution trace — validation error on both paths

```text
HTML: POST /app/orders item=
  ParseForm → CreateInput{Item:""}
  → Validate → ErrInvalid
  → renderForm 400 "Enter an item"

JSON: POST /v1/orders {}
  Decode → Item:""
  → Validate → ErrInvalid
  → writeErr 400

Same ErrInvalid, two renderers.
```

### 11. Static FileServerFS with embed

```go
//go:embed static/*
var staticFS embed.FS

sub, err := fs.Sub(staticFS, "static")
if err != nil {
	log.Fatal(err)
}
mux.Handle("GET /static/", http.StripPrefix("/static/",
	cacheControl(http.FileServerFS(sub), "public, max-age=86400")))
```

HTML templates still go through `ExecuteTemplate` — not through FileServer. Mixing “everything is static” breaks dynamic flash/form pages.

### 12. Predict / Answer — double Create

**Predict:** the user opens the form in two tabs, submits both quickly.

**Answer:** two POSTs → two Creates if there is no idempotency key. PRG does not solve parallel tabs. For stricter UI: idempotency token in the form / unique constraint on a business key → `409`. The API can send an `Idempotency-Key` header (extension beyond the minimal course).

## Example 5 — httptest for UI redirect and API 201

```go
func TestUICreate_Redirects(t *testing.T) {
	svc := order.NewService(order.NewMemoryStore())
	ui := OrderUI{Svc: svc, Tpl: testTpl(t)}
	form := strings.NewReader("item=book")
	req := httptest.NewRequest(http.MethodPost, "/app/orders", form)
	req.Header.Set("Content-Type", "application/x-www-form-urlencoded")
	rr := httptest.NewRecorder()
	ui.Create(rr, req)
	if rr.Code != http.StatusSeeOther {
		t.Fatalf("status %d", rr.Code)
	}
	if loc := rr.Header().Get("Location"); loc != "/app/orders" {
		t.Fatalf("location %s", loc)
	}
}

func TestAPICreate_Created(t *testing.T) {
	svc := order.NewService(order.NewMemoryStore())
	api := OrderAPI{Svc: svc}
	body := strings.NewReader(`{"item":"book"}`)
	req := httptest.NewRequest(http.MethodPost, "/v1/orders", body)
	rr := httptest.NewRecorder()
	api.Create(rr, req)
	if rr.Code != http.StatusCreated {
		t.Fatalf("status %d", rr.Code)
	}
}
```

#### What happens here

- The same `MemoryStore` service proves both adapters.
- UI assert on `303` + Location; API on `201`.
- Neither a browser nor a real port is started.

## Example 6 — error pages without leaking internals

```go
func (h OrderUI) renderError(w http.ResponseWriter, r *http.Request, status int, publicMsg string) {
	vm := ErrorVM{Title: "Error", Message: publicMsg, Status: status}
	h.renderStatus(w, status, "error", vm)
}
```

Log `err` with detail in the server log; give the user `publicMsg`. Same rule as JSON `500` → `"internal error"`.

## Decision analysis

| Decision | Why |
|----------|-----|
| Path split `/app` vs `/v1` | Readability; separate auth |
| Shared `CreateInput` | One validation |
| PRG `303` | No duplicate POST on refresh |
| `201` JSON | REST expectation for Create |
| Separate handler struct | No `wantsJSON` monolith |
| Cache on `/static` | Faster assets; HTML separate |
| CSRF only on cookie UI | Correct threat assumption |

## Trade-offs

- **Path split** — more routes; clearer.
- **Accept negotiation** — fewer URLs; easier to slide into `if` hell.
- **Server-rendered + API** — one deploy; more adapter code.
- **SPA + API only** — UI outside Go; domain still one (this course covers both in-process).
- **One auth middleware** — simpler; dangerous if it mixes CSRF/Bearer.
- **Shared HTML/JSON error type** — consistent codes; rendering still different.

## Common mistakes

1. **Wrong:** copying `Create` rules into UI and API.  
   **Effect:** bug fixed in only one place.  
   **Fix:** only `Service.Create`.

2. **Wrong:** `200 OK` HTML after a form POST.  
   **Effect:** refresh = duplicate.  
   **Fix:** `303` PRG.

3. **Wrong:** SQL in a template / UI handler.  
   **Effect:** bypassing `Store`, leaking schema details.  
   **Fix:** only `Service`.

4. **Wrong:** one handler with a huge `wantsJSON`.  
   **Effect:** unreadable; auth branches mix.  
   **Fix:** path split + two structs.

5. **Wrong:** Bearer and session in the same middleware “if header then else cookie”.  
   **Effect:** CSRF holes or a broken API.  
   **Fix:** middleware per `/app` and `/v1`.

6. **Wrong:** `Cache-Control: max-age=31536000` on HTML.  
   **Effect:** users see old UI after deploy.  
   **Fix:** long cache only for fingerprinted static assets.

7. **Wrong:** `FileServer` on the repo root.  
   **Effect:** leaking source / config.  
   **Fix:** root = `static/` or embed FS.

8. **Wrong:** JSON errors as HTML and vice versa.  
   **Effect:** clients break parse.  
   **Fix:** renderer per adapter.

## Idiomatic Go

- Packages `internal/httpapi` and `internal/httpui`.
- Small input structs in domain or `internal/order`.
- `http.StatusSeeOther` (303) for PRG.
- `embed.FS` for static and templates in production.
- Table-driven service tests; thin adapter tests.
- Middleware stack per `Route` group.

## Practical scenario

A company has a JSON API for a mobile app and a “temporary” admin in the same process. A developer adds a discount only in the API handler — the admin still sells the old price. Refactor: price and validation in `Service`; UI and API only translate. Form POSTs move to 303 — duplicate orders from a “nervous” refresh disappear. CSRF on `/app`, Bearer on `/v1`. Static CSS gets a fingerprint + long cache; HTML `no-store`. The team no longer debates “which handler is the source of truth”.

## Check questions

1. **Why one Service?**  
   One business truth for HTML and JSON.

2. **What is PRG?**  
   Post/Redirect/Get — after POST a `303` to GET so refresh does not repeat POST.

3. **ParseForm vs Decoder?**  
   Form encoding for HTML; JSON Decoder for the API body.

4. **Why path split?**  
   Readable routes and auth boundaries; less `wantsJSON` hell.

5. **CSRF where?**  
   On browser session forms, not blindly on a Bearer API.

6. **Static vs HTML cache?**  
   Assets can be long; HTML usually not.

7. **Where SQL?**  
   Only behind `Store`, never in a UI template.

8. **Which Create status in the API?**  
   `201 Created` (+ resource body).

## Deeper comparison: three ways to “join” HTML and JSON

### A) Path split (recommended)

```text
/app/*  → httpui
/v1/*   → httpapi
```

### B) Accept negotiation

```go
func wantsJSON(r *http.Request) bool {
	return strings.Contains(r.Header.Get("Accept"), "application/json")
}
```

Works for a small number of endpoints. Grows into branching. Auth and CSRF become conditions inside the same handler.

### C) Separate processes

HTML in one service, API in another — shared domain `module` as a library. More ops burden; clear boundary. This course stays in **one process**, two packages.

### Mini status table

| Event | HTML | JSON |
|-------|------|------|
| Create OK | 303 | 201 |
| Bad input | 400 + form | 400 + `{"error"}` |
| Not found | 404 page | 404 JSON |
| Conflict | 409 + form | 409 JSON |
| List | 200 HTML | 200 JSON array |

### Example: Home redirect

```go
func (h OrderUI) Home(w http.ResponseWriter, r *http.Request) {
	http.Redirect(w, r, "/app/orders", http.StatusFound)
}
```

### Example: do not mix ParseMultipart without need

For ordinary forms `ParseForm` is enough. `ParseMultipartForm` only when you have file uploads — and then limit memory (`MaxMemory`). Do not read uploads in a JSON handler “just in case”.

### Anti-pattern: SQL in the UI for a “quick fix”

```go
// NO
rows, _ := db.Query("SELECT ...") // in httpui
```

Even “temporary” stays forever. Go through `Service.List`.

### Web app layer checklist

- [ ] same `Service` in `httpui` and `httpapi`
- [ ] path split `/app` `/v1` `/static` `/healthz`
- [ ] PRG on HTML Create
- [ ] `201` on JSON Create
- [ ] auth middleware per group
- [ ] Cache-Control only on static
- [ ] FileServer root = static
- [ ] error renderer separate
- [ ] no SQL in UI
- [ ] no fat `wantsJSON` handlers as standard

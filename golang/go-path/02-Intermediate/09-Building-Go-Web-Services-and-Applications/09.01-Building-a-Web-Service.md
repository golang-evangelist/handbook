# 09.01 Building a small REST service in Go

> **Go Path - Zero to Gopher** / **02 Intermediate → Building Go Web Services and Applications** / Lesson 09.01

## Lesson goals

After this lesson you can:

- split a small REST service into layers `cmd` → `httpapi` → `domain`/`service` → `repository`;
- write a **thin handler**: parse input → call the domain with `r.Context()` → status and JSON;
- keep the domain free of `http.ResponseWriter` and free of HTTP details;
- introduce `Store` as an `interface` behind the service and hide the implementation in `internal/`;
- choose Go 1.22+ `ServeMux` with `GET /v1/.../{id}` and `PathValue`, or **chi** (`Use`, `Route`, `Timeout`, `Recoverer`, `RequestID`);
- configure `http.Server` with `ReadHeaderTimeout` and graceful `Shutdown` on `SIGINT`/`SIGTERM`;
- write middleware as `func(http.Handler) http.Handler`;
- map domain errors to HTTP status via `writeJSON` / `writeErr`;
- keep dependencies in a handler `struct` and test handlers with `httptest`.

## Prerequisite

- Go 1.22+ (`go version`); modules (`go.mod`).
- Basic `net/http`: `Handler`, `ServeMux`, status codes.
- Packages, `error`, `context` from earlier Intermediate material.
- Concurrency (08.xx) at least at the level: `goroutine` (a lightweight concurrency unit — not a thread) and `context` cancellation — the handler always passes `r.Context()`.
- SQL and HTML are not required; they come in 09.03–09.05 on the same skeleton.

## Problem this lesson solves

One `main.go` with handlers, SQL, validation, and logging quickly becomes unreadable. The team does not know where a business rule goes, where auth goes, where a query goes. Tests spin up the whole process and database. Deploy sends `SIGTERM`, and the process dies mid-write because there is no `Shutdown`.

This lesson establishes a **thin HTTP layer** and clear boundaries before JSON details, the database, and HTML. The goal is not a “framework” — the goal is a structure you can extend without turning everything into ceremony.

## Mental model

```text
client
  → mux / router
    → middleware chain (RequestID, Recoverer, Timeout…)
      → thin handler (parse → domain → status/JSON)
        → service / domain (business rules, no ResponseWriter)
          → Store interface
            → MemoryStore | SQLStore | external API
```

| Layer | Responsibility | Must not |
|-------|----------------|----------|
| `cmd` | wiring: config, logger, server, signal | business rules |
| `httpapi` | HTTP ↔ DTO, status, middleware | SQL, business rules |
| `domain` / `service` | rules, orchestration | `ResponseWriter`, `*http.Request` |
| `repository` / `Store` | persistence | knowledge of HTTP |

The **handler** translates HTTP into a domain call and back into status + body. The **domain** does not know `net/http`. The **repository** hides storage behind an `interface`. **cmd** wires everything together.

Go 1.22+ `ServeMux` supports methods and wildcards (`GET /v1/orders/{id}`). **chi** gives a middleware chain and route grouping — not required, but a common choice when you want `Use` / `Route` without a hand-rolled chain.

## Mechanism

This section is the heart of the lesson. Go in order: layer boundaries → handler contract → errors → mux → middleware → lifecycle → tests.

### 1. Why `internal/`

`internal/` is a convention the compiler enforces: another `module` cannot import your `internal/...`. That is not encapsulation magic inside the same module — it is a boundary toward the outside.

```text
cmd/ordersvc/main.go
internal/httpapi/server.go
internal/httpapi/handlers_order.go
internal/httpapi/json.go
internal/order/service.go
internal/order/store.go
internal/order/memory.go
```

`order` does not import `net/http`. `httpapi` imports `order`. `cmd` sees everything and wires it.

### 2. Thin handler — four steps

1. Parse input (path, query, body).
2. Call the domain with `r.Context()`.
3. Map the domain error to an HTTP status.
4. Write JSON via shared helpers.

The handler does not “do business”. The handler translates.

```go
type OrderHandler struct {
	Svc *order.Service
}

func (h OrderHandler) Get(w http.ResponseWriter, r *http.Request) {
	id := r.PathValue("id")
	o, err := h.Svc.Get(r.Context(), id)
	if err != nil {
		mapDomainErr(w, err)
		return
	}
	writeJSON(w, http.StatusOK, o)
}
```

**Predict:** what happens if `Get` returns `order.ErrNotFound`?

**Answer:** `mapDomainErr` writes `404` and JSON `{"error":"..."}` — not `200` with an error body, and not `panic`.

### 3. Domain without ResponseWriter

```go
package order

type Service struct {
	Store Store
}

func (s *Service) Get(ctx context.Context, id string) (Order, error) {
	if id == "" {
		return Order{}, ErrInvalid
	}
	return s.Store.Get(ctx, id)
}
```

The service takes `context.Context`, not `*http.Request`. That way the same `Service` can be used by a CLI, a test, or later gRPC without copying rules.

### 4. Store as an interface

```go
type Store interface {
	Get(ctx context.Context, id string) (Order, error)
	Create(ctx context.Context, o Order) error
}
```

`MemoryStore` for tests and local start. The SQL implementation comes in 09.03. Handler and service do not know the difference — only `Store`.

### 5. Mapping domain errors to HTTP

Keep domain errors as values (`var ErrNotFound = errors.New("not found")`) and map at the boundary:

| Domain error | HTTP |
|--------------|------|
| `ErrInvalid` / validation | 400 |
| `ErrNotFound` | 404 |
| `ErrConflict` | 409 |
| unknown | 500 (log detail, short message to the client) |

```go
func mapDomainErr(w http.ResponseWriter, err error) {
	switch {
	case errors.Is(err, order.ErrNotFound):
		writeErr(w, http.StatusNotFound, "not found")
	case errors.Is(err, order.ErrInvalid):
		writeErr(w, http.StatusBadRequest, "invalid request")
	case errors.Is(err, order.ErrConflict):
		writeErr(w, http.StatusConflict, "conflict")
	default:
		writeErr(w, http.StatusInternalServerError, "internal error")
	}
}
```

### 6. writeJSON and writeErr

One way of writing responses prevents a mix of `fmt.Fprint`, hand-rolled headers, and a forgotten `Content-Type`.

```go
func writeJSON(w http.ResponseWriter, status int, v any) {
	w.Header().Set("Content-Type", "application/json; charset=utf-8")
	w.WriteHeader(status)
	enc := json.NewEncoder(w)
	if err := enc.Encode(v); err != nil {
		// header already sent — just log
		return
	}
}

func writeErr(w http.ResponseWriter, status int, msg string) {
	writeJSON(w, status, map[string]string{"error": msg})
}
```

Details of `encoding/json` (tags, `Decoder`, traps) are the topic of 09.02. Here what matters: **one helper**, consistent status, clear body.

### 7. Stdlib ServeMux (Go 1.22+)

```go
mux := http.NewServeMux()
mux.HandleFunc("GET /healthz", health)
mux.HandleFunc("GET /v1/orders/{id}", h.Get)
mux.HandleFunc("POST /v1/orders", h.Create)
```

- Method in the pattern: `GET`, `POST`, …
- Wildcard `{id}` → `r.PathValue("id")`.
- Prefix `/v1` reserves space for API versioning.

**Execution trace (Get):**

```text
1. client: GET /v1/orders/ord_42
2. ServeMux picks pattern GET /v1/orders/{id}
3. middleware (if any) → h.Get
4. PathValue("id") == "ord_42"
5. Svc.Get(ctx, "ord_42")
6. Store.Get → Order or ErrNotFound
7. writeJSON 200 or writeErr 404
```

### 8. chi as an alternative

```go
r := chi.NewRouter()
r.Use(middleware.RequestID)
r.Use(middleware.Recoverer)
r.Use(middleware.Timeout(60 * time.Second))

r.Get("/healthz", health)

r.Route("/v1", func(r chi.Router) {
	r.Get("/orders/{id}", h.Get)
	r.Post("/orders", h.Create)
})
```

| chi tool | Role |
|----------|------|
| `Use` | middleware on the current router |
| `Route` | group with a shared prefix |
| `Timeout` | cancels `context` after a duration |
| `Recoverer` | catches `panic` → 500 instead of process crash |
| `RequestID` | ID in context / header for traces |

**Predict:** must the handler know whether chi or stdlib mux is underneath?

**Answer:** No, if you use `http.HandlerFunc` and `r.PathValue` / chi URLParam consistently — or abstract reading the ID. Ideally the handler stays thin and the same.

### 9. Middleware contract

```go
func withRequestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id := r.Header.Get("X-Request-ID")
		if id == "" {
			id = newID()
		}
		ctx := context.WithValue(r.Context(), ctxKeyReqID, id)
		w.Header().Set("X-Request-ID", id)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}
```

Type: `func(http.Handler) http.Handler`. The chain reads outside-in for request, inside-out for response (depending on where you measure status).

### 10. http.Server and graceful Shutdown

```go
srv := &http.Server{
	Addr:              ":8080",
	Handler:           handler,
	ReadHeaderTimeout: 5 * time.Second,
}

go func() {
	if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
		log.Fatal(err)
	}
}()

stop := make(chan os.Signal, 1)
signal.Notify(stop, syscall.SIGINT, syscall.SIGTERM)
<-stop

ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
defer cancel()
_ = srv.Shutdown(ctx)
```

- `ReadHeaderTimeout` — a slow client does not hold the connection forever on header reading.
- `Shutdown` — stops accepting new requests; waits for existing ones to finish up to the timeout.
- Without that, Kubernetes `SIGTERM` often kills the process mid-work.

### 11. Dependencies in a handler struct

```go
type OrderHandler struct {
	Svc *order.Service
	Log *slog.Logger // optional
}
```

Do not use global variables for the store. In a test pass `MemoryStore`. In `main` pass the SQL store. Same handler.

### 12. httptest — test without a port

```go
func TestGetOrder_NotFound(t *testing.T) {
	svc := &order.Service{Store: order.NewMemoryStore()}
	h := OrderHandler{Svc: svc}

	req := httptest.NewRequest(http.MethodGet, "/v1/orders/missing", nil)
	req.SetPathValue("id", "missing")
	rr := httptest.NewRecorder()

	h.Get(rr, req)

	if rr.Code != http.StatusNotFound {
		t.Fatalf("status = %d", rr.Code)
	}
}
```

`httptest` (HTTP test) runs the handler in-process — fast, without `Listen`.

## Rules and syntax

- Handler: parse → `Service` + `r.Context()` → map `error` → `writeJSON`/`writeErr`.
- The domain does not import `net/http`.
- `Store` is an `interface`; implementations live in `internal/...`.
- Go 1.22+: `mux.HandleFunc("GET /v1/orders/{id}", ...)` + `r.PathValue("id")`.
- Or chi: `Use`, `Route`, `Timeout`, `Recoverer`, `RequestID`.
- Middleware: `func(http.Handler) http.Handler`.
- `http.Server` always with at least `ReadHeaderTimeout`.
- Graceful `Shutdown` on `SIGINT`/`SIGTERM`.
- No `panic` / `log.Fatal` from the handler.
- Do not return `200` with an error body.
- Prefix `/v1` for the public API.

## Examples

### Example 1 — Stdlib mux, thin handler, MemoryStore

```go
package main

import (
	"context"
	"encoding/json"
	"errors"
	"log"
	"net/http"
	"os"
	"os/signal"
	"syscall"
	"time"
)

var (
	ErrNotFound = errors.New("not found")
	ErrInvalid  = errors.New("invalid")
)

type Order struct {
	ID     string `json:"id"`
	Item   string `json:"item"`
	Status string `json:"status"`
}

type Store interface {
	Get(ctx context.Context, id string) (Order, error)
	Create(ctx context.Context, o Order) error
}

type MemoryStore struct {
	m map[string]Order
}

func NewMemoryStore() *MemoryStore {
	return &MemoryStore{m: make(map[string]Order)}
}

func (s *MemoryStore) Get(_ context.Context, id string) (Order, error) {
	o, ok := s.m[id]
	if !ok {
		return Order{}, ErrNotFound
	}
	return o, nil
}

func (s *MemoryStore) Create(_ context.Context, o Order) error {
	if o.ID == "" || o.Item == "" {
		return ErrInvalid
	}
	s.m[o.ID] = o
	return nil
}

type Service struct{ Store Store }

func (s *Service) Get(ctx context.Context, id string) (Order, error) {
	if id == "" {
		return Order{}, ErrInvalid
	}
	return s.Store.Get(ctx, id)
}

func (s *Service) Create(ctx context.Context, item string) (Order, error) {
	if item == "" {
		return Order{}, ErrInvalid
	}
	o := Order{ID: "ord_" + item, Item: item, Status: "new"}
	if err := s.Store.Create(ctx, o); err != nil {
		return Order{}, err
	}
	return o, nil
}

type OrderHandler struct{ Svc *Service }

func writeJSON(w http.ResponseWriter, status int, v any) {
	w.Header().Set("Content-Type", "application/json; charset=utf-8")
	w.WriteHeader(status)
	_ = json.NewEncoder(w).Encode(v)
}

func writeErr(w http.ResponseWriter, status int, msg string) {
	writeJSON(w, status, map[string]string{"error": msg})
}

func mapDomainErr(w http.ResponseWriter, err error) {
	switch {
	case errors.Is(err, ErrNotFound):
		writeErr(w, http.StatusNotFound, "not found")
	case errors.Is(err, ErrInvalid):
		writeErr(w, http.StatusBadRequest, "invalid request")
	default:
		writeErr(w, http.StatusInternalServerError, "internal error")
	}
}

func (h OrderHandler) Get(w http.ResponseWriter, r *http.Request) {
	o, err := h.Svc.Get(r.Context(), r.PathValue("id"))
	if err != nil {
		mapDomainErr(w, err)
		return
	}
	writeJSON(w, http.StatusOK, o)
}

func (h OrderHandler) Create(w http.ResponseWriter, r *http.Request) {
	var in struct {
		Item string `json:"item"`
	}
	if err := json.NewDecoder(r.Body).Decode(&in); err != nil {
		writeErr(w, http.StatusBadRequest, "bad json")
		return
	}
	o, err := h.Svc.Create(r.Context(), in.Item)
	if err != nil {
		mapDomainErr(w, err)
		return
	}
	writeJSON(w, http.StatusCreated, o)
}

func main() {
	svc := &Service{Store: NewMemoryStore()}
	h := OrderHandler{Svc: svc}

	mux := http.NewServeMux()
	mux.HandleFunc("GET /healthz", func(w http.ResponseWriter, _ *http.Request) {
		writeJSON(w, http.StatusOK, map[string]string{"status": "ok"})
	})
	mux.HandleFunc("GET /v1/orders/{id}", h.Get)
	mux.HandleFunc("POST /v1/orders", h.Create)

	srv := &http.Server{
		Addr:              ":8080",
		Handler:           mux,
		ReadHeaderTimeout: 5 * time.Second,
	}

	go func() {
		log.Println("listen :8080")
		if err := srv.ListenAndServe(); err != nil && !errors.Is(err, http.ErrServerClosed) {
			log.Fatal(err)
		}
	}()

	stop := make(chan os.Signal, 1)
	signal.Notify(stop, syscall.SIGINT, syscall.SIGTERM)
	<-stop

	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()
	_ = srv.Shutdown(ctx)
}
```

#### What happens here

- `MemoryStore` and `Service` do not know about HTTP.
- `OrderHandler` holds `Svc` — dependency explicit.
- `GET` uses `PathValue`; `POST` decodes the body (stricter JSON in 09.02).
- `main` only wires mux, server, and signal.

### Example 2 — Middleware chain on stdlib mux

```go
package httpapi

import (
	"context"
	"log/slog"
	"net/http"
	"time"
)

type ctxKey int

const keyReqID ctxKey = 1

func RequestID(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		id := r.Header.Get("X-Request-ID")
		if id == "" {
			id = time.Now().UTC().Format("20060102T150405.000000000")
		}
		ctx := context.WithValue(r.Context(), keyReqID, id)
		w.Header().Set("X-Request-ID", id)
		next.ServeHTTP(w, r.WithContext(ctx))
	})
}

func Recoverer(log *slog.Logger) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			defer func() {
				if rec := recover(); rec != nil {
					log.Error("panic", "recover", rec)
					writeErr(w, http.StatusInternalServerError, "internal error")
				}
			}()
			next.ServeHTTP(w, r)
		})
	}
}

func AccessLog(log *slog.Logger) func(http.Handler) http.Handler {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			start := time.Now()
			rw := &statusWriter{ResponseWriter: w, code: 200}
			next.ServeHTTP(rw, r)
			log.Info("request",
				"method", r.Method,
				"path", r.URL.Path,
				"status", rw.code,
				"dur", time.Since(start),
				"req_id", r.Context().Value(keyReqID),
			)
		})
	}
}

type statusWriter struct {
	http.ResponseWriter
	code int
}

func (w *statusWriter) WriteHeader(status int) {
	w.code = status
	w.ResponseWriter.WriteHeader(status)
}

func Chain(h http.Handler, mws ...func(http.Handler) http.Handler) http.Handler {
	for i := len(mws) - 1; i >= 0; i-- {
		h = mws[i](h)
	}
	return h
}
```

In `main`:

```go
handler := Chain(mux, RequestID, Recoverer(log), AccessLog(log))
srv := &http.Server{Addr: ":8080", Handler: handler, ReadHeaderTimeout: 5 * time.Second}
```

#### What happens here

- `Chain` order: first in the list is outermost (first to see the request).
- `Recoverer` prevents process crash from `panic` in a handler.
- `statusWriter` enables logging status after `WriteHeader`.
- The same middleware contract works with chi `Use`.

### Example 3 — chi Route group and Timeout

```go
package main

import (
	"net/http"
	"time"

	"github.com/go-chi/chi/v5"
	"github.com/go-chi/chi/v5/middleware"
)

func newRouter(h OrderHandler) http.Handler {
	r := chi.NewRouter()
	r.Use(middleware.RequestID)
	r.Use(middleware.RealIP)
	r.Use(middleware.Recoverer)
	r.Use(middleware.Timeout(60 * time.Second))

	r.Get("/healthz", func(w http.ResponseWriter, _ *http.Request) {
		writeJSON(w, http.StatusOK, map[string]string{"status": "ok"})
	})

	r.Route("/v1", func(r chi.Router) {
		r.Get("/orders/{id}", h.GetChi)
		r.Post("/orders", h.Create)
	})
	return r
}

func (h OrderHandler) GetChi(w http.ResponseWriter, r *http.Request) {
	id := chi.URLParam(r, "id")
	o, err := h.Svc.Get(r.Context(), id)
	if err != nil {
		mapDomainErr(w, err)
		return
	}
	writeJSON(w, http.StatusOK, o)
}
```

#### What happens here

- `Route("/v1", ...)` groups the API without repeating the prefix.
- `Timeout` cancels `r.Context()` — store/SQL that respect `context` stop.
- The handler still only calls `Svc`; the only difference is reading the path parameter.

### Example 4 — httptest table for Get

```go
package httpapi_test

import (
	"net/http"
	"net/http/httptest"
	"testing"
)

func TestOrderGet(t *testing.T) {
	store := NewMemoryStore()
	_ = store.Create(context.Background(), Order{ID: "ord_1", Item: "book", Status: "new"})
	h := OrderHandler{Svc: &Service{Store: store}}

	tests := []struct {
		name   string
		id     string
		status int
	}{
		{"found", "ord_1", http.StatusOK},
		{"missing", "nope", http.StatusNotFound},
		{"empty", "", http.StatusBadRequest},
	}

	for _, tc := range tests {
		t.Run(tc.name, func(t *testing.T) {
			req := httptest.NewRequest(http.MethodGet, "/v1/orders/"+tc.id, nil)
			req.SetPathValue("id", tc.id)
			rr := httptest.NewRecorder()
			h.Get(rr, req)
			if rr.Code != tc.status {
				t.Fatalf("got %d want %d", rr.Code, tc.status)
			}
		})
	}
}
```

#### What happens here

- Table-driven tests cover the happy path and errors without starting a server.
- `SetPathValue` simulates Go 1.22 mux behavior in a unit test.
- Service + memory — fast; SQL integration is 09.03.

## Decision analysis

| Decision | Why |
|----------|-----|
| `internal/` | Hides application code from other modules |
| Handler → Service → Store | Testability; swap storage without touching HTTP |
| Domain without `ResponseWriter` | Same service for CLI/test/API |
| Domain errors + mapping at the boundary | One source of truth for business `error` |
| `writeJSON` / `writeErr` | Consistent response contract |
| Stdlib mux or chi | Both valid; chi when you want richer DX |
| `ReadHeaderTimeout` | Mitigates slow header reading |
| `Shutdown` on signal | Cleaner deploy, fewer interrupted writes |
| Dependencies in `struct` | No hidden globals |
| `httptest` | Fast handler tests |

## Trade-offs

- **Fat handler** — faster start, harder tests, duplication when a second adapter arrives.
- **Thin handler + service** — more files, better team growth.
- **chi** — richer middleware/groups, extra dependency.
- **Stdlib only** — fewer deps, more hand-rolled chain.
- **One `main` package** — OK for a script; for a team service it quickly hurts.
- **MemoryStore in production** — simple, gone on restart; SQL in 09.03.
- **Central `mapDomainErr`** — consistency; must grow with new errors.

## Common mistakes

1. **Wrong:** business rules only in the handler.  
   **Effect:** CLI/gRPC later copies logic; bugs diverge.  
   **Fix:** rules in `Service`; handler only translates.

2. **Wrong:** ignoring `r.Context()` when calling storage.  
   **Effect:** a cancelled request still holds resources; Timeout middleware does not help.  
   **Fix:** `Svc.Get(r.Context(), id)` through the whole chain.

3. **Wrong:** `log.Fatal` or `panic` in the handler.  
   **Effect:** the whole process dies because of one bad request.  
   **Fix:** `writeErr` + log; `Recoverer` as the last line of defense.

4. **Wrong:** returning `200` with body `{"error":"..."}`.  
   **Effect:** clients and monitoring think it succeeded.  
   **Fix:** real status (`400`/`404`/`409`/`500`) + JSON body.

5. **Wrong:** `ListenAndServe` without timeout fields on `http.Server`.  
   **Effect:** a slow client holds connections; Slowloris-class risk.  
   **Fix:** at least `ReadHeaderTimeout`; consider other limits too.

6. **Wrong:** mixing API versions without a prefix.  
   **Effect:** breaking clients when the contract changes.  
   **Fix:** `/v1/...` from day one.

7. **Wrong:** SQL or file I/O directly in the handler.  
   **Effect:** cannot swap the store; tests are slow.  
   **Fix:** `Store` `interface`.

8. **Wrong:** global `var db` / `var svc`.  
   **Effect:** hidden state, hard parallel tests.  
   **Fix:** fields on the handler `struct`, wiring in `cmd`.

## Idiomatic Go

- `ServeHTTP` or `HandleFunc` — consistent in the project.
- Domain errors: `var ErrX = errors.New(...)` + `errors.Is` at the boundary.
- Middleware as `func(http.Handler) http.Handler`.
- Config from the environment, no secret in the repo.
- Table-driven `httptest` tests.
- Small `interface` near the consumer (`Store` in the `order` package).
- `context.Context` as the first argument of service/store methods.
- Explicit `Content-Type: application/json; charset=utf-8`.

## Practical scenario

A startup has an “API” in one ~2000-line file. A new developer adds an endpoint and breaks CORS/recover middleware order. Refactor: extract `httpapi`, `order`, `cmd`. Introduce chi only for `/v1` groups and `Recoverer`. `Service` tests pass without a port. Deploy gets graceful `Shutdown` — `5xx` count during rolling update drops. Structure is not ceremony; it is team speed and predictable behavior under a signal.

3. Build `OrderHandler` + `MemoryStore` + `httptest` test for `404` and `201`.
4. Add graceful `Shutdown` and check behavior on Ctrl+C.
5. Write middleware that logs method, path, status, and duration.
6. Extract `writeJSON`/`writeErr`/`mapDomainErr` into `internal/httpapi` and use them from two handler files.
7. Add `ErrConflict` on `Create` when the ID already exists and map to `409`.

## Check questions

1. **What does the handler do, and what does the service do?**  
   Handler: HTTP ↔ DTO, status, JSON. Service: business rules without `ResponseWriter`.

2. **Why `internal/`?**  
   The compiler forbids import from other modules — a stronger encapsulation boundary outward.

3. **What is `ReadHeaderTimeout` for?**  
   So a slow client does not hold connections forever on header reading.

4. **When do you choose chi?**  
   When you want a convenient middleware chain and grouping; not required with Go 1.22+ mux.

5. **What does `Shutdown` do?**  
   Stops accepting new requests and waits for existing ones to finish up to the timeout.

6. **Why `Store` as an `interface`?**  
   Swap memory for SQL (or a fake in a test) without touching the handler.

7. **What does middleware look like as a type?**  
   `func(http.Handler) http.Handler` — a wrapper around the next handler.

8. **Why `r.Context()`?**  
   Passes cancellation and values (request ID) through the service to storage.

## Layer by layer — what may know what

Dependency rule (arrow = “knows about” / imports):

```text
cmd → httpapi → order → store implementation
```

`order` does not import `net/http`. Store does not import handlers. `cmd` alone wires everything. When you break the “only this way” rule, in six months you have cyclic imports and tests that spin up the whole world.

### Skeleton of an extended writeErr

```go
type APIError struct {
	Code    string `json:"code"`
	Message string `json:"message"`
}

func writeAPIErr(w http.ResponseWriter, status int, code, msg string) {
	writeJSON(w, status, APIError{Code: code, Message: msg})
}
```

Keep one way of writing errors. Later you can introduce codes (`not_found`, `invalid_input`) without touching the domain — the domain still returns `error` values.

### Checklist before you add a database

- [ ] Handler thin; service testable without a port
- [ ] `Store` `interface` exists
- [ ] `mapDomainErr` covers at least 400/404/500
- [ ] `ReadHeaderTimeout` + `Shutdown`
- [ ] `/healthz` separate from business routes
- [ ] At least one `httptest` test for the happy path and 404

## Summary

A small REST service in Go lives on clear boundaries: thin HTTP, thick domain, swappable storage behind an `interface`, clean `cmd`. Stdlib mux or chi — choose deliberately. Middleware is a wrapper, not magic. The server shuts down gracefully. JSON, database, and HTML come in the next lessons on the same skeleton — do not break boundaries when you add details.

# 09.03 Adding a database: repository, migrations, and sqlc as an option

> **Go Path - Zero to Gopher** / **02 Intermediate → Building Go Web Services and Applications** / Lesson 09.03

## Lesson goals

After this lesson you can:

- connect the chain handler → service → repository → `database/sql` → driver;
- configure the pool: `Open`, `SetMaxOpenConns`, `SetMaxIdleConns`, `SetConnMaxLifetime`, `PingContext`;
- keep a `Store` `interface` with `MemoryStore` and a SQL implementation without changing the handler;
- write queries with `*Context` methods and map `sql.ErrNoRows` → `ErrNotFound`;
- use **only** parameterized placeholders (anti-injection discipline);
- keep migrations in VCS; understand **sqlc** as optional generation of typed queries;
- open transactions in the **SERVICE** (`BeginTx`, `defer Rollback`, `Commit`) — not in the handler;
- close `rows` (`Close` + `rows.Err`); work with `sql.Null*` / `*string`;
- read the DSN from the environment; distinguish readiness (`Ping`) from liveness;
- add indexes through migrations; choose fake vs integration tests.

## Prerequisite

- 09.01 (layers, `Store` `interface`, thin handler).
- 09.02 (JSON DTO at the boundary).
- Basic SQL (SELECT/INSERT/UPDATE); an ORM is not required.
- Go 1.22+; driver e.g. `github.com/jackc/pgx/v5/stdlib` or `modernc.org/sqlite` — the principle is the same.

## Problem this lesson solves

Without a repository boundary, SQL leaks into handlers. Tests spin up a real database. Transactions are opened in the HTTP layer and `Rollback` is forgotten. String concatenation in queries opens a class of injection bugs. Migrations live only on one developer’s laptop.

This lesson attaches persistence to the **same** `Service` + `Store` skeleton from 09.01 — without `s.DB` on the service as a hidden second path.

## Mental model

```text
handler
  → Service  (business rules, Tx orchestration)
    → Store interface
         ├─ MemoryStore      (test / local)
         └─ SQLStore (*sql.DB) → driver → database
```

| Term | Role |
|------|------|
| `*sql.DB` | connection pool, not one connection |
| `*sql.Tx` | transaction; lives briefly |
| `Store` | domain contract over persistence |
| migration | versioned schema change in VCS |
| sqlc | optional: SQL → generated Go code |

**Service** stays consistent: depends on `Store` (+ an ID factory `NewID` when needed). If an example does a money transfer, store methods take `Tx` internally or the service passes a tx-aware store — do **not** invent `s.DB` on `Service` while you also have `Store`.

### Terminology

| Term | Gloss |
|------|-------|
| `package` | package |
| `interface` | contract |
| `error` | error as a value |
| `context` | cancellation / deadline |
| zero value | zero value (`sql.NullString` Valid=false) |

## Mechanism

### 1. Dependency chain

```text
cmd: opens *sql.DB, PingContext, builds SQLStore, New Service, New handlers
httpapi: only Service
order.Service: Store (+ NewID)
order.SQLStore: *sql.DB or queries over Tx
```

The handler does not see `*sql.DB`. The service does not write SQL strings if you have a clean repository — SQL lives in the store package.

### 2. Pool: Open and limits

```go
db, err := sql.Open("pgx", dsn) // driver-specific
if err != nil {
	return err
}
db.SetMaxOpenConns(25)
db.SetMaxIdleConns(25)
db.SetConnMaxLifetime(30 * time.Minute)

ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()
if err := db.PingContext(ctx); err != nil {
	return err
}
```

- `Open` does not guarantee the database is alive — hence `PingContext`.
- `MaxOpenConns` protects the database from too many connections.
- `ConnMaxLifetime` rotates connections (useful behind a load balancer / idle timeout on the server).

### 3. Store interface — Memory vs SQL

```go
package order

type Store interface {
	Get(ctx context.Context, id string) (Order, error)
	Create(ctx context.Context, o Order) error
	UpdateStatus(ctx context.Context, id, status string) error
}

type Service struct {
	Store Store
	NewID func() string // injectable for tests
}

func NewService(store Store) *Service {
	return &Service{
		Store: store,
		NewID: func() string { return "ord_" + strconv.FormatInt(time.Now().UnixNano(), 10) },
	}
}
```

`MemoryStore` remains from 09.01. `SQLStore` implements the same contract.

### 4. Context queries and ErrNoRows

```go
func (s *SQLStore) Get(ctx context.Context, id string) (Order, error) {
	var o Order
	err := s.db.QueryRowContext(ctx, `
		SELECT id, item, status FROM orders WHERE id = $1`, id).
		Scan(&o.ID, &o.Item, &o.Status)
	if errors.Is(err, sql.ErrNoRows) {
		return Order{}, ErrNotFound
	}
	return o, err
}
```

Always `QueryContext` / `QueryRowContext` / `ExecContext` — so `Timeout` middleware and cancellation reach the database.

**Predict:** what does the handler see when there is no row?

**Answer:** `ErrNotFound` (domain), not `sql.ErrNoRows`. Mapping is in the store/service; the HTTP layer stays clean (`404`).

### 5. Parameterized queries — the only allowed form

**Correct:** placeholder + arguments.

```go
// PostgreSQL
_, err := db.ExecContext(ctx,
	`INSERT INTO orders (id, item, status) VALUES ($1, $2, $3)`,
	o.ID, o.Item, o.Status)

// SQLite / MySQL style
_, err := db.ExecContext(ctx,
	`INSERT INTO orders (id, item, status) VALUES (?, ?, ?)`,
	o.ID, o.Item, o.Status)
```

**Forbidden:** joining user input into an SQL string (`fmt.Sprintf("... WHERE id = '%s'", id)`). That is a class of SQL injection bugs. This lesson does **not** show exploit payloads — only the rule: **placeholders only**.

Identifiers (table/column name) cannot be ordinary placeholders — do not take them from the user; keep an allowlist in code.

### 6. Migrations in VCS

```text
migrations/
  0001_init.up.sql
  0001_init.down.sql
  0002_orders_status_index.up.sql
  0002_orders_status_index.down.sql
```

- Every schema change = a file in git.
- The tool (goose, migrate, atlas, …) matters less than the discipline: apply the same on CI and production.
- Indexes go **through migrations**, not “manually on prod when it slows down”.

Example `0001_init.up.sql`:

```sql
CREATE TABLE orders (
    id     TEXT PRIMARY KEY,
    item   TEXT NOT NULL,
    status TEXT NOT NULL
);
```

Example index:

```sql
CREATE INDEX orders_status_idx ON orders (status);
```

### 7. sqlc as an option

[sqlc](https://sqlc.dev) reads SQL and generates typed Go. Not required.

Benefits: less hand-rolled `Scan`, SQL stays visible. Trade-off: generated code + workflow. It can live **behind** your `Store` `interface` — the handler still does not see sqlc.

### 8. Transactions in SERVICE

```go
type TxStore interface {
	Store
	WithTx(tx *sql.Tx) Store // returns a store bound to tx
}

func (s *Service) Transfer(ctx context.Context, fromID, toID string, amount int64) error {
	// Pseudo-concept: SQLStore offers Begin + repo over Tx
	db := s.dbProvider // ONLY if the design explicitly shares DB for Begin —
	// Preferred pattern below: store.InTx
	return s.Store.InTx(ctx, func(txStore Store) error {
		if err := txStore.Debit(ctx, fromID, amount); err != nil {
			return err
		}
		return txStore.Credit(ctx, toID, amount)
	})
}
```

A more concrete, consistent pattern without `s.DB` on the service:

```go
type Store interface {
	Get(ctx context.Context, id string) (Order, error)
	Create(ctx context.Context, o Order) error
	InTx(ctx context.Context, fn func(Store) error) error
}

func (s *SQLStore) InTx(ctx context.Context, fn func(Store) error) error {
	tx, err := s.db.BeginTx(ctx, nil)
	if err != nil {
		return err
	}
	defer func() { _ = tx.Rollback() }() // no-op after Commit

	txStore := &SQLStore{db: s.db, tx: tx} // methods choose tx or db
	if err := fn(txStore); err != nil {
		return err
	}
	return tx.Commit()
}
```

- `BeginTx` + `defer Rollback` + `Commit` live in store/service orchestration.
- The handler only calls `Svc.Transfer` — it does not open Tx.
- On error `Rollback` cleans up; on success `Commit`.

**Predict:** what if the handler does `Begin` then forgets `Rollback` on early return?

**Answer:** the connection stays taken until timeout; the pool saturates. That is why Tx is not in the handler.

### 9. rows.Close and rows.Err

```go
rows, err := s.db.QueryContext(ctx, `SELECT id, item, status FROM orders WHERE status = $1`, status)
if err != nil {
	return nil, err
}
defer rows.Close()

var out []Order
for rows.Next() {
	var o Order
	if err := rows.Scan(&o.ID, &o.Item, &o.Status); err != nil {
		return nil, err
	}
	out = append(out, o)
}
if err := rows.Err(); err != nil {
	return nil, err
}
return out, nil
```

Without `Close` — connection leak. Without `rows.Err()` — missed iteration errors.

### 10. sql.Null* and *string

SQL `NULL` ≠ Go `""`.

```go
var nick sql.NullString
err := row.Scan(&nick)
// nick.Valid == false → NULL

// or in the domain:
var nickPtr *string
// scan via null type then convert
```

Do not mix silently: a `NULL` status in the DB is not the same as a zero value string in JSON — map deliberately (often a pointer in the DTO).

### 11. DSN from the environment

```go
dsn := os.Getenv("DATABASE_URL")
if dsn == "" {
	log.Fatal("DATABASE_URL required")
}
```

Do not commit passwords. Local `.env` stays out of git (gitignore).

### 12. Readiness ≠ liveness

| Probe | What it checks | Example |
|-------|----------------|---------|
| liveness | process is alive | `/healthz` → 200 without DB |
| readiness | ready for traffic | `/readyz` → `PingContext` |

If readiness = liveness and the database briefly fails, the orchestrator can kill pods in a loop. Split them.

### 13. Tests: fake vs integration

| Type | How | Speed | What it proves |
|------|-----|-------|----------------|
| fake / MemoryStore | unit | fast | business rules |
| sqlmock | unit with SQL expectations | medium | that the real queries are called |
| integration | real DB (testcontainer / CI service) | slower | schema, SQL, indexes |

Do not replace everything with integration — keep fast unit tests of the service with `MemoryStore`.

## Rules and syntax

- Handler → Service → `Store` → `database/sql` → driver.
- Pool: limits + `PingContext` at start.
- Only parameterized placeholders; never concatenate user input into SQL.
- `*Context` query methods.
- `sql.ErrNoRows` → `ErrNotFound` before the HTTP layer.
- Tx: `BeginTx`, `defer Rollback`, `Commit` — orchestration in service/store, not in the handler.
- `Service` depends on `Store` (+ `NewID`); do not mix ad-hoc `s.DB` with `Store` without a clear design.
- `rows.Close()` + `rows.Err()`.
- Migrations and indexes in VCS.
- DSN from env.
- `/healthz` ≠ `/readyz` with `Ping`.

## Examples

### Example 1 — SQLStore Get/Create with the same Service

```go
package order

import (
	"context"
	"database/sql"
	"errors"
)

type SQLStore struct {
	db *sql.DB
	tx *sql.Tx // nil → use db; set → use tx
}

func NewSQLStore(db *sql.DB) *SQLStore {
	return &SQLStore{db: db}
}

func (s *SQLStore) exec() interface {
	ExecContext(context.Context, string, ...any) (sql.Result, error)
	QueryRowContext(context.Context, string, ...any) *sql.Row
} {
	if s.tx != nil {
		return s.tx
	}
	return s.db
}

func (s *SQLStore) Get(ctx context.Context, id string) (Order, error) {
	var o Order
	err := s.exec().QueryRowContext(ctx,
		`SELECT id, item, status FROM orders WHERE id = $1`, id,
	).Scan(&o.ID, &o.Item, &o.Status)
	if errors.Is(err, sql.ErrNoRows) {
		return Order{}, ErrNotFound
	}
	return o, err
}

func (s *SQLStore) Create(ctx context.Context, o Order) error {
	_, err := s.exec().ExecContext(ctx,
		`INSERT INTO orders (id, item, status) VALUES ($1, $2, $3)`,
		o.ID, o.Item, o.Status,
	)
	return err
}

func (s *Service) Create(ctx context.Context, item string) (Order, error) {
	if item == "" {
		return Order{}, ErrInvalid
	}
	o := Order{ID: s.NewID(), Item: item, Status: "new"}
	if err := s.Store.Create(ctx, o); err != nil {
		return Order{}, err
	}
	return o, nil
}
```

#### What happens here

- The same `Service.Create` works with Memory or SQL.
- Placeholders `$1..$3` — no string joining.
- `ErrNoRows` stays inside the store → `ErrNotFound`.

### Example 2 — InTx for two operations

```go
func (s *SQLStore) InTx(ctx context.Context, fn func(Store) error) error {
	tx, err := s.db.BeginTx(ctx, nil)
	if err != nil {
		return err
	}
	defer func() { _ = tx.Rollback() }()

	if err := fn(&SQLStore{db: s.db, tx: tx}); err != nil {
		return err
	}
	return tx.Commit()
}

func (s *SQLStore) UpdateStatus(ctx context.Context, id, status string) error {
	res, err := s.exec().ExecContext(ctx,
		`UPDATE orders SET status = $1 WHERE id = $2`, status, id)
	if err != nil {
		return err
	}
	n, err := res.RowsAffected()
	if err != nil {
		return err
	}
	if n == 0 {
		return ErrNotFound
	}
	return nil
}

func (s *Service) MarkPaidIfNew(ctx context.Context, id string) error {
	return s.Store.InTx(ctx, func(st Store) error {
		o, err := st.Get(ctx, id)
		if err != nil {
			return err
		}
		if o.Status != "new" {
			return ErrConflict
		}
		return st.UpdateStatus(ctx, id, "paid")
	})
}
```

#### What happens here

- The handler calls `MarkPaidIfNew` — it does not see Tx.
- `defer Rollback` is safe after `Commit`.
- Status conflict → `ErrConflict` → HTTP `409` (from 09.01 mapping).

### Example 3 — List with rows + Null field

```go
func (s *SQLStore) ListByStatus(ctx context.Context, status string) ([]Order, error) {
	rows, err := s.db.QueryContext(ctx,
		`SELECT id, item, status, note FROM orders WHERE status = $1`, status)
	if err != nil {
		return nil, err
	}
	defer rows.Close()

	var out []Order
	for rows.Next() {
		var o Order
		var note sql.NullString
		if err := rows.Scan(&o.ID, &o.Item, &o.Status, &note); err != nil {
			return nil, err
		}
		if note.Valid {
			o.Note = note.String
		}
		out = append(out, o)
	}
	return out, rows.Err()
}
```

#### What happens here

- `note` can be SQL `NULL` — `NullString` keeps the Valid flag.
- `rows.Err()` after the loop catches cursor errors.
- The `status` filter is an argument, not part of the query string.

### Example 4 — cmd wiring, ready probe, migration checklist

```go
package main

import (
	"context"
	"database/sql"
	"log"
	"net/http"
	"os"
	"time"
)

func main() {
	dsn := os.Getenv("DATABASE_URL")
	db, err := sql.Open("pgx", dsn)
	if err != nil {
		log.Fatal(err)
	}
	defer db.Close()
	db.SetMaxOpenConns(20)
	db.SetMaxIdleConns(10)
	db.SetConnMaxLifetime(30 * time.Minute)

	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()
	if err := db.PingContext(ctx); err != nil {
		log.Fatal("db ping:", err)
	}

	store := order.NewSQLStore(db)
	svc := order.NewService(store)
	h := httpapi.NewOrderHandler(svc)

	mux := http.NewServeMux()
	mux.HandleFunc("GET /healthz", func(w http.ResponseWriter, _ *http.Request) {
		writeJSON(w, 200, map[string]string{"status": "ok"})
	})
	mux.HandleFunc("GET /readyz", func(w http.ResponseWriter, r *http.Request) {
		c, ccancel := context.WithTimeout(r.Context(), 2*time.Second)
		defer ccancel()
		if err := db.PingContext(c); err != nil {
			writeErr(w, 503, "not ready")
			return
		}
		writeJSON(w, 200, map[string]string{"status": "ready"})
	})
	mux.HandleFunc("GET /v1/orders/{id}", h.Get)
	mux.HandleFunc("POST /v1/orders", h.Create)
	// Listen + Shutdown as in 09.01
	_ = mux
}
```

#### What happens here

- Liveness without DB; readiness with `PingContext`.
- DSN from env; pool limits at start.
- The handler stays thin — SQL only in the store.

## Decision analysis

| Decision | Why |
|----------|-----|
| `Store` `interface` | Memory/SQL/fake without touching HTTP |
| `NewID` on Service | Predictable tests; no hidden time |
| Parameterized SQL | The only safe form for values |
| Tx in service/store | Handler stays thin; fewer connection leaks |
| Migrations in VCS | Repeatable schema deploy |
| sqlc optional | Types when the team wants them; not required |
| `/readyz` ≠ `/healthz` | More stable orchestrator |
| `ErrNoRows` → `ErrNotFound` | HTTP layer does not learn SQL |

## Trade-offs

- **MemoryStore in a unit test** — fast; does not catch SQL bugs.
- **Integration test** — slower; catches schema and SQL.
- **Hand-rolled `database/sql`** — control; more boilerplate.
- **sqlc** — fewer Scan bugs; generated workflow.
- **ORM** — faster start; hidden queries and magic (this course prefers sql + repository).
- **One large Tx** — consistency; holds the connection / lock longer.
- **Ping on every request** — expensive; leave for readiness, not the hot path.

## Common mistakes

1. **Wrong:** SQL in the handler.  
   **Effect:** impossible unit tests; duplication.  
   **Fix:** `Store` implementation.

2. **Wrong:** concatenating input into SQL.  
   **Effect:** SQL injection class vulnerability.  
   **Fix:** placeholders + arguments only.

3. **Wrong:** `Query` without `Context`.  
   **Effect:** a cancelled request still holds the query.  
   **Fix:** `QueryContext` / `ExecContext`.

4. **Wrong:** Tx in the handler without `defer Rollback`.  
   **Effect:** pool saturation.  
   **Fix:** `InTx` in the store; handler calls the service.

5. **Wrong:** ignoring `sql.ErrNoRows`.  
   **Effect:** `500` instead of `404`.  
   **Fix:** map to `ErrNotFound`.

6. **Wrong:** forgotten `rows.Close()`.  
   **Effect:** connection leak under load.  
   **Fix:** `defer rows.Close()` + `rows.Err()`.

7. **Wrong:** `Service` with both `Store` and ad-hoc `s.DB` for “just this transfer”.  
   **Effect:** two paths to the DB; inconsistent tests.  
   **Fix:** extend `Store` (`InTx`) or tx-aware methods.

8. **Wrong:** indexes “manually on prod”.  
   **Effect:** staging ≠ production.  
   **Fix:** migration in VCS.

9. **Wrong:** readiness = liveness with mandatory Ping.  
   **Effect:** restart loop when the DB flickers.  
   **Fix:** split the probes.

## Idiomatic Go

- Small `Store` `interface` in the domain package.
- `errors.Is(err, sql.ErrNoRows)` in the store.
- `defer tx.Rollback()` always with `BeginTx`.
- Config/DSN from env; wiring in `cmd`.
- Table-driven unit tests with `MemoryStore`.
- Mark integration tests with a build tag or CI job.
- Indexes and CHECK constraints in migrations, not in Slack comments.

## Practical scenario

A team drops Postgres “temporarily” into handlers. Under load connections vanish — forgotten `rows.Close`, Tx opened in middleware. Refactor: `SQLStore`, `InTx`, pool limits, `/readyz`. Migrations in CI. Unit tests return to `MemoryStore`; one integration job checks Create/Get. One developer tries dynamic SQL with a column name from the user — code review demands an allowlist. “Slow API” incidents drop when a status index enters via migration, not a manual ALTER on prod.

## Check questions

1. **What is `*sql.DB`?**  
   A connection pool, not one open connection forever.

2. **Why placeholders?**  
   The only correct way for values to enter a query without the injection class of bugs.

3. **Where does Tx live?**  
   In service/store orchestration (`BeginTx`/`Commit`), not in the handler.

4. **What about `ErrNoRows`?**  
   Map to domain `ErrNotFound` before HTTP.

5. **Readiness vs liveness?**  
   Ready checks dependencies (e.g. Ping); live that the process breathes.

6. **Why `NewID` on Service?**  
   Injectable factory — tests without flaky time.

7. **Why migrations in VCS?**  
   The same schema everywhere; indexes and changes are repeatable.

8. **Is sqlc required?**  
   No — an option behind `Store`.

### Transfer example — store methods, tx internally

If the domain has `Transfer`, do **not** introduce `s.DB` on `Service` while `Store` already exists. Extend the contract:

```go
type Store interface {
	Get(ctx context.Context, id string) (Order, error)
	Create(ctx context.Context, o Order) error
	InTx(ctx context.Context, fn func(Store) error) error
	Debit(ctx context.Context, id string, amount int64) error
	Credit(ctx context.Context, id string, amount int64) error
}

func (s *Service) Transfer(ctx context.Context, from, to string, amount int64) error {
	if amount <= 0 {
		return ErrInvalid
	}
	return s.Store.InTx(ctx, func(st Store) error {
		if err := st.Debit(ctx, from, amount); err != nil {
			return err
		}
		return st.Credit(ctx, to, amount)
	})
}
```

`MemoryStore.InTx` can take a mutex and call `fn(s)` — semantically “all or nothing” in memory. SQLStore uses a real `BeginTx`. The handler still only `Svc.Transfer`.

## Deeper trace: Create through SQLStore

```text
1. cmd: sql.Open → PingContext → NewSQLStore → NewService → handler
2. POST /v1/orders {"item":"book"}
3. decodeJSON OK → Service.Create
4. NewID() → "ord_..."
5. Store.Create → ExecContext INSERT $1 $2 $3
6. success → 201 JSON
---
Duplicate PK:
5b. INSERT fail unique → store returns error
6b. map to ErrConflict (if you recognize the driver code) or 500 until you add mapping
---
Get missing:
5c. QueryRowContext → ErrNoRows → ErrNotFound → 404
```

### Driver codes and conflict

Different drivers report unique violation differently. Keep mapping in SQLStore (not in the handler):

```go
func mapSQL(err error) error {
	// example: recognize unique → ErrConflict (driver-specific)
	if err == nil {
		return nil
	}
	return err
}
```

Do not let the HTTP layer learn Postgres/SQLite error message strings.

### Checklist before production DB

- [ ] `Store` `interface` + Memory for unit
- [ ] placeholders only
- [ ] `*Context` queries
- [ ] `ErrNoRows` → `ErrNotFound`
- [ ] pool limits + Ping at start
- [ ] migrations in VCS (including indexes)
- [ ] `/healthz` ≠ `/readyz`
- [ ] Tx via `InTx`, not in the handler
- [ ] DSN from env
- [ ] at least one integration smoke Create/Get

## Summary

The database enters behind `Store`, not into the handler. Pool, `context` queries, parameterized SQL, Tx in the service, migrations in git, split probes. `Service` stays on `Store` + `NewID`. The next lesson adds an HTML adapter on the **same** domain — without SQL in templates.

# 09.05 html/template with the service: safe server-side HTML

> **Go Path - Zero to Gopher** / **02 Intermediate → Building Go Web Services and Applications** / Lesson 09.05

## Lesson goals

After this lesson you can:

- use **`html/template`**, not `text/template`, for HTML (XSS escape);
- parse templates **once** at start and call `Execute` / `ExecuteTemplate` per request;
- build a **view model** separate from the raw domain / DB row;
- organize `define` / layout and choose a template by name;
- keep `FuncMap` only for presentation (date formatting, not SQL);
- handle forms: GET display, POST then re-render or PRG;
- use `template.HTML` rarely and only for trusted content;
- write an escape test; send `Content-Type: text/html; charset=utf-8`;
- keep files in `internal/httpui/templates/`;
- show a flash message after a redirect;
- close module 09 before the Secure Coding path.

## Prerequisite

- 09.04: same `Service`, `httpui` adapter, PRG.
- 09.01–09.03: domain without `ResponseWriter`, `Store`.
- Go 1.22+.
- Basic HTML.

## Problem this lesson solves

`text/template` does not escape HTML — user input on the page becomes XSS. Templates are parsed on every request. A `*sql.Row` or a whole domain object with fields that must not appear on screen goes into the template. `template.HTML` is used “to make it work”. Form POST renders 200 then refresh duplicates. Flash after redirect does not exist — the user does not see “saved”.

This lesson closes Building Web: a safe HTML layer with the same service.

## Mental model

```text
request
  → OrderUI handler
    → Service (domain)
      → view model (only fields for the screen)
        → html/template.ExecuteTemplate
          → HTML with automatic escaping
```

| Tool | For HTML pages? |
|------|-----------------|
| `html/template` | **yes** — context-aware escape |
| `text/template` | **no** for HTML — no XSS protection |

`html/template` escapes according to context (element body, attribute, …). That is not magic security for the whole app (CSRF, auth are still yours), but it is the required base for server-side HTML.

### Terminology

| Term | Gloss |
|------|-------|
| `method` | method on the handler / HTTP method |
| zero value | empty view model on the first GET of a form |
| `package` | `httpui` holds the templates |

## Mechanism

### 1. Why not text/template

```go
// DANGEROUS for HTML:
// t := template.Must(template.New("x").Parse(`<p>{{.}}</p>`)) // text/template

// CORRECT:
t := template.Must(template.New("x").Parse(`<p>{{.}}</p>`)) // html/template
```

With `html/template`, input `<script>...` becomes escaped entities in a text context. With `text/template` — a raw string in the response.

**Predict:** does `html/template` also protect against CSRF?

**Answer:** No. Escape ≠ CSRF token. CSRF remains middleware/form from 09.04.

### 2. Parse once, Execute per request

```go
// at start (cmd or httpui.New)
tpl := template.Must(template.ParseFS(templatesFS,
	"templates/layout.gohtml",
	"templates/orders_*.gohtml",
))

// per request
func (h OrderUI) List(w http.ResponseWriter, r *http.Request) {
	vm, err := h.buildListVM(r.Context())
	if err != nil {
		h.serverError(w, r)
		return
	}
	w.Header().Set("Content-Type", "text/html; charset=utf-8")
	if err := h.Tpl.ExecuteTemplate(w, "orders_list", vm); err != nil {
		// header may already have started — log
		return
	}
}
```

Parsing per request burns CPU and hides template errors until production. `Must` at start = fail immediately if the template is wrong.

### 3. View model ≠ raw domain / DB

```go
type OrderListVM struct {
	Title  string
	Orders []OrderRowVM
	Flash  string
}

type OrderRowVM struct {
	ID        string
	Item      string
	StatusLabel string // "New" instead of raw "new"
	Created   string // already formatted date
}

func toRow(o order.Order) OrderRowVM {
	return OrderRowVM{
		ID:          o.ID,
		Item:        o.Item,
		StatusLabel: statusLabel(o.Status),
		Created:     o.CreatedAt.Local().Format("2006-01-02 15:04"),
	}
}
```

Do not pass `*sql.Rows`, passwords, internal flags. The view model is a **deliberate** screen contract.

### 4. define / layout / ExecuteTemplate

`layout.gohtml`:

```html
{{define "layout"}}
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>{{block "title" .}}App{{end}}</title>
  <link rel="stylesheet" href="/static/app.css">
</head>
<body>
  <header><a href="/app/orders">Orders</a></header>
  {{if .Flash}}<p class="flash">{{.Flash}}</p>{{end}}
  <main>
    {{template "content" .}}
  </main>
</body>
</html>
{{end}}
```

`orders_list.gohtml`:

```html
{{define "orders_list"}}{{template "layout" .}}{{end}}

{{define "title"}}Orders{{end}}

{{define "content"}}
<h1>{{.Title}}</h1>
<a href="/app/orders/new">New</a>
<ul>
  {{range .Orders}}
    <li>{{.Item}} — {{.StatusLabel}}</li>
  {{else}}
    <li>No items</li>
  {{end}}
</ul>
{{end}}
```

`ExecuteTemplate(w, "orders_list", vm)` picks the entry point. The layout shares chrome.

### 5. FuncMap — presentation only

```go
func NewTemplates(fsys fs.FS) (*template.Template, error) {
	return template.New("root").Funcs(template.FuncMap{
		"upper": strings.ToUpper,
		"money": func(minor int64) string {
			return fmt.Sprintf("%.2f", float64(minor)/100)
		},
	}).ParseFS(fsys, "templates/*.gohtml")
}
```

Allowed: format, short display. Forbidden: calling `Store`, SQL, HTTP client from `FuncMap`. A side-effect in a template makes testing harder and hides I/O.

### 6. Forms: GET, POST re-render, PRG

```text
GET  /app/orders/new     → empty form VM
POST /app/orders         → validation fail → 400 + same form with error
POST /app/orders         → OK → 303 + flash in session → GET list
```

Re-render keeps entered values (view model from the form). PRG for success — see 09.04.

### 7. template.HTML — rarely

```go
// only when content is already sanitized / fully trusted (e.g. your markdown pipeline)
type PageVM struct {
	Body template.HTML
}
```

Every user string as `template.HTML` = escape off = XSS. Default: ordinary `string`.

### 8. Escape test

```go
func TestOrderItemEscaped(t *testing.T) {
	tpl := template.Must(template.New("t").Parse(`<li>{{.Item}}</li>`))
	var buf bytes.Buffer
	_ = tpl.Execute(&buf, OrderRowVM{Item: `<script>alert(1)</script>`})
	got := buf.String()
	if strings.Contains(got, `<script>`) {
		t.Fatalf("not escaped: %s", got)
	}
	if !strings.Contains(got, `&lt;script&gt;`) {
		t.Fatalf("expected entities: %s", got)
	}
}
```

This is not a pen-test of the whole app — but it catches an accidental switch to `text/template` or `template.HTML` on the wrong field.

### 9. Content-Type

```go
w.Header().Set("Content-Type", "text/html; charset=utf-8")
```

Without charset the browser may misinterpret bytes. Set it **before** `ExecuteTemplate`.


### 11. Flash after redirect

```go
func (h OrderUI) Create(w http.ResponseWriter, r *http.Request) {
	// ... ParseForm, Svc.Create ...
	setFlash(w, r, "Order saved")
	http.Redirect(w, r, "/app/orders", http.StatusSeeOther)
}

func (h OrderUI) List(w http.ResponseWriter, r *http.Request) {
	vm := OrderListVM{Title: "Orders", Flash: takeFlash(r)}
	list, err := h.Svc.List(r.Context())
	// ... map to vm.Orders ...
	h.render(w, "orders_list", vm)
}
```

Flash: a one-time message in a session cookie / store — read and delete. Without it the user after `303` does not see confirmation.

### 12. Execution trace — XSS attempt in item

```text
1. POST item=<script>alert(1)</script>  (auth/CSRF OK)
2. Service saves the string as data
3. GET list → view model Item = same string
4. html/template in {{.Item}} → &lt;script&gt;...
5. Browser shows text, does not execute the script
```

If someone inserts `template.HTML(item)` “for nicer HTML” — the trace breaks at step 4.

## Rules and syntax

- Only `html/template` for HTML.
- Parse at start; Execute per request.
- View model ≠ raw DB/domain.
- `ExecuteTemplate` + `define` layout.
- `FuncMap` without I/O and SQL.
- Form: re-render on error; PRG + flash on success.
- `template.HTML` only trusted.
- `Content-Type: text/html; charset=utf-8`.
- Templates in `internal/httpui/templates/`.
- Escape test in CI.
- No SQL in templates.

## Examples

### Example 1 — ParseFS, layout, list

```go
package httpui

import (
	"embed"
	"html/template"
	"net/http"
)

//go:embed templates/*.gohtml
var templateFS embed.FS

type OrderUI struct {
	Svc *order.Service
	Tpl *template.Template
}

func NewOrderUI(svc *order.Service) (*OrderUI, error) {
	tpl, err := template.New("root").ParseFS(templateFS, "templates/*.gohtml")
	if err != nil {
		return nil, err
	}
	return &OrderUI{Svc: svc, Tpl: tpl}, nil
}

func (h *OrderUI) render(w http.ResponseWriter, name string, vm any) {
	w.Header().Set("Content-Type", "text/html; charset=utf-8")
	if err := h.Tpl.ExecuteTemplate(w, name, vm); err != nil {
		http.Error(w, "template error", http.StatusInternalServerError)
	}
}

func (h *OrderUI) List(w http.ResponseWriter, r *http.Request) {
	list, err := h.Svc.List(r.Context())
	if err != nil {
		http.Error(w, "error", http.StatusInternalServerError)
		return
	}
	vm := OrderListVM{Title: "Orders", Flash: takeFlash(r)}
	for _, o := range list {
		vm.Orders = append(vm.Orders, toRow(o))
	}
	h.render(w, "orders_list", vm)
}
```

#### What happens here

- Templates embedded in the binary; parse once in `NewOrderUI`.
- List calls the service, maps VM, renders by name.
- Flash is read on GET after redirect.

### Example 2 — Form with re-render and PRG

```go
type OrderFormVM struct {
	Title  string
	Item   string
	Error  string
	Flash  string
}

func (h *OrderUI) NewForm(w http.ResponseWriter, r *http.Request) {
	h.render(w, "orders_form", OrderFormVM{Title: "New order"})
}

func (h *OrderUI) Create(w http.ResponseWriter, r *http.Request) {
	if err := r.ParseForm(); err != nil {
		h.render(w, "orders_form", OrderFormVM{Title: "New", Error: "Bad form"})
		return
	}
	item := strings.TrimSpace(r.FormValue("item"))
	_, err := h.Svc.Create(r.Context(), order.CreateInput{Item: item})
	if err != nil {
		msg := "Error"
		if errors.Is(err, order.ErrInvalid) {
			msg = "Enter an item"
		}
		h.render(w, "orders_form", OrderFormVM{
			Title: "New order",
			Item:  item,
			Error: msg,
		})
		w.WriteHeader(http.StatusBadRequest) // caution: better status before Execute — see note
		return
	}
	setFlash(w, r, "Saved")
	http.Redirect(w, r, "/app/orders", http.StatusSeeOther)
}
```

Better status order:

```go
func (h *OrderUI) renderStatus(w http.ResponseWriter, status int, name string, vm any) {
	w.Header().Set("Content-Type", "text/html; charset=utf-8")
	w.WriteHeader(status)
	_ = h.Tpl.ExecuteTemplate(w, name, vm)
}
```

#### What happens here

- Failure: form stays with `Item` and `Error` (no PRG).
- Success: flash + `303`.
- Status is set **before** the body.

### Example 3 — FuncMap presentation + forbidden anti-pattern

```go
tpl := template.Must(template.New("root").Funcs(template.FuncMap{
	"statusLabel": func(s string) string {
		switch s {
		case "new":
			return "New"
		case "paid":
			return "Paid"
		default:
			return s
		}
	},
}).ParseFS(templateFS, "templates/*.gohtml"))
```

```html
<li>{{.Item}} — {{statusLabel .Status}}</li>
```

```go
// ANTI-PATTERN — do not do this:
// "loadOrder": func(id string) order.Order { return store.Get(...) }
```

#### What happens here

- The label is a pure function over a string.
- Loading from the DB stays in the handler/service — the template only draws.

### Example 4 — Escape test and forbidden template.HTML

```go
func TestNoRawHTMLInItem(t *testing.T) {
	ui, err := NewOrderUI(order.NewService(order.NewMemoryStore()))
	if err != nil {
		t.Fatal(err)
	}
	_, _ = ui.Svc.Create(context.Background(), order.CreateInput{
		Item: `<img src=x onerror=alert(1)>`,
	})
	req := httptest.NewRequest(http.MethodGet, "/app/orders", nil)
	rr := httptest.NewRecorder()
	ui.List(rr, req)
	body := rr.Body.String()
	if strings.Contains(body, "<img src=x") {
		t.Fatal("html not escaped")
	}
}
```

#### What happens here

- End-to-end through UI list: user HTML must not stay raw.
- If someone changes the field to `template.HTML`, the test fails.

### Example 5 — Flash via cookie (simple skeleton)

```go
func setFlash(w http.ResponseWriter, _ *http.Request, msg string) {
	http.SetCookie(w, &http.Cookie{
		Name:     "flash",
		Value:    url.QueryEscape(msg),
		Path:     "/",
		HttpOnly: true,
		SameSite: http.SameSiteLaxMode,
		MaxAge:   60,
	})
}

func takeFlash(r *http.Request) string {
	c, err := r.Cookie("flash")
	if err != nil {
		return ""
	}
	// in real code: delete cookie MaxAge=-1 on ResponseWriter in List
	msg, _ := url.QueryUnescape(c.Value)
	return msg
}
```

Production often keeps flash in a server session store — the principle is the same: read once.

#### What happens here

- After `303`, GET list shows the message.
- The cookie is HttpOnly — not available to JS (a complement, not a replacement for XSS discipline).

## Decision analysis

| Decision | Why |
|----------|-----|
| `html/template` | Context escape against the XSS class |
| Parse once | Speed + fail-fast |
| View model | Less field leakage; clear screen |
| Narrow FuncMap | No hidden I/O |
| PRG + flash | UX without duplicate POST |
| Escape test | Error regeneration in CI |
| embed FS | One binary deploy |

## Trade-offs

- **Server-side HTML** — faster first paint for admin; less “app” UX than SPA.
- **View model mapping** — more code; safer and clearer.
- **Rich FuncMap** — shorter template; risk of logic in the wrong layer.
- **Re-render vs PRG** — re-render keeps the form; PRG cleans refresh semantics.
- **`template.HTML`** — flexibility; high risk if abused.
- **Cookie flash** — simple; size limit / do not put secrets.

## Common mistakes

1. **Wrong:** `text/template` for HTML.  
   **Effect:** XSS when user input is printed.  
   **Fix:** only `html/template`.

2. **Wrong:** parse templates on every request.  
   **Effect:** CPU; errors late.  
   **Fix:** parse at start.

3. **Wrong:** passing a domain/DB struct directly.  
   **Effect:** field leakage; tight coupling.  
   **Fix:** view model.

4. **Wrong:** `template.HTML(userInput)`.  
   **Effect:** escape turned off.  
   **Fix:** ordinary `string`; HTML only trusted.

5. **Wrong:** SQL or `Store` in `FuncMap`.  
   **Effect:** hidden I/O; hard tests.  
   **Fix:** load in the handler.

6. **Wrong:** form success as `200` HTML.  
   **Effect:** duplicate POST on refresh.  
   **Fix:** `303` + flash.

7. **Wrong:** without `charset=utf-8`.  
   **Effect:** wrong character display.  
   **Fix:** explicit Content-Type.

8. **Wrong:** WriteHeader after Execute.  
   **Effect:** status stays 200.  
   **Fix:** status then body.

## Idiomatic Go

- `html/template` + `embed.FS`.
- `ExecuteTemplate` with named `define`.
- Small VM structs in `httpui`.
- Escape / smoke test with `httptest`.
- Flash with session discipline.
- Same `Service` as the JSON adapter (09.04).

## Practical scenario

An admin panel inserts a product name with HTML “for bold”. Someone sends `<script>` in the name — the admin session cookie leaks. The team switches to `html/template`, introduces a VM, an escape test in CI, and bans `template.HTML` without review. Form create goes to PRG + flash “saved”. The `FuncMap` that called the DB is removed — the list is filled in the handler. Module 09 closes: REST, JSON, DB, same domain for HTML, safe template layer.

## Check questions

1. **Why `html/template`?**  
   Automatic escape in an HTML context — the base against XSS.

2. **When to parse?**  
   Once at start; Execute per request.

3. **What is a view model?**  
   A deliberate DTO for the screen, not raw domain/DB.

4. **May FuncMap do SQL?**  
   No — presentation only.

5. **What is dangerous about `template.HTML`?**  
   It turns off escape; only trusted content is allowed.

6. **PRG + flash?**  
   Redirect after POST; one-time message on the next GET.

7. **Content-Type?**  
   `text/html; charset=utf-8`.

8. **Where do the files live?**  
   `internal/httpui/templates/` (often embed).

### Shared CSS and htmx? (course boundary)

You can add a little JS for UX, but business truth stays on the server. Do not move validation “only to the browser” — server `Validate` remains required. The template lesson (09.05) does not depend on a JS framework.

## Mechanism (addendum): rendering pipeline

### Header and body order

```text
1. compute VM (may fail → 500 HTML or error page BEFORE successful WriteHeader)
2. Header Content-Type
3. WriteHeader(status)   // for error re-render: 400
4. ExecuteTemplate
```

If `ExecuteTemplate` writes and only then you set status — it is too late.

### Sharing a template set

One `*template.Template` (set) can hold all `define`s from multiple files after `ParseFS`. Names must be unique. A collision of `{{define "content"}}` in two files — the last parse wins; organize a convention (`orders_content`) or one content per entry page via `block`.

### Predict / Answer — missing template name

**Predict:** `ExecuteTemplate(w, "order_list", vm)` but the define is named `orders_list`.

**Answer:** “no template” error; the user sees 500. So keep names in constants:

```go
const tmplOrdersList = "orders_list"
```

### Context escape — attribute vs body

```html
<!-- element body -->
<p>{{.Item}}</p>

<!-- attribute: html/template chooses a different escape -->
<input value="{{.Item}}">
```

Do not assemble HTML by hand in the handler (`fmt.Fprintf(w, "<p>%s</p>", item)`) — you lose escape.

### When may the UI know about JSON?

Never as a dependency. A link to API docs in the footer is OK. Calling `writeJSON` from `httpui` — not OK. The package boundary exists to make that unpleasant.

## Example 6 — orders_form.gohtml skeleton

```html
{{define "orders_form"}}{{template "layout" .}}{{end}}
{{define "title"}}{{.Title}}{{end}}
{{define "content"}}
<h1>{{.Title}}</h1>
{{if .Error}}<p class="error">{{.Error}}</p>{{end}}
<form method="POST" action="/app/orders">
  <!-- CSRF hidden field goes here in a real app -->
  <label>Item
    <input name="item" value="{{.Item}}">
  </label>
  <button type="submit">Save</button>
</form>
{{end}}
```

#### What happens here

- `value="{{.Item}}"` stays escaped.
- Error and entered text stay on re-render.
- The CSRF field is an auth topic from 09.04 — the template only reserves a place.

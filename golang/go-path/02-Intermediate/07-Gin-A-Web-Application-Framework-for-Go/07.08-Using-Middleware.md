# 07.08 Using middleware: Logger, Recovery, demo auth

> **Go Path - Zero to Gopher** / **02 Intermediate → Gin: A Web Application Framework for Go** / Lesson 07.08

## Lesson goals

After this lesson you should be able to:

- assemble an Engine with `gin.New` + explicit **`gin.Logger`** and **`gin.Recovery`**
- configure Logger (`LoggerWithFormatter` / `LoggerConfig`, `SkipPaths` for health)
- use **`CustomRecovery`** so panic becomes JSON 500 (safety net — not a control-flow strategy)
- write **demo** token auth middleware (header `X-Token` / `Bearer`) on a **group**, while `/health` stays public
- load the token from env (**fail-closed**); assume TLS in production; **never** log `Authorization`
- understand the health / secret / boom matrix; a note on `subtle.ConstantTimeCompare`
- see that moving to JWT later keeps the same Abort + Group pattern

## Prerequisite

- 07.07 (`Next`, `Abort`, `Use`, `Set`/`Get`, Group)
- 07.03 (route groups)
- 07.05 (AbortWithStatusJSON, 401, no panic as API)
- basic authentication concepts (what a token is)

## Problem this lesson solves

`gin.Default()` hides Logger/Recovery. Teams often:

- do not know what is included
- put auth everywhere and kill health checks / probes
- “implement security” with string comparison in production without HTTPS, expiry, rotation
- log entire headers and leak Bearer tokens into the log aggregator
- use `panic` for “not logged in” instead of 401

The lesson teaches **practical Engine assembly** and honestly labels demo auth as a lab pattern — not a production IdP.

## Mental model

```text
gin.New()
  Use(Logger)      ← traffic (skip /health if needed)
  Use(Recovery)    ← catches panic → 500 (CustomRecovery → JSON)
  GET /health      ← public
  Group /api
    Use(tokenAuth) ← Abort 401 or Next
    GET /secret
    GET /boom      ← deliberate panic for demo Recovery (not production style)
```

Logger records method, path, status, latency. Recovery catches panic in the chain. Token middleware is a **gate** on the group.

Demo rule: `Authorization: Bearer <secret>` or `X-Token: <secret>` — compare with the value from env. That is **not** signature cryptography, **not** JWT, **not** protected from replay without TLS and extra measures. Moving to JWT later changes **how** you validate the token, not **where** Abort/Group sits.

### Table: what is demo, what remains

| Part | Demo? | Remains in production |
|------|-------|----------------------|
| Group + Use(auth) | no — pattern | yes |
| Abort 401 + return | no — pattern | yes |
| Health outside group | no — pattern | yes |
| Compare string from env | yes — lab | replace with JWT/OAuth introspection |
| Hardcoded token in git | forbidden | forbidden |
| Log whole Authorization | forbidden | forbidden |

## Mechanism

### New + explicit Logger + Recovery

```go
r := gin.New()
r.Use(gin.Logger(), gin.Recovery())
```

The spirit of `Default()`, but you see what you include. In tests often `gin.New()` without Logger (noise) + Recovery as needed; `gin.SetMode(gin.TestMode)` in 07.09.

**Predict:** why not rely on `Default()` forever?

**Answer:** it hides order and composition; harder to replace Logger formatter, SkipPaths, CustomRecovery.

### LoggerWithFormatter

```go
r.Use(gin.LoggerWithFormatter(func(p gin.LogFormatterParams) string {
	return fmt.Sprintf("%s %s %d %s\n", p.Method, p.Path, p.StatusCode, p.Latency)
}))
```

You control the line shape. Do not insert `p.Request.Header.Get("Authorization")` into the format — secret leak.

### LoggerConfig and SkipPaths

```go
r.Use(gin.LoggerWithConfig(gin.LoggerConfig{
	SkipPaths: []string{"/health", "/ready"},
}))
```

Probes and health should not drown the logs. Error log can still exist on other layers; SkipPaths reduces noise from successful pings.

### CustomRecovery → JSON 500

```go
r.Use(gin.CustomRecovery(func(c *gin.Context, recovered any) {
	log.Printf("panic: %v req=%s", recovered, c.GetString("reqID"))
	c.AbortWithStatusJSON(http.StatusInternalServerError, gin.H{"error": "internal error"})
}))
```

Recovery is a **net**: catches unexpected panic (nil pointer, bug). Do not teach the team to do `panic("unauthorized")`. For expected outcomes — Abort + status from 07.05/07.07.

Order: request ID middleware **before** Recovery/Logger if you want the ID in the panic log — or Set ID early in the chain.

### Demo token auth on a group

```go
func tokenAuth(expected string) gin.HandlerFunc {
	return func(c *gin.Context) {
		got := extractToken(c)
		if expected == "" || got == "" || got != expected {
			c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "unauthorized"})
			return
		}
		c.Next()
	}
}

func extractToken(c *gin.Context) string {
	if v := c.GetHeader("X-Token"); v != "" {
		return v
	}
	const prefix = "Bearer "
	h := c.GetHeader("Authorization")
	if strings.HasPrefix(h, prefix) {
		return strings.TrimPrefix(h, prefix)
	}
	return ""
}
```

`X-Token` and `Bearer` are **demo** transports. Not JWT parsing — just a string.

### Token from env, fail-closed

```go
func newRouter() *gin.Engine {
	expected := os.Getenv("API_TOKEN")
	r := gin.New()
	r.Use(gin.LoggerWithConfig(gin.LoggerConfig{SkipPaths: []string{"/health"}}))
	r.Use(gin.CustomRecovery(func(c *gin.Context, recovered any) {
		log.Printf("panic: %v", recovered)
		c.AbortWithStatusJSON(http.StatusInternalServerError, gin.H{"error": "internal error"})
	}))
	r.GET("/health", func(c *gin.Context) { c.Status(http.StatusOK) })

	api := r.Group("/api")
	api.Use(tokenAuth(expected))
	api.GET("/secret", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"secret": true})
	})
	return r
}
```

If `API_TOKEN` is empty, `tokenAuth` is fail-closed: all `/api/*` → 401. Better than an open API with empty expected. At boot you can also refuse to start (`log.Fatal`) if the token is not set — even stricter.

### TLS assumption

Bearer / X-Token over plain HTTP is visible on the network. Demo on `localhost` is OK for learning. Production: HTTPS (termination on a proxy or Go TLS). Without TLS, a “secret header” is not a secret.

### Never log Authorization

```go
// BAD
log.Printf("headers=%v", c.Request.Header)

// GOOD
log.Printf("method=%s path=%s auth_present=%t",
	c.Request.Method, c.FullPath(), c.GetHeader("Authorization") != "")
```

The same principle for `Cookie` and `X-Token` value — log presence, not the secret.

### Route matrix: health / secret / boom

| Route | Auth | Expected |
|-------|------|----------|
| `GET /health` | no | 200, without token |
| `GET /api/secret` without token | yes | 401 |
| `GET /api/secret` with good token | yes | 200 JSON |
| `GET /api/boom` | yes | panic → CustomRecovery → 500 JSON |

`boom` exists **only** so you see Recovery in the lab:

```go
api.GET("/boom", func(c *gin.Context) {
	panic("demo boom")
})
```

Do not copy the boom pattern into business code as a way to return an error.

### ConstantTimeCompare note

Ordinary `got != expected` leaks timing information in theory for a side-channel. For a classroom string token:

```go
import "crypto/subtle"

func eq(a, b string) bool {
	if len(a) != len(b) {
		return false
	}
	return subtle.ConstantTimeCompare([]byte(a), []byte(b)) == 1
}
```

Note: different lengths still reveal length; real systems use hash/JWT signature where comparison is already in the crypto library. This is **hygiene**, not magic that turns a demo token into an IdP.

### Moving to JWT keeps Abort/Group

```text
today:  extract string → eq(env) → Abort|Next
tomorrow:  parse JWT → verify sig/exp/aud → Set(uid) → Abort|Next
```

Group `/api`, public health, Logger, Recovery — remain. What changes is the body of the factory middleware. That is why this lesson insists on the pattern, not on a string secret as the “final solution”.

### Execution trace: secret without token

```text
Logger before → Recovery frame → /api group tokenAuth Abort 401 return
→ secret handler DOES NOT RUN
→ Logger after records 401 (unless SkipPaths — health only)
```

### Execution trace: boom with token

```text
Logger → tokenAuth Next → boom panic
→ CustomRecovery catches → AbortWithStatusJSON 500
→ Logger sees 500
```

The handler after the panic line does not continue. That is OK for a bug; it is not OK as a substitute for an `err != nil` branch.

## Rules and syntax

1. Prefer `gin.New` + explicit Use over opaque Default when learning/prod.
2. Logger with SkipPaths for health/ready.
3. CustomRecovery → generic JSON 500 + log recovered.
4. Auth on Group; health outside the group.
5. Token from env; empty token = fail-closed.
6. Demo ≠ JWT; Bearer/X-Token only demo transport.
7. HTTPS assumption for a production header token.
8. Never log Authorization / token value.
9. Panic only as a bug; Recovery net; boom only lab.
10. ConstantTimeCompare as hygiene for string secrets.
11. Same Abort+return idiom as 07.07.
12. When JWT arrives — replace validation, keep the Group pattern.

## Examples

### Example 1: New + Logger + Recovery

```go
func newRouter() *gin.Engine {
	r := gin.New()
	r.Use(gin.Logger(), gin.Recovery())
	r.GET("/health", func(c *gin.Context) {
		c.Status(http.StatusOK)
	})
	return r
}
```

#### What happens here

Explicit composition. Health 200 without body. No auth. Base to which you attach a group.

### Example 2: SkipPaths + CustomRecovery JSON

```go
func newRouter() *gin.Engine {
	r := gin.New()
	r.Use(gin.LoggerWithConfig(gin.LoggerConfig{
		SkipPaths: []string{"/health"},
	}))
	r.Use(gin.CustomRecovery(func(c *gin.Context, recovered any) {
		log.Printf("panic: %v", recovered)
		c.AbortWithStatusJSON(http.StatusInternalServerError, gin.H{"error": "internal error"})
	}))
	r.GET("/health", func(c *gin.Context) { c.Status(http.StatusOK) })
	r.GET("/boom", func(c *gin.Context) { panic("lab") })
	return r
}
```

#### What happens here

Health does not spam Logger. Boom (public here for brevity) demonstrates JSON 500. In a real app boom does not exist; Recovery remains.

### Example 3: Group auth + secret

```go
func newRouter(token string) *gin.Engine {
	r := gin.New()
	r.Use(gin.LoggerWithConfig(gin.LoggerConfig{SkipPaths: []string{"/health"}}))
	r.Use(gin.Recovery())
	r.GET("/health", func(c *gin.Context) { c.Status(http.StatusOK) })

	api := r.Group("/api")
	api.Use(tokenAuth(token))
	api.GET("/secret", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"secret": true})
	})
	return r
}
```

#### What happens here

Matrix: health without token OK; secret without token 401; secret with token 200. Auth does not touch health — the probe lives.

### Example 4: extractToken Bearer and X-Token

```go
func extractToken(c *gin.Context) string {
	if v := c.GetHeader("X-Token"); v != "" {
		return v
	}
	h := c.GetHeader("Authorization")
	if strings.HasPrefix(h, "Bearer ") {
		return strings.TrimSpace(strings.TrimPrefix(h, "Bearer "))
	}
	return ""
}

func tokenAuth(expected string) gin.HandlerFunc {
	return func(c *gin.Context) {
		got := extractToken(c)
		if expected == "" || !secureEq(got, expected) {
			c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "unauthorized"})
			return
		}
		c.Next()
	}
}

func secureEq(a, b string) bool {
	if len(a) != len(b) {
		return false
	}
	return subtle.ConstantTimeCompare([]byte(a), []byte(b)) == 1
}
```

#### What happens here

Two header shapes; one check. Empty expected → 401. ConstantTimeCompare for equal length. Still a demo secret, not JWT.

### Example 5: Fail-closed boot

```go
func main() {
	token := os.Getenv("API_TOKEN")
	if token == "" {
		log.Fatal("API_TOKEN must be set")
	}
	r := newRouter(token)
	api := r.Group("/api")
	// ...
	_ = r.RunTLS(":8443", "cert.pem", "key.pem") // or TLS on the proxy
}
```

#### What happens here

Without env — the process does not start. RunTLS highlights the TLS assumption (local cert for the lab). In the cloud often TLS termination in front of plain `:8080` — still a “TLS assumption” at the edge.

### Example 6: Boom matrix inside the auth group

```go
api := r.Group("/api")
api.Use(tokenAuth(token))
api.GET("/secret", secretHandler)
api.GET("/boom", func(c *gin.Context) {
	panic("demo boom")
})
```

#### What happens here

Without token boom does not reach panic — 401 first. With token panic → CustomRecovery JSON 500. Shows order: auth before handler, Recovery catches inside.

## Decision analysis

| Decision | Choice | Why |
|----------|--------|-----|
| New vs Default | New + Use | explicit |
| Health log | SkipPaths | less noise |
| Panic response | CustomRecovery JSON | same envelope as 07.05 |
| Auth scope | Group | probe lives |
| Secret | env + fail-closed | no git secret / open API |
| Comparison | ConstantTimeCompare | hygiene |
| Production auth | JWT later | same Abort pattern |

## Trade-offs

- **SkipPaths** — cleaner log; less visibility of successful probes (usually OK).
- **Fatal without token** — safer; harder local start without `.env`.
- **One shared string token** — simple lab; no per-user identity.
- **CustomRecovery JSON** — consistent API; loses HTML/stack to the client (stack stays in the log).
- **Bearer in log formatter “for debug”** — convenient short-term; long-term incident.

## Common mistakes

1. **Wrong:** `r.Use(auth)` then `/health` inside.  
   **Effect:** probe 401, rolling deploy fail.  
   **Fix:** health outside the auth group.

2. **Wrong:** token in source code.  
   **Effect:** leak into git.  
   **Fix:** env / secret manager.

3. **Wrong:** `log.Printf("%v", c.Request.Header)`.  
   **Effect:** Bearer in the log.  
   **Fix:** log only presence / request ID.

4. **Wrong:** `panic("no auth")`.  
   **Effect:** 500 instead of 401; false alarms.  
   **Fix:** AbortWithStatusJSON 401.

5. **Wrong:** empty env then `expected=""` and logic that lets everything through.  
   **Effect:** open API.  
   **Fix:** fail-closed (`expected==""` → 401) or Fatal at boot.

6. **Wrong:** demo token = “done for production”.  
   **Effect:** no expiry/revocation/signature.  
   **Fix:** plan JWT/OAuth; keep Group.

7. **Wrong:** Logger after the handler in a wrong order so it does not see status.  
   **Effect:** bad logs.  
   **Fix:** Logger as Use early; measure after Next internally.

8. **Wrong:** Recovery off “so I see the stack in the browser” in prod.  
   **Effect:** process can crash / ugly response.  
   **Fix:** Recovery always on the HTTP entry; stack in the log.

## Idiomatic Go

- `newRouter(deps)` returns `*gin.Engine` — test and main share (07.09).
- Env loading at the edge (`main`), not deep in the handler.
- `subtle.ConstantTimeCompare` for simple secrets.
- Separation: transport header ≠ identity semantics.
- Comment in code: `// DEMO AUTH — replace with JWT`.
- Test matrix health/401/200/500 (next lesson formalizes).

## Practical scenario

A team turns on Gin Default, adds auth globally, Kubernetes liveness starts failing. They temporarily disable auth — security hole. Fix: Group `/api` + public `/health`, SkipPaths, token from Secret, TLS on ingress. Later security review finds Bearer in JSON logs because of a “debug formatter” — they remove the header dump. They replace the demo string with JWT verification, but the `api.Use(auth)` line stays the same. Boom route deleted before production; CustomRecovery remains.

## Check questions

1. Why `gin.New` + Use instead of blind Default?  
   **Answer:** explicit composition and Logger/Recovery configuration.

2. What is SkipPaths for?  
   **Answer:** so health/ready do not fill the access log.

3. Does Recovery replace Abort 401?  
   **Answer:** no — Recovery catches panic; 401 is expected flow.

4. Where do you attach demo auth?  
   **Answer:** on the Group of protected routes, not on health.

5. What is fail-closed for an empty env token?  
   **Answer:** reject requests (401) or do not start the process — do not open the API.

6. Why not log Authorization?  
   **Answer:** secret in the log aggregator = leak.

7. X-Token demo = JWT?  
   **Answer:** no — only string comparison; JWT comes later with the same Abort/Group.

8. What does CustomRecovery return to the client?  
   **Answer:** generic JSON 500; panic detail in the log.

### Predict: order

```go
r.Use(logger, recovery)
api := r.Group("/api")
api.Use(auth)
api.GET("/boom", panicHandler)
```

Request without token on `/api/boom` — do you see panic?

**Answer:** no — auth Abort 401 before the handler.

### Predict: Default trap

A developer removes Recovery “temporarily”. The handler does a nil dereference.

**Answer:** without Recovery the process can crash the goroutine/connection handling badly; put Recovery back.

### Predict: JWT migration

Which lines stay untouched when you replace `secureEq` with JWT verify?

**Answer:** `r.Group`, `Use(authFactory)`, `AbortWithStatusJSON`, health route, Logger/Recovery Use — the inside of the factory changes.

### Complete lab router (composition)

The following skeleton joins everything from the lesson — use it as a checklist, not as production copy-paste:

```go
func NewRouter(token string) *gin.Engine {
	r := gin.New()
	r.Use(gin.LoggerWithConfig(gin.LoggerConfig{
		SkipPaths: []string{"/health", "/ready"},
	}))
	r.Use(gin.CustomRecovery(func(c *gin.Context, recovered any) {
		log.Printf("panic: %v path=%s", recovered, c.FullPath())
		c.AbortWithStatusJSON(http.StatusInternalServerError, gin.H{"error": "internal error"})
	}))

	r.GET("/health", func(c *gin.Context) { c.Status(http.StatusOK) })
	r.GET("/ready", func(c *gin.Context) { c.Status(http.StatusOK) })

	api := r.Group("/api")
	api.Use(tokenAuth(token))
	{
		api.GET("/secret", func(c *gin.Context) {
			c.JSON(http.StatusOK, gin.H{"secret": true})
		})
		// lab only:
		// api.GET("/boom", func(c *gin.Context) { panic("demo") })
	}
	return r
}
```

Checks by hand or test (07.09):

| # | Request | Expectation |
|---|---------|-------------|
| 1 | GET /health | 200, without token |
| 2 | GET /ready | 200, without token; SkipPaths |
| 3 | GET /api/secret | 401 |
| 4 | GET /api/secret + X-Token | 200 `secret` |
| 5 | GET /api/secret + Bearer | 200 |
| 6 | wrong token | 401 |
| 7 | empty env token (fail-closed) | 401 on /api/* |

### Logger formatter without secrets

```go
r.Use(gin.LoggerWithFormatter(func(p gin.LogFormatterParams) string {
	auth := p.Request.Header.Get("Authorization") != ""
	return fmt.Sprintf("%s %s %d auth=%t latency=%s\n",
		p.Method, p.Path, p.StatusCode, auth, p.Latency)
}))
```

You see whether the auth header is **present**, not the value. Same idea for X-Token.

### Why the boom route exists in the lab (and disappears)

Boom proves that CustomRecovery returns a JSON envelope aligned with 07.05, not HTML. Once you see that once, delete the route. If it stays in staging, someone will hit it and create false incidents. Recovery middleware stays forever; the boom handler does not.

### Auth errors: 401 vs “quietly Next”

```go
// BAD — “pass through and let the handler notice”
if got != expected {
	c.Next() // every handler must watch — easy to forget
	return
}
```

The middleware gate must Abort. Otherwise every handler repeats the check — and one forget opens a hole.

### Env and local development

Fail-closed hurts locally until there is a `.env`. Solutions:

1. `direnv` / `.env` outside git (in `.gitignore`).
2. `API_TOKEN=dev` in the README for the lab.
3. `log.Fatal` in main if there is no token — an explicit message.

Do not solve the pain by making an empty token mean “auth off”. That ends in production by mistake.

### TLS at the edge

Three common layouts:

| Layout | Go listens | TLS where |
|--------|------------|-----------|
| RunTLS | :8443 | in process |
| Ingress/proxy | :8080 plain | on proxy |
| Local lab | :8080 | often without TLS |

The lesson asks for awareness: a header token without TLS on the client→edge path is not acceptable in production. Lab on localhost is an exception for learning.

### Transitional JWT stub (shape only)

```go
func jwtAuth(verify func(raw string) (uid string, err error)) gin.HandlerFunc {
	return func(c *gin.Context) {
		raw := extractToken(c)
		uid, err := verify(raw)
		if err != nil || uid == "" {
			c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "unauthorized"})
			return
		}
		c.Set("uid", uid)
		c.Next()
	}
}
```

Same Abort/Group. `verify` tomorrow calls a library. Today in the lab `verify` can compare a string — tomorrow a signature.

### Use order that works in practice

Recommended order for this module:

```text
1. requestID (optional, from 07.07)
2. Logger (SkipPaths health)
3. CustomRecovery / Recovery
4. CORS (if needed, from 07.06) — careful with credentials
5. routes: public
6. Group: tokenAuth → handlers
```

Recovery should wrap handlers. Logger after Next sees the final status including 401 from auth. Request ID before log/panic so correlation works.

### What LoggerWithConfig still offers

Besides `SkipPaths`, config can take a custom `Formatter` and `Output` (e.g. another writer). For a start SkipPaths + default format holds. When you move to structured log (slog/zap), you often replace Gin Logger with your own middleware that after Next logs fields — the same before/Next/after shape from 07.07.

### Demo vs production — responsibility table

| Responsibility | Lesson demo | Production |
|----------------|-------------|------------|
| Transport | X-Token / Bearer string | Authorization Bearer JWT / session |
| Secret | one env string | JWKS, rotation, short TTL |
| Identity | no uid | Set uid/roles from claims |
| Revocation | none | blocklist / short expiry |
| TLS | assumption | mandatory at the edge |
| Log secrets | forbidden | forbidden (same!) |
| Abort/Group | yes | yes (does not change) |

### Mistake: auth middleware “logs then Next” on fail

```go
if got != expected {
	log.Printf("bad token %s", got) // BAD — logs the secret
	c.Next()                        // BAD — no Abort
	return
}
```

Fix: do not log the value; Abort 401; return. If needed log `auth_failed=true` + request ID.

After exercise 8, your note should look roughly like:

## Summary

- `New` + Logger (+ SkipPaths) + Recovery/CustomRecovery explicitly.
- Demo token auth on a group; health public; env fail-closed; TLS assumption.
- Do not log Authorization; do not panic for 401; boom only lab.
- ConstantTimeCompare hygiene; JWT later with the same Abort/Group pattern.
- Matrix health / secret / boom checks the chain before 07.09 tests.

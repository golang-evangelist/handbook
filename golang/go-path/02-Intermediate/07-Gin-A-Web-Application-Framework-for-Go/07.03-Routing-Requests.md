# 07.03 Advanced routing: groups, Any, NoRoute, versions

> **Go Path - Zero to Gopher** / **02 Intermediate → Gin: A Web Application Framework for Go** / Lesson 07.03

## Lesson goals

After this lesson you should be able to:

- nest `RouterGroup` (public vs admin) and know how prefixes concatenate
- version the API by path (`/v1`, `/v2`) and keep `/health` outside the version
- use `Any` narrowly (probe), not on mutating CRUD
- configure `NoRoute` and `NoMethod` to JSON, with `HandleMethodNotAllowed = true`
- understand `AbortWithStatusJSON` as stopping the chain (preparation for middleware)
- document deprecation (`Deprecation`, `Link`, `Sunset`) without breaking old clients

## Prerequisite

- 07.01 Engine, Default/New, Recovery
- 07.02 `Param`, `Group`, path vs query, `Register`

## Problem this lesson solves

When a route “just works” for a happy GET, production still needs:

- clear contract versions while a mobile client lags on updates
- admin routes protected, health public
- predictable JSON 404/405 instead of an HTML debug page
- controlled chain abort when auth fails

Without that you get: an LB that fails because health is under auth, clients that parse HTML 404, and “Any” routes that accept DELETE where you did not want it.

## Mental model

```text
Engine
  ├─ GET /health          (outside version)
  ├─ Group /v1
  │    ├─ Group /public   (no auth)
  │    └─ Group /admin    Use(auth) → Abort or Next
  ├─ Group /v2            (new contract)
  ├─ NoRoute  → JSON 404
  └─ NoMethod → JSON 405  (if HandleMethodNotAllowed)
```

**NoRoute** (no matched path): first gloss — “the route does not exist in the tree”.  
**NoMethod** (path exists, method does not): “wrong verb for a known path”.

`AbortWithStatusJSON` = write a JSON status **and** mark that the rest of the chain must not run. Always `return` after Abort in that handler/middleware.

## Mechanism

### Nested groups

```go
r := gin.New()
r.Use(gin.Recovery())

v1 := r.Group("/v1")
{
	pub := v1.Group("/public")
	pub.GET("/catalog", catalog)

	adm := v1.Group("/admin")
	adm.Use(demoAuth())
	adm.GET("/stats", stats)
}
```

Full paths:

- `GET /v1/public/catalog`
- `GET /v1/admin/stats` (passes `demoAuth` before the handler)

Prefixes **concatenate**. In logs, OpenAPI, and tests write the final path, not only the relative piece.

**Predict the result:** `adm.GET("/v1/admin/stats", …)` after `Group("/v1")` + `Group("/admin")` — what is the full path?

**Answer:** `/v1/admin/v1/admin/stats` — double prefix. Fix: `adm.GET("/stats", …)`.

### Path versioning

Why path (`/v1`, `/v2`) and not only a header?

| Approach | Advantage | Drawback |
|----------|-----------|----------|
| Path `/v1` | visible in the URL, cache/proxy friendly, easy curl | “uglier” path |
| Header `Accept: …v2+json` | cleaner path | harder curl, cache, debug |

This course chooses **path**. Header versioning exists in the industry — you will know it exists; here we practice `/v1`.

Rules:

1. `/health` or `/healthz` **outside** `/v1` — the load balancer does not depend on the API contract version.
2. Breaking change → new `/v2` (or a new resource shape under v2).
3. Compatible addition of optional JSON fields can stay in v1.
4. Do not break v1 until traffic metrics on v1 have dropped.

```go
r.GET("/health", func(c *gin.Context) {
	c.Status(http.StatusOK)
})

RegisterV1(r.Group("/v1"), deps)
RegisterV2(r.Group("/v2"), deps)
```

### Any — a narrow weapon

```go
r.Any("/probe", func(c *gin.Context) {
	c.Status(http.StatusOK)
})
```

`Any` registers a handler for all methods. That makes sense for probe/health when you do not care whether it is GET or HEAD.

**Do not** do this:

```go
r.Any("/items/:id", mutateOrRead) // DANGEROUS as a design
```

If you must have one entry, switch on `c.Request.Method` and return 405 for disallowed — better explicit `GET`/`POST` registrations.

**Predict the result:** `Any("/items")` and the client sends `DELETE /items`. What happens if the handler does not check the method?

**Answer:** DELETE enters the same handler. If the handler “deletes the list” or ignores the method, you have a design hole. That is why Any is not a CRUD shortcut.

### NoRoute and NoMethod

```go
r := gin.New()
r.Use(gin.Recovery())
r.HandleMethodNotAllowed = true

r.GET("/items/:id", getItem)

r.NoRoute(func(c *gin.Context) {
	c.AbortWithStatusJSON(http.StatusNotFound, gin.H{
		"error": "route not found",
		"code":  "route_missing",
	})
})

r.NoMethod(func(c *gin.Context) {
	c.AbortWithStatusJSON(http.StatusMethodNotAllowed, gin.H{
		"error": "method not allowed",
		"code":  "method_not_allowed",
	})
})
```

Without `HandleMethodNotAllowed = true`, Gin often treats a wrong method as if the route does not exist (404 instead of 405). Turn the flag on deliberately.

Distinguish:

| Situation | Status | Suggested `code` |
|-----------|--------|------------------|
| No matched path | 404 | `route_missing` |
| Resource does not exist in the DB | 404 | `item_missing` |
| Path exists, method does not | 405 | `method_not_allowed` |

Both are 404, but metrics and support like different `code` values.

### AbortWithStatusJSON in demo auth

```go
func demoAuth() gin.HandlerFunc {
	return func(c *gin.Context) {
		token := c.GetHeader("X-Token")
		if token != expectedToken() {
			c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "unauthorized"})
			return
		}
		c.Next()
	}
}
```

Trace when the token fails:

1. Middleware enters.
2. `AbortWithStatusJSON` writes 401 JSON and sets the aborted flag.
3. `return` — without `Next`, the `stats` handler is **not** called.
4. Outer middleware after its own `Next` can still run (timing log) — see 07.07 `IsAborted`.

When the token passes: `c.Next()` calls the rest of the chain, then returns.

This is **not** production auth (not OAuth/JWT/mTLS). Learn the Abort + group pattern. Token from env; fail-closed if the secret is not set; do not log the raw token.

### Deprecation without breakage

When you introduce v2:

```go
func deprecateV1() gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Header("Deprecation", "true")
		c.Header("Link", `</v2>; rel="successor-version"`)
		c.Header("Sunset", "Wed, 01 Sep 2027 00:00:00 GMT")
		c.Next()
	}
}

v1 := r.Group("/v1", deprecateV1())
```

The client still works. Operators see the headers. Remove v1 only when traffic and the contract allow it.

### CORS awareness

`NoMethod` and `Any` are **not** a substitute for CORS. The browser sends a preflight `OPTIONS`. Use dedicated middleware (e.g. `gin-contrib/cors`) with explicit origins. Do not put `Access-Control-Allow-Origin: *` together with credentials.

### NoRoute metrics

A counter `http_requests_not_found_total` on NoRoute helps you see bots and wrong clients. Separate it from business 404 (`item_missing`) so you do not mix “bad URL” and “no row in the DB”.

### RegisterV1 / RegisterV2

```go
func RegisterV1(rg *gin.RouterGroup, d Deps) {
	rg.GET("/items/:id", d.Items.GetV1)
}

func RegisterV2(rg *gin.RouterGroup, d Deps) {
	rg.GET("/items/:id", d.Items.GetV2)
}
```

Same `Deps`, different adapter response shape. The domain service can be shared.

### Trace: request through nested groups + auth

```text
GET /v1/admin/stats  Header X-Token: bad

1. Recovery (global) → Next
2. Match: Group /v1 → Group /admin
3. demoAuth:
     token != want
     AbortWithStatusJSON(401)
     return          ← stats IS NOT CALLED
4. (return) Logger/Recovery see status 401
```

```text
GET /v1/admin/stats  Header X-Token: good

1. Recovery → Next
2. demoAuth: Next()
3. stats handler → 200 JSON
4. return through Next
```

**Predict the result:** auth middleware calls `c.JSON(401, …)` **without** `Abort`, then `c.Next()`. What happens?

**Answer:** the `stats` handler can still run and overwrite / append to the response. That is why Abort (or at least do not call Next) + `return`. `JSON` alone is not a chain stop.

### Table: where you attach Use

| Place of `Use` | What it covers | Typical use |
|----------------|----------------|-------------|
| `r.Use` on Engine | all routes | Recovery, request ID, CORS |
| `v1.Use` | only `/v1/...` | Deprecation, v1 metrics |
| `admin.Use` | only admin | auth |
| per-route `GET(path, mw, h)` | one route | rare; prefer Group |

Register health **before** or **outside** auth groups — Engine-level `Use` order still applies to health if auth is global. That is why auth goes on a narrower group.

### HandleMethodNotAllowed — comparative outcomes

Assume only `GET /items/:id` is registered.

| Flag | Request | Typical status | Handler |
|------|---------|----------------|---------|
| `false` (often default) | `POST /items/1` | 404 | `NoRoute` if present |
| `true` | `POST /items/1` | 405 | `NoMethod` |
| either | `GET /nope` | 404 | `NoRoute` |
| either | `GET /items/1` (not in DB) | 404 from **your** handler | not NoRoute |

**Predict the result:** you turn the flag on but forget `r.NoMethod(...)`. Do you still get a sensible 405?

**Answer:** Gin may return 405 with a default body — but not your JSON contract. Explicit `NoMethod` keeps the same error shape as the rest of the API.

### Versions: what may stay in v1, what goes to v2

| Change | v1 | v2 |
|--------|----|----|
| New optional JSON field | OK | — |
| Removed field / rename | breaking → v2 | new shape |
| Same path, different ID semantics | avoid | new contract |
| New resource `/widgets` | can be in v1 | or only v2 if part of a new model |

Deprecation headers on v1 do **not** replace a changelog and communication with the mobile team.

### AbortWithStatusJSON vs AbortWithStatus vs Abort

| API | Body | Abort flag |
|-----|------|------------|
| `AbortWithStatusJSON` | JSON | yes |
| `AbortWithStatus` | no JSON body | yes |
| `Abort()` | does not write by itself | yes — you already wrote |

For a JSON API prefer `AbortWithStatusJSON` in auth and NoRoute/NoMethod. After Abort in **that** middleware always `return`.

### Health vs readyz (brief)

| Endpoint | Question | Auth |
|----------|----------|------|
| `/health` or `/healthz` | is the process alive? | no |
| `/readyz` | ready for traffic (DB up)? | usually no |

Both outside `/v1` if LB/K8s does not need to know the contract version. `readyz` uses `c.Request.Context()` for `PingContext` (07.01).

## Rules and syntax

1. Group prefixes concatenate — write the final path in docs/tests.
2. `/health` outside `/v1`.
3. `Any` only for probe or a deliberately limited entry.
4. `NoRoute` / `NoMethod` → JSON + `AbortWithStatusJSON`.
5. `HandleMethodNotAllowed = true` so NoMethod works.
6. Auth `Use` on the admin group, not on the whole Engine if health must be public.
7. After `Abort*` always `return` in that layer.
8. Demo token ≠ production crypto.
9. Deprecation headers do not replace communication with clients.
10. Different `code` for route 404 vs resource 404.

## Examples

### Example 1: v1 public/admin + health

```go
package main

import (
	"net/http"
	"os"

	"github.com/gin-gonic/gin"
)

func demoAuth() gin.HandlerFunc {
	want := os.Getenv("ADMIN_TOKEN")
	return func(c *gin.Context) {
		if want == "" {
			c.AbortWithStatusJSON(http.StatusServiceUnavailable, gin.H{"error": "auth not configured"})
			return
		}
		if c.GetHeader("X-Token") != want {
			c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "unauthorized"})
			return
		}
		c.Next()
	}
}

func main() {
	r := gin.New()
	r.Use(gin.Recovery())
	r.HandleMethodNotAllowed = true

	r.GET("/health", func(c *gin.Context) { c.Status(http.StatusOK) })

	v1 := r.Group("/v1")
	v1.GET("/public/catalog", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"items": []string{"a", "b"}})
	})

	adm := v1.Group("/admin", demoAuth())
	adm.GET("/stats", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"orders": 12})
	})

	r.NoRoute(func(c *gin.Context) {
		c.AbortWithStatusJSON(http.StatusNotFound, gin.H{"error": "route not found", "code": "route_missing"})
	})
	r.NoMethod(func(c *gin.Context) {
		c.AbortWithStatusJSON(http.StatusMethodNotAllowed, gin.H{"error": "method not allowed", "code": "method_not_allowed"})
	})

	_ = r.Run(":8080")
}
```

#### What happens here

Health is public. Catalog is under `/v1/public` without auth. Stats requires `X-Token`. If `ADMIN_TOKEN` is not in env, fail-closed 503 — better than an open admin. NoRoute/NoMethod return JSON. `HandleMethodNotAllowed` enables 405.

**Predict the result:** `GET /health` without a token?

**Answer:** 200 — not under the `demoAuth` group.

### Example 2: RegisterV1 and RegisterV2

```go
package httpapi

import (
	"net/http"

	"github.com/gin-gonic/gin"
)

type Items struct{}

func (Items) GetV1(c *gin.Context) {
	c.JSON(http.StatusOK, gin.H{"id": c.Param("id"), "name": "old shape"})
}

func (Items) GetV2(c *gin.Context) {
	c.JSON(http.StatusOK, gin.H{"data": gin.H{"id": c.Param("id"), "name": "new shape"}})
}

func RegisterV1(rg *gin.RouterGroup, items Items) {
	rg.GET("/items/:id", items.GetV1)
}

func RegisterV2(rg *gin.RouterGroup, items Items) {
	rg.GET("/items/:id", items.GetV2)
}

func Mount(r *gin.Engine, items Items) {
	RegisterV1(r.Group("/v1"), items)
	RegisterV2(r.Group("/v2"), items)
}
```

#### What happens here

Same Param, different JSON wrapper. The mobile client stays on v1; web moves to v2. `Mount` is called from `main` and from tests. No panic, no mixing `gin.Context` with `context.Context` because there is no I/O here — when you add a store, pass `c.Request.Context()`.

### Example 3: Any probe vs explicit methods

```go
r.Any("/probe", func(c *gin.Context) {
	c.JSON(http.StatusOK, gin.H{"method": c.Request.Method})
})

// better for a resource:
r.GET("/items/:id", getItem)
r.DELETE("/items/:id", deleteItem)
// POST on /items/:id → NoMethod 405 if the flag is on
```

#### What happens here

Probe accepts any method and returns which one arrived — useful for diagnostics. Items explicitly lists GET and DELETE. A wrong POST does not enter getItem.

### Example 4: Deprecation middleware on v1

```go
func deprecateV1() gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Header("Deprecation", "true")
		c.Header("Link", `</v2>; rel="successor-version"`)
		c.Next()
	}
}

func main() {
	r := gin.New()
	r.Use(gin.Recovery())
	v1 := r.Group("/v1", deprecateV1())
	v1.GET("/ping", func(c *gin.Context) {
		c.JSON(200, gin.H{"ok": true})
	})
	_ = r.Run(":8080")
}
```

#### What happens here

Every v1 response carries Deprecation and Link. The handler still returns 200. The client can plan migration. `Next` lets the handler through; there is no Abort.

### Example 5: route_missing vs item_missing

```go
func getItem(store Store) gin.HandlerFunc {
	return func(c *gin.Context) {
		it, err := store.Find(c.Request.Context(), c.Param("id"))
		if errors.Is(err, ErrNotFound) {
			c.JSON(http.StatusNotFound, gin.H{"error": "not found", "code": "item_missing"})
			return
		}
		if err != nil {
			c.JSON(http.StatusInternalServerError, gin.H{"error": "internal error", "code": "internal"})
			return
		}
		c.JSON(http.StatusOK, it)
	}
}

// NoRoute → code: route_missing
```

#### What happens here

Both can be HTTP 404, but `code` separates “wrong URL” from “no row”. Support and metrics thank you. The store uses Request Context.

### Example 6: Mount with health, flag, and two versions

```go
package httpapi

import (
	"net/http"

	"github.com/gin-gonic/gin"
)

type Deps struct {
	Items Items
}

func Mount(r *gin.Engine, d Deps) {
	r.HandleMethodNotAllowed = true
	r.GET("/health", func(c *gin.Context) { c.Status(http.StatusOK) })

	RegisterV1(r.Group("/v1", deprecateV1()), d.Items)
	RegisterV2(r.Group("/v2"), d.Items)

	r.NoRoute(func(c *gin.Context) {
		c.AbortWithStatusJSON(http.StatusNotFound, gin.H{
			"error": "route not found", "code": "route_missing",
		})
	})
	r.NoMethod(func(c *gin.Context) {
		c.AbortWithStatusJSON(http.StatusMethodNotAllowed, gin.H{
			"error": "method not allowed", "code": "method_not_allowed",
		})
	})
}

func deprecateV1() gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Header("Deprecation", "true")
		c.Header("Link", `</v2>; rel="successor-version"`)
		c.Next()
	}
}
```

#### What happens here

One `Mount` for `main` and tests. Health outside the version. v1 carries Deprecation on the whole group. Shared NoRoute/NoMethod. Flag on before route registration (order: flag + health + versions + fallback). No panic for “no route”.

**Predict the result:** `GET /v1/items/1` — must the body contain `"Deprecation"`?

**Answer:** not in the JSON body — header `Deprecation: true` on the response. The client reads headers, not a field in JSON (unless you explicitly add it there too — not required).

### Example 7: Any probe + explicit CRUD on the same Engine

```go
func registerSurface(r *gin.Engine) {
	r.Any("/probe", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"method": c.Request.Method})
	})

	items := r.Group("/v1/items")
	{
		items.GET("", listItems)
		items.POST("", createItem)
		items.GET("/:id", getItem)
		items.DELETE("/:id", deleteItem)
	}
}
```

#### What happens here

Probe is wide on purpose. Items are narrow methods. `POST /v1/items/1` (if there is no POST on `/:id`) goes to NoMethod when the flag is on — not to `createItem` (create is on the collection `""`). This separates “diagnostics” from “resource mutation”.

## Decision analysis

| Decision | Choice | Why |
|----------|--------|-----|
| Path vs header versioning | path `/v1` | simpler ops/curl/cache |
| Auth scope | admin Group | health stays public |
| 404 bodies | JSON + code | API clients, not HTML |
| Any on CRUD | no | prevents accidental methods |
| Fail-open without token | no | fail-closed 503 |

## Trade-offs

- **More versions** — compatibility; cost of maintaining two contracts.
- **Deep group nesting** — structure; harder to review final paths.
- **HandleMethodNotAllowed** — more accurate 405; slightly different router behavior, test it.
- **Demo header token** — teaches Abort; does not replace a real auth system.

## Common mistakes

1. **Wrong:** auth on the whole Engine, health under it.  
   **Effect:** LB gets 401, restart loop.  
   **Fix:** health outside the auth group.

2. **Wrong:** `NoMethod` without `HandleMethodNotAllowed`.  
   **Effect:** 404 instead of 405.  
   **Fix:** turn the flag on.

3. **Wrong:** `Any` on a write resource.  
   **Effect:** unexpected methods mutate state.  
   **Fix:** explicit methods.

4. **Wrong:** Abort without `return`.  
   **Effect:** the rest of the function still runs (locally); confusing bugs.  
   **Fix:** Abort + return.

5. **Wrong:** double prefix `/v1` in Group and path.  
   **Effect:** `/v1/v1/...`.  
   **Fix:** relative path in the group.

6. **Wrong:** HTML 404 for a JSON API.  
   **Effect:** client cannot parse.  
   **Fix:** `NoRoute` + JSON.

7. **Wrong:** panic when there is no route.  
   **Effect:** Recovery 500.  
   **Fix:** NoRoute handler.

8. **Wrong:** `c.JSON(401, …)` in auth without Abort, then `Next`.  
   **Effect:** the protected handler still runs.  
   **Fix:** `AbortWithStatusJSON` + `return`.

9. **Wrong:** same `code: "not_found"` for NoRoute and “no row”.  
   **Effect:** metrics lie; support wanders.  
   **Fix:** `route_missing` vs `item_missing`.

10. **Wrong:** shut down v1 as soon as v2 exists.  
    **Effect:** mobile clients break.  
    **Fix:** Deprecation + metrics + Sunset, then removal.

11. **Wrong:** solve CORS with `Any` on all paths.  
    **Effect:** overly broad method allowance; still wrong headers.  
    **Fix:** dedicated CORS middleware, explicit origin.

## Idiomatic Go

- `RegisterV1` / `RegisterV2` on `*gin.RouterGroup`.
- One error JSON shape globally (`error` + `code`).
- Auth middleware factory `func() gin.HandlerFunc`.
- Token/secret from env; empty env = fail-closed.
- Do not log Authorization / X-Token values.
- Test the matrix: health 200, admin without token 401, NoRoute 404, wrong method 405.

## Practical scenario

Mobile v1 expects flat JSON. The web team wants a `{ "data": … }` wrapper. You introduce `/v2` without shutting down `/v1`. Deprecation header on the v1 group. Admin metrics under `/v1/admin` with a token from the secret store. Health on `/health` for Kubernetes probes. After a quarter v1 traffic < 2% — Sunset date, then remove RegisterV1. The “probe 401” incident does not repeat because health was never under the auth group.

## Check questions

1. Why health outside `/v1`?  
   **Answer:** probe/LB must not depend on the API contract version or on version auth.

2. What is needed for NoMethod to work?  
   **Answer:** `HandleMethodNotAllowed = true` plus a `NoMethod` handler.

3. What is `AbortWithStatusJSON` for in auth middleware?  
   **Answer:** writes 401 and prevents the protected handler from running.

4. When is `Any` acceptable?  
   **Answer:** narrowly, e.g. probe — not as a substitute for CRUD methods.

5. How do path versions help cache/proxy?  
   **Answer:** the version is in the URL, easier for rules and debug than a hidden header.

6. Why `route_missing` vs `item_missing`?  
   **Answer:** same HTTP 404, different diagnostics and metrics.

7. What is fail-closed for a demo token?  
   **Answer:** if the secret is not in env, admin does not work (e.g. 503), instead of letting everything through.

8. Does the Deprecation header change the HTTP status of a successful v1 call?  
   **Answer:** no — still 200/201; the header only signals deprecation.

9. Where do you attach auth `Use` if health must be public?  
   **Answer:** on a narrower admin (or protected) group, not globally on Engine.

10. What happens if you forget `return` after Abort in middleware?  
    **Answer:** the rest of **that** function can continue; always Abort + return.

11. Why is `readyz` often outside `/v1`?  
    **Answer:** the orchestrator checks readiness independently of the API contract version.

12. Is `NoMethod` a substitute for CORS preflight?  
    **Answer:** no — OPTIONS preflight needs CORS middleware and headers, not only 405 JSON.

### Expectation matrix (memorize)

| Request | Expectation |
|---------|-------------|
| `GET /health` | 200 |
| `GET /v1/admin/stats` without token | 401 |
| `GET /v1/admin/stats` with good token | 200 |
| `GET /nope` | 404 `route_missing` |
| `POST /v1/public/catalog` (only GET registered) | 405 with flag |
| `GET /v1/items/xyz` (route ok, not in DB) | 404 `item_missing` |

### Mini trace: Abort vs Next

```text
demoAuth: bad token
  AbortWithStatusJSON(401)
  return
  → stats handler IS NOT CALLED

demoAuth: good token
  Next()
  → stats handler is called
  → return into demoAuth after Next (if there is code after)
```

Code **after** `Next` in outer middleware can still run even when the inner Abort happened — that is why 07.07 teaches `IsAborted` for timing/log. For now remember: Abort + return in the auth layer protects the handler.

### CORS and NoMethod — short boundary

The browser sends `OPTIONS` before `POST` from another origin. That is not a “wrong CRUD”. That is preflight. If you answer only `NoMethod` JSON without CORS headers, the browser blocks. That is why CORS middleware sits early and explicitly lists origin, methods, and headers. Do not mix `*` + cookies.

### Predict the result — quick set (07.03)

**1.** `v1 := r.Group("/v1"); adm := v1.Group("/admin"); adm.GET("/stats", h)` — full path?

**Answer:** `/v1/admin/stats`.

**2.** Registered `GET /v1/public/catalog`, flag `true`, request `DELETE /v1/public/catalog` — status?

**Answer:** 405 via NoMethod (if NoMethod is configured).

**3.** `Any("/probe")` and `GET /probe` — do they collide as a conflict of two GET registrations?

**Answer:** `Any` already registers GET (and other methods). An extra `GET /probe` on the same is a conflict. Pick one.

**4.** Admin group with auth; someone registers `r.GET("/v1/admin/stats", h)` outside the group — does auth apply?

**Answer:** no — that route did not go through `admin.Use`. Always register protected routes **on** the group with auth.

### Checklist before merging an API version

1. `/health` (and `/readyz` if needed) outside `/v1`
2. `HandleMethodNotAllowed = true` + JSON NoMethod
3. JSON NoRoute with `route_missing`
4. Auth only on protected groups
5. Fail-closed if there is no secret
6. v1 and v2 through `RegisterV*`
7. Deprecation on the obsolete group when migration starts
8. Table test: health, 401, 404 route, 405, item_missing

## Summary

- Nested groups build the public vs admin surface; prefixes concatenate.
- Path `/v1`/`/v2` + health outside the version is an ops-friendly model.
- `Any` narrowly; CRUD explicitly.
- `NoRoute`/`NoMethod` + flag give JSON 404/405.
- `AbortWithStatusJSON` + `return` protect the chain; Recovery still catches panic, not business errors.

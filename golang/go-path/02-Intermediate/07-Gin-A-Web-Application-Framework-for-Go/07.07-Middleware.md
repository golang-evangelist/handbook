# 07.07 Middleware in Gin: Next, Abort, order, Context

> **Go Path - Zero to Gopher** / **02 Intermediate → Gin: A Web Application Framework for Go** / Lesson 07.07

## Lesson goals

After this lesson you should be able to:

- write a `gin.HandlerFunc` middleware and a **factory** that returns middleware
- understand **`c.Next()`** (continue the chain) and **`c.Abort()`** (stop the rest of the chain)
- predict the **order** of execution before / inside / after `Next`
- know that code **after** `Next` can still run after Abort — use `c.IsAborted()` when needed
- use `Set` / `Get` / `GetString` for **request-scoped** values (not for a DB pool)
- use `MustGet` only when the value is guaranteed; `c.Copy()` before a goroutine
- compare the model with `func(http.Handler) http.Handler` from module 06 and `gin.WrapH`
- attach middleware with `Use` and at route level `GET("/x", mw1, mw2, h)`; write a `requireRole` factory

## Prerequisite

- 06.06 (middleware chain in `net/http`)
- 07.01–07.06 (Engine, routes, AbortWithStatusJSON, header/cookie order)
- basic `defer` and goroutine caution (do not share `gin.Context` across the boundary)

## Problem this lesson solves

In Gin, middleware is not a wrapper that returns `http.Handler` — it is the same kind of function as a handler (`func(*gin.Context)`), and the chain is controlled by Context. Without the `Next`/`Abort` model people:

- forget `Next` — the handler never runs
- do not Abort after 401 — the handler still runs
- put auth after the business handler in the list
- in code after `Next` log “success” even though Abort already returned 401
- put a DB pool in `c.Set` or pass `*gin.Context` into a background goroutine

This lesson builds the correct mental model of the chain, request-scoped storage, and comparison with standard `net/http` middleware.

## Mental model

Gin collects a chain: `[mw1, mw2, handler]`.

```text
mw1 before → mw2 before → handler → mw2 after → mw1 after
```

`c.Next()` enters the rest of the chain. Code **after** `Next()` in mw1 runs when the inside returns (like a “defer around” the inner call).

`c.Abort()` marks that **remaining** handlers (those that have not started yet) must not run. Code that is already “around” `Next` in outer middleware still continues after the return.

```text
Abort in mw2 before Next:
  mw1 before → mw2 Abort+return (no Next) → handler IS SKIPPED
  → mw1 after Next STILL RUNS
```

So after `Next` check `c.IsAborted()` or at least the status code before declaring success.

**Request-scoped** data (`c.Set("uid", ...)`) lives for **this** request. Do not put a connection pool, global config, or “cache of the whole world” there. For a pool use dependency injection in a factory / `NewRouter(deps)`.

`gin.Context` is **not** safe for concurrent access from another goroutine — use `c.Copy()` if you must read a copy in the background (and still do not write an HTTP response from that goroutine without a clear pattern).

### Glossary table

| Term | Short gloss (once) | Note |
|------|--------------------|------|
| `gin.HandlerFunc` | type `func(*gin.Context)` | both middleware and handler |
| `c.Next` | continue the chain | blocks until the inside returns |
| `c.Abort` | stop the rest of the chain | does not erase the rest of **your** function |
| `c.Set`/`Get` | request-scoped map | not a DB pool |
| `c.Copy` | copy of the context | for reading in a goroutine |
| `gin.WrapH` | bridge from `http.Handler` | when you have a standard handler |

## Mechanism

### Basic shape and factory

```go
func timing() gin.HandlerFunc {
	return func(c *gin.Context) {
		start := time.Now()
		c.Next()
		log.Printf("%s %s %d %s", c.Request.Method, c.FullPath(), c.Writer.Status(), time.Since(start))
	}
}
```

A factory (`timing()`) returns `gin.HandlerFunc`. Why a factory? So you can close over configuration (threshold, logger, expected token) in a **closure** without global variables.

```go
func requireToken(expected string) gin.HandlerFunc {
	return func(c *gin.Context) {
		if c.GetHeader("X-Token") != expected {
			c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "unauthorized"})
			return
		}
		c.Next()
	}
}
```

### Chain before / Next / after

```go
func trace(name string) gin.HandlerFunc {
	return func(c *gin.Context) {
		log.Printf("%s before", name)
		c.Next()
		log.Printf("%s after aborted=%v status=%d", name, c.IsAborted(), c.Writer.Status())
	}
}
```

Registration:

```go
r.Use(trace("A"), trace("B"))
r.GET("/x", func(c *gin.Context) {
	log.Printf("handler")
	c.Status(http.StatusOK)
})
```

**Execution trace (success):**

```text
A before → B before → handler → B after → A after
```

**Predict:** if B does Abort without Next, which log lines disappear?

**Answer:** `handler` does not run. `B after` also disappears if B returns **before** `Next` (there is no “after” block after Next). `A after` **remains**, because A already entered Next and is waiting for the return.

### Abort + return + IsAborted

```go
func auth() gin.HandlerFunc {
	return func(c *gin.Context) {
		if c.GetHeader("X-Token") == "" {
			c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "missing token"})
			return
		}
		c.Set("uid", "42")
		c.Next()
	}
}

func accessLog() gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Next()
		if c.IsAborted() {
			log.Printf("aborted status=%d path=%s", c.Writer.Status(), c.FullPath())
			return
		}
		log.Printf("ok status=%d path=%s", c.Writer.Status(), c.FullPath())
	}
}
```

Without `IsAborted`, accessLog could say “ok” based on a wrong assumption. Status and the Abort flag are the source of truth after Next.

### Use order

```go
r := gin.New()
r.Use(gin.Recovery())
r.Use(requestID())
r.Use(accessLog())
r.Use(auth()) // if global — all routes require auth
```

`Use` order = order of the **before** phase. Recovery on the outside catches panic from the inside. Request ID before the log so the log sees the ID. Auth after the ID so a 401 log has the ID.

Often auth is **not** global — it goes on a group (07.03 / 07.08):

```go
r.GET("/health", health)
api := r.Group("/api")
api.Use(auth())
api.GET("/secret", secret)
```

### Set / Get / GetString

```go
c.Set("uid", "42")
c.Set("reqID", id)

v, ok := c.Get("uid")
uid := c.GetString("uid") // "" if missing or not a string
```

Agree on keys as constants in the package:

```go
const ctxUID = "uid"
```

**Do not** put:

- `*sql.DB` pool (lives in the router’s `deps` struct)
- large files / a buffer of the whole body “for later” without need
- mutable structures you share between requests

### MustGet

```go
uid := c.MustGet(ctxUID).(string)
```

`MustGet` panics if the key is missing. Use **only** in a handler that sits behind middleware that **guarantees** Set. Otherwise `Get` + `ok`. Panic here is caught by Recovery as 500 — that is a bug in middleware order, not a happy AuthZ strategy.

### c.Copy() and goroutine

```go
func auditAsync() gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Next()
		cp := c.Copy()
		go func() {
			// READ from cp — do not write a response via cp in production without a clear design
			log.Printf("async audit method=%s path=%s", cp.Request.Method, cp.FullPath())
		}()
	}
}
```

The original `*gin.Context` is recycled / not thread-safe. `Copy` makes a copy suitable for **reading** metadata. Still: do not do `cp.JSON` from the background as a substitute for the request response — the response is already finished after Next.

### FullPath and timing

`c.FullPath()` returns the route template (`/items/:id`), not the raw URL with values — better for metrics (lower cardinality than raw path).

```go
start := time.Now()
c.Next()
latency := time.Since(start)
log.Printf("%s %s %d %s", c.Request.Method, c.FullPath(), c.Writer.Status(), latency)
```

### Comparison with net/http middleware

Standard shape:

```go
func stdMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		// before
		next.ServeHTTP(w, r)
		// after
	})
}
```

Gin equivalent:

```go
func ginMiddleware() gin.HandlerFunc {
	return func(c *gin.Context) {
		// before
		c.Next() // ≈ next.ServeHTTP
		// after
	}
}
```

Bridge:

```go
r.Any("/legacy", gin.WrapH(stdHandler))
r.Any("/legacy2", gin.WrapF(stdHandlerFunc))
```

Use `WrapH` / `WrapF` when you have an existing `http.Handler` ecosystem. Inside there is no Gin `Set` unless you manually bridge it.

### Middleware at route level

```go
r.GET("/admin/stats", requireRole("admin"), statsHandler)
```

Order in the list: left → right in the before phase. `requireRole` before `statsHandler`.

### requireRole factory

```go
func requireRole(role string) gin.HandlerFunc {
	return func(c *gin.Context) {
		got := c.GetString("role")
		if got != role {
			c.AbortWithStatusJSON(http.StatusForbidden, gin.H{"error": "forbidden"})
			return
		}
		c.Next()
	}
}
```

Auth middleware before that does Set `"role"`. Separation: AuthN (who you are) vs AuthZ (may you). 401 vs 403 remains from 07.05.

### Execution trace: group + route mw

```text
r.Use(requestID, accessLog)
g := r.Group("/api", auth)
g.GET("/admin", requireRole("admin"), handler)

GET /api/admin:
  requestID before → accessLog before → auth before → requireRole before → handler
  → requireRole after → auth after → accessLog after → requestID after
```

If auth Abort 401: handler and requireRole are skipped; accessLog after sees Abort/status 401.

### Predict: code after Next after Abort

```go
func mw() gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Next()
		fmt.Println("always?")
	}
}
```

The inner handler does Abort. Is `always?` printed?

**Answer:** yes, if `Next` was called — Abort does not erase stack frames waiting for return from Next. That is why `IsAborted` / status check.

## Rules and syntax

1. Middleware = `gin.HandlerFunc`; a factory returns configured middleware.
2. After Abort always `return` in the same function.
3. Code after `Next` can see Abort — use `IsAborted` when logging success.
4. `Use` order = before-phase order; Recovery on the outside.
5. `Set`/`Get` only request-scoped; pool outside Context.
6. `MustGet` only when guaranteed by previous middleware.
7. Goroutine: `c.Copy()` for reading; do not share a live Context.
8. Measure latency: start before Next, log after; prefer `FullPath`.
9. Compare with `func(http.Handler) http.Handler`; bridge `gin.WrapH`.
10. Route-level: `GET(path, mw1, mw2, h)`.
11. `requireRole` = AuthZ factory; AuthN separately.
12. Do not panic on purpose for 401 — Abort + JSON (Recovery is a net).

## Examples

### Example 1: Timing middleware

```go
func timing() gin.HandlerFunc {
	return func(c *gin.Context) {
		start := time.Now()
		c.Next()
		log.Printf("%s %s %d %s", c.Request.Method, c.FullPath(), c.Writer.Status(), time.Since(start))
	}
}

func main() {
	r := gin.New()
	r.Use(gin.Recovery(), timing())
	r.GET("/ping", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"ok": true})
	})
	_ = r.Run(":8080")
}
```

#### What happens here

Recovery on the outside. Timing measures the whole inner chain including the handler. FullPath for `/ping` is `/ping`. Status after Next reflects JSON 200.

### Example 2: Request ID + Set/Get

```go
const ctxReqID = "reqID"

func requestID() gin.HandlerFunc {
	return func(c *gin.Context) {
		id := c.GetHeader("X-Request-ID")
		if id == "" {
			id = fmt.Sprintf("%d", time.Now().UnixNano())
		}
		c.Set(ctxReqID, id)
		c.Header("X-Request-ID", id)
		c.Next()
	}
}

func handler(c *gin.Context) {
	c.JSON(http.StatusOK, gin.H{"reqID": c.GetString(ctxReqID)})
}
```

#### What happens here

ID from the client or generated. Set in Context, Header on the response (before Next — no body yet). Handler reads GetString. Correlation for 07.05/07.06 is complete.

### Example 3: Auth Abort and IsAborted in the logger

```go
func tokenAuth(expected string) gin.HandlerFunc {
	return func(c *gin.Context) {
		if c.GetHeader("X-Token") != expected {
			c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "unauthorized"})
			return
		}
		c.Set("uid", "u1")
		c.Next()
	}
}

func afterLog() gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Next()
		if c.IsAborted() {
			log.Printf("fail %d %s", c.Writer.Status(), c.GetString(ctxReqID))
			return
		}
		log.Printf("ok %d %s", c.Writer.Status(), c.GetString(ctxReqID))
	}
}
```

#### What happens here

Without token: Abort 401, handler is not called, afterLog sees IsAborted. With token: uid Set, handler runs, afterLog “ok”. **Predict:** forgotten return after Abort in tokenAuth — what? **Answer:** Next can be called and the handler runs despite a 401 response — duplicate/chaotic outcome.

### Example 4: requireRole on a route

```go
func withRole(role string) gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Set("role", role) // in real auth this comes from token/store
		c.Next()
	}
}

func main() {
	r := gin.New()
	r.Use(gin.Recovery())
	r.GET("/admin", withRole("user"), requireRole("admin"), func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"secret": true})
	})
	_ = r.Run(":8080")
}
```

#### What happens here

The demo forces role=user then requireRole(admin) → 403 Abort. The handler does not run. In a real system withRole is replaced by JWT/session lookup. This shows the **order** of the route middleware list.

### Example 5: WrapH bridge

```go
mux := http.NewServeMux()
mux.HandleFunc("/legacy", func(w http.ResponseWriter, r *http.Request) {
	_, _ = w.Write([]byte("legacy"))
})

r := gin.New()
r.Use(gin.Recovery())
r.Any("/legacy", gin.WrapH(mux))
```

#### What happens here

The Gin chain (Recovery) still wraps the legacy handler. Legacy does not see `c.Set` unless you write an extra bridge. Useful for migration from net/http.

### Example 6: Copy in a goroutine after Next

```go
func fanoutLog() gin.HandlerFunc {
	return func(c *gin.Context) {
		c.Next()
		cp := c.Copy()
		go func() {
			log.Printf("fanout status=%d aborted=%v path=%s",
				cp.Writer.Status(), cp.IsAborted(), cp.FullPath())
		}()
	}
}
```

#### What happens here

The response is finished. Copy keeps a snapshot for async log. Do not use the original `c` in `go func`. Do not call `cp.JSON` — it is too late and the wrong layer.

## Decision analysis

| Decision | Choice | Why |
|----------|--------|-----|
| Auth scope | Group Use | health public |
| Success log | after Next + IsAborted | accurate signal |
| Pool | deps in NewRouter | not Set |
| Metrics path | FullPath | low cardinality |
| Role check | factory requireRole | reusable |
| Legacy | WrapH | migration |
| Async | Copy | no data race on Context |

## Trade-offs

- **Global auth Use** — fewer forgets; easy to kill health/metrics.
- **MustGet** — shorter code; panic if order breaks.
- **Heavy work after Next** — slows the response (still holds the connection); async with Copy or a queue.
- **Many small middlewares** — clear separation; harder to follow order.
- **WrapH** — fast migration; two mental models in one process.

## Common mistakes

1. **Wrong:** forgotten `c.Next()`.  
   **Effect:** handler does not run.  
   **Fix:** call Next when the chain should continue.

2. **Wrong:** Abort without `return`.  
   **Effect:** Next/handler still runs.  
   **Fix:** Abort + return.

3. **Wrong:** log “success” after Next without IsAborted.  
   **Effect:** false success on 401.  
   **Fix:** check Abort/status.

4. **Wrong:** `c.Set("db", db)` as DI.  
   **Effect:** hidden dependency, Context abuse.  
   **Fix:** `NewRouter(deps)`.

5. **Wrong:** `go func(){ c.JSON(...) }` with a live Context.  
   **Effect:** race / panic / broken Writer.  
   **Fix:** do not write the response from the background; Copy only for reading meta.

6. **Wrong:** auth after the handler in the list.  
   **Effect:** business code runs before the check.  
   **Fix:** mw before the handler.

7. **Wrong:** MustGet on a public route without Set.  
   **Effect:** panic → 500.  
   **Fix:** Get+ok or guarantee middleware.

8. **Wrong:** measuring only raw `c.Request.URL.Path` in metrics.  
   **Effect:** label explosion (`/items/1`, `/items/2`, …).  
   **Fix:** `FullPath()`.

## Idiomatic Go

- Factory middleware closes config in a closure.
- Constants for Set keys.
- `NewRouter(deps)` + Group Use for auth.
- Timing/Recovery/Logger order explicit (`gin.New`, not magic).
- Test Abort: status 401 and that the handler side-effect did not happen (07.09).
- Document order in one comment above the `Use` block if the chain grows.

## Practical scenario

Incident: “/health returns 401 in Kubernetes probe”. Cause: `r.Use(auth())` globally. Fix: auth only on the `/api` group. Second incident: metrics have 50k path labels — switch to `FullPath`. Third: async audit uses live `c` → occasional panic in the race detector; `c.Copy()` after Next. Fourth: access log always “ok” because it did not look at `IsAborted` after token fail — dashboard lied. All four mistakes are points from this lesson.

## Check questions

1. What does `c.Next()` do?  
   **Answer:** runs the rest of the chain and returns when the inside finishes.

2. Does Abort erase code after Next in outer middleware?  
   **Answer:** no — that code still runs after the return; use IsAborted.

3. Why factory `func(cfg) gin.HandlerFunc`?  
   **Answer:** closes configuration in a closure without global state.

4. What may go in `c.Set`?  
   **Answer:** request-scoped values (uid, reqID, role) — not a DB pool.

5. When `c.Copy()`?  
   **Answer:** before reading metadata in another goroutine.

6. What is `FullPath` for in the log?  
   **Answer:** the route template — better for metric aggregation.

7. How do you attach mw to only one route?  
   **Answer:** `r.GET("/x", mw1, mw2, handler)`.

8. Relation to `func(http.Handler) http.Handler`?  
   **Answer:** the same before/next/after shape; Gin uses Next instead of next.ServeHTTP; WrapH is the bridge.

### Predict: Use order

```go
r.Use(a(), b())
r.GET("/", h)
```

Which before order?

**Answer:** a before, b before, h, b after, a after.

### Predict: Abort in the handler

The handler calls `AbortWithStatusJSON(404)` + return. Does outer timing see status 404 after Next?

**Answer:** yes — Writer.Status should reflect 404; IsAborted true.

### Predict: Set type

```go
c.Set("uid", 42) // int
s := c.GetString("uid")
```

What is `s`?

**Answer:** `""` — GetString expects a string; the type does not match. Keep a consistent type or use Get + type assertion deliberately.

### Detailed walkthrough: three middlewares

Assume registration:

```go
r.Use(requestID(), accessLog(), auth())
r.GET("/x", handler)
```

**Success:**

```text
requestID: Set + Header
accessLog: enter Next
auth: token OK, Set uid, Next
handler: JSON 200
auth: return from Next (no after code)
accessLog: IsAborted=false, log ok + status 200
requestID: return
```

**Auth failure:**

```text
requestID: Set + Header
accessLog: Next
auth: AbortWithStatusJSON 401; return  // no Next
handler: SKIPPED
accessLog: IsAborted=true, log fail + 401
requestID: return
```

Remember: Abort does **not** mean “skip everything already on the stack”. It means “do not call remaining handlers in the chain”.

### Keys and type assertion

```go
v, ok := c.Get(ctxUID)
if !ok {
	c.AbortWithStatusJSON(http.StatusUnauthorized, gin.H{"error": "unauthorized"})
	return
}
uid, ok := v.(string)
if !ok {
	c.AbortWithStatusJSON(http.StatusInternalServerError, gin.H{"error": "internal error"})
	return
}
_ = uid
```

Type assertion after Get protects against a wrong type in Set. `MustGet` + assert without a check = panic on bug.

### Group Use vs route Use

```go
admin := r.Group("/admin")
admin.Use(auth(), requireRole("admin"))
admin.GET("/stats", stats)
admin.GET("/users", users)

r.GET("/public/stats", stats) // without auth — deliberately different
```

Group reduces repetition. Route-level mw when **one** route has an exception. Do not mix without documentation: the reader must see who is protected.

### What is not middleware

- Calling a service inside a handler is not middleware.
- `defer` in a handler is not a chain — it is local to that function.
- Global `http.Server` timeout is not Gin middleware, but it affects the same request.

Middleware solves **cross-cutting** concerns: log, auth, request ID, CORS, Recovery.

### Link to 07.05 AbortWithStatusJSON

`AbortWithStatusJSON` = write a JSON error + `Abort()`. In middleware that is the idiom for 401/403. In a handler the same for 404/409. After that `return`. Code after `Next` in outer layers still sees the status — that is why Logger works.

### Middleware and binding

Auth middleware **before** a handler that does ShouldBindJSON means: an invalid token does not spend time parsing the body (and does not log body errors for anonymous users). The reverse order (bind then auth) is sometimes needed when auth depends on the body — rare; document the exception.

### Chain testability (preview of 07.09)

Middleware is tested with the same `ServeHTTP` pattern:

1. Request without token → 401, body has `error`.
2. Request with token → 200.
3. Side-effect in the handler (e.g. a counter) stays 0 when 401 — proof the handler did not run.

Without point 3, the test only confirms status, not Abort behavior.

### Common key constants

```go
package httpapi

const (
	CtxReqID = "reqID"
	CtxUID   = "uid"
	CtxRole  = "role"
)
```

One package, one set of names. Prevents `"userId"` vs `"uid"` chaos between middlewares.

### What gin.Engine.Use does

`Use` adds middleware to the Engine (or Group). Orders **concatenate**: Group inherits Engine Use, then adds its own. The route list adds more locals. Final chain = engine + group + route + handler.

## Summary

- Middleware is `gin.HandlerFunc`; `Next` continues, `Abort`+`return` stops the rest of the chain.
- Code after Next lives even after Abort — `IsAborted` / status.
- `Set`/`Get` request-scoped; `MustGet` with a guarantee; `Copy` for goroutine reading.
- Use order, Group, route-level lists; `requireRole` factory; WrapH for the net/http bridge.
- FullPath for metrics; do not panic for expected 401/403.

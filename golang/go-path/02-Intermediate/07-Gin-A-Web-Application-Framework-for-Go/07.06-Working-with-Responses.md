# 07.06 Working with responses: headers, cookies, files, stream

> **Go Path - Zero to Gopher** / **02 Intermediate → Gin: A Web Application Framework for Go** / Lesson 07.06

## Lesson goals

After this lesson you should be able to:

- set response **headers** via `c.Header` **before** the body (`Cache-Control`, request ID, `Location`)
- read and write **cookies** (`SetCookie` / `Cookie`), understand `HttpOnly`, `Secure`, deletion with `maxAge=-1`, and SameSite via `http.SetCookie`
- serve files with `c.File` / `c.FileAttachment` with a **path jail** (no path traversal)
- know when a large file should not go through app memory but via a signed URL / object storage
- use briefly **`c.Stream`** while respecting `c.Request.Context()` cancellation and `WriteTimeout`
- sketch CORS without `*` when sending credentials; serve static with `embed.FS` / `StaticFS`
- pass the download checklist: AuthZ + jail + audit

## Prerequisite

- 07.05 (JSON / Status / Abort / one response / header before body)
- cookie basics from 06.03
- awareness of `WriteTimeout` / `ReadTimeout` (06.01 / 06.08)
- difference `gin.Context` vs `context.Context` (`c.Request.Context()` for cancellation)

## Problem this lesson solves

An API is not only a JSON body:

- report download (PDF, CSV)
- session cookie with JSON login
- CORS and cache headers
- occasional log or event streams
- request ID to correlate logs with 500 from 07.05

Without a clear order (**header then body**) the cookie “does not arrive”, the cache caches private responses, the stream “breaks” on timeout, and `c.File("../../etc/passwd")` becomes an incident. This lesson connects Gin helpers with HTTP and security boundaries.

## Mental model

```text
Response =
  status + headers (+ Set-Cookie) + body

Order discipline:
  1) AuthZ decision
  2) Header / SetCookie
  3) JSON | File | Stream | Status

Stream / File:
  - respect context cancel
  - do not hold a gigabyte in []byte in-process if a signed URL works
  - path always clean + root jail
```

- Headers are part of the response **before** (or with) the first body write.
- A cookie is a special `Set-Cookie` header — Gin gives a `SetCookie` helper; SameSite often goes through standard `http.SetCookie`.
- `c.File` reads from disk and typically guesses Content-Type by extension — **the path must be under server control**, not a raw user string.
- `c.Stream` allows chunked writing while the client reads — keep `context` cancellable and align `WriteTimeout`.

CORS sketch: `Access-Control-Allow-Origin: *` does **not** go together with `Access-Control-Allow-Credentials: true`. The browser rejects that. For a cookie-based SPA name the exact origin.

## Mechanism

### Headers before body

```go
c.Header("X-Request-ID", id)
c.Header("Cache-Control", "no-store")
c.JSON(http.StatusOK, gin.H{"ok": true})
```

`c.Header` writes into `c.Writer.Header()`. After the body starts, a late Header is unreliable. The idiom from 07.05 still applies: **all metadata decisions before Write**.

Common headers in an API:

| Header | Example value | Purpose |
|--------|---------------|---------|
| `Cache-Control` | `no-store` / `private, max-age=0` / `public, max-age=60` | cache |
| `X-Request-ID` | UUID from middleware | correlation |
| `Location` | `/items/42` | 201 create |
| `Content-Disposition` | `attachment; filename="a.pdf"` | download name (FileAttachment helps) |

**Predict:** a public config endpoint with `Cache-Control: public, max-age=60` — may it contain user-specific fields?

**Answer:** no. Public cache + private data = leak between users via CDN/browser cache. Private → `private` or `no-store`.

### Request ID

Middleware (detail in 07.07) does `c.Set("reqID", id)` and often sets the response header. The handler only reads:

```go
c.Header("X-Request-ID", c.GetString("reqID"))
```

The same ID goes into the log line with a 500. Without it, “internal error” from 07.05 cannot be tied to a stack trace.

### Cookie: SetCookie and Cookie

```go
// name, value, maxAge(sec), path, domain, secure, httpOnly
c.SetCookie("sid", "value", 3600, "/", "", false, true)

val, err := c.Cookie("sid")
if err != nil {
	// no cookie or read error
}
```

Flag meanings:

| Flag | Effect |
|------|--------|
| `HttpOnly` | JavaScript does not read the cookie — reduces XSS session theft |
| `Secure` | sent only over HTTPS |
| `maxAge` | lifetime in seconds; `0` = session cookie (browser-dependent); `-1` = delete |
| `path` | which paths the cookie is sent for — often `"/"` |
| `domain` | empty = host-only of the current host |

Deletion:

```go
c.SetCookie("sid", "", -1, "/", "", true, true)
```

**Predict:** `Secure=false` on a production login over HTTPS termination — what do you risk?

**Answer:** the cookie can also travel over plain HTTP if the user ever hits an http URL — session theft. In production with TLS: `Secure=true`.

### SameSite via http.SetCookie

Gin `SetCookie` in many versions does not expose SameSite directly as a parameter. Idiom:

```go
http.SetCookie(c.Writer, &http.Cookie{
	Name:     "sid",
	Value:    sessionID,
	Path:     "/",
	MaxAge:   3600,
	HttpOnly: true,
	Secure:   true,
	SameSite: http.SameSiteLaxMode, // or Strict / None(+Secure)
})
```

`SameSite=None` requires `Secure=true` in modern browsers. For a first-party API often `Lax` or `Strict`. Cross-site SPA+cookie needs a careful CORS + SameSite plan — not “put `*` and done”.

### File vs FileAttachment

```go
c.File("./reports/out.pdf")
c.FileAttachment("./reports/out.pdf", "report.pdf")
```

- `File` — typically inline / browser decides display.
- `FileAttachment` — forces a download name via Content-Disposition.

Both read from the process’s **local** filesystem. Do not insert raw `c.Query("path")` without a jail.

### Path jail

```go
func safeReportPath(root, name string) (string, error) {
	if name == "" || strings.Contains(name, "..") {
		return "", errBadPath
	}
	clean := filepath.Clean(name)
	full := filepath.Join(root, clean)
	rel, err := filepath.Rel(root, full)
	if err != nil || strings.HasPrefix(rel, "..") {
		return "", errBadPath
	}
	return full, nil
}
```

Then:

```go
full, err := safeReportPath("/var/app/reports", c.Param("name"))
if err != nil {
	c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": "invalid input"})
	return
}
c.FileAttachment(full, filepath.Base(full))
```

**Predict:** `name=../../etc/passwd` without a jail — what does naive `c.File(root+"/"+name)` do?

**Answer:** path traversal — reading outside the root. Jail + `Clean` + `Rel` check are mandatory.

### Large files → signed URL, not app memory

Anti-pattern:

```go
b, _ := os.ReadFile(huge) // BAD for GB files
c.Data(200, "application/pdf", b)
```

Better:

1. Authorize the user in your API.
2. Generate a short-lived signed URL to S3/GCS/MinIO (or nginx `X-Accel-Redirect` / CDN).
3. The client downloads directly from storage.

The app process does not hold a gigabyte on the heap and does not hold `WriteTimeout` busy for minutes per download. `c.File` is OK for **small/medium** local artifacts under a jail.

### c.Stream — introduction

```go
c.Header("Content-Type", "text/plain; charset=utf-8")
c.Stream(func(w io.Writer) bool {
	select {
	case <-c.Request.Context().Done():
		return false // client cancelled / timeout
	default:
	}
	_, err := w.Write([]byte("chunk\n"))
	if err != nil {
		return false
	}
	// true = continue callback; false = end of stream
	return false
})
```

For real SSE (`text/event-stream`) you need more: correct Content-Type, flush, `data: ...\n\n` format, keepalive. Here it is an **introduction**: the callback writes chunks; `false` ends; always watch `Context().Done()`.

`WriteTimeout` on `http.Server` must allow the stream duration. If the timeout is 5s and the stream lasts 5 min — the connection breaks. Options: longer timeout for that server, a separate endpoint/server for stream, or reverse-proxy settings.

**Predict:** the callback ignores cancel and writes in a loop. What happens when the client closes the tab?

**Answer:** the process spends CPU/IO until Write fails; it can hold a goroutine longer than needed. That is why `select` on `Done()`.

### CORS sketch (without *)

```go
func corsAllow(origin string) gin.HandlerFunc {
	return func(c *gin.Context) {
		o := c.GetHeader("Origin")
		if o == origin {
			c.Header("Access-Control-Allow-Origin", origin)
			c.Header("Access-Control-Allow-Credentials", "true")
			c.Header("Vary", "Origin")
		}
		if c.Request.Method == http.MethodOptions {
			c.Header("Access-Control-Allow-Methods", "GET,POST,OPTIONS")
			c.Header("Access-Control-Allow-Headers", "Content-Type,X-Token")
			c.Status(http.StatusNoContent)
			c.Abort()
			return
		}
		c.Next()
	}
}
```

Do not use `Allow-Origin: *` with credentials. Do not blindly copy `Origin` from the request without an allowlist — that is reflection and opens CSRF-ish problems.

### embed.FS and StaticFS

```go
//go:embed static/*
var staticFS embed.FS

func mountStatic(r *gin.Engine) {
	sub, err := fs.Sub(staticFS, "static")
	if err != nil {
		panic(err) // startup fail — OK at boot, not in a request handler as an error strategy
	}
	r.StaticFS("/assets", http.FS(sub))
}
```

`embed.FS` packs files into the binary. No runtime path traversal outside the embedded tree. For user-upload reports you still need a jail on disk or object storage — embed is for UI/assets.

Startup `panic` here means “the app must not start without assets”. That is not the same as panic in a handler for 404 (forbidden in 07.05).

### Download checklist: AuthZ + jail + audit

Before every `File` / `FileAttachment`:

1. **AuthN** — who is the user (token/session).
2. **AuthZ** — may that user have that object (ownership, role).
3. **Jail** — path under the root; no `..`.
4. **Audit** — log: user, request ID, file name, outcome (no secrets in the log).
5. Only then `FileAttachment`.

Skipping step 2 + direct `c.File("/data/"+id)` = IDOR (Insecure Direct Object Reference).

### Execution trace: login cookie + JSON

```text
POST /login
  → validation
  → http.SetCookie(... Secure HttpOnly SameSite)
  → c.JSON(200, {"ok": true})
Browser stores Set-Cookie; the next request sends the Cookie header.
```

If JSON goes **before** Set-Cookie and the Writer flushes early, the cookie may be missing. Keep the order: cookie helper, then JSON.

### Execution trace: stream + cancel

```text
GET /events (Stream)
  chunk1 Write OK
  client closes connection → Context canceled
  next loop select sees Done → return false
  middleware after Next logs status / duration
```

### Content-Type and File

`c.File` / `http.ServeContent` typically guess MIME by extension (`.pdf` → `application/pdf`). If you serve a file without an extension or with a wrong name, the client may misinterpret. `FileAttachment` additionally sets the download filename — that is the **name for the client**, not the path on disk. Never put a raw user string into `filename=` without sanitization (`\r`, `\n`, paths).

```go
safeName := filepath.Base(full) // no directory
c.FileAttachment(full, safeName)
```

### Cookie reading vs Authorization header

Two common AuthN models:

| Model | Where the secret lives | CSRF surface | CORS |
|-------|------------------------|--------------|------|
| Cookie session | Cookie automatically with the request | larger — needs SameSite/CSRF strategy | credentials + exact origin |
| Bearer / X-Token | Authorization header manually | smaller for a plain API | often without credentials cookie |

07.08 builds the demo on a header token. This lesson teaches cookie mechanics because JSON login often mixes both worlds. Do not confuse “I set a cookie” with “the API is secure” — without Secure/HttpOnly/SameSite and AuthZ on download you still have holes.

### WriteTimeout and reverse proxy

Even when the Go server has a large `WriteTimeout`, nginx/ALB can have its own idle timeout. A stream that “works locally” fails in staging because of the proxy. Checklist:

1. Go `http.Server` WriteTimeout
2. Proxy `proxy_read_timeout` / idle
3. Load balancer idle
4. Client timeout

For short REST JSON responses keep timeouts short (DoS hygiene). For stream — either isolate, or document longer timeouts as a deliberate exception.

### Cache-Control variants (brief)

| Value | When |
|-------|------|
| `no-store` | auth responses, PII, token echo |
| `private, max-age=0` | browser cache OK but not shared CDN — still be careful |
| `public, max-age=N` | truly public, same for all users |
| `no-cache` | may cache but must revalidate — does not mean “do not store” |

The name `no-cache` confuses beginners: it is not the same as `no-store`. When in doubt in an API with login — `no-store`.

## Rules and syntax

1. `c.Header` / cookie **before** JSON/File/Stream body.
2. `Cache-Control: no-store` (or private) for authenticated / personal responses.
3. Request ID in the response header + log.
4. Cookie: `HttpOnly` for session; `Secure` with HTTPS; delete with `maxAge=-1`.
5. SameSite via `http.SetCookie` when you need it explicitly.
6. `File` / `FileAttachment` only after AuthZ + path jail.
7. Large files → signed URL / storage, not `ReadFile` of the whole content.
8. Stream: check `c.Request.Context().Done()`; align `WriteTimeout`.
9. CORS: no `*` with credentials; allowlist origin.
10. `embed.FS` / `StaticFS` for static; user content separately.
11. Download checklist always: AuthZ + jail + audit.
12. Do not log session cookie / Authorization values.

## Examples

### Example 1: Cache and request ID headers

```go
func getPublicConfig(c *gin.Context) {
	c.Header("Cache-Control", "public, max-age=60")
	c.Header("X-Request-ID", c.GetString("reqID"))
	c.JSON(http.StatusOK, gin.H{"featureX": true})
}

func getMe(c *gin.Context) {
	c.Header("Cache-Control", "no-store")
	c.Header("X-Request-ID", c.GetString("reqID"))
	c.JSON(http.StatusOK, gin.H{"user": c.GetString("uid")})
}
```

#### What happens here

Public config may have a short public cache. `/me` must not — `no-store`. Both echo the request ID for support. Header before JSON.

### Example 2: Login cookie + logout deletion

```go
func login(c *gin.Context) {
	sid := "session-demo" // in production: crypto-random ID in a store
	http.SetCookie(c.Writer, &http.Cookie{
		Name:     "sid",
		Value:    sid,
		Path:     "/",
		MaxAge:   3600,
		HttpOnly: true,
		Secure:   true,
		SameSite: http.SameSiteLaxMode,
	})
	c.JSON(http.StatusOK, gin.H{"ok": true})
}

func logout(c *gin.Context) {
	http.SetCookie(c.Writer, &http.Cookie{
		Name:     "sid",
		Value:    "",
		Path:     "/",
		MaxAge:   -1,
		HttpOnly: true,
		Secure:   true,
		SameSite: http.SameSiteLaxMode,
	})
	c.Status(http.StatusNoContent)
}
```

#### What happens here

Login sets the cookie then JSON. Logout deletes with the same name/path/secure/httpOnly combination (otherwise the browser does not delete). 204 without body. **Predict:** if path on set is `"/api"` and on delete `"/"`, what? **Answer:** deletion may not hit the same cookie — path must match.

### Example 3: FileAttachment with jail and AuthZ

```go
var errForbidden = errors.New("forbidden")
var errBadPath = errors.New("bad path")

func downloadReport(root string, allowed func(uid, name string) bool) gin.HandlerFunc {
	return func(c *gin.Context) {
		uid := c.GetString("uid")
		name := c.Param("name")
		if !allowed(uid, name) {
			c.AbortWithStatusJSON(http.StatusForbidden, gin.H{"error": "forbidden"})
			return
		}
		full, err := safeReportPath(root, name)
		if err != nil {
			c.AbortWithStatusJSON(http.StatusBadRequest, gin.H{"error": "invalid input"})
			return
		}
		log.Printf("download user=%s req=%s file=%s", uid, c.GetString("reqID"), name)
		c.FileAttachment(full, filepath.Base(full))
	}
}

func safeReportPath(root, name string) (string, error) {
	if name == "" || strings.Contains(name, "\x00") {
		return "", errBadPath
	}
	clean := filepath.Clean(name)
	if clean == "." || strings.HasPrefix(clean, "..") {
		return "", errBadPath
	}
	full := filepath.Join(root, clean)
	rel, err := filepath.Rel(root, full)
	if err != nil || rel == ".." || strings.HasPrefix(rel, ".."+string(os.PathSeparator)) {
		return "", errBadPath
	}
	return full, nil
}
```

#### What happens here

First AuthZ, then jail, then audit log, then FileAttachment. No raw user path. 403 and 400 are separate. The file goes from disk — not loaded entirely into `[]byte` in the handler explicitly (Gin/stream OS read).

### Example 4: Stream with context cancel

```go
func tickStream(c *gin.Context) {
	c.Header("Content-Type", "text/plain; charset=utf-8")
	c.Header("Cache-Control", "no-store")
	n := 0
	c.Stream(func(w io.Writer) bool {
		select {
		case <-c.Request.Context().Done():
			return false
		case <-time.After(200 * time.Millisecond):
		}
		n++
		_, err := fmt.Fprintf(w, "tick %d\n", n)
		if err != nil {
			return false
		}
		return n < 5 // five chunks then end
	})
}
```

#### What happens here

Five ticks or earlier cancel/error. `Cache-Control: no-store` because it is a dynamic stream. In production align server `WriteTimeout` to be larger than the expected duration (here ~1s — easy). For hours-long streams consider a separate setup.

### Example 5: StaticFS from embed

```go
package main

import (
	"embed"
	"io/fs"
	"net/http"

	"github.com/gin-gonic/gin"
)

//go:embed static/*
var staticRoot embed.FS

func main() {
	sub, err := fs.Sub(staticRoot, "static")
	if err != nil {
		panic(err)
	}
	r := gin.New()
	r.Use(gin.Recovery())
	r.StaticFS("/assets", http.FS(sub))
	r.GET("/health", func(c *gin.Context) { c.Status(http.StatusOK) })
	_ = r.Run(":8080")
}
```

#### What happens here

Assets are in the binary. `/assets/...` serves them. Health remains a JSON/status API. Panic only at boot if the embed structure is wrong — not on the request path as “file missing”.

### Example 6: CORS allowlist + credentials

```go
func main() {
	r := gin.New()
	r.Use(gin.Recovery())
	r.Use(corsAllow("https://app.example.com"))
	r.GET("/api/me", func(c *gin.Context) {
		c.Header("Cache-Control", "no-store")
		c.JSON(http.StatusOK, gin.H{"user": "marko"})
	})
	_ = r.Run(":8080")
}
```

#### What happens here

Only the exact Origin gets ACAO + credentials. Preflight OPTIONS Abort with 204. The API route still sends JSON after Next. No `*`.

## Decision analysis

| Decision | Choice | Why |
|----------|--------|-----|
| Session cookie | HttpOnly + Secure + SameSite | XSS / HTTPS / CSRF surface |
| Private JSON | `Cache-Control: no-store` | prevent cache leak |
| Download | AuthZ → jail → FileAttachment | IDOR + traversal |
| Large blob | signed URL | memory / timeout |
| Stream | Context Done | clean cancel |
| CORS + cookie | allowlist origin | browser rules |
| Static | embed.FS | reproducible deploy |

## Trade-offs

- **c.File in app** — simple; keeps IO on the API node.
- **Signed URL** — more scalable; more moving parts (IAM, expiry).
- **SameSite=Strict** — stronger CSRF; can bother some cross-nav flows.
- **Long stream on the same server** — fewer services; conflict with short WriteTimeout for REST.
- **Reflected Origin** — “works in the demo”; dangerous without an allowlist.
- **Cookie auth for SPA** — comfortable for the browser; requires CORS/CSRF discipline vs Bearer header.

## Common mistakes

1. **Wrong:** `c.JSON` then only `SetCookie`.  
   **Effect:** cookie does not arrive.  
   **Fix:** cookie/header before body.

2. **Wrong:** `c.File(c.Query("f"))` without a jail.  
   **Effect:** path traversal.  
   **Fix:** allowlist / Clean+Rel root.

3. **Wrong:** `Cache-Control: public` on `/me`.  
   **Effect:** cache mixes users.  
   **Fix:** `no-store` / `private`.

4. **Wrong:** `Allow-Origin: *` + `Allow-Credentials: true`.  
   **Effect:** browser rejects / insecure demo.  
   **Fix:** exact origin.

5. **Wrong:** stream without `Context().Done()`.  
   **Effect:** goroutine/CPU leak after disconnect.  
   **Fix:** select on Done.

6. **Wrong:** `ReadFile` 2GB in the handler.  
   **Effect:** OOM / latency.  
   **Fix:** signed URL or stream from disk with limits.

7. **Wrong:** download without AuthZ (only “knows the URL”).  
   **Effect:** IDOR.  
   **Fix:** ownership check + audit.

8. **Wrong:** deleting cookie with a different Path/Domain.  
   **Effect:** session remains.  
   **Fix:** same attributes as on set, MaxAge=-1.

## Idiomatic Go

- Request ID middleware + `c.Header` echo.
- Session cookie via `http.Cookie` struct (SameSite clear).
- `safeJoin(root, name)` helper tested with table tests including `..`.
- Static from `embed.FS` for UI; reports outside the binary.
- Stream demo separated from the hot REST timeout profile.
- Never log `Cookie` / `Authorization` values — only presence or request ID.

## Practical scenario

Support gets a ticket “download gives me someone else’s PDF”. The routine was `GET /files/:name` → `c.File("./data/"+name)` without authz. An attacker guesses names. The team introduces: token middleware, `owner_id` check, `safeReportPath`, audit log with request ID, and for files >50MiB a move to signed URL with 5 min expiry. At the same time on JSON `/me` they set `no-store` because the CDN cached someone else’s profile after a wrong `public, max-age=300`. The incident closes with this lesson’s checklist as a PR template.

## Check questions

1. Why header before `c.JSON`?  
   **Answer:** after the body starts, headers often can no longer be changed reliably.

2. What is HttpOnly for on a session cookie?  
   **Answer:** JS does not read the cookie — reduces theft on XSS.

3. How do you delete a cookie?  
   **Answer:** same name/path/domain/secure/httpOnly with `MaxAge: -1` (and empty value).

4. Why not `*` with credentials in CORS?  
   **Answer:** the spec/browser do not allow it; use the exact origin.

5. What is a path jail?  
   **Answer:** restricting the resolved path so it stays under the root directory.

6. When a signed URL instead of `c.File`?  
   **Answer:** large files / scaling / moving IO off the API process.

7. Why `Context().Done()` in Stream?  
   **Answer:** react to client cancellation or timeout — stop writing.

8. Which three steps before download?  
   **Answer:** AuthZ, path jail, audit (plus AuthN as prerequisite).

### Predict: cache

```go
c.Header("Cache-Control", "public, max-age=300")
c.JSON(200, gin.H{"email": userEmail})
```

**Answer:** bad — public cache of a personal email. Fix: `no-store` or at least `private`.

### Predict: traversal

Root `/var/reports`, input `..\\..\\Windows\\win.ini` on a Windows host. Does only `strings.Contains(name, "..")` hold?

**Answer:** it helps, but is not enough alone — use `filepath.Clean` + `filepath.Rel` check on the resolved path; test OS-specific separators.

### Predict: timeout

`WriteTimeout: 2s`, stream sends a chunk every 1s, 10 chunks total.

**Answer:** the connection will likely drop before the end. Either shorten the stream, or increase the timeout / isolate a stream server.

### Mini lab: header order

Do locally and record:

1. `SetCookie` then `JSON` — cookie present in the response.
2. `JSON` then `SetCookie` — often the cookie disappears or a warning in debug.
3. `Header("X-Request-ID")` then `FileAttachment` — ID goes with the file response.

Conclusion you write in your own notes: **metadata before body** is not decoration, but a condition for a correct HTTP response.

### What Gin File does (conceptually)

`c.File(path)` roughly:

1. Opens the file from disk.
2. Sets Content-Type (guesses by extension where it can).
3. Uses a mechanism similar to `http.ServeContent` (Range requests may be supported depending on the path).
4. Streams bytes to the client.

That is why the jail must be **before** the call: once File starts, you are already reading from the path you gave it. AuthZ also before — otherwise you served a forbidden object.

### Cookie and multiple Set-Cookie

HTTP allows multiple `Set-Cookie` headers. You can set session + CSRF cookie in the same login response, both before JSON. On deletion delete **each** name separately with the same Path/Domain attributes.

### Security checklist download (extended)

| Step | Check | Fail status |
|------|-------|-------------|
| AuthN | is there a session/token | 401 |
| AuthZ | may they have the object | 403 |
| Name validation | allowed charset, length | 400 |
| Jail | Rel under root | 400 |
| Existence | Stat/open | 404 |
| Audit | log user+req+file | — |
| Send | FileAttachment | 200 |

Skipping AuthZ + guessing names = classic IDOR. Skipping jail = traversal. Both are worse than “the file is not pretty”.

### Range requests and large PDF

Browsers / download managers often send `Range` for resume. ServeContent-style behavior (which File uses in spirit) can answer 206 Partial Content. That is another reason not to read the whole file into `[]byte`: Range needs the ability to read a **part** of the file. A signed URL to object storage typically scales Range better at the CDN edge.

### Cookie MaxAge nuances

| MaxAge | Meaning |
|--------|---------|
| `< 0` | delete cookie |
| `0` | session cookie (lives while the browser session lasts — browser-dependent) |
| `> 0` | lifetime in seconds |

Do not mix “session cookie” with “server session store”. The cookie may hold only an ID; state lives on the server. If you put data in the cookie, sign it (out of scope of this lesson) — otherwise the client can change it.

### When not to use c.Stream

- Small JSON response — plain `c.JSON`.
- File from disk — `c.File` / signed URL.
- Long SSE in a monolithic API with a short WriteTimeout — isolate a service.

Stream is a tool, not the default transport.

## Summary

- Headers and cookie before body; `Cache-Control` and request ID deliberately; SameSite via `http.SetCookie`.
- `File` / `FileAttachment` with AuthZ + path jail + audit; large → signed URL.
- `c.Stream` with context cancel and aligned `WriteTimeout`.
- CORS without `*` with credentials; `embed.FS`/`StaticFS` for static.
- The download checklist is part of the contract, not an optional decoration.

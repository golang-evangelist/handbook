# 07.02 Routing in Gin: routes, groups, path parameters

> **Go Path - Zero to Gopher** / **02 Intermediate → Gin: A Web Application Framework for Go** / Lesson 07.02

## Lesson goals

After this lesson you should be able to:

- register routes with `GET`, `POST`, `PUT`, `PATCH`, `DELETE` on `*gin.Engine`
- read path parameters via `c.Param` and understand the difference between `:name` and `*name`
- organize prefixes with `RouterGroup` (`Group`)
- distinguish path (resource identity) from query (filter/sort/page)
- map Go 1.22+ `ServeMux` patterns (`{id}`, `PathValue`) to Gin (`:id`, `Param`)
- keep routes out of `main` via `Register(r *gin.Engine, …)`

## Prerequisite

- 07.01: `gin.Default` / `gin.New`, Engine, `gin.Context` vs `context.Context`
- HTTP methods and REST basics (resource, collection)
- module 06: `ServeMux` patterns Go 1.22+

## Problem this lesson solves

Without a clear routing model you quickly get:

- long paths copy-pasted in every handler
- confusion “where is the ID — in the path or in the query?”
- conflicts between a static segment and a parameter
- a `main` of 2000 lines with all routes

Gin offers a radix tree, parameters, and groups. This lesson teaches **how to use them correctly**, not only the syntax.

## Mental model

```text
registration:  METHOD + pattern + []HandlerFunc
                         │
                         ▼
              radix tree inside Engine / Group
                         │
request GET /api/users/42 ┤
                         ▼
              match → Param{"id":"42"} → handler chain
```

A route is not just a string. A route is **method + pattern + chain**. The same path with `GET` and `DELETE` are two routes. `RouterGroup` adds a prefix and can share middleware (Use — more detail in 07.07/07.08).

**Param** (path parameter): name in the pattern (`:id`) → value from the URL (`c.Param("id")`). First gloss: Param here means “path segment”, not query.

## Mechanism

### Registration by method

```go
r := gin.New()
r.Use(gin.Recovery())

r.GET("/items", listItems)
r.POST("/items", createItem)
r.GET("/items/:id", getItem)
r.PUT("/items/:id", replaceItem)
r.PATCH("/items/:id", patchItem)
r.DELETE("/items/:id", deleteItem)
```

Trace for `GET /items/7`:

1. Engine sees method `GET`.
2. The tree walks `/items/` then the parameter node `:id`.
3. The `Param` map gets `id=7`.
4. The chain for that route (here `getItem`) runs.
5. `DELETE /items/7` goes to a **different** route — a different handler.

**Predict the result:** you register only `GET /items/:id`. `POST /items/1` arrives. What happens?

**Answer:** no match for POST on that pattern. Without `NoMethod`/`NoRoute` configuration (07.03) you typically get 404. So explicitly register the methods you support.

### c.Param — the name must match

```go
r.GET("/users/:id", func(c *gin.Context) {
	id := c.Param("id")
	c.JSON(http.StatusOK, gin.H{"id": id})
})
```

| Pattern | Call | `c.Param("id")` | `c.Param("ID")` |
|---------|------|-----------------|-----------------|
| `/users/:id` | `/users/42` | `"42"` | `""` (wrong name) |
| `/users/:uid` | `/users/42` | `""` | — use `Param("uid")` |

The name is case-sensitive and must exactly match the one in the pattern.

### :name vs *name (wildcard)

| Syntax | Meaning | Example |
|--------|---------|---------|
| `:id` | exactly one segment | `/files/:name` → `/files/a.txt` |
| `*filepath` | rest of the path | `/assets/*filepath` → `/assets/css/app.css` |

```go
r.GET("/assets/*filepath", func(c *gin.Context) {
	fp := c.Param("filepath") // often starts with "/"
	c.String(http.StatusOK, "path=%s", fp)
})
```

**Predict the result:** request `/assets/css/app.css` — what is a typical value of `filepath`?

**Answer:** often `"/css/app.css"` (with a leading slash). Do not assume without a test; normalize before joining with a root directory.

Wildcard + disk requires a **path jail**: `filepath.Clean`, forbid `..` escaping the root. Do not learn an exploit — learn defense: Clean + check that the resolved path stays under the root.

### Static segment vs parameter

```go
r.GET("/sku/export", exportSKU)   // static
r.GET("/sku/:code", getSKU)       // parameter
```

Static `/sku/export` takes priority over `/sku/:code` for path `/sku/export`. That is what you want. A conflict arises when you register two patterns the tree cannot separate — debug mode warns; in CI construct the router in a test to catch panic/conflict early.

### RouterGroup — prefix without copy-paste

```go
api := r.Group("/api")
{
	api.GET("/ping", ping)
	api.GET("/users/:id", getUser)
}
// full paths: GET /api/ping, GET /api/users/:id
```

`Group` returns `*gin.RouterGroup`. The prefix concatenates. Later (07.03) you nest versions; later (07.07) `api.Use(auth)`.

**Predict the result:** `v1 := r.Group("/v1"); v1.GET("/v1/items", …)` — what is the full path?

**Answer:** `/v1/v1/items` — a common double-prefix mistake. Write `v1.GET("/items", …)`.

### Path vs query

| URL part | Role | Example |
|----------|------|---------|
| Path + Param | resource identity | `/orders/99` |
| Query | filter, sort, page | `/orders?status=open&page=2` |

```go
r.GET("/orders/:id", getOrder) // id in the path
r.GET("/orders", listOrders)   // filters in query — bind in 07.04
```

Do not mix `GET /orders?id=99` and `GET /orders/:id` without clear documentation — clients and cache proxies get confused.

### Handler as method (receiver)

```go
type ItemAPI struct {
	Store ItemStore
}

func (a *ItemAPI) Get(c *gin.Context) {
	id := c.Param("id")
	item, err := a.Store.Find(c.Request.Context(), id)
	if err != nil {
		c.JSON(http.StatusNotFound, gin.H{"error": "not found"})
		return
	}
	c.JSON(http.StatusOK, item)
}

func Register(r *gin.Engine, api *ItemAPI) {
	r.GET("/items/:id", api.Get)
}
```

Dependencies live in the struct. `Register` keeps `main` thin. `c.Request.Context()` goes into the store — cancellation follows the HTTP request.

### Mapping from ServeMux 1.22+

| net/http (1.22+) | Gin |
|------------------|-----|
| `GET /items/{id}` | `GET /items/:id` |
| `r.PathValue("id")` | `c.Param("id")` |
| sub-mux / prefix | `Group("/api")` |
| method in the pattern | separate registration per method |

### Trailing slash and redirect

Gin can redirect `/foo` ↔ `/foo/` depending on `RedirectTrailingSlash` / `RedirectFixedPath`. Strict API clients that do not follow redirects see a surprise. **Team rule:** pick a canonical form, document it, test both.

### HEAD and OPTIONS

A `GET` registration often also covers `HEAD` (same handler, no body — behavior depends on the stack). `OPTIONS` / CORS are not CRUD — that is middleware (07.08 / gin-contrib), not `Any` on everything.

### File organization

```text
cmd/api/main.go          // New, Server, Register call
internal/httpapi/
  router.go              // Register(r, deps)
  items.go               // handlers
```

`r.Routes()` in dev lists registered routes — useful for debug, not for production logic.

### Execution trace: Group + Param + Store

Imagine registration:

```go
api := r.Group("/api")
api.GET("/users/:uid/orders/:oid", a.GetOrder)
```

Request: `GET /api/users/u9/orders/o3`

```text
1. Engine.ServeHTTP
2. Global middleware (e.g. Recovery) → Next
3. Prefix /api matches Group
4. Tree: users → :uid=u9 → orders → :oid=o3
5. Param map: uid=u9, oid=o3
6. a.GetOrder:
     uid := c.Param("uid")
     oid := c.Param("oid")
     a.Orders.Get(c.Request.Context(), uid, oid)
7. JSON response / 404 mapping
```

**Predict the result:** the client sends `GET /api/users/u9/orders/o3?verbose=1`. Does `c.Param("verbose")` return `"1"`?

**Answer:** no — `verbose` is **query**, not a path Param. You read query via `c.Query` / `ShouldBindQuery` (07.04). Path and query are different sources.

### Table: where each identifier lives

| Information | Place | Gin API |
|-------------|-------|---------|
| Resource ID | path segment | `c.Param("id")` |
| Status filter | query | `c.Query("status")` / bind |
| Sort | query | `form:"sort"` |
| API version (course) | path prefix | `Group("/v1")` (07.03) |
| Auth token | header | `c.GetHeader` (07.03/07.07) |

### Route conflicts — what you look for in a test

```go
func TestRouterConstructs(t *testing.T) {
	r := gin.New()
	r.Use(gin.Recovery())
	Register(r, deps) // panic/conflict at registration = CI fail
	_ = r
}
```

Do not wait for production to discover “catch-all ate the static route”. Construct the router in a test. DebugMode warns additionally — still, a CI test is a cheaper signal.

| Situation | Expectation |
|-----------|-------------|
| `/sku/export` + `/sku/:code` | OK — static wins for `/sku/export` |
| Two identical `GET /items/:id` | conflict / panic at registration |
| `GET /items/:id` and `GET /items/:code` | often conflict (same shape) |

**Predict the result:** you register `GET /items/:id` then `GET /items/:code`. What do you expect?

**Answer:** typically a conflict — both are one parameter segment in the same place. Choose **one** Param name in the API contract.

### Query string does not change the route

```go
r.GET("/orders", listOrders)
r.GET("/orders/:id", getOrder)
```

| Request | Matched route |
|---------|---------------|
| `GET /orders` | list |
| `GET /orders?status=open` | list (same path) |
| `GET /orders/12` | get |
| `GET /orders/12?expand=1` | get — `expand` is query |

Radix chooses by **path** (and method), not by query keys. Do not register a “route” for every filter.

### Method receiver vs closure — comparison

| Style | Advantage | Drawback |
|-------|-----------|----------|
| Closure in `main` that captures `db` | quick for demos | hard to test, `main` grows |
| Method on `ItemAPI` | DI, mock store, Register | a few more types |
| Package-level func + global DB | looks short | hidden dependency, parallel tests suffer |

Course idiom: method + `Register`.

### RedirectTrailingSlash — mini trace

```text
Registered: GET /users/
Request:    GET /users
→ possible 301/302 to /users/ (if redirect is on)
→ API client that does not follow redirect sees “it doesn’t work”
```

**Team rule:** either always without trailing slash, or always with — document and test both forms in one table test (07.09).

### Multiple Group levels (preview of 07.03)

```go
api := r.Group("/api")
v1 := api.Group("/v1")
v1.GET("/ping", ping) // full: /api/v1/ping
```

Prefixes concatenate. Here you learn the mechanics; nesting public/admin and versions in detail is in 07.03.

**Predict the result:** `api := r.Group("/api"); api.Group("/api").GET("/ping", …)` — full path?

**Answer:** `/api/api/ping` — the same kind of mistake as double `/v1`.

### r.Handle — generic registration

```go
r.Handle(http.MethodGet, "/ping", ping)
// equivalent in spirit: r.GET("/ping", ping)
```

`GET`/`POST`/… are sugar over `Handle`. Useful when you pick the method from a constant or a slice of allowed methods in a route generator — still explicit, not `Any` on CRUD.

## Rules and syntax

1. `r.GET(path, handlers...)` — path relative to Engine or Group prefix.
2. Parameter: `:id` in the path, read with `c.Param("id")`.
3. Wildcard: `*name` captures the rest; normalize before I/O.
4. `Group(prefix)` returns `*gin.RouterGroup` with the same registration API.
5. Same path, different method = different route.
6. Path = identity; query = filter.
7. Do not duplicate the group prefix in the path string.
8. Handler with a receiver > huge closures in `main`.
9. Catch conflicts by constructing the router in a test.
10. For DB/IO always `c.Request.Context()`, not `c` as `context.Context`.

## Examples

### Example 1: CRUD skeleton

```go
package main

import (
	"net/http"

	"github.com/gin-gonic/gin"
)

func main() {
	r := gin.New()
	r.Use(gin.Recovery())

	r.GET("/items", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"items": []any{}})
	})
	r.POST("/items", func(c *gin.Context) {
		c.JSON(http.StatusCreated, gin.H{"id": "new"})
	})
	r.GET("/items/:id", func(c *gin.Context) {
		c.JSON(http.StatusOK, gin.H{"id": c.Param("id")})
	})
	r.DELETE("/items/:id", func(c *gin.Context) {
		_ = c.Param("id")
		c.Status(http.StatusNoContent)
	})

	_ = r.Run(":8080")
}
```

#### What happens here

Four routes, two share the pattern `/items/:id` but different methods. `POST` returns 201 with a body; `DELETE` returns 204 with no body via `c.Status`. `Param("id")` reads the segment. This is a skeleton — body binding comes in 07.04.

### Example 2: Group and full path

```go
package main

import (
	"net/http"

	"github.com/gin-gonic/gin"
)

func main() {
	r := gin.New()
	r.Use(gin.Logger(), gin.Recovery())

	api := r.Group("/api")
	{
		api.GET("/ping", func(c *gin.Context) {
			c.JSON(http.StatusOK, gin.H{"ok": true})
		})
		api.GET("/users/:id", func(c *gin.Context) {
			c.JSON(http.StatusOK, gin.H{"id": c.Param("id")})
		})
	}

	_ = r.Run(":8080")
}
```

#### What happens here

`Group("/api")` does not register a handler by itself — only a prefix. `GET /api/ping` and `GET /api/users/3` work. `GET /ping` (without `/api`) does not match. Logger prints full paths. This prevents copy-pasting `/api` in every registration.

### Example 3: Multiple Params and Store

```go
package main

import (
	"context"
	"errors"
	"net/http"

	"github.com/gin-gonic/gin"
)

var errNotFound = errors.New("not found")

type OrderStore interface {
	Get(ctx context.Context, userID, orderID string) (map[string]string, error)
}

type API struct {
	Orders OrderStore
}

func (a *API) GetOrder(c *gin.Context) {
	uid := c.Param("uid")
	oid := c.Param("oid")
	out, err := a.Orders.Get(c.Request.Context(), uid, oid)
	if errors.Is(err, errNotFound) {
		c.JSON(http.StatusNotFound, gin.H{"error": "not found"})
		return
	}
	if err != nil {
		c.JSON(http.StatusInternalServerError, gin.H{"error": "internal error"})
		return
	}
	c.JSON(http.StatusOK, out)
}

func Register(r *gin.Engine, a *API) {
	r.GET("/users/:uid/orders/:oid", a.GetOrder)
}
```

#### What happens here

The pattern has two parameters. Names `uid` and `oid` must match in `Param`. The store receives `context.Context` from Request — client cancellation can interrupt Find. A sentinel `error` (`errNotFound`) maps to 404; other errors to 500 **without** leaking internal text. Panic is not used.

### Example 4: Static vs parameter

```go
r.GET("/files/readme", func(c *gin.Context) {
	c.String(http.StatusOK, "canonical readme")
})
r.GET("/files/:name", func(c *gin.Context) {
	c.String(http.StatusOK, "file=%s", c.Param("name"))
})
```

#### What happens here

Request `/files/readme` goes to the first route, not to `:name=readme`. Request `/files/other` goes to the second. Test both in a table test later (07.09). Thinking order: “is there a special static segment?” before a parametric “everything else”.

### Example 5: Wildcard with a jail sketch

```go
import (
	"net/http"
	"path"
	"path/filepath"
	"strings"

	"github.com/gin-gonic/gin"
)

func serveAsset(root string) gin.HandlerFunc {
	return func(c *gin.Context) {
		rel := c.Param("filepath")
		rel = strings.TrimPrefix(path.Clean("/"+rel), "/")
		full := filepath.Join(root, filepath.FromSlash(rel))
		if !strings.HasPrefix(full, filepath.Clean(root)+string(filepath.Separator)) &&
			full != filepath.Clean(root) {
			c.Status(http.StatusBadRequest)
			return
		}
		c.File(full)
	}
}

// r.GET("/assets/*filepath", serveAsset("/var/www/assets"))
```

#### What happens here

The wildcard captures the rest. `Clean` and the prefix check prevent escaping `root` via `..`. If the check fails, 400 — not panic. `c.File` sends the file (response details in 07.06). This is a defensive pattern, not an attack.

### Example 6: Register + multiple methods on the same Param pattern

```go
package httpapi

import (
	"net/http"

	"github.com/gin-gonic/gin"
)

type ItemAPI struct{}

func (ItemAPI) List(c *gin.Context) {
	c.JSON(http.StatusOK, gin.H{"items": []any{}})
}

func (ItemAPI) Create(c *gin.Context) {
	c.JSON(http.StatusCreated, gin.H{"id": "generated"})
}

func (ItemAPI) Get(c *gin.Context) {
	c.JSON(http.StatusOK, gin.H{"id": c.Param("id")})
}

func (ItemAPI) Delete(c *gin.Context) {
	_ = c.Param("id")
	c.Status(http.StatusNoContent)
}

func RegisterItems(r *gin.Engine, api ItemAPI) {
	g := r.Group("/api/items")
	{
		g.GET("", api.List)        // GET /api/items
		g.POST("", api.Create)     // POST /api/items
		g.GET("/:id", api.Get)     // GET /api/items/:id
		g.DELETE("/:id", api.Delete)
	}
}
```

#### What happens here

One `Group("/api/items")` holds the collection and the member. Empty path `""` on the group means exactly the group prefix. Four routes, two Param patterns by method. `main` only calls `RegisterItems(r, ItemAPI{})`. Tests construct the same Engine. No mixing of `context.Context` — when Store arrives, `Get` will call `c.Request.Context()`.

**Predict the result:** `g.GET("/", api.List)` instead of `g.GET("", api.List)` — what is the full path and what about trailing slash?

**Answer:** often `/api/items/` (with slash). Align with the team’s trailing-slash policy; test both `/api/items` and `/api/items/`.

### Example 7: Path vs query in the same handler (on purpose)

```go
func getOrder(c *gin.Context) {
	id := c.Param("id")
	expand := c.Query("expand") // string; empty if missing
	if id == "" {
		c.JSON(http.StatusBadRequest, gin.H{"error": "missing id"})
		return
	}
	c.JSON(http.StatusOK, gin.H{"id": id, "expand": expand})
}

// r.GET("/orders/:id", getOrder)
```

#### What happens here

Identity is in the path (`Param`). Optional `expand` is query — it does not change which route matches. An empty `Param` on a well-registered route is rare (the tree already extracted the segment); the check is defensive. Detailed typed query bind comes in 07.04; here you see the path/query boundary.

**Predict the result:** `GET /orders?id=5` while only `/orders/:id` is registered. What happens?

**Answer:** it does not match `/orders/:id` (no segment). It may fall on the list route `/orders` if it exists, or 404. ID in query is **not** a substitute for `:id` path without an explicit design.

## Decision analysis

| Decision | Choice | Why |
|----------|--------|-----|
| ID in path vs query | path `:id` | REST identity, cache, clarity |
| Group vs repeating prefix | Group | DRY, place for Use |
| Wildcard vs more routes | more routes when you can | clearer, less jail risk |
| Anonymous handler vs method | method + Register | testing, DI |
| 204 vs 200 on DELETE | 204 | no body; client does not wait for JSON |

## Trade-offs

- **Deep groups** — less repetition; harder to see the final path without docs/tests.
- **Wildcard** — powerful for assets; requires path-jail discipline.
- **Many Params** — expressive; uglier URLs and harder cache rules.
- **Strict trailing-slash** — consistency; breaks clients that guess.

## Common mistakes

1. **Wrong:** `c.Param("ID")` but the route has `:id`.  
   **Effect:** empty string, fake 404 in the service.  
   **Fix:** same name as in the pattern.

2. **Wrong:** `v1.GET("/v1/items", …)` after `Group("/v1")`.  
   **Effect:** `/v1/v1/items`.  
   **Fix:** `v1.GET("/items", …)`.

3. **Wrong:** ID only in query while the path looks like a collection.  
   **Effect:** confused clients and proxy cache.  
   **Fix:** path for identity.

4. **Wrong:** wildcard without Clean/jail.  
   **Effect:** risk of reading outside the root.  
   **Fix:** Clean + HasPrefix check.

5. **Wrong:** all routes in `main`.  
   **Effect:** impossible to reuse in a test.  
   **Fix:** `Register(r, deps)`.

6. **Wrong:** `db.Query(..., c)` by type.  
   **Effect:** does not compile / wrong model.  
   **Fix:** `c.Request.Context()`.

7. **Wrong:** panic when Param is missing.  
   **Effect:** 500 instead of 400/404.  
   **Fix:** check + JSON status.

8. **Wrong:** expecting query to change route selection.  
   **Effect:** “filter routes” that do not exist; confused debug.  
   **Fix:** one list route + query bind.

9. **Wrong:** `GET /items/:id` and `GET /items/:code` as “two names”.  
   **Effect:** conflict at registration.  
   **Fix:** one Param name in the contract.

10. **Wrong:** wildcard then `filepath.Join` without Clean/HasPrefix.  
    **Effect:** path traversal risk toward disk.  
    **Fix:** jail pattern from Example 5.

11. **Wrong:** mixing `c.Param` names (`:id` vs `Param("userId")` or `Param("ID")`).  
    **Effect:** always empty string.  
    **Fix:** same ASCII name as in the pattern, consistently.

## Idiomatic Go

- `Register(r *gin.Engine, deps Deps)` in `internal/httpapi`.
- Handler as a **method** with a pointer **receiver** on the API struct.
- Sentinel `error` in the domain; HTTP map in the adapter.
- Leave query bind for 07.04; keep the path clean here.
- Do not use a **blank identifier** to swallow a store error without a status.
- Document route and Param names in the team’s OpenAPI / README.

## Practical scenario

An e-commerce API moves from `ServeMux` `GET /users/{uid}/orders/{oid}` to Gin. The team maps `{uid}` → `:uid`, `PathValue` → `Param`, sub-mux `/api` → `Group("/api")`. Special `/files/readme` stays a static route beside `/files/:name`. `Register` is called from both `main` and tests — the same route tree. After a week, tickets “works on my main, not in CI” disappear because there is no longer a duplicate router.

Second wave: someone adds `GET /items/:code` beside the existing `:id` “for readability”. CI fails on router construction. The team picks one name (`id`) and documents it in OpenAPI. Query filters stay on `GET /items` — nobody tries to register a special route per `?status=` anymore.

### Mini matrix request → route (memorize this)

| Request | Registered | Outcome |
|---------|------------|---------|
| `GET /api/ping` | `Group("/api")+GET("/ping")` | matches |
| `GET /ping` | same | 404 (no prefix) |
| `DELETE /items/1` | only `GET /items/:id` | 404 (or 405 in 07.03) |
| `GET /files/readme` | static + `:name` | static handler |
| `GET /assets/a/b` | `*filepath` | Param rest |
| `GET /orders/1?x=1` | `/orders/:id` | get; `x` is query |

## Check questions

1. How do you read `:id` from `/users/:id`?  
   **Answer:** `c.Param("id")` — the name must match.

2. What is `Group("/api")` for?  
   **Answer:** a shared prefix (and later shared middleware via `Use`).

3. What is the difference between `:name` and `*name`?  
   **Answer:** one segment vs the rest of the path.

4. Where does the resource ID go — path or query?  
   **Answer:** path (Param); query for filter/sort/page.

5. How do you map Go 1.22 `{id}` to Gin?  
   **Answer:** `:id` and `c.Param("id")`.

6. Why `Register` instead of routes only in `main`?  
   **Answer:** the same router in production and `httptest` tests; thinner `main`.

7. What to do with `context` for a store call?  
   **Answer:** pass `c.Request.Context()`.

8. Does `?page=2` pick a different route from `GET /orders`?  
   **Answer:** no — the same path route; query is an extra input.

9. Why static `/sku/export` beside `/sku/:code`?  
   **Answer:** a special segment must not fall into the generic Param handler.

10. What is a common mistake after `Group("/v1")`?  
    **Answer:** `GET("/v1/items")` → full path `/v1/v1/items`.

11. Why construct the router in a test without an HTTP call?  
    **Answer:** early catch of route conflicts / panic at registration.

12. How does `r.Handle(http.MethodGet, path, h)` relate to `r.GET`?  
    **Answer:** more generic registration of the same idea; `GET` is convenient sugar.

### Predict the result — quick set

**1.** Pattern `/users/:id/posts/:pid`, request `/users/1/posts/2`. `Param("id")` and `Param("pid")`?

**Answer:** `"1"` and `"2"`.

**2.** Pattern `/assets/*filepath`, request `/assets`. What do you expect?

**Answer:** often no match (no rest) or it depends on trailing rules — verify with a test; do not assume `filepath` is reliably an empty string.

**3.** `api := r.Group("/api"); api.GET("ping", h)` without a leading `/` — risk?

**Answer:** paths can glue unexpectedly (`/apiping` in some cases). Idiom: path segments with a leading `/` like `"/ping"`.

### ServeMux ↔ Gin table (extended)

| Need | Go 1.22+ mux | Gin |
|------|--------------|-----|
| Method + path | `"GET /x/{id}"` | `r.GET("/x/:id", …)` |
| Read param | `r.PathValue("id")` | `c.Param("id")` |
| Prefix | sub-mux / StripPrefix | `Group` |
| Custom 404 | `mux` not found | `NoRoute` (07.03) |
| Wildcard | `$` / manual | `*name` |

## Summary

- Route = method + pattern + handler chain in the radix tree.
- `Param` reads `:id`; the name must match exactly.
- `Group` solves prefixes; do not duplicate the prefix in the path.
- Path = identity; query = filter; wildcard needs a jail.
- `Register` + method handlers keep DI and tests clean.
